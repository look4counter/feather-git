# Feather Git

Rust, GPUI, gix로 만든 Git 데스크톱 클라이언트입니다. 프로젝트마다 상단 탭을 열고 단일 화면에서 참조·커밋·변경 파일·차이를 탐색합니다.

```text
저장소 탭 / 새 탭                                          [+]
┌────────────────────────┬───────────────────────────────────┐
│ 브랜치 목록            │ 커밋 히스토리                     │
│ Local Remote Stash Tag │ 제목 · 해시 · 작성자 · 날짜       │
├────────────────────────┼───────────────────────────────────┤
│ 파일 목록              │ Diff Viewer                       │
│ Stage / History        │ 이전/이후 행 번호 · 통합 차이     │
└────────────────────────┴───────────────────────────────────┘
저장소 경로                                             읽기 전용
```

## 실행

Windows용 Rust MSVC 도구 체인, Visual Studio C++ 빌드 도구, Windows SDK와 GPU 드라이버가 필요합니다.

```powershell
cargo run -- "D:\Projects\my-repository"
```

경로 여러 개를 전달하면 저장소별 탭이 생성됩니다. 인자 없이 실행하면 빈 탭으로 시작합니다. 상단 맨 오른쪽 **+**를 누르면 신규 저장소·저장소 열기·Clone을 선택하는 탭이 추가됩니다. 탭 오른쪽 ×로 닫으며, 마지막 탭을 닫으면 빈 탭이 하나 남습니다.

## 사용 방법

- **Local / Remote / Stash / Tag**: 참조를 선택해 해당 이력을 탐색합니다. Stash는 각 보관 항목을 표시합니다.
- **커밋 히스토리**: 커밋을 선택하면 파일 목록이 History로 전환됩니다.
- **Stage**: 스테이징 변경과 작업 디렉터리 변경을 구분합니다. 같은 파일이 두 그룹에 있을 수 있으며 각각 HEAD↔인덱스, 인덱스↔작업 디렉터리를 비교합니다.
- **History**: 선택한 커밋과 첫 부모 사이의 변경을 표시합니다. 최초 커밋은 빈 트리와 비교합니다.
- **Diff Viewer**: 파일을 선택하면 추가·삭제 행과 이전/이후 행 번호를 표시합니다.
- **탭 바**: 탭이 상단 높이를 채우며 여백과 둥근 모서리가 없습니다. 맨 오른쪽 +는 고정되고 많은 탭은 가로 스크롤합니다. 빈 탭과 저장소 탭을 전환해도 저장소의 선택 상태는 유지됩니다. 상단 도구 버튼은 없으며 새 탭에서 저장소를 열 수 있습니다.
- **영역 크기 조절**: 패널 사이 세로 경계선을 좌우로, 가로 경계선을 상하로 드래그합니다. 네 영역은 여백 없이 맞붙으며, 조절한 비율은 프로젝트를 전환해도 유지됩니다. 각 영역은 최소 크기 이하로 줄어들지 않습니다.

## 초기 버전 범위

저장소 조회를 구현했습니다. 스테이징 실행, 커밋 생성, 체크아웃, fetch/push는 제공하지 않습니다. 기존 조회는 gix로 수행합니다. 신규 생성과 Clone은 설치된 Git을 사용하며 기존 대상 경로를 덮어쓰지 않습니다.

이력은 모든 로컬·원격 브랜치·태그·stash와 HEAD에서 도달 가능한 전체 커밋을 표시합니다. 파일 미리보기는 1 MiB, 차이 표시는 5,000줄로 제한합니다. 바이너리·UTF-8 이외의 파일·심볼릭 링크·서브모듈에는 안내를 표시합니다. 이름 변경은 삭제와 추가로 나타납니다. 텍스트 차이는 원본 내용을 비교하므로 줄바꿈 및 Git 필터의 정규화 결과와 다를 수 있습니다. 탭 상태는 앱 실행 중에 유지되며 종료 후에는 복원하지 않습니다.

## 개발 검증

```powershell
cargo fmt --check
cargo check --locked
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
```

테스트 준비에는 Git CLI가 필요합니다. 실제 임시 저장소에서 참조·stash·빈 저장소·인덱스 및 작업 트리·병합·파일 모드·바이너리·제한을 검증합니다. 조회 전후 인덱스 바이트와 HEAD도 비교합니다.

설계 산출물은 [기능 명세](specs/001-git-client/spec.md), [계획](specs/001-git-client/plan.md), [작업 목록](specs/001-git-client/tasks.md), [실행 검증 안내](specs/001-git-client/quickstart.md)에 있습니다.

형식·컴파일·Clippy 검사와 테스트 29개(그래프 5개, 열·날짜 3개, 분할 계산 3개, 스크롤 수치 2개, 시작 기능 1개, 저장소 통합 15개)가 통과했습니다. Computer Use 자동 승인 검토에서 앱 실행이 거절되어 실제 창의 화면 배치 및 마우스 조작은 아직 검증하지 못했습니다. 실행 중인 앱을 닫고 `cargo run`으로 다시 빌드·실행하면 변경된 배치가 적용됩니다.

## 새 탭에서 저장소 시작

- 신규 저장소: 저장소를 만들 새 경로를 선택합니다.
- 저장소 열기: 기존 저장소 폴더를 선택합니다.
- Clone: URL을 입력하거나 Ctrl+V로 붙여넣고 실행 버튼 또는 Enter로 새 저장 위치를 선택합니다. Ctrl+A로 URL 전체를 선택할 수 있습니다.

Git이 PATH에 있어야 합니다. 인증은 Git 설정을 사용합니다. 진행 중에는 중복 실행을 막으며 실패한 Clone의 일부 파일은 자동 삭제하지 않습니다.

이번 검증에서 실행 중인 앱의 EXE 잠금으로 전체 cargo test 명령은 완료되지 않아 단위 테스트와 기존 조회 통합 테스트 실행 파일을 나누어 실행했습니다. 실제 GUI 조작은 미확인입니다. 변경 사항을 실행하려면 기존 앱을 닫고 cargo run으로 다시 시작합니다.

## 커밋 그리드와 상세

커밋 히스토리는 Graph·Description·Author·Date·Hash 열로 표시합니다. zit 프로젝트와 같은 부모 레인 방식으로 분기·병합을 곡선으로 연결합니다. 화면에 보이는 행만 가상 스크롤로 렌더링하며 헤더는 고정됩니다. 그리드는 패널 폭을 100% 채우고 열 경계를 드래그해 너비를 조절할 수 있습니다. 브랜치 선택은 필터링하지 않고 해당 브랜치 끝 커밋으로 이동합니다.

커밋 행을 선택하면 History로 이동하고 상세를 표시합니다. History의 **커밋상세** 항목은 변경 파일 목록 위에 고정되어 있습니다. 이 항목을 선택하면 Diff Viewer에 전체 해시·부모 해시·작성자·커미터·시간대가 포함된 시간·전체 메시지를 표시합니다. 파일을 선택하면 해당 파일의 Diff로 전환합니다. Stage에는 상세 항목을 표시하지 않습니다.

컴파일·Clippy 및 테스트 29개가 통과했습니다. 기본 EXE 잠금으로 단위 테스트는 Cargo로, 새로 컴파일한 저장소 통합 테스트는 직접 실행했습니다. Computer Use 자동 승인 검토가 별도 빌드의 실행을 허용하지 않아 GUI 시각 검증은 미완료입니다.

## 히스토리 성능 개선

이전 구현은 전체 행을 매번 생성하고 커밋을 클릭할 때마다 전체 이력·작업 상태·그래프를 다시 조회했습니다. 이제 GPUI uniform_list가 가시 범위만 생성하고 그래프 경로 캐시도 해당 범위에 한정합니다. 커밋 선택은 파일과 상세만 조회합니다. Description 맨 앞의 배지로 로컬·원격 브랜치의 끝을 표시하고 Date는 커밋 시간대 기준 YYYY-MM-DD HH:MM으로 표시합니다. 전체 폭을 유지하도록 열 경계는 이웃 두 열 사이에서 조절됩니다.

측정 예제는 `cargo run --example history_profile -- 저장소경로`로 실행합니다. 이번 개발 빌드의 10,000개 커밋 bare 저장소에서 전체 재조회 1회는 약 547ms, 상세 전용 조회 20회 평균은 약 1.9ms였습니다. 이는 조회 경로 측정이며 GUI 프레임률 측정은 아닙니다. 최초 전체 메타데이터 조회는 백그라운드에서 계속 필요합니다.

## 공통 스크롤바와 점진 조회

커밋 히스토리·브랜치·파일·Diff Viewer는 같은 표시 스크롤바를 사용합니다. 휠, 트랙 클릭, 손잡이 드래그로 이동하며 Diff에는 긴 줄을 위한 가로 스크롤바도 있습니다. 네 목록과 커밋상세 메시지는 가시 행만 생성합니다. History의 커밋상세 항목은 파일 목록 위에 고정되며 Stage 그룹과 파일 선택 인덱스는 유지합니다.

히스토리는 처음 200개를 읽고 맨 아래에 도달하면 다음 200개를 자동으로 이어 읽습니다. 끝까지 가면 멈추며 추가 조회 중에는 중복 요청하지 않습니다. 실패하면 다시 시도를 누를 수 있습니다. 전체 개수와 첫 부모 기준 라벨은 제거했고 Graph 열에도 공통 왼쪽 여백을 적용했습니다. ●는 실제 체크아웃 로컬 브랜치 이름 앞에 표시되며 선택 강조와 구분됩니다. detached HEAD에서는 이 표식을 표시하지 않습니다.

탐색 iterator와 그래프 레인을 유지하여 페이지마다 처음부터 다시 읽지 않습니다. 위상 정렬은 관계 판단에 필요한 객체 헤더를 더 탐색할 수 있으므로 첫 페이지가 저장소 크기에 완전히 독립적인 비용은 아닙니다. 1만 개 bare 저장소의 개발 빌드 측정에서 첫 200개는 632.10ms, 다음 200개는 17.28ms였습니다. 조회 시간 측정이며 GUI 프레임률 수치는 아닙니다.

검사와 테스트 29개가 통과했습니다. 실제 GUI의 클릭·드래그 검증은 수행하지 못했습니다. 기존 앱을 닫고 cargo run으로 재실행하면 변경 사항이 적용됩니다.

## 영역 배치와 상세 표시

브랜치 목록·커밋 히스토리·파일 목록·Diff Viewer의 제목 헤더를 제거했습니다. 참조/파일 탭, 그리드 컬럼 헤더와 파일 경로는 유지합니다. 브랜치·파일·Stage 그룹·고정 커밋상세 행은 가용 폭 100%와 공통 24px 높이를 사용합니다.

스크롤이 필요한 축에만 바와 해당 공간을 생성합니다. 가로/세로 바의 상호 영향을 함께 계산하며 Diff의 가로 폭은 최초 표시 때 실제 글꼴로 측정하여 캐시합니다. 커밋 추가 로딩 중에는 그리드 안에 움직이는 진행 표시를 겹쳐 보여 기존 행을 밀어내지 않습니다.

커밋상세는 ‘상위 항목: 해시’를 한 줄로 표시합니다. 병합의 각 상위 항목도 같은 형식이고 초기 커밋은 같은 줄에 안내합니다. 작성/커밋 시간은 기록된 시간대의 시각을 유지하면서 시간대 문자열만 숨깁니다. 커밋 메시지 라벨을 제거하고 메시지 본문과 빈 줄은 보존합니다.

검사와 테스트 32개가 통과했습니다. 실제 창에서 스크롤바 표시·행 hover·진행 애니메이션은 미확인입니다. 실행 중인 앱을 닫고 cargo run으로 다시 시작하면 적용됩니다.
