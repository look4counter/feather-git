작성일: 2026-11-11 · 상태: 명세 검증 완료 · 브랜치: 저장소 초기화 전

## 사용자 시나리오 및 검증

### 사용자 이야기 1 — 작업 공간 파악 (우선순위 P1)

사용자는 프로젝트 탭 아래 작업 툴바와 네 영역의 Git 작업 공간을 본다.
독립 검증: 실행 시 탭, 툴바, 브랜치, 커밋 기록, 변경 파일, 상세, 상태 표시줄이 보인다.
수용 시나리오: 창을 열면 왼쪽에 브랜치와 변경 파일, 오른쪽에 커밋 그래프와 상세가 표시된다.

### 사용자 이야기 2 — 화면 탐색 (우선순위 P2)

사용자는 프로젝트와 커밋을 선택해 강조 표시와 상세 내용을 확인한다.
독립 검증: 프로젝트 탭과 커밋 행을 클릭하면 선택 상태가 갱신된다.
수용 시나리오: 커밋을 선택하면 상세 해시와 메시지가 해당 커밋으로 바뀐다.

### 경계 조건

- 긴 파일명과 메시지는 패널 너비를 밀어내지 않는다.
- 작은 창에서는 최소 크기를 적용하고 목록을 스크롤한다.
- 실제 저장소 미연결과 샘플 데이터임을 표시한다.
- 작업 버튼은 실행 완료를 가장하지 않고 연결 예정 상태를 알린다.

## 요구사항

- FR-001: 프로젝트 탭 바로 아래에 커밋, 풀, 푸시, 패치, 브랜치, 병합, 스태시 7개 작업을 배치한다.
- FR-002: 참조 이미지의 좌우 및 상하 패널 관계와 상태 표시줄을 유지한다.
- FR-003: 네이비 바탕, 단계별 패널 명도, 청록 포인트, 일관된 간격과 선택 강조를 적용한다.
- FR-004: 프로젝트 탭과 커밋 선택을 지원하고 상세를 동기화한다.
- FR-005: 샘플 데이터와 미연결 상태를 표시하며 실제 Git 변경은 수행하지 않는다.
- FR-006: 긴 문자열 잘림, 목록 스크롤, 최소 창 크기를 지원한다.

### 주요 개체

- 프로젝트: 이름과 현재 브랜치.
- 커밋: 메시지, 해시, 작성자, 날짜, 참조 라벨.
- 변경 파일: 상태와 경로.

## 성공 기준

- SC-001: 1280×800에서 7개 작업, 4개 본문 영역, 상태 표시줄을 볼 수 있다.
- SC-002: 커밋 선택 직후 상세의 메시지와 해시가 일치한다.
- SC-003: 미연결 작업은 저장소를 변경하지 않고 안내를 표시한다.

## 가정 및 명확화

- 기본 골격 요청에 따라 Git 연동과 저장 기능은 후속 범위이다.
- 색상은 디자인 재량으로 해석하여 다크 테마를 기본으로 한다.
- 범위, 데이터, 상호작용, 경계 조건을 검토했으며 구현을 막는 모호성은 없다.

## 실행 오류 수정 명세 (2026-11-11)

현재 Cargo.toml은 로컬 패치 없이 배포된 GPUI 0.2.2를 사용한다. 사용자가 변경한 의존성 설정을 유지한다.
- FR-007: 기존 기본 화면을 유지하면서 표준 GPUI 0.2.2로 컴파일 및 실행할 수 있어야 한다.
- SC-004: cargo check와 cargo test가 통과하고 실행 시 창 생성 과정에서 오류가 없어야 한다.
- 명확화: 실행 오류는 직접 재현된 E0599 두 건으로 범위가 명확하며 추가 질문이 필요하지 않다.

## 프로젝트 바 개선 명세

- FR-008: 프로젝트 바의 로고와 브랜드 문구를 제거한다.
- FR-009: 각 프로젝트 탭 오른쪽에 × 닫기 버튼을 배치하고 해당 탭만 닫는다. 닫기 클릭은 탭 선택으로 전파하지 않는다.
- FR-010: 선택된 탭의 청록색 강조선을 위쪽에 배치한다.
- FR-011: 프로젝트 바 오른쪽 끝에 + 버튼을 고정한다. 기존 데모 범위에 맞춰 클릭 시 프로젝트 열기 연결 예정 안내를 표시한다.
- SC-005: 탭을 닫아도 나머지 탭의 순서와 선택이 유지되며, 선택 탭을 닫으면 오른쪽 이웃 또는 마지막 왼쪽 탭이 선택된다.
- SC-006: 마지막 탭을 닫으면 빈 작업 공간과 + 버튼을 표시하며 오류가 발생하지 않는다.
- 명확화: 이번 요청은 프로젝트 바 디자인 개선이다. +의 실제 저장소 열기는 기존 미연결 데모 범위를 유지한다. 선택/비선택/마지막 탭 닫기 동작은 위 기준으로 정의했다.

## Windows 커스텀 제목 표시줄 명세

- FR-012: Windows 기본 제목 표시줄을 숨기고 프로젝트 탭바와 동일한 배경색의 커스텀 제목 표시줄을 탭바 위에 표시한다.
- FR-013: 제목 표시줄은 앱 이름과 최소화, 최대화/복원, 닫기 버튼을 제공한다. 제목 영역 드래그로 창을 이동하고 더블클릭으로 최대화/복원할 수 있어야 한다.
- SC-007: Windows 제목 표시줄과 프로젝트 탭바는 같은 색상이며 기존 기본 제목 표시줄이 중복 노출되지 않는다.
- SC-008: 창 이동, 최소화, 최대화/복원, 닫기와 기존 탭 동작을 유지한다.
- 명확화: 제목 표시줄은 기존처럼 탭바 위의 별도 행으로 유지하며 배경색만 동일하게 맞춘다. 프로젝트 바에는 로고를 다시 추가하지 않는다. Windows만 변경하고 다른 플랫폼의 기본 제목 표시줄은 유지한다.

## 제목 버튼 및 프로젝트 바 밀도 개선 명세

- FR-014: Windows 창 제어 버튼은 일반 문자 기호 대신 Windows 전용 창 제어 아이콘을 사용하고 균일한 크기와 중앙 정렬을 적용한다. 기존 네이티브 제어 영역과 동작을 유지한다.
- FR-015: 프로젝트 바 높이를 51px에서 36px로 줄이고 닫기 및 추가 버튼도 이에 맞게 조정한다. 위쪽 선택선과 오른쪽 고정 +는 유지한다.
- SC-009: 최소화/최대화/복원/닫기 아이콘은 Windows 아이콘 글꼴로 같은 크기에 표시되며 최대화 상태에 따라 복원 기호로 전환된다.
- SC-010: 프로젝트 바는 36px이며 텍스트와 닫기 버튼이 세로 중앙에 배치된다.
- 명확화: 자연스럽지 않은 버튼은 현재 일반 문자(−/□/❐/×)의 서로 다른 자형과 큰 16px 크기를 우선 개선한다. 프로젝트 바는 요청 취지에 맞춰 36px로 압축한다. 시스템 동작과 테마는 유지한다.
- FR-016: 프로젝트 바 위쪽에 1px 구분선 한 줄을 배치하여 같은 배경의 타이틀바와 구분한다. 기존 탭 선택 강조선은 유지한다.

## 프로젝트 탭바 정렬 보정 명세

- FR-017: 프로젝트 탭바 높이를 기존 36px에서 42px로 변경한다. 이는 FR-015와 SC-010의 기존 높이 기준을 대체한다.
- FR-018: 비선택 탭은 위쪽 강조선용 테두리 공간 없이 배경이 상단까지 채워져야 한다. 선택 탭만 위쪽 2px 강조선을 표시하고 텍스트 위치는 선택 여부와 무관하게 동일하다.
- FR-019: 오른쪽 고정 + 버튼의 기호 중심을 탭바의 세로 중심에 맞춘다.
- SC-011: 42px 탭바에서 선택 변경 시 텍스트가 움직이지 않고 비선택 탭 호버 배경이 상단까지 채워지며 + 기호가 중앙에 표시된다.
- 명확화: 기존 타이틀바 경계선과 탭 선택색은 유지한다. 요청은 시각 정렬 변경이며 탭 동작은 그대로 둔다.

## 프로젝트 탭 닫기 버튼 호버 표시 명세

- 사용자 이야기 3 (P1): 사용자는 프로젝트 탭에 마우스를 올렸을 때만 해당 탭의 × 닫기 버튼을 본다.
- FR-020: 선택 여부와 관계없이 마우스가 올라간 프로젝트 탭의 닫기 버튼만 표시하고, 탭을 벗어나면 숨긴다. FR-009의 닫기 동작은 유지한다.
- FR-021: 닫기 버튼이 숨겨져도 공간을 유지하여 탭 너비와 글자 위치가 바뀌지 않아야 한다.
- SC-012: 탭 밖에서는 모든 ×가 숨겨지고, 탭 사이 이동 시 해당 탭의 ×만 보이며 버튼으로 이동해 클릭하면 해당 탭만 닫힌다. 마지막 탭 닫기와 선택 유지 동작도 유지된다.
- 수용 시나리오: 선택/비선택 탭 각각 진입 → × 표시 → 버튼으로 이동 → 표시 유지 → 클릭 → 해당 탭 닫힘을 확인한다. 탭 밖에서는 ×가 숨겨지고 배치는 유지된다.
- 명확화: 호버 대상은 프로젝트 탭 전체이며 선택 탭에도 숨김을 적용한다. 기존 빈 상태와 + 버튼을 유지한다. 경계 조건과 범위를 검토했으며 추가 질문이 필요한 모호성은 없다.

## 프로젝트 탭 경계와 활성 닫기 표시

- FR-022: 모든 프로젝트 탭과 시작 탭 오른쪽에 1px 구분선을 표시한다. 활성 탭의 닫기 버튼은 상시 표시하고 비활성 탭은 호버 때만 표시한다. 숨김 전후 공간과 클릭 전파 방지는 유지한다. FR-020·SC-012의 활성 탭 호버 전용 조건을 대체한다.
- SC-013: 선택 전환 후에도 모든 탭의 오른쪽 경계가 유지되고 활성 탭 닫기는 포인터 위치와 무관하게 표시된다. 비활성 탭은 호버 때만 표시하고 닫기 및 고정 + 동작을 유지한다.
- 복원 근거: 현재 src/ui.rs의 tabs()와 기존 T032 설명에서 확인한 계약이다. 손상된 원문의 정확한 문장이나 과거 수동 검증 결과를 복원한 것으로 간주하지 않는다.

## 패널 헤더 높이 축소 명세

- 사용자 이야기 4 (P1): 사용자는 저장소, 커밋 기록, 변경 파일, 커밋 상세 패널에서 더 낮은 헤더로 본문 공간을 확보한다.
- FR-023: 네 패널 헤더의 높이를 48px에서 36px로 줄이고 제목, 배지, 가로 여백, 아래 구분선 및 세로 중앙 정렬을 유지한다.
- SC-014: 네 패널에 같은 36px 높이를 적용하고 제목과 배지가 잘리지 않으며 본문 영역은 확보된 12px만큼 늘어난다.
- 수용 시나리오: 기본 화면의 네 패널 헤더가 모두 낮아지고 제목과 배지가 중앙에 표시된다. 커밋 선택과 상세 갱신은 기존대로 작동한다.
- 명확화: 요청 대상은 공통 패널 헤더 전체이며 높이는 36px로 정한다. 프로젝트 탭, 툴바와 본문 행 높이는 변경하지 않는다. 구현을 막는 모호성은 없다.
