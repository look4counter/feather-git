# 사용자 인터페이스 계약

- 실행: `cargo run -- [저장소 경로]...`. 인자가 없으면 빈 페이지 탭을 표시한다.
- 상단: 44px 높이의 탭 바. 전체 높이 사각 탭과 중앙 24px 닫기 버튼, 맨 오른쪽에 고정된 +만 제공한다. 로고·앱 이름·새로고침·저장소 열기 버튼은 없다.
- +를 클릭할 때마다 새 빈 탭을 추가하고 활성화한다. 빈 본문에는 패널·상태줄·안내·대화상자를 표시하지 않는다. 마지막 탭을 닫으면 빈 탭을 하나 만든다.
- 좌상: 브랜치 목록 및 Local/Remote/Stash/Tag 탭. 선택은 탐색만 수행한다.
- 우상: 커밋 제목, 해시, 작성자와 시각. 모든 참조에서 도달 가능한 전체 커밋 수를 표시한다.
- 좌하: Stage/History. Stage는 스테이징과 작업 디렉터리 변경을 별도 표시한다.
- 우하: 행 번호가 있는 통합 Diff. 추가 녹색, 삭제 붉은색, 헤더 청록색.
- 하단: 저장소 탭에만 경로, 읽기 전용 상태, 로딩 또는 오류 안내.
- 최소 창 크기: 1000×680. 각 내용 영역은 독립적으로 스크롤한다.
- 오류가 발생해도 탭 닫기 및 새 빈 탭 추가가 가능하다.
- 본문 외곽과 네 패널 사이에 여백과 둥근 모서리가 없다. 콘텐츠 내부 여백은 유지한다.
- 공통 세로·가로 경계선은 1px이며 포인터 판정 영역은 각각 7px다. 방향별 크기 조절 커서를 제공한다.
- 세로 경계선 드래그는 좌우 열 너비를, 가로 경계선 드래그는 상하 행 높이를 바꾼다. 마우스를 놓으면 종료한다.
- 최소 크기는 좌측 260px, 우측 360px, 위·아래 180px이다. 작은 창에서는 가용 공간에 맞춰 축소한다. 비율은 프로젝트 전환 중 유지한다.

## 새 탭 시작 계약

세 선택지에서 새 경로·기존 폴더·URL과 새 경로를 각각 받는다. 취소는 상태를 유지하고 실패는 해당 탭에 표시한다. 진행 중 중복 요청은 무시한다. 성공은 동일 탭에 적용하며 닫힌 탭은 복원하지 않는다.

## 커밋 그리드와 상세 계약

Graph·Description·Author·Date·Hash 헤더와 24px 행을 정렬한다. 그래프 클릭도 커밋 행 선택이다. History 상단 커밋상세는 파일 스크롤에 관계없이 보이며 Stage에서는 숨긴다. 커밋 선택 시 상세를 기본 표시하고 파일 선택 시 Diff로 전환한다. 상세에는 줄 번호나 Diff 색상을 붙이지 않으며 조회 중·빈 커밋·실패를 구분한다.

## 전체 이력 그리드 계약

브랜치 선택은 필터링 대신 해당 브랜치 끝 커밋을 선택한다. Description은 브랜치명 다음에 제목을 표시한다. Date는 커밋 시간대 기준 날짜와 시분이다. 그리드는 패널 폭 100%를 사용하고 이웃 열 경계를 드래그하여 전체 폭을 유지한다. 고정 헤더와 가상 행은 동일 열 배열을 사용하며 가시 행만 생성한다. 커밋 선택은 상세와 파일만 갱신한다.

## 공통 스크롤 계약

히스토리·브랜치·파일·Diff는 같은 스크롤바를 쓰며 Diff에는 가로 바도 제공한다. 히스토리 아래 끝에서 200개를 추가하고 더 이상 없으면 멈춘다. 개수/첫 부모 라벨은 없고 체크아웃 표식은 ●다. 커밋상세는 파일 스크롤 위 고정 항목이며 메시지 자체는 Diff의 가상 목록에 표시한다.

## 콘텐츠 중심 표시 계약

네 영역의 제목 헤더는 없고 탭·그리드 컬럼과 파일 경로만 유지한다. 스크롤이 필요할 때만 같은 공통 바를 표시한다. 목록과 상세 고정 행은 폭 100%·높이 24px이다. 추가 로딩 진행 표시는 그리드 안의 오버레이다. 상세 상위 해시는 라벨과 한 줄이고 시간대 및 메시지 라벨은 표시하지 않는다.

## 복구와 모달 계약

새 탭에는 최근 저장소 이름·일반 경로와 열기·목록에서 제거·저장소 삭제를 제공한다. 삭제는 앱 내 확인을 거쳐 휴지통 이동하며 실패 시 목록과 탭을 유지한다. 도움말과 진행은 같은 창 안의 중앙 오버레이이다. 진행 중 배경과 전역 단축키를 차단하며 실패 시 종료하고 오류를 보여준다. 입력 중 f와 ?는 입력 문자로 처리한다. fetch는 작업 트리를 변경하지 않는다.

## 목록 포커스·읽기 전용 선택 계약

클릭한 브랜치·파일·커밋 목록의 ↑/↓는 클릭과 동일한 선택 조회를 수행하며 파일 그룹 라벨은 건너뛴다. 커밋상세와 Diff 본문은 클릭 커서·드래그·Shift 방향키·Ctrl+A·Ctrl+C를 지원한다. 복사는 줄번호/변경 표식 없이 원문 텍스트·탭·빈 줄을 보존한다. 입력/삭제/붙여넣기는 내용을 바꾸지 않는다. 데이터 선택 변경은 텍스트 범위를 초기화한다.

## 히스토리 진행과 최소 도움말 계약

Progress는 히스토리 최초/재조회·추가 페이지·브랜치 탐색에만 나타난다. 상세/Diff 선택은 전역 입력을 막지 않는다. 도움말에는 `[단축키]`와 `f - 패치`만 보이고 Esc/바깥 클릭으로 닫는다. 브랜치는 미로딩 대상까지 200개 페이지를 누적하고 발견한 행으로 이동한다.


## Stage 상태·원격 HEAD·새로고침 계약

origin/HEAD와 origin/main은 같은 커밋을 가리켜도 다른 배지이다. Stage에서는 작업 디렉터리 헤더가 없고 unstaged 상태는 빨강 `??`/` M`/` D`, staged 상태는 초록 `A `/`M `/`D `이다. staged 파일명도 초록이다. Space는 선택한 unstaged 파일을 실제 스테이징하며 History/텍스트/입력 필드에서는 실행하지 않는다. F5는 로컬 새로고침이고 도움말에 `F5 - 새로고침`을 표시한다. f는 원격 fetch이다.


## Stage 양방향 전환 계약

Stage 목록에는 그룹 헤더가 없다. Space로 선택 경로를 stage/unstage하고 기존 두 칸 표기와 색상을 갱신한다. unstage는 작업 파일 내용을 유지하며 다른 파일의 인덱스에 영향을 주지 않는다. 반대 상태 행이 남으면 선택을 유지하고 변경 자체가 사라지면 Diff를 비운다.


## 지연 탭과 커밋 오버레이 계약

시작 시 활성 탭만 조회하고 나머지는 처음 클릭할 때 읽는다. stage 전환은 경로 정렬을 바꾸지 않는다. History의 커밋상세 행은 파일 행과 같은 글자 크기이다. 도움말에 `c - 커밋`을 표시한다. c로 열린 메시지 오버레이는 Ctrl+Enter/Ctrl+S로 제출하며 하단에 `Ctrl+Enter 또는 Ctrl+S`를 표시한다. 빈 메시지/실패는 오버레이 안에서 알리고 메시지를 보존한다. 실행 중 편집·중복·취소는 막고 성공 시 닫아 갱신한다.


## 작은 제목과 커밋 입력 스크롤 계약

커밋과 `[단축키]` 제목은 본문 크기이다. staged가 없으면 c는 팝업을 열지 않는다. 커밋은 Ctrl+S 또는 하단 우측 커밋 버튼, 취소는 Esc 또는 닫기 버튼이며 Ctrl+Enter로 제출하지 않는다. 하단 안내는 `커밋 : ctrl + s, 취소 : esc`이다. 긴 메시지는 입력 영역 안에서만 스크롤하고 제목과 하단은 고정한다.


## 작성자 표시와 Stage 다중 선택 계약

Author는 `이름 <메일주소>`이다. Stage에서 Shift는 범위, Ctrl은 개별 선택 추가/해제, Ctrl+Shift는 범위 추가이다. Space는 선택 전체를 반전하고 같은 경로 양쪽 행 선택은 stage 우선이다. 선택 행을 모두 강조하고 대표 행의 Diff를 보여준다. 상태 변경 후 실제 남은 행으로 선택을 복원한다.

## 선택 파일 폐기 계약

d는 Stage의 선택을 대상으로 전체 변경 폐기 확인창을 연다. 대상 목록과 신규 파일 삭제를 알리고 확인 후에만 HEAD 복원 또는 신규 파일 삭제를 수행한다. Esc/취소/바깥 클릭은 실행 전에 취소하며 실행 중에는 막는다. 다른 경로를 변경하거나 디렉터리를 재귀 삭제하지 않는다.

도움말의 p는 fast-forward 풀, shift+p는 일반 푸시이다. 입력/모달에서는 실행하지 않고 중복 요청은 무시한다. 하단에 진행 상태를 표시하고 성공 후 해당 저장소를 재조회한다.

커밋 팝업은 버튼 없이 `커밋 : ctrl + s, 커밋 후 푸시 : ctrl + p, 취소 : esc`를 표시한다. Ctrl+P의 push 실패는 이미 만들어진 로컬 커밋을 실패로 되돌리거나 재생성하지 않고 별도 오류로 알린다.


## Ctrl+A와 폐기 확인 키 계약

Stage 목록의 Ctrl+A는 모든 행을 선택하고 기존 대표 Diff를 유지한다. 폐기 창에는 개별 파일/버튼이 없고 `폐기 : ctrl + s, 취소 : esc`를 표시한다. Ctrl+S는 그 확인창 안에서만 폐기하고 Esc는 실행 전에 취소한다.

하단 오류는 약 3초 뒤 일반 상태로 돌아가며 새 오류가 오면 시간을 다시 센다. 확인창 내부 오류는 수정/재시도까지 유지한다.

## 포커스와 도움말 표시 계약

목록 선택은 활성 청록색/비활성 회색으로 구분하고 호버로 덮지 않는다. 도움말은 공통·목록·Stage 파일·텍스트·확인창 조건을 구분하며 키 표기를 소문자로 쓴다. 새로고침은 f5와 ctrl+r가 동일하다.

## 새 탭 최근 저장소 계약

왼쪽 신규 저장소 작업과 오른쪽 최근 목록은 좌우로 표시한다. 최근 목록은 높이 40px의 한 줄 가상 행과 독립 수직 스크롤이다. 휴지통 아이콘은 열기를 전파하지 않고 목록 제거/저장소 삭제 선택창을 연다. 제거는 기록만 지우고 삭제는 추가 확인을 거친다. esc/취소는 변경 없이 닫는다.

History 커밋상세 행은 일반 파일 행과 같은 활성/비활성 선택색 및 호버 계약을 따른다. 선택 상태는 포커스 이동으로 해제하지 않는다.

최근 저장소와 생성·폴더 열기·복제 성공은 작업을 시작한 빈 탭만 소비한다. 실패/취소는 빈 탭을 유지한다. 비동기 완료는 다른 현재 선택을 빼앗지 않으며 닫힌 시작 탭을 다시 만들지 않는다.

도움말 표시 계약은 공통→브랜치→커밋히스토리→파일목록→텍스트뷰어 순서다. 각 키는 한 줄이고 확인창 전용·기존 diff/커밋상세 제목·이전/다음 행 선택 안내는 제외한다. 새 요구는 이전 도움말 그룹 계약을 대체하며 실제 단축키 동작은 보존한다.

## 설정 오버레이 계약

두 화면의 우측 하단 도움말 옆 `f12 - 세팅`과 f12로 연다. 사용자/원격 탭과 닫기를 제공하며 esc는 IME 조합 중이 아니면 닫고 ctrl+s는 사용자 설정 저장이다. 사용자 탭에서 전역 선택·이름·이메일을 명시적으로 저장한다. 전역 사용 시 현재 저장소의 개별 사용자 키는 제거한다. 새 탭에서는 전역만 가능하다. 인증은 HTTPS 주소와 GCM 상태 확인·브라우저 로그인·로그아웃·Git 연결 버튼으로 관리하며 토큰을 표시하지 않는다. 원격 탭은 이름·fetch/push 주소·브랜치/추적을 읽기 전용으로 표시한다. 빈 상태·진행·실패를 구분하고 오버레이가 열리면 기존 섹션 키는 실행하지 않는다.

## 브랜치 조작과 태그 표시 계약

커밋히스토리 포커스의 b는 선택 커밋 기준 이름 입력창을 연다. 이름 확인 후 생성만 하고 HEAD는 유지한다. Local 더블클릭은 그 브랜치를 체크아웃하며 Remote는 같은 이름 Local 재사용 또는 추적 생성/체크아웃 확인창을 연다. 명시적 확인 전에는 원격 대응 로컬을 생성하지 않는다. 확인창은 enter/ctrl+s/버튼 확인과 esc/취소를 지원하며 실행 중 중복/닫기를 차단한다. 실패는 현재 상태를 재조회하고 작업 변경을 강제로 삭제하지 않는다. Description은 청록 브랜치 배지와 보라 태그 배지 및 기존 제목을 표시한다.

## 스태시 확인

s로 확인창을 연다. enter·확인 버튼은 저장, esc·취소 버튼·바깥 클릭은 취소한다. 실행 중 닫기를 막는다. 입력·다른 모달에서는 실행하지 않는다. 도움말은 `s - 스태시`다.

## 스태시 목록과 복원

저장 후 현재 참조 탭을 유지한 채 목록을 갱신한다. Stash 더블클릭은 stage 상태 포함 복원이며 항목은 삭제하지 않는다. 진행 중 입력을 차단하고 실패는 오류로 표시한다. 성공 시 Stage 파일 화면을 표시한다.

## 이름 입력·삭제

s 확인창에서 이름을 입력해야 저장 가능하다. 한글 조합을 완료한 후 enter로 저장한다. Stash 목록 선택 후 d는 이름이 표시된 삭제 확인창이며 enter·확인 버튼으로 삭제한다. 취소·esc·바깥 클릭은 저장소를 변경하지 않는다. 파일 목록 d 동작은 유지한다.

## 참조 작업·설정 표시

참조 목록 d는 선택 종류에 맞는 삭제 확인이다. History의 t는 태그명 입력이다. 모달과 입력 중 전역 단축키를 실행하지 않는다. 전역 설정 사용 문구는 고정하고 하단 설명·설정 저장 버튼·GCM 정보는 표시하지 않는다. ctrl+s 저장은 유지한다.

Remote d 확인은 로컬 추적 참조 삭제, Shift+d 확인은 서버 브랜치 포함 삭제라고 명시한다.

체크아웃된 HEAD의 그래프 노드는 중앙이 빈 굵은 원이며 행 선택과 독립적으로 표시한다.

## 원격 생성·커밋 체크아웃

Local u는 원격명 입력 확인창이며 기본값 origin을 편집할 수 있다. Tag/History 더블클릭은 detached HEAD 전환이다. 단일 클릭은 조회다. 단일 행 입력은 부모 안에서 클리핑하고 HEAD 그래프 중앙은 흰색·테두리는 2px이다.

## 히스토리 브랜치 우선

히스토리 더블클릭에서 브랜치가 없으면 detached, 하나면 브랜치 전환, 여럿이면 Local/Remote 이름이 구분된 선택창을 연다. 선택 후 확인 또는 enter로 전환하고 취소는 무변경이다. Remote 선택 시 필요하면 로컬 추적을 생성한다.

## 즉시 브랜치 선택

동일 이름 Local이 있으면 Remote 후보를 제외한다. 후보 하나는 바로 체크아웃한다. 복수 후보는 버튼 없는 선택창에서 브랜치 클릭 즉시 적용한다. Esc·바깥 클릭은 취소다.

## 공통 팝업

모든 모달은 13px 제목 영역·스크롤 본문·필요한 경우만 하단 영역을 갖는다. 설정 닫기는 제목 오른쪽이다. 브랜치 선택과 진행에는 확인/취소 하단이 없다. 기존 키·클릭 규칙은 유지한다.

## 현재 브랜치 재선택

선택창은 설명 없이 후보 목록을 보여준다. 현재 브랜치 클릭은 선택창을 유지하며 아무 작업도 시작하지 않는다. 현재 Local 더블클릭과 단일 현재 후보도 전환·재조회를 생략한다.

## 라이트 테마

배경은 옅은 회색, 패널·입력은 흰색, 텍스트는 짙은 색이다. 선택·hover·오류·파일 상태·Diff·태그·그래프는 밝은 배경용 팔레트로 구분한다. HEAD 중앙은 흰색이다. 기능과 레이아웃은 유지한다.

## 탭과 배지

앱 탭바 상단과 브랜치/파일 탭바 하단은 경계선으로 구분한다. 브랜치/태그 배지는 11px 글자와 벡터 아이콘이며 Remote는 붉은 계열이다. 그래프 노드는 여백 안에서 그린다.

## 히스토리·상세 표시

태그가 브랜치보다 먼저 나오고 선택 강조는 파랑이다. 본문 컬럼 선은 없고 헤더 선만 남는다. 커밋상세는 작은 글자와 커밋 아이콘이며 메타데이터 라벨만 굵게 표시한다. 작성시간·커밋시간은 붙여 쓴다.

## 강조·배지·목록

선택 배경은 파랑, 강조 글자는 녹색이다. 배지에는 테두리가 있고 HEAD는 지름 15px, 목록 아이콘은 18px이다.

## 현재 브랜치 배지 원

배지 안의 원만 16px이고 이름은 11px다. 그래프 HEAD는 원래 지름 11px다.

## 원 정렬

브랜치/태그 배지는 18px로 고정한다. 현재 원은 폰트 문자 대신 중앙 정렬된 아이콘이며 목록 행은 24px를 유지한다.

## 원격 HEAD 숨김

Remote HEAD는 브랜치 목록/히스토리 배지에 표시하지 않으며 실제 참조는 유지한다.

## 선명한 그래프

DPI에 맞춘 선 두께와 좌표를 사용하며 곡선 안티앨리어싱과 기존 조작은 유지한다.

## 상세 굵기와 빈 안내

라벨은 굵게, 내용은 일반 굵기다. 파일 미선택 시 빈 헤더 없이 상단 8px 여백으로 안내한다.

## 뷰어 밖 선택

텍스트 드래그 시작 후 범위를 벗어나도 선택이 이어지고 바깥 방향으로 스크롤한다. 왼쪽 버튼 해제 시 종료한다.

## 단축키 배지

ctrl + s는 각각의 키 배지 사이에 +로 표시한다. 설명은 일반 글자이며 클릭/입력 동작은 유지한다.

## 생성 팝업 표시

13px 본문/입력·기본 해제 원격 생성 체크박스·우측 하단 확인만 표시한다. Esc와 바깥 클릭으로 취소한다. History/Stage 파일명은 14px다.

## 체크박스·입력

체크박스는 항상 같은 크기다. 새 브랜치 체크아웃은 선택 옵션이다. 단일 행 텍스트는 중앙이며 입력 밖 드래그도 유지된다.

## 체크 항목 간격

체크 항목은 빈 라벨 없이 상하 4px 패딩을 사용한다.

## 입력 이동

Tab은 다음 입력, Shift+Tab은 이전 입력으로 순환한다. 체크박스 Space 전환과 포커스 표시를 제공하며 진행/IME 중에는 이동하지 않는다.

## Space 한 번 전환

Space를 눌렀다 놓으면 체크 상태가 한 번만 바뀐다. 마우스 클릭과 Tab 이동은 유지한다.

## 숫자 포커스

1 브랜치·2 히스토리·3 파일목록·4 뷰어이며 입력/모달에서는 전역 실행하지 않는다.

## 옵션·o·태그

체크 옵션은 복원된다. 브랜치/히스토리 o는 더블클릭과 같고 태그 입력은 이름과 우측 확인만 표시한다. 생성 후 선택행은 유지한다.

## 탐색 키

i 위·j 왼쪽·k 아래·l 오른쪽이다. 브랜치 선택은 목록만 바꾸고 Space가 위치 탐색이다. 선택창 숫자는 즉시 체크아웃이다.

## 체크아웃 포커스

체크아웃 후 시작 섹션과 탭을 유지한다. 후보는 숫자와 브랜치명만 표시한다.

## Reset 팝업

x는 선택 커밋 reset이며 soft/mixed/hard selectbox와 우측 확인을 제공한다. 선택만으로 실행하지 않고 모드 설명을 표시한다. 체크아웃은 선택행을 유지한다.


## 히스토리 작업 계약

x → Reset 라디오 1/2/3, v → Revert no commit, m → Merge 히스토리, r → Rebase 히스토리. 입력/다른 섹션에서는 실행하지 않는다. 목록 클릭/방향키/ijkl은 팝업 내부 대상만 바꾼다. 확인은 우측 하단, Esc는 취소한다. 성공/실패 후 재조회하고 원래 선택과 포커스를 유지한다.


## Merge·Rebase 확인 계약

m/r → 본 히스토리 선택 커밋을 고정한 확인 팝업 → 우측 하단 확인으로 실행. 팝업에서 대상을 재선택하지 않는다. Esc 취소와 기존 포커스 복원을 유지한다.


## 단축키 설정 화면 계약

도움말 옆 버튼과 기본 F11로 연다. 공통/브랜치/커밋히스토리/파일목록/뷰어 순서로 기능·단축키1·단축키2를 표시한다. 슬롯 클릭 후 키 조합을 누르면 즉시 적용한다. 슬롯별 지우기와 전체 기본값 복원을 제공한다. Esc로 등록을 취소하거나 화면을 닫는다. 확인창 제어는 공통 영역에 창 종류를 구분하여 표시한다. 도움말은 현재 설정을 읽어 같은 표로 표시한다.


## 방향 선택 확장 표시 계약

공통 표에서 select-up, select-left, select-down, select-right를 표시하지 않는다. 기본 이동 항목과 실제 Shift 선택 확장 동작은 유지한다. 설정과 도움말은 같은 필터를 사용한다.


## 확인창 공통 키 계약

공통 표에 확인·취소·다음입력·이전입력만 표시하고 창 이름이 붙은 중복 항목은 제거한다. 키 재정의는 각 창에서 같은 의미로 실행한다. 커밋 본문의 줄바꿈은 Shift+Enter로 수행한다. 등록 중 Escape는 등록 취소다.


## 커밋 팝업 배치 계약

본문은 커밋메시지 라벨 → 입력창 → 커밋 후 푸시 체크박스 순이다. footer 우측에는 확인 버튼 하나만 표시하며 단축키를 붙이지 않는다. 확인 키는 체크 상태대로 실행하고 취소 키는 닫는다. 체크는 클릭 또는 포커스 후 Space로 변경하고 실행하지 않는다.


## 설정 탭 표시 계약

편집 화면에 공통·브랜치·커밋히스토리·파일목록·뷰어 탭을 표시한다. 활성 탭만 기능/단축키1/단축키2 표로 렌더링한다. 상단 사용 안내는 없다. 도움말은 전체 목록을 유지한다. 커밋히스토리의 세 항목은 Add Branch, Add Tag, Checkout이다.


## 히스토리 작업 표시 계약

Revert는 no commit 체크와 확인을, Merge·Rebase는 작업 방향 설명과 확인을 표시한다. 세 창 모두 대상 커밋 행은 표시하지 않으며 기존 선택 커밋을 대상으로 실행한다.


## 단축키 일괄 승인 계약

편집 표는 전 탭 임시 설정을 표시하고 회색 헤더로 제목을 구분한다. footer 우측에 기본값 복원·확인 순서로 표시한다. 복원은 임시 상태만 바꾸고 확인만 저장·적용한다. 취소/바깥 클릭은 폐기하며 등록 중 키 입력은 승인하지 않는다. 오류 시 팝업과 편집 내용을 유지한다.


## 설정 헤더 제거 계약

단축키 설정 각 탭에는 기능·단축키1·단축키2 제목 행이 없고 본문부터 표시한다. 셀 가로 여백과 열 너비는 기존대로이며 편집·승인·복원 동작을 유지한다. 도움말은 기존 헤더를 유지한다.


## 단축키 설정 높이 계약

설정 팝업 높이는 640픽셀과 화면 높이에서 64픽셀을 뺀 값 중 작은 값이다. 모든 탭에서 같고 항목 수에 따라 변하지 않는다. 본문만 스크롤하며 footer는 하단에 유지한다.


## 공통 방향·전환 표시 계약

공통에는 방향키 위·아래·왼쪽·오른쪽과 입력전환 항목만 표시하며 Reset 전용 방향·창별 전환 중복은 없다. 브랜치/파일목록의 별도 Space 행은 유지한다. 입력전환은 해당 컨트롤 포커스에서만 실행하며 편집 문자 입력은 그대로다.


## 커밋·스태시 키 범위 계약

파일목록 설정에 스태시·커밋을 표시한다. 두 키는 파일목록 포커스이면서 Stage일 때만 실행한다. History 파일목록과 다른 영역은 제외한다. 변경 승인은 기존 확인 버튼으로 수행한다.


## 하위 분류·숨김 계약

해당 설정 탭에서 각 실제 화면 탭 이름을 소제목으로 표시한다. 같은 기능을 바꾼 값은 모든 분류에서 공유하고 확인 전에는 활성화하지 않는다. History처럼 전용 키가 없는 분류는 등록된 단축키 없음으로 표시한다. 후보와 Reset 숫자 선택 행은 표시하지 않는다.


## 선택 키 배지 계약

후보 번호와 Reset 번호는 짧은 둥근 배지 안에 표시한다. 후보 이름/라디오 모드 이름과 나란히 배치하고 숫자 선택·클릭은 기존처럼 처리한다. 첫 열 개 이후 후보에는 배지를 표시하지 않는다.


## 설정 슬롯 배지 계약

각 단축키 슬롯은 짧은 둥근 배지로 표시하며 미지정·키 입력 대기 상태도 같은 형태다. 배지 클릭은 기존 등록을 시작하고 지우기 및 확인 승인은 그대로 동작한다.


## 브랜치 삭제 표시 계약

제목은 브랜치 삭제, 본문은 선택한 브랜치 또는 태그를 삭제할까요?와 원격 브랜치 삭제 체크 순이다. 이름 행과 취소 버튼은 없고 우측 확인만 있다. Remote는 체크 가능하고 다른 참조는 비활성이며 공통 취소는 유지한다.


## 종류별 삭제 계약

Local 브랜치 삭제: 선택 로컬 안내·연결 원격 또는 없음·원격 브랜치 삭제 체크. Remote 브랜치 삭제: 서버 삭제 안내·연결 로컬 목록 또는 없음·로컬 브랜치 삭제 체크. 연결 없는 체크는 비활성이다. Tag 삭제와 Stash 삭제는 체크 없이 확인한다. 모든 삭제 창은 우측 확인·취소 키·바깥 클릭을 제공하고 취소 버튼은 없다. 조회/실행 중에는 중복 조작을 막고 원격 성공 후 로컬 실패는 부분 완료로 표시한다.


## 브랜치 푸시 표시·실행 계약

Local 설정의 기능명과 팝업 제목은 브랜치 푸시다. 기본 Shift+P이며 공통 푸시와 겹칠 때 Local 브랜치 푸시를 실행한다. 팝업에는 원격 이름 입력과 확인만 표시하고 브랜치명·설명·취소 버튼은 없다. 기존 취소 키/바깥 클릭은 유지한다.


## 복원된 브랜치 푸시 키 계약

Local 브랜치 푸시 기본 키는 u이며 기본 Shift+P는 공통 푸시다. 팝업 제목과 입력 구성 및 브랜치 키 우선은 유지한다.
## 팝업 드래그 계약 (US86)

왼쪽 버튼의 내부→내부, 내부→배경, 배경→내부 동작은 배경 닫기를 실행하지 않는다. 배경→배경만 기존 닫기 조건을 적용한다. 입력 선택·내부 버튼·취소 키·진행 중 보호는 유지한다.

## 커밋 줄바꿈 계약 (US87)

메시지 포커스에서 Shift+Enter는 기존 편집기로 전달하며 확인 명령으로 바꾸지 않는다. 진행 중 입력은 차단한다. 추가 수정키·다른 포커스에는 기존 단축키 정책을 적용한다.

## 파일 트리 계약 (US88)

백틱 기본 키는 파일목록 포커스에만 적용하며 Stage·History에 제공한다. 토글·폴더 접힘은 저장소를 변경하지 않는다. 폴더 클릭은 접힘만 바꾸며 파일 클릭은 기존 원본 변경 항목을 선택한다. 위/아래와 Shift 범위는 가시 파일 순서, 전체 선택은 모든 변경 파일에 적용한다.

## 폴더 일괄 Stage 계약 (US89)

트리는 항상 펼치며 폴더 클릭/방향키는 폴더를 선택한다. Stage의 기존 Space 명령은 선택 폴더의 모든 깊이 하위 변경을 전체 Stage(미스테이징 존재) 또는 전체 Unstage(모두 Stage)한다. History는 실행하지 않는다. 파일·전체 선택/탭/모드 전환은 폴더 대상을 해제하고 작업 후에는 유지한다. US88의 접힘 계약을 대체한다.

## Local 원격 연결 계약 (US90)

Local r은 원격 브랜치 연결 창을 열고 기존 u 푸시는 제거한다. 목록 선택은 변경하지 않으며 확인만 선택 Local의 upstream을 갱신한다. 현재 연결을 기본 선택하고 클릭/공통 방향키·확인/취소를 지원한다. 빈 목록은 Fetch 안내를 표시하며 실행하지 않는다. 진행 중 중복 실행과 닫기를 제한하고 취소/바깥 클릭은 설정을 바꾸지 않는다.

## 연결 라디오 계약 (US91)

Local 브랜치명 행 없이 원격 라디오 목록을 표시한다. 클릭/위/아래와 입력전환 포커스를 지원하고 Space는 선택을 유지한다. 확인만 연결한다. 30px 행 최대 8개, 초과 항목은 내부 스크롤과 선택 행 자동 노출을 제공한다. 작은 창에서는 가용 높이로 제한한다.

## Merge 해결 계약 (US92)

상단 Merge 진행/충돌 수와 파일목록 이동·병합 완료·병합 중단을 표시한다. Stage 충돌 행은 충돌 배지와 작업 결과 미리보기·외부 수정 후 Space Stage 안내를 제공한다. 완료는 미해결 0개일 때만 확인 실행하며 중단은 변경 손실/복원 한계 확인을 거친다. 닫기/취소만으로 Git 작업을 중단하지 않는다. 실행/재조회 중 중복을 막고 오류를 남기며 다른 저장소/대상에 실행하지 않는다.

## Rebase 해결 계약 (US93)

진행 표시줄은 Rebase 단계·커밋·충돌 수와 해결 파일 보기/계속/건너뛰기/중단을 제공한다. 계속은 미해결 0개, 건너뛰기/중단은 내용 손실 확인 후 실행한다. 다음 충돌이면 새 Stage 해결 화면을 유지하며 완전히 끝난 경우에만 표시를 제거한다. 실제 실패는 오류와 재시도를 제공하고 경합/중복을 막는다. Merge의 기존 계약은 유지한다.

## Revert 해결 계약 (US94)

Revert 대상·충돌 수·커밋 여부와 해결 파일 보기/계속/건너뛰기/중단을 표시한다. 미해결이면 계속을 막고 세 동작 모두 확인한다. 커밋 없는 단일 계속은 해결 결과를 Stage로 남긴다. 외부 단일의 시작 옵션이 불명확하면 커밋하지 않기 기본 체크를 확인창에 표시한다. 여러 커밋 no commit 계속은 안내와 함께 상태를 유지한다. 원래 시작 팝업 대신 Stage로 이동하고 다음 일반 충돌도 같은 흐름을 유지한다. 기존 Merge/Rebase 계약은 유지한다.

## Stash 충돌 해결 계약 (US95)

앱 Stash 복원 실패는 복원 결과 확인/미해결 수와 해결 파일 보기·해결 완료·복원 취소를 표시한다. 해결 완료는 미병합 0개에서 확인 후 결과를 유지한다. 복원 취소는 적용 후 해당 경로의 해결 내용을 잃을 수 있음을 확인하고 보관한 상태를 복구한다. 원본 Stash는 삭제하지 않는다. 외부 미병합은 출처를 추측하지 않는 일반 안내와 파일 보기만 제공한다. 백업/잠금/현재 상태 검증 실패는 오류와 백업을 유지한다.

## US96 충돌 선택 계약

Stage 미병합 파일의 충돌 시작 줄에 현재 변경 사용·들어오는 변경 사용·양쪽 모두 사용 버튼을 표시한다. 클릭하면 해당 구간만 즉시 저장하고 미리보기를 갱신한다. 처리 중 중복 실행은 막으며 실패는 기존 오류 영역에 표시한다. Stage는 별도로 Space로 수행한다. 마커 미지원 충돌은 외부 편집 안내를 유지한다.

## US97 부분 Stage·마커 보존 계약

충돌 버튼은 별도 행이고 바로 아래 <<<<<<< HEAD 원문을 가리지 않는다. 일반 미스테이지 텍스트 차이의 각 @@ 헤더에 이 구간 Stage 버튼을 표시한다. 추가/삭제 줄 앞의 체크박스를 클릭하면 그 줄 전체가 선택되며 상단 선택한 줄 Stage로 적용한다. 선택 해제로 체크를 지울 수 있다. 선택 수와 처리 중 비활성 상태를 표시한다. 적용 후 Stage/미스테이지 목록과 미리보기를 갱신하고 선택을 초기화한다. 오류는 기존 오류 영역에 표시한다. 이미 Stage된 쪽·History·미병합은 부분 Stage 대상이 아니다.

## US98 고정 도구 모음·키보드 계약

Stage 미스테이지 DiffViewer에서 기본 Space는 커서의 추가/삭제 줄 체크 토글, Enter는 선택한 줄 Stage다. 단축키 설정과 도움말에서 재지정할 수 있다. 선택 해제 버튼은 없고 구간 Stage·줄 체크박스는 유지한다.

충돌 파일은 상단 스크롤 영역 밖에 현재 대상 구간 표시와 현재 변경 사용·들어오는 변경 사용·양쪽 모두 사용 버튼을 둔다. 커서가 속한 구간에만 적용하며 구간 밖/좌표 없음/커서 없음/처리 중에는 비활성화한다. 본문은 원래 마커를 포함한 Diff 줄만 표시한다. 버튼 클릭으로 다른 구간을 자동 선택하지 않는다.

## US99 버튼 키 표시 계약

단축키가 연결된 버튼은 이름 오른쪽에 현재 키캡을 표시한다. 두 슬롯을 구분하고 빈 슬롯은 생략한다. 실행 핸들러와 비활성 조건을 유지하며 긴 안내는 줄바꿈을 허용한다.

## US100 오류 열람 계약

왼쪽 하단 붉은 느낌표는 오류 건수를 포함하고 클릭 시 오래된 오류부터 연다. 카드는 전체 메시지 스크롤과 이전/다음·페이지 수·닫기를 제공한다. 경계 이동은 무변경이고 새 오류는 마지막에 추가한다. 닫기는 다른 팝업과 기록을 보존한다.

## US101 오류 카드 계약 변경

US100의 닫기 버튼은 확인완료로 대체하고 열기 기본 페이지는 최신 오류로 변경한다. 확인완료는 현재 한 건만 제거하며 바깥 클릭/Esc는 카드만 닫는다. 바깥 클릭은 배경에 전달하지 않는다. 마지막 오류 제거 시 하단 표시도 숨긴다.

## US102 하단 표시 계약

하단 도움말 버튼을 제거하고 오른쪽 끝에 작은 오류 느낌표·건수·키 안내를 둔다. 카드는 위쪽/왼쪽으로 펼친다. F10과 클릭은 동일 토글 경로다. 확인 기본 Ctrl+S 표기는 제거하고 Enter만 사용한다.

## US103 DiffViewer 선택 계약

Space는 선택 범위의 변경 행을 일괄 체크/해제하고 Enter는 체크 집합을 기존 부분 Stage 경로로 보낸다. 번호 없는 행은 끝점이 될 수 없으며 문맥 행은 커서 이동만 허용한다. 버튼 최소 너비는 220px이며 기본 라벨/Enter는 한 줄로 표시한다.

## US104 하단 순서 계약

두 하단 행은 오류(느낌표와 건수만) → 단축키 설정 → 세팅 순서다. 오류는 내용 너비만 사용하고 숨김 시 공간을 차지하지 않는다. 오류 기록 카드는 최상위에서 열며 F10 실행은 유지한다.

## US105 하단 위치 계약

오류는 왼쪽, 단축키/세팅은 오른쪽이다. 오류와 하단 바는 BG 색을 공유하고 오류 내부 좌우는 8px다. 카드는 왼쪽 위로 열린다. 이전 US104의 오른쪽 순서는 이 계약으로 대체한다.

## US106 기록·복사 계약

같은 실패를 다시 실행하면 같은 문구도 새 건이다. 렌더/선택/복사는 새 건이 아니다. 오류 본문은 읽기 전용 선택 영역이며 Ctrl+C는 포커스된 선택을, 전체 복사 버튼은 현재 메시지 전체를 복사한다. 본문 밖 Ctrl+C도 전체 메시지를 복사한다.

## US107 오류 표시 배경 계약

기본 상태는 완전 투명이고 hover는 기존 붉은색이다. F11 팝업의 어두워진 바탕을 기본 상태에서 그대로 드러낸다.

## US108 오류 스크롤 계약

오류 메시지는 표시상 줄바꿈·세로 스크롤만 사용한다. 가로 스크롤은 없고 선택/전체 복사는 원문을 보존한다. 다른 편집기/뷰어의 가로 이동은 변경하지 않는다.

## US109 동일 결과 표시 계약

한 브랜치 결과를 여러 화면에 표시해도 기록은 하나다. 재실행 실패는 별도 발생이다. Revert 실제 충돌 파일은 배너/진단에서 확인하며 로컬 변경 보호 거절에는 충돌 라벨을 붙이지 않는다.

## US110 대괄호 탭 계약

목록 포커스에서 [는 이전, ]는 다음 내부 탭이다. 참조 네 탭과 파일 두 탭은 순환한다. 입력/다른 영역은 영향을 받지 않으며 재지정은 기존 Bindings를 따른다.

## US111 체크박스 키 계약

수동 키 처리 체크박스는 첫 keydown에서만 토글하고 합성 keyup 클릭은 상태를 바꾸지 않는다. 마우스 클릭은 별도로 한 번 토글한다. 설정 체크박스의 기존 단일 keyup 처리는 유지한다.

## US112 키 계약

설정 팝업의 [/]는 분류 순환이며 캡처가 우선한다. Ctrl+[/]는 팝업 밖에서 프로젝트 순환이다. 원격 기본 키는 Pull Ctrl+P/Fetch Ctrl+F/Push Ctrl+U이며 설정과 실행은 같은 Bindings를 따른다.

US112 공통화: 이전 탭/다음 탭은 공통에서 한 번만 설정하며 브랜치·파일·설정 팝업에 함께 적용한다.

## US113 공통 설정 계약

공통의 전체 선택/체크아웃은 관련 영역에 하나의 키 설정을 적용한다. 브랜치/파일목록 하위 섹션의 공유 명령은 공통 섹션에만 보인다. 기능이 다른 같은 키는 독립 설정을 유지한다.

## US120 세팅과 방향키 계약

세팅은 작성자·원격 저장소 정보·인증의 단일 스크롤 화면이다. 전역 불러오기는 입력만 변경, 전역 저장은 global만 변경, 현재 저장소 저장은 local만 변경한다. 세 버튼은 Tab/Shift+Tab 및 Enter/Space로 실행 가능하고 작업/IME 중 차단한다. 내부 탭은 좌우 방향키, 프로젝트 탭은 Ctrl+[/]로 이동한다. 사용자 재지정은 보존한다.

## US121 방향과 탭 계약

공통 방향키 왼쪽/오른쪽의 두 슬롯으로 내부 탭과 다른 영역 좌우 탐색을 함께 설정한다. 프로젝트 이동은 독립 두 슬롯(Ctrl+좌우, Ctrl+J/L)이다. 설정 캡처와 프로젝트/내부 탭 범위는 유지한다.

## US122 작성자 체크 계약

세 버튼 대신 전역 설정 사용 체크와 저장 버튼을 제공한다. 체크하면 전역값 읽기 전용(복사 가능), 해제하면 개별 draft 편집이다. 저장은 체크 시 local 작성자 override만 제거하고 해제 시 local만 기록한다. 전역 파일을 쓰지 않으며 없는 저장소에서는 체크 전환/저장을 비활성화한다. 단일 화면 및 원격/인증은 유지한다.

## US127 Git 작업 계약

기존 버튼/키/오류/충돌 복구 UI를 유지하되 제품 동작은 git.exe를 실행하지 않는다. 오류는 구조적 backend 실패를 기존 오류 이력에 전달한다. 보존이 불가능한 미지원 상태는 변경 전 거부하며 설치된 Git으로 fallback하지 않는다.

## US128 전체 Stage 결과

작업 파일을 변경하지 않고 전체 Stage한 신규 파일은 A, 수정 파일은 M 스테이징 행으로 표시한다. 정규화 설정 차이 때문에 미스테이징 행을 중복 표시하지 않는다.

## US129 스태시 추가 팝업

제목은 스태시 추가, 입력 라벨은 스태시 이름이다. 추가 팝업에는 취소 버튼과 일반 설명을 표시하지 않는다. 확인·오류·진행·닫기 동작과 삭제 팝업은 유지한다.

## US130 그래프와 스태시 탭

스태시 전용 커밋은 일반 그래프에 표시하지 않는다. 스태시 탭에서 명시적으로 선택한 내용은 기존 상세 조회로 제공한다. 스태시 선택을 위해 일반 그래프 페이지를 추가로 읽지 않는다. 복원·삭제는 유지한다.

## US131 읽기 전용 입력

읽기 전용 입력 영역과 스크롤바 바탕은 연한 회색이다. 편집 가능 상태에서는 기존 배경을 표시하며 선택·복사 동작을 유지한다.

## US132 입력 전체 배경

세팅 입력 테두리 내부는 패딩을 포함하여 동일 배경을 표시한다. 라벨은 제외하고 이름·이메일의 읽기 전용 전환에 따라 동기적으로 갱신한다.

## US133 저장 버튼 입력 계약

저장 버튼은 포커스 대상이 아니다. Tab 순환은 이름·이메일·전역 체크·인증 URL이며 저장소가 없으면 체크도 제외한다. 클릭과 확인 단축키로 저장한다.

## US134 원격 목록과 추가 팝업

세팅은 이름·URL 쌍을 모두 표시한다. 추가 버튼은 Tab·Space·클릭으로 동작한다. 하위 팝업은 이름·URL·저장을 표시하고 Tab 순환·확인 단축키 저장·Esc/외부 클릭 복귀를 지원한다. 오류 시 입력을 유지하며 성공 시 목록을 갱신한다. 작성자 저장과 초안은 독립이다.

## US135 겹친 원격 추가 팝업

원격 목록 아래 별도 줄에 추가 버튼을 둔다. 세팅은 같은 제목·크기·본문을 유지하고 그 위에 원격 추가 팝업을 표시한다. 최상위 팝업만 입력을 받으며 외부 클릭·Esc는 그것만 닫는다. 저장 오류·진행 상태도 최상위 팝업에 표시한다.

## US136 원격 입력 테두리

이름·URL 입력은 높이를 유지하고 URL 하단에는 스크롤 경계와 구분되는 여백을 둔다. 낮은 창에서도 스크롤로 전체 입력을 볼 수 있다.

## US137 원격 삭제 아이콘

이름·URL 목록의 원격별 묶음에 삭제 아이콘 하나를 표시한다. 클릭은 해당 로컬 원격 연결 전체를 제거한다. 저장 중에는 실행을 차단하고 성공 후 목록, 실패 후 오류를 표시한다. 서버 저장소는 변경하지 않는다.

## US138 삭제 버튼 입력

원격 삭제 아이콘은 목록 순서로 Tab과 Shift+Tab 이동을 지원하며 포커스를 강조한다. Space만 해당 원격을 삭제하고 키 반복은 차단한다. 성공 후 추가 버튼으로 복귀하며 오류 후 삭제 버튼 포커스는 유지한다.

## US139 Fetch 오류 안내

원격 작업 실패 안내와 기존 오류 기록에 원격 이름과 전송 오류 분류/코드·원문 원인을 표시한다. URL 자격 증명과 토큰은 표시하지 않는다. 인증이 필요하다고 일괄 안내하지 않는다.

## US140 인증 목록과 추가 팝업

인증은 URL·계정·방식 및 삭제 아이콘으로 표시하고 아래 추가 버튼을 둔다. 세팅 위의 추가 팝업에서 GCM·브라우저 로그인·ID와 비밀번호를 선택한다. 브라우저는 GCM과 독립 GitHub OAuth를 선택한다. 방식에 필요한 입력만 표시하고 비밀번호는 마스킹한다. 독립 OAuth는 Client ID와 Device Flow 안내·사용자 코드를 제공한다. 저장 중 입력을 막고 인증 대기는 Esc/바깥 클릭으로 취소한다. 삭제는 앱 인증 등록과 앱 비밀만 제거한다. 직접 입력은 저장 완료로 표시하며 인증 검증 성공으로 표시하지 않는다.

## US141 기존 인증과 버튼

인증 추가의 저장·로그인 버튼은 한 개의 내용 영역만 갖는다. 인증 목록에는 기존 Windows Git/GCM 계정도 기존 인증 표시와 함께 나타난다. 목록 삭제는 앱에서 제외하며 공유 GCM 비밀은 그대로 두고 재불러오기 시 숨김을 유지한다. 시스템 조회 실패는 등록 목록을 유지하며 경고한다.

## US142 프로젝트별 인증 목록

현재 원격의 정확 URL 인증이 있으면 해당 범위만, 없으면 경로를 한 단계씩 올라가며 첫 일치 범위만 표시한다. 최우선 범위의 여러 계정은 모두 보이고 원격 간 중복은 제거한다. 원격 또는 인증 변경 직후 재계산하며 일치 항목이 없을 때 다른 전역 인증을 대신 나열하지 않는다.

## US143 인증 삭제와 로그아웃

삭제는 GCM 저장 인증 제거 또는 앱 전용 비밀 제거를 수행하고 성공한 뒤 목록을 갱신한다. GCM 공유 인증이 제거되면 같은 계정을 사용하는 다른 Git 도구에도 영향을 줄 수 있다. GCM 제거 실패는 목록을 유지하고, 로그아웃 성공 후 목록 저장 실패는 부분 성공으로 안내한다. 브라우저 웹사이트 세션과 서버 권한은 유지한다.

## US144 오류 단축키 안내

오류 표시 순서는 느낌표·개수·단축키 배지다. 기본 키는 f10이며 재지정 설정을 따른다. 클릭과 키 동작은 유지한다.

## US145 배경과 F1

오류 표시는 팝업 뒤에서 다른 배경과 함께 어두워진다. 기본 배지는 f1이며 전역 F1으로 오류 기록을 열고 닫는다. 기본 F10은 해제하고 사용자 재지정과 클릭 동작은 유지한다.

## US146 검증된 로그아웃

삭제한 계정이 Windows에 남아 있으면 성공 메시지를 표시하지 않는다. 선택한 대상의 제거를 확인한 후 앱 등록을 지운다. 다른 계정은 보존하고 오류 시 기존 등록과 설명을 표시한다.

## US147 주소 원칙과 오류

사용자가 등록한 .git 경로를 저장/조회에서 보존한다. /zit와 /zit.git을 같은 인증 주소라고 표시하지 않는다. 잘못된 기존 주소를 위한 호환 조회는 하지 않으며 사용자가 정확한 원격 주소로 새로 등록할 수 있다. Push 실패는 실제 서버/전송 원인을 표시한다.

## US148 인증 추가 선택

최상위 방식은 브라우저 로그인·ID와 비밀번호다. 브라우저 안에서 GCM 사용·독립 OAuth를 선택한다. 기본은 브라우저 GCM이며 기존 GCM 프로필 자동 표시는 유지한다.

US148 브라우저 GCM은 URL만 입력하고 계정 ID 선택을 표시하지 않는다. 계정은 GCM 대화식 로그인에서 선택한다.



## US149 인증 추가 계약

브라우저 로그인은 URL만 받는 GCM 로그인이다. 하위 선택·Client ID·기기 코드·관련 Tab 대상과 GitHub 토큰 안내는 제거한다. 직접 입력과 기존 인증 목록 동작은 유지한다.


## US150 탐색기 계약

프로젝트 footer에서 탐색기 배지 다음에 단축키 안내가 위치한다. 클릭/F10은 활성 프로젝트 폴더를 열고 실패를 오류 기록에 남긴다. Linux/macOS도 같은 표시를 사용한다.


## US151 터미널 계약

footer 오른쪽은 터미널 [f9]·탐색기 [f10]·단축키 순서다. 클릭/F9는 같은 활성 프로젝트 Bash 실행 함수를 호출한다. 팝업과 프로젝트 없는 상태는 실행하지 않고 누름 반복을 막는다. 실행 실패는 기존 오류 기록에서 확인한다.
