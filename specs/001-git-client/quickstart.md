# 실행 및 검증

## 준비와 실행

Windows용 Rust MSVC, Visual Studio C++ 빌드 도구와 Windows SDK가 필요하다. 최초 의존성 다운로드에는 네트워크가 필요하다.

```powershell
cargo run -- D:\Projects\example-repository
```

인자 없이 실행하면 빈 페이지 탭을 표시한다. 경로 여러 개를 전달하면 프로젝트별 탭으로 열린다. 상단 +는 시작 화면 탭을 추가하며 상단 도구 버튼은 없다. 새 탭에서 저장소를 열 수 있다.

## 검증

```powershell
cargo fmt --check
cargo check --locked
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
```

1. 두 저장소를 열어 프로젝트 선택 상태가 보존되는지 확인한다.
2. 네 영역과 참조 탭 네 개, 파일 탭 두 개를 확인한다.
3. 참조와 커밋을 선택하고 History 파일의 차이를 확인한다.
4. Stage에서 스테이징 및 작업 디렉터리 변경을 각각 확인한다.
5. 빈 저장소, 바이너리 파일, 잘못된 실행 경로를 확인한다.
6. 본문 외곽과 네 영역 사이의 여백 및 둥근 모서리가 없는지 확인한다.
7. 세로·가로 경계선을 드래그하여 양쪽 행·열이 정렬된 상태로 조절되는지 확인한다.
8. 드래그 중 최소 크기, 해제 후 포인터 이동, 창 축소·확대, 프로젝트 전환 후 비율 유지를 확인한다.
9. 상단 탭이 44px 높이에 맞붙고 둥글림·여백·로고·도구 버튼이 없는지 확인한다.
10. 맨 오른쪽 +를 세 번 눌러 빈 탭 세 개가 생기고 선택되는지 확인한다. 저장소 탭으로 돌아가 선택 상태가 유지되는지 확인한다.
11. 탭을 닫아 마지막 탭까지 제거해도 새 빈 탭이 남는지, 많은 탭에서도 +가 오른쪽에 고정되는지 확인한다.

조회는 읽기 전용이고 신규 초기화·Clone만 저장소 쓰기를 허용한다. 통합 테스트는 임시 저장소 준비에 Git CLI를 사용한다.

```powershell
cargo test --locked --lib --bin feather-git
$repoLibrary = (Get-ChildItem target/debug/deps/libfeather_git-*.rlib | Sort-Object LastWriteTime -Descending | Select-Object -First 1).FullName

rustc --edition=2024 --test tests/repository.rs --extern "feather_git=$repoLibrary" --extern "tempfile=$tempLibrary" -L dependency=target/debug/deps -o target/debug/repository-current-tests.exe
& target/debug/repository-current-tests.exe
```

공통 열 너비·행 높이·캐시·고정 항목·파일 조회 세대 무효화·탭별 상태는 코드 검토로 확인했다. Computer Use 자동 승인 검토가 feather-git-preview 실행을 허용하지 않아 GUI hover·스크롤·선택의 시각 확인은 수행하지 못했다. 앱을 닫고 cargo run으로 실행하여 위 수동 시나리오를 확인할 수 있다.

## 복구·최근 저장소·단축키 검증 절차

두 저장소와 빈 탭을 열고 가운데 탭을 선택한 뒤 재시작해 순서와 선택을 확인한다. 새 탭의 최근 항목을 다시 열어 중복 탭이 없는지 확인한다. 목록에서 제거 후 실제 파일이 유지되는지 확인한다. 삭제 확인 취소는 파일과 상태를 보존해야 하며 실제 휴지통 이동은 폐기 가능한 임시 저장소에서만 확인한다. ?와 하단 도움말 클릭, Esc·바깥 클릭·닫기, URL 입력 중 문자 키를 확인한다. f는 로컬 시험 원격의 변경을 가져오며 작업 트리를 보존해야 한다. 모든 조회·열기·fetch·삭제 중 진행 오버레이와 입력 차단을 확인한다.

목록의 첫/마지막 행과 Stage 그룹 경계에서 ↑/↓를 확인한다. 상세와 Diff의 한글/탭/빈 줄을 여러 줄 또는 역방향으로 선택해 Ctrl+C로 복사하고, 문자 입력·Backspace·붙여넣기로 원문이 바뀌지 않는지 확인한다. 다른 파일이나 커밋을 선택하면 이전 텍스트 범위는 사라져야 한다.

검증 결과: cargo fmt --check, cargo check --offline, cargo clippy --offline --all-targets -- -D warnings 통과. cargo test --offline --lib --bin feather-git의 단위 테스트 25개가 통과했다. 실행 중인 기존 앱의 파일 잠금을 피하여 tests/repository.rs를 현재 라이브러리 산출물로 별도 컴파일한 저장소 통합 테스트 15개도 통과했다. 로컬 fetch는 원격 참조만 갱신하고 HEAD와 미커밋 파일을 보존했으며 조회 세션 종료 후 추가 요청 거절도 검증했다. 상태 왕복·빈 탭 순서·활성 위치·없는 경로·중복 인자·손상 파일 보존·표시 경로·삭제 대상 거절·Unicode/여러 줄 복사를 검증했다.

별도 검증 실행 파일은 .build/feather-review.exe로 빌드했다. Computer Use 자동 승인 검토가 해당 앱 실행을 허용하지 않아 실제 창·마우스·클립보드 동작은 화면에서 검증하지 못했다. 삭제 대상 검증만 수행했으며 사용자 저장소에 실제 휴지통 이동을 실행하지 않았다. 모달 렌더링·입력 차단·키 처리·복사 연결은 코드로 검토했다.

수렴 보완: 고정 커밋상세 행도 파일 목록 포커스를 받아 첫 파일과 ↑/↓로 상호 이동하도록 T060을 완료했다. 보완 후 Clippy와 단위 테스트 25개를 다시 통과했다.

## 히스토리 진행 표시·브랜치 위치 검증

## 원격 HEAD·Stage 상태·Space·F5 검증

임시 저장소에서 origin/HEAD를 origin/main의 심볼릭 참조로 만들고 두 이름이 참조와 커밋 배지에서 구분되는지 확인한다. 신규·수정·삭제 파일을 만들고 두 칸 상태와 색상을 확인한다. 선택 파일의 Space 이후 해당 경로만 staged로 바뀌며 작업 내용과 히스토리 위치가 유지되어야 한다. staged 행과 다른 목록/텍스트에서 Space는 인덱스를 바꾸지 않아야 한다. 외부 파일 수정 후 F5로 로컬 상태를 갱신하고 도움말의 F5 항목을 확인한다.

원격 HEAD·Stage·F5 검증 결과: 단위 테스트 27개와 저장소 통합 테스트 18개가 통과했다. 원격 심볼릭 HEAD와 실제 원격 브랜치가 loose/packed refs 및 커밋 배지에서 각각 원래 이름으로 한 번씩 표시되고 annotated tag 대상 해석이 유지됨을 확인했다. 신규·수정·삭제의 여섯 두 칸 상태, 부분 staged 두 행, 작업 디렉터리 헤더 부재, 신규 저장소의 첫 스테이징, 공백/대괄호 경로의 literal 처리, 다른 경로와 작업 내용 보존 및 잘못된 경로의 인덱스 비변경을 검증했다.

F5는 기존 로컬 reload에 연결되고 원격 fetch를 호출하지 않는다. Space는 Stage 파일 포커스와 unstaged 선택을 요구하고 성공 시 Stage/Diff만 갱신하며 히스토리 모델·세션·스크롤을 유지한다. 비활성 프로젝트의 스테이징 완료가 현재 탭이나 텍스트 선택을 바꾸지 않도록 프로젝트별 Diff 조회를 재사용한다. 색상·도움말·키 처리·입력 차단 및 오류/중복 처리는 코드로 검토했다. 실제 화면 검증은 이번 실행에서 수행하지 않았다. fmt/check/Clippy를 통과했다.


## 헤더 제거와 Unstage 검증

Stage 목록에서 두 그룹 헤더가 모두 없는지 확인한다. 신규/수정/삭제 파일 각각에 Space를 두 번 눌러 staged와 unstaged 상태를 왕복한다. 첫 커밋 전 신규 파일 및 인덱스/작업 내용이 다른 부분 staged 파일도 해제하고 작업 내용과 다른 경로의 인덱스가 유지되는지 확인한다.

양방향 Space 검증 결과: 단위 테스트 27개와 저장소 통합 테스트 18개가 통과했다. 신규/수정/삭제 파일의 stage→unstage 왕복, 부분 staged 인덱스 해제, 첫 커밋 전 수정된 신규 파일 해제, literal 파일명, 다른 staged 경로와 작업 파일 보존 및 해제 후 변경이 완전히 사라지는 사례를 검증했다. 잘못된 경로는 stage/unstage 모두 인덱스를 변경하지 않는다. 초기 조회와 작업 완료 후의 Stage UI 매핑은 모두 그룹 없는 매핑을 사용한다. 전환 후 목표 상태 선택·Diff 갱신·중복 방지·포커스 제한과 히스토리/Progress 보존은 코드로 검토했다. 실제 화면 검증은 이번 실행에서 수행하지 않았다. fmt/check/Clippy를 통과했다.


## 지연 탭·정렬·커밋 검증

여러 저장소와 빈 탭을 복원해 활성 저장소만 조회되는지 확인하고 미조회 탭 선택/닫기 후 자동 선택 시 최초 조회를 확인한다. stage/unstage 전후 파일명 순서를 비교한다. History 커밋상세 행과 파일 행 글자 크기를 비교한다. 임시 저장소의 staged/unstaged 내용을 구분해 c로 한글 여러 줄 메시지를 입력하고 두 실행 단축키를 각각 확인한다. 공백 메시지·실패·취소·중복 실행과 메시지 보존도 확인한다.

안정 정렬·지연 탭·커밋 검증 결과: 단위 테스트 30개와 저장소 통합 테스트 19개가 통과했다. 파일의 staged 여부 변경에도 경로 정렬을 유지하는 실제 저장소 검증과, 비활성/없는 경로를 시작 시 검증하지 않고 활성화할 때 검사하는 세션 검증을 추가했다. 첫 활성 탭만 reload하고 탭 클릭/닫기 후 미조회 활성 탭을 한 번 읽는 경로를 코드로 확인했다.

커밋 입력기의 한글 조합 교체·UTF-16/UTF-8 범위·이모지·여러 줄 편집을 검증했다. 실제 임시 저장소에서 한글 여러 줄 메시지 커밋, 현재 인덱스만 포함, unstaged/미추적 파일 내용 보존, 빈 메시지/NUL/변경 없음 거절을 확인했다. 커밋 실패 시 모달/메시지 유지, 실행 중 입력/중복/취소 차단, Ctrl+Enter와 Ctrl+S, 하단 안내, c 도움말, 성공 후 최신 커밋 조회와 History 고정 행 글자 크기는 코드로 검토했다. 실제 Windows 화면과 IME 연결 동작은 이번 실행에서 검증하지 않았다. 사용자 저장소에는 커밋하지 않았다. fmt/check/Clippy를 통과했다.


## 커밋 팝업 조건과 스크롤 검증

unstaged 변경만 있는 저장소에서 c가 팝업을 열지 않는지 확인한다. staged 파일을 준비한 뒤 c로 열고 작은 제목과 소문자 하단 안내 및 우측 커밋/닫기 버튼을 확인한다. Ctrl+Enter는 커밋하지 않고 Ctrl+S/커밋 버튼만 제출해야 한다. 여러 줄과 긴 한 줄의 메시지에서 두 축 바가 필요한 경우에만 나타나고 제목/하단이 고정되는지 확인한다. 실행 중 닫기/중복 제출을 막는지 확인한다.

커밋 팝업 정리 검증 결과: 단위 테스트 30개와 저장소 통합 테스트 19개가 통과했다. 실제 임시 저장소에서 staged 없음/unstaged만 있음에 대한 별도 차단 오류와 기존 staged 커밋 성공을 확인했다. UI의 열기/제출 조건도 staged 존재를 검사한다. 두 제목은 text_sm이며, Ctrl+Enter 제출 경로를 제거하고 Ctrl+S/커밋 버튼을 공통 제출 함수로 연결했다. 우측 닫기 버튼과 Esc/바깥 클릭은 실행 중 취소를 막는다. 하단 안내는 정확히 `커밋 : ctrl + s, 취소 : esc`이다.

메시지는 실제 글꼴 폭·행 수와 공통 스크롤 수치 계산으로 필요한 축의 바만 표시한다. 클릭·드래그·휠·커서 자동 스크롤을 연결하고 사라진 축의 드래그를 초기화한다. 입력은 220px 고정 영역이며 제목/하단은 별도 레이아웃이다. 짧은 내용의 불필요한 최소 가로 폭을 제거했다. fmt/check/Clippy와 코드 검토를 통과했다. 실제 Windows 화면·IME·포인터 동작은 이번 실행에서 검증하지 않았다.


## 작성자 메일·Stage 다중 선택 검증

Author가 이름/메일을 함께 표시하는지 초기/추가 페이지에서 확인한다. Stage의 연속 범위·역방향 Shift·Ctrl 분산/해제·Ctrl+Shift·Shift 방향키를 확인하고 Space로 전체 선택이 반전되는지 확인한다. 혼합 staged/unstaged와 부분 staged 양쪽 행을 선택해 중복 경로 처리·선택 복원·비선택 경로와 작업 파일 보존을 확인한다.

## 폐기 검증

선택한 tracked 변경은 HEAD로 복원하고 새 파일은 삭제되는지 임시 저장소에서 확인한다. 미선택 파일과 staged 변경은 보존해야 한다. d만 누르거나 확인창을 취소하면 변경하지 않아야 한다. 디렉터리/링크 경로는 거절하고 실패 시 최신 상태와 오류를 표시해야 한다.

## 풀·푸시 검증

임시 bare 원격과 두 작업 저장소를 준비해 push 후 상대 저장소 pull로 내용이 갱신되는지 확인한다. 두 저장소에서 각기 커밋한 분기 이력은 pull --ff-only가 거절하고 기존 HEAD를 유지해야 한다. p/Shift+p 도움말·입력/모달 차단·중복/오류 상태를 검토한다.

작성자 메일·다중 선택·폐기·원격 단축키 검증 결과: 단위 테스트 35개와 저장소 통합 테스트 19개가 통과했다. 초기/추가 페이지에서 작성자 이름/메일을 읽고 작성자와 커미터가 다른 커밋의 표시를 검증했다. 범위/역방향/개별 선택·해제·범위 추가·같은 경로 두 상태 선택·목표 상태 복원과 사라진 행 해제를 검증했다.

실제 임시 저장소에서 상태별 복수 경로 전환·literal 이름·다른 경로 보존·잘못된 경로 사전 거절, 수정/삭제/신규/부분 staged/첫 커밋 전 폐기와 디렉터리/메타데이터 경로 거절을 검증했다. 재귀 삭제는 사용하지 않는다. 폐기는 확인창에서 캡처한 경로만 실행하며 오류 후 상태를 다시 읽는 연결은 코드로 확인했다. 사용자 저장소에는 폐기하지 않았다.

실제 임시 bare 원격과 작업 저장소에서 pull --ff-only·일반 push·분기 이력의 pull 거절·HEAD 보존을 검증했다. Ctrl+P의 공통 백엔드는 커밋 성공 후 push하고 커밋 실패 시 push하지 않으며 push만 실패해도 새 로컬 커밋을 보존하는 것을 확인했다. 사용자 원격에는 push하지 않았다. 도움말 p/shift+p/d, 커밋 창 버튼 부재와 새 소문자 하단 안내, 입력/모달/중복 차단·원격 진행 라벨은 코드로 검토했다. fmt/check/Clippy를 통과했다. 실제 화면·IME·포인터 동작은 이번 실행에서 검증하지 않았다.


## 전체 선택과 폐기 확인 키 검증

Stage에서 Ctrl+A로 모든 행을 강조한 뒤 Ctrl+클릭 해제·Shift 범위·Space 전환·d를 확인한다. 빈 목록과 입력/텍스트의 Ctrl+A도 확인한다. 폐기 확인창은 파일 목록과 버튼이 없고 정확한 소문자 안내가 있어야 한다. d 후 Esc는 변경하지 않으며 Ctrl+S로만 폐기한다. 실제 폐기 검증은 임시 저장소에서만 수행한다.

하단 오류를 발생시켜 약 3초 후 일반 경로/상태로 복원되는지 확인한다. 만료 직전 다른 오류가 오면 이전 타이머로 조기 제거되지 않아야 한다. 확인창 오류와 조회 실패 안내는 유지되어야 한다.

폐기 확인 키·Ctrl+A·하단 오류 수명 검증 결과: 단위 테스트 36개와 저장소 통합 테스트 19개가 통과했다. Stage 전체 선택은 staged/unstaged 두 상태를 포함하며 Ctrl 개별 해제·Shift 범위·빈 목록·상태 전환 복원을 검증했다. Ctrl+A는 텍스트/메시지/URL 처리 이후 Stage 파일 포커스에만 적용하고 대표 Diff가 있으면 재조회하지 않는다.

폐기 모달의 파일 목록/취소·폐기 버튼을 제거하고 정확한 `폐기 : ctrl + s, 취소 : esc` 안내를 추가했다. Ctrl+S는 폐기 모달 안에서만 실행하고 Esc는 실행 전에만 취소한다. 내부 캡처 경로와 기존 사전 검증·중복 방지·실패 후 재조회는 유지한다. 하단 오류는 원본 오류와 분리된 표시 문자열을 3초 타이머로 지우며 세대로 이전 타이머의 새 오류 제거를 막는다. 전체/프로젝트 오류를 각각 관찰해 오래된 전체 오류가 새 프로젝트 오류를 가리지 않게 한다. 모달 오류와 패널 실패 상태는 유지한다. fmt/check/Clippy와 코드 검토를 통과했다. 실제 화면과 3초 표시 시간의 시각 검증은 이번 실행에서 수행하지 않았다.

## 포커스 표시 수동 검증

cargo run 후 브랜치→이력→파일→Diff를 클릭하여 선택 보존과 활성 색 이동을 확인한다. Stage 다중 선택 뒤 이력 클릭 시 모든 파일 선택이 회색인지 확인한다. 도움말/커밋 창을 열고 닫아 비활성화와 복원을 확인한다. 도움말의 적용 범위와 소문자 표기를 확인한다. 일반 화면에서 f5/ctrl+r 새로고침, URL/커밋 입력과 모달에서 새로고침 차단을 확인한다.

포커스/도움말 검증 결과: cargo fmt --check, cargo check --offline, cargo clippy --offline --all-targets -- -D warnings 통과. 최신 단위 테스트 28개 통과. 전체 cargo test는 실행 중인 feather-git.exe 파일 잠금으로 바이너리 교체에서 실패하여 cargo test --offline --bin feather-git와 이번 빌드에서 생성된 repository-beb45aad408a49e8.exe를 개별 실행했고 저장소 통합 테스트 19개도 통과했다. 실제 화면의 시각 검증은 수행하지 않았다.

## 새 탭 화면 검증 안내

cargo run으로 새 탭을 열어 기존 헤더 제거와 좌우 배치를 확인한다. 생성·열기·복제 폼을 확인한다. 최근 목록에 충분한 항목이 있을 때 휠/스크롤바로 뒤쪽 항목을 확인하고 왼쪽 작업이 고정인지 확인한다. 긴 경로는 한 줄 말줄임되고 휴지통 아이콘이 유지되어야 한다. 아이콘 클릭 시 저장소가 열리지 않고 두 선택지가 표시되어야 한다. 목록 제거는 폴더/열린 탭을 보존하고 재시작 후에도 기록에 없어야 한다. 저장소 삭제 선택 뒤 최종 확인과 esc 취소를 확인하며 실제 사용자 저장소 삭제는 실행하지 않는다.

## 커밋상세 행 포커스 검증

History에서 커밋을 선택하면 커밋상세 행은 비활성 회색이다. 커밋상세 클릭 시 청록색, Diff/이력/브랜치 클릭과 모달 열기 시 회색이어야 한다. 선택된 행에 마우스를 올려도 색이 유지되고 일반 파일 선택 후에는 커밋상세가 기본 배경으로 돌아와야 한다. 변경 파일이 없는 커밋에서도 동일하게 확인한다.

커밋상세 행 보정 검증 결과: fmt/check/clippy 통과, 기존 단위 테스트 28개 통과. FR-097~FR-098과 SC-044를 코드의 선택색·호버·Window 전달 및 기존 클릭 처리와 대조한 수렴 검토에서 남은 구현 누락이 없었다. 실제 앱 화면은 시각 검증하지 않았다.

## 빈 탭 소비 회귀 검증

빈 탭 여러 개 중 하나에서 최근 저장소 또는 폴더 열기를 수행하여 동일 위치에서 저장소로 대체되는지 확인한다. 이미 열린 저장소를 선택하면 기존 저장소 탭을 사용하고 시작 빈 탭만 없어야 한다. 취소/실패는 빈 탭을 유지한다. 요청 후 다른 탭으로 이동하면 완료 후에도 현재 선택을 유지하고, 요청한 탭을 닫으면 다시 생성하지 않는다. 재시작 후에도 완료된 탭 구성이 저장되어야 한다.

## 도움말 다섯 섹션 검증

## US140 인증 목록과 방식별 추가 검증

### 구현 결과

인증 영역은 URL·계정·방식·삭제 아이콘의 목록과 아래 추가 버튼으로 구성한다. 추가는 세팅을 유지하는 상위 팝업이고 GCM·브라우저 로그인·ID와 비밀번호를 선택한다. 브라우저는 GCM과 독립 GitHub OAuth를 모두 제공한다. GCM은 저장된 인증을 비대화식 조회하고 브라우저 GCM은 대화식 로그인을 실행한다. 독립 OAuth는 GitHub OAuth 앱의 Client ID와 Device Flow 활성화가 필요하다. 직접 입력은 비밀번호/토큰을 저장하며 서버 로그인 검증 완료로 표시하지 않는다.

앱 데이터 경로의 FeatherGit/auth.json에는 id·URL·계정·방식만 기록한다. 직접/OAuth 비밀은 Windows 자격 증명 관리자의 FeatherGit/auth/<id> 항목으로 저장한다. 메타데이터 저장 실패 시 비밀을 롤백하며 삭제의 읽기/삭제 실패는 기존 목록을 보존한다. 실제 비밀이 사라진 오래된 등록만 정리할 수 있다. 같은 URL 중복은 거부하고 더 구체적인 저장소 URL의 인증을 전송에서 우선 사용한다. GCM 삭제는 앱 등록만 제거하여 외부 도구의 공유 계정은 보존한다.

키 경로는 AuthPanel에 위임한다. 인증 목록의 삭제·추가, 팝업 방식 선택은 Tab·Space를 지원하고 확인은 저장한다. 표시된 입력에만 Tab을 순환하며 인증 대기는 Esc/외부 클릭으로 취소한다. 저장 중 닫기를 막고 취소된 작업의 늦은 결과는 등록하지 않는다. 작성자 초안·원격 설정과 기존 원격 팝업을 유지한다. 비밀번호는 마스킹하고 복사/잘라내기·IME 원문 조회를 차단하며 취소/방식 전환/성공 시 지운다.

### 진단 근거와 수정

D:/Project/zit의 origin은 https://github.com/tcpip147/zit.git이고 credential.useHttpPath는 true다. 앱 메타데이터의 BrowserGcm 등록은 .git이 제거된 /zit 주소였다. 등록 단계는 정규화 주소로 GCM을 호출하고 전송 단계는 실제 원격 .git 주소로 조회하며, 전송 helper에는 프로젝트 current_dir도 없었다. 사용자 오류는 Push의 일반 실패 안내여서 실제 서버 원인도 숨겨져 있었다.

진단 프로세스의 Windows 자격 증명 열거는 로그온 세션 접근 오류 1312로 실패했다. GCM get 비교도 비밀을 얻지 못했으므로 실제 사용자 토큰의 유효성이나 URL별 실제 캐시 조회 성공은 단정하지 않았다. 토큰 값은 출력하지 않았고 GitHub 실제 Push는 실행하지 않았다.

앱을 완전히 닫고 `cargo run --offline`으로 수정 앱을 실행한다. D:/Project/zit의 인증 추가에서 브라우저 로그인 → GCM을 선택하고 원격과 같은 https://github.com/tcpip147/zit.git 주소로 새로 등록한다. /zit의 이전 등록을 자동 변환하거나 호환 조회하지 않으므로 실제 .git 주소의 등록이 필요하다. 이후 Push 실패 시 F1 오류 기록의 상세 원격/분류/서버 이유로 인증·쓰기 권한·브랜치 거부를 구분한다.

최종 수렴 검토에서 FR-420~FR-424와 SC-167은 T459~T461 및 코드·회귀로 모두 추적되며 추가 구현 작업은 없다. 실제 계정 Push 성공은 위 사용자 환경 확인으로 남긴다.

## US149 검증과 수렴

포맷·컴파일·전체 대상 Clippy가 통과했고 GCM 인증 8개와 인증 프로필 13개 회귀가 통과했다. 독립 OAuth 등록·Client ID·하위 선택·기기 코드·토큰 안내와 전용 reqwest 의존성 제거를 확인했다. 기존 프로필 저장·전송·삭제는 유지한다. 실제 화면과 브라우저 로그인은 자동 검증하지 않았다.

명세 FR-428~429·SC-169, 수용 시나리오와 계획·작업을 현재 코드에 대조했다. 남은 구현 차이와 추가 작업은 없다. 실행 중 앱을 종료하고 cargo run --offline으로 재실행하면 반영된다.


## US150 탐색기 검증과 수렴

프로젝트 우측 하단에서 탐색기 배지가 단축키 왼쪽에 표시된다. 클릭 또는 F10으로 활성 프로젝트를 연다. Windows explorer.exe·Linux xdg-open·macOS open에 경로를 단일 인수로 전달한다. 프로젝트 없는 화면은 버튼을 표시하지 않고 실행도 하지 않는다. 변경한 단축키가 배지와 동작에 반영되며 팝업과 반복 입력은 실행에서 제외한다.

cargo check --offline, cargo clippy --offline --all-targets -- -D warnings, cargo fmt --check를 통과했다. 플랫폼별 명령/경로 테스트 1개, 단축키 기본 테스트 1개와 바인딩 회귀 17개가 통과했다. Linux/macOS 빌드·실제 파일 관리자 실행과 화면 검증은 이 Windows 환경에서 수행하지 않았다. 앱 재실행 후 프로젝트 탭을 바꾸면서 버튼/F10과 오류 기록을 수동 확인할 수 있다.

FR-430~432·SC-170과 계획·작업을 현재 코드에 대조한 수렴 결과, 남은 구현 차이는 없다. 새 수렴 작업은 추가하지 않는다.


## US151 Bash 터미널 검증과 수렴

프로젝트 footer는 터미널 [f9]·탐색기 [f10]·단축키 순서다. 클릭 또는 F9는 실행 시 활성 프로젝트 경로를 복사하여 외부 대화식 Bash를 연다. Windows는 PATH의 Git 설치 주변과 기본 설치 위치에서 Git Bash를 찾는다. Linux는 x-terminal-emulator·GNOME Terminal·Konsole·Xfce Terminal·xterm 순서로 발견한 터미널에서 설치된 Bash를 실행한다. macOS는 Terminal의 AppleScript에 경로와 Bash를 별도 인수로 전달한다. 설치되지 않은 구성요소나 실행 실패는 오류 기록에 표시한다. 터미널 설치나 환경 설정은 변경하지 않는다.

cargo check --offline, cargo clippy --offline --all-targets -- -D warnings가 통과했다. 플랫폼 명령/특수문자 경로·탐색/미설치 회귀 2개와 단축키 기본/변경/팝업/충돌 회귀 18개가 통과했다. Windows·Linux·macOS에서 실제 터미널 창 열기는 자동 검증하지 않았고 Linux/macOS의 빌드도 수행하지 않았다. 앱을 종료하고 cargo run --offline으로 실행한 뒤 탭 전환과 버튼/F9·오류 기록을 수동 확인할 수 있다.

구현 전 분석: FR-433~435와 SC-171을 T471~473 및 실행 모듈·UI·단축키 계획에 대조했고 누락·모순이 없었다. 품질 체크리스트의 미완료 항목은 없고 헌법은 미작성 템플릿이었다. 구현 후 수렴: 같은 요구·수용 시나리오를 현재 코드와 검증 결과에 대조한 결과 구현 차이와 추가 작업은 없다.
