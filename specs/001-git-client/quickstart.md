# 실행 및 검증

## 준비와 실행

Windows용 Rust MSVC, Visual Studio C++ 빌드 도구와 Windows SDK가 필요하다. 최초 의존성 다운로드에는 네트워크가 필요하다.

```powershell
cargo run -- D:\Projects\example-repository
```

인자 없이 실행하면 빈 페이지 탭을 표시한다. 경로 여러 개를 전달하면 프로젝트별 탭으로 열린다. 상단 +는 시작 화면 탭을 추가하며 상단 도구 버튼은 없다. 새 탭에서 저장소를 열 수 있다.

## 검증

```powershell
cargo fmt --check
cargo check --locked
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
```

1. 두 저장소를 열어 프로젝트 선택 상태가 보존되는지 확인한다.
2. 네 영역과 참조 탭 네 개, 파일 탭 두 개를 확인한다.
3. 참조와 커밋을 선택하고 History 파일의 차이를 확인한다.
4. Stage에서 스테이징 및 작업 디렉터리 변경을 각각 확인한다.
5. 빈 저장소, 바이너리 파일, 잘못된 실행 경로를 확인한다.
6. 본문 외곽과 네 영역 사이의 여백 및 둥근 모서리가 없는지 확인한다.
7. 세로·가로 경계선을 드래그하여 양쪽 행·열이 정렬된 상태로 조절되는지 확인한다.
8. 드래그 중 최소 크기, 해제 후 포인터 이동, 창 축소·확대, 프로젝트 전환 후 비율 유지를 확인한다.
9. 상단 탭이 44px 높이에 맞붙고 둥글림·여백·로고·도구 버튼이 없는지 확인한다.
10. 맨 오른쪽 +를 세 번 눌러 빈 탭 세 개가 생기고 선택되는지 확인한다. 저장소 탭으로 돌아가 선택 상태가 유지되는지 확인한다.
11. 탭을 닫아 마지막 탭까지 제거해도 새 빈 탭이 남는지, 많은 탭에서도 +가 오른쪽에 고정되는지 확인한다.

조회는 읽기 전용이고 신규 초기화·Clone만 저장소 쓰기를 허용한다. 통합 테스트는 임시 저장소 준비에 Git CLI를 사용한다.

```powershell
cargo test --locked --lib --bin feather-git
$repoLibrary = (Get-ChildItem target/debug/deps/libfeather_git-*.rlib | Sort-Object LastWriteTime -Descending | Select-Object -First 1).FullName

rustc --edition=2024 --test tests/repository.rs --extern "feather_git=$repoLibrary" --extern "tempfile=$tempLibrary" -L dependency=target/debug/deps -o target/debug/repository-current-tests.exe
& target/debug/repository-current-tests.exe
```

공통 열 너비·행 높이·캐시·고정 항목·파일 조회 세대 무효화·탭별 상태는 코드 검토로 확인했다. Computer Use 자동 승인 검토가 feather-git-preview 실행을 허용하지 않아 GUI hover·스크롤·선택의 시각 확인은 수행하지 못했다. 앱을 닫고 cargo run으로 실행하여 위 수동 시나리오를 확인할 수 있다.
