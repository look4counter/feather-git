# 기술 조사

## 전체 높이 탭 바

- 결정: 기존 GPUI의 h_full, flex_shrink_0, overflow_x_scroll과 사각 div를 사용한다. 추가 의존성은 없다.
- 근거: 기존 탭이 공용 button의 padding·rounded 스타일을 사용하여 떠 있는 형태가 됐다. 프로젝트 탭 전용 요소를 구성하면 높이를 부모에 맞출 수 있다.
- 대안: 빈 페이지를 가짜 저장소로 표현하면 불필요한 조회와 오류가 생기므로 Empty/Repository 탭 상태를 명시적으로 구분한다.

## GPUI

- 결정: 공식 GPUI 0.2.2를 고정한다.
- 근거: WindowsPlatform과 Direct3D11/DirectWrite 지원이 있다. Application, Render, div, Context listener를 사용한다.
- 대안: 커뮤니티 포크 및 Zed 전체 Git 의존성은 초기 앱에 불필요하다.
- 출처: [공식 소스](https://docs.rs/crate/gpui/0.2.2/source/).

## gix

- 결정: 로컬 소스를 확인한 gix 0.87.1을 고정한다. 참조 열거, reflog, 리비전 순회, 트리 및 status API를 사용한다.
- 근거: Git CLI 없이 읽기 전용 조회를 수행할 수 있다. 상태 결과의 write_changes는 호출하지 않는다.
- 대안: libgit2 및 Git CLI는 사용자 지정 기술에 부합하지 않는다.
- 출처: [공식 문서](https://docs.rs/gix/0.87.1/gix/).

## 비동기와 비교

- 결정: GPUI background_executor에서 저장소를 열어 소유 데이터만 반환한다. 프로젝트 ID와 요청 세대로 결과를 검증한다.
- 파일 차이는 이전/이후 내용을 similar로 비교한다. 크기·바이너리·파일 종류를 확인하고 표시를 제한한다.
- 이름 변경은 삭제/추가로 표시할 수 있다. 외부 필터 실행은 범위 밖이다.

## 영역 크기 조절

- 결정: 기존 GPUI의 canvas prepaint/paint, MouseMoveEvent.pressed_button, Window::on_mouse_event의 캡처 단계, ResizeLeftRight/ResizeUpDown을 사용한다. 추가 의존성은 없다.
- 근거: 로컬 GPUI 0.2.2 소스의 elements/div.rs, elements/canvas.rs, interactive.rs와 painting 예제에서 이벤트 API를 확인했다.
- 대안: 새 컴포넌트 의존성은 경계선 두 개에 불필요하다. 네 패널의 독립 비율은 정렬이 어긋나므로 공통 비율을 사용한다.
- 이벤트 보완: occlude는 상위 hitbox의 hover 판정도 차단한다. data_table 공식 예제와 같이 paint 단계에서 전역 이벤트를 등록하여 드래그 중 포인터가 핸들을 벗어나도 이동·해제를 처리한다.

## 초기화와 Clone 결정

설치된 Git의 전송과 인증 설정을 활용하기 위해 Git CLI를 선택했다. 셸 없이 인자를 넘기며 기존 조회는 gix로 유지한다. gix 네트워크 의존성 확장은 범위를 늘리므로 제외한다.

## zit 그래프 조사

참조 파일: D:/Project/zit/crates/zit/src/project/repository.rs의 build_commit_graph와 page.rs의 history_columns·build_commit_graph_paths·commit_graph. 입력/출력 반행 레인으로 부모를 기다리고 첫 부모는 색상을 유지하며 추가 부모는 레인과 색상을 배정한다. 행 사이 직선과 0.6 제어점 비율의 곡선을 사용한다. UI 위젯 전체를 가져오지 않고 기존 GPUI에 알고리즘과 캔버스 렌더링만 적용한다. 고정 폭 열과 가로 스크롤로 정렬을 보장한다.

## 지연 원인 조사와 개선 결정

기존 history_panel은 모든 행·셀·canvas를 매 렌더마다 생성하고 graph_width도 전체 레인을 순회했다. 커밋 클릭은 git::load로 전체 이력과 작업 상태를 다시 읽고 UI에서 모든 RowGraph를 생성했다. GPUI 0.2.2의 uniform_list 소스는 고정 높이와 제한된 높이 컨테이너에서 가시 범위만 render_items에 전달한다. 이를 적용하고 전체 순회는 백그라운드 최초 조회로 한정한다. 기존 경로 캐시는 절대 원점이 바뀌면 재생성되지만 가상화로 가시 행에만 비용이 발생하게 한다.

## 공통 스크롤 조사

GPUI uniform_list는 자체 표시 스크롤바가 없고 UniformListScrollHandle.0의 base_handle로 offset·max_offset·bounds를 얻을 수 있다. 공통 프레임으로 트랙을 만들고 비율로 offset을 설정한다. 기존 목록 중 커밋만 가상화되어 있어 나머지 목록과 상세 메시지도 같은 uniform_list로 바꾼다. 페이징은 살아 있는 iterator 작업자와 채널을 사용하여 재순회와 UI 블로킹을 방지한다.

## 불필요한 스크롤바 원인

기존 공통 프레임은 max_offset이 0이어도 바와 12px 공간을 항상 생성했다. 조건부 바는 콘텐츠 크기와 프레임 크기로 두 축을 함께 결정해야 한 축의 바가 만든 넘침이 고착되지 않는다. Diff의 기존 보수적인 문자 폭 추정도 불필요한 바를 만들 수 있어 실제 텍스트 폭을 최초 표시 때 측정하고 캐시한다.

## 날짜·해시 너비 결정

결정: 기본 가중치에서 Date·Hash의 여유 공간 배분을 제거하고 기존 고정폭 글꼴을 재사용한다. 이유: 현재 날짜 16자와 해시 8자는 일정 길이이므로 창 비례 확대가 필요 없다. 대안인 드래그 제거는 기존 조절 기능을 바꾸므로 채택하지 않는다.

## 세션과 작업 실행 결정

결정: 기존 캐시에 있는 serde와 serde_json을 직접 의존성으로 사용하고 사용자 앱 데이터에 상태를 둔다. 이유: 저장소 위치와 실행 위치에 무관하게 복구할 수 있다. 대안인 저장소별 파일은 최근 목록과 여러 탭을 함께 보관하기 어렵다.

결정: 원격 통신은 기존 초기화/Clone과 같은 Git CLI를 사용하고 자동 터미널 입력을 막는다. 이유: 기존 Git 인증과 전송을 재사용한다. 작업 트리는 갱신하지 않는다.

결정: 폴더 삭제는 Windows 휴지통으로 한정하고 연결 worktree·링크 루트는 거절한다. 이유: 실제 대상 범위를 명확히 하고 사용자 복구 가능성을 유지한다. 영구 삭제는 대안에서 제외한다.

휴지통 API의 RECYCLEONDELETE와 오류 즉시 중단 플래그는 [Microsoft의 IFileOperation 공식 문서](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifileoperation-setoperationflags)를 확인했다. 페이지 세션은 종료 응답 후 파일 핸들이 해제되며 COM 작업은 전용 스레드를 사용한다.

## 히스토리 탐색 결정

결정: 별도 일괄 조회 대신 기존 200개 페이지 콜백을 연속 실행한다. 이유: 그래프 세션과 순서를 보존하고 중간 오류 후 재시도에서 소비한 페이지를 잃지 않는다. 전체 재조회는 이전 위치와 캐시를 버리므로 제외한다. Progress는 상세와 별도 플래그를 사용한다.


## 참조 이름과 선택 파일 스테이징 결정

결정: gix 참조의 peel 전에 원래 이름을 보존한다. 이유: 심볼릭 참조를 따라가면 Reference의 이름이 대상 이름으로 바뀌므로 배지가 중복될 수 있다. packed 버퍼를 보유한 iterator와 개별 peel을 중첩하지 않도록 먼저 원본을 수집한다.

결정: Space는 명시된 경로의 Git add를 사용하고 작업 상태만 재조회한다. 이유: 인덱스 의미를 Git에 맡기면서 기존 200개 페이지와 탐색 위치를 보존한다. 경로는 literal pathspec으로 전달하여 대괄호·공백·옵션처럼 보이는 파일명도 정확히 처리한다. F5는 기존 로컬 전체 재조회를 재사용한다.


## Unstage 결정

결정: 일반 저장소의 선택 경로 인덱스를 HEAD 기준으로 reset하고 첫 커밋 전에는 선택 경로만 rm --cached한다. 이유: 작업 파일 내용을 보존하면서 Git의 표준 인덱스 해제 의미를 따른다. rm의 --force는 작업 파일과 인덱스 내용이 다른 신규 파일에도 적용하기 위해 사용하며 --cached로 작업 파일은 유지한다.


## 지연 조회와 커밋 입력 결정

결정: 저장된 탭의 파일 경로는 비활성 상태에서 검증하지 않고 처음 활성화할 때 조회한다. 이유: 비활성 탭의 저장소 객체/이력 조회 비용과 오류 처리를 시작 시점에서 제외한다. 최초 조회 플래그로 중복을 막는다.

결정: 커밋 메시지는 GPUI의 실제 텍스트 입력 핸들러와 UTF-16 범위를 사용한다. 이유: 일반 키 이벤트만으로는 한글 IME 조합을 정확하게 처리할 수 없다. Git 메시지는 명령 문자열에 삽입하지 않고 stdin으로 전달한다.


## 커밋 입력 스크롤 결정

결정: 기본 overflow_scroll의 이동뿐 아니라 기존 공통 손잡이 계산을 재사용해 입력창에 보이는 스크롤바를 제공한다. 이유: 내용이 길다는 사실과 이동 위치를 표시하고 클릭/드래그로도 탐색할 수 있다. 실제 글꼴 폭을 사용해 짧은 메시지에는 바를 표시하지 않는다.


## 다중 인덱스 작업 결정

결정: 선택은 행 번호가 아니라 경로와 상태로 식별한다. 이유: stage 전환으로 같은 경로의 행 수가 바뀌어도 다른 파일을 잘못 선택하지 않는다. 명령은 상태별로 묶고 전체 경로를 먼저 검증한다. 서로 반대인 같은 경로는 stage 우선으로 통합한다. 오류 후 상태를 읽어 부분 성공을 숨기지 않는다.


## 폐기 확인과 전체 선택 결정

결정: 폐기 모달은 기존 캡처 경로를 그대로 사용하고 표시 목록과 버튼만 제거한다. 이유: Ctrl+S가 실행할 범위를 모달을 여는 시점과 동일하게 유지한다. 전체 선택은 기존 경로/상태 키 집합을 채워 Space/폐기 코드를 재사용한다.

## 포커스 표시 결정

- 결정: 기존 ListFocus와 실제 워크스페이스 포커스를 함께 사용한다.
- 이유: 키보드 대상과 선택 표시를 일치시키며 모달과 입력창을 구분한다.
- 대안: 섹션별 새 FocusHandle 도입은 기존 키 전달 구조를 바꾸므로 채택하지 않는다.
- 결정: 비활성 선택은 회색, 활성 선택은 기존 청록색을 사용한다.

## 최근 저장소 가상 목록 조사

결정: 기존 uniform_list/scroll_frame을 사용한다. 이유: 프로젝트에서 사용하는 가상 목록과 드래그 스크롤바를 재사용하고 고정 행 높이를 보장한다. 대안인 일반 overflow 스크롤은 모든 행을 렌더하므로 제외했다.
결정: 아이콘에서 선택창을 열고 삭제에만 별도 최종 확인을 유지한다. 이유: 목록 제거와 폴더 삭제를 분리해 기존 삭제 계약을 보존한다. 직접 삭제 실행은 요구에 맞지 않아 제외했다.

## 커밋상세 행 보정 결정

결정: 공통 선택색 계산을 커밋상세 행에도 적용한다. 이유: 일반 버튼의 active는 선택만 표현하고 키보드 포커스를 확인하지 않는다. 대안인 별도 포커스 상태 추가 대신 기존 Files 포커스를 재사용한다.

## 빈 탭 전환 원인과 결정

결정: 최근 저장소와 폴더 열기의 완료 처리를 통합한다. 이유: 최근 목록 open은 tabs.push로 새 탭을 만들지만 start_repository는 기존 탭을 대체해 불일치가 있었다. 대안인 빈 탭 전체 제거는 사용자의 다른 새 탭을 지우므로 제외한다. 순수 탭 전환 함수로 탭 수/순서/ID를 회귀 검증한다.

## 도움말 재구성 결정

결정: 다섯 섹션과 개별 키 행을 정적 목록으로 렌더한다. 이유: 표시 구성만 변경하고 키 기능을 보존한다. 브랜치/커밋히스토리에 제거된 행 이동을 다시 적는 대신 빈 안내를 표시한다. 길어진 목록에는 스크롤을 제공한다.

## 설정·인증 조사

- 결정: Git config 명시 범위와 GCM 표준 credential 프로토콜 사용. 이유: 설치 환경의 서비스별 OAuth 앱과 OS 자격 증명 저장을 재사용한다. 로컬 GCM 2.0.935에서는 최신 github 로그인 하위 명령이 없어 get/store/erase 호환 경로를 선택한다. 자체 OAuth 서버/토큰 저장은 도입하지 않는다.
- 결정: 전역 저장 후 현재 저장소 개별 사용자 키를 제거한다. 이유: 사용자가 전역 값을 현재 저장소에도 쓰도록 명확히 선택했다. 실패 시 관련 기존 키를 복구한다.
- 결정: URL 파싱은 이미 잠긴 url 2.5.8을 사용한다. HTTPS만 GCM 대상이며 SSH는 정보로 표시한다. 인증 버퍼와 원문 stderr는 화면·로그로 보내지 않는다.
- 근거: [Git credential 프로토콜](https://git-scm.com/docs/git-credential), [Git config](https://git-scm.com/docs/git-config), [GCM 설정](https://github.com/git-ecosystem/git-credential-manager/blob/main/docs/configuration.md), [GCM 환경 변수](https://github.com/git-ecosystem/git-credential-manager/blob/main/docs/environment.md).

## 브랜치·태그 조사

- 결정: Git branch로 생성만 수행하고 switch로 명시적 로컬 전환/추적 생성을 수행한다. 이유: 생성과 체크아웃 의도를 분리하고 변경 충돌 보호를 Git에 맡긴다. 강제 옵션과 원격 푸시는 사용하지 않는다.
- 결정: 원격 이름 접두어를 실제 remote 목록으로 해석한다. 이유: 슬래시가 있는 브랜치나 원격 이름을 잘못 잘라내지 않기 위해서다. 원격 HEAD는 symbolic-ref로 실제 대상에 연결한다.
- 결정: 태그는 기존 페이징 세션의 ID별 장식 목록으로 전달한다. 이유: 화면에서 매 행마다 전체 참조를 검색하지 않고 초기/추가 페이지를 동일하게 처리한다.
- 근거: [Git switch](https://git-scm.com/docs/git-switch), [Git branch](https://git-scm.com/docs/git-branch), [Git 참조 이름](https://git-scm.com/docs/git-check-ref-format).

## 스태시 결정

기존 Git CLI의 --include-untracked를 사용한다. Git 인덱스 보존과 저장 규칙을 활용한다. --all은 ignored까지 치우므로 제외한다.

## 스태시 복원 결정

삭제 없는 apply --index를 선택한다. 사용자가 목록에서 다시 사용할 수 있고 충돌 시 원본도 보존된다. 순번 대신 조회된 커밋 해시로 적용해 추가 stash에 따른 순번 변경을 피한다.

## 이름·삭제 결정

이름은 기존 단일 행 편집기를 사용한다. 셸 결합 없이 --message 인수로 전달한다. 삭제는 확인 시 캡처한 selector와 해시를 재검증하여 다른 스태시를 지우지 않는다. 순번 변경 시 목록을 새로 조회한 뒤 다시 선택하게 안내한다.

## 참조 작업 결정

태그는 메시지 없는 lightweight 생성이며 Git CLI의 이름 검증을 사용한다. Local 삭제는 기존 Git 안전 삭제로 정하고 설정의 저장 단축키는 유지한다. Remote는 서버 삭제와 추적 참조 삭제의 효과가 달라 사용자 답변을 확인한다.

Remote 사용자 답변: d는 추적 참조만, Shift+d는 서버도 삭제한다. push의 명시적 lease로 서버 변경을 보호한다.

## 입력 넘침과 체크아웃 결정

입력 편집기 루트가 단일 행에서도 220px 고정 높이여서 36px 래퍼 밖으로 배경이 튀어나간다. 단일 행은 부모 높이를 사용하고 클리핑을 추가한다. 원격 생성은 빈 기대값의 lease로 기존 브랜치 덮어쓰기를 거절한다. 커밋/태그 체크아웃은 switch --detach로 작업 변경 보호를 유지한다.

## 브랜치 후보 결정

브랜치는 커밋의 조상이 아니라 직접 가리키는 ref로 판별한다. Local/Remote를 모두 보여주고 종류를 표시한다. 원격 HEAD는 동일 브랜치 별칭이므로 제외한다. 조회 후 대상이 이동한 경우 체크아웃을 거절한다.

## 중복 후보 결정

origin/feature/nested와 Local feature/nested를 같은 이름으로 비교한다. 원격 이름에 슬래시가 있어도 가장 긴 등록 원격 접두사를 사용한다. Local의 커밋 위치와 무관하게 Remote를 후보에서 제외한다.

## 팝업 구조 결정

팝업은 이미 공통 backdrop을 사용하지만 제목·본문·버튼이 각 분기에 섞여 있다. 공통 프레임에서 header/body/footer를 배치하고 기존 이벤트를 그대로 전달하여 동작을 보존한다. 제목은 기존보다 작은 13px로 통일한다.

## 현재 브랜치 판별

커밋 ID만 같으면 서로 다른 브랜치까지 무시하므로 symbolic HEAD의 전체 ref를 비교한다. UI는 이미 읽은 current_branch로 빠르게 무시하고 백엔드도 실제 HEAD를 확인한다.

## 라이트 테마 결정

밝은 회색 앱 배경과 흰 패널에 짙은 회청색 텍스트를 사용한다. 청록 강조는 밝은 화면에서도 읽히도록 어둡게 하고 상태/그래프도 어두운 채도로 바꾼다. Diff는 연한 상태 배경과 어두운 상태 텍스트로 조합한다. 공통 팔레트로 분산된 색상 차이를 방지한다.

## 그래프 잘림 원인

기존 그래프는 고정 12px 레인 간격에 열 내부 패딩/클리핑을 사용한다. 여러 레인이 있거나 Graph 열을 좁히면 오른쪽 노드가 열 밖으로 나갈 수 있다. 모든 행에 동일한 레인 수와 폭 기반 좌표를 적용하고 좌우 8px를 확보한다.

## 원·텍스트 렌더 결정

이전 좌표 경계 수정만으로 충분한 폭의 잘림이 해결되지 않아 노드의 rounded quad 렌더를 대칭 벡터 원으로 교체한다. 메타데이터는 문자열을 보존하고 run만 나눠 라벨을 굵게 하므로 기존 텍스트 복사·선택 좌표를 유지할 수 있다.

## 색상 역할 분리

선택 배경과 강조 글자를 별도 토큰으로 유지한다. HEAD 반지름 7.5px는 기존 좌우 8px 여백 안에 들어간다.

## 확대 대상 정정

사용자가 지칭한 원은 배지 안의 현재 브랜치 표시다. 배지 이름과 독립 요소로 나눠 원만 키운다.

## 원 높이 원인

큰 ● 문자는 폰트 줄높이를 키워 flex 배지 높이를 확장한다. 고정 크기 canvas로 바꾸면 배지 높이와 원 중심을 독립적으로 제어할 수 있다.

## 표시 필터 결정

조회 결과를 삭제하면 다른 내부 용도에 영향을 주므로 원본 참조를 유지하고 목록 인덱스와 배지 구성만 필터한다.

## 선명도 결정

열/스크롤 원점과 압축된 레인 좌표가 분수 픽셀에 걸릴 수 있고 125% 배율에서 2 논리 px 선은 2.5 물리 px가 된다. 정수 물리 두께와 반 두께에 맞춘 중심 정렬로 불필요한 퍼짐을 줄인다.

## 실제 굵기 문제 원인

설치된 GPUI text_system.rs의 layout_line 547~565행은 색/밑줄 등이 같으면 폰트 차이를 보지 않고 병합한다. shape_text는 455~468행에서 먼저 font_id를 확인하므로 굵기를 보존한다. 기존 코드의 run 분리만으로 충분하다고 판단한 검증이 부족했다.

## 범위 밖 이벤트 원인

이동 핸들러가 bounds.contains와 viewport.contains를 둘 다 요구해 뷰어 밖 포인터를 무시한다. 이미 window 전역 캡처 이벤트를 사용하므로 시작 조건은 유지하고 이동에만 경계 clamp를 적용한다.

## 키캡 결정

키 이름만 배지로 만들고 +는 배지 밖에 둔다. 버튼의 일반 이름과 원격/브랜치 레이블은 키 패턴을 검증해 오인하지 않는다.

## 원격 생성 선택

기존 안전한 publish_branch를 재사용한다. 원격 선택은 origin 또는 유일 원격이며 Local 생성 전 선택 가능성을 검증한다. publish 실패는 Local 성공과 구분해 안내한다.

## 표시·이벤트 결정

체크 문자 두 종류는 폰트 glyph 경계가 달라 크기가 변한다. 벡터 박스를 고정한다. 입력은 content canvas 상단부터 그려 2px 위로 치우쳤으며 단일 행에 중앙 오프셋을 추가한다.

## 체크 여백 원인

빈 문자열 라벨을 가진 버튼에 체크박스를 child로 추가하면서 빈 라벨 줄과 기존 큰 패딩이 남았다. 빈 라벨을 생략하고 체크 항목 패딩만 줄인다.

## 포커스 결정

팝업 내부 입력 목록을 명시해 Tab이 텍스트에 입력되거나 배경으로 이동하지 않게 한다. 체크박스는 표시/동작에 FocusHandle을 붙이고 Space 전환을 지원한다.

## Space 이중 실행 근거

GPUI 0.2.2 elements/div.rs 2180행 부근은 포커스된 on_click 요소에 Space KeyUp의 KeyboardClickEvent를 생성한다. 기존 수동 KeyDown 처리와 겹쳤으므로 수동 처리만 제거한다.

## 포커스 이동 결정

기존 ListFocus와 공통 FocusHandle을 재사용하면 저장소 조회나 선택 변경 없이 섹션 키 동작을 연결할 수 있다.

## 선택 복원 결정

현재 최초 200개 안에서만 선택 커밋을 인정해 오래된 선택이 재조회 때 사라진다. 실제 커밋 객체로 검증하고 선택 위치까지 페이지를 복원한다.

## 선택과 이동 분리

branch revision 선택과 history_target 탐색을 분리하여 목록 탐색이 히스토리를 계속 로드하지 않게 한다. 입력창에서는 ijkl을 문자로 유지한다.

## 포커스 원인

공통 체크아웃 후처리가 항상 Local 탭과 Branches 포커스로 덮어쓰고 있었다. 시작한 섹션 상태를 그대로 사용한다.

## Reset 실행 결정

기존 Git CLI와 모달 진행/오류/재조회 구조를 재사용한다. reset의 파괴 범위는 모드 선택 시 설명하고 실제 실행은 확인 클릭/단축키에서만 한다.


## 히스토리 작업 결정

기본 Git merge/rebase 의미를 따른다. merge는 --no-edit, revert는 --no-edit 또는 --no-commit을 사용한다. rebase 편집기는 비대화 환경으로 제한한다. 충돌은 사용자가 해결할 수 있도록 보존하고 재실행을 거절한다. 전체 히스토리는 백그라운드에서 읽고 가상화하여 렌더링한다.


## 단축키 설정 조사

결정: 기존 명령 키 정규화와 공통 목록을 사용한다. 근거: 기존 비동기 동작·선택·모달 보호를 재사용하며 표시/설정/실행의 데이터 원천을 통일한다. 대안: 실행 분기 전체 재작성은 변경 범위가 커 선택하지 않았다. 로컬 GPUI Keystroke 파서와 이벤트 정의를 확인했다. 추가 라이브러리나 미확정 기술은 없다.


## 방향 선택 확장 목록 결정

결정: 공용 표 렌더링에서만 제외한다. 근거: 사용자 요청은 목록 제거이며 키 처리까지 삭제하면 기존 Shift 범위 선택이 사라진다. 별도 데이터 모델 변경이나 외부 조사는 필요 없다.


## 확인창 제어 통합 결정

결정: 설정 ID 네 개를 공유하고 실행 직전에 창별 기존 명령으로 변환한다. 기존 비동기 확인과 조합·실행 중 보호를 유지하기 위한 선택이다. 외부 의존성이나 미확정 기술은 없다.


## 커밋 체크박스 결정

기존 CommitDialog의 push_after 상태와 공통 checkbox·팝업 footer를 재사용한다. 확인 시 한 번 상태를 읽어 실행하므로 클릭과 키보드 경로가 같다. 외부 의존성이나 조사할 미확정 기술은 없다.


## 설정 탭 결정

기존 GROUPS 배열과 button의 선택 상태를 재사용한다. 그룹 데이터나 키 저장 형식을 바꾸지 않고 표시만 필터링하므로 기존 설정을 보존한다. 외부 의존성이나 미확정 기술은 없다.


## 히스토리 대상 행 제거 결정

표시 분기만 변경하면 실행 상태와 기존 작업 로직을 보존할 수 있다. 새 데이터 모델·의존성·외부 조사 항목은 없다.


## 단축키 승인 상태 결정

활성 설정 복제본을 팝업 수명 동안 유지하면 전 탭 편집과 복원을 원본에 영향 없이 처리할 수 있다. 저장 성공 후 활성 설정을 대입하여 실패 시 무변경을 보장한다. 기존 session::save의 임시 파일 저장을 재사용하며 외부 의존성은 없다.


## 헤더 제거 결정

설정과 도움말은 공용 렌더러를 사용하므로 editable 조건으로 헤더 표시를 제한한다. 패딩 요청은 소스 변경 전 취소되어 여백을 변경하지 않는다. 외부 조사·새 데이터 모델은 필요 없다.


## 고정 높이 결정

프레임의 선택 높이와 본문 가용 공간 확장을 사용하면 짧은 탭도 footer 위치를 유지하고 긴 목록은 기존 overflow_y_scroll을 재사용할 수 있다. 다른 팝업은 선택 높이 없이 기존 동작을 유지한다.


## 통합 범위 결정

사용자 정정에 따라 공통 정의만 통합한다. nav ID를 유지하면 기존 방향 설정을 보존할 수 있다. 공통 입력전환은 별도 적용 범위를 사용하여 브랜치·파일목록 Space와 독립적으로 설정한다. 실제 범위 교집합을 사용하면 공통 키와 충돌을 놓치지 않는다. 외부 의존성은 없다.


## Stage 범위 결정

단축키 해석 시 별도 Stage 파일 범위를 사용하면 키 재정의에도 동일 조건을 적용하고 설정 충돌도 정확히 검사할 수 있다. 기존 ID를 유지하여 저장된 키가 보존된다. 외부 의존성은 없다.


## 하위 분류 공유 결정

사용자 답변에 따라 공통 기능을 각 하위 분류에 반복 표시하면서 같은 저장 ID를 참조한다. 실제 RefTab::ALL과 FileTab 순서에 맞춘 분류를 사용한다. 내부 숫자키 정의를 지우지 않고 표시 필터만 사용하여 기존 동작을 보존한다. 외부 의존성은 없다.


## 삭제 체크박스 범위 결정

기존 server 옵션은 Remote 참조만 대상으로 하며 Local/Tag 처리에서 원격을 추정하지 않는다. 동일 범위를 유지하면서 UI에서 체크로 선택하도록 바꾼다. 새 데이터 모델·라이브러리·외부 조사는 필요 없다.


## 연결 삭제 설계 결정

upstream은 실제 관계의 근거이며 이름 유사성은 사용하지 않는다. remote fetch refspec의 목적지에서 서버 원본을 역매핑하여 사용자 지정 추적 이름도 안전하게 처리한다. 서버 변경에는 force-with-lease를 유지한다. 로컬과 서버의 분산 트랜잭션은 없으므로 전 대상 선검사·원격 먼저·부분 실패 명시를 사용한다. 기존 Git 실행 도우미와 gix 모델을 재사용하며 새 라이브러리는 없다.


## 브랜치 우선 결정

사용자가 공통과 충돌할 때 브랜치 우선을 명시했으므로 별도 공통 키 삭제 대신 해석 우선순위를 사용한다. 같은 그룹 중복은 거절하고 브랜치/공통 중복만 허용한다. Local 전용 범위를 두면 Remote·Tag·Stash의 공통 푸시는 유지된다. 추가 라이브러리는 없다.


## 기본 키 복원 결정

안정 ID의 기본값만 되돌리면 기존 사용자 설정과 실행 경로를 유지한다. 외부 조사·새 데이터 모델은 필요 없다.
## 팝업 입력 드래그 조사 (US86)

- 결정: 공통 카드의 왼쪽 버튼 누름 전파를 차단한다.
- 근거: 설치된 GPUI 0.2.2의 div 클릭은 버블 단계에서 누름을 저장하고 해제 시 해당 hitbox 위에 있으면 실행한다. 배경은 카드도 포함하므로 내부 누름이 전달되면 외부 해제도 클릭이 된다. 기존 카드 클릭 차단은 외부 해제에 실행되지 않는다.

## 커밋 줄바꿈 조사 (US87)

결정: 메시지 포커스의 Shift+Enter를 단축키 해석보다 우선하여 편집기로 전달한다. 근거: 편집기는 이미 Shift를 허용하는 Enter 줄바꿈을 구현하지만 상위 캡처가 사용자 단축키를 먼저 해석한다. 대안인 별도 줄바꿈 삽입은 IME·선택 처리 중복을 만든다.

## 파일 트리 조사 (US88)

결정: 원시 경로를 계층으로 나누고 원본 인덱스를 행에 저장한다. 이유: 표시 문자열로 경로를 해석하면 비 UTF-8 경로가 충돌할 수 있고 파일 배열 정렬은 선택/실제 작업의 인덱스를 깨뜨린다. 모드와 접힘은 실행 중 UI에만 저장한다. 대안인 파일 데이터 재정렬과 매 렌더 전체 트리 생성은 피한다.

## 폴더 Stage 결정 (US89)

기존 toggle_files는 경로별 목표 Stage bool 맵을 검증하고 일괄 처리하므로 새 Git 명령을 만들지 않는다. 폴더에는 원시 경로 + / 경계를 사용해 src2 같은 형제 경로를 제외한다. 혼합 상태는 전체 Stage로 통일하여 다음 Space에서 전체 Unstage가 되게 한다. 기존 US88 접힘 상태는 사용자 지시에 따라 제거한다.

## Local upstream 연결 결정 (US90)

Git branch --set-upstream-to를 사용해 체크아웃 없이 선택 Local의 remote/merge 설정을 갱신한다. 후보는 Fetch된 참조와 remote fetch refspec을 사용하며 기존 역매핑 함수를 재사용한다. 사용자 매핑을 지원하기 위해 refs/remotes 이름만 추정하지 않는다. Local 푸시 UI만 제거하고 생성 옵션의 publish_branch는 유지한다. 과거 단축키 ID와 새 ID를 분리한다.

## 라디오/스크롤 결정 (US91)

공통 radio와 FocusHandle을 재사용하고 선택 인덱스는 유지한다. 기존 max_h만 있는 flex 목록은 행이 축소될 수 있으므로 고정 행 높이와 flex_shrink_0를 적용한다. 8행을 넘으면 내부 ScrollHandle로 이동한다. 별도 라디오 상태나 Git 실행 경로는 만들지 않는다.

## Merge 상태·복구 결정 (US92)

Git 공식 merge 문서의 --continue/--abort를 사용하고 강제 Reset을 쓰지 않는다. 충돌은 인덱스 미병합 stage로 판정하며 작업 파일 마커 문자열로 추측하지 않는다. gix Repository.path는 linked worktree의 실제 git 디렉터리를 가리키므로 MERGE_HEAD를 읽고 worktree 테스트로 검증한다. Git이 기본 MERGE_MSG로 커밋하도록 편집기 대기를 막는다. 기존 status의 경로별 인덱스 재탐색을 충돌 집합으로 대체해 미병합 파일을 중복 없이 표시한다. Abort 확인에는 해결 내용 손실과 병합 전 변경 복원의 한계를 명시한다. Rebase/Revert·내부 병합 편집기는 범위 밖이다.

## Rebase 복구 결정 (US93)

Git 공식 rebase 문서의 --continue/--abort/--skip을 사용한다(https://git-scm.com/docs/git-rebase). 단계별 충돌은 Continue가 비정상 종료해도 Git이 정상적으로 다음 해결을 기다리는 경우이므로 같은 세션의 새 단계·새 충돌인지 재조회해 구분한다. merge/apply 메타데이터를 실제 저장소 테스트로 확인하며 applying만 있는 git am은 제외한다. 기존 커밋 메시지로 계속하고 편집기 대기를 막는다. Merge의 상태/실행 경로를 유지하면서 표시·가드는 공통화한다.

## Revert no commit 복구 결정 (US94)

공식 문서(https://git-scm.com/docs/git-revert)의 Continue/Abort/Skip/Quit를 검토하고 설치 Git으로 실험했다. 단일 -n과 ^! 시퀀스 -n 모두 충돌 후 --continue에서 커밋이 생성됐으며 -n --continue 결합도 거절됐다. 따라서 단일 no commit은 해결 내용을 Stage한 뒤 --quit로 상태만 종료한다. ^!는 초기 옵션을 sequencer/opts에 남겨 재실행 후 모드를 판정하기 위한 것이다. 커밋 없는 다중 외부 시퀀스는 임의로 상태/목록을 재작성하지 않고 안내한다. 외부 단일은 옵션을 복원할 근거가 없으므로 확인창에서 선택한다. 중단/건너뛰기는 Git의 기본 동작과 변경 손실 안내를 사용한다.

충돌 없이 no commit이 성공한 경우에도 Git이 남길 수 있는 REVERT_HEAD를 --quit로 정리하여, 완료된 작업을 진행 중으로 잘못 표시하지 않게 한다. 이 정리는 HEAD·인덱스·작업 내용을 변경하지 않으며 기존 성공 경로 회귀 테스트로 검증했다.

## Stash 복구 결정 (US95)

Git stash 공식 문서(https://git-scm.com/docs/git-stash)의 apply --index는 충돌/실패 후 자동 Abort가 없고 원본 Stash를 유지한다. 따라서 앱의 적용 전에 원본 파일/인덱스를 보관하며 강제 Reset을 사용하지 않는다. rename 병합으로 기존 경로가 바뀔 수 있어 추적 경로와 Stash의 작업/인덱스/미추적 트리 경로 합집합을 보관하고 실제 변경 경로만 취소한다. 외부 apply에는 출처/백업을 추측하지 않는다. 안전하게 원복할 수 없는 특수 경계는 실행 전 거절하며, 원본 백업이 손상되거나 다른 Stage/HEAD가 바뀌면 취소하지 않는다.

원본 Stage 객체는 복구 전용 Git 참조에 트리로 고정해 정리 작업에도 보존한다. 원본 인덱스와 별도로 분할 인덱스를 해제한 전체 사본을 보관하며, 공유 인덱스가 사라지면 검증한 전체 사본으로 복구한다. Windows Git에 전달하는 인덱스 경로는 확장 경로 접두사를 제거한다.

## US96 조사

결정: 원문 바이트 범위 기반 치환을 사용한다. 이유: Diff 표시용 탭/개행 변환을 저장에 사용하면 원문이 손상된다. 대안인 전체 파일 ours/theirs checkout은 구간별 선택 요구를 만족하지 않는다. 기존 gix 인덱스 조회와 안전한 작업 파일 검증을 재사용하며 별도 기술 조사 미확정 사항은 없다.

## US97 조사

결정: 원문 줄 좌표로 선택 결과를 재구성하고 Git apply --cached로 반영한다. 이유: 표시 문자열에는 탭/줄바꿈 변환이 있으므로 패치 원문으로 사용할 수 없고 파일 전체 git add는 미선택 내용을 포함한다. 기존 인덱스 객체를 기준으로 해야 이미 Stage한 변경이 보존된다. 대안인 대화형 git add -p는 앱 줄 선택과 비대화형 처리가 맞지 않는다. 기술 미확정 사항은 없고 실제 저장소 테스트로 Git 패치 해석·특수 경로·개행을 검증한다.

## US98 조사

결정: 기존 텍스트 커서와 작업 파일 new 줄 좌표로 구간을 판정한다. 이유: 스크롤 위치나 이전 선택 구간으로 추측하면 다른 충돌을 해결할 수 있다. 원문 시작/종료 마커를 포함한 줄 범위는 CRLF·diff3에서도 동일하게 판정할 수 있다. 대안인 스크롤의 첫 충돌이나 선택 범위 전체 적용은 사용자 지시와 다르므로 제외했다. 기존 viewer 단축키 매핑에 등록하여 사용자 재지정과 도움말을 유지하며 미확정 기술 사항은 없다.

## US99 버튼 키 안내 조사

결정: 기존 Bindings.label과 키캡을 재사용한다. 이유: 실행과 안내를 같은 명령 ID로 연결한다. 대안: 기본 키 직접 표기는 재지정과 불일치하므로 제외한다. 미확정 기술 사항은 없다.

## US100 오류 수명 조사

결정: 오류 출처별 마지막 상태를 추적하고 변경 알림에서 기록하며 렌더링에서도 보완한다. 이유: 렌더링마다 추가하면 중복되고 활성 탭만 추적하면 다른 탭의 오류를 놓친다. 대안: 3초 상태 문자열만 저장하는 방식은 이후 열람과 복수 오류를 지원하지 못한다. 기록은 메모리에 두며 새 오류가 와도 선택 페이지를 유지한다.

## US101 바깥 클릭 조사

로컬 GPUI 0.2.2의 on_mouse_down_out은 카드 경계 밖 입력을 캡처 단계에서 통지한다. 바깥 입력을 소비하여 배경 작업의 실행을 막고 카드 내부 입력은 기존 이벤트를 사용한다. 확인완료는 관찰 상태를 유지한 채 기록만 제거하여 아직 활성인 오류가 즉시 다시 생기지 않게 한다.

## US102 단축키 범위 조사

오류 기록은 일반 영역과 작업 팝업 모두에서 접근하는 전역 명령으로 등록한다. 재지정 충돌 검사도 모든 영역과 겹치게 하여 다른 확인 키를 가로채지 않는다. Ctrl+S는 확인의 기본 입력에서만 제거하며 Enter에서 기존 내부 확인 경로로 변환하는 처리는 유지한다.

## US103 선택 의미 조사

텍스트 선택 끝점은 반개방 범위를 사용하므로 다음 줄 0열은 대상에서 제외한다. 번호 없는 헤더는 선택 범위 내부에는 존재할 수 있지만 끝점과 체크 대상에서는 제외한다. 유효 행의 참조 목록으로 커서를 이동하면 헤더를 건너뛰면서 기존 문자/줄 경계 이동을 유지할 수 있다.

## US104 레이아웃 조사

로컬 GPUI 0.2.2 deferred는 자식 레이아웃을 현재 트리에 두고 그리기만 뒤로 미룬다. 이를 사용하면 재지정된 F11/F12 키 길이에 따라 실제 오류 표시 위치가 자동 조절되고 기존 작업 팝업 위에서도 오류 표시에 접근할 수 있다. 고정 우측 오프셋 계산은 사용하지 않는다.

## US105 흰 배경 원인

src/theme.rs에서 PANEL은 0xffffff이고 BG는 0xf3f5f8이다. 오류 표시가 PANEL을 명시해 저장소 하단에서 흰 영역이 생겼다. 두 하단과 표시를 기존 BG로 통일하며 전역 테마는 변경하지 않는다.

## US106 재발생/복사 조사

문구 기반 관찰만으로는 같은 값 대입을 구분할 수 없다. 실제 실패 대입에서 기록하고 관찰 기준을 갱신하면 화면 갱신 중복을 막으면서 재시도는 새 건으로 남길 수 있다. 기존 CommitEditor의 Unicode 선택/스크롤/복사를 읽기 전용으로 재사용해 오류 문자열의 임의 편집을 막는다.

## US107 F11 어두움과 밝은 배경 원인

F11은 단축키 팝업을 열고 기존 backdrop이 뒤를 어둡게 한다. 오류 표시는 deferred로 위에서 그리며 불투명 BG를 명시해 밝은 사각형이 남았다. 기본 알파를 0으로 명시하고 붉은 hover를 유지한다.

## US108 표시상 줄바꿈 조사

기존 편집기는 원문 줄 하나를 하나의 ShapedLine으로 만들고 내용 폭만큼 가로 스크롤한다. 읽기 전용 오류에서만 실측 폭으로 바이트 범위를 나누고 각 표시 행의 원문 시작 인덱스를 유지하면 복사 원문과 기존 마우스 선택 좌표를 보존할 수 있다.

## US109 네 건 발생 원인

submit_branch 실패가 refresh_after_branch에서 workspace report를 호출한 뒤 같은 결과를 branch-dialog report로 다시 기록했다. 단순 전달용 mirror가 필요하다. GPUI KeyDownEvent.is_held는 누르고 있는 키 반복을 구분하므로 기존 브랜치 확인 반복도 막는다. 실제 충돌 경로는 stderr 문구 추측 대신 기존 인덱스 기반 revert_state.conflicts를 사용한다.

## US110 탭 전환 조사

참조 탭 순서는 RefTab::ALL에 있고 파일은 Stage/History다. 기존 키 해석은 영역별 scope가 있으며 서로 다른 두 영역에 같은 키를 둘 수 있다. 파일 탭의 클릭 전환에 선택/차이 초기화 정책이 있으므로 키에서도 같은 메서드를 사용한다.

## US111 중복 이벤트 원인

로컬 GPUI 0.2.2 elements/div.rs는 track_focus와 on_click이 있는 요소에서 Space/Enter keyup에 ClickEvent::Keyboard를 합성한다. Workspace는 이미 keydown에서 상태를 바꾸므로 keydown 전파 차단만으로 keyup 토글을 막을 수 없다. 클릭 핸들러를 Mouse로 제한하고 키 반복은 별도로 소비한다.

## US112 키 해석 조사

설정 팝업은 캡처를 먼저 처리한 뒤 modal 키를 해석한다. 전용 scope로 바꾸고 캡처 순서를 유지한다. 프로젝트 키는 URL 입력의 clone scope에도 적용하되 다른 팝업에서는 제외한다. 원격 키의 target과 default를 분리하면 기존 UI 명령 실행 분기를 바꾸지 않아도 새 기본 조합이 동작한다.

US112 추가 결정: 내부 탭 이전/다음은 사용자 요청대로 공통 한 쌍이다. 기존 영역별 네 명령은 제거하고 tabs 범위를 목록/설정 팝업에 적용한다.

## US113 중복 조사

전체 선택과 체크아웃은 동일 target이지만 영역별 별도 ID로 등록되어 있었다. 브랜치 하위 탭과 파일 트리는 같은 ID가 여러 섹션에 표시되었다. 전자는 기준 ID/공유 범위로 합치고 후자는 표시 분류만 합친다. 저장된 양쪽 키가 다르면 기준 ID를 우선해 결과를 결정 가능하게 한다.

## US120 결정

작성자 저장 범위를 체크 상태로 추론하지 않고 버튼으로 명시한다. 전역 저장은 개별 override 삭제를 수반하지 않는다. 기존 GitContext 읽기/쓰기·rollback을 재사용하며 실제 사용자 전역 파일 대신 격리 테스트를 사용한다. GPUI 포커스 버튼의 keyup 합성 클릭과 수동 keydown이 중복되지 않게 마우스만 클릭 처리한다. 좌우 탐색 scope를 분리해 탭 방향키와 충돌하지 않게 한다.

## US121 결정

내부 탭은 별도 키 명령 대신 nav-left/right 동작을 공유한다. 프로젝트는 사용자 답변에 따라 독립 설정을 유지하며 Ctrl+좌우 및 Ctrl+J/L 두 기본 슬롯을 제공한다. 과거 내부 탭 override는 무시하고 공통 방향 override를 우선한다. 프로젝트 override는 보존한다.

## US122 결정

전역 사용은 전역 파일을 편집하는 모드가 아니라 현재 저장소가 전역 작성자를 상속하는 모드다. 체크는 화면 draft만 전환하고 저장 시 local 두 키만 제거한다. 해제하면 이전 개별 draft를 복원한다. read-only는 기존 입력 보호를 재사용하되 단일행의 가로 표시를 유지한다.

## US127 기술 결정

gix 조회를 보존하고 git2로 프로세스 생성 비용을 제거한다. libgit2는 작업 API를 제공하지만 Git CLI 전체 orchestration을 자동 대체하지 않으므로 안전 체크·상태 보존·후속 복구는 앱에서 구성한다. 네트워크는 로컬 remote로 검증하고 인증 helper는 직접 호출한다. 테스트에서만 Git 정답 도구를 허용한다.

### US127 gix 우선 정책으로 변경

사용자는 gix를 사용할 수 있는 곳에 우선 사용하도록 명시했다. 현재 버전의 config File 파싱/수정·ref transaction·write_blob/commit·index 편집 API를 확인했다. 따라서 로컬 기본 작업을 일괄 git2로 바꾸지 않는다. 복합 로컬 작업의 git2 허용 여부는 확인 중이며 의존성이 필요한 구현은 답변 후 확정한다. git2 0.21.0은 로컬 캐시로 오프라인 컴파일 가능함을 확인했다.

### US127 구현 검증에서 확인한 차이

사용자 답변으로 복합 로컬 작업은 git2로 확정했다. Windows 확장 경로 접두사를 libgit2 호출 경계에서 정규화한다. split-index는 gix로 펼쳐 libgit2가 읽을 수 있게 하며 Stash 백업/취소는 원래 Stage 의미를 보존한다. gix index 쓰기는 읽기 전에 잠금을 획득하고 부분 Stage는 잠금 안에서 이전 항목을 비교한다. gix 필터 파이프라인·커밋 서명 API를 사용해 줄바꿈/파일 속성/서명을 처리한다. git2의 인덱스 핸들은 공유될 수 있으므로 복사 전 항목을 소유한 뒤 대상 인덱스를 비운다.

제품 코드의 기존 문자열 요청 경계는 인프로세스 라이브러리 dispatcher로 유지했다. std::process::Command 기반의 Git 실행은 테스트 fixture/oracle에만 남기고 로그인 helper는 실행 파일을 직접 호출한다. Git2의 기본 credential_helper는 내부에서 Git을 호출할 수 있어 사용하지 않는다. 원격은 명시적 자격 증명 콜백 및 SSH agent/GCM 직접 호출을 사용한다.

gix-path의 Windows system_prefix()는 git --exec-path를 호출할 수 있다. 제품 opener에서는 이 자동 시스템 탐색을 비활성화하고 실행 파일을 호출하지 않는 직접 파일 조회로 바꿨다. 단순히 앱 소스의 Command 호출만 제거하면 충분하지 않다는 점을 라이브러리 소스에서 확인했다.

## US128 설정 불일치 조사

스테이징은 native_local::repo에서 시스템 설정을 직접 병합하지만 조회의 git::open은 시스템 설정을 제외한 채 열고 있었다. 같은 파일의 정규화가 달라 A/M 이중 행을 만들 가능성이 있다. 공통 열기 함수에 조회의 외부 필터 차단 옵션을 전달한다. Git 실행으로 시스템 경로를 탐색하지 않는다.

## US129 팝업 구성 결정

추가와 삭제가 같은 표시 분기를 공유하므로 삭제 설명만 조건부로 보존한다. 입력 라벨은 기존 커밋 메시지 라벨과 같은 MUTED 스타일을 사용한다. 미해결 기술 사항은 없다.

## US130 그래프 탐색 결정

스태시 본체를 탐색 시작점에서 제외하면 내부 보관 커밋과 공유 조상을 별도 식별할 필요가 없다. 브랜치·태그·HEAD에서 도달하는 커밋을 사후 필터링하지 않는다. 스태시 선택은 기존 load_commit 직접 조회를 사용하므로 그래프 밖이어도 내용을 읽을 수 있다.

## US131 배경색 결정

기존 theme::BG(0xf3f5f8)는 연한 회색이고 INPUT은 흰색이다. 공통 입력과 스크롤바에 동일 조건을 적용하여 스크롤 시 흰색 띠가 생기지 않도록 한다.

## US132 패딩 누락 원인

세팅 field의 p_1 래퍼에는 배경이 없어서 내부 입력의 회색이 패딩에 적용되지 않았다. 래퍼와 내부가 공통 상태별 배경색을 사용하도록 한다.

## US133 포커스 경로 조사

저장 핸들이 Tab 목록·track_focus·클릭 focus·키 활성화에 사용된다. Tab만 제외하면 클릭 포커스가 남으므로 저장 핸들을 완전히 제거하고 체크박스 전용 핸들을 유지한다.

## US134 원격 추가 결정

기존 config_set은 잠금 후 원자 교체한다. 두 번 설정하면 부분 저장이 가능하므로 공통 편집 함수 안에서 URL과 fetch를 함께 쓴다. 팝업 상태는 SettingsPanel에 두어 초안과 비동기 수명을 유지한다. 기존 modal 카드 제목·본문을 전환하고 닫기는 하위 팝업을 우선 처리한다.

## US135 동시 표시 결정

현재 세팅 엔티티는 유지되지만 본문과 카드 제목을 추가 화면으로 바꾸어 세팅이 보이지 않는다. 세팅을 계속 렌더하고 같은 상태를 읽는 별도 modal 프레임을 그 위에 추가한다. 기존 settings-body 식별자를 유지하여 스크롤 상태를 보존한다. 별도 OS 창 대신 기존 공통 팝업 스타일을 사용한다.

## US136 하단 경계 조사

URL은 원격 추가 본문의 마지막 요소이며 공통 팝업은 본문을 스크롤 경계로 자른다. 본문의 하단 여백을 확보하고 입력 래퍼의 축소를 막는다. 공용 overflow 제거는 작은 창의 스크롤을 잃으므로 적용하지 않는다.

## US137 삭제 경계 결정

URL 설정만 지우면 원격 추적 참조가 남을 수 있다. git2 remote_delete의 표준 로컬 원격 제거를 사용하여 관련 추적 설정·참조도 정리한다. 목록 전체가 아닌 원격별 묶음에 삭제 아이콘 하나를 표시하고 추가 팝업과 저장 작업 중 실행을 차단한다.

## US138 안정적인 삭제 포커스

배열 인덱스별 핸들은 삭제 후 다른 원격을 가리킬 수 있으므로 이름별 맵을 사용한다. 렌더마다 핸들을 생성하지 않고 실제 목록 갱신 시 동기화한다. 기존 Space·확인 공통 처리에는 삭제 허용 여부를 전달하여 확인 단축키가 삭제로 이어지지 않게 한다.

## US139 실제 오류 누락

native_remote::fetch의 map_err가 git2::Error를 버리고 고정 안내만 반환한다. 사용자 ls-remote 성공은 주소 접근을 증명하지만 앱의 라이브러리 전송 원인을 증명하지 않는다. 오류 class/code와 가림 처리한 원문을 보존해야 원인을 판단할 수 있다. 실행 환경의 GitHub 연결은 실패하므로 실제 원격 재현은 사용자 환경에서 수행해야 한다.

### US139 git2 기능 누락 확인

설치된 git2 0.21.0의 기본 기능은 비어 있다. https는 명시적 기능이며 libgit2-sys HTTPS를 켠다. Version::get().https()로 실제 링크된 라이브러리 지원을 검사한다. Windows는 운영체제 TLS 구현을 사용하며 Unix용 선택 의존성은 Cargo 해결 과정에 포함될 수 있다.

## US140 인증 구현 결정

브라우저 로그인은 사용자 답변에 따라 GCM과 독립을 모두 지원한다. GCM은 외부 설치 계정을 재사용하고 독립은 GitHub Device Flow를 사용해 Client Secret을 앱에 넣지 않는다. Client ID는 사용자 입력이며 Device Flow를 켠 OAuth 앱이 필요하다. GitHub 공식 OAuth 문서의 authorization_pending·slow_down·만료·거절 규칙을 따른다. GitHub Git 인증의 비밀번호 폐지 때문에 직접 입력은 PAT 안내를 제공한다.

[GitHub Device Flow](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps), [GitHub HTTPS 인증](https://docs.github.com/en/get-started/git-basics/about-remote-repositories), [GCM 브라우저 옵션](https://github.com/git-ecosystem/git-credential-manager/blob/main/docs/environment.md).

등록한 비밀을 실제 전송에 연결하기 위해 UI 전용이 아닌 공용 라이브러리 인증 저장소를 사용한다. GCM 공유 비밀을 삭제하면 다른 앱 계정까지 영향을 주므로 앱 등록 삭제와 앱 전용 비밀 삭제로 범위를 한정한다. 같은 URL 중복은 거부하고 저장소 URL의 최장 일치로 계정을 구분한다.

## US141 누락과 크기 원인

AuthPanel 초기화는 앱 auth.json만 읽어 기존 시스템 계정을 표시하지 않았다. Windows Credentials 열거는 대상·계정 메타데이터만 복사하고 비밀 blob을 읽지 않아도 된다. GCM 기본 namespace인 git:*만 가져온다. 기존 계정을 표시했다고 전송의 계정을 임의로 강제하지 않으며 앱이 명시적으로 등록한 프로필만 직접 선택에 사용한다.

인증 button 헬퍼는 빈 문자열도 child로 생성하여 hint와 함께 여분의 레이아웃 요소를 만든다. 다른 설정 action처럼 빈 라벨을 생략한다. imported·hidden 기본값과 안정적인 imported id로 중복/재등장/이전 JSON 호환을 처리한다.

## US142 표시 범위 결정

전체 인증을 버리거나 현재 프로젝트 목록만 저장하면 다른 프로젝트의 인증이 사라진다. 전체 활성 프로필은 보존하고 현재 원격별 최우선 범위만 화면에서 선택한다. 동일 범위 여러 계정은 모두 표시하고 id로 중복을 제거한다. 전송용 select는 imported를 제외하는 기존 정책을 유지한다. 부모 주소를 직접 계산하므로 repo와 repo-other 같은 문자열 부분 일치는 발생하지 않는다.

## US143 실제 로그아웃 경계

기존 삭제는 앱 등록/숨김만 변경하여 기본 GCM fallback이 계속 인증을 사용할 수 있었다. 새 사용자 지시는 해당 GCM의 로컬 저장 인증 제거를 요구하므로 계정 지정 erase를 실제 실행한다. 웹 브라우저 서비스 세션이나 서버 OAuth 승인은 별도이며 철회하지 않는다. 공유 저장소 제거와 앱 JSON은 단일 원자 트랜잭션이 아니므로 후자 실패는 부분 성공을 명시한다.

## US144 공용 오류 표시 경로

오류 표시 함수는 시작/프로젝트 화면이 공유한다. 오류 단축키 명령 id는 errors이며 scope는 error-history다. id로 label을 조회해야 현재 사용자 바인딩을 표시할 수 있다. 기존 keys 헬퍼의 테두리 배지를 재사용한다.

## US145 오류 표시 우선순위

두 하단 모두 오류 표시를 deferred(...).with_priority(1)로 그려 뒤에 추가한 팝업의 backdrop보다 위에 남는다. 일반 자식으로 렌더하면 버튼·배지도 다른 하단과 함께 가려진다. F1은 현재 기본 바인딩에서 사용하지 않으며 errors의 target/default와 키 디스패치를 함께 변경한다.

## US146 GCM 무효 성공 근거

[GCM host provider 계약](https://github.com/git-ecosystem/git-credential-manager/blob/main/docs/hostprovider.md)은 대상이 없을 때 erase가 성공 종료해야 한다고 명시한다. 정규화 URL과 실제 저장 target, 계정 메타데이터가 다르면 성공 코드만으로 삭제를 검증할 수 없다. Windows 기본 저장소에서는 정확한 target을 메타데이터로 찾아 제거 후 재조회한다. 다른 계정의 자격 증명을 범위 전체로 지우지 않는다.

## US147 확인한 불일치

사용자 프로젝트 원격은 https://github.com/tcpip147/zit.git이고 credential.useHttpPath=true다. 메타데이터에는 BrowserGcm 인증이 /zit로 저장되어 있다. 인증 추가에서 normalize_url의 .git 제거 후 helper를 호출하지만 native_remote는 .git 원격으로 get을 호출한다. native helper에는 프로젝트 current_dir도 없다. 두 차이는 코드에서 확인했으며 실제 사용자 비밀 조회는 로그온 세션 오류 1312로 실패하여 토큰 유효성을 단정하지 않았다.

사용자는 임의 호환보다 URL 원칙을 요구했다. .git은 URL 경로의 일부로 보존하고 같은 경로로 조회한다. 기존 잘못된 주소는 자동 보정/재조회하지 않는다. 공개 저장소 Fetch 성공과 Push 권한은 구분하며 Push의 일반 문구도 실제 원인을 유지하도록 바꾼다.

별도 GCM 선택은 비대화식 저장 인증 가져오기였지만 현재 기존 인증은 자동 조회하므로 추가 팝업에서 역할이 중복된다. GCM 도구 자체는 브라우저 로그인과 전송/로그아웃에 계속 사용한다. 최상위 UI만 두 방식으로 정리한다.

플랫폼 기본 명령 explorer.exe·xdg-open·open을 사용한다. 셸을 거치지 않아 경로의 공백과 특수문자를 보존한다. 실제 Linux/macOS 실행은 해당 운영체제에서 확인이 필요하다.


## US151 결정

Git Bash는 Windows용 외부 터미널 런처이다. Linux는 터미널 프로그램이 별도로 필요하고 macOS는 Terminal 자동화를 사용한다. OS 셸 기본값과 관계없이 Bash를 명시한다. 플랫폼 분기와 인수는 이 환경에서 순수 테스트하고 실제 Linux/macOS 실행은 해당 환경 확인으로 남긴다.


## US152 검색 결정

도달 가능한 모든 브랜치·태그 커밋을 git2 revwalk로 중복 없이 순회한다. 커밋 메시지는 UTF-8 문자열로 비교하고 파일 경로 및 텍스트 blob 내용은 대소문자 구분 없이 검색한다. 같은 blob의 내용 비교는 캐시한다. 바이너리 blob은 내용 검색에서 제외한다. 파일 이력은 경로별 첫 부모와 현재 tree의 blob ID 차이로 구성하며 삭제도 표시한다. 파일 Diff는 독립 창에서 해당 커밋과 첫 부모의 내용을 비교한다.


## US153 결정

검색어가 커밋 본문에만 있으면 제목만 표시하는 기존 결과에서는 일치 근거가 보이지 않는다. 전체 메시지에서 찾고 일치한 첫 줄을 제목 대신 보여준다. Diff의 unified 텍스트를 그대로 표시하는 대신 줄 번호를 원본/결과 기준으로 추적한다.

## US156 구현 결정

기존 브랜치·이력 행은 선택되지 않은 행에만 `HISTORY_HOVER`를 적용한다. Search와 파일 이력 행에도 같은 조건을 쓴다. 파일 이력 키보드 이동은 목록 포커스에서만 처리하고 `ScrollHandle`로 선택 항목을 보이게 한다. ## US157 구현 결정

GPUI의 `uniform_list`는 균일 높이 목록에서 가시 범위의 행만 생성한다. 파일 이력 목록에 24px 고정 행과 전용 `UniformListScrollHandle`을 적용한다. Diff는 선택 가능한 읽기 전용 텍스트를 유지하므로 전체 텍스트의 줄 시작 바이트 오프셋만 보관하고, 현재 스크롤 높이와 뷰포트 높이에서 앞뒤 여유 행을 포함한 범위만 형상화한다. 전체 높이는 줄 수로, 가로 폭은 텍스트 변경 시 한 번 계산한 고정폭 문자 수로 정한다. 번호 13문자, 기호 3문자, 본문 순서를 유지하고 기호는 가운데 정렬한다. 마우스 위치와 키보드 커서는 각 줄의 본문 시작 이상으로 제한하며 선택 배경도 본문 열부터 그린다. 번호 열의 회색 배경과 오른쪽 선, 기호 열 오른쪽 선은 실제 글리프 좌표로 그린다. 크기 조절 손잡이는 절대 배치해 패널 사이의 레이아웃 공백을 제거한다.
## US158 구현 결정

가상 목록 컨테이너의 너비가 전체 폭이어도 각 커밋 행이 내용 너비로 측정되면 선택·호버 배경과 클릭 영역이 패널 끝까지 닿지 않는다. 행 루트에 전체 너비와 최소 너비 0을 주고 텍스트 자식에 남은 폭과 줄임표를 적용한다. 가상 목록의 행 높이와 선택·호버 방식은 유지한다.
## US159 구현 결정

## US160 구현 결정

## US161 구현 결정

파일 이력 Diff는 선택 가능한 읽기 전용 `CommitEditor`를 사용한다. 기존 DiffViewer 키는 `Bindings::resolve("viewer", 입력 키)`로 해석하며 이동·선택·복사에 해당하는 매핑만 편집기에 전달한다. 편집기의 원시 키 처리와 중복되지 않도록 부모 창의 캡처 단계에서 지원 키를 차단한다. 이를 통해 사용자 변경값을 적용하면서 변경으로 해제된 이전 키가 다시 실행되는 것도 막는다. 과거 커밋 Diff에는 작업 트리 변경 줄의 체크·Stage 상태가 없으므로 읽기 전용 조작을 대상으로 한다.
## US162 구현 결정

커밋 수보다 패널 높이가 클 때 빈 영역을 추가 목록 행으로 채우면 가상 목록의 길이와 키보드 선택 범위가 달라진다. 목록 패널의 헤더 아래에 절대 배치한 투명한 배경 가이드를 두고, 실제 그리드와 동일한 유동 Description 및 고정 Author·Date·Hash 폭으로 오른쪽 경계선을 그린다. 헤더와 실제 커밋 행은 그 위에 그려져 기존 선택·호버·클릭 동작을 유지한다.
## US163 구현 결정

파일 Diff의 캔버스는 실제 줄 높이보다 뷰포트가 크면 최소 높이가 뷰포트를 채운다. 고정폭 글꼴로 16문자를 형상화하여 번호 열 13문자와 기호 열 16문자의 끝 좌표를 구하고, 실제 줄보다 먼저 캔버스 전체 높이에 회색 번호 배경과 두 경계선을 그린다. 기존 줄별 추가·삭제 배경과 번호·기호 영역은 그 위에 그리므로 선택·커서·가상 스크롤의 데이터는 변하지 않는다.
## US164 구현 결정

기존 DiffViewer는 가상 목록 행의 줄 번호 두 셀(각 48px)과 변경 기호 셀(20px)을 사용한다. 실제 행에서는 두 번호 셀에 회색 배경을 주고 두 번째 번호 셀과 기호 셀의 오른쪽에 경계선을 추가한다. 목록 뒤의 절대 배치 가이드는 같은 열 폭을 패널 높이 전체에 그린다. 부분 Stage에서는 24px 체크 셀을 먼저 두고, 가로 스크롤 오프셋만큼 가이드를 이동해 실제 행과 일치시킨다. 커밋 상세 텍스트는 Diff 열 구조가 아니므로 기존 표현을 유지한다.
## US165 구현 결정

기존 Diff의 커서 행 목록은 이전·현재 줄 번호가 있는 행만 포함하고, 마우스 줄도 같은 조건으로 막았다. 해당 필터를 제거하여 hunk 헤더 등 번호 없는 행을 선택할 수 있게 한다. 부분 Stage의 체크 대상은 기존 `+`/`-` 필터가 별도로 유지된다. 드래그 중에는 작업공간의 전역 마우스 캡처에서 뷰포트 밖 포인터를 경계로 제한하고 현재 스크롤 오프셋으로 실제 행·열을 계산한다. 가장자리 자동 스크롤 뒤에도 선택 끝점을 갱신한다. 줄별 이동 콜백은 중복 갱신을 피하기 위해 제거한다.

## US166 구현 결정

GPUI의 `WrappedLine::paint`는 주어진 22px 줄 높이에서 글꼴의 상승·하강 높이를 뺀 여백을 반으로 나눠 글리프 기준선을 배치한다. 따라서 본문 캔버스는 이미 세로 중앙 정렬이며 줄 번호 두 칸에 Flex 중앙 정렬을 추가한다. Diff 뷰어의 스크롤 프레임은 남은 높이를 채우지만 기존 포커스 처리는 실제 텍스트 줄에만 있었다. 프레임의 클릭 처리에서 현재 선택을 유지하며 뷰어 키보드 포커스를 설정한다.

## US167 구현 결정

변경 기호 칸의 Flex 중앙 정렬은 기본 텍스트 줄 상자를 22px 셀 안에 배치하지만, 본문 캔버스는 22px 줄 높이 자체를 기준으로 그린다. 변경 기호에도 22px `line_height`를 지정하고 가로 중앙 정렬을 적용하여 본문과 같은 세로 기준을 사용한다.

## US168 구현 결정

파일 히스토리 Diff의 번호는 `{:>5}` 고정 폭 문자열로 오른쪽에 정렬된다. 기존 DiffViewer는 각 번호를 독립된 48px Flex 셀에 그리므로 두 셀에 `justify_end`를 적용한다. 기존 22px 행 중앙 정렬과 패딩·배경·경계선은 그대로 사용한다.

## US169 구현 결정

Search 탭은 기존 결과 선택 인덱스에 `usize::MAX` 가상 위치를 사용한다. 이 값은 실제 결과 인덱스가 아니므로 결과 행을 선택 표시하지 않는다. Search 진입 시 Workspace 포커스를 주고, 가상 위치의 아래 방향키에서 입력창으로 이동한다. 입력창의 위 방향키는 가상 위치로, 아래 방향키는 첫 결과 또는 결과가 없는 경우 가상 위치로 이동한다. 결과 행의 위 방향키는 첫 행에서 입력창으로 돌아간다. 순수 이동 함수에 대한 단위 테스트로 경계 상태를 확인한다.

## US170 구현 결정

기존 참조 탭은 네 개로 순환했고 Search는 Tag의 오른쪽에서만 별도로 진입했다. 그래서 Local의 왼쪽이 Search를 건너뛰었다. 현재 Search 여부를 다섯 번째 인덱스로 환산해 공통 순환 함수를 사용한다. Search 우선 분기를 제거해 파일 목록 포커스의 좌우 이동은 파일 탭으로 처리한다. Search 활성 때는 일반 브랜치 단축키 범위를 사용한다.

## US171 구현 결정

브랜치·파일·커밋 히스토리의 스크롤 프레임은 이미 패널의 남은 높이를 채운다. 포커스 처리가 실제 행 클릭에만 있어 마지막 행 아래는 포커스가 없었다. 각 프레임에 클릭 핸들러를 연결해 해당 `ListFocus`와 Workspace 포커스를 설정한다. Search는 별도 결과 스크롤 영역에 같은 처리를 연결한다. 선택 모델은 변경하지 않는다.

## US172 구현 결정

파일 목록의 24px 행은 Flex로 자식을 가운데 놓지만 파일명 셀은 내용 높이만 사용했다. 파일명 셀을 행 높이로 채우고 줄 높이를 24px로 지정해 글리프가 행 중앙 기준으로 그려지게 한다. 기존 줄임표와 색상은 유지한다.

## US173 구현 결정

Stage와 History의 상태 문자는 모두 `text_xs`를 사용하지만 Stage는 두 글자 정렬을 위해 고정폭 글꼴을 사용한다. Stage 상태 셀에만 `text_sm`을 적용해 시각적 크기를 높이고, History 크기 및 상태 칸의 폭·색상·고정폭 글꼴은 유지한다.

## US174 구현 결정

부분 Stage 체크 열은 실제 Diff 행에서는 행별 추가·삭제 배경을 상속했고 빈 영역 가이드는 투명했다. 실제 24px 셀과 전체 높이 가이드에 같은 회색 배경 및 오른쪽 경계선을 적용한다. 체크 아이콘은 22px 줄 높이와 가로 중앙 정렬을 사용한다. 가이드의 기존 가로 스크롤 오프셋은 유지한다.

## US175 구현 결정

사용자 피드백에 따라 체크 열과 줄 번호 열 사이의 선은 제거하고 회색 배경은 유지한다. 실제 행 셀과 빈 공간 가이드 양쪽에서 선을 제거해야 세로로 끊긴 경계가 남지 않는다. Stage 상태 글꼴은 이전 단계에서만 명시한 `Cascadia Mono`를 제거하여 History 상태 셀과 같은 기본 글꼴을 상속한다. Stage의 큰 글자 크기는 유지한다.

## US176 구현 결정

Stage 상태 문자열의 앞뒤 공백은 비례 글꼴에서 문자 폭보다 좁아 staged·unstaged 위치가 어긋난다. 기존 `stage_status()`의 두 문자 결과를 각 14px 칸에 독립적으로 그려 공백은 빈 칸으로 처리한다. 두 칸의 전체 폭은 28px이며, History와 같은 상속 글꼴과 Stage의 큰 글자 크기를 유지한다.

## US177 구현 결정

두 상태 칸의 배치는 유지하고 각 칸만 14px에서 13px로 좁힌다. 전체 상태 영역은 26px이 되며 문자 매핑·글꼴·크기·색상은 바뀌지 않는다.

## US178 구현 결정

사용자 지정 간격에 따라 Stage 상태 두 칸을 각 11px, 전체를 22px로 줄인다. 두 칸의 독립 배치와 상태 매핑은 그대로 사용한다.

## US179 구현 결정

Stage는 이전 시각적 크기 조정으로 `text_sm`, History는 `text_xs`였다. Stage의 고정폭 글꼴을 제거한 뒤에도 크기 차이가 남았으므로 두 상태 셀 모두 `text_xs`를 사용한다. 두 탭은 같은 상속 글꼴과 크기를 사용하고 Stage의 두 칸 구조는 유지한다.

## US180 구현 결정

Stage 상태 두 칸을 각각 9px, 전체 18px로 줄인다. 기존 상태 문자 매핑과 History에 맞춘 `text_xs` 글꼴 크기는 유지한다.

## US181 구현 결정

파일명은 24px 행과 같은 줄 높이를 사용하지만 Stage 상태 문자는 내용 높이의 줄 상자 안에 있었다. Stage 상태 셀과 두 문자 칸을 행 전체 높이로 채우고 각 칸에 24px 줄 높이를 지정한다. 글리프 크기는 History 상태와 같은 `text_xs`로 유지한다.

## US182 구현 결정

공통 `empty`는 사방 20px 패딩을 사용한다. 브랜치 섹션의 빈 목록 안내에만 좌우 12px·상하 8px을 덮어써 목록 행의 좌우 12px 여백과 맞춘다.

## US183 구현 결정

파일명 셀의 14px 절대 글자 크기를 `text_xs`로 바꾼다. 같은 셀을 Stage와 History가 사용하므로 두 탭의 파일명이 브랜치·커밋 히스토리 목록의 기본 글자 크기와 일치한다. 24px 줄 높이는 유지한다.

## US184 구현 결정

파일 히스토리 그리드는 Description이 남은 폭을 사용하고 Author·Date·Hash가 고정 폭이다. 세 열 경계의 드래그는 맞닿은 두 칸의 폭을 반대로 변경하되 Description 최소 72px, Author·Date 최소 80px, Hash 최소 60px을 지킨다. 현재 열 폭과 드래그 시작 상태는 창 로컬로 유지한다. 헤더·가상 커밋 행·빈 영역 가이드는 같은 폭 배열을 사용하며, 목록과 Diff 사이의 높이 조절 상태는 별도로 유지한다.

## US185 구현 결정

새 탭의 신규 저장소는 기존 폴더를 선택하고 그 안에 바로 `.git`을 만든다. `.git`이 이미 있거나 선택 경로가 디렉터리가 아니면 초기화를 거부한다. Clone은 기존 새 경로 생성 흐름을 유지한다. Windows에서는 `SetFileAttributesW`로 `.git`의 기존 속성에 숨김 비트를 추가한다. 다른 운영체제에서는 점으로 시작하는 이름을 사용한다. 선택한 디렉터리의 파일은 보존한다.

## US186 구현 결정

최근 저장소 관리 팝업의 footer에서 취소 버튼만 제거한다. 팝업 바깥 클릭과 Esc의 닫기 처리, 저장소 삭제 확인창의 취소 버튼은 기존 경로를 사용한다.

## US187~191 구현 결정

Clone은 기존 빈 디렉터리를 선택하고 그 안에 바로 복제한다. 기존 파일이 있으면 거부하며 Windows의 `.git`에 숨김 속성을 설정한다. 삭제는 저장소 루트 검증 뒤 휴지통을 거치지 않는 폴더 삭제를 사용한다. 삭제 확인창은 취소 버튼 없이 `삭제`를 표시한다. `Ctrl+N`은 프로젝트 탭 범위에 등록해 Clone URL 편집 중에도 적용한다. 새 탭 버튼과 최근 저장소 열기·삭제에는 전용 포커스 핸들을 두고 Tab 순환과 Space 실행을 연결한다. 앞선 US185·186의 Clone 새 경로 및 삭제 확인 취소 버튼 결정은 이 요구사항으로 대체된다.

## US192 구현 결정

`Ctrl+X`는 프로젝트 탭 범위의 공통 명령으로 등록한다. 활성 탭이 저장소일 때 기존 `close_tab`을 실행한다. Clone URL 입력과 검색 입력이 포커스된 경우에는 입력창의 잘라내기를 우선한다. 팝업에서는 프로젝트 탭 명령이 해석되지 않는다.
