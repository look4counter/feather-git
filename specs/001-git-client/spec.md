# 기능 명세: 단일 화면 Git 클라이언트

**작성일**: 2026-10-26
**상태**: 명확화 완료
**사용자 요청**: Rust, GPUI, gix를 사용하여 프로젝트 탭과 네 영역으로 구성된 Git 클라이언트를 만든다.

## 기존 기능과 확정 범위

2026-10-26에 실제 저장소 조회, 여백 없는 네 영역과 공통 경계선 크기 조절, 전체 높이 탭 바 및 독립된 새 탭을 확정했다. 스테이징 실행·커밋·체크아웃·fetch/push는 제외한다.

## 사용자 시나리오 및 검증

### 사용자 이야기 1 — 프로젝트 전환 (P1)

두 저장소를 열어 탭을 전환하면 각 저장소의 참조·커밋·파일 선택이 유지된다. +를 누르면 독립된 새 탭이 활성화된다. 마지막 탭을 닫으면 새 탭 하나가 남는다. 탭이 많으면 목록만 스크롤하고 +는 오른쪽에 고정된다.

### 사용자 이야기 2 — 참조와 커밋 탐색 (P1)

Local·Remote·Stash·Tag를 전환하면 해당 참조와 커밋을 표시한다. 항목이 없으면 빈 상태를 안내한다. 이력은 모든 참조에서 도달 가능한 전체 커밋을 표시한다.

### 사용자 이야기 3 — 변경 파일과 차이 확인 (P1)

Stage는 인덱스와 작업 디렉터리를 구분하고 History는 선택한 커밋의 파일을 표시한다. 파일 선택으로 제목과 Diff가 갱신된다. 병합은 첫 부모와 비교한다.

## 기능 요구사항

- **FR-001**: 프로젝트별 상단 탭을 제공한다.
- **FR-002**: 저장소 본문에 왼쪽 위 참조, 오른쪽 위 커밋, 왼쪽 아래 파일, 오른쪽 아래 Diff를 동시에 표시한다.
- **FR-003**: 참조에 Local·Remote·Stash·Tag 탭을 제공한다.
- **FR-004**: 파일에 Stage·History 탭을 제공한다.
- **FR-005**: 프로젝트별 선택 상태를 분리한다.
- **FR-006**: 선택된 프로젝트·참조·커밋·파일에 맞는 내용을 표시한다.
- **FR-007**: 빈 상태와 오류를 구분해 안내한다.
- **FR-008**: 실행 인자와 새 탭에서 로컬 저장소를 연다. 초기화와 Clone을 제외한 저장소 변경 명령은 실행하지 않는다. 상단에는 새로고침·열기 도구 버튼을 두지 않는다.
- **FR-009**: 모든 참조와 HEAD에서 도달 가능한 전체 커밋을 표시한다. 병합 변경은 첫 부모와 비교한다.
- **FR-010**: 조회를 백그라운드에서 실행하고 로딩을 표시하며 결과는 요청한 프로젝트에만 반영한다.
- **FR-011**: 파일 미리보기는 1 MiB, Diff는 5,000줄로 제한한다. 바이너리·심볼릭 링크·서브모듈은 종류와 제한을 안내한다.
- **FR-012**: 본문과 네 영역은 외곽·영역 간 여백과 둥근 모서리 없이 맞붙고 경계선만 표시한다. 내부 콘텐츠 여백은 유지한다.
- **FR-013**: 공통 세로·가로 경계선을 드래그하여 양쪽 열·행을 함께 조절한다. 방향 커서와 7px 드래그 영역을 제공한다.
- **FR-014**: 좌측 260px·우측 360px·위아래 180px의 최소 크기를 가능한 범위에서 보장하고 창 변경에 대응한다. 마우스를 놓으면 드래그를 끝내며 분할 비율은 탭 전환 중 유지한다.
- **FR-015**: 상단은 높이 44px의 탭 바만 표시한다. 탭과 +는 높이를 채우고 여백·둥근 모서리 없이 구분선과 활성 표시를 제공한다.
- **FR-016**: +는 맨 오른쪽에 고정하고 탭 목록만 스크롤한다. 클릭마다 독립된 새 탭을 추가하고 세 저장소 시작 선택지를 표시한다.
- **FR-017**: 빈 탭과 저장소 탭은 고유 ID로 선택·닫기를 지원한다. 마지막 탭을 닫거나 저장소 없이 실행하면 새 탭을 하나 표시하며 기존 저장소 상태를 보존한다.

## 주요 개체

프로젝트는 ID·저장소 경로·이름·선택 상태를 가진다. 참조는 종류·이름·대상 커밋을, 커밋은 ID·제목·작성자·부모를, 변경 파일은 경로·종류·스테이징 여부·차이를 가진다.

## 성공 기준

- **SC-001**: 저장소 탭에서 네 영역과 프로젝트 탭을 동시에 볼 수 있다.
- **SC-002**: 네 참조 탭과 두 파일 탭을 모두 전환할 수 있다.
- **SC-003**: 두 프로젝트를 전환해도 각 선택 상태가 보존된다.
- **SC-004**: 커밋·파일 선택으로 해당 변경 내용에 도달한다.
- **SC-005**: 본문과 영역 사이 여백이 없고 드래그 시 정렬과 최소 크기가 유지된다.
- **SC-006**: 탭과 +가 높이를 채우고 +를 세 번 누르면 독립된 새 탭 세 개가 추가된다. 기존 저장소 상태는 보존된다.

## 가정과 경계 조건

Windows·어두운 테마·Rust·GPUI·gix를 사용한다. 잘못된 경로·권한·초기 커밋이 없는 저장소를 안내하며 긴 이름과 많은 항목은 영역 안에서 스크롤한다. 분할 비율과 탭 상태의 재실행 후 복원은 제외한다.

## 새 탭 시작 기능 변경 및 명확화 (2026-10-27)

사용자는 신규 생성과 Clone 실행까지 모두 구현하도록 확정했다. 이전 빈 본문 요구는 세 선택지 표시로 대체하며, 읽기 전용 요구는 초기화와 Clone만 예외로 허용한다.

### 사용자 이야기 4 — 저장소 시작 (P1)

새 탭에서 신규 저장소, 저장소 열기, Clone을 선택한다. 생성은 새 경로, 열기는 기존 폴더, Clone은 URL과 새 경로를 선택한다. 성공하면 같은 탭에서 저장소를 탐색한다. 취소는 현재 상태를 유지하고 오류는 재시도를 허용한다.

- **FR-018**: 닫기 hover는 중앙 24px 정사각형 안에 한정되며 클릭은 해당 탭만 닫는다.
- **FR-019**: 모든 새 탭에 신규 저장소·저장소 열기·Clone 선택지를 표시한다.
- **FR-020**: 신규 저장소는 새 경로에 초기화하고 열기는 선택한 기존 폴더를 연다. 기존 대상은 덮어쓰지 않는다.
- **FR-021**: Clone은 URL과 새 경로를 받아 복제하고 연다. 빈 URL은 거절하며 오류와 진행 상태를 표시한다.
- **FR-022**: 비동기 결과는 요청한 탭 ID에만 적용하고 닫힌 탭은 복원하지 않는다. 진행 중 중복 요청을 막고 취소는 오류로 표시하지 않는다.
- **SC-007**: 세 동작에서 저장소 화면에 도달한다. 취소·잘못된 URL·기존 경로·작업 중 탭 전환 및 닫기를 검증한다.

가정: 초기화와 Clone은 설치된 Git을 사용한다. 인증은 Git 설정에 따르며 앱 내 인증 UI는 제외한다. 실패한 Clone의 일부 파일은 자동 삭제하지 않는다.

## 커밋 그리드·그래프 및 상세 (2026-10-27)

### 사용자 이야기 5 — 커밋 관계와 상세 탐색 (P1)

커밋을 Graph·Description·Author·Date·Hash 열로 비교하고 분기·병합 관계를 확인한다. 행을 선택하면 History로 이동하여 해당 변경 파일과 커밋상세를 볼 수 있다. 커밋상세를 선택하면 Diff Viewer에 선택 커밋의 메타데이터와 전체 메시지가 표시된다. 파일을 선택하면 파일 Diff로 돌아온다.

### 명확화와 가정

참조한 D:/Project/zit의 레인 할당과 곡선 연결 방식을 사용한다. 최신 요청에 따라 모든 참조의 전체 이력과 열 크기 조절을 제공한다. 고정 항목은 History 파일 스크롤 위에 항상 보이는 행으로 해석한다. 추가 질문이 필요한 모호성은 없다.

- **FR-023**: 커밋 히스토리를 Graph·Description·Author·Date·Hash 헤더와 일정한 행 높이의 그리드로 표시한다. 열은 정렬되고 긴 텍스트는 다른 열을 침범하지 않으며 영역 폭을 100% 사용하고 열 크기를 조절한다.
- **FR-024**: 부모 관계를 따라 색상 레인·연결 곡선·커밋 노드를 그린다. 선형·분기·병합·여러 부모·조회 제한 밖 부모를 처리하고 노드 선택은 기존 커밋 행 선택과 일치한다.
- **FR-025**: History에 커밋상세 항목을 파일 목록 위에 고정한다. Stage에는 표시하지 않고 파일 수에 포함하지 않는다. 커밋이 없을 때도 항목을 표시하며 선택 시 빈 상태를 안내한다.
- **FR-026**: 커밋상세 선택 시 Diff Viewer에 전체 해시·부모 해시·작성자와 이메일·커미터와 이메일·각 시간과 시간대·전체 메시지를 표시한다. 파일 Diff와 선택 강조를 상호 배타적으로 전환한다.
- **FR-027**: 커밋 변경 시 상세 내용도 새 커밋에 맞추며 이전 파일 비동기 결과가 상세를 덮어쓰지 않게 한다. 로딩·실패·프로젝트 전환에서 오래된 상세를 표시하지 않는다.
- **SC-008**: 선형·분기·병합·여러 부모·200개 초과 이력에서 레인 연결을 검증하며 그리드의 다섯 열이 같은 너비 규칙을 사용한다.
- **SC-009**: 긴 메시지·초기 커밋·병합·빈 저장소에서 상세를 확인하고 파일→상세→파일·커밋 전환·프로젝트 전환을 검증한다.

## 전체 이력과 가상 그리드 개선 (2026-10-27)

### 사용자 이야기 6 — 대규모 전체 이력 탐색 (P1)

어떤 브랜치를 선택하든 전체 이력을 보고 Description 앞의 브랜치명으로 각 브랜치 끝을 찾는다. 스크롤 시 화면에 보이는 행만 출력하며 커밋 선택은 이력을 다시 탐색하지 않는다. 그리드는 패널 폭을 채우고 열 경계를 드래그하면 헤더와 행이 함께 조절된다.

### 명확화 및 가정

전체 커밋은 로컬·원격 브랜치·커밋 태그·stash 및 detached HEAD에서 도달 가능한 커밋이다. 참조가 없는 삭제된 객체와 일반 reflog 복구는 제외한다. 기존 200개 제한과 선택 참조 필터, 고정 합계 폭, 열 조절 제외 가정을 이번 요청으로 대체한다. Date는 날짜를 유지한 YYYY-MM-DD HH:MM 표기로 커밋 시간대의 시·분까지 표시한다. 열 경계는 이웃 두 열의 폭을 교환하여 합계가 항상 100%가 되게 하고 작은 창에서는 최소 폭을 비례 축소한다. 추가 확인이 필요한 모호성은 없다.

- **FR-028**: 히스토리는 가상 스크롤로 가시 범위와 측정 행만 생성한다. UI 렌더링에서 전체 커밋·전체 그래프 경로를 순회하지 않고 그래프 캐시는 가시 행 수준으로 제한한다.
- **FR-029**: 모든 참조와 HEAD의 도달 가능한 전체 커밋을 중복 없이 조회하고 200개 제한을 제거한다. 참조 선택은 이력을 필터링하지 않는다. 로컬·원격 브랜치가 가리키는 행의 Description 맨 앞에 모든 해당 브랜치명을 표시한다.
- **FR-030**: Date는 YYYY-MM-DD HH:MM과 커밋 시간대를 사용한다.
- **FR-031**: 그리드는 항상 사용 가능한 패널 폭의 100%이며 가로 오버플로 없이 다섯 열을 같은 규칙으로 배치한다. 네 열 경계에 조절 커서를 표시하고 드래그·해제·창 크기 변경·프로젝트 전환에도 합계 폭과 정렬을 유지한다.
- **FR-032**: 커밋 선택은 선택 커밋의 상세와 파일만 백그라운드 조회한다. 전체 이력·상태·그래프를 다시 구성하지 않으며 선택 세대와 프로젝트 ID로 오래된 결과를 버린다.
- **SC-010**: 서로 갈라진 로컬·원격·태그·detached HEAD와 200개 초과 이력이 브랜치 선택과 관계없이 모두 조회된다.
- **SC-011**: 대규모 이력에서 렌더링 콜백은 요청받은 범위만 생성한다. 공통 열 폭 합계가 가용 폭과 일치하고 드래그 경계·최소 폭·창 변경 및 날짜 시분을 자동 검증한다.

경계: 최신 요청에 따라 최초 메타데이터는 200개로 제한하고 이후 페이지를 읽는다. 위상 탐색은 관계 판단을 위해 추가 객체 헤더를 읽을 수 있다.

## 공통 스크롤 및 200개 점진 조회 (2026-10-27)

### 사용자 이야기 7 — 긴 목록의 마우스 탐색 (P1)

히스토리·Diff·브랜치·파일 목록에 같은 스크롤바를 표시하고 휠·트랙 클릭·손잡이 드래그로 탐색한다. 모든 목록은 가시 행만 만든다. 최초 커밋은 200개를 읽고 맨 아래에 도달하면 200개씩 자동 추가한다.

명확화: 전체 브랜치 범위는 유지하고 한번에 전부 읽던 방식은 200개 페이지로 대체한다. 체크아웃 표식은 선택 강조와 구분하여 로컬 현재 브랜치 이름 앞에 ●로 표시한다. detached HEAD는 같은 이름의 브랜치를 현재 브랜치로 표시하지 않는다. Diff의 커밋상세 메시지도 가상화 대상이다. 동일 스크롤을 브랜치와 파일에도 적용하라는 추가 요청을 반영한다. 질문이 필요한 모호성은 없다.

- **FR-033**: 네 목록은 공통으로 눈에 보이는 세로 스크롤바와 휠·트랙 클릭·손잡이 드래그를 지원한다. 범위 밖 드래그는 처음/끝으로 제한하고 마우스 해제로 종료한다. 긴 Diff는 가로 스크롤도 제공한다.
- **FR-034**: 히스토리 최초와 추가 요청은 최대 200개 커밋을 반환한다. 맨 아래 도달 시 한 번만 추가 요청하며 진행 중 중복·끝 이후 요청을 막는다. 기존 행과 선택을 보존하고 페이지 경계 그래프를 연결한다. 실패 시 재시도할 수 있고 닫힌 탭의 결과를 적용하지 않는다.
- **FR-035**: 히스토리의 전체 개수 및 첫 부모 기준 라벨을 삭제한다. Graph 헤더와 셀의 왼쪽 여백을 다른 열과 맞춘다.
- **FR-036**: 히스토리 Description과 브랜치 목록에서 현재 체크아웃 로컬 브랜치 이름 앞에 ●를 표시한다. 선택 변경은 이 표식을 바꾸지 않는다.
- **FR-037**: Diff·커밋상세·브랜치·파일은 고정 높이의 가상 행을 사용한다. History 상세 고정 항목·Stage 그룹·파일 원래 인덱스·Diff 줄번호와 색상·빈 상태 및 오류를 유지한다.
- **SC-012**: 200·400·최종 페이지와 정확한 200배수·빈 저장소·중복 요청·취소 및 오류 경계와 페이지 그래프 연속성을 검증한다.
- **SC-013**: 스크롤 손잡이와 트랙의 수치 매핑·경계·작은 뷰포트, Stage 행 인덱스·현재 브랜치 및 detached 상태·긴 Diff 가상화 연결을 검증한다.

전체 개수 계산은 하지 않는다. 브랜치 tip이 아직 읽히지 않았더라도 상세 선택은 가능하며 목록 위치 이동은 로드된 행에 한정한다.

## 목록 배치 및 상세 표시 정리 (2026-10-27)

### 사용자 이야기 8 — 콘텐츠 중심 배치 (P1)

스크롤이 필요한 축에만 바를 표시하고 불필요한 공간을 돌려준다. 추가 커밋 로딩은 그리드 안의 진행 표시로 보여 기존 행과 컬럼 위치를 유지한다. 브랜치·파일·고정 커밋상세 행은 그리드와 같은 높이와 전체 폭으로 선택한다.

명확화: 네 영역의 이름 헤더만 제거하고 참조/파일 탭과 그리드 컬럼 헤더, 파일 경로 표시행은 유지한다. 상위 항목은 한 줄에 라벨과 해시를 함께 표시하며 병합 커밋의 각 상위 해시도 같은 형식의 독립 행으로 표시한다. 시간은 커밋에 기록된 오프셋을 반영하되 화면의 시간대 문자열만 숨긴다. 추가 질문이 필요한 모호성은 없다.

- **FR-038**: 콘텐츠가 뷰포트를 넘는 축에만 스크롤바를 생성하고 불필요한 바의 공간과 포인터 영역을 제거한다. 창 크기·탭·데이터 변경에 대응하고 가로/세로 바의 상호 영향을 안정적으로 계산한다.
- **FR-039**: 페이지 추가 로딩 중에는 그리드 내부에 움직이는 진행 표시와 ‘커밋을 더 읽는 중입니다…’를 표시한다. 기존 행·헤더를 밀어내지 않고 성공·실패 시 숨긴다.
- **FR-040**: 브랜치·파일·Stage 그룹 및 고정 커밋상세 행의 높이는 공통 그리드 행 24px이고 폭은 가용 목록의 100%다. 선택·hover도 전체 행에 적용한다.
- **FR-041**: 상세의 ‘부모:’를 ‘상위 항목:’으로 바꾸고 바로 뒤에 해시 또는 초기 커밋 안내를 같은 줄로 표시한다. 작성/커밋 시간의 시간대 표기와 ‘커밋 메시지’ 라벨만 제거하고 메시지와 빈 줄은 보존한다.
- **FR-042**: 브랜치 목록·커밋 히스토리·파일 목록·Diff Viewer의 제목 헤더 영역을 제거한다. 네 영역 경계·탭·그리드 컬럼·파일 경로와 기능은 유지한다.
- **SC-014**: 맞춤/넘침 경계·한 축의 바가 다른 축을 유발하는 경우·크기 변경의 스크롤 표시를 수치 검증하고 헤더와 가상 행의 정렬을 코드 검토한다.
- **SC-015**: 초기·일반·병합 상세의 상위 항목 단일 행, 시간대 비표시와 현지 시각 보존, 메시지 라벨 제거 및 빈 줄 보존을 검증한다.
