# 기능 명세: 단일 화면 Git 클라이언트

**작성일**: 2026-10-26
**상태**: 명확화 완료
**사용자 요청**: Rust, GPUI, gix를 사용하여 프로젝트 탭과 네 영역으로 구성된 Git 클라이언트를 만든다.

## 기존 기능과 확정 범위

2026-10-26에 실제 저장소 조회, 여백 없는 네 영역과 공통 경계선 크기 조절, 전체 높이 탭 바 및 독립된 새 탭을 확정했다. 체크아웃은 제외한다. 풀과 일반 푸시는 추가 요청으로 허용한다. 메시지 입력 후 staged 변경 커밋은 추가 요청으로 허용한다. 선택 파일의 스테이징은 추가 요청으로 허용한다. fetch와 확인 후 저장소 휴지통 이동은 2026-10-27 추가 요구로 허용한다.

## 사용자 시나리오 및 검증

### 사용자 이야기 1 — 프로젝트 전환 (P1)

두 저장소를 열어 탭을 전환하면 각 저장소의 참조·커밋·파일 선택이 유지된다. +를 누르면 독립된 새 탭이 활성화된다. 마지막 탭을 닫으면 새 탭 하나가 남는다. 탭이 많으면 목록만 스크롤하고 +는 오른쪽에 고정된다.

### 사용자 이야기 2 — 참조와 커밋 탐색 (P1)

Local·Remote·Stash·Tag를 전환하면 해당 참조와 커밋을 표시한다. 항목이 없으면 빈 상태를 안내한다. 이력은 모든 참조에서 도달 가능한 전체 커밋을 표시한다.

### 사용자 이야기 3 — 변경 파일과 차이 확인 (P1)

Stage는 인덱스와 작업 디렉터리를 구분하고 History는 선택한 커밋의 파일을 표시한다. 파일 선택으로 제목과 Diff가 갱신된다. 병합은 첫 부모와 비교한다.

## 기능 요구사항

- **FR-001**: 프로젝트별 상단 탭을 제공한다.
- **FR-002**: 저장소 본문에 왼쪽 위 참조, 오른쪽 위 커밋, 왼쪽 아래 파일, 오른쪽 아래 Diff를 동시에 표시한다.
- **FR-003**: 참조에 Local·Remote·Stash·Tag 탭을 제공한다.
- **FR-004**: 파일에 Stage·History 탭을 제공한다.
- **FR-005**: 프로젝트별 선택 상태를 분리한다.
- **FR-006**: 선택된 프로젝트·참조·커밋·파일에 맞는 내용을 표시한다.
- **FR-007**: 빈 상태와 오류를 구분해 안내한다.
- **FR-008**: 실행 인자와 새 탭에서 로컬 저장소를 연다. 초기화·Clone·fetch·선택 파일 스테이징·메시지 입력 커밋과 확인 후 저장소 휴지통 이동 외의 변경은 실행하지 않는다. 상단에는 새로고침·열기 도구 버튼을 두지 않는다.
- **FR-009**: 모든 참조와 HEAD에서 도달 가능한 전체 커밋을 표시한다. 병합 변경은 첫 부모와 비교한다.
- **FR-010**: 조회를 백그라운드에서 실행하고 로딩을 표시하며 결과는 요청한 프로젝트에만 반영한다.
- **FR-011**: 파일 미리보기는 1 MiB, Diff는 5,000줄로 제한한다. 바이너리·심볼릭 링크·서브모듈은 종류와 제한을 안내한다.
- **FR-012**: 본문과 네 영역은 외곽·영역 간 여백과 둥근 모서리 없이 맞붙고 경계선만 표시한다. 내부 콘텐츠 여백은 유지한다.
- **FR-013**: 공통 세로·가로 경계선을 드래그하여 양쪽 열·행을 함께 조절한다. 방향 커서와 7px 드래그 영역을 제공한다.
- **FR-014**: 좌측 260px·우측 360px·위아래 180px의 최소 크기를 가능한 범위에서 보장하고 창 변경에 대응한다. 마우스를 놓으면 드래그를 끝내며 분할 비율은 탭 전환 중 유지한다.
- **FR-015**: 상단은 높이 44px의 탭 바만 표시한다. 탭과 +는 높이를 채우고 여백·둥근 모서리 없이 구분선과 활성 표시를 제공한다.
- **FR-016**: +는 맨 오른쪽에 고정하고 탭 목록만 스크롤한다. 클릭마다 독립된 새 탭을 추가하고 세 저장소 시작 선택지를 표시한다.
- **FR-017**: 빈 탭과 저장소 탭은 고유 ID로 선택·닫기를 지원한다. 마지막 탭을 닫거나 저장소 없이 실행하면 새 탭을 하나 표시하며 기존 저장소 상태를 보존한다.

## 주요 개체

프로젝트는 ID·저장소 경로·이름·선택 상태를 가진다. 참조는 종류·이름·대상 커밋을, 커밋은 ID·제목·작성자·부모를, 변경 파일은 경로·종류·스테이징 여부·차이를 가진다.

## 성공 기준

- **SC-001**: 저장소 탭에서 네 영역과 프로젝트 탭을 동시에 볼 수 있다.
- **SC-002**: 네 참조 탭과 두 파일 탭을 모두 전환할 수 있다.
- **SC-003**: 두 프로젝트를 전환해도 각 선택 상태가 보존된다.
- **SC-004**: 커밋·파일 선택으로 해당 변경 내용에 도달한다.
- **SC-005**: 본문과 영역 사이 여백이 없고 드래그 시 정렬과 최소 크기가 유지된다.
- **SC-006**: 탭과 +가 높이를 채우고 +를 세 번 누르면 독립된 새 탭 세 개가 추가된다. 기존 저장소 상태는 보존된다.

## 가정과 경계 조건

Windows·어두운 테마·Rust·GPUI·gix를 사용한다. 잘못된 경로·권한·초기 커밋이 없는 저장소를 안내하며 긴 이름과 많은 항목은 영역 안에서 스크롤한다. 분할 비율과 탭 상태의 재실행 후 복원은 제외한다.

## 새 탭 시작 기능 변경 및 명확화 (2026-10-27)

사용자는 신규 생성과 Clone 실행까지 모두 구현하도록 확정했다. 이전 빈 본문 요구는 세 선택지 표시로 대체하며, 저장소 쓰기는 초기화·Clone 및 추가 요구의 fetch·선택 파일 스테이징·확인 후 휴지통 이동을 허용한다.

### 사용자 이야기 4 — 저장소 시작 (P1)

새 탭에서 신규 저장소, 저장소 열기, Clone을 선택한다. 생성은 새 경로, 열기는 기존 폴더, Clone은 URL과 새 경로를 선택한다. 성공하면 같은 탭에서 저장소를 탐색한다. 취소는 현재 상태를 유지하고 오류는 재시도를 허용한다.

- **FR-018**: 닫기 hover는 중앙 24px 정사각형 안에 한정되며 클릭은 해당 탭만 닫는다.
- **FR-019**: 모든 새 탭에 신규 저장소·저장소 열기·Clone 선택지를 표시한다.
- **FR-020**: 신규 저장소는 새 경로에 초기화하고 열기는 선택한 기존 폴더를 연다. 기존 대상은 덮어쓰지 않는다.
- **FR-021**: Clone은 URL과 새 경로를 받아 복제하고 연다. 빈 URL은 거절하며 오류와 진행 상태를 표시한다.
- **FR-022**: 비동기 결과는 요청한 탭 ID에만 적용하고 닫힌 탭은 복원하지 않는다. 진행 중 중복 요청을 막고 취소는 오류로 표시하지 않는다.
- **SC-007**: 세 동작에서 저장소 화면에 도달한다. 취소·잘못된 URL·기존 경로·작업 중 탭 전환 및 닫기를 검증한다.

가정: 초기화와 Clone은 설치된 Git을 사용한다. 인증은 Git 설정에 따르며 앱 내 인증 UI는 제외한다. 실패한 Clone의 일부 파일은 자동 삭제하지 않는다.

## 커밋 그리드·그래프 및 상세 (2026-10-27)

### 사용자 이야기 5 — 커밋 관계와 상세 탐색 (P1)

커밋을 Graph·Description·Author·Date·Hash 열로 비교하고 분기·병합 관계를 확인한다. 행을 선택하면 History로 이동하여 해당 변경 파일과 커밋상세를 볼 수 있다. 커밋상세를 선택하면 Diff Viewer에 선택 커밋의 메타데이터와 전체 메시지가 표시된다. 파일을 선택하면 파일 Diff로 돌아온다.

### 명확화와 가정

참조한 D:/Project/zit의 레인 할당과 곡선 연결 방식을 사용한다. 최신 요청에 따라 모든 참조의 전체 이력과 열 크기 조절을 제공한다. 고정 항목은 History 파일 스크롤 위에 항상 보이는 행으로 해석한다. 추가 질문이 필요한 모호성은 없다.

- **FR-023**: 커밋 히스토리를 Graph·Description·Author·Date·Hash 헤더와 일정한 행 높이의 그리드로 표시한다. 열은 정렬되고 긴 텍스트는 다른 열을 침범하지 않으며 영역 폭을 100% 사용하고 열 크기를 조절한다.
- **FR-024**: 부모 관계를 따라 색상 레인·연결 곡선·커밋 노드를 그린다. 선형·분기·병합·여러 부모·조회 제한 밖 부모를 처리하고 노드 선택은 기존 커밋 행 선택과 일치한다.
- **FR-025**: History에 커밋상세 항목을 파일 목록 위에 고정한다. Stage에는 표시하지 않고 파일 수에 포함하지 않는다. 커밋이 없을 때도 항목을 표시하며 선택 시 빈 상태를 안내한다.
- **FR-026**: 커밋상세 선택 시 Diff Viewer에 전체 해시·부모 해시·작성자와 이메일·커미터와 이메일·각 시간과 시간대·전체 메시지를 표시한다. 파일 Diff와 선택 강조를 상호 배타적으로 전환한다.
- **FR-027**: 커밋 변경 시 상세 내용도 새 커밋에 맞추며 이전 파일 비동기 결과가 상세를 덮어쓰지 않게 한다. 로딩·실패·프로젝트 전환에서 오래된 상세를 표시하지 않는다.
- **SC-008**: 선형·분기·병합·여러 부모·200개 초과 이력에서 레인 연결을 검증하며 그리드의 다섯 열이 같은 너비 규칙을 사용한다.
- **SC-009**: 긴 메시지·초기 커밋·병합·빈 저장소에서 상세를 확인하고 파일→상세→파일·커밋 전환·프로젝트 전환을 검증한다.

## 전체 이력과 가상 그리드 개선 (2026-10-27)

### 사용자 이야기 6 — 대규모 전체 이력 탐색 (P1)

어떤 브랜치를 선택하든 전체 이력을 보고 Description 앞의 브랜치명으로 각 브랜치 끝을 찾는다. 스크롤 시 화면에 보이는 행만 출력하며 커밋 선택은 이력을 다시 탐색하지 않는다. 그리드는 패널 폭을 채우고 열 경계를 드래그하면 헤더와 행이 함께 조절된다.

### 명확화 및 가정

전체 커밋은 로컬·원격 브랜치·커밋 태그·stash 및 detached HEAD에서 도달 가능한 커밋이다. 참조가 없는 삭제된 객체와 일반 reflog 복구는 제외한다. 기존 200개 제한과 선택 참조 필터, 고정 합계 폭, 열 조절 제외 가정을 이번 요청으로 대체한다. Date는 날짜를 유지한 YYYY-MM-DD HH:MM 표기로 커밋 시간대의 시·분까지 표시한다. 열 경계는 이웃 두 열의 폭을 교환하여 합계가 항상 100%가 되게 하고 작은 창에서는 최소 폭을 비례 축소한다. 추가 확인이 필요한 모호성은 없다.

- **FR-028**: 히스토리는 가상 스크롤로 가시 범위와 측정 행만 생성한다. UI 렌더링에서 전체 커밋·전체 그래프 경로를 순회하지 않고 그래프 캐시는 가시 행 수준으로 제한한다.
- **FR-029**: 모든 참조와 HEAD의 도달 가능한 전체 커밋을 중복 없이 조회하고 200개 제한을 제거한다. 참조 선택은 이력을 필터링하지 않는다. 로컬·원격 브랜치가 가리키는 행의 Description 맨 앞에 모든 해당 브랜치명을 표시한다.
- **FR-030**: Date는 YYYY-MM-DD HH:MM과 커밋 시간대를 사용한다.
- **FR-031**: 그리드는 항상 사용 가능한 패널 폭의 100%이며 가로 오버플로 없이 다섯 열을 같은 규칙으로 배치한다. 네 열 경계에 조절 커서를 표시하고 드래그·해제·창 크기 변경·프로젝트 전환에도 합계 폭과 정렬을 유지한다.
- **FR-032**: 커밋 선택은 선택 커밋의 상세와 파일만 백그라운드 조회한다. 전체 이력·상태·그래프를 다시 구성하지 않으며 선택 세대와 프로젝트 ID로 오래된 결과를 버린다.
- **SC-010**: 서로 갈라진 로컬·원격·태그·detached HEAD와 200개 초과 이력이 브랜치 선택과 관계없이 모두 조회된다.
- **SC-011**: 대규모 이력에서 렌더링 콜백은 요청받은 범위만 생성한다. 공통 열 폭 합계가 가용 폭과 일치하고 드래그 경계·최소 폭·창 변경 및 날짜 시분을 자동 검증한다.

경계: 최신 요청에 따라 최초 메타데이터는 200개로 제한하고 이후 페이지를 읽는다. 위상 탐색은 관계 판단을 위해 추가 객체 헤더를 읽을 수 있다.

## 공통 스크롤 및 200개 점진 조회 (2026-10-27)

### 사용자 이야기 7 — 긴 목록의 마우스 탐색 (P1)

히스토리·Diff·브랜치·파일 목록에 같은 스크롤바를 표시하고 휠·트랙 클릭·손잡이 드래그로 탐색한다. 모든 목록은 가시 행만 만든다. 최초 커밋은 200개를 읽고 맨 아래에 도달하면 200개씩 자동 추가한다.

명확화: 전체 브랜치 범위는 유지하고 한번에 전부 읽던 방식은 200개 페이지로 대체한다. 체크아웃 표식은 선택 강조와 구분하여 로컬 현재 브랜치 이름 앞에 ●로 표시한다. detached HEAD는 같은 이름의 브랜치를 현재 브랜치로 표시하지 않는다. Diff의 커밋상세 메시지도 가상화 대상이다. 동일 스크롤을 브랜치와 파일에도 적용하라는 추가 요청을 반영한다. 질문이 필요한 모호성은 없다.

- **FR-033**: 네 목록은 공통으로 눈에 보이는 세로 스크롤바와 휠·트랙 클릭·손잡이 드래그를 지원한다. 범위 밖 드래그는 처음/끝으로 제한하고 마우스 해제로 종료한다. 긴 Diff는 가로 스크롤도 제공한다.
- **FR-034**: 히스토리 최초와 추가 요청은 최대 200개 커밋을 반환한다. 맨 아래 도달 시 한 번만 추가 요청하며 진행 중 중복·끝 이후 요청을 막는다. 기존 행과 선택을 보존하고 페이지 경계 그래프를 연결한다. 실패 시 재시도할 수 있고 닫힌 탭의 결과를 적용하지 않는다.
- **FR-035**: 히스토리의 전체 개수 및 첫 부모 기준 라벨을 삭제한다. Graph 헤더와 셀의 왼쪽 여백을 다른 열과 맞춘다.
- **FR-036**: 히스토리 Description과 브랜치 목록에서 현재 체크아웃 로컬 브랜치 이름 앞에 ●를 표시한다. 선택 변경은 이 표식을 바꾸지 않는다.
- **FR-037**: Diff·커밋상세·브랜치·파일은 고정 높이의 가상 행을 사용한다. History 상세 고정 항목·Stage 그룹·파일 원래 인덱스·Diff 줄번호와 색상·빈 상태 및 오류를 유지한다.
- **SC-012**: 200·400·최종 페이지와 정확한 200배수·빈 저장소·중복 요청·취소 및 오류 경계와 페이지 그래프 연속성을 검증한다.
- **SC-013**: 스크롤 손잡이와 트랙의 수치 매핑·경계·작은 뷰포트, Stage 행 인덱스·현재 브랜치 및 detached 상태·긴 Diff 가상화 연결을 검증한다.

전체 개수 계산은 하지 않는다. 브랜치 tip이 아직 읽히지 않았더라도 상세 선택은 가능하며 목록 위치 이동은 로드된 행에 한정한다.

## 히스토리 진행 표시와 브랜치 위치 탐색 (2026-10-27)

### 사용자 이야기 15 — 필요한 로딩만 안내하고 브랜치로 이동 (P1)

일반 선택마다 Progress가 나타나지 않으며 커밋 히스토리를 읽을 때만 기다린다. 도움말은 필요한 단축키 하나만 보여준다. 브랜치를 클릭하거나 키보드로 선택하면 해당 커밋까지 이력을 읽어 위치와 선택을 맞춘다.

- **FR-055**: Progress 표시와 전역 입력 차단의 기준을 히스토리 최초/재조회·추가 페이지·브랜치 탐색 로딩으로 한정한다. 커밋상세·Diff 선택만으로는 표시하지 않는다. fetch 완료 후 히스토리 재조회 구간은 표시한다.

## 참조 이름·Stage 상태와 로컬 새로고침 (2026-10-27)

### 사용자 이야기 16 — 정확한 참조와 파일 상태로 변경 준비 (P1)

- **FR-061**: Stage 탭은 unstaged 신규 `??`, 수정 ` M`, 삭제 ` D`, staged 신규 `A `, 수정 `M `, 삭제 `D `를 두 칸 고정폭으로 표시한다. unstaged 상태는 빨강, staged 상태와 파일명은 초록으로 표시한다. unstaged 파일명은 기존 색상이다. 충돌 상태는 별도 식별하며 같은 경로의 staged/unstaged 변경은 각 행으로 보존한다. History 탭 표기는 변경하지 않는다.

- **FR-063**: 도움말에 `F5 - 새로고침`을 추가하고 F5로 활성 저장소의 로컬 참조·히스토리·파일 상태를 재조회한다. 원격 fetch는 실행하지 않는다. 히스토리를 다시 읽는 구간은 기존 Progress 기준을 따른다. `f - 패치`는 유지한다.
- **SC-024**: 심볼릭 원격 HEAD와 실제 원격 브랜치의 이름·공통 대상·커밋 배지가 각각 정확하며 packed refs에서도 동일함을 검증한다.
- **SC-025**: 임시 저장소의 신규·수정·삭제 및 부분 staged 상태에서 여섯 상태 문자열·단일 경로 스테이징·다른 파일 보존·작업 파일 보존·헤더/행 매핑을 검증한다.
- **SC-026**: F5가 로컬 재조회로 연결되고 도움말에 등록되며 입력 필드·다른 목록·모달에서 Space 스테이징이 실행되지 않는지 검토한다.

명확화: 원격 HEAD 이름을 원래대로 보존한다. 헤더 제거는 명시된 작업 디렉터리 헤더에 한정한다. Space는 추가 요청에 따라 staged/unstaged 양방향으로 전환한다. F5는 로컬 전체 재조회이며 원격 통신은 f로 분리한다. 구현에 필요한 추가 질문은 없다.

명확화: 복수 상태는 각 행을 반전한다. 같은 경로 양쪽 행을 동시에 반전하는 것은 하나의 인덱스로 표현할 수 없으므로 이때는 stage 우선으로 통합한다. History는 기존 단일 선택을 유지한다. 추가 질문이 필요한 모호성은 없다.

### 사용자 이야기 21 — 선택한 변경사항 폐기 (P1)

명확화 질문과 답변: 폐기 범위를 물었고 사용자는 선택 파일의 staged·unstaged 전체를 HEAD로 복원하며 신규 파일을 제거하도록 확정했다. 실행 전 대상 확인창은 유지한다.

명확화: 풀은 fast-forward만 허용하고 자동 병합 커밋을 만들지 않는다. push는 현재 저장소의 표준 설정을 사용하며 force를 사용하지 않는다.

### 커밋 후 푸시 추가 지시

- **FR-084**: 커밋 메시지 오버레이의 커밋·닫기 버튼을 제거하고 Ctrl+S 커밋·Ctrl+P 커밋 후 푸시·Esc 취소를 사용한다. 하단에 `커밋 : ctrl + s, 커밋 후 푸시 : ctrl + p, 취소 : esc`를 표시한다. Ctrl+P는 커밋 성공 후에만 일반 push를 실행하며 커밋 실패 시 푸시하지 않는다. 푸시만 실패하면 커밋 완료와 푸시 실패를 구분해 표시하고 로컬 커밋을 재생성하지 않는다.

수용 시나리오: 히스토리 선택→b→이름 입력→생성. Local 더블클릭→HEAD 변경. Remote 더블클릭→기존 Local 사용 또는 확인창→추적 생성. Description에서 브랜치와 태그가 서로 다른 배지 색으로 보인다.
경계 조건: Detached HEAD·빈 저장소·중복 이름·잘못된 문자·슬래시 포함 원격/브랜치·심볼릭 원격 HEAD·다른 worktree·체크아웃 충돌·원격 삭제/변경·긴 이름·여러 태그를 고려한다.

## 스태시 목록 갱신과 복원 (US39)

- **SC-054**: 저장 후 목록에 새 항목이 보이고, 두 stash 중 선택한 이전 항목의 stage·unstage·untracked가 복원된다. 복원과 충돌 실패 모두 stash 목록을 보존한다.

명확화: 복원은 삭제 없는 적용으로 정한다. 이전 요구의 복원 UI 제외를 이번 요청으로 확장한다. 더블클릭은 추가 확인 없이 복원한다. 추가 질문이 필요한 모호성은 없다.

## 이름 있는 스태시와 확인 삭제 (US40)

- **FR-124**: s 저장 확인창에서 이름을 입력하고 입력한 이름으로 전체 변경을 저장한다. 공백 이름은 거절한다. 한글 조합 중 enter·esc는 저장·닫기를 실행하지 않는다. 기존 저장 범위·stage 보존을 유지한다.
- **FR-125**: Stash 탭의 선택 항목에 브랜치 목록 포커스가 있을 때 d는 해당 항목의 이름을 보여주는 삭제 확인창을 연다. 확인 버튼·enter로만 삭제하며 취소·esc·바깥 클릭은 무변경이다. 파일 목록의 기존 d 폐기는 유지한다.
- **FR-126**: 삭제 후 해당 저장소 Stash 목록을 갱신한다. 작업 트리·인덱스·다른 stash는 보존한다. 선택 이후 순번의 대상이 바뀌면 삭제를 거절한다. 실행 중 편집·닫기·중복 실행을 막고 오류는 창에 표시한다.
- **SC-055**: 한글·공백·옵션처럼 보이는 이름이 그대로 저장되고 빈 이름은 무변경 거절된다. 복수 stash 중 선택 항목만 삭제하고 재삭제·잘못된 대상·순번 변경을 거절하며 작업 트리와 인덱스를 보존한다.

명확화: 이름은 필수 단일 행이다. Stash 선택은 기존 참조 선택을 사용한다. 삭제는 복원과 별도이며 저장 내용은 영구히 목록에서 제거된다고 안내한다. 추가 질문은 없다.

## 참조 삭제·태그 추가·설정 간소화 (US41)

- **FR-127**: Local·Remote·Tag 목록 포커스에서 d로 선택 항목의 삭제 확인창을 연다. 확인·enter로 실행하고 취소·esc·바깥 클릭은 무변경이다. 현재 체크아웃·다른 worktree의 Local 및 미병합 브랜치는 강제로 삭제하지 않는다. Stash 삭제와 파일 폐기는 유지한다. Remote d는 로컬 추적 참조만, Shift+d는 서버도 삭제한다.
- **FR-128**: 히스토리 포커스에서 t를 누르면 선택 커밋의 태그 이름 입력창을 연다. 이름을 입력하고 확인하면 lightweight 태그를 만든다. 중복·잘못된 이름을 거절하고 기존 태그를 덮어쓰지 않는다. 현재 브랜치는 유지한다.
- **FR-129**: 전역 설정 체크박스는 체크 여부와 무관하게 전역 설정 사용이라는 문구를 유지하고 아래 범위 설명은 제거한다. 사용자 설정 저장 버튼을 제거하되 기존 ctrl+s 저장은 유지한다.
- **FR-130**: 원격 로그인에서 GCM 버전·연결 상태·설명과 GCM이라는 구현 용어를 숨긴다. 인증 기능과 계정 상태·오류는 유지하고 연결 버튼은 Git 연결로 표시한다.
- **SC-056**: Local·Tag 삭제 및 태그 생성의 정확한 대상·취소·중복·오류·작업 파일 보존을 검증한다. 각 작업 후 참조 목록과 태그 배지를 갱신한다. 설정 표시 변경과 기존 저장/인증 동작 보존을 코드로 확인한다.

명확화: 태그는 선택 커밋의 로컬 lightweight 태그이다. Local은 안전 삭제만 제공한다. 설정 저장은 버튼만 제거하며 자동 저장으로 변경하지 않는다. 입력·IME·모달·중복 실행 격리는 기존 규칙을 따른다.

명확화 답변: Remote의 d는 로컬 원격 추적 참조만 삭제한다. Shift+d는 서버 브랜치도 삭제한다. 두 동작은 확인창에 범위를 구분하고 원격 HEAD 심볼릭 참조는 거절한다. 서버 대상이 변경되면 삭제를 거절한다.

- **FR-131**: 히스토리 그래프에서 실제 HEAD 커밋은 중앙을 비우고 굵은 외곽선으로 표시한다. 행 선택과 별개이며 detached HEAD도 지원하고 초기 커밋이 없는 저장소에는 표시하지 않는다.

- **SC-057**: HEAD 표시 대상은 선택 커밋과 독립적이며 일반·Detached HEAD의 실제 해시와 일치하고 unborn 저장소는 표시 대상이 없다.

## 입력 영역·원격 생성·커밋 체크아웃 (US42)

- **FR-132**: 단일 행 input은 부모 높이에 맞고 배경·텍스트·스크롤바가 테두리 밖으로 그려지지 않는다. 여러 줄 커밋 입력은 기존 높이와 편집 동작을 유지한다.
- **FR-133**: Local 목록 포커스에서 u는 선택 브랜치의 원격 생성 확인창을 연다. 원격 이름은 origin을 기본으로 편집할 수 있다. 확인하면 선택 브랜치를 같은 이름으로 원격에 새로 생성하고 upstream을 설정한다. 기존 서버 브랜치는 덮어쓰지 않는다. 실패는 창에 표시하고 성공 후 참조를 갱신한다.
- **FR-134**: Tag 더블클릭과 히스토리 커밋 더블클릭은 해당 커밋으로 detached HEAD 체크아웃한다. 로컬 수정 충돌 시 강제 덮어쓰기 없이 거절한다. 성공 후 HEAD·파일 상태·히스토리를 갱신한다. 단일 클릭의 조회는 유지한다.
- **FR-135**: 실제 HEAD의 그래프 중앙은 흰색이며 기존 3px 테두리를 1px 줄인 2px로 표시한다. 일반 노드와 선택 행 표시는 유지한다.
- **SC-058**: 선택한 비활성 Local 브랜치가 원격에 생성되고 upstream이 일치하며 기존 서버 브랜치 생성 시도는 무변경 거절된다. 선택 커밋 체크아웃은 Detached HEAD와 정확한 파일 내용을 만들고 충돌은 HEAD·작업 파일을 보존한다.

명확화: 원격은 이름 입력으로 지정하며 기본값은 origin이다. 태그/커밋 체크아웃은 브랜치를 이동하지 않는 detached 방식이다. 외곽선은 현재보다 1px 줄이는 뜻으로 2px로 정한다. 추가 질문은 없다.

## 히스토리 체크아웃 브랜치 우선 (US43)

- **FR-136**: 히스토리 커밋 더블클릭 시 해당 커밋을 직접 가리키는 Local·Remote 브랜치를 우선한다. 후보가 없으면 detached HEAD, 한 개면 해당 브랜치 체크아웃, 두 개 이상이면 브랜치 선택 팝업을 표시한다. Tag·Stash·원격 HEAD 심볼릭 참조는 후보가 아니다.
- **FR-137**: 선택창은 Local/Remote를 구분한 이름을 보여주고 브랜치 선택 후 확인으로 체크아웃한다. 취소·esc·바깥 클릭은 무변경이다. Remote 선택 시 로컬 추적 생성이 필요함을 안내한다. 현재 브랜치도 다른 후보와 동일하게 선택할 수 있다.
- **FR-138**: 실행 전에 선택 브랜치가 여전히 해당 커밋을 가리키는지 검증한다. Remote와 같은 이름의 Local이 다른 커밋에 있으면 덮어쓰거나 다른 커밋으로 전환하지 않고 오류를 표시한다. 기존 충돌 보호·중복 차단·성공 후 재조회를 유지하며 Tag 더블클릭은 기존 detached 동작을 유지한다.
- **SC-059**: 0/1/복수 후보 분기·Local/Remote 구분·심볼릭 제외·선택 대상 변경 거절·Remote의 다른 Local 보호를 검증한다.

명확화: 브랜치 후보는 Local과 Remote 전체이며 이름이 같아도 서로 다른 참조는 목록에 구분해 표시한다. Local을 먼저 정렬한다. 히스토리만 브랜치 우선으로 바꾸며 태그 동작은 유지한다. 추가 질문이 필요한 모호성은 없다.

## 브랜치 후보 간소화·즉시 선택 (US44)

- **FR-139**: 커밋 체크아웃 후보에서 동일 이름의 Local이 존재하는 Remote는 제외한다. Local이 다른 커밋에 있어도 원격 후보를 제외한다. 원격명 뒤의 전체 브랜치 이름을 비교하며 중첩 이름을 보존한다.
- **FR-140**: 필터 후 후보가 하나면 Local/Remote 여부와 관계없이 확인 없이 즉시 체크아웃한다. 유일한 Remote는 필요하면 로컬 추적 브랜치를 생성한다. 후보가 없으면 detached HEAD로 전환한다.
- **FR-141**: 복수 후보 선택창은 브랜치 클릭 즉시 체크아웃하고 확인·취소 버튼은 표시하지 않는다. Enter로 임의의 기본 후보를 적용하지 않는다. Esc·바깥 클릭은 무변경 닫기다. 오류 표시·중복 차단·대상 재검증은 유지한다.
- **SC-060**: 동일 커밋과 다른 커밋의 같은 이름 Local에 대해 Remote 제외·슬래시 이름 비교·필터 후 후보 수를 검증한다. 유일 Remote의 추적 생성과 정확한 HEAD를 검증한다.

이전 US43의 Remote 중복 노출·선택 후 확인·단일 Remote 확인은 이번 요구로 대체한다. 별도 질문은 없다.

## 팝업 공통 구조와 작은 제목 (US45)

- **FR-142**: 도움말·진행·설정·브랜치/태그 작업·선택창·스태시·폐기·커밋·최근 저장소/삭제의 제목을 동일한 작은 글자 크기로 표시한다. 기존 14~18px 제목은 13px로 통일한다.
- **FR-143**: 모든 팝업은 공통 프레임의 제목 영역·스크롤 가능한 본문·선택적 하단 영역을 사용한다. 폭은 기존 용도별 크기를 유지하고 높이는 창 안으로 제한한다. 버튼이나 안내가 없는 팝업은 빈 하단을 만들지 않는다.
- **FR-144**: 설정 닫기·기존 확인/취소·단축키 안내·버튼 없는 브랜치 즉시 선택·IME·바깥 클릭·진행 중 닫기 차단 등 기존 동작을 유지한다. 오류는 본문에 표시하며 단일 행 입력 클리핑을 유지한다.
- **SC-061**: 모든 팝업 렌더 경로가 공통 프레임을 사용하고 개별 제목 크기 지정은 남지 않는다. 설정 760px·넓은 편집 640px·일반 500px 폭과 각 하단 유무를 검토한다.

명확화: 제목 크기는 공통 13px이며 본문 크기와 팝업별 기능은 바꾸지 않는다. 별도 질문은 없다.

## 선택창 설명 제거·현재 브랜치 무시 (US46)

- **FR-145**: 체크아웃 브랜치 선택창의 하단 설명을 제거하고 제목과 후보 목록만 표시한다.

## 히스토리·상세 표시 보완 (US49)

- **FR-155**: History 파일 목록의 커밋상세와 브랜치 목록 글자를 12px로 줄인다. 커밋상세 앞에 벡터 커밋 아이콘을 표시한다.

명확화: 굵게 표시는 콜론까지의 라벨만 적용한다. 일반 원의 외곽선은 그리지 않아 투명하게 취급한다. 추가 질문은 없다.

## 배경·강조 분리와 아이콘 확대 (US50)

명확화: 선택된 브랜치의 큰 원은 기존 HEAD 표시를 확대한다. 별도 질문은 없다.

## 히스토리 작업 팝업 확장 (US68)

- **FR-200**: Reset 모드는 selectbox 대신 [1] soft, [2] mixed, [3] hard 라디오 버튼으로 표시한다. 클릭과 숫자키는 선택만 바꾸고 확인으로 실행한다. 기본 soft와 모드 설명은 유지한다. FR-197의 selectbox 요구를 대체한다.
- **FR-201**: History에서 v는 선택 커밋 Revert 팝업을 열고 no commit 체크 입력을 제공한다. 기본 해제이며 이후 선택을 기억한다. 확인 시 역변경 커밋을 만들거나 체크 시 커밋하지 않고 인덱스/작업 트리에 적용한다.
- **FR-202**: History에서 m/r은 Merge/Rebase 팝업을 열고 저장소 커밋 히스토리에서 대상을 선택한다. 처음에는 원래 선택 커밋을 선택하고 팝업 내부 선택은 원래 선택을 바꾸지 않는다. 확인 시 현재 HEAD에 선택 커밋을 merge하거나 선택 커밋 위로 현재 브랜치를 rebase한다.
- **FR-203**: 공통 팝업/우측 하단 확인/Esc 취소/Tab 탐색/중복 실행 방지/재조회와 선택·포커스 유지 규칙을 따른다. 충돌은 Git 상태를 보존하고 오류로 표시하며 자동 중단/강제 덮어쓰기를 하지 않는다. 진행 중 작업에는 재실행을 거절한다.
- **SC-084**: 임시 저장소에서 revert 기본/no commit, merge, rebase, 충돌 보존 및 무효 대상 거절을 검증한다. Reset 숫자 선택·팝업 대상 분리·확인 경로를 점검한다.

수용 시나리오: 숫자 3은 hard만 선택하고 확인 전에는 변경이 없다. v의 no commit 옵션은 재열기에도 유지된다. m/r 목록에서 다른 커밋을 선택해 확인하면 해당 대상으로 실행한다. Esc는 변경 없이 닫는다. 충돌 시 작업 상태와 해결할 파일을 유지한다.

명확화: 표준 Git 방향(현재 HEAD에 merge, 선택 커밋을 rebase 기반으로 사용)을 적용한다. merge 커밋 revert는 mainline을 추정하지 않고 Git 오류를 표시한다. 충돌 해결/continue/abort 전용 UI는 이번 범위에서 제외한다. 추가 질문은 없다.

## Merge·Rebase 확인 간소화 (US70)

- **FR-205**: m/r 팝업은 히스토리에서 이미 선택한 커밋을 고정 대상으로 사용한다. 팝업 내부 히스토리/추가 선택/조회는 제거하고 대상 커밋과 작업 방향을 확인하는 내용 및 우측 하단 확인 버튼만 제공한다. FR-202의 팝업 내 대상 선택 요구를 대체한다.
- **FR-206**: 확인 전에는 Git 작업을 실행하지 않는다. Merge는 대상 이력을 현재 HEAD에 합치고 Rebase는 현재 브랜치의 고유 커밋을 대상 위에 재배치한다. 기존 취소/충돌 보호/재조회/선택·포커스 복원은 유지한다.
- **SC-086**: 팝업을 열 때 선택 커밋이 고정되고 확인 시 동일한 대상으로 전달되며 추가 히스토리 조회가 없는지 검증한다.

수용 시나리오: 선택 커밋 A에서 m/r을 열면 A와 작업 방향을 확인하고 실행한다. Esc는 변경 없이 닫는다. 추가로 대상을 선택하지 않는다. 명확화 결과 추가 질문은 없다.

명확화 검토: 다섯 영역과 두 슬롯은 명확하다. 기존 기능에 키를 할당하는 범위로 해석하며 새 기능 작성은 제외한다. 즉시 적용·세션 저장·충돌 거절·Esc 복구를 기본 정책으로 결정하여 추가 질문은 없다.


## 방향 선택 확장 목록 정리 (US72)

- **FR-211**: 공통 단축키 목록에서 위/왼쪽/아래/오른쪽 이동의 선택 확장 항목 네 개를 제거한다. 기본 이동 항목과 기존 Shift 조합의 선택 동작·저장된 키 설정은 유지한다. 설정과 도움말에 동일하게 적용한다.
- **SC-088**: 두 화면이 사용하는 표의 필터에서 네 항목이 제외되고 기존 키 해석과 이동 항목은 변경되지 않았음을 확인한다. 포맷·컴파일·기존 단축키 테스트를 통과한다.

수용 시나리오: 설정과 도움말에서 이동 네 항목은 보이고 ‘이동 / 선택 확장’ 네 항목은 보이지 않는다. Shift+방향키와 Shift+IJKL은 기존처럼 선택을 확장한다.

명확화: 사용자가 지목한 방향 이동의 파생 항목 네 개를 목록에서만 제거한다. 독립 동작과 기존 실행 설정은 변경하지 않으므로 추가 질문은 없다.


## 확인창 공통 키 통합 (US73)

- **FR-212**: 창별 Enter·Escape·Tab·Shift+Tab 항목을 공통 확인·취소·다음입력·이전입력 네 기능으로 통일한다. 기본 키는 확인 Enter/Control+S, 취소 Escape, 다음입력 Tab, 이전입력 Shift+Tab이다. 공통 설정 변경은 모든 관련 창의 실제 동작과 표시에 적용한다.
- **FR-213**: 입력 조합·실행 중 보호를 유지한다. 커밋창 Enter는 확인으로 처리하고 Shift+Enter는 줄바꿈으로 남긴다. 체크아웃 후보창 확인은 선택 후보를 실행한다. 단축키 등록 중 Escape는 등록 취소로 유지한다. 기존 창별 네 기능 재정의는 통합 기본값으로 대체한다.
- **SC-089**: 네 공통 기능만 표시되고 여러 창에서 동일 재정의가 해석되는지, 기존 키 해제·충돌·조합 보호 경로를 검사하고 포맷·컴파일·Clippy·관련 테스트를 통과한다.

수용 시나리오: 확인을 다른 키로 지정하면 브랜치·스태시·커밋·세팅창에서 같은 키가 각 창의 확인을 실행한다. 취소와 다음/이전 입력도 모든 확인창에서 동일하다.

명확화: 사용자가 지정한 네 동작만 통합한다. 확인 없는 도움말은 취소·탐색만 처리한다. 기존 창별 재정의 대신 통합 기본값을 적용하고 새 통합 설정을 저장한다. 추가 질문은 없다.


## 확인 표시·커밋 팝업 구조 (US74)

- **FR-214**: 확인 버튼에는 ‘확인’만 표시하고 키 이름·키 캡을 라벨에 포함하지 않는다. 공통 단축키 설정·실행은 유지한다.
- **FR-215**: 커밋 팝업 본문은 ‘커밋메시지’ 라벨, 메시지 입력창, ‘커밋 후 푸시’ 체크박스 순서로 제공하고 우측 하단에 확인 버튼 하나를 제공한다. 초기 체크는 해제하며 확인 클릭/공통 확인 키는 체크 상태에 따라 커밋만 또는 커밋 후 푸시를 실행한다.
- **FR-216**: 체크 변경은 실행을 유발하지 않는다. 체크는 클릭과 포커스 후 Space로 전환하고 공통 다음입력·이전입력으로 입력창과 체크박스를 탐색한다. 기존 실행 중 중복 방지·조합 입력 보호·오류·취소·메시지 보존을 유지한다. 기존 커밋 후 푸시 전용 키는 체크 전환으로 통합한다.
- **SC-090**: 확인 버튼 렌더링에 단축키 표기가 없고 커밋 실행이 체크 상태를 읽는 단일 경로인지 확인한다. 포맷·컴파일·Clippy 및 관련 기존 테스트를 통과한다.

수용 시나리오: 체크 해제 후 확인은 커밋만 하고, 체크 선택 자체는 실행하지 않으며 확인 후에만 푸시한다. 실패하면 입력과 체크 상태를 유지한다.

명확화: 요청 순서와 초기 해제·팝업별 상태를 적용한다. 이전 직접 커밋 후 푸시 키는 이제 체크 전환이며 확인은 공통 키로 실행한다. 추가 질문은 없다.


## 단축키 설정 탭·명칭 (US75)

- **FR-217**: 단축키 설정 팝업의 상단 사용 안내 문구를 제거한다. 공통·브랜치·커밋히스토리·파일목록·뷰어를 탭으로 제공하고 선택한 섹션의 표만 표시한다. 팝업을 열면 공통 탭을 선택하고 탭 전환 시 진행 중 키 등록과 안내 상태를 취소한다. 기존 두 슬롯 편집·충돌 안내·복원·저장은 유지한다.
- **FR-218**: 커밋히스토리 기능명 ‘브랜치 만들기’, ‘태그 추가’, ‘선택 커밋 체크아웃’을 각각 Add Branch, Add Tag, Checkout으로 표시한다. 기능 ID와 실제 동작·기존 키 설정은 유지한다.
- **SC-091**: 안내 문구 부재·다섯 탭 및 선택 섹션 필터·등록 취소·세 기능명과 기존 ID를 검토하고 포맷·컴파일·관련 테스트를 통과한다.

수용 시나리오: 설정을 열면 공통 표만 보이고 커밋히스토리 탭을 클릭하면 영문 세 기능명이 표시된다. 탭을 바꾼 뒤에도 등록된 키는 유지된다. 명확화: 도움말은 기존 전체 목록을 유지하며 공유 기능명의 영문 표시는 함께 반영한다. 추가 질문은 없다.


## 히스토리 작업 대상 행 제거 (US76)

- **FR-219**: Revert·Merge·Rebase 팝업에서 대상 커밋 표시 행을 제거한다. 선택 커밋을 실행 대상으로 보관·전달하는 동작과 옵션·설명·확인·취소는 유지한다. 기존 FR-205의 대상 커밋 표시 요구는 이번 요구로 대체한다.
- **SC-092**: 세 팝업의 표시 행이 없고 실행 대상 전달이 유지되는지 검토하고 포맷·컴파일 검사를 통과한다.

수용 시나리오: 히스토리에서 선택 커밋으로 팝업을 열면 대상 행 없이 옵션 또는 작업 설명과 확인을 표시하고 확인 시 같은 커밋으로 실행한다. 명확화: 표시 행만 제거하므로 추가 질문은 없다.


## 단축키 일괄 승인 (US77)

- **FR-220**: 단축키 팝업에서 등록·변경·해제는 모든 탭이 공유하는 임시 편집 상태에만 반영한다. 우측 하단 확인 시 전체 탭 변경을 한 번에 저장·적용하고 닫는다. 확인 전 실제 키 처리·도움말·저장된 설정은 유지한다.
- **FR-221**: 기본값 복원은 확인 왼쪽에 두며 모든 탭의 임시 상태만 기본값으로 바꾼다. 확인 전에는 실행·저장에 반영하지 않는다. 확인 없이 취소하거나 바깥을 클릭해 닫으면 임시 변경을 버린다.
- **FR-222**: 편집 중 충돌은 임시 전체 설정 기준으로 검사한다. 확인/취소 키는 승인 전 기존 설정을 사용한다. 키 등록 중 확인 키는 등록 입력으로만 취급한다. 저장 실패 시 기존 실행 설정을 유지하고 편집 내용과 오류를 남겨 재시도할 수 있게 한다.
- **SC-093**: 등록·해제·복원의 임시 상태 변경과 단일 확인 경로·저장 성공 전 실행 설정 불변·닫기 폐기·탭 간 유지 경로를 점검하고 포맷·컴파일·Clippy 및 기존 단축키/세션 테스트를 통과한다.

수용 시나리오: 공통과 뷰어에서 키를 변경해도 확인 전에는 적용되지 않으며 확인하면 둘 다 반영된다. 복원 후 취소하면 기존 설정을 유지하고 확인하면 전체 기본값이 적용된다. 명확화: 기존 즉시 적용 요구 FR-209를 본 요구로 대체한다. 추가 질문은 없다.

- **FR-223**: 단축키 표 헤더에 회색 배경을 넣어 기능·단축키1·단축키2 제목을 본문과 구분한다.


## 단축키 설정 헤더 제거 (US78)

- **FR-224**: 단축키 설정 팝업에서 기능·단축키1·단축키2 헤더 행을 제거한다. 가로 패딩은 추가하지 않는다. 탭·본문 셀·임시 편집·복원·일괄 확인 동작은 유지한다. 설정 화면의 기존 FR-223 헤더 요구는 대체한다.
- **SC-094**: 편집 화면에 헤더를 렌더링하지 않고 기존 셀 여백·열 너비가 유지되는지 검토하고 포맷·컴파일 검사를 통과한다.

수용 시나리오: 각 설정 탭에서 헤더 없이 바로 기능과 두 단축키 슬롯을 표시한다. 명확화: 앞선 패딩 요청은 취소되어 구현하지 않는다. 도움말의 기존 헤더는 유지하며 추가 질문은 없다.


- **FR-225**: 단축키 설정 팝업의 높이를 탭 내용과 무관하게 일정하게 유지한다. 기본 640픽셀이며 작은 화면에서는 기존 화면 여백을 보장하는 높이로 제한한다. 긴 목록은 본문 내부 스크롤로 표시하고 우측 하단 확인·복원 위치는 유지한다.
- **SC-095**: 고정 높이가 탭에 의존하지 않고 화면 높이에 제한되며 본문이 가용 공간을 채워 스크롤하는지 검토하고 포맷·컴파일·Clippy 검사를 통과한다.

명확화: 고정 높이는 기존 최소 창 크기와 화면 여백에 맞춰 제한한다. 다른 팝업의 내용 기반 높이는 유지하며 추가 질문은 없다.


## 공통 방향키·입력전환 통합 (US79)

- **FR-226**: 공통 섹션의 기본 방향 이동과 Reset 모드 이동을 방향키 위·아래·왼쪽·오른쪽 네 기능으로 통합한다. 같은 설정이 기존 목록/뷰어 이동과 Reset 라디오 이동을 처리한다. 기본 방향키 및 IJKL은 유지한다.
- **FR-227**: 공통 섹션의 Space 기능인 브랜치 작업 체크 전환·Reset 라디오 전환·커밋 후 푸시 체크 전환을 입력전환 하나로 통합한다. 해당 컨트롤에 포커스가 있을 때 같은 설정으로 전환한다. 브랜치·파일목록 섹션의 Space 동작은 별도 유지한다.
- **FR-228**: 편집 입력·조합·실행 중 보호와 전 탭 임시 편집·확인 적용을 유지한다. 새 공통 입력전환은 기본 Space이며 기존 창별 전환 재정의는 대체한다. 기존 nav ID와 재정의는 유지하고 Reset 전용 방향 재정의는 공통 설정으로 대체한다.
- **SC-096**: 공통 네 방향·한 전환 정의만 존재하고 여러 범위에서 동일 재정의가 실행 명령으로 해석되는지, 전용 Space 보존·충돌·포커스 분기를 확인하며 포맷·컴파일·Clippy·관련 테스트를 통과한다.

수용 시나리오: 공통 위 키 변경 후 확인하면 목록과 Reset에서 같은 키로 위 이동한다. 입력전환 키는 포커스된 각 체크박스를 전환한다. 브랜치 위치 이동·파일 Stage Space는 바뀌지 않는다. 명확화: 사용자가 적용 범위를 공통 섹션으로 한정했으며 추가 질문은 없다.


## Stage 파일목록 커밋·스태시 제한 (US80)

- **FR-229**: 커밋·스태시 단축키는 활성 저장소의 파일목록에 포커스가 있고 Stage 탭이 활성화된 경우에만 팝업을 연다. 다른 영역 또는 History 파일 탭에서는 실행하지 않는다.
- **FR-230**: 설정의 두 기능을 공통에서 파일목록 섹션으로 옮기며 기능 ID·기존 지정 키·확인 승인 방식은 유지한다. 다른 파일목록 키와 일반 단축키·팝업 내 입력·실행 보호는 유지한다.
- **SC-097**: Stage 파일 범위에서만 기본/재정의 커밋·스태시 키가 해석되고 나머지 범위는 실행하지 않는지와 공통/파일 키 충돌 및 기존 파일 키를 검증한다. 포맷·컴파일·Clippy·관련 테스트를 통과한다.

수용 시나리오: Stage 파일목록에서 s/c는 팝업을 열지만 히스토리·브랜치·뷰어 및 History 파일목록에서는 열지 않는다. 명확화: 단축키 호출만 제한하며 기존 기능 내부 실행 조건과 설정 키는 보존한다. 추가 질문은 없다.


## 단축키 탭 하위 분류·내부 선택 숨김 (US81)

- **FR-231**: 단축키 설정에서 브랜치는 Local·Remote·Stash·Tag, 파일목록은 Stage·History 하위 분류를 실제 탭 순서대로 표시한다. 각 탭에서 적용되는 기능을 표시하고 빈 분류는 단축키 없음으로 안내한다. 사용자 선택대로 같은 기능의 설정 ID와 두 슬롯은 여러 하위 분류에서 공유한다.
- **FR-232**: 체크아웃 후보 선택·Reset 모드 숫자 선택 항목은 단축키 설정 목록에서 숨기되 기존 실행 정의·저장된 재정의·실제 숫자키 동작은 유지한다. 기존 방향 선택 확장 숨김도 유지한다.
- **FR-233**: Local 원격 생성은 Local, 서버 원격 삭제는 Remote에만 표시하고 공통 참조 이동·체크아웃·삭제는 각 해당 분류에 표시한다. Stage 전용 커밋·스태시·파일 선택/Stage/폐기는 Stage에만 표시한다. 기존 탭·고정 높이·임시 편집·일괄 확인은 유지한다.
- **SC-098**: 하위 분류·기능 배치·공유 ID·중복 UI ID 방지·내부 선택 숨김과 실행 보존을 점검하며 포맷·컴파일·Clippy·관련 테스트를 통과한다.

수용 시나리오: Local의 공통 참조 키를 편집하면 다른 참조 분류에서도 같은 값이 보이고 확인할 때 함께 적용된다. Stage 분류에는 커밋·스태시가 있고 History에는 표시하지 않는다. 공통 목록에는 후보/Reset 숫자 행이 없지만 실제 선택창 숫자키는 동작한다.

명확화: 사용자는 ‘기존처럼 같은 기능의 키 설정 공유’를 선택했다. 하위 분류는 섹션 제목으로 표시하며 별도 키 정의를 만들지 않는다. 숨김은 설정/도움말의 공용 목록에 적용한다. 추가 질문은 없다.


- **FR-234**: 체크아웃 후보창의 첫 열 개 후보 키 및 Reset 세 모드 키를 대괄호 텍스트 대신 배지로 표시한다. 기존 숫자/재정의 키 표시와 클릭·숫자 선택 동작은 유지하며 열한 번째 이후 후보에는 번호 배지를 추가하지 않는다.
- **SC-099**: 두 화면이 같은 배지 표현을 사용하고 기존 키 라벨과 선택 전달을 보존하는지 검토하고 포맷·컴파일 검사를 통과한다.

명확화: 번호는 키 설정의 현재 표시값을 재사용하며 배지는 시각 표현만 변경한다. 추가 질문은 없다.


- **FR-235**: 단축키 설정의 두 슬롯 값과 미지정·키 등록 상태도 공통 배지 형태로 표시한다. 클릭 등록·지우기·하위 분류 공유·임시 편집·일괄 확인은 유지한다.
- **SC-100**: 설정 두 슬롯이 공통 배지를 사용하고 기존 등록 이벤트·상태·공유 ID가 유지되는지 검토하고 포맷·컴파일·Clippy 검사를 통과한다.

명확화: 배지는 표시 방식만 바꾸고 기능 및 설정 승인 방식은 유지한다. 추가 질문은 없다.


## 브랜치 삭제 팝업 정리 (US82)

- **FR-236**: 브랜치 섹션 d의 참조 삭제 팝업 제목을 브랜치 삭제로 바꾸고 참조 이름 행을 제거한다. 본문에 ‘선택한 브랜치 또는 태그를 삭제할까요?’와 그 아래 ‘원격 브랜치 삭제’ 체크박스를 표시한다. footer는 우측 확인만 두고 취소 버튼을 제거하며 공통 취소 키·바깥 클릭은 유지한다.
- **FR-237**: 체크박스는 기존처럼 Remote 참조에서만 선택 가능하며 Local·Tag에서는 비활성화한다. d는 기본 해제, 기존 Remote Shift+d는 선택으로 연다. 체크 선택은 실행하지 않으며 확인 시 기존 server 옵션으로 실제 원격 삭제 범위를 전달한다. 기존 무효 대상·HEAD·참조 변경·원격 lease·중복 실행 보호를 유지한다.
- **FR-238**: 활성 체크박스는 클릭·공통 입력전환과 다음/이전 입력을 지원한다. 선택은 팝업 상태에만 보관하며 취소 시 삭제하지 않는다. 별도 원격 추정이나 Local/Tag 원격 삭제 기능은 추가하지 않는다.
- **SC-101**: 제목·이름 행/취소 버튼 제거·체크 위치·Remote 제한·기본값·확인 대상 및 server 전달을 검토하고 포맷·컴파일·Clippy와 기존 삭제 회귀 테스트를 통과한다.

수용 시나리오: Remote에서 d로 연 뒤 체크하고 확인하면 선택 원격 브랜치를 삭제한다. 체크하지 않으면 추적 참조만 삭제한다. Local/Tag는 체크 비활성이며 기존 로컬 삭제를 수행한다. 명확화: 체크 적용 범위는 기존 server 옵션의 Remote 제한을 보존하고 추가 질문은 없다.


## 참조 종류별 삭제·연결 대상 (US83)

- **FR-239**: Local·Remote·Tag·Stash 삭제 팝업을 각각 구분한다. 제목은 Local 브랜치 삭제·Remote 브랜치 삭제·Tag 삭제·Stash 삭제다. Local은 연결 원격 참조와 원격 브랜치 삭제 체크, Remote는 연결 로컬 참조와 로컬 브랜치 삭제 체크를 제공한다. 연결이 없으면 없음으로 표시하고 체크를 비활성화한다. Tag·Stash에는 체크를 두지 않는다. 취소 버튼 없이 우측 확인과 기존 취소 키/바깥 클릭을 유지한다.
- **FR-240**: 연결은 Git upstream 설정으로 확인하며 같은 이름을 추정하지 않는다. Local은 선택 로컬과 실제 원격 추적 참조를, Remote는 선택 원격을 upstream으로 사용하는 모든 로컬을 표시한다. 공통 체크의 기본값은 해제이며 표시한 관련 대상만 추가 삭제한다. 기존 Remote Shift+d도 같은 팝업을 열고 로컬 추가 삭제는 기본 해제한다.
- **FR-241**: Local 기본 확인은 선택 로컬만 삭제하고 체크 시 연결된 서버 원격과 추적 참조도 삭제한다. Remote 기본 확인은 서버 원격과 추적 참조를 삭제하고 체크 시 표시된 로컬도 삭제한다. Tag와 Stash는 기존 전용 삭제 경로를 유지한다. 이는 이전 FR-237의 Remote 추적 참조만 기본 삭제하는 정책과 Local 비활성 정책을 대체한다.
- **FR-242**: 팝업 대상·연결·참조 해시 및 원격 refspec 목적지를 스냅샷으로 고정하고 실행 전 재검증한다. 추가 대상이 달라지면 재열기를 요구한다. 서버 삭제는 원격 해시 lease를 사용하며 로컬 추가 삭제는 현재/다른 worktree 사용 및 현재 HEAD에 병합되지 않은 경우 원격 변경 전에 거절한다. 원격 삭제 실패 전에는 로컬을 삭제하지 않는다. 서버와 로컬 간 완전한 원자성은 보장하지 않으며 원격 성공 후 로컬 실패는 부분 완료를 명시하고 강제 삭제/자동 복구를 하지 않는다.
- **FR-243**: 관계 조회는 비동기로 수행하고 조회/삭제 중 중복 실행을 막는다. 체크는 클릭·공통 입력전환·다음/이전 입력을 지원하며 확인 전에는 변경하지 않는다. 실패 후 기존 재조회·선택 보존을 유지한다.
- **SC-102**: 실제 임시 로컬/서버 저장소에서 upstream 이름 불일치·다중 로컬·연결 없음·체크 선택/해제·Tag·사용 중/미병합/변경된 대상·원격 lease 및 사용자 refspec 매핑을 검증한다. 포맷·컴파일·Clippy·삭제 회귀 테스트를 통과한다.

수용 시나리오: Local topic이 origin/other를 추적하면 그 원격을 표시하고 체크 시 둘을 삭제한다. Remote origin/other를 두 로컬이 추적하면 둘을 표시하고 체크 시 둘 다 삭제한다. 참조가 없으면 체크할 수 없다. 확인 전 어떤 참조도 삭제하지 않는다.

명확화: 여러 연결 로컬은 모두 표시하고 체크 시 표시된 전체를 대상으로 한다. Remote의 기본 작업은 실제 서버 삭제로 해석한다. 로컬 추가 삭제는 현재 HEAD에 병합된 경우로 제한하여 강제 삭제를 방지한다. 추가 질문은 없다.


## 브랜치 푸시 이름·키·우선순위 (US84)

- **FR-244**: 브랜치 Local의 Local 브랜치 원격 생성 기능명을 브랜치 푸시로 바꾸고 기본 키를 u에서 Shift+P로 변경한다. 기능 ID와 기존 원격 게시·입력·실행 보호는 유지한다. 사용자 재정의는 보존한다.
- **FR-245**: 브랜치 단축키와 공통 단축키가 같은 활성 범위에서 충돌하면 브랜치 기능을 우선 실행한다. 두 그룹 간 같은 키 지정을 허용하며 같은 브랜치 그룹 내부 또는 다른 기존 충돌은 거절한다. Local Shift+P는 브랜치 푸시를 열고 다른 영역에서는 공통 푸시를 유지한다. 순서는 정의 배열 순서에 의존하지 않는다.
- **FR-246**: 해당 팝업 제목을 브랜치 푸시로 변경하고 브랜치명·설명·취소 버튼을 제거한다. 원격 이름 입력과 우측 확인·공통 취소 키·바깥 클릭 및 실제 선택 브랜치 게시 동작은 유지한다.
- **SC-103**: 기본 키/이름·Local 범위·브랜치 우선·충돌 허용/거절·다른 범위 공통 푸시·팝업 배치·실제 게시 전달을 검토하고 포맷·컴파일·Clippy·관련 테스트를 통과한다.

수용 시나리오: Local에서 Shift+P는 공통 자동 푸시 대신 브랜치 푸시 팝업을 열고 u는 기본으로 실행하지 않는다. 공통 키와 중복 지정한 브랜치 키는 브랜치 포커스에서 우선하고 다른 영역에서는 공통 기능을 실행한다. 명확화: 사용자가 브랜치 섹션 우선순위를 명시했으며 추가 질문은 없다.


## 브랜치 푸시 기본 키 복원 (US85)

- **FR-247**: 브랜치 푸시의 기본 키를 다시 u로 변경한다. 기능명·Local 범위·팝업 구성·브랜치 우선 정책·기존 사용자 재정의는 유지한다. FR-244의 기본 Shift+P 요구만 대체한다.
- **SC-104**: 기본 u가 Local 브랜치 푸시로, 기본 Shift+P가 공통 푸시로 해석되는지와 우선순위 회귀를 검증하고 포맷·컴파일·관련 테스트를 통과한다.

수용 시나리오: 기본 설정에서 Local의 u는 브랜치 푸시 팝업을 열고 Shift+P는 공통 푸시를 실행한다. 명확화: 단축키만 되돌리며 추가 질문은 없다.

## 팝업 입력 드래그 보호 (US86, 우선순위 P1)

- **FR-248**: 모든 공통 팝업은 입력창이나 카드 내부에서 왼쪽 버튼을 누르고 배경에서 놓더라도 닫히지 않는다. 입력 선택과 카드 내부 버튼은 정상 동작한다.
- **FR-249**: 배경에서 누르고 배경에서 놓으면 기존 닫기 정책을 적용한다. 배경에서 눌러 카드 안에서 놓으면 닫지 않는다. 취소 키와 작업 진행 중 닫기 제한은 유지한다.
- **SC-105**: 내부→내부, 내부→배경, 배경→내부, 배경→배경의 네 경계 시나리오가 각 요구를 만족하고 포맷·컴파일·Clippy·기존 팝업 및 입력 테스트를 통과한다.

수용 시나리오: 입력 텍스트를 선택하다 카드 밖에서 놓아도 팝업과 입력 내용이 유지된다. 이후 배경을 클릭하면 닫기 가능한 팝업은 닫힌다. 내부 버튼과 취소 키도 정상 동작한다.

명확화: 앞서 확인한 원인의 수정으로 범위를 한정한다. 사용자·데이터·성능·외부 연동 변경은 없고 추가 질문은 없다. 화면 동작의 실제 검증 여부는 검증 기록에서 구분한다.

## 커밋 입력 Shift+Enter 줄바꿈 (US87, 우선순위 P1)

- **FR-250**: 커밋 팝업의 메시지 입력에 포커스가 있으면 Shift+Enter는 커서 위치에 줄바꿈을 한 번 삽입하며 선택 영역이 있으면 대체한다. 커밋 확인이나 다른 팝업 작업을 실행하지 않는다. 단축키 재정의보다 메시지 줄바꿈을 우선한다.
- **FR-251**: 일반 Enter·기존 확인 키·다른 입력창의 동작을 유지한다. 한글 조합과 작업 진행 중 입력 보호를 유지한다. Ctrl·Alt·플랫폼 키를 함께 누른 조합은 이번 고정 줄바꿈에 포함하지 않는다.
- **SC-106**: 커밋 입력 포커스에서 Shift+Enter가 확인 명령 해석을 거치지 않고 기존 편집기의 줄바꿈에 도달하는지 검토하고 포맷·컴파일·Clippy·기존 편집기/단축키 테스트를 통과한다.

수용 시나리오: 커밋 메시지 중간에서 Shift+Enter를 누르면 다음 줄로 나뉘고 팝업은 유지된다. 선택 텍스트는 줄바꿈으로 대체된다. 확인 키에 Shift+Enter를 지정해도 메시지 입력에서는 줄바꿈한다. 명확화: 메시지 입력 포커스로 범위를 한정하며 추가 질문은 없다.

## 파일목록 트리 토글 (US88, 우선순위 P1)

- **FR-252**: 활성 파일목록에서 백틱(`) 키를 누르면 평면 목록과 폴더 트리를 왕복 전환한다. 초기값은 평면이며 실행 중 Stage·History와 프로젝트에 공통 적용한다. 입력창·팝업·다른 영역에서는 토글하지 않는다. 단축키 설정·도움말의 파일목록 기능으로 등록하고 재지정을 지원한다.
- **FR-253**: 트리는 실제 경로를 폴더 계층으로 표시하고 폴더를 클릭하여 접고 펼친다. 처음에는 모두 펼친다. 폴더는 파일 작업 대상이 아니며 파일 이름·상태·선택·미리보기를 표시한다. 같은 경로의 Stage/Unstage 항목은 각각 유지한다.
- **FR-254**: 모드 변경은 선택·미리보기·실제 작업 대상을 변경하지 않는다. 키보드 위/아래는 보이는 파일 순서로 이동하며 Shift 범위 선택은 보이는 파일만 포함한다. 전체 선택은 기존처럼 모든 변경 파일에 적용한다. 데이터 재조회·커밋 전환 후에도 현재 모드를 적용하고 빈 목록·한글 경로를 처리한다. 재실행 복원은 추가하지 않는다.
- **SC-107**: 경로 계층·접힘·같은 경로 중복·원본 인덱스·가시 범위 선택·단축키 범위와 재지정을 자동 검증하고 포맷·컴파일·Clippy·관련 테스트를 통과한다.

수용 시나리오: Stage에서 백틱으로 트리를 열고 폴더를 접으면 자식 파일만 숨는다. 다시 펼쳐 파일을 선택하면 해당 변경을 미리본다. 백틱으로 평면으로 돌아와도 선택이 유지된다. History·재조회에도 모드를 적용한다. 명확화: 실행 중 공통 보기 모드, 목록별 접힘 상태, 기본 전체 펼침으로 정하며 추가 질문은 없다.

## 펼친 트리·디렉터리 일괄 Stage (US89, 우선순위 P1)

- **FR-255**: 트리 폴더는 항상 펼쳐서 유지하며 클릭·키보드로 접거나 펼치지 않는다. 접힘 상태·접힘 화살표를 제거한다. FR-253~FR-254의 접힘 및 가시 파일 한정 탐색 요구를 이 항목과 FR-257로 대체한다.
- **FR-256**: Stage 트리에서 디렉터리를 선택하고 기존 Space(Stage/Unstage) 명령을 실행하면 모든 깊이의 하위 변경 파일을 한 번의 일괄 작업으로 처리한다. 하위에 Unstaged 변경이 하나라도 있으면 전체를 Stage하고, 모두 Staged이면 전체를 Unstage한다. 같은 경로는 중복 실행하지 않고 접두 이름만 같은 형제 폴더와 바깥 파일은 제외한다. History 디렉터리에서는 저장소를 변경하지 않는다.
- **FR-257**: 디렉터리는 클릭과 위/아래 이동으로 선택할 수 있고 선택을 강조한다. 파일 선택은 기존 동작을 유지하며 Shift 파일 범위 선택은 디렉터리를 건너뛴다. 디렉터리 선택은 이전 파일 선택/미리보기와 구분하고, 처리 후 디렉터리 선택을 유지해 다시 Space로 반대 작업을 수행할 수 있다. 모드/탭 전환·다른 파일 선택·전체 선택은 디렉터리 작업 대상을 해제한다. 기존 진행/중복 실행 방지·경로 검증·오류 표시를 유지한다.
- **SC-108**: 전체 펼침·하위 경계·깊은 하위·혼합 상태/부분 스테이징 중복·모두 Staged·빈 대상의 자동 테스트와 기존 일괄 Stage 테스트를 통과한다. 포맷·컴파일·Clippy 및 관련 테스트를 통과한다.

수용 시나리오: Stage 트리에서 src를 클릭하거나 방향키로 선택한 뒤 Space를 누르면 src 아래 변경만 모두 Stage되고 다음 Space로 모두 Unstage된다. src2는 영향을 받지 않는다. History의 폴더는 선택만 가능하다. 명확화: 혼합 상태는 전체 Stage로 통일하고 폴더 구조는 항상 펼친 채 유지한다. 기존 일괄 처리와 보호를 재사용하며 추가 질문은 없다.

## Local 원격 브랜치 연결 (US90, 우선순위 P1)

- **FR-258**: 브랜치 Local의 브랜치 푸시 기능과 해당 설정/도움말 항목·기본 u 실행을 제거한다. 대신 기본 r로 선택한 Local 브랜치의 원격 연결 창을 연다. 새 기능은 단축키 재지정을 지원하고 Local에만 적용한다. 공통 Push·브랜치 생성 시 원격 생성 옵션·History r은 유지한다. FR-244·FR-246~FR-247의 Local 푸시 요구를 대체한다.
- **FR-259**: 연결은 선택 Local 브랜치의 Git upstream 설정이다. 이미 Fetch된 원격 추적 브랜치 목록을 보여주고 클릭·위/아래로 선택하며 현재 upstream을 기본 선택한다. 여러 원격·다른 브랜치 이름·사용자 fetch 매핑을 처리하고 symbolic HEAD·매핑 불명확 참조는 제외한다. 대상이 없으면 Fetch 안내를 표시한다. 자동 Fetch는 하지 않는다.
- **FR-260**: 확인 전에는 변경하지 않는다. 확인하면 선택 Local 브랜치만 선택한 원격 브랜치에 연결하며 기존 연결 교체도 허용한다. Checkout·Push·참조 이동·파일/인덱스 변경은 하지 않는다. 취소 키·바깥 클릭은 변경 없이 닫고 목록이 비어 있으면 실행하지 않는다.
- **FR-261**: 목록 조회·설정 변경은 비동기로 처리하고 중복 실행을 막는다. 확인 전에 Local/원격 대상 해시·기존 upstream·fetch 매핑을 재검증하여 변경되거나 사라진 경우 재열기를 요구한다. 실패는 창에 표시하고 성공 후 재조회와 브랜치 포커스를 복원한다. 삭제된 푸시 기능의 저장된 키 설정이 새 기능으로 이전되거나 실행되지 않게 한다.
- **SC-109**: 실제 임시 저장소에서 현재/비현재 Local·이름 불일치·여러 원격·사용자 매핑·기존 연결 교체·symbolic 제외·빈 목록·대상/매핑 변경 거절과 파일/인덱스/HEAD 보존을 검증한다. 단축키 범위·재지정·과거 기능 무효화를 검증하고 포맷·컴파일·Clippy·관련 테스트를 통과한다.

수용 시나리오: Local topic에서 r을 누르면 origin/main·backup/other 등 후보를 표시한다. backup/other를 선택해 확인하면 topic이 해당 브랜치를 추적한다. topic으로 Checkout하거나 원격을 변경하지 않는다. 명확화: 서버 실시간 조회가 아닌 Fetch된 목록을 사용하고 확인으로 upstream만 설정한다. 추가 질문은 없다.

## 원격 연결 라디오 목록 (US91, 우선순위 P1)

- **FR-262**: 원격 브랜치 연결 팝업의 Local 브랜치명 표시 행을 제거한다. 연결 대상은 기존 선택 Local로 유지한다. 원격 후보는 하나만 선택되는 라디오 목록으로 표시하며 현재 upstream 기본 선택을 유지한다. 클릭·다음/이전 입력 포커스·공통 위/아래 키로 선택할 수 있고 선택 행으로 자동 스크롤한다. Space는 선택 유지, 확인 키/버튼만 실제 연결한다.
- **FR-263**: 목록은 최대 8행을 표시하고 초과하면 목록 안에서 세로 스크롤할 수 있다. 각 행 높이를 일정하게 유지해 항목이 줄어들지 않게 한다. 작은 창에서는 목록 높이를 가용 높이로 제한한다. 빈 목록 안내·진행 보호·취소·재검증은 유지한다.
- **SC-110**: Local 표시 행 제거·라디오 단일 선택·포커스/키 처리·8행 초과 스크롤과 기존 실행 보호를 코드 검토하고 포맷·컴파일·Clippy·기존 연결/단축키 테스트를 통과한다. 실제 화면 검증 여부는 별도로 기록한다.

수용 시나리오: r로 연 목록에서 위/아래로 라디오 선택을 이동하고 9번째 항목으로 이동하면 해당 행이 스크롤되어 보인다. 확인 전에는 연결을 바꾸지 않는다. 명확화: 한 화면 8행을 기본으로 하며 추가 질문은 없다.

## Merge 충돌 해결·완료·중단 (US92, 우선순위 P1)

- **FR-264**: 저장소 조회/새로고침/재실행에서 실제 진행 중인 Merge와 미해결 파일 수를 감지해 상단에 표시한다. Merge 충돌 시 일반 오류 팝업만 남기지 않고 Stage 화면으로 연결한다. Rebase/Revert 진행은 이번 완료/중단 대상이 아니다.
- **FR-265**: Stage 목록의 미해결 충돌 파일을 별도 표시하고 현재 작업 파일 내용을 기존 뷰어로 확인할 수 있게 한다. 외부 편집기로 수정/저장한 뒤 기존 Space Stage로 해결 완료 표시하며 삭제로 해결한 파일도 지원한다. 충돌은 문자열 마커가 아닌 인덱스의 미병합 항목으로 판단하고 경로별 한 항목으로 표시한다. 앱 내부 병합 편집기는 추가하지 않는다.
- **FR-266**: 미해결 충돌이 없으면 병합 완료 버튼을 사용할 수 있다. 확인 후 기본 병합 메시지로 Merge를 완료하며, 미해결 충돌이 있으면 UI와 실행 직전 검증에서 거절한다. 병합 중단은 확인창에서 해결 내용 손실 가능성과 병합 전 미커밋 변경의 완전 복원 불가 가능성을 안내하고 Git의 Abort로 수행한다. 강제 Reset으로 대체하지 않는다.
- **FR-267**: 완료/중단 실행 직전에 같은 저장소의 HEAD·현재 브랜치·병합 대상이 유지되는지 확인한다. 다른 작업 상태·이미 종료/교체된 병합을 거절한다. 실행은 비동기이며 중복을 막고 성공/실패 후 상태를 다시 조회한다. 실패하면 상태와 오류를 남겨 재시도할 수 있다. Stage 후 충돌 수와 완료 가능 상태를 갱신한다.
- **FR-268**: 병합 중 일반 커밋·Checkout·Reset·새 Merge/Rebase/Revert·Stash·삭제·Pull/Push 등 경합하는 단축키 작업을 제한하고 Stage·조회·새로고침·탐색은 허용한다. 진행 중 Merge는 프로젝트별로 관리하고 연결된 worktree에서도 인식한다. 기존 ff-only Pull 정책은 유지한다.
- **SC-111**: 임시 실제 저장소에서 텍스트 충돌·수정/삭제 충돌·외부 수정 후 Stage·완료 커밋 부모/내용·Abort 원상태·재실행 조회·worktree·미해결/오래된 상태 거절·실패 상태 보존을 검증하고 포맷·컴파일·Clippy·관련 테스트를 통과한다.

수용 시나리오: Merge 충돌 후 Stage 목록에서 충돌 파일을 보고 외부에서 수정한 뒤 Space로 Stage한다. 충돌 수가 0이 되면 병합 완료 확인으로 두 부모의 커밋을 만든다. 대신 병합 중단 확인을 선택하면 Git이 복구를 시도하고 결과를 다시 표시한다. 명확화: Merge만 대상으로 기존 편집/Stage 흐름과 기본 병합 메시지를 사용한다. 추가 질문은 없다.

## Rebase 충돌 해결·계속·중단·건너뛰기 (US93, 우선순위 P1)

- **FR-269**: Rebase 진행 상태를 저장소 조회·재실행·새로고침에서 읽고 현재 단계/전체 단계·현재 커밋(알 수 있는 경우)·충돌 수를 표시한다. Merge와 구분하고 merge/apply 방식 및 linked worktree를 지원한다. 일반 git am 상태는 Rebase로 취급하지 않는다.
- **FR-270**: Merge와 같은 충돌 행/작업 결과 뷰어·외부 수정 후 Space Stage 흐름을 사용한다. 미해결 충돌이 없을 때 확인 후 Rebase를 계속한다. 원래 커밋 메시지를 유지하며 대화형 편집기를 기다리지 않는다. Continue가 다음 커밋의 충돌로 멈추면 실패로만 처리하지 않고 새 단계/커밋/충돌을 갱신해 Stage 해결 화면을 유지한다. 모든 단계가 끝나야 진행 표시를 제거한다.
- **FR-271**: 리베이스 중단과 커밋 건너뛰기를 각각 확인창으로 제공한다. 중단은 시작 전 상태로 복귀를 시도하며 해결 내용 손실 가능성을 알린다. 건너뛰기는 현재 커밋과 해결 내용이 제외됨을 알리고 다음 단계로 진행한다. 자동 건너뛰기·강제 Reset은 하지 않는다.
- **FR-272**: 실행 직전 저장소·Rebase 세션/방식·현재 HEAD·원래 브랜치/끝/커밋·새 기반·단계/현재 커밋을 재검증한다. 종료/교체/진행된 오래된 확인이나 다른 작업을 거절한다. 중복 실행을 방지하고 성공·다음 충돌·실패 모두 재조회한다. 실제 실행 실패는 오류와 상태를 남겨 재시도할 수 있게 한다.
- **FR-273**: 기존 Merge의 표시/완료/중단을 유지하고 Rebase에도 같은 경합 단축키 제한을 적용한다. Stage·탐색·조회·F5는 허용한다. Merge/Rebase 외 작업 복구와 대화형 Rebase 편집기는 추가하지 않는다. 기존 ff-only Pull은 유지한다.
- **SC-112**: 실제 임시 저장소에서 연속 두 커밋 충돌의 단계 이동과 최종 완료·미해결 거절·Abort 원래 HEAD/브랜치·Skip 누락 결과·실패 후 재시도·오래된 단계/세션/참조 거절·apply 방식·linked worktree와 기존 Merge 회귀를 검증하고 포맷·컴파일·Clippy·관련 테스트를 통과한다.

수용 시나리오: Rebase 첫 충돌을 수정/Stage하고 계속하면 다음 충돌의 단계와 파일을 표시한다. 두 번째도 해결하면 Rebase를 끝낸다. 대신 확인 후 중단하거나 현재 커밋만 건너뛸 수 있다. 명확화: 기존 Merge UX를 Rebase에 확장하며 Skip에는 별도 확인을 둔다. 추가 질문은 없다.

## Revert 충돌 해결·계속·중단·건너뛰기 (US94, 우선순위 P1)

- **FR-274**: Revert 진행 상태·현재 대상 커밋·미해결 충돌 수를 조회/재실행/새로고침에서 표시한다. 기존 Stage 충돌 표시·작업 결과 미리보기·외부 수정 후 Space Stage를 재사용한다. Cherry-pick/Merge/Rebase와 구분하고 linked worktree를 지원한다.
- **FR-275**: 미해결 0개일 때 확인 후 Revert를 계속한다. 일반 Revert는 기본 메시지의 새 커밋을 만들고, 앱에서 시작한 단일 커밋의 no commit 옵션은 재실행 후에도 확인할 수 있게 보존하여 HEAD 변경 없이 해결 결과와 기존 Stage 내용을 남긴다. 옵션을 알 수 없는 외부 단일 Revert는 확인창에서 커밋 여부를 명시적으로 선택하며 기본값은 커밋하지 않기다. 외부 여러 커밋의 일반 Revert는 다음 충돌까지 계속할 수 있다. 외부 여러 커밋의 no commit 자동 계속은 지원하지 않고 상태를 유지한 채 안내한다.
- **FR-276**: 중단과 현재 Revert 건너뛰기를 각각 확인 후 Git의 해당 명령으로 수행한다. 중단/건너뛰기는 현재 해결 내용과 미커밋/Stage 변경이 사라질 수 있음을 알린다. 강제 Reset이나 자동 건너뛰기를 하지 않는다. 확인 취소/닫기는 저장소를 변경하지 않는다.
- **FR-277**: 실행 직전 저장소·세션·현재 HEAD/브랜치·대상·대기 목록·저장된 옵션을 재검증하고 미해결/오래된 확인/다른 작업/중복 실행을 거절한다. 다음 충돌은 새 해결 단계로 표시하며 실제 실패는 오류와 상태를 남긴다. 완료/중단/건너뛰기/실패/Stage 후 상태를 갱신한다.
- **FR-278**: Revert에도 기존 경합 단축키 제한을 적용하고 Stage·탐색·F5는 허용한다. 기존 Merge/Rebase·no commit 성공 경로·ff-only Pull 정책은 유지한다. 새 커밋 범위 선택 UI와 내부 충돌 편집기는 추가하지 않는다.
- **SC-113**: 실제 임시 저장소로 일반/커밋 없는 충돌 해결·커밋 부모/내용 또는 HEAD/Stage 보존·재실행 시 옵션 인식·중단/건너뛰기·연속 일반 충돌·실패 재시도·오래된 대상/옵션 거절·외부 단일 옵션 선택·worktree·다른 작업 구분과 기존 회귀를 검증하고 포맷·컴파일·Clippy·관련 테스트를 통과한다.

수용 시나리오: Revert 충돌을 외부 수정 후 Stage하고 계속하면 새 Revert 커밋을 만든다. no commit으로 시작했다면 새 커밋 없이 Stage 결과를 남긴다. 대신 확인 후 중단/건너뛰기를 수행한다. 명확화: 앱의 기존 단일 커밋 Revert에 옵션 보존을 보장하며 Git 자체 Continue의 옵션 손실을 피한다. 추가 질문은 없다.

## Stash 복원 충돌 해결·완료·취소 (US95, 우선순위 P1)

- **FR-279**: 앱에서 시작한 Stash 복원 실패/충돌을 전용 상태로 표시하고 Stage 화면의 충돌 파일·외부 수정/Space Stage 안내로 연결한다. 미병합 항목이 없어지면 확인 후 해결 완료를 표시한다. 완료는 커밋·추가 apply·stash 삭제 없이 결과를 유지하고 복구 상태만 종료한다. 원본 Stash는 성공/실패/취소 모두 유지한다.
- **FR-280**: 복원 전에 원래 HEAD/브랜치·인덱스·관련 작업 파일과 기존 미추적 파일 내용을 보관한다. 백업에 실패하거나 안전하게 처리할 수 없는 링크/특수 파일/파일-디렉터리 경계이면 apply 전에 거절한다. 복원은 기존 --index 동작을 유지한다. 일반 파일의 추가·삭제·바이너리·한글 경로와 기존 Stage/작업 디렉터리 변경을 보존한다.
- **FR-281**: 앱이 보관한 복원 전 상태가 있을 때만 확인 후 복원 취소를 제공한다. apply로 바뀐 경로와 인덱스만 복원하고 다른 경로의 이후 작업 파일 변경은 유지한다. 복원 후 해결 내용은 사라질 수 있음을 알린다. HEAD/브랜치가 바뀌거나 복원 범위 밖의 Stage 상태가 변경되면 무변경 거절한다. 강제 Reset·자동 clean·원본 Stash 삭제는 하지 않는다.
- **FR-282**: 백업/복원 대상·세션을 worktree별 Git 메타데이터에 보관해 재실행/F5로 인식한다. 백업 무결성·원시 경로·범위·다른 Git 작업·잠금·오래된 확인을 실행 직전 검증한다. 중복 실행을 방지하고 오류/부분 복구 실패 시 백업을 유지해 재시도할 수 있게 한다. 적용 중 상태가 남아 있으면 자동 완료/취소하지 않는다.
- **FR-283**: 외부에서 시작한 미병합 충돌도 일반 충돌 해결 안내를 제공하되 백업이 없으면 Stash로 추정하거나 복원 취소를 제공하지 않는다. 앱 복원이 충돌 없이 성공하면 백업/진행 표시를 정리한다. 실패했지만 미병합 항목이 없는 경우에도 결과 확인·완료/취소를 제공한다.
- **FR-284**: 기존 Merge/Rebase/Revert와 경합 가드·Stage·탐색·새로고침을 재사용한다. 외부 미병합 상태에서는 일반 커밋은 해결 후 가능하나 해결 전 경합 작업을 제한한다. Stash 전용 Continue/Abort 명령은 만들지 않는다.
- **SC-114**: 실제 저장소에서 충돌 수정/Stage/완료·백업 취소의 HEAD/인덱스/기존 Stage/작업/미추적/삭제 복원·이후 다른 작업 파일 보존·바깥 Stage/HEAD 변경 거절·백업 손상/잠금/경로 보호·비충돌 성공·미병합 없는 실패·재실행/worktree·원본 Stash 유지와 기존 회귀를 검증하고 포맷·컴파일·Clippy·관련 테스트를 통과한다.

수용 시나리오: Stash 복원 충돌을 수정/Stage한 뒤 해결 완료를 선택하면 결과만 유지된다. 대신 복원 취소를 확인하면 보관한 적용 전 상태로 되돌린다. 외부 apply 충돌은 안내만 보이고 안전한 취소를 추측하지 않는다. 명확화: 안전한 백업이 가능한 일반 파일만 자동 취소를 지원하며 진행 중 비정상 종료 잠금은 자동 해제하지 않는다. 추가 질문은 없다.


## DiffViewer 충돌 구간 선택 (US96, 우선순위 P1)

사용자는 충돌 파일의 각 구간에서 원하는 쪽을 클릭하여 해결한다. 외부 편집 없이 구간별로 선택하는 것이 목적이다.

- **FR-285**: Stage의 미병합 UTF-8 일반 텍스트 파일에서 완전한 충돌 구간마다 현재 변경 사용·들어오는 변경 사용·양쪽 모두 사용 버튼을 표시한다. History·일반 변경에는 표시하지 않는다.
- **FR-286**: 클릭은 해당 구간의 마커와 선택하지 않은 내용만 제거하고 작업 파일에 즉시 저장한다. 양쪽 모두는 현재 쪽 다음 들어오는 쪽 순서다. 다른 구간·주변 내용·원래 줄바꿈은 보존한다. diff3/zdiff3의 공통 조상 구간은 결과에서 제외한다.
- **FR-287**: 자동 Stage·커밋·작업 계속은 하지 않는다. 적용 후 미리보기를 재조회하고 모든 구간 해결 뒤 기존 Space Stage로 이어진다.
- **FR-288**: 실행 직전 미병합 여부·작업 파일 원문을 재검증하고 오래된 미리보기·링크·특수 파일·바이너리·비 UTF-8·크기 초과·불완전하거나 중첩된 마커는 무변경 거절한다. 중복 실행을 막고 실패를 표시한다.
- **SC-115**: 서로 다른 두 구간을 독립적으로 해결하고 현재/들어오는/양쪽 결과, 빈 쪽·CRLF·마지막 개행 없음·diff3·오래된 내용 거절·인덱스 보존을 자동 검증하며 포맷·컴파일·Clippy·기존 회귀를 통과한다.

수용 시나리오: 두 구간 중 첫 구간에서 현재 변경을 선택하면 두 번째 구간과 주변 내용은 그대로 남는다. 재조회 뒤 두 번째에서 양쪽 모두를 선택하면 현재 다음 들어오는 내용만 남고 Space로 Stage할 수 있다. 외부 편집 뒤 오래된 버튼을 클릭하면 덮어쓰지 않고 다시 조회하도록 안내한다.

경계 조건: 마커가 없는 삭제/바이너리 충돌은 기존 외부 편집 안내를 사용한다. 표시 제한 밖 구간에는 버튼을 표시하지 않는다.

명확화 점검: 별도 질문이 필요한 중대한 모호성은 없다. 현재/들어오는 쪽은 파일 마커의 위/아래를 의미하며 Rebase의 브랜치 이름으로 재해석하지 않는다. FR-278의 내부 편집기 제외 범위는 이번 구간 선택에 한해 확장한다.

## DiffViewer 마커 보존과 부분 Stage (US97, 우선순위 P1)

사용자는 충돌 마커와 선택 버튼을 동시에 보고 한 파일에서 원하는 변경 구간이나 개별 줄만 Stage한다.

- **FR-289**: 충돌 선택 버튼을 원문과 독립된 행에 표시한다. 기존 <<<<<<< HEAD 시작 줄과 줄 번호·내용·색상 및 나머지 충돌 마커는 그대로 표시한다. 기존 세 선택 기능은 유지한다. US96의 시작 줄 대체 방식은 폐기한다.
- **FR-290**: Stage 화면의 미스테이지 일반 UTF-8 텍스트 파일에서 변경 구간마다 이 구간 Stage 버튼을 제공한다. 추가·삭제 줄은 체크하여 여러 줄을 선택한 뒤 선택한 줄 Stage로 적용할 수 있다. 문맥·헤더·버튼 행은 선택 대상이 아니다. 선택 해제도 제공한다.
- **FR-291**: 부분 Stage는 선택한 추가·삭제만 인덱스에 반영하며 작업 파일·선택하지 않은 변경·다른 파일·기존 Stage 결과를 보존한다. 교체 변경은 삭제 줄과 추가 줄을 각각 선택할 수 있고 양쪽을 선택하면 교체로 반영한다. 새 파일과 삭제 파일도 내용 줄을 기준으로 지원한다.
- **FR-292**: 실행 직전 파일/인덱스 원문과 대상 경로·모드·미병합 여부를 재검증한다. 오래된 미리보기·링크/특수 파일·바이너리·비 UTF-8·크기 초과는 거절하고 원문/인덱스를 보존한다. 미병합 파일과 History·이미 Stage된 쪽에는 부분 Stage 버튼을 제공하지 않는다. 사용자 필터가 있는 경로는 부분 Stage를 거절하고 전체 Stage를 안내한다.
- **FR-293**: 비동기 처리·중복 실행 방지·오류 표시·성공/실패 후 재조회를 제공한다. 파일 전환/새로고침/부분 Stage 후 줄 선택을 초기화하여 다른 파일이나 오래된 행 번호에 적용되지 않게 한다. 기존 파일 단위 Space Stage/Unstage는 유지한다.
- **SC-116**: 실제 임시 저장소로 두 구간 중 하나와 한 구간 내 일부 추가/삭제·교체 줄을 선택하여 정확한 인덱스 결과와 작업 파일/기존 Stage/다른 파일 보존을 검증한다. 새/삭제 파일·한글/특수 경로·CRLF·마지막 개행 없음·외부 변경 거절과 기존 충돌/Stage 회귀 및 포맷·컴파일·Clippy를 통과한다.

수용 시나리오: 충돌 파일에서 선택 버튼 바로 아래의 <<<<<<< HEAD를 읽고 현재/들어오는/양쪽을 선택한다. 일반 파일의 첫 구간만 Stage하면 두 번째는 미스테이지로 남는다. 남은 구간의 원하는 추가·삭제 줄만 체크하고 선택한 줄 Stage하면 그 줄만 추가로 Stage되며 작업 파일은 그대로다.

경계 조건: 1 MiB·5,000줄 표시 제한을 유지하고 표시되지 않은 줄은 선택할 수 없다. 줄 선택이 없으면 선택 Stage를 실행하지 않는다. CRLF와 개행 없는 마지막 줄은 원문 바이트를 보존한다. 파일 모드만 바뀐 경우에는 기존 전체 Stage를 사용한다.

### 명확화 기록 (2026-10-30)

- 질문: 부분 Stage의 선택 단위는 무엇인가? 답변: 변경 구간과 개별 줄 모두.
- 가정: 줄 선택은 문자 일부가 아닌 추가·삭제 한 줄 전체에 적용하며 이미 Stage된 쪽의 부분 Unstage는 이번 범위에 포함하지 않는다.

## DiffViewer 키보드 선택과 고정 충돌 도구 모음 (US98, 우선순위 P1)

사용자는 DiffViewer의 커서로 줄과 충돌 구간을 지정하고 스크롤 위치와 관계없이 상단 도구 모음을 사용한다.

- **FR-294**: Stage 미스테이지 DiffViewer에 포커스가 있을 때 기본 Space로 커서의 추가/삭제 줄 체크를 토글한다. 같은 줄에서 다시 누르면 해제한다. 헤더·문맥·미지원 파일은 무변경 처리한다. 기본 Enter는 선택한 줄 Stage 버튼과 동일한 처리로 체크된 줄을 Stage한다. 선택이 없거나 처리 중이면 무변경이다. 두 단축키를 기존 설정/도움말·재지정 체계에 등록하며 다른 영역/대화상자의 Space/Enter는 유지한다.
- **FR-295**: 상단 선택 해제 버튼을 제거한다. 선택 수와 선택한 줄 Stage 버튼 및 기존 체크박스·구간 Stage는 유지한다. 체크박스나 Space를 다시 사용하여 개별 해제할 수 있다. 기존 FR-290·FR-293의 선택 해제 버튼 요구를 대체한다.
- **FR-296**: 충돌 선택의 세 버튼을 DiffViewer 상단의 스크롤되지 않는 도구 모음으로 이동한다. 본문 구간별 버튼/동작 행은 제거하고 원래 충돌 마커와 모든 원문 줄·좌표를 유지한다. 기존 FR-289의 독립 본문 동작 행은 이 요구로 대체한다.
- **FR-297**: 충돌 버튼은 커서가 속한 충돌 구간에만 적용한다. 마우스·방향키로 커서를 옮기면 상단 대상 구간 표시와 활성 상태를 갱신한다. 시작/공통 조상/구분/종료 마커와 양쪽 내용은 해당 구간에 포함한다. 구간 밖·작업 파일 좌표가 없는 삭제/헤더 줄·커서 없음은 버튼을 비활성화하고 다른 구간을 추측하지 않는다. 버튼 클릭 시 현재 커서를 다시 확인하며 파일/미리보기 세대 검증을 유지한다.
- **FR-298**: 파일 전환·재조회 시 오래된 커서/체크로 실행하지 않는다. DiffViewer 포커스 중 새 미리보기가 로드되면 유효한 초기 커서를 제공하여 방향키로 계속 탐색할 수 있다. 기존 비동기·중복 방지·원문 검증·Stage/작업 파일 보존을 유지한다.
- **SC-117**: Space 토글/Enter·재지정/범위/이전 키 무효화, 두 충돌 구간의 시작/내부/종료와 바깥 경계·diff3·CRLF 매핑, 원문 마커 보존과 기존 충돌/부분 Stage 회귀를 자동 검증하고 포맷·컴파일·Clippy를 통과한다.

수용 시나리오: 미스테이지 파일에서 줄을 클릭하거나 방향키로 이동하여 Space로 여러 줄을 체크하고 Enter로 해당 줄만 Stage한다. 선택 해제 버튼은 없으며 같은 줄에서 Space를 다시 눌러 해제한다. 두 충돌이 있는 파일에서 두 번째 구간에 커서를 놓고 상단 현재 변경 사용을 누르면 두 번째만 바뀐다. 스크롤해도 상단 버튼은 유지되며 구간 밖에서는 실행되지 않는다.

명확화 점검: 사용자 지시와 기존 커서/선택 체계로 범위가 명확하여 추가 질문은 없다. 충돌 구간은 작업 파일의 원문 줄 범위(시작·종료 마커 포함)로 판정한다. Enter는 충돌 자동 해결이나 파일 전체 Stage를 실행하지 않는다.
