# 구현 계획: 기존 프로젝트 방식의 커밋 그래프

> 정리 안내: 단계별 설계·작업 기록이며 후속 변경은 [현재 명세 색인](../README.md)과 해당 기능의 spec.md를 따른다. 기존 체크 상태와 과거 검증 이력은 현재 재검증 완료를 의미하지 않는다.

## 기술적 맥락과 분석

현재 Rust 2024/GPUI 0.2.2 앱은 main → ui → sample 구조이다. Workspace::history()는 38px 행에 45px 그래프 열을 만들고 항상 같은 세로 div와 점을 그린다. Commit에는 부모 관계가 없다. 선택은 commit 인덱스이며 상세도 같은 COMMITS를 읽는다.
참조 앱은 graph.rs의 GraphBuilder가 부모 해시를 기다리는 레인을 입력·출력 간선으로 전환한다. history_view.rs의 RowGraph는 행 상·하반부의 선분을 캔버스로 그리며 좌표/DPI/열 너비를 보정하고 캐시한다. palette와 HEAD_FILL은 theme.rs에 있다.

## 헌장 및 아키텍처 확인

헌장은 미작성 템플릿이라 규칙 검사를 생략한다. 기존 UI/데이터 책임을 유지하며 의존성 추가와 공개 API 변경은 없다. graph는 GPUI와 무관한 순수 데이터 계산, history_graph는 GPUI 표시, sample은 데모 데이터만 담당한다. 이전 앱은 읽기만 한다.

## 설계와 영향 범위

- src/graph.rs: 기존 GraphBuilder와 그래프 모델만 이식한다. Commit은 GraphCommit으로 이름을 한정하고 정렬·저장소 접근은 포함하지 않는다. 부모 관계 계산은 원본과 동일하게 유지한다.
- src/history_graph.rs: RowGraph, 도형·좌표·DPI 처리, 경로 캐시와 팔레트를 이식한다. 행 높이는 현재 앱의 38px에 맞춘다. 원본의 열 크기 변경·날짜 포맷 등은 그래프와 무관하므로 제외한다.
- src/sample.rs: 기존 Commit에 parent_ids를 추가한다. 샘플 첫 행은 두 부모를 가진 병합이며 두 레인은 공통 조상에서 합류한다. 메시지/해시/순서는 유지한다.
- src/ui.rs: 기본 Workspace 생성 시 그래프를 한 번 계산하고 RowGraph 및 전체 최대 레인 수를 저장한다. history()는 기존 그래프 div 대신 캔버스를 렌더링한다. 선택 상태와 체크아웃 상태를 구분한다.
- src/main.rs: 두 모듈을 등록한다.

## 단계와 검증

1. 참조 그래프 모델·알고리즘과 레이아웃 수학 테스트를 이식한다. 원본과 같은 그래프 결과를 테스트로 비교한다.
2. 데모 부모 관계, 캐시와 기존 UI 연결을 구현한다.
3. cargo fmt --check, cargo check --offline, cargo test --offline, 별도 실행 파일 빌드를 실행한다. 실환경 창 검증 가능 여부를 별도 기록한다.

선형, 병합, 다중 루트, 여러 부모, 빈 입력, 외부 부모와 페이지 분할의 연속성 및 결정성을 검증한다. DPI 및 좁은 열 테스트를 유지한다. 선택/닫기 기존 테스트도 회귀 검증한다.

## 커밋 행 밀도와 노드 선명도 계획

- 실제 코드 분석: ROW_HEIGHT=38은 UI 행과 RowGraph 선분 양쪽에서 공유된다. 원은 선용 중심 snap 후 반경 4.5/5.5의 베지어 경로를 그리므로 100%에서 경계가 반 픽셀에 놓인다. 원본 행 높이는 24이다.
- src/history_graph.rs의 ROW_HEIGHT를 24로 변경한다. src/ui.rs는 이미 같은 상수를 사용한다. 메시지 기본 글꼴 크기를 작성자 등과 같은 12px로 명시해 24px 행에 맞춘다. 배지와 열은 유지한다.
- 원은 물리 지름을 반올림하고 좌상단 경계를 물리 픽셀로 정렬한 정사각형 Bounds에 fill().corner_radii(지름/2)를 사용한다. 체크아웃 링은 같은 외곽 Bounds에 정수 물리 픽셀 두께의 border로 그려 동심을 유지한다. 베지어 원 근사와 별도 내부 원 그리기는 제거한다.
- graph.rs 알고리즘, 부모 데이터, 곡선 및 선 좌표 보정과 캐시는 유지한다. 의존성 추가나 책임·방향 변경은 없다. 미작성 헌장은 검사 생략.
- 검증: 노드 경계/링 정렬과 24px 선분 경계 테스트를 먼저 작성한다. 포맷, 컴파일, 전체 테스트와 별도 이름 빌드를 수행한다. 이전 화면 도구 미승인에 따른 실제 시각 검증 한계는 유지한다.

## 체크아웃 바깥 원 확대 계획

- 분석: node_geometry()가 Bounds와 ring을 반환하며 paint_node()가 하나의 둥근 도형에 테두리를 그린다. 바깥 Bounds만 늘리면 안쪽 흰 원도 커지므로 테두리 두께도 같은 양만큼 늘려야 한다.
- checked_out일 때만 배율당 1px에 가장 가까운 정수 물리 픽셀만큼 Bounds를 사방으로 늘리고 ring을 늘린다. 기존 중심·안쪽 지름과 일반 노드는 유지한다.
- 영향은 src/history_graph.rs의 노드 기하와 관련 검증뿐이다. 상태·레인·의존성·구조는 유지하며 미작성 헌장은 검사 생략한다.
- 검증: 기존 픽셀 정렬 테스트의 크기 기대값을 새 기준으로 갱신하고 일반 노드/내부 지름 보존을 검증한다. 포맷, 컴파일, 전체 테스트 및 빌드를 수행한다. 실제 화면 검증 제한은 별도 유지한다.

## 체크아웃 메시지 강조 계획

`src/history.rs`의 기존 HEAD 비교값을 행 제공 시 갱신해 재사용한 행도 최신 상태를 반영한다. `src/ui.rs`의 저장소 기록 메시지 요소에만 굵은 글꼴을 적용한다. 기존 메시지 줄임 처리, 그래프 표시 및 파일 기록 구성은 유지한다. 커밋은 생성하지 않는다.
