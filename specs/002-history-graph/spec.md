# 기능 명세: 기존 프로젝트 방식의 커밋 그래프

> 문서 정리일: 2026-11-17. 본문은 이 기능의 단계별 요구사항 이력을 포함한다. 현재 유효 기준과 검증 한계는 [전체 명세 색인](../README.md)을 함께 확인한다. 과거 검증 기록은 현재 버전의 재검증 결과가 아니다.
> 후속 변경 참고: [008](../008-history-performance/spec.md) · [018](../018-remove-graph-minimum/spec.md) · [059](../059-footer-overlay-actions/spec.md) · [080](../080-history-revert-reset/spec.md).
> 현재 기준: 현재 레인 간격은 18px, 좌측 기준은 10px, 행 높이는 24px이다. 열 압축 대신 잘라 표시하며 추가 부모의 기존 레인은 가장 왼쪽 후보를 재사용한다.

## 사용자 시나리오 및 검증

### 사용자 이야기 1 — 커밋 관계 파악 (P1)

사용자는 커밋 기록에서 feather-git-old와 같은 레인별 선과 노드로 부모 관계, 분기와 병합을 파악한다.
수용 시나리오: 선형 이력에서는 한 레인의 같은 색 선이 이어지고 분기·병합에서는 다른 레인으로 부드러운 곡선이 연결된다. 마지막 루트 아래로 연결선이 이어지지 않는다.

### 사용자 이야기 2 — 기존 탐색 유지 (P2)

커밋을 선택하면 기존처럼 해당 행이 강조되고 상세가 동기화된다. 체크아웃 커밋의 링은 선택 행 변경과 무관하게 유지된다.

## 요구사항

- FR-001: feather-git-old/src/graph.rs의 행별 입력·출력 레인 및 색상 할당 알고리즘을 적용한다.
- FR-002: feather-git-old/src/history_view.rs의 캔버스 렌더링을 적용한다. 레인 간격 12px, 왼쪽 기준 8px, 약 2px 선, 세로선 채움, 곡선 제어점 0.6, 일반 노드 반경 4.5px, 체크아웃 노드 반경 5.5px 및 흰색 내부 원, 동일한 8색 팔레트를 사용한다.
- FR-003: 동일 프로젝트의 DPI별 좌표 보정, 좁은 열의 공통 레인 간격 압축과 경로 캐시를 유지한다.
- FR-004: 기존 샘플 커밋의 메시지·해시·순서와 선택·상세 동작을 유지한다. 부모 관계를 샘플 데이터로 명시하고 분기·병합 예제를 포함한다. 실제 저장소 접근은 추가하지 않는다.
- FR-005: 기존 38px 커밋 행과 45px 그래프 열을 유지하며 선이 행 사이에서 끊기지 않게 연결한다. 비어 있는 이력, 단일 루트, 다중 부모, 화면 밖 부모도 안전하게 처리한다.

## 성공 기준

- SC-001: 선형/병합/다중 루트/여러 부모/화면 밖 부모에서 기존 알고리즘과 같은 레인·색·입력·출력이 생성된다.
- SC-002: 100%, 125%, 150%, 175%, 200% DPI에서 선의 경계가 물리 픽셀에 맞고 16px 이상 열에서 노드가 열 경계를 넘지 않는다.
- SC-003: 컴파일, 포맷, 자동화 테스트 및 실행 파일 빌드가 통과하며 기존 선택 테스트도 유지된다.
- SC-004: 실제 창에서 분기·병합 곡선, 노드, 체크아웃 링, 행 경계 연결과 선택·상세 동기화를 확인한다.

## 가정 및 명확화

그리는 방식의 이식이며 이전 앱 전체의 레이아웃, 저장소 로딩, 정렬 및 페이징을 이식하지 않는다. 현재 샘플은 표시 순서가 고정되어 있으므로 정렬은 필요 없다. 첫 번째 커밋을 샘플 체크아웃 커밋으로 해석한다. 부모 관계는 실제 저장소 관계라고 주장하지 않는 데모 데이터이다. 모호성 검토 결과 추가 질문 없이 진행할 수 있다.

## 커밋 행 밀도와 노드 선명도 개선

- 사용자 이야기 3 (P1): 사용자는 이전 앱처럼 조밀한 커밋 목록과 또렷한 그래프 노드를 본다.
- FR-006: 커밋 행 높이를 이전 앱과 같은 24px로 줄이고 그래프 행 높이도 같은 상수를 사용한다. 이는 FR-005의 38px 기준을 대체한다. 열 너비, 선택·상세 및 부모 레인 계산은 유지한다.
- FR-007: 원 노드는 반경 약 4.5px/체크아웃 5.5px를 유지하되 화면 배율에 맞춰 지름과 경계를 물리 픽셀로 정렬하고 GPUI 둥근 도형으로 그린다. 이는 FR-002의 노드 경로 그리기만 대체한다. 체크아웃 내부 흰색 원은 같은 중심과 약 2px 두께의 링을 유지한다.
- SC-005: 24px 행에서 선분은 행 상단·중앙·하단에 연결되고 제목·배지가 행에 들어간다. 기존 커밋 선택과 상세 동기화는 유지된다.
- SC-006: 100/125/150/175/200%에서 원의 가로·세로 크기가 같고 경계 및 링 두께가 물리 픽셀 단위이며 내부 원과 외부 원은 동심이다.
- 명확화: 목록 높이는 각 커밋 행 높이를 의미한다. 패널 전체 높이는 유지한다. 흐림 개선은 노드 그리기와 픽셀 정렬로 한정하며 색상·레인·곡선은 변경하지 않는다. 추가 질문이 필요한 모호성은 없다.

## 체크아웃 바깥 원 확대

- FR-008: 체크아웃 원의 바깥 경계를 각 방향으로 1px 확대한다. 안쪽 흰 원 크기와 중심은 유지하며 일반 노드는 변경하지 않는다. 화면 배율별 확대량은 가장 가까운 정수 물리 픽셀로 보정한다. FR-007의 체크아웃 바깥 크기만 대체한다.
- SC-007: 100% 배율에서 바깥 지름은 11px에서 13px로 커지고 안쪽 지름은 7px로 유지된다. 모든 지원 배율에서 기존 안쪽 지름과 동심 및 물리 픽셀 경계가 유지된다.
- 명확화: 1px 확대는 바깥 경계를 사방으로 1px 늘리는 것으로 해석한다. 목록 높이, 그래프 선과 일반 원은 유지한다. 추가 질문이 필요한 모호성은 없다.

## 체크아웃된 커밋 메시지 강조

- FR-009 저장소 커밋 기록에서 현재 HEAD의 메시지를 굵게 표시한다. 브랜치 체크아웃과 분리된 HEAD에 동일하게 적용한다.
- SC-008 HEAD가 바뀌면 캐시된 행의 강조도 새 커밋으로 이동한다. 행 선택과 메시지 굵기는 독립적이다.

강조 범위는 저장소 커밋 기록의 메시지 텍스트다. 파일 기록 창, 참조 배지와 나머지 열은 기존 스타일을 유지한다.
