# 구현 계획: 마지막 커밋 수정

날짜: 2026-11-01
명세: [기능 명세](spec.md)

## 요약
커밋창 옵션을 네이티브 커밋 계층까지 전달하여 기존 커밋의 부모와 작성자를 보존한 새 객체로 HEAD를 교체한다.

## 기술 문맥
Rust 2024, GPUI 0.2.2, gix 0.87.1 기반 Windows 데스크톱 앱이다. 저장소와 인덱스는 기존 gix 구현을 사용한다. 검증은 cargo test 및 cargo check로 수행한다. 추가 의존성은 없다.

## 규칙 확인
헌법은 미작성 템플릿이므로 적용할 확정 원칙이 없다. 한글 문서와 speckit 절차를 준수한다. 설계 전후 위반 없음.

## 조사 결과와 설계
기존 create_commit의 참조 갱신은 첫 부모를 이전 HEAD로 간주하므로 수정 커밋에서는 별도 expected HEAD가 필요하다. 내부 보조 함수로 이전 HEAD와 새 커밋의 부모를 분리하고 기존 호출 계약은 유지한다. 서명 처리도 재사용한다.

## 구조
- src/ui.rs: 옵션, 포커스, 클릭과 스페이스 입력, 제출 연결
- src/setup.rs: 커밋 옵션 전달과 통합 검증
- src/native_git.rs: 공개 수정 커밋 진입점
- src/native_local.rs: 부모와 작성자 보존 및 안전한 HEAD 갱신

## 검증 단계
일반 커밋 회귀, 수정 커밋의 부모·작성자·트리·메시지·미스테이징 파일 보존, 첫 커밋 수정과 HEAD 없는 오류를 검증한다.

## 사용자 이야기 2: 메시지 입력창 테두리

src/ui.rs의 커밋창에서 메시지 편집기만 div로 감싸고 border_1 및 border_color(rgb(LINE))를 적용한다. 공유 편집기는 변경하지 않는다. 기존 높이·포커스·스크롤 처리를 유지한다. 새 데이터나 의존성은 없다. 검증은 cargo check --all-targets와 cargo fmt --check 및 코드 검토로 수행한다. 스타일만 바꾸므로 별도 자동 테스트는 추가하지 않는다. 규칙 확인 결과 위반 없음.

## 한 줄 입력창과 스타일 통일

추가 명확화 점검: 비교 기준은 src/settings.rs의 field 함수이며 추가 사용자 질문이 필요한 모호함이 없다. src/ui.rs 커밋 메시지 래퍼에 동일한 rounded_sm, p_1, overflow_hidden, flex_shrink_0 및 편집기 background_color를 적용한다. 여러 줄 편집기 높이는 그대로 사용한다. 데이터 변경은 없다. 검증은 전체 대상 컴파일·서식 검사와 비교 코드 검토로 수행한다.

## 메시지 라벨 삭제

명확화 점검 결과 추가 질문이 필요한 모호함은 없다. src/ui.rs 커밋창의 커밋메시지 라벨 자식 요소만 삭제한다. 입력창 스타일·동작 및 데이터 모델 변경은 없다. 전체 대상 컴파일과 서식 및 해당 라벨 부재를 확인한다. 규칙 위반 없음.
