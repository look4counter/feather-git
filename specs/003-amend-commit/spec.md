# 기능 명세: 마지막 커밋 수정

작성일: 2026-11-01
상태: 명세 검증 완료
입력: 커밋창에 마지막 커밋 수정 체크박스를 추가한다.

## 사용자 시나리오와 검증

### 사용자 이야기 1: 마지막 커밋 수정 (우선순위 P1)
기존 커밋창에서 마지막 커밋 수정을 선택하고 변경사항과 메시지를 반영한다.
독립 검증: 임시 저장소에서 수정 전후 커밋 수와 부모 및 파일 내용을 비교한다.
수용 시나리오:
1. 기본 해제 상태에서는 새 커밋이 추가된다.
2. 선택하면 입력 메시지와 스테이징 내용으로 마지막 커밋을 교체하며 부모와 원래 작성자를 유지한다.
3. 취소 후 다시 열면 해제 상태다.

### 사용자 이야기 2: 커밋 메시지 입력 영역 구분 (우선순위 P2)
사용자는 테두리로 구분된 입력 영역에 커밋 메시지를 작성한다.
독립 검증: 입력창 전체 둘레의 테두리와 여러 줄 입력 및 스크롤을 확인한다.
수용 시나리오:
1. 커밋창을 열면 비어 있는 메시지 입력 영역에도 테두리가 보인다.
2. 메시지를 입력하거나 처리 중 비활성 상태가 되어도 테두리가 유지된다.
3. 한 줄 입력창과 내부 여백, 모서리 둥글기 및 배경이 일치한다.

4. 커밋창에 커밋메시지 라벨 없이 입력창이 표시된다.

### 경계 사례
- 첫 커밋도 부모 없는 커밋으로 교체한다.
- 기존 커밋이 없으면 오류로 처리한다.
- 빈 메시지와 스테이징 없는 제출은 기존처럼 거부한다.
- 실패하면 창과 입력을 유지한다.

## 요구사항
- FR-001: 체크박스 명칭은 마지막 커밋 수정이며 기본 해제다.
- FR-002: 선택 시 마지막 커밋을 교체하고 부모와 작성자를 유지한다.
- FR-003: 일반 커밋, 오류 처리, 커밋 후 푸시 동작을 유지한다.
- FR-004: 마우스와 키보드로 선택하고 처리 중에는 변경할 수 없다.

- FR-005: 커밋 메시지 입력 영역의 전체 둘레에 앱의 한 줄 입력창과 동일한 테두리, 내부 여백, 둥근 모서리 및 배경을 표시한다.

- FR-006: 커밋창에서 메시지 입력창 위의 커밋메시지 라벨을 표시하지 않는다.

## 성공 기준
- SC-001: 일반 커밋은 커밋 수가 1 증가하고 수정 커밋은 증가하지 않는다.
- SC-002: 수정 후 스테이징 내용과 메시지가 반영되고 스테이징되지 않은 파일은 보존된다.

- SC-003: 빈 입력창과 메시지가 있는 입력창 모두 전체 둘레를 구분할 수 있고 한 줄 입력창과 동일한 여백·모서리·배경을 사용하며 기존 여러 줄 입력과 스크롤을 사용할 수 있다.

## 가정
- 기존 커밋창의 스테이징 필수 조건과 메시지 입력 방식을 유지한다.
- 추가 명세 확인 결과 중대한 모호함이 없어 질문 없이 계획으로 진행한다.
