# 구현 계획: 단일 임시 새 탭

## 분석과 기술적 맥락

Rust 2024/GPUI 0.2.2 앱이다. Workspace는 원본 프로젝트 인덱스와 열린 목록으로 선택·닫기를 처리한다. tabs()는 프로젝트 목록을 렌더링하고 +는 안내만 표시한다. render()는 열린 프로젝트 여부에 따라 툴바·네 패널 또는 빈 화면을 표시한다. 저장/복원 코드가 없고 Default가 앱 시작 상태이다.
old/src/ui.rs의 add_empty_tab은 여러 Empty 탭을 만들고 persist한다. start_page는 300px/최대40% 작업 열과 가변 최근 목록을 20px 간격/여백으로 배치한다. old의 세션·편집기·Git 연동은 현재 화면 구성에 필요하지 않다.

## 설계

- src/ui.rs의 Workspace에 start_tab_open과 start_tab_active를 추가하며 둘 다 기본 false이다. open_start_tab은 두 값을 true로 만들어 중복 생성 없이 활성화한다.
- select_project, close_start_tab 및 close_project에서 유효한 선택과 안내를 유지한다. 새 탭 닫기는 이전 프로젝트 선택을 복원하고, 마지막 프로젝트 닫기는 새 탭이 있으면 새 탭으로 이동한다. 열린 프로젝트가 없는 경우 인덱스로 본문을 읽지 않는다.
- tabs()의 동일 렌더링 순회에 새 탭 항목을 연결하여 스타일·강조선·닫기 정책을 재사용한다. 새 탭은 프로젝트 배열 인덱스로 접근하지 않는다.
- start_page()에 old와 같은 작업/최근 저장소 2열 구성을 추가한다. 세 작업은 현재 데모에 맞춰 연결 예정 안내만 표시한다. 실제 디렉터리 접근이나 설정 쓰기는 없다.
- render()는 새 탭 활성 상태를 우선하여 시작 화면을 표시한다. 프로젝트가 활성일 때만 기존 툴바·패널을 렌더링한다.

## 헌장과 영향 범위

헌장은 미작성 템플릿이므로 검사 생략. UI 내부 상태/렌더링만 변경하며 main → ui → sample 구조와 기존 그래프·Git 데이터 계층 책임은 유지한다. 새 의존성이나 공개 API/파일 형식 변경은 없다. 원본 프로젝트는 읽기만 한다.

## 검증

상태 전이 테스트를 먼저 작성해 신규 기능 부재를 확인한다. + 반복/재활성화, 프로젝트·새 탭 전환, 닫기·재열기, 마지막 프로젝트/전체 탭 닫기, 재시작에 해당하는 새 Default 상태를 검증한다. cargo fmt --check, cargo check --offline, cargo test --offline 및 별도 실행 파일 빌드를 수행한다. 실제 화면 조작은 도구 승인 제한에 따라 미검증 여부를 별도 기록한다.

## 시작 버튼 문구와 아이콘 계획

- 분석: start_page()의 start-actions 열은 별도 제목과 문자열 배열로 세 버튼을 생성한다. 버튼 클릭 안내는 title을 공유하므로 배열 문구 변경이 안내에도 반영된다.
- src/ui.rs에서 왼쪽 제목 child를 제거하고 배열을 Create/Open/Clone으로 변경한다. 버튼에 8px 간격과 16px 캔버스 아이콘을 앞에 추가한다.
- 더하기, 폴더, 겹친 사각형은 GPUI PathBuilder의 선 도형으로 그린다. 외부 이미지·아이콘 의존성이나 플랫폼 전용 글꼴 없이 현재 글자 색상을 따르도록 한다.
- 변경은 시작 화면의 표시뿐이며 상태·데이터·클릭 처리 및 기존 모듈 책임을 유지한다. 헌장은 미작성 템플릿이므로 검사 생략.
- 검증: 포맷, 컴파일, 기존 전체 테스트 및 별도 실행 파일 빌드. 단순 문구·도형 표시 변경에 구현을 복제하는 신규 테스트는 추가하지 않는다. 실제 화면 확인은 기존 도구 제한에 따라 별도 기록한다.
