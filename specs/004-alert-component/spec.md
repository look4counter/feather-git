# 기능 명세: 재사용 alert 팝업

> 문서 정리일: 2026-11-17. 본문은 이 기능의 단계별 요구사항 이력을 포함한다. 현재 유효 기준과 검증 한계는 [전체 명세 색인](../README.md)을 함께 확인한다. 과거 검증 기록은 현재 버전의 재검증 결과가 아니다.
> 후속 변경 참고: [005](../005-repository-dialogs/spec.md) · [062](../062-dialog-buttons-escape/spec.md).
> 현재 기준: Create 버튼은 테스트 알림 대신 실제 저장소 대화상자를 연다. 공통 Alert 자체의 오류·닫기 계약은 유지한다.

## 사용자 시나리오 및 검증

### 사용자 이야기 1 — Create로 테스트 (P1)

사용자는 새 탭의 Create를 누르면 화면 중앙에 테스트 alert를 본다. 제목, 안내 메시지와 확인 버튼이 보이며 확인·Enter·Esc로 닫을 수 있다. 닫은 뒤 다시 Create로 열 수 있다.

### 사용자 이야기 2 — 컴포넌트 재사용 (P2)

다른 호출부도 제목·메시지를 지정해 같은 alert 컴포넌트를 사용할 수 있다. 컴포넌트는 저장소나 Workspace의 업무 로직을 알지 않는다.

## 요구사항

- FR-001: 제목·메시지·확인 버튼 및 닫기 콜백을 지원하는 재사용 alert 컴포넌트를 제공한다.
- FR-002: 새 탭 Create 클릭은 테스트 제목과 메시지의 alert를 표시한다. 실제 저장소 생성은 수행하지 않으며 Open/Clone의 기존 안내는 유지한다.
- FR-003: alert는 기존 다크 테마의 중앙 모달과 어두운 배경으로 표시하고, 팝업이 열린 동안 배경 화면 클릭을 차단한다. 중복 alert는 쌓이지 않는다.
- FR-004: 확인 클릭·Enter·Esc는 같은 닫기 동작을 수행한다. 열 때 팝업에 포커스를 주고 닫을 때 이전 포커스가 있으면 복원한다. 배경 클릭만으로 닫지 않는다.
- FR-005: 제목과 긴 메시지는 모달 안에서 줄바꿈하며 작은 창에서도 가용 너비/높이를 넘지 않게 표시한다. 팝업 상태는 메모리에만 둔다.

## 성공 기준

- SC-001: Create → alert 표시 → 확인/Enter/Esc로 닫기 → 재열기를 지원하며 기본 상태와 새 Workspace에는 alert가 없다.
- SC-002: alert가 표시된 동안 프로젝트 전환·닫기·작업 버튼이 배경 클릭으로 실행되지 않는다.
- SC-003: 사용자 지정 제목·메시지를 전달할 수 있고 컴포넌트에서 Workspace나 저장소에 의존하지 않는다.
- SC-004: 포맷·컴파일·자동화 테스트·실행 파일 빌드가 통과한다. 실제 시각/키보드/포커스 검증 여부는 별도 기록한다.

## 가정 및 명확화

앱 내부 테마를 따르는 alert 모달로 해석한다. 테스트 문구는 알림 / Alert 팝업 테스트입니다.로 정한다. 확인 버튼 한 개를 제공하며 추가 확인·취소 업무 흐름은 범위 밖이다. 모호성 검토 결과 추가 질문 없이 진행 가능하다.
