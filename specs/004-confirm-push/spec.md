# 기능 명세: 푸시 확인창

작성일: 2026-11-01
상태: 검증 완료
입력: 푸시 전에 창을 띄우고 원격 변경 확인 후 강제 푸시 옵션을 제공한다.

## 사용자 시나리오와 검증

### 사용자 이야기 1: 푸시 확인 (우선순위 P1)
사용자는 푸시를 요청한 뒤 확인창에서 옵션을 선택하여 실행하거나 취소한다.
독립 검증: 실행 전 원격이 변하지 않으며 확인 시에만 갱신된다.
수용 시나리오:
1. 단독 푸시 요청 시 확인창이 열리고 실행되지 않는다.
2. 커밋 후 푸시를 선택하면 커밋 성공 후 같은 푸시 확인창을 연다.
3. 옵션은 기본 해제이고 명칭은 원격 변경 확인 후 강제 푸시다.
4. 해제 상태의 확인은 일반 푸시를 수행한다.
5. 선택하면 마지막으로 확인한 원격 상태가 유지된 경우에만 이력을 교체한다.
6. Escape 또는 창 바깥 클릭으로 닫으면 푸시를 하지 않고 완료된 로컬 커밋은 유지한다.
7. 제목·체크옵션·확인 버튼이 표시되고 설명 문구와 취소 버튼은 표시되지 않는다. 오류 발생 시 오류 문구는 표시한다.

### 경계 사례
- 원격이 다른 작업으로 변경되면 강제 푸시를 거절한다.
- 추적 원격 또는 브랜치가 없으면 오류를 표시한다.
- 실행 중 중복 제출과 옵션 변경을 차단한다.
- 실패 시 확인창과 오류를 유지하고 사용자가 재시도하거나 닫을 수 있다.

## 요구사항
- FR-001: 단독 푸시와 커밋 후 푸시는 확인창을 거친다.
- FR-002: 확정된 명칭의 기본 해제 옵션을 제공하고 대상 안내·확인 질문·옵션 설명 문구는 표시하지 않는다.
- FR-003: 일반 푸시와 원격 상태 일치 조건부 강제 푸시를 구분한다.
- FR-004: 취소 시 원격을 변경하지 않고 이미 완료된 로컬 커밋을 보존한다.
- FR-005: 키보드와 마우스 조작 및 처리 중 잠금과 오류 표시를 지원한다.

- FR-006: 푸시창에는 취소 버튼을 표시하지 않으며 Escape와 창 바깥 클릭으로 닫을 수 있다.

## 성공 기준
- SC-001: 모든 푸시 진입점에서 확인 전 원격 변경 횟수가 0이다.
- SC-002: 조건부 강제 푸시는 원격이 예상과 일치할 때 성공하고 다르면 실패한다.

## 가정과 명확화
- 사용자가 명칭을 원격 변경 확인 후 강제 푸시로 확정했다.
- 마지막으로 확인한 상태는 로컬 원격 추적 참조이며 확인창을 열거나 실행할 때 자동 패치하지 않는다.
- 현재 브랜치의 기존 추적 원격과 목적지 설정을 사용한다.
- 중대한 미해결 모호함이 없다.
