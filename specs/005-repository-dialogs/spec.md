# 기능 명세: 저장소 설정 팝업과 실제 프로젝트 열기

> 문서 정리일: 2026-11-17. 본문은 이 기능의 단계별 요구사항 이력을 포함한다. 현재 유효 기준과 검증 한계는 [전체 명세 색인](../README.md)을 함께 확인한다. 과거 검증 기록은 현재 버전의 재검증 결과가 아니다.
> 후속 변경 참고: [020](../020-remove-sample-projects/spec.md) · [029](../029-global-repository-progress/spec.md) · [062](../062-dialog-buttons-escape/spec.md) · [063](../063-shared-input-checkbox/spec.md).
> 현재 기준: 샘플 탭은 제거되었고 저장소 작업 진행은 본문 전역 오버레이를 사용한다. 입력·버튼은 공통 폼 컨트롤을 재사용한다.

## 사용자 시나리오 및 검증

### 사용자 이야기 1 — 저장소 생성 및 열기 (P1)

새 탭 Create/Open은 각각 Create Repository/Open Repository 팝업을 연다. 저장소 경로 입력과 탐색 버튼, 저장소 이름 입력, 우측 정렬 확인/취소 버튼을 표시한다. Create는 저장소가 이미 있으면 Alert를 표시하며 없으면 초기화한다. Open은 저장소 유무를 검사하고 실패 시 Alert, 성공 시 Alert 없이 바로 프로젝트를 표시한다.

### 사용자 이야기 2 — 복제 (P1)

Clone Repository는 소스 경로, 저장소 경로/탐색, 저장소 이름과 확인/취소를 제공한다. 소스를 먼저 검증하고 대상 경로가 비었는지 검사한다. 오류는 Alert로 표시하며 모든 조건이 통과하면 복제한 저장소를 연다.

### 사용자 이야기 3 — 입력 유지와 전환 (P1)

경로 변경 시 마지막 폴더명으로 이름을 자동 갱신하며 이름을 직접 수정할 수 있다. 오류 Alert를 닫으면 폼과 입력을 유지한다. 성공 시 설정 팝업과 임시 새 탭을 닫고 해당 실제 저장소를 선택한다.

## 요구사항

- FR-001: 위 세 타이틀과 필드 순서, 경로 옆 탐색 버튼, 우측 정렬 확인/취소를 공통 팝업으로 제공한다. Clone에서만 소스 경로를 표시한다.
- FR-002: 경로는 실제 저장소 폴더이고 이름은 탭 표시 이름이다. 경로를 직접 수정하거나 탐색으로 바꾸면 마지막 폴더명으로 이름을 갱신한다. 이후 이름 직접 수정이 가능하다. 빈 경로/이름과 줄바꿈 등 잘못된 입력은 Alert로 안내한다.
- FR-003: 탐색은 단일 폴더 선택을 사용하며 취소하면 값을 유지한다. 입력은 한글·유니코드·IME·붙여넣기·선택 편집을 지원한다.
- FR-004: Create는 선택 위치의 기존 Git 저장소/메타데이터를 감지하여 덮어쓰지 않고 Alert를 표시한다. 없다면 비파괴 초기화하고 필요한 새 폴더를 생성한다. 기존 일반 파일은 유지한다. 부모 저장소를 선택 위치의 저장소로 오인하지 않는다.
- FR-005: Open은 선택 위치의 실제 Git 저장소를 열고 없거나 접근할 수 없으면 Alert를 표시한다. 유효한 저장소는 성공 Alert 없이 바로 프로젝트로 연다. 작업 트리 및 bare 저장소를 지원한다.
- FR-006: Clone은 로컬 Git 폴더 또는 원격 Git 주소의 유효성/접근 가능성을 먼저 확인한다. 이후 대상이 없는 경로 또는 완전히 빈 폴더인지 확인하며 파일/비어 있지 않은 폴더이면 Alert를 표시한다. 검증 후 실제 복제를 수행한다. 실패 시 사용자 파일을 삭제하지 않는다.
- FR-007: Git/파일 작업은 백그라운드에서 실행하고 진행 중 중복 확인과 폼 수정/취소를 막는다. 오류는 Alert로 알리고 같은 입력으로 재시도할 수 있게 한다. 소스 인증정보를 Alert나 문서에 노출하지 않는다.
- FR-008: 성공 시 단일 새 탭을 닫고 실제 경로와 지정 이름의 프로젝트 탭을 활성화한다. 같은 저장소가 이미 열려 있으면 기존 탭을 선택한다. 실제 브랜치·커밋 기록/그래프·변경 파일/상세를 표시하고 샘플 데이터로 가장하지 않는다. 커밋 없는 저장소는 빈 상태를 표시한다.
- FR-009: 기존 샘플 탭, 단일 새 탭 수명과 Alert 컴포넌트를 유지한다. 취소/Esc는 입력 폼을 닫고 새 탭을 남긴다. 오류 Alert는 폼보다 위에 표시되고 닫으면 입력 포커스를 복원한다. 폼 필드는 Tab/Shift+Tab으로 이동하고 Enter로 확인한다.

## 성공 기준

- SC-001: 세 모드의 필드·타이틀·버튼 배치와 경로→이름 자동 갱신 및 수동 이름 수정이 일치한다.
- SC-002: 임시 폴더 테스트에서 생성/기존 저장소 거절/열기 성공과 실패/부모 오인 방지/유효·무효 소스/빈·비어 있지 않은 복제 대상 및 로컬 복제를 검증한다.
- SC-003: 실패는 원본 파일과 폼 상태를 유지하고 성공만 새 탭을 닫으며 실제 저장소 탭으로 이동한다. 중복 저장소 탭을 만들지 않는다.
- SC-004: 실제 저장소의 부모 관계, 커밋·파일·브랜치와 빈 저장소 표시를 검증하고 기존 그래프·탭·Alert 테스트가 통과한다.
- SC-005: 포맷·컴파일·자동화 테스트·빌드가 통과한다. 실제 폴더 탐색/IME/화면 조작 및 원격 인증은 별도 검증 여부를 명시한다.

## 가정 및 명확화

사용자 답변: 경로는 실제 저장소 폴더이며 이름은 프로젝트 탭 표시 이름이다. Open 성공 시 Create/Clone과 동일하게 Alert 없이 바로 프로젝트로 전환한다. 초기 이력은 최근 200개까지 읽고 추가 이력이 있음을 표시한다. 초기 열기 이후 자동 감시/갱신과 커밋·푸시 등 별도 작업은 이번 범위 밖이다. Git 작업에 실패하면 정리 목적으로 폴더를 삭제하지 않는다. 입력 의미와 오류/성공 전환을 검토했으며 추가 미해결 모호성은 없다.

## Open 성공 흐름 보완

- FR-010: Open 성공 시 저장소 확인 Alert를 표시하지 않고 설정 팝업/새 탭을 닫은 뒤 해당 프로젝트를 바로 활성화한다. 실패 시 기존 오류 Alert와 입력 유지 동작은 보존한다.
- SC-006: Create/Open/Clone 성공 분기는 모두 프로젝트 활성화로 종료하고 성공 Alert를 생성하지 않는다. 오류 분기는 기존대로 Alert를 표시한다.
- 명확화: 제거 대상은 Open 성공 안내뿐이며 유효성 검사, Git 작업, 중복 탭 방지와 실패 안내는 유지한다. 추가 모호성은 없다.
