# 검증 결과: 저장소 설정 팝업

## 요구사항과 구현 대응

| 요구사항 | 구현 및 확인 |
|---|---|
| FR-001 | RepositoryDialog가 Create/Open/Clone 타이틀과 공통 경로/이름, Clone 전용 소스, 우측 확인/취소를 구성한다. |
| FR-002 | 경로 변경 Changed 이벤트는 마지막 폴더명으로 이름을 갱신한다. 이름 입력에는 역방향 구독이 없어 표시 이름만 수정한다. 빈 값/제어문자를 서비스에서 검증한다. |
| FR-003 | GPUI 단일행 EntityInputHandler, UTF-16/IME 범위, 선택/클립보드, 긴 경로 가로 스크롤과 단일 폴더 탐색을 연결했다. 탐색 취소는 기존 값 유지이다. |
| FR-004 | NO_SEARCH/no_reinit와 .git 메타데이터 검사로 기존/부모 저장소를 보호하고 일반 파일을 보존한다. 필요한 새 부모 폴더를 만든다. |
| FR-005 | 정확한 선택 위치의 Git 저장소/작업 트리/bare를 열고 실제 스냅샷을 읽는다. 성공 시 바로 프로젝트를 열고 오류 Alert를 구현했다. |
| FR-006 | 소스 접근 검증 후 대상 비어 있음 검사를 수행한다. 없는 대상/빈 폴더에서 실제 복제하며 실패 시 재귀 삭제를 하지 않는다. |
| FR-007 | 백그라운드 작업과 busy 오버레이·포커스로 중복 제출/수정을 막고 오류 후 입력을 유지한다. 소스 연결/복제 오류는 인증정보 없는 안내로 변환한다. |
| FR-008 | 성공 시 새 탭을 닫고 canonical 경로의 실제 Project를 선택한다. 이미 열린 경로를 재사용하며 실제 이력·브랜치·변경 파일과 빈 상세를 표시한다. |
| FR-009 | 기존 샘플과 단일 임시 탭을 유지한다. 폼의 Tab/Shift+Tab, Enter/Esc와 취소, 폼 위 Alert 및 포커스 복원을 연결했다. |

UI → 저장소 서비스/모델, UI → 공통 입력/폼/Alert 책임을 유지했다. 외부 의존성 및 기존 사용자 파일/프로젝트는 변경하지 않았다. 실제 프로젝트의 별도 커밋·푸시 작업은 연결 예정 안내로 유지한다.

## 자동화 결과

- 서비스 테스트를 먼저 작성하고 미구현 상태에서 실패를 확인한 후 구현했다. 초기 시스템 임시 경로의 Git 메타데이터 쓰기 제한은 작업 공간 target/repository-tests의 격리 fixture로 옮겨 해결했다.
- cargo fmt --check: 통과.
- cargo check --offline: 통과.
- cargo test --offline: 총 33개 통과. 저장소 서비스 9개, 유니코드 단일행/UTF-16 경계, 실제 생성 저장소→빈 프로젝트 전환 및 기존 탭/그래프/Alert 테스트 포함.
- 기존 Create 테스트 Alert 진입 테스트는 사용자 요청으로 제거된 임시 동작이므로 실제 저장소 성공/중복 프로젝트 전환 테스트로 대체했다. Alert 컴포넌트 테스트는 유지했다.
- cargo clippy --offline --all-targets: 통과. 기존 탭 테스트의 field_reassign_with_default 경고 1개가 남으며 신규 프로덕션 코드 경고는 없다.
- cargo rustc --offline --bin feather-git -- -o target/debug/feather-git-repositories.exe: 통과.
- proc-macro-error2 미래 Rust 호환성 경고, 링크 출력 안내 및 별도 출력 경로 안내가 있다.

## 구체적 검증 범위

생성/중복 거절/기존 파일 보존, 없는 상위 폴더 생성, 부모 저장소 오인 방지, 가짜 .git, bare/빈 저장소, 잘못된 경로/빈 이름/파일 대상, 무효 소스 우선 검사와 비어 있지 않은 대상 보존, 로컬 Clone 및 file 주소의 빈 소스 Clone을 확인했다. 실제 커밋 메시지/변경 파일/브랜치 읽기와 샘플·실제 프로젝트 전환을 확인했다. 잘못된 소스 오류가 인증정보를 노출하거나 대상을 생성하지 않는 것도 확인했다.

## 미검증 항목과 제한

이전 화면 도구의 실행 파일 사용 승인 제한으로 실제 팝업 배치, 네이티브 탐색, 한글 IME 조작/클립보드, 키보드·마우스 및 오류 Alert 포커스 복원을 직접 확인하지 못했다. UTF-16/유니코드 범위는 자동화로 확인했으나 실제 IME 실행을 검증했다고 간주하지 않는다. 원격 HTTP/SSH 서버 및 인증 환경에서 Clone은 미검증이다.
초기 커밋 로딩은 최근 200개이며 추가 이력은 +로 표시한다. 이후 자동 저장소 감시/새로고침 및 기존 툴바의 커밋·풀·푸시 등은 이번 구현 범위 밖이다.

## Open 성공 Alert 제거 검증

- submit_repository의 Ok(project)는 공통 설정 팝업 종료와 activate_repository 호출로 끝나며 Open 전용 성공 Alert를 생성하지 않는다. 오류 Alert와 입력 유지/잠금 해제는 그대로다.
- FR-010 및 SC-006과 코드가 일치한다. 기존 서비스와 프로젝트 전환 테스트를 포함한 최종 전체 테스트 42개가 통과했다.
- 포맷·컴파일·clippy 및 target/debug/feather-git-loading.exe 최종 빌드가 통과했다. 기존 의존성과 테스트 경고는 유지된다.
- 실제 Open 클릭의 시각 확인은 기존 도구 승인 제한으로 미검증이다. 기존 T009 실제 조작 검증에서 확인한다.
