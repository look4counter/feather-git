# 기능 명세: 외부 변경 자동 감지

작성일: 2026-11-01
상태: 검증 완료
입력: 외부 변경을 묶어 필요한 화면만 갱신하고 무시 파일 및 비활성 탭의 부하를 제한한다.

## 사용자 시나리오와 검증

### 사용자 이야기 1: 외부 변경 자동 반영 (우선순위 P1)
IDE 저장 및 외부 스테이징을 자동 반영하고, 외부 커밋·브랜치 변경은 이력까지 갱신한다.
독립 검증: 임시 저장소의 파일·인덱스·참조 변경을 발생시켜 갱신 범위를 확인한다.
수용 시나리오:
1. 마지막 변경 500ms 후 갱신 가능 상태가 된다.
2. 연속 변경은 최대 2초 대기 후 반영하며 연속 스트림에서는 갱신 시작 간격을 2초 이상으로 제한한다.
3. 일반 파일 및 인덱스 변경은 Stage와 현재 Stage 파일 Diff만 조회한다. 커밋·브랜치·통합 상태 변경은 이력도 조회한다.

### 사용자 이야기 2: 대량 변경 및 여러 탭 (우선순위 P1)
빌드와 연속 저장 중에도 조회가 겹치지 않고 활성 저장소에 자원을 집중한다.
독립 검증: 가상 시계 기반 스케줄러 및 실제 무시 파일·추적 파일 변경을 검증한다.
수용 시나리오:
1. 조회 중 변경은 합쳐서 완료 이후 한 번의 후속 조회로 처리한다.
2. Git에서 무시하는 미추적 빌드 파일 변경만으로 상태를 다시 조회하지 않는다. 무시 규칙에 포함된 추적 파일은 감지한다.
3. 비활성 탭은 변경 표시만 누적하고 활성화 시 한 번 반영한다.
4. 탭을 닫으면 감시 자원을 해제한다.

### 경계 사례
- 파일 생성·삭제·이름 변경과 인덱스의 원자적 교체를 감지한다.
- 연결된 worktree의 별도 Git 디렉터리와 공통 참조를 감지한다.
- 감시 버퍼 초과는 전체 갱신으로 합친다. 감시 오류는 기존 오류 경로로 알린다.
- 입력 모달과 저장소 쓰기 작업 중에는 자동 반영을 미루고 변경은 보존한다.
- 파일 선택과 스크롤을 가능한 한 유지하며 사라진 파일 선택은 해제한다.

## 요구사항
- FR-001: 마지막 변경 후 500ms, 연속 변경의 최대 대기 2초를 적용한다.
- FR-002: 작업 파일·인덱스와 이력·참조 변경을 분류해 필요한 조회만 실행한다.
- FR-003: 저장소별 조회를 직렬화하고 진행 중 변경은 하나의 후속 작업으로 합친다.
- FR-004: Git 무시 파일 이벤트는 필터링하되 추적 파일과 무시 규칙 변경은 반영한다.
- FR-005: 비활성 탭은 조회를 지연하고 활성화 후 누적 변경을 반영한다.
- FR-006: 탭 수명에 맞춰 감시를 시작·해제하고 연결된 worktree를 지원한다.
- FR-007: 자동 조회는 백그라운드로 수행하고 기존 선택·스크롤을 가능한 한 유지한다.
- FR-008: 자동 스테이징·커밋·패치·풀 등 저장소 쓰기 작업은 실행하지 않는다.

## 성공 기준
- SC-001: 가상 시계 검증에서 499ms에는 조회하지 않고 500ms에 조회하며 연속 이벤트는 2초 내 준비된다.
- SC-002: 1,000개 이벤트를 받아도 동시에 진행하는 자동 조회는 저장소당 1개다.
- SC-003: 무시 빌드 파일만 변경하거나 비활성 탭인 동안 상태 조회 횟수는 0이다.
- SC-004: Stage 전용 갱신에서는 커밋 이력 조회 횟수가 0이다.

## 가정과 명확화
현재 제품의 Windows 대상에서 운영체제 파일 변경 알림을 사용한다. 다른 운영체제에서는 기능을 활성화하지 않는다. 대기 시간은 조회 및 UI가 사용 가능한 경우의 스케줄 기준이며 진행 중 작업·모달 종료까지 지연할 수 있다. 중대한 미해결 모호함은 없으며 결정적 스케줄러 테스트와 실제 파일 감시 테스트를 추가한다.
