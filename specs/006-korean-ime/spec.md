# 기능 명세: Windows 한글 조합 뒤 영문 입력 보존

> 문서 정리일: 2026-11-17. 본문은 이 기능의 단계별 요구사항 이력을 포함한다. 현재 유효 기준과 검증 한계는 [전체 명세 색인](../README.md)을 함께 확인한다. 과거 검증 기록은 현재 버전의 재검증 결과가 아니다.
> 후속 변경 참고: [063](../063-shared-input-checkbox/spec.md) · [080](../080-history-revert-reset/spec.md).

## 사용자 시나리오 및 검증

### 사용자 이야기 1 — 한글/영문 혼합 입력 (P1)

사용자는 저장소 설정 input에서 러를 조합한 뒤 한/영 전환하여 l을 입력해 러l을 얻는다. 앞선 한글이 사라지거나 늦은 확정으로 중복되지 않아야 한다. 다른 입력 필드도 같은 동작을 적용한다.

### 사용자 이야기 2 — 기존 편집 유지 (P1)

한/영 양방향 전환, 연속 한글 조합, 일반 영문·dead-key, 선택 교체, 방향키·삭제·붙여넣기를 유지한다. 입력 본문을 진단 로그에 남기지 않는다.

## 요구사항

- FR-001: old 프로젝트 007-fix-korean-ime에서 확인한 Windows 메시지 순서의 문자 손실 조치를 현재 앱에 적용한다. 조합 중 일반 WM_CHAR가 도착하면 네이티브 조합을 먼저 확정하고 일반 문자를 삽입한다.
- FR-002: 조합 종료와 결과의 순서가 달라도 한글을 보존하고 중복하지 않는다. 이전 결과와 새 조합이 같은 알림에 있으면 이전 결과를 먼저 적용한다. 취소는 현재 조합만 제거한다.
- FR-003: VK_PROCESSKEY 및 실제 IME 제어 키를 일반 문자 변환·앱 단축키보다 먼저 Windows 번역으로 전달한다. 일반 Alt/오른쪽 Alt/AltGr·문자·방향키 경로를 유지한다.
- FR-004: Windows 조합 완료 호출은 창 상태·입력 핸들러를 빌리지 않은 상태에서 수행해 동기 재진입 충돌을 피한다.
- FR-005: 같은 GPUI 0.2.2에 대한 로컬 패치로 고정한다. 사용자 Cargo 캐시나 old 프로젝트를 수정하지 않고 다른 플랫폼/렌더링 동작은 변경하지 않는다. 진단 로깅은 이식하지 않는다.
- FR-006: 회귀 테스트는 현재 TextInput이 사용하는 실제 텍스트 교체 로직과 Windows 메시지 순서 조정 로직을 함께 사용한다. 한글·이모지 접두어, 러l과 쿼리ID, 조합 후 편집을 검증한다.

## 성공 기준

- SC-001: 조합 중 영문 도착, 종료 선행/후행, 결과+새 조합, 취소·새 조합 경계에서 기대 문자열과 유효한 문자 경계를 유지한다.
- SC-002: IME 모드 키는 Windows 번역으로 전달하고 일반 Alt·문자·방향키는 기존 앱 경로를 유지한다. dead-key 합성 결과도 유지한다.
- SC-003: 포맷·컴파일·전체 자동화 테스트·실행 파일 빌드가 통과하고 Cargo 의존성 경로가 로컬 패치임을 확인한다.
- SC-004: Windows 실제 IME에서 러 → 한/영 전환 → l 및 왕복 전환을 확인한다. 도구 제한이 있으면 미검증으로 명시한다.

## 가정 및 명확화

사용자 입력 러l의 영문은 소문자 l로 해석한다. old의 최종 사용자 확인 기록과 실제 메시지 로그에 근거한 수정만 가져온다. 영문 여부로 조합을 임의 해제하는 우회는 다른 입력기/dead-key를 손상시키므로 적용하지 않는다. 구현을 막는 미해결 모호성은 없다.
