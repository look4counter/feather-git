# 구현 계획: 한글 조합 종료 후 입력 보존

**기능**: `007-fix-korean-ime` | **날짜**: 2026-11-03 | **명세**: [spec.md](spec.md)

## 요약

Windows 조합 종료를 누락한 GPUI 0.2.2의 입력 경로를 수정한다. 종료 직후 늦은 확정 결과를 받을 수 있도록 종료 상태를 기록하고, 다음 일반 입력·새 조합·마우스 조작 전에 조합 표시를 해제한다. 확정 결과와 새 조합이 동시에 있으면 확정을 먼저 처리한다.

## 기술 배경

- 언어: Rust 2024, 기존 도구 체인.
- 의존성: GPUI 0.2.2, Windows IMM32 입력 메시지.
- 플랫폼: Windows 데스크톱. 저장 형식과 Git 처리 변경 없음.
- 검증: 실제 편집 버퍼와 메시지 상태 전이를 연결한 단위 회귀 검증, 기존 편집기 검증, 애플리케이션 빌드.
- 성능: 입력당 상수 개수의 이벤트 처리. 문서 전체 복사나 별도 스레드 없음.
- 범위: 로컬 GPUI 의존성의 Windows 입력 처리와 편집기 회귀 검증.

## 헌장 확인

헌장은 미작성 템플릿으로 별도 규범은 없다. 저장소의 한글 문서 규칙과 speckit 단계 순서를 준수한다. 설계 이후에도 위반 없음.

## 조사 및 설계

[research.md](research.md)의 원인과 대안을 기준으로 로컬 GPUI 복사본을 Cargo 패치로 사용한다. 다른 입력기를 손상시킬 수 있는 ASCII 판별 우회나 한영키 이름 검사는 사용하지 않는다. 기존 소스와 라이선스를 유지하며 변경 출처를 기록한다.

조합 상태와 계약은 [data-model.md](data-model.md), [contracts/input.md](contracts/input.md)에 정의한다. 실행 절차는 [quickstart.md](quickstart.md)에 둔다.

## 구조

- `vendor/gpui/`: GPUI 0.2.2 원본과 Windows 입력 수정, 한글 수정 내역.
- `vendor/gpui/src/platform/windows/ime.rs`: 외부 라이브러리 없이 검증할 수 있는 조합 생명주기 상태 전이.
- `vendor/gpui/src/platform/windows/events.rs`: 메시지 해석과 편집 동작 연결.
- `vendor/gpui/src/platform/windows/window.rs`: 창별 조합 상태.
- `Cargo.toml`, `Cargo.lock`: 로컬 패치 연결.
- `src/commit_editor.rs`: 실제 버퍼를 사용하는 회귀 검증.

## 구현 단계

1. 원본 의존성과 라이선스 확인 및 로컬 패치 준비.
2. 실패하는 입력 시퀀스를 검증으로 고정.
3. 조합 종료·확정·취소와 동시 플래그 순서 수정.
4. 기존 검증과 빌드를 실행하고 명세 대비 잔여 작업 확인.

## 복잡도 검토

약 8MB의 GPUI 복사본이 추가된다. 창 프로시저를 외부에서 가로채는 방식의 재진입과 수명 관리 복잡성을 피하고, 캐시 수정 없이 누구나 같은 수정본을 빌드하도록 하기 위해 필요하다.

## 재조사 계획

`cargo run`에서 재현된다는 사용자 확인으로 이전의 종료 알림 가정을 검증해야 한다. `FEATHER_IME_TRACE`가 설정된 경우에만 로컬 파일에 Windows 입력 메시지, IME 열림 여부와 조합 길이, 전달 동작의 길이를 기록한다. 본문을 기록하지 않는다. 관측 결과에 따라 상태 전이를 수정한다. 실제 앱 자동 실행은 Computer Use에서 거절되어 사용자의 재현이 필요할 수 있다. 단위 검증만으로 완료 판단하지 않는다.

추가 파일: `vendor/gpui/src/platform/windows/ime_trace.rs`. 기존 `events.rs`에서 메시지와 전달 동작을 관측한다. 저장 형식과 사용자 기능은 바꾸지 않는다.

## 관측에 따른 수정 설계

`.build/ime-trace.log`에서 조합 길이 2바이트와 조합 영역 `1..2`가 남은 상태로 `WM_CHAR`가 도착해 1바이트 입력이 기존 조합을 교체했다. 한글 확정 `GCS_RESULTSTR`은 그 뒤에 도착했다.

`WM_CHAR` 처리 시 Windows 입력기에 실제 조합 문자열이 있는지 확인한다. 있으면 `ImmNotifyIME(NI_COMPOSITIONSTR, CPS_COMPLETE)`로 확정을 요청한 후 일반 문자를 전달한다. 입력기 호출 전에는 창 상태나 편집기 핸들러를 빌리지 않아 동기 재진입으로 전달되는 확정 알림을 처리할 수 있게 한다. 조합이 없는 일반 입력과 dead-key 처리는 보존한다. `ime.rs`의 작은 순서 제어 함수를 실제 메시지 경로와 회귀 검증이 공유한다.

자동 검증만으로 최종 완료하지 않고, 수정 후 동일 진단을 켠 실제 사용자 입력에서 결과와 순서를 다시 확인한다.

## 한/영 전환 키 설계

Windows 메시지 루프는 TranslateMessage를 공통 호출하지 않고 각 키 핸들러에 맡긴다. 기존 `handle_keydown_msg`는 `VK_PROCESSKEY`에서 원래 키를 복원한 후 일반 키 변환이 실패하면 TranslateMessage 없이 반환한다. 일반 문자로 매핑되지 않는 한/영·한자 전환이 이 경로에서 누락될 수 있다.

`VK_PROCESSKEY`와 입력기 모드 제어 키는 일반 키 변환과 앱 콜백에 들어가기 전에 원래 메시지 그대로 TranslateMessage에 전달한다. key-up도 기본 Windows 처리로 넘긴다. `ime.rs`의 순서 제어 함수와 회귀 검증을 공유한다. 물리적인 오른쪽 Alt 전체를 한/영키로 간주하지 않아 AltGr와 일반 Alt 단축키를 보존한다. 진단에는 입력기 제어 키의 종류만 추가 기록한다.
