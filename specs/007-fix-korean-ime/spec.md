# 기능 명세: 한글 조합 종료 후 입력 보존

**기능 식별자**: `007-fix-korean-ime`
**작성일**: 2026-11-03
**상태**: 검토 완료
**요청**: 커밋창에서 `쿼리I`가 `쿼I`로 바뀌고 입력 중 프로그램이 종료되는 문제를 수정한다.

## 사용자 시나리오와 검증

### 사용자 이야기 1 — 한글과 영문 연속 입력 (우선순위: P1)

사용자는 커밋 메시지에서 한글을 입력하고 한/영 전환 후 영문을 이어 입력한다.
**우선순위 이유**: 작성한 메시지가 손실되는 핵심 입력 결함이다.
**독립 검증**: `쿼리` 입력 → 한/영 전환 → `ID` 입력 결과가 `쿼리ID`인지 확인한다.

1. 마지막 `리`가 조합 중일 때 영문으로 전환하고 `I`를 입력하면 `쿼리I`가 된다.
2. 이어서 `D`를 입력하면 `쿼리ID`가 되며 입력과 커서 이동이 계속 동작한다.
3. 한글 조합을 취소하면 취소한 글자가 되살아나지 않는다.

### 경계 조건

- 한글 조합 도중 받침과 모음을 바꾸는 과정은 기존처럼 동작한다.
- 이모지와 여러 줄 문장 앞뒤에서도 마지막 한글과 영문이 보존된다.
- 조합 확정과 다음 조합 시작이 같은 입력 알림으로 전달될 수 있다.
- 선택 영역 교체, 일본어 조합 취소, 영문만 입력하는 동작을 보존한다.

## 요구사항

### 기능 요구사항

- **FR-001**: 한글에서 영문으로 전환한 후 입력한 문자는 확정된 한글 뒤에 추가되어야 한다.
- **FR-002**: 조합 갱신·확정·취소는 각각 해당 조합 영역에만 적용되어야 한다.
- **FR-003**: 조합 종료 후에는 이전 조합 영역이 남아 후속 입력을 덮어쓰지 않아야 한다.
- **FR-004**: 이모지·여러 줄·선택 영역을 포함한 입력에서 문자 손실이나 비정상 종료 없이 편집을 계속할 수 있어야 한다.

### 주요 개체

- 편집 문서: 메시지, 커서, 선택 영역, 현재 조합 영역.
- 조합 생명주기: 시작, 갱신, 확정 또는 취소, 종료.

## 성공 기준

- **SC-001**: `쿼리I`, `쿼리ID` 및 이모지·여러 줄 변형의 회귀 검증이 모두 통과한다.
- **SC-002**: 조합 갱신·확정·취소·종료 뒤 후속 편집 검증에서 글자 손실과 비정상 종료가 0건이다.

## 가정

- Windows의 기존 입력기를 사용하며 커밋창과 동일 편집기를 사용하는 입력창에도 수정이 적용된다.
- 보고된 종료 현상과 글자 손실의 원인이 같다고 단정하지 않으며 확인 가능한 입력 경로를 검증한다.
- 회귀 자동 검증을 추가한다. 새로운 입력 기능이나 화면 개편은 범위에 포함하지 않는다.

## 명확성 검토

2026-11-03: 사용자 재현 설명으로 기대 결과와 범위가 명확하다. 추가 질문 0건. 기능·데이터·상호작용·경계 조건·검증 범주에 중요한 미결 사항이 없다.

## 재검토 — 실제 입력에서 미해결

2026-11-03 사용자 확인: `cargo run`으로 실행한 debug 빌드에서도 `쿼리I`가 `쿼I`로 바뀐다. 기존 회귀 검증은 가정한 이벤트 순서만 다루었으며 실제 입력 경로의 해결 증거가 아니다. 기대 동작과 범위는 변경하지 않는다. 추가 질문 없이 실제 메시지 관측을 우선한다.

- **FR-005**: 문제 재현을 위해 명시적으로 활성화한 로컬 진단은 입력 메시지 종류·조합 상태·교체 길이를 기록하되 문서 본문과 비밀 입력 내용을 기록하지 않아야 한다.
- **SC-003**: 실제 입력 메시지로 원인을 확인하고 동일 흐름의 재현 결과를 확보하기 전에는 수정 완료로 보고하지 않는다.

## 관측된 입력 순서 — 2026-11-03

사용자 재현 로그에서 마지막 한글 조합이 남아 있는 동안 일반 문자 입력이 먼저 전달되고, 이후에 한글 확정 결과와 종료 알림이 도착했다. 따라서 일반 문자를 삽입할 때 진행 중인 조합을 입력기에 확정 요청한 뒤 삽입해야 한다. 종료 알림이 먼저 도착한다고 가정하지 않는다. 기존 기대 동작과 범위는 동일하며 추가 질문은 필요하지 않다.

## 한/영 전환 요구사항

사용자는 한/영키를 눌러도 전환되지 않는 경우가 있음을 보고했다. 기존 입력 보존 수정과 별도로 입력기 전환 키가 앱의 일반 키 변환 실패나 단축키 처리에 막히지 않아야 한다.

- **FR-006**: 한/영·한자·변환 등 입력기 제어 키와 입력기가 이미 처리하는 키는 Windows 입력기에 전달되어야 하며 앱 단축키로 소비되면 안 된다.
- **SC-004**: 한글 조합 중과 조합하지 않는 상태에서 한/영키를 반복 입력하여 각 방향의 전환 및 기존 한글 보존을 확인한다.
- 추가 명확성 검토: 사용자 기대 동작은 명확하며 질문 없이 기존 기능 범위에서 처리한다.
