# 기능 명세: 공통 진행 표시와 Dialog 기반

> 문서 정리일: 2026-11-17. 본문은 이 기능의 단계별 요구사항 이력을 포함한다. 현재 유효 기준과 검증 한계는 [전체 명세 색인](../README.md)을 함께 확인한다. 과거 검증 기록은 현재 버전의 재검증 결과가 아니다.
> 후속 변경 참고: [021](../021-persist-workspace/spec.md) · [029](../029-global-repository-progress/spec.md).

## 사용자 시나리오 및 검증

### 사용자 이야기 1 — 공통 진행 표시 (P1)

저장소 작업 중 표시하는 진행 오버레이를 업무 코드와 독립된 공통 컴포넌트로 재사용한다. 호출부가 작업 식별자를 지정하며 기존 테마와 중앙 진행 애니메이션, 가려진 영역의 입력 차단을 유지한다.

### 사용자 이야기 2 — 탐색과 작업 구분 (P1)

폴더 탐색 중에는 네이티브 선택 창만 표시하고 별도 처리 중 문구는 띄우지 않는다. 중복 탐색/확인·취소는 계속 막는다. 실제 Git 검증·생성·복제 중에만 공통 진행 표시를 띄운다.

## 요구사항

- FR-001: 작업 식별자를 받아 지정 영역을 덮는 독립 ProgressOverlay 컴포넌트를 제공한다. 저장소/Workspace 업무 상태에 의존하지 않는다.
- FR-002: 기존 RepositoryDialog 내부의 전용 진행 UI를 제거하고 공통 컴포넌트를 사용한다. 기존 테마·중앙 정렬 및 폼 영역의 오버레이를 유지한다. 새 창이나 진행률/취소 동작은 추가하지 않는다.
- FR-003: 폼 상태는 대기/폴더 탐색/Git 작업을 구분한다. 탐색과 Git 작업 둘 다 중복 입력을 막되 진행 표시는 Git 작업에만 보인다. 성공·오류·탐색 취소 후 상태 해제를 유지한다.
- FR-004: Alert와 Create/Open/Clone 공통 폼은 기존처럼 별도 컴포넌트로 유지한다. 폼 위 오류 Alert와 포커스 복원을 변경하지 않는다.

## 성공 기준

- SC-001: 진행 표시의 시각 구현이 한 공통 컴포넌트에만 존재하고 호출부가 작업 식별자를 지정한다.
- SC-002: 폴더 탐색은 입력 잠금/진행 숨김, Git 작업은 입력 잠금/진행 표시, 대기는 입력 허용/진행 숨김이라는 상태 계약을 검증한다.
- SC-003: 포맷·컴파일·기존 전체 테스트·정적 검사·빌드가 통과한다. 실제 화면 검증 여부는 구분한다.

## 가정 및 명확화

앞선 탐색 버튼 논의에 따라 탐색 시 불필요한 진행 문구를 제거하되 단일 작업 보호는 유지한다. 컴포넌트는 상대 위치 부모 안에서 사용하고 키보드 포커스와 작업 수명은 호출부가 관리한다. 퍼센트·취소 기능은 이번 범위 밖이다. 추가 모호성은 없다.

## 공통 Dialog 기반 확장

### 사용자 이야기 3 — 팝업 기반 재사용과 타이틀바 보존 (P1)

저장소 설정과 Alert는 공통 Dialog를 기반으로 제목·본문·버튼을 구성한다. 어떤 팝업도 타이틀바를 어둡게 덮거나 창 제어 버튼을 가리지 않는다.

- FR-005: 공통 Dialog가 모달 배경, 카드 크기/테마/제목/본문/우측 버튼 영역, 입력 차단과 포커스/키 처리 연결점을 제공한다. 호출부가 업무별 내용을 조합한다.
- FR-006: RepositoryDialog는 공통 Dialog에 저장소 필드·버튼·진행 표시를 얹고, Alert도 같은 Dialog에 메시지·확인 버튼을 구성한다. 중복 모달 껍데기를 제거하며 업무 이벤트·검증은 각 호출부에 남긴다.
- FR-007: Workspace의 타이틀바와 본문 영역을 분리하고 모든 Dialog는 본문 영역 안에서만 배경/카드를 렌더링한다. 창 크기 변경에도 타이틀바 높이를 침범하지 않는다. 타이틀바의 이동/최소화/최대화/닫기 영역은 유지한다.
- FR-008: 오류 Alert가 RepositoryDialog보다 위에 표시되는 순서, 확인/취소/Enter/Esc/Tab, 포커스 복원, 작업 중 보호와 공통 진행 표시를 유지한다.
- SC-004: Alert/RepositoryDialog의 모달 배경·카드·제목·우측 버튼 배치를 공통 Dialog가 한 곳에서 구현한다. 두 호출부는 공통 API를 사용한다.
- SC-005: 두 팝업 및 중첩 오류 Alert에서 타이틀바 배경과 창 제어가 가려지지 않고, 작은 창/크기 변경에도 본문 영역 내에서 표시된다. 실제 시각 검증 여부는 별도 기록한다.
- 명확화: Dialog ← RepositoryDialog 관계는 Rust에서 공통 Dialog의 조합으로 구현한다. Alert도 같은 기반을 사용하며 ProgressOverlay는 기존 폼 내부 공통 요소로 유지한다. 타이틀바를 포함한 창 전체가 아닌 타이틀바 아래의 본문을 모달 호스트로 사용한다.

## 깃털과 물결 진행 애니메이션

- 사용자 이야기 4 (P1): 작업 중 텍스트 대신 깃털이 천천히 내려와 물에 닿고 물결이 바깥으로 퍼지는 반복 애니메이션을 본다.
- FR-009: 공통 ProgressOverlay의 고정 진행 문구를 깃털 낙하 → 수면 접촉 → 물결 확산/소멸의 약 2.8초 반복 벡터 애니메이션으로 대체한다. 수면 접촉 전에는 물결이 생기지 않는다.
- FR-010: 실제 작업 중에만 반복하고 작업 종료 시 표시와 프레임 갱신이 중단된다. Git 완료를 기다리게 하거나 실제 진행률을 가장하지 않는다. 탐색 시 숨김, 모달 입력 차단과 타이틀바 비침범은 유지한다.
- SC-006: 깃털 끝이 수면에 도달하는 시점부터 물결이 생기며 이후 반경이 커지고 투명해진다. 반복 경계에서 깃털/물결이 투명해지고 새 장면이 시작된다. 좌표/불투명도는 유효한 범위이다.
- 명확화: 회전 로딩 제안은 사용자의 구체적인 깃털/물결 요청으로 대체한다. 이미지 파일이나 새 의존성 없이 GPUI 벡터·프레임 애니메이션으로 그린다. 기존 new(message) 호출 형태는 유지하고 문자열은 작업별 애니메이션 식별자로 사용한다. 화면에 기존 진행 문구는 표시하지 않는다.
