# 기능 명세: 커밋 히스토리 렌더링 최적화와 레인 겹침 방지

> 문서 정리일: 2026-11-17. 본문은 이 기능의 단계별 요구사항 이력을 포함한다. 현재 유효 기준과 검증 한계는 [전체 명세 색인](../README.md)을 함께 확인한다. 과거 검증 기록은 현재 버전의 재검증 결과가 아니다.
> 후속 변경 참고: [015](../015-history-grid-columns/spec.md) · [018](../018-remove-graph-minimum/spec.md) · [059](../059-footer-overlay-actions/spec.md) · [080](../080-history-revert-reset/spec.md).
> 현재 기준: 현재 레인 간격 18px, 초기 그래프 열 92px, 최소 열 너비 0이다. 수직선은 채움 경로를 사용하며 후속 058의 1,500개 초기 조회·200개 추가 조회를 적용한다.

## 사용자 시나리오 및 검증

### 사용자 이야기 1 — 빠른 이력 탐색 (P1)

커밋 목록은 old처럼 보이는 행만 렌더링한다. 커밋 선택/스크롤/프로젝트 전환에서 불필요한 전체 행 생성과 그래프 재계산을 줄이고 기존 상세 동기화와 24px 행을 유지한다.

### 사용자 이야기 2 — 그래프 가독성 (P1)

브랜치 레인이 많아도 원이 겹치지 않는다. 그래프 열은 필요한 너비를 확보하고 공간이 부족하면 표를 가로로 스크롤하여 그래프/메시지/작성자/날짜/해시를 확인한다. 헤더와 본문은 함께 가로 이동한다.

## 요구사항

- FR-001: old의 GPUI uniform_list 방식을 적용하여 현재 표시 범위 및 프레임워크 측정에 필요한 행만 생성한다. 전체 커밋 행을 render마다 순회해 생성하지 않는다.
- FR-002: 프로젝트별 그래프 토폴로지와 스크롤/행 표시 캐시를 재사용한다. 커밋 선택·다른 UI 갱신·동일/다른 프로젝트 재선택에서 그래프를 불필요하게 재구축하지 않는다. 실제 스냅샷 교체 시 캐시를 무효화하고 탭 닫기 시 해제한다.
- FR-003: 그래프 행과 표시용 문자열은 해당 행이 처음 필요할 때 준비하고 재사용한다. 보이지 않는 행은 준비하지 않는다. 그래프 부모 관계/색상 및 현재 HEAD 링을 유지한다.
- FR-004: 레인 중심 간격은 20px, 첫/마지막 레인 중심과 열 경계 사이 여백은 최소 10px로 유지한다. 기존 45px 그래프 열의 최소 크기는 유지하되 레인 수에 따라 열을 넓히며 더 이상 압축하지 않는다. 헤더/행에 같은 너비를 적용한다.
- FR-005: 그래프가 넓어지면 메시지와 나머지 열을 밀어 겹치게 하지 않고 전체 표의 가로 스크롤을 제공한다. 기존 세로 스크롤은 가상 목록에서 제공하고 프로젝트별 위치를 유지한다.
- FR-006: 선택 행·상세 동기화, 빈 이력, 기존 샘플/실제 저장소, 24px 높이와 체크아웃 원 확대/픽셀 정렬을 유지한다. 새 저장소 로딩·페이징·정렬 정책은 추가하지 않는다.

## 성공 기준

- SC-001: 200/10,000개 합성 이력에서도 요청한 표시 범위만 행 표시 데이터를 준비하며 반복 요청은 기존 캐시를 재사용한다. 테스트로 준비 행 개수와 범위 경계를 확인한다.
- SC-002: 200개 이력의 반복 프로젝트 선택을 현재 구현에서 먼저 측정하고 변경 후 동일 작업으로 비교한다. 렌더링 준비 비용도 전체 행/표시 범위별로 측정하며 실제 화면 FPS와 혼동하지 않는다.
- SC-003: 1~64개 레인, 100/125/150/175/200% 배율에서 인접 노드 외곽 사이에 최소 4px 여유를 유지하고 그래프 열 경계를 넘지 않는다. 체크아웃 링 확대는 유지한다.
- SC-004: 포맷·컴파일·전체 테스트·정적 검사·빌드가 통과하고 실제 스크롤/가로 이동의 시각 검증 여부를 별도 기록한다.

## 가정 및 명확화

old의 가상 목록과 캐시 방식을 참고하되 원 겹침을 만드는 레인 압축은 유지하지 않는다. 현재 로딩 상한 200개는 이번 작업에서 변경하지 않고 10,000개 데이터는 확장성 회귀 검증에만 사용한다. 성능 저하의 모든 원인이 목록이라고 단정하지 않으며 확인한 전체 행 생성/재계산을 개선한다. 추가 모호성은 없다.

## 추가 요구: 창 이동과 스크롤의 그리기 비용

- 명확화: 사용자는 빈 새 탭이 아니라 저장소 커밋 기록 화면에서만 지연이 발생한다고 확인했다.
- FR-007: 수직 그래프 선은 경로 대신 직접 사각형으로 그려 Windows 경로 중간 렌더링 비용을 줄인다. 곡선, 색상, 24px 행, DPI 정렬과 노드 모양은 유지한다.
- SC-005: 직선만 있는 이력의 그래프 경로 수는 0이며, 혼합 이력에서는 곡선만 경로로 생성한다. 분수 배율과 스크롤 좌표에서도 선 연결을 검증한다. 실제 GPU 응답은 별도 측정 전까지 미검증으로 보고한다.

## 렌더링 동등화 요구 및 명확화

사용자는 앞선 변경 후에도 느리며 old의 렌더링 방식을 동일하게 적용하도록 요청했다. 기존 FR-007과 SC-005의 수직선 quad 조건은 이 요청으로 대체한다.
- FR-008: old history_view.rs와 동일하게 수직선은 채움 경로, 곡선은 스트로크 경로, 원은 네 개의 3차 베지어 채움 경로로 그린다. 기존 경로 캐시 키와 행별 canvas를 유지한다.
- FR-009: 목록은 old처럼 flex_1/min_h_0/min_w_0/overflow_hidden의 제한된 뷰포트 안에 둔다. 이전 요구의 공통 가로 스크롤, 20px 레인 간격, 24px 행, 13px 체크아웃 외경과 7px 내경은 유지한다.
- SC-006: old와 경로 생성 및 페인트 순서를 소스 대조하고 기존 노드/배율/간격 테스트와 전체 검사를 통과한다. 실제 GPU 성능은 실측 없이 완료로 단정하지 않는다.
- 명확화: 느린 곳은 저장소의 커밋 기록 화면이며 현재 실행 명령은 cargo run이다. old 실행 프로세스는 release 경로로 확인되므로 실행 프로필 차이는 별도 한계로 기록한다.

## 실제 프레임 진단

FR-010: 이전 수정 후에도 지연이 지속되어 실제 GPUI 프레임의 목록 요청 범위, UI 준비 시간과 Windows 그리기 시간을 측정한다. 임시 진단은 정상 동작에 남기지 않는다. 원인 확인 후 필요한 최소 수정만 적용하고 실측 한계를 보고한다. 추가 사용자 모호성 없음.

FR-011: cargo run의 개발 빌드에서도 GPUI와 taffy 레이아웃 엔진을 최적화한다. 사용자 앱의 개발 디버그 동작과 release 설정은 유지하고 핵심 의존성 교체는 하지 않는다. SC-007: 동일 200개 합성 이력의 60개 반복 실제 프레임에서 변경 전후 UI 준비 시간 중앙값을 비교하고 감소 여부를 기록한다. 숨겨진 창의 DirectX 시간은 GPU 완료 시간이 아닌 CPU 호출 시간으로 한정한다.

FR-011 보완: GPUI 패키지의 개발 프로필은 debug-assertions도 비활성화하여 release와 같은 비검사 렌더 경로를 사용한다. 앱 자체의 debug-assertions는 유지한다.
