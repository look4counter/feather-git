# 구현 계획: 조회 완료 후 입력 차단 해제

**날짜**: 2026-11-03 | **명세**: [spec.md](spec.md)

## 요약

새로고침의 상태 소유 세대를 별도로 기록한다. 완료 콜백은 결과 적용 여부와 상태 해제를 구분하여, 대체된 결과를 버리더라도 자신이 소유한 히스토리 로딩은 해제한다. 더 최신 요청의 상태와 데이터는 보존한다.

## 기술 맥락

- 언어: Rust 2024, 기존 도구 체인 사용.
- 의존성: GPUI 0.2.2, 기존 Git 조회 계층. 새 의존성 없음.
- 저장: 영속 형식 변경 없음. 탭 내부 메모리 상태만 추가.
- 대상: Windows 데스크톱 앱.
- 검증: 모델의 조회 완료 순서 회귀 테스트, 전체 바이너리 테스트, 오프라인 빌드, 형식 검사.
- 성능: 상태 전이에 정수 비교만 추가하며 폴링이나 타이머를 도입하지 않는다.
- 범위: src/model.rs와 src/ui.rs의 새로고침 생명주기 및 인접 상태 점검.

## 헌법 점검

헌법은 미작성 템플릿이므로 규범 검사를 생략한다. 저장소 지침인 한글 문서와 speckit 전 단계 수행을 준수한다. 설계 전후 위반 없음.

## 조사 단계

[research.md](research.md)에 경쟁 조건, 다른 로딩 경로의 점검, 대안 비교를 기록한다. 읽기 전용 연구 검토 결과도 반영한다. 미해결 기술 항목 없음.

## 설계 단계

- Project에 비공개 history_generation을 추가한다.
- begin_reload는 세대 증가와 히스토리·일반 로딩 시작을 담당한다.
- finish_reload는 히스토리 소유권에 따라 차단을 해제하고 현재 세대일 때만 일반 로딩을 해제하며 결과 적용 가능 여부를 반환한다.
- reload 완료 콜백은 탭 식별자로 찾은 후 finish_reload를 호출한다. 오래된 결과를 버릴 때도 화면에 통지한다.
- 성공·실패 분기보다 먼저 상태를 정리한다. 닫힌 탭은 무시한다.
- 모델의 같은 전이 함수를 테스트하여 두 완료 순서, 새로고침 중첩, 실패 완료와 최신 선택 보존을 검증한다.

## 프로젝트 구조

- src/model.rs: 소유권 필드, 상태 전이 함수, 회귀 테스트.
- src/ui.rs: 새로고침 시작·완료 연결.
- specs/009-fix-loading-state/: 명세, 계획, 조사, 데이터 모델, 화면 계약, 검증 절차와 작업 목록.

## 복잡성 추적

소유 세대 하나로 상태 해제와 결과 적용을 분리한다. 작업 관리자나 취소 프레임워크는 도입하지 않는다.
