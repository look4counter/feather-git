# 조사 결과

## 결정: 새로고침 상태의 소유권 분리

reload만 history_loading을 켜지만 select_commit도 generation을 증가시킨다. 기존 reload 콜백은 세대가 다르면 상태 해제 전에 반환한다. history_generation으로 소유자를 기록하고 결과 폐기와 상태 정리를 분리한다.

**근거**: 최신 커밋 조회의 loading과 최신 새로고침의 history_loading을 보호하면서 이전 작업이 남긴 차단을 해제한다. 읽기 전용 연구 검토도 같은 결과이며, 오래된 완료 경로의 화면 통지가 필요하다.

**검토한 대안**: 커밋 선택 시 즉시 로딩을 끄면 아직 실행 중인 작업 보호가 사라진다. 모든 오래된 완료가 로딩을 끄면 최신 새로고침 상태도 손상된다. 검색 입력을 전부 막으면 기존 검색 동작을 바꾸며 상태 소유권 결함도 남는다.

## 인접 경로 점검

page_generation을 바꾸는 reload는 page_loading을 초기화한다. 외부 변경 조회는 페이지 조회 중 시작되지 않는다. diff_generation은 별도 로딩 상태와 함께 관리된다. 이 범위에서 같은 영구 로딩 누락은 추가 확인되지 않았다. 실제 외부 작업이 멈추는 문제는 이번 수정과 구분한다.
