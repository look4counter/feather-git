# 구현 계획: HTTP 인증 주소 지원

작성일: 2026-11-04 | 명세: [spec.md](spec.md)

## 요약

HTTP와 HTTPS를 인증 경로 전반에서 허용하고 요청 프로토콜은 URL에서 추출한다. 기존 입력 검증 및 프로토콜별 자격 증명 분리를 유지한다.

## 기술 맥락

Rust 2024, GPUI 데스크톱 앱, url·git2 및 Git 자격 증명 도우미를 사용한다. Windows 자격 증명과 기존 JSON 프로필 저장 구조를 유지한다. 추가 의존성, 저장 형식 변경 및 성능 목표 변경은 없다. 검증은 cargo test와 cargo fmt로 진행한다.

## 헌장 점검

헌장은 미작성 템플릿이므로 구체 원칙 점검은 생략한다. AGENTS.md의 한글 문서 및 speckit 단계 준수를 설계 전후 확인했다.

## 구조와 구현 단계

- src/auth_profiles.rs: 등록 URL 검증, 요청 프로토콜, 기존 자격 증명 가져오기 및 원격 연결을 HTTP로 확장한다.
- src/credentials.rs: LoginTarget에 프로토콜을 보존하고 도우미 요청에 사용한다.
- src/native_remote.rs: HTTP 원격에도 기존 계정 탐색을 적용한다.
- src/auth_settings.rs: HTTP/HTTPS 주소 안내를 표시한다.
- 관련 모듈의 기존 단위 테스트에 HTTP 등록·요청·연계·프로토콜 분리 회귀 사례를 추가한다.

## 검증 전략

인증 관련 테스트를 먼저 실행하고 전체 테스트 및 포맷을 확인한다. 실제 외부 서버 로그인은 서버와 도우미가 필요하므로 자동 검증에서는 요청 생성과 저장·선택·삭제 계약을 검증한다.

## 복잡도 추적

기존 경로 확장만 필요하며 신규 계층이나 의존성은 없다.

## 후속 구현 계획: URL 계정 처리

src/auth_profiles.rs의 select에서 원격 URL을 파싱하고 URL 계정과 콜백 계정의 일치를 확인한다. 사용자 정보만 분리한 URL로 기존 엄격한 정규화 및 범위 비교를 재사용한다. 등록 주소의 검증은 완화하지 않는다. 프로토콜·포트·경로는 변경하지 않는다. URL의 비밀번호는 등록 인증 선택 조건으로 사용하지 않는다. URL의 퍼센트 인코딩 계정은 디코딩한 계정과 대조하며 잘못된 인코딩은 선택하지 않는다.

회귀 테스트는 로컬 가짜 비밀 저장소로 직접 비밀 해석까지 검증한다. 대상은 HTTP/HTTPS, 계정 유무, 명시적 계정 충돌, 다른 계정, 인코딩된 ID, 다른 프로토콜·포트·경로이다. 기존 인증 모듈 테스트와 cargo check --offline --locked --all-targets로 검증한다. 실제 내부 서버 연결은 하지 않는다. 새로운 의존성이나 저장 구조 변경은 없다. 헌장 점검 결과 기존 미작성 템플릿 외 추가 제약 없음.
