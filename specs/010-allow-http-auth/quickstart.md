# 검증 안내

1. Rust 및 기존 의존성이 준비된 환경에서 cargo test를 실행한다.
2. HTTP 등록, 프로토콜·포트·경로 유지, 기존 인증 가져오기와 삭제, HTTP/HTTPS 분리 테스트 통과를 확인한다.
3. cargo fmt --all -- --check를 실행한다.
4. 앱 인증 설정에서 HTTP 주소로 등록한다. 실제 인증을 지원하는 서버와 도우미가 있다면 해당 저장소의 가져오기를 실행한다.

외부 서버 인증의 성공 여부는 서버 및 인증 제공자의 HTTP 지원에 의존한다.

## 후속 수정 검증 결과: 2026-11-05

- URL에 계정 ID가 있으면 등록 인증을 찾지 못하는 회귀 테스트의 수정 전 실패와 수정 후 성공을 확인했다.
- 인증 프로필 19개, 자격 증명 9개, 원격 진단 6개 테스트가 통과했다.
- cargo check --offline --locked --all-targets 및 cargo fmt --all -- --check가 통과했다.
- 전체 테스트 최초 실행은 기본 임시 폴더 접근 거부로 일부 저장소 테스트가 실패했다. TEMP/TMP를 target/auth-test-tmp로 지정한 재실행에서 라이브러리 66개 통과·1개 무시, 바이너리 167개 통과·1개 실패·1개 무시였다.
- 남은 전체 테스트 실패는 src/shortcut.rs의 dialog_controls_share_bindings_and_contextual_confirmation이다. 인증 수정과 무관한 단축키 정의 검증이므로 이번 범위에서 수정하지 않았다. 바이너리 실패로 이후 통합 테스트는 실행되지 않았다.
- 내부망 서버에는 접속하지 않았으며 실제 실패 주소와 작업 종류도 미확인이다. 이번에 수정한 URL 계정 선택 결함이 사용자 서버 오류의 확정 원인인지는 검증되지 않았다.

## 후속 수렴 점검

추가 요구사항 FR-006~007, 추가 성공 기준 SC-004, 추가 인수 시나리오 4개와 계획의 계정·범위 격리 결정을 코드와 테스트에서 확인했다. 기존 FR-001~005 관련 경로는 유지했다. 헌장은 미작성 템플릿으로 추가 원칙 검사는 생략했다. 이번 수정 범위의 누락·부분 구현·모순·요청 외 구현은 0건이며 추가 구현 작업은 없다.
