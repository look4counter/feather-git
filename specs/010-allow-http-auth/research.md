# 조사 결과

## 결정: 허용 프로토콜 확장

코드에서 HTTPS 제한은 인증 프로필, 로그인 대상, 원격 콜백에 존재한다. HTTP와 HTTPS를 허용하고 요청은 URL의 스킴을 사용한다. HTTPS로 강제 치환하면 서버와 자격 증명 범위가 달라지므로 배제했다.

## 결정: 저장 구조 유지

프로필 URL에 프로토콜이 이미 포함되어 있어 마이그레이션은 필요 없다. 프로토콜을 지우는 정규화는 계정 혼용을 일으키므로 배제했다. 외부 문서나 신규 기술 선택에 대한 미해결 사항은 없다.

## 후속 조사: URL 계정 포함 원격

등록 URL과 달리 Git 원격 URL에는 계정이 포함될 수 있다. 현재 select는 등록용 normalize_url을 원격 URL에 그대로 적용해 ID가 있는 원격을 거부하지만, 설정의 목록 표시 함수는 사용자 정보를 제거하므로 목록과 실제 선택이 불일치한다. 범위 비교 전에 원격 사용자 정보만 분리하고 계정을 별도로 검증하는 방식을 선택했다. 계정을 무시하는 대안은 다른 계정 비밀을 사용할 수 있어 제외했다. 서버 접속 없이 메모리 기반 비밀 저장소 테스트로 재현할 수 있다.
