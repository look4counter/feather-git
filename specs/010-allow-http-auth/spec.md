# 기능 명세: HTTP 인증 주소 지원

**작성일**: 2026-11-04
**상태**: 명세 검증 완료
**사용자 요청**: 현재 HTTPS만 가능한 인증에 HTTP 주소도 허용한다.

## 사용자 시나리오와 검증

### 사용자 이야기 1 — HTTP 서버 인증 (우선순위: P1)

사용자는 HTTP 서비스 또는 Git 저장소 주소로 기존 방식의 인증을 등록하고 원격 작업에 사용한다.
독립 검증: HTTP 등록, 인증 요청, 기존 자격 증명 가져오기, 원격 계정 선택을 확인한다.

1. HTTP 주소를 입력하면 기존 인증 방식으로 등록할 수 있다.
2. HTTP 원격 작업 시 프로토콜·호스트·포트·경로와 계정이 인증 요청에 반영된다.
3. 저장된 HTTP Git 인증이 목록에 표시되고 해당 원격과 연결된다.

### 사용자 이야기 2 — 기존 인증과 입력 검증 유지 (우선순위: P2)

사용자는 HTTPS 인증을 계속 사용하며 프로토콜이 다른 계정은 혼용되지 않는다.
독립 검증: 같은 호스트의 HTTP와 HTTPS 계정을 각각 선택하고 잘못된 주소를 거부한다.

1. 기존 HTTPS 주소는 계속 허용한다.
2. HTTP 계정은 HTTPS 원격에 적용하지 않으며 그 반대도 동일하다.
3. 미지원 프로토콜, 사용자 정보·쿼리·프래그먼트·제어문자를 포함한 등록 주소는 거부한다.

### 경계 조건

- 사용자 지정 포트와 저장소 경로를 보존한다.
- 계정 ID의 줄바꿈으로 인증 요청을 변조할 수 없어야 한다.
- 제공자가 지원하지 않는 로그인 방식의 기존 실패 처리를 유지한다.

## 요구사항

### 기능 요구사항

- **FR-001**: 인증 등록과 로그인 주소 검증에서 HTTP와 HTTPS를 허용한다.
- **FR-002**: 인증 요청은 입력 주소의 프로토콜, 호스트, 포트, 경로와 계정을 사용한다.
- **FR-003**: HTTP 자격 증명의 가져오기, 원격 연계, 계정 선택과 삭제에 기존 인증 흐름을 적용한다.
- **FR-004**: HTTP와 HTTPS 인증 범위를 구분하고 기존 잘못된 입력 차단을 유지한다.
- **FR-005**: 인증 주소 입력 안내와 검증 오류에 HTTP 지원을 반영한다.

### 주요 개체

- 인증 프로필: 프로토콜을 포함한 주소, 계정, 인증 방식, 저장 식별자.
- 인증 요청: 서버 프로토콜, 호스트와 포트, 경로, 선택적 계정.

## 성공 기준

- **SC-001**: HTTP와 HTTPS 각각 등록 및 계정 선택 검증이 모두 통과한다.
- **SC-002**: 프로토콜 혼용과 잘못된 주소 검증에서 잘못된 허용이 0건이다.
- **SC-003**: 기존 인증 회귀 검증이 모두 통과한다.

## 가정

기존 인증 방식을 재사용하며 제공자 자체의 HTTP 지원 여부는 변경하지 않는다. HTTP를 HTTPS로 자동 변환하지 않는다. 인증 범위 변경에 대한 자동 회귀 테스트를 추가한다.

## 명확화 결과

2026-11-04: 사용자 추가 설명으로 HTTPS만 허용되는 제한 해제가 목적임을 확인했다. 기능·데이터·오류·보안·연동 범위를 검토했으며 추가 질문이 필요한 모호성은 없다.

## 후속 수정 명세: 원격 URL의 계정 ID

2026-11-05: 내부망 HTTP 서버에서 ID 등록 후 인증 실패가 보고되었다. 서버 접속 없이 로컬 인증 선택을 검증한다. 실제 실패 작업과 주소 형식은 확인되지 않았으므로 이번 수정이 보고된 실패의 확정 원인이라고 단정하지 않는다.

### 추가 인수 시나리오

1. 등록 주소가 사용자 정보 없는 HTTP 주소이고 원격 URL에 같은 ID가 있으면 해당 등록 인증을 선택한다.
2. 원격 URL에 다른 ID가 있으면 다른 계정의 비밀을 반환하지 않는다.
3. URL의 ID와 콜백의 명시적 ID가 충돌하면 등록 인증을 반환하지 않는다.
4. 기존 등록 주소 검증과 HTTP/HTTPS·포트·경로 격리를 유지한다.

### 추가 요구사항

- **FR-006**: 원격 URL의 계정 ID를 인증 선택에 반영하되 주소 범위 비교에서는 사용자 정보를 분리한다.
- **FR-007**: 명시된 계정과 URL 계정이 다르면 다른 계정의 등록 인증을 선택하지 않는다.

### 추가 성공 기준

- **SC-004**: HTTP/HTTPS 및 URL 계정 유무·계정 불일치 회귀 테스트가 모두 통과한다.

### 후속 명확화 결과

사용자는 대상 서버가 내부망이라 직접 테스트할 수 없다고 설명했다. 로컬에서 확인된 선택 결함 수정으로 범위를 한정하며 서버 자체의 비밀번호 유효성·권한·인증 방식은 미검증으로 남긴다. 추가 구현 결정을 막는 모호함은 없다.
