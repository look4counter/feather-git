# 기능 명세: 패널 탭 버튼과 전환

> 문서 정리일: 2026-11-17. 본문은 이 기능의 단계별 요구사항 이력을 포함한다. 현재 유효 기준과 검증 한계는 [전체 명세 색인](../README.md)을 함께 확인한다. 과거 검증 기록은 현재 버전의 재검증 결과가 아니다.
> 후속 변경 참고: [028](../028-independent-repository-tabs/spec.md) · [080](../080-history-revert-reset/spec.md).

작성일: 2026-11-12
상태: 명세 확정
입력: 패널 안의 탭을 버튼처럼 표시하고 클릭으로 전환한다.

## 사용자 시나리오 및 검증

### 사용자 이야기 1 — 저장소 분류 선택 (우선순위: P1)
사용자는 로컬·원격·태그·스태시 버튼을 눌러 해당 분류를 확인한다.
독립 검증: 각 버튼을 누르면 선택 강조와 목록 제목 및 내용이 일치한다.
수용 시나리오: 최초 로컬 표시, 원격 클릭 시 원격 브랜치 표시, 태그 및 스태시 클릭 시 실제 항목 또는 빈 상태 표시.

### 사용자 이야기 2 — 파일 범위 선택 (우선순위: P1)
사용자는 작업 트리·히스토리 버튼으로 파일 표시 범위를 전환한다.
독립 검증: 작업 트리는 현재 변경 파일, 히스토리는 선택 커밋의 변경 파일을 표시한다.
수용 시나리오: 히스토리 선택 후 커밋을 변경하면 해당 커밋의 파일이 갱신된다. 작업 트리로 돌아오면 기존 목록을 표시한다.

### 경계 조건
빈 저장소와 빈 분류는 빈 상태를 표시한다. 읽기 실패는 오류를 표시한다. 같은 탭을 반복 클릭해도 안정적으로 동작한다. 샘플 저장소의 커밋 파일 데이터는 미제공 안내를 표시한다.

## 요구사항
- FR-001: 여섯 탭은 테두리와 배경 및 여백을 가진 버튼이며 선택·비선택·호버 상태를 구분한다.
- FR-002: 저장소 분류는 한 번에 하나만 선택되고 해당 목록만 표시한다.
- FR-003: 파일 범위는 한 번에 하나만 선택되며 히스토리는 선택 커밋에 대응한다.
- FR-004: 빈 결과와 읽기 오류를 명확히 구분하고 저장소를 변경하지 않는다.
- FR-005: 프로젝트 탭, 커밋 선택, 기존 저장소 열기 동작을 유지한다.

## 주요 개체
분류 선택, 파일 범위 선택, 선택 범위의 파일 목록과 오류 상태.

## 성공 기준
- SC-001: 여섯 버튼 모두 클릭 후 선택 표시와 표시 내용이 일치한다.
- SC-002: 실제 저장소에서 분류·선택 커밋 파일을 자동화 테스트로 검증하고 기존 테스트와 빌드가 통과한다.

## 가정 및 명확화
대상은 프로젝트 탭이 아닌 패널 내부의 기존 여섯 탭이다. 기본 선택은 로컬과 작업 트리이며 선택은 작업 공간 내에서 유지한다. 키보드 탐색 확장은 이번 범위에 포함하지 않는다.
명확화 검토: 기능·데이터·상호작용·오류·의존성·완료 기준에 구현을 차단하는 모호성 없음. 질문 0건.
