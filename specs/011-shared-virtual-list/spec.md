요청: 커밋 기록 목록을 추상화하여 저장소와 변경 파일에서 재사용한다.

## 사용자 시나리오 및 검증

### 사용자 스토리 1 — 많은 항목 탐색 (우선순위: P1)

세 목록에서 필요한 범위만 화면 요소로 생성하여 불필요한 작업을 방지한다.
독립 검증: 10만 개 중 20개 범위를 요청하여 생성 횟수를 검사한다.

1. 저장소를 스크롤하면 원래 순서의 이름과 현재 브랜치 강조가 표시된다.
2. 변경 파일을 스크롤하면 원래 순서의 상태와 경로가 표시된다.

### 사용자 스토리 2 — 기존 기능 유지 (우선순위: P1)

기존 탐색 기능을 유지하면서 탭·프로젝트를 전환하고 커밋을 선택한다.
독립 검증: 기존 패널 전환 및 커밋 캐시 테스트를 실행한다.

1. 탭·프로젝트·커밋 전환 시 현재 데이터가 표시되고 목록 간 스크롤이 간섭하지 않는다.
2. 빈 데이터와 조회 오류는 기존 메시지로 표시된다.
3. 커밋 그래프·선택·가로 스크롤·프로젝트별 세로 스크롤을 유지한다.

### 경계 조건

0개, 1개, 10만 개, 마지막 행, 데이터 감소 후 범위 초과를 처리한다. 긴 파일 경로는 기존처럼 말줄임하고 일정한 행 높이를 유지한다.

## 요구사항

- **FR-001**: 세 목록은 하나의 재사용 가능한 가상화 목록을 사용해야 한다.
- **FR-002**: 필요한 범위의 행만 생성하며 전체 데이터 복제나 전체 행 사전 생성을 피해야 한다.
- **FR-003**: 이름·현재 브랜치 강조·파일 상태·경로·순서와 기존 행 스타일을 유지해야 한다.
- **FR-004**: 기존 탭 전환·빈 상태·오류 메시지·커밋 선택·그래프·스크롤을 유지해야 한다.
- **FR-005**: 목록 식별자를 분리하고 범위 밖 데이터 접근을 방지해야 한다.

### 주요 개체

- 목록: 식별자, 항목 수, 필요한 범위의 행 생성 동작.
- 행: 각 화면이 제공하는 일정 높이의 표시 단위.

## 성공 기준

- **SC-001**: 세 목록이 공통 구현 하나를 사용한다.
- **SC-002**: 10만 개 중 20개 범위를 요청하면 행 생성은 20회이며 빈 범위는 0회이다.
- **SC-003**: 기존 회귀 테스트와 범위·경계 조건 자동 테스트가 통과한다.

## 가정 및 명확화

디자인 변경·새 조작·데이터 조회 변경은 범위 밖이다. 행 높이는 아래 최신 공통 높이 요구사항을 따른다.
기능·데이터·사용 흐름·성능·오류·제약·용어·완료 기준에 중대한 모호성은 없으며 추가 질문은 없다.
성능은 생성 행 수로 검증하며 실제 프레임 속도 개선을 단정하지 않는다.
## 행 선택 확장 명세 (2026-11-13)

### 사용자 스토리 3 — 공통 행 선택 (우선순위: P1)

세 목록에서 행을 클릭하면 하나의 행이 선택되고 다른 행을 클릭하면 선택이 이동한다. 이유는 선택 처리 중복을 제거하고 동일한 조작을 제공하기 위함이다.
독립 검증: 선택 변경·반복 선택·빈 목록·범위 초과 테스트와 패널 갱신 및 커밋 선택 회귀 테스트를 실행한다.

1. 저장소·파일 행을 클릭하면 그 행에 선택 배경이 표시된다. 현재 브랜치 표시는 독립적으로 유지된다.
2. 커밋을 선택하면 기존 상세 내용과 히스토리 파일 갱신이 유지된다.
3. 목록 데이터 갱신 시 저장소·파일 선택은 해제되며 잘못된 인덱스는 선택되지 않는다.

- **FR-006**: 행 클릭 이벤트 연결, 단일 선택 표시와 호버를 공통 목록이 제공해야 한다.
- **FR-007**: 선택 상태는 호출자가 전달하며 도메인 동작은 선택 콜백으로 처리해야 한다. 저장소 선택은 Git 상태를 변경하지 않는다.
- **FR-008**: 선택 범위를 검증하고 데이터 갱신 시 패널 선택을 해제해야 한다. 커밋의 프로젝트·열린 탭 검증을 유지한다.
- **SC-004**: 세 화면에서 개별 행 선택 이벤트 연결과 선택 배경 중복이 없으며 선택·경계·전환 자동 테스트가 통과한다.

명확화 검토: 요청을 기존 가상 목록에 대한 단일 클릭 선택 공통화로 해석한다. 다중 선택·키보드 탐색·파일 상세 기능 추가는 범위 밖이다. 추가 질문은 없다.

## 행 선택 우선순위와 입력 시점 수정 명세

### 사용자 스토리 4 — 즉시 선택 및 선택 표시 유지 (우선순위: P1)

사용자는 왼쪽 마우스 버튼을 누르는 순간 행이 선택되고 포인터가 선택 행 위에 있어도 선택 배경이 유지되기를 원한다.

1. 선택 행에 포인터를 올리거나 벗어나도 선택 배경은 유지된다.
2. 미선택 행에는 기존 호버 배경이 표시된다.
3. 왼쪽 버튼을 누르면 선택되며 버튼을 놓을 때 중복 선택 이벤트가 발생하지 않는다. 오른쪽·가운데 버튼은 선택하지 않는다.

- **FR-009**: 선택 배경은 호버 배경보다 우선해야 한다.
- **FR-010**: 공통 목록은 왼쪽 마우스 버튼 누름 이벤트에서 선택 콜백을 호출하고 클릭 완료 이벤트에서는 호출하지 않아야 한다.
- **SC-005**: 공통 행에 선택 여부에 따른 호버 적용 조건과 왼쪽 버튼 누름 이벤트만 연결되어 있고 기존 전체 자동 테스트가 통과한다.

명확화: 세 목록 모두 동일하게 적용한다. 왼쪽 단일 선택 이외의 조작 변경은 없다. 추가 질문은 없다. 직접 화면 입력의 시각 검증 여부는 별도 기록한다.

## 행 높이 공통 속성 명세

### 사용자 스토리 5 — 공통 목록의 행 높이 (우선순위: P1)

행 높이를 목록 생성 시 한 곳에서 지정하고 행 내용과 선택 영역이 같은 높이를 사용한다. 독립 검증은 세 목록의 높이 설정과 기존 그래프 및 목록 회귀 테스트이다.

1. 커밋 목록은 기존 24픽셀 높이를 유지하고 그래프의 연결점이 행 경계와 일치한다.
2. 저장소·파일 목록도 공통 기본 높이 24픽셀을 사용한다.
3. 행 내용·호버·선택·마우스 누름 영역은 지정된 행 높이에 맞는다.

- **FR-011**: 공통 목록은 공통 기본 행 높이로 일정한 높이의 행을 구성해야 한다. 화면별 행 렌더러는 고정 높이를 중복 지정하지 않아야 한다.
- **FR-012**: 커밋의 기존 24픽셀 높이는 공통 목록의 기본 높이 정의로 추출하고 그래프 계산과 목록에서 동일 정의를 사용해야 한다. 모든 목록은 공통 기본 높이 24픽셀을 사용하고 그래프 모양은 유지해야 한다.
- **SC-006**: 세 목록의 행 높이를 공통 목록에서 적용하고 고정 높이 중복이 없으며 기존 그래프·목록 자동 테스트가 통과한다.

명확화: 기본 행 높이는 현재 커밋 높이 24픽셀이다. 저장소·파일의 개별 높이는 제거하며 사용자 설정 화면은 추가하지 않는다. 추가 질문은 없다.

## 개별 행 높이 제거 명세

최신 요청에 따라 저장소·파일의 36/35픽셀 높이 보존 가정을 폐기한다.
- **FR-013**: 세 목록 호출자는 행 높이를 전달하지 않고 공통 목록의 ROW_HEIGHT=24만 적용해야 한다.
- **SC-007**: 목록 API와 세 호출부에 개별 높이 인자가 없고 기존 자동 테스트가 통과한다.

수용 시나리오: 세 목록 모두 높이 24픽셀로 표시되고 기존 선택·호버·마우스 누름 및 커밋 그래프 동작은 유지된다. 명확화 검토 결과 추가 질문은 없다.
