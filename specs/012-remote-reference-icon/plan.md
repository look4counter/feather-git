# 구현 계획: 커밋 원격 참조 아이콘

## 기술 맥락 및 현재 흐름

Rust 2024, 로컬 GPUI 0.2.2, git2를 사용한다. repository.rs가 참조를 is_remote로 분류하지만 커밋에는 shorthand를 쉼표로 합친 reference 문자열만 저장한다. history.rs가 이를 SharedString으로 캐시하고 ui.rs가 배지 하나로 그린다. 원격 종류 정보가 사라지므로 단순 문자열 치환은 로컬 참조·복수 참조를 오인한다.

## 설계 및 영향 범위

- src/repository.rs: CommitReference(name, label, is_remote)와 Commit.references를 추가한다. 원격 여부는 reference.is_remote()에서 보존한다. 원격 표시 이름은 등록된 원격 이름 중 가장 긴 일치 접두사를 제거하고, 등록 정보가 없는 원격 추적 참조는 첫 경로 구성요소를 제거한다. 기존 reference 문자열과 Project.remotes는 그대로 유지한다.
- src/history.rs: 캐시에 참조별 표시 이름과 원격 여부를 Rc<Vec<PreparedReference>>로 보존한다. 기존 reference만 있는 데이터는 비원격 배지 하나로 폴백한다. 가시 행 캐시와 SharedString 재사용을 유지한다.
- src/ui.rs: 참조마다 배지를 그리며 원격에는 구름 아이콘을 붙인다. 샘플의 새 메타데이터는 빈 기본값으로 호환한다. 배지 색상·폭 제한과 커밋 선택·그래프·목록은 유지한다.

## 헌법 및 제약

헌법은 미작성 템플릿이므로 선언된 원칙 검사는 생략한다. AGENTS.md의 UI·데이터 계층 책임과 최소 변경 원칙을 적용한다. 기존 문자열·원격 목록·Git 데이터는 변경하지 않는다. 새 필드는 내부 실행 파일 모델의 메타데이터이며 외부 API·직렬화 형식은 없다. 새로운 의존성은 없다.

## 조사 및 검증

실제 저장소 테스트로 origin·upstream·슬래시가 있는 원격 별칭·중첩 브랜치·로컬 동명·쉼표·태그·혼합 참조와 원래 문자열을 검증한다. 캐시 테스트로 원격 종류·표시 이름·기존 문자열 폴백과 캐시 재사용을 검증한다. 기존 전체 테스트·cargo check·fmt·clippy 및 별도 경로 실행 파일 빌드를 수행한다. GUI 표시의 직접 확인 여부를 구분해 기록한다.

## 실행 단계

명세·명확화 → 계획 → 작업 목록 → 읽기 전용 일관성 분석 → 선행 테스트·구현·검증 → 수렴. 원격 종류 보존을 먼저 구현하고 캐시와 화면에 연결한다.
