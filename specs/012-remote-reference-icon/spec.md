요청: 커밋 기록에서 origin/ 같은 접두사 대신 원격 아이콘을 표시한다.

## 사용자 시나리오 및 검증

### 사용자 스토리 1 — 원격 참조 구분 (우선순위: P1)

원격 이름을 반복해서 읽지 않고 아이콘으로 원격 참조를 구분한다. 독립 검증은 실제 저장소의 참조 분류와 표시 이름 테스트이다.

1. origin/main과 upstream/main은 각각 원격 아이콘과 main으로 표시된다.
2. 원격 브랜치 feature/login의 슬래시는 유지된다.
3. 로컬 origin/topic 및 태그는 원격 아이콘을 붙이거나 이름을 줄이지 않는다.
4. 같은 커밋의 로컬·원격·태그는 각 참조 종류에 맞게 표시된다.

### 사용자 스토리 2 — 기존 탐색 유지 (우선순위: P1)

커밋 선택·그래프·스크롤·가상화와 저장소 패널은 기존처럼 동작한다. 독립 검증은 기존 전체 회귀 테스트이다.

### 경계 조건

빈 참조, 여러 원격, 로컬 이름에 origin이나 remotes 포함, 슬래시·쉼표가 있는 브랜치 이름을 다룬다. 샘플 데이터 및 기존 문자열만 가진 커밋도 표시할 수 있어야 한다. 원격 추적 참조라는 사실은 서버의 현재 존재 여부와 무관하다.

## 요구사항

- **FR-001**: 커밋 배지의 원격 참조는 원격 이름 접두사 대신 원격 아이콘과 브랜치 이름으로 표시해야 한다.
- **FR-002**: 원격 분류는 Git 참조 종류에 기반하고 origin 이름이나 문자열 포함 여부로 추측하지 않아야 한다.
- **FR-003**: 여러 참조를 개별적으로 표시하고 로컬·태그 이름 및 원격 브랜치 내부 슬래시·쉼표를 보존해야 한다.
- **FR-004**: 기존 참조 문자열과 원격 목록 데이터는 유지하고 샘플·캐시·커밋 선택·그래프·가상화를 회귀시키지 않아야 한다.

### 주요 개체

참조는 원래 이름·표시 이름·원격 여부를 가진다. 커밋은 여러 참조를 가질 수 있다.

## 성공 기준

- **SC-001**: origin·upstream·중첩 브랜치·동명 로컬·태그·혼합 참조 테스트가 통과한다.
- **SC-002**: 기존 전체 회귀 테스트와 빌드·정적 검증이 통과한다.

## 가정 및 명확화

원격 아이콘은 구름 모양을 사용한다. 변경 범위는 커밋 기록 배지이며 원격 서버 접속이나 Git 변경 작업은 없다. 이름을 줄이는 것은 표시만의 변경이다. 기능·데이터·오류·성능·범위 검토 결과 중대한 모호성은 없고 추가 질문은 없다.
