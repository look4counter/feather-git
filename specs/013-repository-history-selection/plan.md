# 구현 계획: 저장소 패널과 커밋 선택 연동

## 기술 맥락 및 기존 구조

Rust 2024, GPUI 0.2.2와 git2. ui.rs의 branches는 panel_tabs 아래 종류 라벨을 추가하며 행 이름에 ACCENT/MUTED를 지정한다. 커밋 본문은 Workspace의 TEXT를 상속한다. 저장소 선택 콜백은 SingleSelection만 갱신한다. select_history_row는 기존 커밋 선택·패널 데이터 갱신을 수행하지만 refresh_panel_data가 저장소 선택도 지운다.
repository.rs는 전체 참조를 커밋으로 peel하여 메타데이터를 수집하지만 snapshot은 로컬·원격 기반 기록을 최대 200개만 읽는다. 태그만 가리키는 커밋이나 오래된 커밋은 없을 수 있다. HistoryState는 프로젝트별 가상화 스크롤 핸들을 가진다.

## 설계 및 영향 범위

- src/ui.rs: 종류 라벨과 불필요해진 title 함수를 제거한다. 본문색은 TEXT로 통일하고 현재 배지는 유지한다. RepositoryTab에서 전체 참조 경로를 만든다. select_repository_row가 프로젝트·탭·시작 화면·열린 프로젝트·인덱스를 검증하고 기존 메타데이터에서 대상 인덱스를 찾는다. 없는 대상은 데이터 계층으로 조회·확장한다. 기존 select_history_row로 상세를 갱신한 뒤 저장소 선택을 다시 적용하고 scroll_to_item(Center)을 요청한다. 스태시는 저장소 선택만 한다. 오류는 notice에 표시하고 커밋은 유지한다.
- src/repository.rs: CommitReference에 full_name을 추가하여 동명 참조를 구별한다. 기존 snapshot을 내부 목표 커밋 선택형 함수로 분리하며 기본 200개 제한은 유지한다. reference_snapshot은 전체 참조를 정확히 찾아 최종 커밋으로 peel하고, 대상이 포함될 때까지 기록을 확장한다. 대상도 revwalk 시작점에 추가하여 태그 전용 이력도 처리한다. 태그 전체를 시작점으로 넣지 않아 비커밋 태그로 기본 조회가 실패하지 않게 한다. 기존 문자열·아이콘·원격 목록은 유지한다.
- src/history.rs: 테스트용 참조 메타데이터 생성에 full_name을 추가한다. 기존 캐시 구현은 유지한다.

## 헌법 및 제약

헌법은 미작성 템플릿이므로 선언된 원칙 검사를 생략한다. UI와 데이터 접근 책임을 분리하고 기존 내부 필드·외부 형식을 유지한다. 새 의존성·checkout·Git 쓰기 작업은 없다. 확장 시 해당 프로젝트의 그래프 캐시만 다시 만든다. 같은 이름의 다른 참조로 이동하지 않는다.

## 검증

실제 저장소 테스트로 로컬·원격·경량 태그·주석 태그, 동명 참조, 초기 200개 밖 대상과 태그 전용 이력, 삭제·비커밋 태그 오류를 확인한다. Workspace 테스트로 참조 선택→커밋 및 스크롤 요청, 저장소 선택 강조 복원, 상세 파일 갱신, 반복 선택, 스태시 제외·오래된 이벤트를 확인한다. 기존 전체 테스트·cargo check/fmt/clippy 및 별도 경로 실행 파일 빌드를 수행한다. GUI 시각 검증 여부는 별도 기록한다.

## 단계 및 실행 순서

명세·명확화 → 계획 → 작업 목록 → 읽기 전용 일관성 분석 → 선행 테스트·구현 → 전체 검증 → 수렴. 데이터 범위 해결을 먼저 구현하고 UI 연동 및 표시를 변경한다.
