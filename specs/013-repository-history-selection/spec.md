작성일: 2026-11-13. 상태: 명세 검증 완료.
요청: 탭과 목록 사이 라벨 제거, 목록 글자색을 커밋 기록과 통일, 로컬·원격·태그 선택 시 대상 커밋 선택.

## 사용자 시나리오 및 검증

### 사용자 스토리 1 — 패널 표시 간소화 (우선순위: P1)

탭 아래의 중복 종류 라벨 없이 목록을 보고 커밋 기록과 같은 본문 글자색으로 읽는다.
수용 기준: 중간 라벨 영역은 없고 목록 이름·아이콘의 본문색은 커밋 메시지와 같다. 현재 브랜치 배지는 유지하며 빈 목록·오류 메시지도 유지한다.
독립 검증: 패널 렌더링 소스와 색상 상수를 검토한다.

### 사용자 스토리 2 — 참조 대상 커밋 탐색 (우선순위: P1)

로컬·원격·태그 행을 선택하면 참조가 가리키는 커밋이 선택되고 화면에 보인다.

1. 로컬·원격·태그 각각에서 해당 커밋이 선택되고 상세·히스토리 파일도 갱신된다.
2. 같은 이름의 로컬·태그, 여러 원격도 정확한 참조 종류에 따라 이동한다.
3. 화면 밖·현재 로드 범위 밖의 대상도 선택되고 화면에 보인다.
4. 저장소의 선택 행 강조가 유지되며 현재 브랜치나 작업 트리에는 변경이 없다.

독립 검증: 실제 저장소의 참조 해석·범위 확장과 Workspace의 선택·스크롤 요청 테스트.

### 경계 및 오류

빈 목록·잘못된 인덱스·다른 프로젝트나 탭의 오래된 이벤트는 안전하게 무시한다. 삭제된 참조·커밋을 가리키지 않는 태그·조회 실패·샘플에서 대상이 없는 참조는 현재 커밋을 유지하고 상태 표시줄로 원인을 알린다. 경량 태그와 주석 태그를 모두 처리한다. 스태시는 기존 행 선택만 유지한다.

## 요구사항

- **FR-001**: 탭 아래 종류 라벨 영역을 제거하고 저장소 행 본문색을 커밋 메시지색과 동일하게 해야 한다.
- **FR-002**: 로컬·원격·태그 행의 단일 선택은 정확한 참조 대상 커밋을 선택하고 기존 상세 갱신을 수행해야 한다.
- **FR-003**: 화면 밖 대상에는 스크롤을 요청하고 로드 범위 밖 대상도 기록을 확장하여 선택해야 한다.
- **FR-004**: 선택한 저장소 행 강조·현재 브랜치 배지·공통 행 선택·원격 아이콘·그래프 동작을 유지하며 checkout 등 Git 변경은 없어야 한다.
- **FR-005**: 참조 종류·프로젝트·탭·인덱스를 검증하고 오류 시 기존 커밋을 유지하며 원인을 표시해야 한다. 스태시는 연동하지 않는다.

### 주요 개체

전체 참조 경로는 로컬 refs/heads, 원격 refs/remotes, 태그 refs/tags로 구분한다. 대상 커밋은 참조를 최종 커밋으로 해석한 결과다. 확장 기록은 대상까지 포함하는 현재 프로젝트의 커밋 목록이다.

## 성공 기준

- **SC-001**: 중간 라벨이 없고 저장소 행 본문색이 커밋과 동일하다.
- **SC-002**: 참조별 선택·주석 태그·동명 참조·200개 밖 대상·오류·스태시 제외 자동 테스트가 통과한다.
- **SC-003**: 기존 전체 테스트·타입·포맷·정적 검사·빌드가 통과한다.

## 명확화 및 가정

행 선택은 탐색이며 브랜치 전환이나 태그 변경이 아니다. 커밋이 화면에 보이도록 세로 스크롤한다. 글자색 통일은 본문에 적용하며 현재 브랜치 배지의 의미 색은 유지한다. 추가 질문은 없다.
