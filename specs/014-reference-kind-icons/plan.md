# 구현 계획: 참조 종류별 아이콘

## 현재 구조 및 영향

Rust 2024, GPUI 0.2.2. CommitReference에는 full_name과 is_remote가 있으나 PreparedReference는 원격 여부만 캐시하므로 로컬·태그를 구별할 수 없다. ui.rs는 커밋 원격에만 구름을 붙이며 저장소 행은 모든 탭에서 같은 브랜치 기호를 쓴다.

## 설계

- src/repository.rs: ReferenceKind(Local, Remote, Tag, Other)를 추가하고 CommitReference.kind()가 full_name의 정확한 네임스페이스로 판단한다. 기존 필드·조회 방식은 유지한다.
- src/history.rs: PreparedReference에 종류를 전달한다. 기존 is_remote는 kind로 대체하고 캐시 공유 구조는 유지한다. 문자열만 있는 폴백은 Other이다.
- src/ui.rs: reference_icon 함수에 종류별 기호를 모아 커밋 배지와 패널이 재사용한다. RepositoryTab의 로컬·원격·태그를 매핑하며 스태시는 기존 기호를 유지한다. 샘플의 알려진 main·태그를 명시적 메타데이터로 제공한다.

## 제약 및 검증

기존 참조·표시 이름·선택·가상화·그래프를 바꾸지 않고 새 의존성을 추가하지 않는다. 데이터 계층은 종류만 제공하며 아이콘은 UI가 소유한다. 헌법은 미작성 템플릿이므로 선언된 원칙 검사를 생략하고 AGENTS.md의 계층·호환성·최소 변경 제약을 적용한다.
종류 분류·오인 유발 이름·캐시·아이콘 구분·샘플 메타데이터 테스트를 먼저 추가하고 구현한다. 전체 테스트와 cargo check/fmt/clippy, 별도 출력 실행 파일 빌드를 수행하며 직접 GUI 확인 여부는 별도 기록한다.

원격 종류는 기존 Git is_remote() 분류 메타데이터를 재사용하고, 로컬·태그는 full_name의 refs/heads/·refs/tags/ 경로로 구별한다. 원래 메타데이터를 중복·폐기하지 않으며 이름 모양으로 추측하지 않는다.

## 브랜치 아이콘 형태 개선 계획

실제 구현은 reference_icon이 로컬에 가는 유니코드 글리프를 반환하고 커밋 배지는 아이콘·이름을 한 문자열로 합친다. 글자 굵기만 바꾸면 글꼴에 따라 형태와 두께가 달라진다.
src/ui.rs에 작은 코드 기반 벡터 브랜치 아이콘을 만들고 굵은 연결선·채워진 원형 노드를 사용한다. 기존 GPUI Div의 둥근 사각형·원형 요소로 렌더링하며 새 파일·이미지·의존성은 없다. 아이콘 매핑은 Branch 또는 Glyph로 구분하고 공통 아이콘 뷰를 배지와 패널이 사용한다. 배지는 아이콘과 이름을 나누어 이름만 말줄임하고 원격·태그의 기존 기호는 유지한다. 현재 스타일·색상·행 높이·선택은 바꾸지 않는다.
기존 종류·아이콘 대응 테스트를 표현 타입에 맞게 갱신하고 전체 테스트·타입·포맷·Clippy 및 별도 경로 빌드를 수행한다. 단순 도형 스타일을 복제하는 새 테스트는 추가하지 않는다. GUI 확인 여부는 별도 기록한다. 기존 계층·호환성·최소 변경 제약과 충돌하지 않는다.

## 최신 계획: 로컬 컴퓨터 아이콘

현재 src/ui.rs는 ReferenceIcon::Branch와 branch_icon의 둥근 선·노드를 공통 뷰로 표시한다. 이 부분만 ReferenceIcon::Computer와 computer_icon으로 바꾸고 16픽셀 영역에 컴퓨터 화면·받침대·발판을 그린다. 기존 두 호출부는 공통 뷰를 계속 사용한다. 원격·태그·색상·크기·선택 로직은 변경하지 않는다. 소스 변경은 src/ui.rs 한 파일이다.
앞선 브랜치 형태 결정은 폐기한다. 기존 아이콘 대응 테스트를 컴퓨터 타입으로 갱신하고 전체 테스트·타입·포맷·Clippy·별도 경로 빌드를 수행한다. 새 의존성이나 데이터 구조 변경은 없다. 헌법은 미작성 템플릿이며 AGENTS.md 제약과 충돌하지 않는다.
