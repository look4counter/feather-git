## 사용자 시나리오 및 검증

### 사용자 스토리 1 — 참조 종류별 아이콘 (우선순위: P1)

사용자는 로컬·원격·태그를 각각 브랜치·구름·태그 아이콘으로 구분한다. 커밋 배지와 저장소 패널에서 동일한 종류에 같은 아이콘을 사용한다.

1. 로컬 main은 브랜치 아이콘과 main으로 표시된다.
2. 원격 origin/main은 기존처럼 구름 아이콘과 main으로 표시된다.
3. 태그 v1.0은 태그 아이콘과 v1.0으로 표시된다.
4. 이름이 같거나 이름에 origin·tags가 포함되어도 실제 참조 종류에 맞는 아이콘을 사용한다.

독립 검증: 참조 경로 분류·캐시 전달·아이콘 대응 자동 테스트.

### 사용자 스토리 2 — 기존 동작 보존 (우선순위: P1)

선택·스크롤·원격 이름 축약·본문색·현재 배지·가상화·그래프·기존 문자열 폴백을 유지한다. 샘플의 알려진 로컬·태그에도 아이콘을 표시한다. 스태시에는 새 참조 아이콘을 강제하지 않는다.
독립 검증: 전체 기존 회귀 테스트 및 샘플 메타데이터 검증.

## 요구사항

- **FR-001**: 로컬·원격·태그에 서로 다른 아이콘을 커밋 배지와 저장소 패널에서 동일하게 적용해야 한다.
- **FR-002**: 실제 전체 참조 경로로 종류를 판단하고 이름 문자열로 추측하지 않아야 한다.
- **FR-003**: 기존 이름·원격 접두사 축약·선택 연동·공통 목록 동작을 유지해야 한다.
- **FR-004**: 샘플에 명시적 종류 정보를 제공하고 종류를 모르는 기존 문자열은 아이콘 없이 보존해야 한다.

## 성공 기준

- **SC-001**: 세 종류·미상 참조·동명·오인 유발 이름·샘플·캐시 및 아이콘 대응 자동 테스트가 통과한다.
- **SC-002**: 기존 전체 테스트·타입·포맷·Clippy·빌드가 통과한다.

## 경계 및 명확화

빈 참조는 표시하지 않고 미상 참조는 아이콘을 붙이지 않는다. 스태시의 기존 표시는 유지한다. 아이콘은 기존 텍스트 UI에 맞춰 브랜치·구름·태그 기호를 사용한다. 추가 질문은 없다.

## 브랜치 아이콘 형태 개선

로컬 브랜치 아이콘을 가는 글리프 대신 굵은 연결선과 둥글고 채워진 노드로 표시한다. 커밋 배지와 저장소 목록에 동일하게 적용하며 원격·태그와 이름·색상·선택 동작은 유지한다.
- **FR-005**: 로컬 브랜치 아이콘은 굵은 선과 채워진 원형 노드로 구성하고 두 화면이 같은 렌더러를 사용해야 한다.
- **SC-003**: 두 화면의 로컬 아이콘이 공통 벡터 렌더러를 사용하고 기존 전체 자동 검증이 통과한다.
명확화: 기존 아이콘의 의미와 소형 크기를 유지하면서 시각적 두께만 강화한다. 추가 질문은 없다.

## 로컬 아이콘을 컴퓨터 모양으로 변경

최신 요청에 따라 앞선 로컬 브랜치 형태 결정을 컴퓨터 모양으로 대체한다.
- **FR-006**: 로컬은 컴퓨터 화면·받침대 형태의 아이콘을 사용하고 커밋 배지와 저장소 목록에 동일하게 적용해야 한다. 기존 FR-005의 브랜치 형태 조건은 이 요구사항으로 대체한다.
- **SC-004**: 두 화면이 공통 컴퓨터 아이콘을 사용하고 기존 전체 검증이 통과한다.
명확화: 기존 크기·색상·원격·태그·선택 동작을 유지한다. 추가 질문은 없다.
