# 기능 명세: 커밋 그리드 정렬 및 컬럼 크기 조절

> 현재 기준: 그래프 열은 레인 수와 무관하게 초기 92px·최소 0이다. 실제 그림의 레인 간격은 18px이고 넘친 영역은 셀에서 자른다.

작성일: 2026-11-13. 상태: 명세 검증 완료.

## 사용자 시나리오 및 검증

### 사용자 스토리 1 — 왼쪽 정렬 및 헤더 구분 (우선순위: P1)

그래프를 커밋 그리드의 왼쪽에 맞추고 헤더 사이 세로 구분선으로 컬럼 경계를 구분한다.

1. 그래프 앞의 불필요한 행 여백이 없고 첫 레인은 노드가 잘리지 않는 최소 여백에 배치된다.
2. 그래프·메시지·작성자·날짜·해시 헤더 경계가 본문 컬럼과 일치한다.

독립 검증: 공유 컬럼 배치와 그래프 왼쪽 좌표 및 기존 그래프 테스트.

### 사용자 스토리 2 — 컬럼 너비 조절 (우선순위: P1)

사용자는 헤더 구분선을 왼쪽 버튼으로 드래그하여 각 컬럼의 너비를 바꾸고 본문 변화를 즉시 확인한다.

1. 다섯 컬럼 각각 오른쪽 경계를 드래그하면 헤더와 본문이 함께 변경된다.
2. 버튼을 놓으면 조절이 끝나고, 헤더 밖으로 움직여도 같은 드래그가 이어진다.
3. 너비 합이 화면보다 크면 기존 가로 스크롤로 탐색한다.
4. 같은 작업 공간에서 프로젝트·탭 전환 후에도 설정한 너비가 유지된다.

독립 검증: 너비·최소값·드래그 시작/이동/종료·프로젝트 전환 자동 테스트.

## 요구사항

- **FR-001**: 그래프는 첫 컬럼의 왼쪽에 정렬되고 불필요한 행 바깥 여백을 제거해야 한다. 노드와 레인 간격은 유지해야 한다.
- **FR-002**: 헤더 사이에 눈에 보이는 세로 구분선과 너비 조절 커서를 제공해야 한다.
- **FR-003**: 모든 컬럼의 너비를 왼쪽 버튼 드래그로 조절하고 헤더·가시 행·가로 스크롤 폭에 동일하게 적용해야 한다.
- **FR-004**: 컬럼 최소 너비를 적용하고 그래프는 모든 레인이 들어갈 너비 이하로 줄이지 않아야 한다. 잘못된 입력은 무시해야 한다.
- **FR-005**: 너비는 작업 공간 세션에서 유지하며 드래그 중 프로젝트·화면 전환 또는 버튼 해제 시 조절을 종료해야 한다.
- **FR-006**: 기존 가상화·행 높이·선택·아이콘·참조 이동·그래프·상세 동작을 유지해야 한다.

## 성공 기준

- **SC-001**: 헤더와 본문이 같은 컬럼 너비 모델을 사용하고 그래프 앞 추가 여백이 없다.
- **SC-002**: 다섯 컬럼 조절·최소값·다수 레인·비정상 입력·드래그 종료·전환·너비 유지 테스트가 통과한다.
- **SC-003**: 기존 전체 테스트·타입·포맷·Clippy·실행 파일 빌드가 통과한다.

## 경계 및 명확화

빈 커밋 목록, 매우 좁거나 넓은 컬럼, 긴 텍스트, 여러 그래프 레인, 버튼을 헤더 밖에서 놓기, 드래그 중 프로젝트 변경을 다룬다. 그래프 레인 간격·현재 노드 모양은 변경하지 않는다. 자동 저장·프로그램 재시작 후 복원·컬럼 재정렬·정렬 기능은 범위 밖이다. 추가 질문은 없다.

## 메시지 컬럼 자동 확장 명세

최신 요청에 따라 메시지 컬럼은 초기 상태에서 flex: 1로 남는 공간을 채우고 직접 조절한 뒤 고정 폭으로 전환한다.
- **FR-007**: 초기 상태에서 헤더와 본문의 메시지 컬럼은 동일하게 flex: 1을 사용하여 그리드가 사용 가능한 폭의 100%를 채우게 해야 한다. 다른 컬럼은 조절된 고정 너비를 유지한다.
- **SC-004**: 메시지 헤더·본문에 동일한 유연 너비와 최소 너비가 적용되고 기존 전체 검증이 통과한다.
메시지의 기존 조절값은 최소 너비로 사용한다. 최소 너비 합이 화면보다 클 때만 가로 스크롤하며 넓은 화면의 남는 여백은 메시지가 채운다. 별도 너비 저장이나 조작은 추가하지 않는다. 추가 질문은 없다.

## 메시지 초기 자동 확장 및 수동 너비 전환

이 절은 앞선 항상 자동 확장·조절값을 최소 너비로만 사용하는 결정을 대체한다.
- **FR-008**: 메시지는 초기에는 flex: 1이며, 사용자가 해당 컬럼을 드래그하면 실제 표시 너비에서 시작하여 고정 픽셀 너비로 전환해야 한다. 헤더·본문에 같은 상태를 적용해야 한다.
- **SC-005**: 초기 자동 확장·드래그 후 고정·시작 표시 너비 기준 이동·클릭만 할 때 자동 상태 유지·전환 후 너비 유지 테스트가 통과한다.
다른 컬럼 조절은 메시지의 초기 자동 상태를 해제하지 않는다. 메시지를 직접 조절한 이후에는 너비를 유지하고 기존 최소값·가로 스크롤도 유지한다. 추가 질문은 없다.

## 최신 명세: 전체 폭을 보존하는 경계 이동

사용자 확인에 따라 앞선 단일 컬럼 확대·메시지 고정 전환 결정을 대체한다.
- **FR-009**: 핸들은 네 내부 경계에만 존재하고, 드래그 시 경계 양쪽 컬럼을 같은 양만큼 반대로 조절하여 전체 표시 폭과 나머지 컬럼 너비를 보존해야 한다.
- **FR-010**: 초기 메시지는 남는 폭을 채우고 조절 후에도 전체 그리드의 사용 가능 폭 100%를 유지해야 한다. 단순 드래그 때문에 전체 폭이 늘거나 가로 스크롤이 추가되면 안 된다.
- **SC-006**: 네 경계의 좌우 너비 합·전체 합·다른 컬럼 불변, 양쪽 최소값, 반복 이동·화면 전환·측정 너비 기준 테스트가 통과한다.
기존 최소 너비 합이 창보다 큰 경우에만 잘림 방지용 가로 스크롤을 유지한다. 최소값 때문에 더 줄일 수 없는 경계는 이동을 제한한다. 메시지 고정 여부 상태는 제거하며 현재 표시 너비를 기준으로 두 컬럼을 조절한다. 추가 질문은 없다.

## 그래프 초기 너비: 5개 레인

- **FR-011**: 그래프 컬럼의 초기 너비는 기존 그래프 간격·여백 기준으로 5개 레인이 들어갈 크기여야 한다. 실제 레인 수가 더 많으면 기존 최소 너비 보정을 유지한다. 사용자 경계 조절 동작은 유지한다.
- **SC-007**: 기본 그래프 너비가 graph_width(5)와 일치하고 레인 수·사용자 조절·전체 폭 보존 회귀 테스트가 통과한다.
명확화: 초기 너비만 변경한다. 레인 간격·노드 크기는 변경하지 않으며 5개보다 좁은 사용자 조절을 금지하지 않는다. 추가 질문은 없다.

## 목록 바깥 좌우 여백 제거

- **FR-012**: 저장소·변경 파일 목록 컨테이너의 좌우 바깥 여백을 제거하여 목록과 선택 배경이 패널 폭을 채우게 해야 한다. 행 내부 아이콘·텍스트 간격, 제목·탭 여백은 유지한다.
- **SC-008**: 두 목록 컨테이너에 좌우 패딩이 없고 기존 전체 검증이 통과한다.
명확화: 목록 둘레의 여백 제거로 해석하며 행 내부 가독성 간격은 유지한다. 추가 질문은 없다.
