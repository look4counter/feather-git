## 구현 및 추적성

- FR-001: src/ui.rs의 커밋 행에서 바깥 px_5와 컬럼 사이 gap을 제거했다. 그래프는 첫 셀의 시작점에서 기존 10픽셀 노드 안전 여백을 사용한다. src/history_graph.rs의 기존 레인 간격·그리기·DPI 처리는 유지하며 레인 수가 늘어도 첫 레인 x가 10이고 컬럼 중심으로 이동하지 않는지 검증했다.
- FR-002: 헤더의 오른쪽 경계에 1픽셀 구분선과 8픽셀 너비 핸들·ResizeLeftRight 커서를 제공한다. 그래프·메시지·작성자·날짜·해시 모두 같은 방식이다.
- FR-003: src/history_grid.rs의 HistoryColumns가 다섯 너비를 제공한다. 헤더·본문이 같은 배열을 사용하고 가로 스크롤 최소 폭도 같은 너비 합을 사용한다. 드래그 시작 너비와 시작 x 대비 이동량으로 실시간 갱신한다.
- FR-004: 최소값은 그래프 45(실제 레인에 필요한 graph_width 이상)·메시지 160·작성자 60·날짜 96·해시 64픽셀이다. 잘못된 인덱스·비유한 수치·계산 오버플로를 무시한다.
- FR-005: 너비는 Workspace 세션 상태에 보관한다. 루트 이동 및 내부·외부 마우스 해제 이벤트로 조절을 마치며 프로젝트·시작 탭·닫기·저장소 전환 시 드래그 상태만 해제한다. 너비는 유지한다.
- FR-006: 기존 공통 목록·24픽셀 행 높이·아이콘·참조 선택·스크롤 핸들·가시 행 및 그래프 캐시를 유지한다. 텍스트는 셀 내부 여백과 말줄임을 사용하여 다른 컬럼을 침범하지 않게 한다.

## 최신 검증: 100% 폭 보존 경계 이동

FR-009·FR-010 및 SC-006에 맞춰 이전 단일 컬럼 확대·메시지 고정 전환 요구를 대체했다. 명확화와 품질 점검, 일관성 분석을 수행하여 최신 수용 기준과 작업 사이 누락·모순이 없음을 확인했다.

- src/history_grid.rs: resize_boundary는 드래그 시작 시 표시된 다섯 너비를 받아 경계 양쪽에 같은 이동량을 반대로 적용한다. 나머지 세 컬럼과 전체 합을 유지한다. 이동량은 양쪽 최소값으로 제한하며 비정상 입력은 무시한다. message_fixed와 단일 컬럼 resize API를 제거했다.
- src/ui.rs: 헤더 전체 너비를 하나의 Rc<Cell<[f32; 5]>>에 측정하여 시작 상태로 사용한다. 핸들은 네 내부 경계에만 존재한다. 메시지는 남는 폭을 채우되 인접 고정 컬럼이 반대로 조절되므로 메시지 경계도 실제로 이동한다. 최소 전체 폭에 메시지의 현재 폭 대신 최소값만 넣어 단순 드래그가 가로 스크롤을 새로 만들지 않게 했다.
- 컬럼 최소값 합이 창보다 큰 경우에만 기존 가로 스크롤을 유지한다. 기존 헤더·본문 동기화·선택·행 높이·그래프·프로젝트 전환은 유지한다.
