# 구현 계획: 히스토리 고정 커밋 상세 행

> 정리 안내: 단계별 설계·작업 기록이며 후속 변경은 [현재 명세 색인](../README.md)과 해당 기능의 spec.md를 따른다. 기존 체크 상태와 과거 검증 이력은 현재 재검증 완료를 의미하지 않는다.

## 참조 및 현재 구조 분석

기존 D:/Projects/feather-git-old/src/ui.rs의 files_panel은 탭 다음에 commit-detail 행을 flex_shrink_0으로 배치하고 그 아래에 파일 가상 목록을 둔다. History 진입 시 show_commit_detail=true이며 행 선택은 파일 선택을 해제한다. 참조 프로젝트는 읽기만 했다.
현재 src/ui.rs의 files에는 탭과 가상 목록만 있다. 오른쪽 detail은 이미 선택 커밋의 상세를 표시한다. refresh_panel_data는 파일 선택을 해제하므로 별도 중복 상태 없이 히스토리에서 파일 선택이 없을 때 상세 행이 선택된 것으로 표현할 수 있다.

## 설계 및 영향 범위

- src/virtual_list.rs: 기존 가상 행의 생성 코드를 selectable_row로 추출하여 고정 행에서도 공통 높이 24·선택 배경 우선·미선택 호버·왼쪽 누름을 재사용한다. virtual_list는 동일 함수로 기존 행을 생성한다.
- src/ui.rs: commit_detail_selected와 select_commit_detail에서 표시·선택 및 프로젝트·탭·열린 프로젝트 가드를 처리한다. files의 panel_tabs 뒤, 목록 컨테이너 앞에 히스토리일 때만 고정 행을 둔다. 원본과 같은 커밋 노드 아이콘을 코드 기반 도형으로 제공하고 하단 구분선을 둔다. 파일 개수에 고정 행은 포함하지 않는다. 작업 트리에는 추가하지 않는다.
파일 행 선택은 기존 SingleSelection을 사용하고 상세 행 선택은 이를 지운다. 탭 진입·커밋 변경 시 기존 갱신 흐름이 선택을 지워 상세 기본 선택을 만든다. 기존 detail 뷰는 이미 현재 커밋을 표시하므로 새 viewer·diff·데이터 조회를 추가하지 않는다.

## 제약 및 검증

Rust 2024와 기존 GPUI만 사용한다. 새 의존성·도메인 변경·참조 프로젝트 수정은 없다. 데이터 계층 및 공통 가상화 범위는 그대로다. 헌법은 미작성 템플릿이므로 선언된 원칙 검사를 생략하고 AGENTS.md의 기존 책임·호환성·최소 변경 제약을 적용한다.
Workspace의 기본 선택·상호 배타·탭/커밋 전환·빈 값/오류·이벤트 가드 테스트를 먼저 추가한다. 공통 행 추출 후 전체 테스트·타입·포맷·Clippy·빌드를 실행한다. 직접 GUI 스크롤 고정 및 시각 확인 여부는 구분해 기록한다.

## 커밋 행 선택 연동 추가 분석 및 계획

현재 src/ui.rs의 select_history_row는 이벤트 유효성을 확인한 후 commit 인덱스 설정과 refresh_panel_data만 수행한다. refresh_panel_data는 파일 선택을 지우므로 file_history가 true이면 이미 커밋상세 선택이 된다. file_history가 false이면 작업 트리를 유지하는 것이 이번 누락의 원인이다. viewer_target은 히스토리에서 파일 선택이 없으면 선택 커밋의 실제 Detail 대상을 반환한다.
select_repository_row도 select_history_row를 호출하므로 단순히 플래그를 바꾸면 브랜치·태그 클릭의 패널 동작까지 달라진다. 공통 커밋 선택 처리에서 유효성 검사·조회·선택 해제를 공유하되 호출자가 히스토리 전환 여부를 전달하게 한다. 커밋 기록 행만 전환을 요청하고 참조 선택은 기존 탭을 유지한다. 변경은 src/ui.rs로 한정하며 새 상태·뷰어·의존성·데이터 API를 추가하지 않는다.

실제 임시 저장소의 작업 트리 파일 선택에서 커밋 기록을 선택하는 재현 테스트를 먼저 작성한다. 성공 시 히스토리·커밋상세 선택·Detail의 커밋 ID를 확인하고 같은/다른 행 재선택 및 무효 이벤트 무변경을 확인한다. 조회 오류·빈 목록과 참조 선택의 기존 동작도 검증한다. 전체 테스트·형식·정적 검사·Clippy·빌드를 수행한다. 화면 직접 조작 여부는 구분해 기록한다. 헌장은 미작성 템플릿이며 기존 책임·호환성 제약을 유지한다.
