## 사용자 시나리오 및 검증

### 사용자 스토리 1 — 고정 커밋 상세 행 (우선순위: P1)

변경 파일의 히스토리 탭에서 파일 목록 위에 커밋상세 행을 항상 보고 선택할 수 있다.

1. 히스토리에 들어가면 탭 아래·파일 목록 위에 아이콘과 커밋상세 행이 표시되고 기본 선택된다.
2. 파일 목록을 스크롤해도 해당 행은 같은 위치에 남는다.
3. 파일을 선택하면 상세 행 강조가 해제되고, 상세 행을 선택하면 파일 선택이 해제된다.
4. 작업 트리 탭에서는 해당 행이 표시되지 않는다.

독립 검증: 표시 조건·기본 상태·상호 배타 선택 및 탭 전환 자동 테스트와 스크롤 영역 외부 배치 검토.

### 사용자 스토리 2 — 기존 동작 유지 (우선순위: P1)

커밋·프로젝트를 바꾸면 현재 커밋 기준으로 상세 행을 표시하고 기존 상세 화면을 사용한다. 파일 0개·조회 오류에서도 고정 행이 남고 기존 메시지는 아래에서 표시된다. 기존 공통 가상 목록·행 선택·원격/로컬/태그 아이콘·커밋 탐색은 유지한다.
독립 검증: 기존 전체 회귀 테스트와 오류·빈 상태·이벤트 가드 테스트.

### 사용자 스토리 3 — 커밋 기록 선택과 상세 연결 (우선순위: P1)

커밋 기록에서 유효한 행을 선택하면 변경 파일 패널의 히스토리 탭으로 전환되고 그 커밋의 커밋상세 행이 선택된다.

1. 작업 트리에서 파일을 선택한 상태로 커밋 행을 선택하면 히스토리로 전환되고 파일 선택이 해제되며 해당 커밋상세가 표시된다.
2. 히스토리 파일을 선택한 상태에서 같은 커밋 또는 다른 커밋 행을 선택해도 커밋상세가 선택된다.
3. 오래된 프로젝트·닫힌 탭·시작 화면·범위를 벗어난 행 선택은 커밋·패널·파일 선택 상태를 바꾸지 않는다.
4. 선택한 커밋의 파일이 없거나 조회에 실패해도 히스토리의 커밋상세 선택을 유지한다.

독립 검증: 실제 임시 저장소를 사용해 작업 트리에서의 전환, 뷰어 대상 커밋 일치, 반복 선택, 잘못된 이벤트 무변경 및 기존 참조 선택 동작 보존을 자동 검증한다.

## 요구사항

- **FR-001**: 히스토리 탭 아래의 파일 스크롤 영역 밖에 아이콘과 커밋상세 선택 행을 고정 배치해야 한다.
- **FR-002**: 공통 24픽셀 높이·선택 우선 호버·왼쪽 마우스 누름 선택을 재사용하고 가로 폭을 채워야 한다.
- **FR-003**: 히스토리 진입·커밋 변경 시 상세 행을 기본 선택하고 파일 선택과 상호 배타적으로 동작해야 한다.
- **FR-004**: 작업 트리에는 행을 표시하지 않고, 빈 파일·조회 오류에서도 히스토리의 행을 유지해야 한다. 오래된 프로젝트·탭 이벤트는 무시해야 한다.
- **FR-005**: 기존 커밋 상세 화면과 데이터·선택·가상화 동작을 유지하고 참조 프로젝트는 수정하지 않아야 한다.

- **FR-006**: 커밋 기록 행의 유효한 선택은 변경 파일 패널을 히스토리로 전환하고 선택한 커밋의 상세 행을 선택해야 한다. 기존 파일 선택은 해제하고 브랜치·태그 선택의 탭 동작은 유지한다.

## 성공 기준

- **SC-001**: 고정 행이 목록 가상화·스크롤 밖에 있고 조건·선택·전환·오류 자동 테스트가 통과한다.
- **SC-002**: 기존 전체 테스트·타입·포맷·Clippy·빌드가 통과한다.

- **SC-003**: 작업 트리·히스토리 파일 선택에서 커밋 행 선택 시 해당 커밋상세로 전환되고 잘못된 이벤트는 상태를 바꾸지 않는 회귀 검증이 통과한다.

## 경계 및 명확화

고정 대상은 실제 상세 텍스트가 아닌 참조 프로젝트와 같은 커밋상세 선택 행이다. 오른쪽 기존 커밋 상세 뷰를 재사용하며 파일 diff 등 새 기능은 추가하지 않는다. 커밋이 없는 경우 기존 상세 빈 상태를 유지한다. 추가 질문은 없다.

2026-11-14 명확화: 전환 대상은 변경 파일 패널의 히스토리 탭과 고정 커밋상세 행이다. 새 상세 뷰나 별도 선택 상태는 추가하지 않는다. 같은 행 재선택도 상세 선택을 복구한다. 브랜치·태그 클릭 동작은 이번 요구의 변경 범위 밖이다. 추가 질문 없음.
