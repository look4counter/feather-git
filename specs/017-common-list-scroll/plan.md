# 구현 계획: 공통 목록 스크롤 및 마우스 조작

> 정리 안내: 단계별 설계·작업 기록이며 후속 변경은 [현재 명세 색인](../README.md)과 해당 기능의 spec.md를 따른다. 기존 체크 상태와 과거 검증 이력은 현재 재검증 완료를 의미하지 않는다.

## 기존 구조 및 참조 분석

Rust 2024, 로컬 GPUI 0.2.2. src/virtual_list.rs는 uniform_list와 공통 행 선택만 제공한다. 저장소·파일은 명시적 스크롤 핸들이 없고 커밋만 HistoryState의 세로·가로 핸들을 사용한다. 커밋의 가로 영역과 헤더는 ui.rs에 분리 구현되어 있다.
참조 프로젝트의 scrolling.rs는 교차 축 표시·손잡이 크기·오프셋 변환을 계산하고 ui.rs의 scroll_frame·scroll_bar가 트랙 클릭·grab 위치·프레임 밖 이동·해제를 처리한다. 행 드래그 재정렬이나 다중 선택은 이번 요구의 범위가 아니다.

## 설계 및 영향 범위

- src/scrolling.rs: 참조 방식의 Visibility·Thumb·축/드래그 계산과 휠 오프셋 제한을 순수 함수/구조체로 제공한다. 빈 크기·짧은 트랙·비정상 수치는 안전하게 처리한다.
- src/virtual_list.rs: ListScrollHandle이 기존 UniformListScrollHandle·ScrollHandle, 프레임/트랙 측정값·호버·드래그 상태를 공유 소유한다. VirtualList는 RenderOnce 컴포넌트로 세로 목록·선택 헤더·가로 최소 콘텐츠 폭·스크롤바를 하나의 프레임으로 렌더링한다. 빌더의 scroll_handle·header·min_content_width로 화면 차이를 전달한다.
프레임은 넘침을 계산하여 12픽셀 스크롤 공간을 확보한다. 헤더와 본문은 같은 가로 뷰포트 안에 두고 세로 목록만 스크롤한다. 고정 상세 행은 프레임 밖에 둔다. 프레임 크기 변경은 다음 프레임 갱신을 예약하여 표시와 두 축을 재계산한다.
손잡이는 canvas로 그리며 호버/활성 색을 표시한다. 트랙 누름은 grab을 기록하고 즉시 이동한다. paint 단계에서 프레임별 전역 마우스 이동·해제 리스너를 등록하여 트랙 밖도 처리한다. 휠은 프레임 안에서 capture로 한 번 처리하여 native 이중 스크롤을 방지한다. 행 선택 콜백을 실행하지 않는다.
- src/history.rs: common scroll handle을 상태에 보관하고 기존 scroll/horizontal_scroll은 같은 내부 핸들로 유지한다. 기존 선택 이동 및 테스트와 호환된다.
- src/ui.rs: 프로젝트·종류·탭별 패널 핸들을 보관하고 세 목록이 공통 컴포넌트를 사용한다. 커밋의 별도 가로 프레임을 제거하고 헤더/최소 폭을 공통 컴포넌트에 전달한다. 화면 전환·닫기·교체 시 드래그를 취소한다. 기록 확장 시 공통 핸들과 기존 스크롤을 함께 보존한다.
- src/main.rs: scrolling 모듈 등록.

## 제약 및 성능

데이터 조회·Git 작업·의존성 패키지를 추가하지 않는다. UI 내부 구현이며 외부 형식은 유지한다. 가시 범위 렌더링과 기존 그래프 캐시를 유지한다. 헌법은 미작성 템플릿이므로 선언된 원칙 검사를 생략하고 AGENTS.md의 계층·호환성·최소 변경 제약을 적용한다. 참조 프로젝트는 읽기만 한다.

## 검증 및 단계

넘침·교차 축·손잡이·grab·트랙 클릭·범위 제한·데이터 감소·휠·Shift·비정상 입력 테스트를 먼저 작성한다. 공통 핸들 공유·독립성·드래그 취소·프로젝트별 상태 및 기존 고정 상세·참조 이동·그리드 경계·가상화 테스트를 검증한다. cargo test/check/fmt/clippy와 별도 출력 빌드를 수행한다. GUI 드래그·휠·시각 배치 확인 여부는 별도 기록한다.
명세·명확화 → 계획 → 작업 → 읽기 전용 일관성 분석 → 선행 테스트·구현·검증 → 수렴 순서다.
