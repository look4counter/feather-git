# 검증 기록: 그래프 최소 너비 제거

## 절차

명세 품질 16/16 통과. 명확화는 직전 대화로 범위·초기값·하한 제거가 명확하여 질문 0개이며 미해결 사항은 없다. 일관성 분석에서 FR-001은 T002·T003, FR-002는 T003·T004, FR-003은 T004, SC-001·002는 T005로 연결되어 누락·충돌·중복이 없었다. 헌법은 미작성 템플릿으로 해당 검사만 생략했다. 확장 훅 파일은 없다.

## 구현 및 회귀

기존 테스트를 요구사항에 맞게 바꾸어 12레인의 초기 폭이 100 대신 240이 되는 실패를 먼저 재현했다. 이후 레인 최소폭 인수를 모델과 UI에서 제거했다. 초기 폭 100은 유지하며 그래프는 0까지 줄어들고 다시 확장된다. 그래프 셀을 잘라 인접 셀 침범을 막는다. 0에서 경계 핸들이 뷰포트 왼쪽 밖으로 사라지지 않도록 그래프 핸들 위치를 제한하고 메시지 등 나머지 핸들은 실제 셀의 오른쪽 끝을 유지한다.

## 실행 결과

- cargo test --quiet: 91개 중 89개 통과, 실패 0, 기존 수동 성능 테스트 2개 무시.
- cargo check·cargo fmt --check·cargo clippy --all-targets: 통과.
- cargo rustc --bin feather-git -- -o target/feather-git-graph-width.exe: 통과.
- 기존 GPUI 부동소수점 경고, 기존 테스트 초기화 Clippy 경고 및 별도 출력 관련 링커 경고는 남아 있다.

## 미검증 범위

이번 변경의 실제 GUI 마우스 조작과 시각 배치는 수동 검증하지 않았다. 이전 작업의 테스트 앱 사용 승인 거부 이후 추가 앱 실행은 시도하지 않았다. 컬럼 계산·0 재확장·전체 너비 보존·선택과 기존 스크롤 회귀는 자동 테스트로 확인했다.

## 수렴 검토 대상

기능 요구사항 3개, 성공 기준 2개, 수용 시나리오 3개 및 계획의 모델·UI·테스트 결정을 실제 코드와 대조한다. 주요 파일은 src/history_grid.rs, src/ui.rs다.
