# 조사 및 결정

- 결정: old의 차이 생성·부분 Stage·충돌·범위 모델을 재사용한다. 이유: 동등성 및 검증된 경계 조건 보존. 대안인 단순 git patch 표시만으로는 줄/충돌 조작이 빠진다.
- 결정: 현재 공통 24픽셀 가상 목록을 재사용한다. old의 22픽셀 개별 프레임 복제는 공통 목록 요구와 중복된다.
- 결정: DiffViewer 엔티티가 비동기 조회와 입력을 소유한다. Workspace에 모든 뷰어 입력을 합치는 방식은 기존 UI 책임을 과하게 확대한다.
- 결정: 같은 경로의 staged/unstaged를 별도 행으로 나타낸다. 단일 합산 차이는 old의 비교 계층을 잃는다.
- 결정: 뷰어 관련 기본 단축키와 재지정 UI를 포함한다. old 전체 설정·원격·브랜치 기능은 이식하지 않는다.
- 미해결 기술적 질문 없음.

충돌 문구 결정: 브랜치 의미 대신 마커 내 위치를 사용한다. 내부 Current·Incoming enum은 이미 위쪽·아래쪽 범위에 대응하므로 이름 변경이나 새 선택 모델은 불필요하다. 즉시 적용 여부는 질문으로 확인한 내용이며 안내 추가를 원하지 않는 사용자 지시를 반영한다. 미해결 질문 없음.

Stage 버튼 제거 결정: 뷰어의 전용 호출·조건만 제거하고 파일 목록이 재사용하는 백엔드 stage_resolved는 보존한다. 자동 Stage와 백엔드 삭제는 요청 범위가 아니므로 제외했다. 미해결 질문 없음.
