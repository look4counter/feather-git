## 사용자 시나리오 및 검증

### 사용자 스토리 1 — 파일 차이와 커밋 상세 조회 (우선순위 P1)

작업 트리 또는 히스토리에서 파일을 선택하면 해당 비교를 읽고, 커밋상세 행을 선택하면 상세 정보를 읽는다.
독립 검증: 임시 저장소에서 최초·일반·병합 커밋과 staged/unstaged 변경을 선택해 원본과 결과를 비교한다.

1. 작업 트리에서는 인덱스에 담긴 변경과 아직 담기지 않은 변경을 구분하고 각각 HEAD→인덱스, 인덱스→작업 파일을 비교한다.
2. 히스토리에서는 첫 부모→선택 커밋을 비교한다. 최초 커밋은 빈 파일과 비교한다.
3. 제목·구간 헤더·이전/새 줄 번호·변경 기호·추가/삭제/구간 색상·구분선을 표시한다. 탭은 4칸으로 보이고 줄바꿈으로 접지 않는다.
4. 커밋상세 행은 전체 커밋 ID·부모·작성자/커미터와 이메일·각 시간·전체 메시지를 표시하고 메타데이터 라벨을 강조한다.
5. 조회 중·실패·선택 없음·동일 텍스트·바이너리·비 UTF-8·1 MiB 초과·링크/서브모듈 안내를 표시한다. 파일 차이는 최대 5,000줄이다.

### 사용자 스토리 2 — 탐색과 선택 (우선순위 P1)

긴 차이에서도 스크롤하고 원하는 텍스트만 선택하여 복사한다.
독립 검증: 가로·세로 이동, 역방향/한글/탭/여러 줄 선택 및 복사 결과를 검증한다.

1. 공통 목록을 사용해 가시 행만 렌더링하고 세로·가로 스크롤바/휠/Shift 휠/트랙/드래그를 제공한다.
2. 왼쪽 누름으로 커서를 놓고 드래그·Shift 클릭으로 범위를 선택한다. 영역 밖 이동 시 범위를 제한하고 자동 스크롤하며 해제 시 종료한다.
3. 방향키와 I/J/K/L로 이동하고 Shift로 범위를 확장한다. Home/End·Shift Home/End·Ctrl+A·Ctrl+C를 제공한다. 키보드 이동 시 커서가 화면에 보인다.
4. 단축키는 뷰어 포커스에서만 동작하며 재지정할 수 있다. 파일·프로젝트·탭 전환 또는 닫기로 이전 드래그/체크/조회 결과가 새 대상에 섞이지 않는다.

### 사용자 스토리 3 — 변경 줄 Stage 및 충돌 해결 (우선순위 P1)

선택한 변경만 인덱스에 담고 충돌 구간에서 유지할 내용을 선택한다.
독립 검증: 임시 저장소의 인덱스·작업 파일을 직접 비교해 부분 적용과 오래된 조회 거부를 확인한다.

1. 일반 미스테이지 텍스트 파일에서 추가/삭제 줄을 체크하고 Space로 현재/선택 범위를 체크·해제하며 Enter 또는 버튼으로 선택 줄을 Stage한다. 구간 헤더의 버튼으로 해당 구간도 Stage한다.
2. Stage는 선택 변경만 인덱스에 쓰며 작업 파일을 바꾸지 않는다. 충돌·링크·비정규 파일·변환 필터 등 부적합한 대상은 제한한다.
3. 충돌 구간에 커서를 두면 위쪽/아래쪽/양쪽 사용을 선택할 수 있다. diff3 마커도 처리하고 선택한 구간만 작업 파일에 반영한다. 해결한 파일은 변경 파일 목록에서 Stage한다.
4. 변경 전에 실제 인덱스와 파일을 다시 확인하고 조회 이후 변한 대상은 덮지 않는다. 중복 실행을 막고 완료 후 파일 목록과 차이를 갱신하며 실패는 표시한다.

### 경계 조건

빈 저장소·삭제/추가·같은 경로의 staged와 unstaged·CRLF·마지막 개행 없음·긴 줄·한글·잘못된 경로·미완성 충돌 마커·잠긴 인덱스·대상 전환 중 비동기 응답을 다룬다. 샘플 저장소는 실제 파일인 것처럼 차이를 꾸미지 않는다.

## 요구사항

- **FR-001**: 작업 트리의 두 변경 계층과 히스토리 비교 대상을 정확히 구분한다.
- **FR-002**: 구간·줄 번호·기호·색·구분선·4칸 탭 및 비접힘 표시를 제공한다.
- **FR-003**: 커밋상세의 전체 메타데이터와 메시지를 선택 가능한 텍스트로 표시한다.
- **FR-004**: 조회·실패·빈 상태와 텍스트 미리보기 제한을 명시하고 1 MiB·5,000줄 상한을 지킨다.
- **FR-005**: 공통 가상 목록과 두 축의 기존 스크롤 조작을 사용한다.
- **FR-006**: 포인터·Shift·드래그/해제·영역 밖 자동 스크롤과 문자 단위 텍스트 선택을 제공한다.
- **FR-007**: 기존 이동·범위·복사·전체 선택 단축키 및 재지정을 제공하며 포커스를 격리한다.
- **FR-008**: 줄 체크·범위 토글·선택 줄/구간 Stage를 제공한다.
- **FR-009**: 일반 텍스트만 부분 Stage하고 원본·필터·인덱스 검증과 잠금으로 변경을 보호한다.
- **FR-010**: 충돌 구간의 위쪽/아래쪽/양쪽 선택을 제공하고 해결한 파일은 변경 파일 목록에서 Stage한다.
- **FR-011**: 비동기 조회와 쓰기·세대 검증·중복 방지·상태 갱신을 구현한다.
- **FR-012**: 기존 고정 상세 행·컬럼 조절·선택·저장소 작업의 회귀를 방지한다.

## 주요 개체

비교 파일은 경로·staged 여부·이전/이후 원본으로 식별한다. 차이 행은 이전/새 번호·기호·본문을 가진다. 뷰어 대상·조회 세대·텍스트 범위·체크 행·충돌 구간·스크롤 상태를 구분한다.

## 성공 기준

- **SC-001**: 비교·제한·상태 분리·선택·부분 Stage·충돌 및 오래된 대상 보호 자동 테스트가 통과한다.
- **SC-002**: 파일 선택과 고정 상세 행이 올바른 뷰어로 연결되고 기존 회귀 테스트가 통과한다.
- **SC-003**: 전체 테스트·타입·포맷·정적 분석·빌드가 통과한다. 수동 GUI 미검증은 별도로 명시한다.

## 명확화 및 범위

참조 소스의 diff_panel·diff_row·selectable_line·text_selection·git::diff·partial_stage·conflict·뷰어 단축키를 조사하여 위 기능 목록을 확정했다. 추가 질문은 없다. 비교 뷰어 관련 기능 전체가 대상이며 브랜치·원격 조작·커밋 편집기 등 앱 전체의 기능 이식은 포함하지 않는다. 참조 프로젝트는 읽기만 한다.

## 2026-11-16 충돌 선택 문구 갱신 및 명확화

사용자 요청: 현재 변경 사용·들어오는 변경 사용을 위치 기준인 위쪽(현재) 변경 사용·아래쪽(대상) 변경 사용으로 바꾼다. 양쪽 모두 사용과 실제 적용 동작은 유지한다. 기존 안내에서 현재/들어오는 의미를 해설하는 문장은 제거한다. 즉시 반영 안내와 체크 후 일괄 적용은 추가하지 않는다.
수용 기준: 두 버튼은 새 문구를 표시하고 각각 기존 위쪽·아래쪽 선택으로 연결된다. 양쪽 선택·구간별 즉시 반영·파일 목록 Stage·입력 보호는 그대로다. 리베이스에서도 브랜치 이름을 추측하지 않는다. 추가 질문이 필요한 모호성 없음.

추가 표시 요구: 하단 안내에서 충돌 구간에 커서를 놓고 상단에서 선택하라는 문장도 제거한다. 기존 해결 후 Stage 안내와 충돌 구간별 동작은 유지한다.

## 충돌 해결 후 Stage 버튼 제거

요청: DiffViewer의 해결한 파일 전체 Stage 버튼을 제거한다.
수용 기준: 충돌 마커를 모두 해결해도 해당 버튼을 표시하지 않는다. 해결된 파일은 기존 변경 파일 목록에서 Stage할 수 있다. 충돌 선택·일반 부분 Stage·해결 내용 및 인덱스 검증은 유지한다. 버튼 제거가 자동 Stage로 이어지지 않는다. 추가 질문이 필요한 모호성 없음.

최종 충돌 선택 표시 요구: 위쪽 버튼은 위쪽(현재) 변경 사용, 아래쪽 버튼은 아래쪽(대상) 변경 사용으로 표시한다. 위치와 괄호 표현은 사용자 지정 문구이며 실제 선택 범위·콜백은 유지한다. 명확화할 모호성 없음.
