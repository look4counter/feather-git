# 구현 계획: 샘플 프로젝트 제거

## 기술 맥락 및 구조 분석

Rust 2024, GPUI 앱이다. main.rs가 sample 모듈을 등록하고 ui.rs의 Workspace::default가 프로젝트 4개를 생성한다. 실제 저장소는 repository::execute → activate_repository → prepare_history → refresh_panel_data로 연결된다.
샘플 데이터는 초기화 외에 참조 선택의 이름 대체, 데모 배지, 경로 없는 뷰어 안내에 사용된다. 기존 테스트도 기본 프로젝트에 의존한다.

## 헌장 점검

헌장은 미작성 템플릿이므로 규범 검사는 생략한다. 기존 UI·저장소·뷰어 책임과 공개 데이터 형식을 유지한다. 새 의존성·아키텍처 변경은 없다. 시작 시 사용자 변경은 없었다.

## 설계 및 영향 범위

1. src/ui.rs: 빈 프로젝트 목록과 활성 시작 탭으로 초기화한다. 샘플 전용 분기를 제거하고 경로 누락 오류는 일반 오류로 처리한다.
2. src/main.rs, src/sample.rs: 샘플 모듈 등록과 데이터 파일을 삭제한다.
3. src/ui.rs 테스트: 실제 임시 저장소를 명시적으로 준비해 기존 검증을 유지한다. 빈 초기 상태·마지막 탭 닫기·중복 열기를 검증한다.

Project.path의 선택적 형식은 호환성을 위해 유지한다. 시작 화면과 모든 탭을 닫은 화면은 기존 렌더링을 재사용한다. 과거 기능 명세는 수정하지 않는다.

## 검증 방법

샘플 코드 검색, cargo fmt --check, cargo test --offline, cargo check --offline를 실행한다. 미실행 검증과 화면 수동 확인 여부를 기록한다. 구현 전 명세·계획·작업 일관성을 분석하고 구현 후 수렴 검사한다.
