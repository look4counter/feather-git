# 기능 명세: 샘플 프로젝트 제거

> 문서 정리일: 2026-11-17. 본문은 이 기능의 단계별 요구사항 이력을 포함한다. 현재 유효 기준과 검증 한계는 [전체 명세 색인](../README.md)을 함께 확인한다. 과거 검증 기록은 현재 버전의 재검증 결과가 아니다.
> 후속 변경 참고: [021](../021-persist-workspace/spec.md).
> 현재 기준: 샘플 제거는 유지한다. 재실행 시 시작 화면만 보장한다는 초기 조건은 021의 저장된 프로젝트·시작 탭 복원으로 대체되었다.

작성일: 2026-11-14 · 상태: 검증 완료
입력: 샘플로 만든 프로젝트 탭과 관련 코드 삭제

## 사용자 시나리오 및 검증

### 사용자 이야기 1: 실제 저장소만 사용하는 작업 공간 (우선순위: P1)

사용자는 가짜 프로젝트 없이 시작하고 실제 저장소를 연결한다.
독립 검증: 새 작업 공간 생성 후 저장소 생성·열기·전환·닫기를 확인한다.

1. 실행하면 프로젝트 탭은 0개이고 시작 탭 1개가 활성화된다.
2. 실제 저장소를 연결하면 해당 탭이 시작 탭을 대체한다.
3. 마지막 프로젝트나 시작 탭을 닫아도 오류가 없고 다시 시작할 수 있다.
4. 같은 실제 저장소를 다시 열면 프로젝트 탭을 중복 생성하지 않는다.

### 경계 조건

커밋 없는 저장소, 여러 프로젝트 전환, 잘못된 선택·닫기 이벤트, 모든 탭 닫기, 읽기 실패를 검증한다.

## 요구사항

- FR-001: 실행 시 샘플 프로젝트·커밋·파일을 생성하지 않고 시작 탭만 표시한다.
- FR-002: 샘플 데이터 정의·주입과 샘플 전용 안내·참조 선택·뷰어 대체 표시를 제거한다.
- FR-003: 실제 저장소 생성·열기·복제, 탭 중복 방지·전환·닫기와 오류 표시를 유지한다.
- FR-004: 기존 회귀 검증을 샘플 런타임 데이터에서 독립시키고 빈 초기 상태를 검증한다.

### 주요 개체

작업 공간은 실제 프로젝트와 단일 시작 탭을 관리한다. 프로젝트의 경로와 기존 데이터 형식은 유지한다.

## 성공 기준

- SC-001: 새 실행의 샘플 프로젝트 수 0개, 시작 탭 수 1개.
- SC-002: 실제 저장소 연결·중복 열기·전환·닫기 검증이 모두 통과한다.
- SC-003: 샘플 전용 코드가 남지 않고 관련 자동 검증이 통과한다.

## 가정 및 명확화

기존 시작 화면을 재사용한다. 사용자 저장소·파일은 삭제하지 않는다. 기존 설계 문서는 이력으로 보존한다. 테스트 전용 데이터는 샘플 UI 기능과 구분해 유지한다.
명확화 검토: 범위·데이터·화면·오류·완료 기준은 명확하며 추가 질문은 없다. 성능·인증·외부 인터페이스는 변경하지 않는다.
