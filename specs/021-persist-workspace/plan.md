# 구현 계획: 탭 복원 및 최근 저장소

## 기술 맥락과 기존 구조 분석

Rust 2024·GPUI·git2·serde·serde_json을 사용한다. Workspace::default는 빈 탭과 시작 화면을 만든다. main.rs에서 기본 작업 공간을 생성한다. 저장소 생성·열기·복제는 submit_repository의 백그라운드 repository::execute → activate_repository → prepare_history → refresh_panel_data로 처리한다. 저장소 스냅샷이 canonicalize한 경로를 제공해 중복 경로 판단을 재사용할 수 있다.
탭의 변화는 open_start_tab/select_project/close_start_tab/close_project/activate_repository에 모여 있다. 시작 화면의 최근 저장소는 빈 안내뿐이다. diff_viewer.rs는 사용자 설정 경로 선택과 임시 파일 쓰기·동기화·이름 변경 패턴을 이미 사용한다.

## 헌장 및 아키텍처 점검

헌장은 미작성 템플릿이므로 규범 검사를 생략한다. 공개 Project/Request 모델과 저장소 계층은 변경하지 않는다. 새 의존성 없이 session.rs가 저장 데이터와 파일 접근을 담당하고 ui.rs는 상태 전이·표시만 연결한다. 기존 뷰어의 독립 설정을 불필요하게 리팩터링하지 않는다.

## 설계 결정 및 영향 범위

- src/session.rs 추가: 버전 1 JSON 상태, 저장소 이름·경로, 열린 목록·최근 목록·활성 경로·시작 상태. 사용자 설정 경로는 기존 패턴과 같은 LOCALAPPDATA, XDG_CONFIG_HOME, HOME/.config 아래 feather-git/workspace.json이다. 원본 JSON 오류·버전 오류는 반환한다.
- 안전 저장: 같은 디렉터리의 고유 임시 파일에 직렬화·동기화 후 rename으로 교체한다. 오류는 기존 파일을 보존하며 임시 파일만 정리한다. 최근 목록은 정규 경로 기준 중복 제거, 20개 제한이다.
- src/ui.rs: 기본 상태는 테스트 격리를 위해 순수하게 유지한다. 운영 진입점 load가 저장 파일을 읽고 기존 repository::execute(Open)로 최신 저장소 데이터를 다시 읽는다. 초기 복원은 UI 생성 직후 GPUI 백그라운드 실행기로 처리한다. 설정·저장소·활성 프로젝트 파일 목록을 백그라운드에서 읽고 소유 데이터만 UI에 전달한다. 인위적 저장소 수 제한은 두지 않는다. 자동 복원 중 저장·최근 순서 갱신을 억제한다. 누락 경로는 건너뛰고 최근 목록을 남긴다.
- 탭 변화마다 저장하며 활성 프로젝트 선택 시 최근 사용 순서를 갱신한다. 설정 실패 메시지는 별도 상태에 보관해 일반 안내에 덮이지 않게 하단에 표시한다. 정상 저장 후 이전 저장 오류를 해소한다.
- 최근 저장소 클릭은 기존 비동기 실행 및 Alert를 재사용한다. 처리 중 중복 요청을 막고 성공할 때만 activate_repository로 반영한다.
- src/main.rs: 운영용 load 진입점을 사용한다. 기존 기본 상태·샘플 제거 테스트는 유지한다.

## 검증

session.rs의 저장·재읽기·중복·20개 제한·한글/공백·손상·버전·쓰기 실패·원본 보존을 테스트한다. ui.rs는 실제 임시 저장소를 이용해 탭 순서·활성/시작 상태·닫기·누락 경로·재열기·최근 순서·실패 보존을 검증한다. 테스트는 실제 사용자 설정에 접근하지 않는다.
cargo fmt --check, cargo test --offline, cargo check --offline, cargo build --offline를 실행한다. 기존 실행 파일이 잠겼으면 별도 파일명으로 링크를 검증한다. 화면 수동 검증 미실행 시 기록한다.

## 재시작 정지 원인 분석 및 수정 설계

main.rs의 창 생성 콜백 → Workspace::load → load_from_path → repository::execute와 activate_repository → prepare_history → refresh_panel_data가 모두 UI 스레드에서 동기로 실행됐다. 복원 중 저장소마다 변경 파일을 다시 읽어 작업이 중복됐다.

src/ui.rs에 전송 가능한 복원 결과 구조체와 백그라운드 읽기 함수를 분리한다. GPUI Context와 Window는 작업에 전달하지 않는다. 결과는 프로젝트·활성 인덱스·저장된 상태·실패 목록·활성 프로젝트의 변경 파일 목록으로 구성한다. 결과 적용은 목록 교체와 활성 기록 캐시 생성만 하며 activate_repository/prepare_history/refresh_panel_data/remember를 호출하지 않는다. 기본 패널은 기존 로컬·작업 파일 탭이므로 태그·과거 파일 조회는 필요 없다.

Workspace::load는 Window와 Context를 받아 기본 작업 공간을 즉시 반환하고 cx.spawn_in으로 백그라운드 작업을 기다린다. 약한 엔티티 갱신을 사용해 창이 사라지면 결과를 버린다. 복원 중 상태 플래그와 안내를 표시한다. 탭 열기·선택·닫기, 저장소 대화상자·최근 재열기 및 설정 저장 진입점을 차단한다. 완료·오류는 플래그를 해제한다. 저장 JSON 버전·공개 저장소 API·새 의존성은 변경하지 않는다.

검증: 공통 시작 함수의 스케줄러를 주입하고 채널로 완료를 지연시키는 테스트로 작업 공간의 즉시 반환·읽기 작업의 다른 스레드 실행·완료 전후 상태를 확인한다. 현재 의존성에는 GPUI test-support가 활성화되지 않아 실제 창 이벤트 처리는 정적 검토 및 별도 수동 검증 대상으로 명시한다. 기존 실제 임시 저장소 복원 테스트는 동일한 읽기·결과 반영 경로를 재사용한다. 복원 중 변경 및 파일 쓰기가 차단되고 완료 후 조작이 복구되는지, 선택 프로젝트 파일 목록이 사전 조회 결과와 일치하는지 확인한다. 기존 전체 테스트·형식·정적 검사·빌드를 재실행한다.

## 시작 전용 로딩 화면 설계

현재 Workspace::render는 restoring 여부와 무관하게 탭과 시작 페이지를 렌더링하므로 로딩 중 새 탭과 최근 저장소 영역이 노출된다. src/progress.rs에는 canvas와 with_animation 기반의 FeatherWaterScene/ProgressOverlay가 있고 다른 저장소 작업에서 사용하므로 그 동작은 유지한다.

src/progress.rs에 시작 전용 StartupLoadingScreen과 비행 장면을 추가한다. 기존 깃털 그리기 경로는 작은 공통 함수로 추출해 기존 물결 장면과 시작 장면에서 재사용한다. 고정 논리 좌표를 캔버스 크기에 맞춰 스케일링하고 화면 위쪽에 비행 장면을 배치한다. 새는 가로 비행과 반복 날갯짓, 깃털은 서로 다른 방출 시점·회전·흔들림·점진적 투명도로 구성한다. GPUI 애니메이션 생명주기를 사용하고 별도 스레드·타이머·이미지 의존성은 추가하지 않는다.

src/ui.rs는 restoring일 때 먼저 전용 화면을 반환해 탭·패널·상태줄이 생성되지 않게 한다. 공통 창 프레임 함수를 재사용해 네이티브 제목줄과 테마를 유지한다. 정상 화면 경로에는 기존 화면을 유지한다. 복원 완료가 restoring을 해제하면 애니메이션 요소도 제거되며 인위적인 대기는 추가하지 않는다.

검증: 논리 장면의 비행·여러 깃털·반복 경계·유효 좌표 및 투명도를 자동 검증한다. 전용 화면 선택과 복원 완료·실패 상태 전이를 회귀 검증한다. 기존 ProgressOverlay 테스트·전체 테스트·형식·정적 검사·빌드를 실행한다. 실제 화면의 미관·프레임 속도는 별도 시각 확인 여부를 명시한다. 헌장은 기존 미작성 템플릿이며 계층·공개 저장소 모델·의존성 변경은 없다.
