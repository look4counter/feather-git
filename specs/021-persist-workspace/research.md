# 조사 결과

- 결정: 기존 serde JSON과 설정 저장 패턴을 사용한다. 새 설정 라이브러리나 데이터베이스는 규모에 비해 불필요하다.
- 결정: 저장소의 정규화된 경로를 식별자로 사용한다. 기존 repository 스냅샷이 제공해 중복 로직을 최소화한다.
- 결정: 작업 공간 기본값은 순수하게 유지하고 운영용 load에서만 읽는다. 기존 테스트 및 사용자 설정의 격리를 보장한다.
- 결정: 상태 변화 직후 저장한다. 종료 훅만 사용하는 방식보다 비정상 종료에서 최근 변경을 보존한다.
- 결정: 초기 복원과 최근 재열기 모두 기존 GPUI 비동기 실행 패턴을 따른다. 초기 복원에서는 변경 파일 조회까지 백그라운드로 옮기고 결과 적용 시 중복 조회를 하지 않는다.
- 미해결 기술 질문 없음.

- 추가 결정: 기본 화면을 즉시 생성하고 복원 결과만 UI에 반영한다. Workspace 전체는 GPUI의 Rc 기반 상태를 포함해 스레드로 이동할 수 없으므로 순수 소유 데이터만 전달한다. 초기 화면에서 결과 반영 전 프로젝트 조작은 보류해 경쟁 상태와 설정 손실을 방지한다.

- 디자인 결정: 기존 GPUI canvas/with_animation을 사용한다. 코드 기반 애니메이션은 창 크기에 맞게 선명하고 외부 자산·추가 디코더가 필요 없다. 기존 공통 진행 오버레이를 바꾸는 대신 시작 전용 화면을 추가해 다른 작업의 동작을 보존한다.
