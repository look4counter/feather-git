# 조사 및 검증 계획

## 기존 구조와 실제 원인

src/main.rs에는 on_window_closed 구독이 없지만 vendor/gpui/src/platform/windows/events.rs는 WM_DESTROY에서 WM_GPUI_CLOSE_ONE_WINDOW를 보내며 platform.rs가 마지막 네이티브 창 제거 시 PostQuitMessage를 호출한다. 따라서 구독 부재만으로 Windows 프로세스 잔류 원인이라고 단정할 수 없다.
기존 앱 코드에 다음 프레임 창 제거와 종료 마커만 주입한 임시 실행 파일 및 명시적인 종료 구독을 넣은 비교 실행 파일을 target/lifecycle-check에 빌드한다. 두 파일 모두 독립 설정을 사용해 실행하며 프로세스 종료를 확인한다. 실제 사용자 설정과 실행 중인 사용자 앱은 변경하지 않는다.
원래 코드와 비교 코드가 모두 정상 종료했으며 잔류 PID 34344는 이전 로딩 미리 보기에서 에이전트가 숨겨 실행한 인스턴스로 확인됐다. 해당 인스턴스만 정리하고 잠금 해제 후 기본 빌드를 검증한다.

## 최종 변경 범위

조사 중 src/main.rs에 추가했던 종료 구독은 필요성이 입증되지 않아 이번 작업의 변경분만 되돌린다. UI·저장소·프레임워크·공개 API·의존성에는 변경을 남기지 않는다. 최종 산출물은 조사 문서와 테스트 프로세스 정리다.
헌장은 미작성 템플릿이므로 규범 검사는 생략한다. 기존 사용자 변경은 보존한다.

## 검증

기존 코드의 실제 GPUI 창 제거 및 프로세스 종료 마커를 확인한다. 직접 제목줄 닫기 조작과 대규모 저장소 복원 중 종료는 별도 미검증으로 기록한다. cargo test --offline, cargo fmt --check, cargo check --offline, cargo build --offline를 실행한다. 동일 구현을 복제하는 단위 테스트나 제품용 진단 플래그는 추가하지 않는다.
