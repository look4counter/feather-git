# 기능 명세: 창 종료와 잔류 프로세스 원인 조사

> 문서 정리일: 2026-11-17. 본문은 이 기능의 단계별 요구사항 이력을 포함한다. 현재 유효 기준과 검증 한계는 [전체 명세 색인](../README.md)을 함께 확인한다. 과거 검증 기록은 현재 버전의 재검증 결과가 아니다.

작성일: 2026-11-14 · 상태: 조사 결과 반영 및 명확화 완료
입력: 창을 닫아도 프로세스가 남는 원인이 코드에 있는지 확인한다.

## 사용자 시나리오 및 검증

### 사용자 이야기 1 — 원인 확인 후 정상 재실행 (우선순위: P1)

사용자는 실행 파일 교체를 막는 실제 원인을 알고 기존 앱을 다시 빌드할 수 있어야 한다.

1. 기존 앱의 마지막 창 닫기 경로와 프로세스 종료를 확인한다.
2. 잠금을 발생시킨 프로세스의 기원을 확인하고 에이전트가 남긴 테스트 인스턴스만 정리한다.
3. 원인과 무관한 앱 종료 코드는 추가하지 않고 원래 코드로 빌드가 성공하는지 확인한다.

독립 검증: 기존 앱 코드를 사용하는 별도 실행 검증에서 창 제거 후 프로세스가 끝나는지 확인하고 테스트 프로세스 정리 후 기본 실행 파일 빌드를 확인한다.

## 요구사항

- FR-001: 앱 종료 경로와 실행 검증에 근거해 코드 문제 여부를 판단하고 메모리 누수를 추측으로 확정하지 않는다.
- FR-002: 에이전트가 생성한 잔류 테스트 인스턴스임을 확인한 경우 해당 인스턴스만 정리하고 사용자의 다른 앱은 종료하지 않는다.
- FR-003: 불필요한 종료 로직 변경을 남기지 않고 실제 기본 실행 파일이 다시 빌드되는지 확인한다.

## 성공 기준

- SC-001: 수정 전·후 종료 경로 검증 결과와 실제 잔류 프로세스 기원을 기록한다.
- SC-002: 테스트 인스턴스 정리 후 전체 자동 테스트·형식·정적 검사·기본 빌드가 통과한다.
- SC-003: 원인·정리 결과·코드 변경 여부와 직접 창 조작 미검증 범위를 명확히 보고한다.

## 경계 및 명확화

초기에는 종료 구독 누락을 원인으로 의심했으나 Windows GPUI에도 마지막 네이티브 창 종료 처리가 있고 기존 코드의 별도 실행 검증이 통과했다. 실제 잠금 원인은 이전 시각 검증에서 에이전트가 숨겨 실행하고 정리하지 못한 PID 34344다. 해당 인스턴스의 생성 기록·실행 경로·창 없는 상태를 확인했다. 메모리 누수를 입증하는 결과는 없다. 불필요한 수정은 원복하고 진단·정리만 최종 변경으로 남긴다. 추가 질문 없음.
