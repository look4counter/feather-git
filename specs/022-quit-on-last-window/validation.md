# 조사 및 검증 결과

## 실제 원인

실행 파일을 잠근 프로세스는 PID 34344였다. 이 PID는 이전 로딩 화면 시각 검증 중 에이전트가 숨겨 실행한 미리 보기 인스턴스의 생성 기록과 일치한다. 실행 경로는 target/debug/feather-git.exe였고 MainWindowHandle은 0이었다. 앞선 정리 명령의 종료 실패를 놓쳐 인스턴스가 계속 남았다.
코드의 앱 종료 구독 누락을 최초 원인으로 단정한 설명은 잘못됐다. Windows GPUI에는 마지막 네이티브 창 제거 후 PostQuitMessage를 보내는 자체 종료 경로가 있다. 메모리 누수를 입증한 결과는 없다.

## 조사와 처리

- src/main.rs와 GPUI app/window/Windows events/platform 종료 경로를 분석했다.
- target/lifecycle-check에 현재 앱 코드의 임시 사본 두 개를 빌드했다. 제품 모듈은 실제 src 경로를 사용하고 창 생성 콜백에 다음 프레임 창 제거와 앱 실행 반환 후 마커 출력만 주입했다.
- 기존 코드: 0.90초 후 종료 코드 0, LIFECYCLE_EXITED 출력.
- 명시적 종료 구독 추가 코드: 1.10초 후 종료 코드 0, 같은 마커 출력.
- 두 실행 검증은 별도 LOCALAPPDATA 설정 경로를 사용했고 실제 사용자 설정은 수정하지 않았다.
- PID와 실행 경로·창 없는 상태를 확인한 뒤 에이전트가 만든 PID 34344만 종료했다. 이후 남아 있는 feather-git 프로세스가 없음을 확인했다.
- 필요성이 입증되지 않은 src/main.rs의 종료 구독 추가는 되돌렸다. 제품 소스에는 이번 조사로 인한 동작 변경을 남기지 않았다.
