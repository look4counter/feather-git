# 기능 명세: 백엔드 공통 지연 옵션

> 문서 정리일: 2026-11-17. 본문은 이 기능의 단계별 요구사항 이력을 포함한다. 현재 유효 기준과 검증 한계는 [전체 명세 색인](../README.md)을 함께 확인한다. 과거 검증 기록은 현재 버전의 재검증 결과가 아니다.
> 후속 변경 참고: [024](../024-responsive-backend/spec.md) · [025](../025-backend-resource-limits/spec.md).

작성일: 2026-11-14 · 상태: 명확화 완료
입력: cargo run 옵션으로 모든 백엔드 동작을 느리게 만들어 UI 비동기 처리를 확인하고, 개별 지연 삽입 대신 공통 컴포넌트를 사용한다.

## 사용자 시나리오 및 검증

### 사용자 이야기 1 — 실행 옵션으로 지연 제어 (우선순위: P1)

1. 옵션 없이 실행하면 인위적인 지연이 없다.
2. 개발자가 밀리초 단위 지연 옵션을 주면 백엔드 요청에 지정한 추가 지연이 적용된다.
3. 0은 지연을 끄고 잘못된 값·알 수 없는 옵션은 창을 열기 전에 사용법과 오류를 알린다.
4. 도움말에서 사용법·범위·동기 호출 영향이 설명된다.

독립 검증: 옵션 파싱과 실제 실행 파일의 도움말·오류·0값 동작을 확인한다.

### 사용자 이야기 2 — 동기 호출을 포함한 공통 진입점 (우선순위: P1)

1. 저장소 생성·열기·복제, 참조·커밋·변경 파일·diff·상세 조회, 부분 스테이징·충돌 처리 및 설정 읽기·쓰기가 공통 지연 정책을 사용한다.
2. 하나의 요청 안에서 내부 백엔드를 호출해도 추가 지연을 중복 적용하지 않는다. 독립 요청은 각각 지연한다.
3. UI 스레드의 동기 호출도 지연하며 진단 로그로 이를 알린다. 기존 비동기 호출은 백그라운드에서 지연된다.
4. 오류·반환 데이터·실행 순서는 유지하고 요청을 임의로 비동기로 바꾸지 않는다.
5. 이후 개발자가 개별 작업에 지연 코드를 넣지 않고 공통 진입점에 작업을 등록할 수 있다.

독립 검증: 실제 백엔드 인터페이스 호출, 중첩·오류·패닉·동시 작업에서 지연 정책과 복구를 자동 검증한다.

## 요구사항

- FR-001: --backend-delay-ms 옵션으로 요청 전 추가 지연을 지정하고 기본값·0값은 지연하지 않는다.
- FR-002: 백엔드 I/O 공개 진입점을 공통 컴포넌트로 관리하며 업무 구현 내부에 개별 sleep을 삽입하지 않는다.
- FR-003: 저장소·diff·스테이징·충돌·세션·뷰어 단축키 설정 I/O를 포함하고 순수 변환·화면 그리기·운영체제 파일 선택창에는 지연을 넣지 않는다.
- FR-004: 동일 스레드에서 중첩 호출한 요청은 한 번만 지연하고 독립·동시 요청은 각각 지연한다. 오류·패닉 뒤에도 정책이 정상 복구된다.
- FR-005: 동기 호출도 그대로 지연하고 UI 스레드 여부와 작업 이름·지연 시간만 로그에 출력한다. 저장소 경로·내용·인증정보는 출력하지 않는다.
- FR-006: 잘못된 값·중복 옵션·알 수 없는 옵션을 거절하고 도움말을 제공한다. 지연 범위는 0~60000밀리초다.
- FR-007: 기존 공개 함수 서명·데이터·실패 동작·동기/비동기 배치와 사용자 설정을 유지하고 실행 옵션은 저장하지 않는다.

## 성공 기준

- SC-001: 옵션 기본·0·최대값·잘못된 입력·도움말 자동 검증이 통과한다.
- SC-002: 실제 백엔드 진입점의 지연 적용·중첩 억제·동시성·복구 검증이 통과한다.
- SC-003: 모든 지정 I/O가 공통 진입점을 경유하며 개별 업무 코드에 sleep이 없다.
- SC-004: 전체 테스트·형식·정적 검사·빌드가 통과하고 UI 수동 검증 범위를 명시한다.

## 경계 및 명확화

사용자 답변: 동기 호출에도 지연을 적용해 UI 멈춤을 드러낸다. 여기서 스로틀링은 초당 처리량 제한이 아닌 요청마다의 고정 추가 지연이다. 임의 지터·실패 주입·속도 제한·동시성 제한은 범위 밖이다. 지연은 I/O 요청 전에 적용하고 순수 계산에는 적용하지 않는다. 여러 독립 요청으로 구성된 화면 작업은 각각 지연될 수 있다. 사용자 앱은 강제 종료하지 않는다. 추가 질문 없음.
