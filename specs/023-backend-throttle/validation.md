# 구현 및 검증 결과

## 목적과 구현 결과

cargo run -- --backend-delay-ms 1500으로 백엔드 요청 전에 1.5초 추가 지연을 적용한다. --backend-delay-ms=1500도 지원한다. 기본 실행과 0값은 지연하지 않는다. 0~60000 범위를 허용하며 중복·잘못된 값·알 수 없는 옵션은 종료 코드 2로 거절한다. --help/-h는 한국어 사용법을 출력하고 GUI를 열지 않는다.
개별 업무 코드에 sleep을 넣지 않고 backend.rs의 공통 실행 정책과 모듈 게이트웨이를 사용한다. 기존 repository/diff_git/partial_stage/conflict/session 이름·타입·함수 서명을 유지하며 I/O 19개를 명시적으로 등록했다. 구현은 비공개 implementation 하위에서 사용하므로 UI 호출이 게이트웨이를 우회하지 않는다. 순수 유틸리티는 직접 재노출하고 기존 UI 실행기 배치는 유지했다.
공통 실행기는 스레드 지역 재진입 가드로 동일 스레드의 중첩 호출에 한 번만 지연한다. 독립·동시 요청은 각각 지연하며 오류·패닉 뒤에도 가드가 복구된다. 로그에는 작업 이름·밀리초·UI 스레드 동기 호출/백그라운드 호출 구분만 출력한다.
단축키 설정 파일 읽기·쓰기도 세션 바이트 I/O를 재사용하며 기존 설정 형식·검증·안전 파일 교체를 유지한다.

## 주요 변경 파일

- src/backend.rs: 옵션 파싱·공통 정책·UI 스레드 진단·재진입 가드·게이트웨이 선언·8개 테스트.
- src/main.rs: 공통 게이트웨이 등록과 UI 시작 전 옵션 처리·정책 초기화.
- src/session.rs: 기존 안전 저장을 바이트 I/O로 공유하고 기존 세션 검증·형식을 유지.
- src/diff_viewer.rs: 단축키 설정 I/O의 공통 경계 사용.
- .specify/feature.json 및 specs/023-backend-throttle/: 명세·사용자 명확화·계획·계약·작업·검증 문서.

## 단계별 검증

- 사용자 답변으로 동기 호출에도 지연을 적용하는 정책을 확정했다.
- 구현 전 일관성 분석: 요구사항 7개가 구현·검증 작업에 연결되며 누락·충돌·중복·미해결 모호성 없음.
- 옵션 기본·0·최대값·등호 문법·도움말, 값 부재·음수·소수·초과·정수 오버플로·중복·알 수 없는 옵션을 자동 검증했다.
- 지연 전 업무 미실행과 최소 실제 지연 시간, 반환값·오류 보존, 중첩 지연 억제, 패닉 후 복구를 검증했다.
- 독립 작업 스레드 둘이 동시에 업무에 진입하고 각각 한 번만 지연하며 백그라운드로 판별되는지 확인했다.
- 실제 게이트웨이 I/O 19개 각각에 정확히 한 번 지연을 적용하는지 확인했다. 부분 스테이징·충돌 처리의 내부 diff_git 호출과 명시적 외부 요청으로 감싼 호출이 중복 지연되지 않는지도 검증했다.
- 순수 이름 변환·텍스트 파싱·행 계산·설정 경로 계산은 지연하지 않는지 확인했다.
- 실제 저장소 테스트는 작업 공간의 target/backend-throttle-tests 임시 경로를 사용해 샌드박스 임시 디렉터리의 저장소 초기화 접근 제한을 피했다. 테스트 정책은 스레드 지역으로 주입하고 기존 병렬 테스트를 지연시키지 않았다.
- cargo test --offline: 142개 통과, 실패 0개, 기존 수동 성능 테스트 2개 제외. 기존 세션·단축키 저장·Git·UI 선택·비동기 복원 회귀 검증 포함.
- cargo fmt --check, cargo check --offline, cargo clippy --offline --all-targets, cargo build --offline: 모두 통과.
- 실제 실행 파일의 도움말·0+도움말·1500+도움말은 종료 코드 0, 잘못된 값·60001·중복·알 수 없는 옵션은 종료 코드 2를 확인했다.
- 실제 cargo run --offline -- --backend-delay-ms 1500 --help 실행 성공을 확인했다. GUI를 실행하지 않았고 잔류 feather-git 프로세스도 없다.
- 지연용 thread::sleep은 backend.rs 한 곳에만 존재한다.

## 제약과 미검증

실제 GUI를 띄우고 지연 중 각 화면을 조작하는 수동 검증은 수행하지 않았다. 동기 패널 갱신·세션 저장·단축키 읽기 등은 의도적으로 느려지며 UI가 멈출 수 있다. 이 옵션은 비동기 처리를 검증하기 위한 것이며 기존 호출을 자동으로 비동기로 바꾸지 않는다. 한 화면 조작이 여러 독립 I/O를 요청하면 지연 시간이 누적될 수 있다.
지연은 지정한 I/O 진입점에 적용하며 렌더링·순수 계산·파일 선택창에는 적용하지 않는다. 새 I/O는 backend.rs 게이트웨이 선언에 등록해야 한다. 기존 내부 테스트의 이름은 각 모듈의 implementation 하위 경로로 바뀌지만 테스트 내용은 유지됐다.
기존 GPUI 실수 리터럴·proc-macro-error2 향후 호환성·미사용 commit_files 및 기존 Clippy 경고가 남아 있다. commit_files 경고는 호환성을 유지한 게이트웨이와 원래 구현 양쪽에서 표시될 수 있다.

## 수렴 검사

요구사항 7개·성공 기준 4개·수용 시나리오 9개와 옵션 처리·공통 정책·게이트웨이·설정 I/O 공유·진단·기존 스케줄링 보존을 실제 코드와 자동 검증에 대조했다. 누락·부분 충족·모순·요청 외 구현은 0개이며 후속 구현 작업은 없다. 미작성 헌장 템플릿의 규범 검사는 생략했다. tasks.md는 수렴 검사 중 변경하지 않았다. 실제 GUI 지연 조작은 별도 미검증 범위로 명시했다.
