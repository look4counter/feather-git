# 구현 계획: 응답성을 유지하는 백엔드 경계

> 정리 안내: 단계별 설계·작업 기록이며 후속 변경은 [현재 명세 색인](../README.md)과 해당 기능의 spec.md를 따른다. 기존 체크 상태와 과거 검증 이력은 현재 재검증 완료를 의미하지 않는다.

## 기존 구조 분석

공통 I/O 게이트웨이는 src/backend.rs에 있지만 UI가 동기 함수를 직접 호출할 수 있다. Workspace::refresh_panel_data·select_repository_row·viewer_changed·save_session·remember_current_repository와 DiffViewer::new/save_keys가 실제 동기 I/O 지점이다. 기존 복원·저장소 연결·diff 조회·쓰기에는 백그라운드 실행이 있으나 완료 콜백이 다시 동기 패널 갱신을 호출한다. HistoryState::new는 UI에서 그래프를 준비한다.

## 설계 및 영향 범위

- src/workspace_backend.rs 추가: 소유 데이터만 가진 패널/참조 요청과 결과, 파일 목록 변환, 백그라운드 조회를 담당한다. GPUI Window/Context/Rc를 넘기지 않는다.
- src/backend.rs: 기존 지연 정책을 유지하고 공통 spawn(executor, closure) 진입점을 제공한다. 테스트 전용 스레드 지역 정책 주입으로 UI의 백엔드 호출 부재를 검증한다.
- src/ui.rs: 상태 변경은 즉시 수행하고 요청을 큐에 기록한다. 렌더링 시작 시 공통 실행기로 대기 요청을 제출하고 완료 콜백에서 순수 결과 적용만 수행한다. 패널 요청 번호·프로젝트·파일 모드·커밋과 참조 선택 버전을 확인한다. 새 선택 시 이전 파일과 선택은 지우고 완료 전 빈 목록 안내는 숨긴다. 내부 진행 상태는 안전 가드로만 사용하며 로딩 표시를 만들지 않는다. 비활성 프로젝트 변경은 캐시를 지우고 재선택 시 조회한다.
- src/history.rs: Send 가능한 PreparedHistory와 UI 핸들 생성을 분리한다. 패널·참조·초기 복원 작업에서 그래프를 준비하고 결과 반영 시 UI 핸들만 만든다.
- src/session.rs: 이미 정규화된 경로를 받는 순수 최근 목록 갱신 함수를 제공한다. 기존 remember API는 경로 정규화 후 같은 순수 함수를 재사용해 호환성을 유지한다.
- 세션 저장: workspace_backend.rs의 Arc 기반 직렬 작성기가 짧은 메모리 잠금으로 최신 대기 스냅샷을 받아 별도 작업 스레드에서 저장한다. 대기 스냅샷은 병합하고 진행 중 저장은 먼저 완료해 순서를 보장한다. 결과 채널의 요청 번호로 오래된 오류를 무시한다. main.rs는 앱 이벤트 루프가 반환된 뒤 공유 작성기를 flush해 정상 종료 시 마지막 변경을 보존한다. UI 실행 중 flush를 호출하지 않는다.
- src/diff_viewer.rs: 단축키 초기 읽기·저장도 백그라운드로 분리한다. 초기 읽기/저장 버전과 편집 내용·폼 상태를 비교해 오래된 결과가 최근 편집을 덮지 않게 한다. 기존 diff 결과 버전 가드는 유지한다. 일반 조회의 불러오는 중 문구는 제거하고 쓰기 안전 가드·기존 오류 표시는 유지한다.
- 기존 테스트는 순수 UI 상태 전이와 실제 백엔드 결과 적용을 분리한다. 기존 동기 검증이 필요한 경우 테스트 전용 구동기가 요청을 다른 스레드에서 완료해 같은 적용 함수를 사용하며 운영 코드에 테스트용 동기 실행 분기를 넣지 않는다.

## 아키텍처·헌장 점검

헌장은 미작성 템플릿이므로 규범 검사는 생략한다. 게이트웨이·기존 데이터 형식과 의존성 방향을 유지하며 UI → 요청 → 백엔드 → 결과 → UI로 명확히 분리한다. 새 외부 의존성·공개 데이터 파괴 변경은 없다. 정상 종료 시 작성기를 배출하는 유한 대기는 데이터 유실 방지를 위한 것이며 숨겨진 테스트 프로세스를 남기지 않는다.

## 검증

채널로 완료를 지연시킨 뒤 UI 선택이 반환되는지, UI 스레드에서 게이트웨이가 호출되지 않는지 검증한다. 패널/참조 역순 성공·오류, 같은 커밋 재선택, 프로젝트·패널 변경, 닫힌 프로젝트를 검증한다. 직렬 작성기의 두 작업과 병합·실패·flush를 제어된 저장 함수로 검증한다. 실제 저장소·설정 회귀와 그래프 결과 일치를 유지한다.
cargo fmt --check, cargo test --offline, cargo check --offline, cargo clippy --offline --all-targets, cargo build --offline를 실행한다. GUI 직접 조작 미실행은 별도로 기록한다.

## 지연된 히스토리 로딩 안내 추가

기존 panel_waiting/panel_revision은 이미 요청 대기와 최신성을 표현하며 finish_panel과 invalidate_requests가 완료·선택 변경을 처리한다. files는 고정 커밋상세 행 아래의 목록 영역을 별도로 렌더링하므로 해당 영역에만 문구를 추가한다.

src/loading.rs에 공통 LOADING_DELAY=150ms와 재사용 가능한 DelayedLoading 상태를 둔다. 시작 시각·요청 번호·표시 여부만 관리하고 begin/reset/remaining/reveal을 제공해 실제 sleep 없이 경계 테스트를 한다. src/main.rs는 모듈을 등록한다.
src/ui.rs의 히스토리 요청 생성 시 시작 시각을 기록하고 기존 dispatch_pending이 백그라운드 작업과 GPUI 비차단 타이머를 함께 예약한다. 타이머는 남은 시간만 기다린다. 완료 공유 AtomicBool로 백엔드 응답이 UI보다 먼저 끝난 경우도 표시를 막는다. 타이머 콜백은 요청 버전·프로젝트 화면·히스토리 모드·panel_waiting·완료 여부를 검증한 후에만 표시하고 notify한다. 성공·오류 반영과 요청 무효화에서 상태를 초기화한다.
files의 목록 영역에 정확한 요청 문구를 기존 MUTED 텍스트 스타일로 표시한다. 스피너·오버레이·다른 패널 표시는 추가하지 않는다. 기존 비동기 백엔드·선택 보호·빈/오류 상태를 유지한다. 헌장·의존성·공개 저장소 API 변경은 없다.
검증은 공통 상수·149/150ms 경계·잔여 시간·중복 타이머·빠른 응답·완료 후 늦은 타이머·선택/모드/프로젝트 전환·오래된 완료/오류로 구성한다. 전체 테스트·형식·정적 검사·Clippy·빌드를 실행하고 시각 검증 여부를 구분한다.

## 로딩 안내 대기 시간 조정

사용자 요청에 따라 src/loading.rs의 공통 상수만 150ms로 변경한다. UI는 LOADING_DELAY와 remaining을 사용하므로 호출부 변경은 없다. 기존 경계 테스트를 149/150ms로 갱신하고 완료·오래된 요청·탐색 회귀를 검증한다. 기존 구조·데이터 형식·의존성·백엔드 자원 제한에는 영향이 없다.
