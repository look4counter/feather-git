# 기능 명세: 백엔드 지연에 막히지 않는 UI

> 문서 정리일: 2026-11-17. 본문은 이 기능의 단계별 요구사항 이력을 포함한다. 현재 유효 기준과 검증 한계는 [전체 명세 색인](../README.md)을 함께 확인한다. 과거 검증 기록은 현재 버전의 재검증 결과가 아니다.
> 후속 변경 참고: [025](../025-backend-resource-limits/spec.md) · [026](../026-list-delayed-loading/spec.md) · [028](../028-independent-repository-tabs/spec.md) · [035](../035-viewer-loading-message/spec.md) · [054](../054-scroll-axis-grid-loading/spec.md).
> 현재 기준: 현재 조회 로딩은 150ms 공통 정책이며 작업 트리·저장소 목록·파일 이력·뷰어에도 후속 명세에 따라 적용한다. 백엔드 동시 실행 상한은 2개다.

작성일: 2026-11-14 · 상태: 명확화 완료
입력: 백엔드와 프론트엔드를 분리하여 느린 백엔드에도 UI가 막히지 않게 하고 새 로딩 표시는 추가하지 않는다.

## 사용자 시나리오 및 검증

### 사용자 이야기 1 — 즉시 선택과 최신 결과 (우선순위: P1)

1. 커밋·프로젝트·참조·패널 탭을 선택하면 선택 상태가 즉시 바뀌고 조회는 백그라운드에서 수행한다.
2. 커밋 기록 선택 시 히스토리·커밋상세를 즉시 선택한다. 새 파일 결과가 오기 전 이전 커밋 파일을 잘못 선택하거나 변경하지 못한다.
3. A 다음 B를 선택했을 때 A의 늦은 성공·실패 결과가 B의 화면·선택·오류를 덮어쓰지 않는다.
4. 닫힌 프로젝트·시작 탭·다른 패널로 이동한 뒤 도착한 결과는 해당 화면에 적용하지 않는다.

독립 검증: 완료를 제어하는 요청으로 선택·조회 분리 및 역순 완료·닫기·탭 전환을 검증한다.

### 사용자 이야기 2 — 파일 작업과 설정도 비동기 (우선순위: P1)

1. 저장소 열기·복제·생성, 변경 파일·상세·diff 조회, 부분 스테이징·충돌 후 갱신이 UI 스레드에서 I/O를 하지 않는다.
2. 세션·최근 목록 변경은 즉시 화면에 반영하고 파일 저장은 백그라운드에서 순서대로 처리한다. 마지막 변경이 오래된 저장에 덮이지 않는다.
3. 단축키 설정의 초기 읽기와 적용도 UI를 막지 않고 실패를 기존 오류 영역에 표시한다.
4. 정상 종료 시 대기 중인 세션 저장을 유실하지 않으며 사용자 설정 파일·공개 데이터 형식은 유지한다.

독립 검증: 파일 저장 순서·최신값·오류·종료 배출과 지연 중 키 설정 변경의 경쟁 상태를 검증한다.

### 사용자 이야기 3 — 표시 추가 없이 지연 검증 (우선순위: P1)

1. 공통 백엔드 지연 옵션을 켜도 UI 이벤트 처리와 선택 갱신은 작업 완료를 기다리지 않는다.
2. 일반 조회 중 즉시 로딩 문구·스피너·오버레이를 표시하지 않는다. 추가 요청된 히스토리 목록의 150ms 지연 문구와 기존 시작 전용 화면·저장소 대화상자는 예외로 유지한다.
3. 기존 조회의 진행 문구도 커밋 전환 때 깜빡이지 않게 제거한다. 실제 빈 결과와 오류는 조회 완료 후 표시한다.

독립 검증: UI 상태 전이가 백엔드 게이트웨이를 호출하지 않는지 확인하고 지연된 결과의 올바른 반영을 검증한다.

### 사용자 이야기 4 — 느린 히스토리 조회만 안내 (우선순위: P1)

1. 커밋 행 선택 후 히스토리 파일 조회가 150ms 안에 끝나면 로딩 문구를 표시하지 않는다.
2. 150ms가 지나도 현재 요청의 응답이 없으면 히스토리 목록에 정확히 ‘조회 중 입니다..’를 표시한다.
3. 성공·실패 응답을 받으면 문구를 없애고 결과·기존 빈 상태·오류를 표시한다. 응답이 끝났지만 UI 반영이 늦은 경우에도 새 로딩 문구를 켜지 않는다.
4. 다른 커밋·프로젝트·작업 트리·시작 탭으로 바꾸거나 프로젝트를 닫으면 이전 타이머가 문구를 켜거나 최신 상태를 지우지 못한다.

독립 검증: 공통 지연값과 가상 시각으로 149/150ms 경계, 빠른 완료, 타이머/응답 역순 및 새 선택을 검증한다.

## 요구사항

- FR-001: UI는 선택·표시 상태만 갱신하며 저장소·파일·설정 I/O는 공통 백그라운드 실행 경로로 보낸다.
- FR-002: 패널·참조 조회에 요청 버전과 프로젝트·탭·커밋 식별자를 적용해 오래된 성공·실패를 무시한다.
- FR-003: 대기 중 이전 파일 데이터를 새 선택 대상으로 사용하지 않으며 유효한 최신 결과만 표시·변경한다.
- FR-004: 비활성 프로젝트의 변경은 캐시를 무효화하고 재선택 시 백그라운드에서 다시 조회한다.
- FR-005: 세션 저장은 직렬화·최신 대기값 병합으로 순서를 유지하고 오류를 알린다. 정상 앱 종료 후 대기 쓰기를 배출한다.
- FR-006: 최근 목록 갱신은 이미 정규화된 경로의 메모리 연산으로 처리하고 단축키 설정 읽기·쓰기를 비동기로 분리한다.
- FR-007: Git 기록 그래프 준비 등 조회에 딸린 무거운 계산도 백그라운드에서 처리하고 UI 전용 핸들은 UI에서만 만든다.
- FR-008: 일반 조회의 즉시 로딩 표시와 스피너는 추가하지 않는다. 추가 요청된 히스토리 파일 목록의 지연 문구 및 기존 시작 전용 화면·저장소 작업 화면은 유지한다.
- FR-009: 공통 지연·기존 API·설정 형식·선택 및 파일 변경의 안전성·오류 처리를 유지한다.

- FR-010: 공통 로딩 지연 설정을 150ms로 정의하고 히스토리 조회의 시작 시각부터 이 시간이 지난 뒤에만 ‘조회 중 입니다..’를 표시한다.
- FR-011: UI를 막지 않는 타이머와 기존 요청 버전 검사를 사용하고 완료·오류·무효화 때 문구를 해제한다. 백엔드 완료 여부도 확인해 이미 응답한 작업에는 문구를 켜지 않는다. 작업 트리에는 적용하지 않는다.

## 성공 기준

- SC-001: UI 상태 변경 테스트에서 백엔드 I/O 호출 0건이며 실제 작업은 다른 스레드에서 수행한다.
- SC-002: 역순 완료·재선택·프로젝트 닫기·시작/패널 전환·오류의 최신성 검증을 통과한다.
- SC-003: 직렬 저장·최신값·실패 복구·종료 배출과 단축키 비동기 경합 검증을 통과한다.
- SC-004: 전체 테스트·형식·정적 검사·빌드가 통과하고 실제 GUI 검증 범위를 명시한다.

- SC-005: 149ms 이전 미표시·150ms 도달 시 표시·빠른 완료/완료 후 미표시·선택 변경/오래된 타이머 무시를 자동 검증하고 공통 설정 한 곳에만 150ms를 정의한다.

## 경계 및 명확화

일반 선택·조회 흐름은 즉시 로딩 표시를 하지 않는다. 2026-11-14 추가 요청으로 히스토리 파일 목록의 150ms 지연 안내만 허용한다. 사용자가 앞서 요청한 초기 새/깃털 화면과 기존 저장소 대화상자는 유지한다. 백엔드 작업 자체의 취소를 보장하지는 않으며 오래된 완료는 폐기한다. 조회 대상이 바뀌면 파일 선택과 오래된 파일 데이터는 지워 오동작을 막고, 완료 전 빈 목록 안내 문구는 표시하지 않는다. 정상 종료 시 설정 저장을 마칠 때까지 창이 닫힌 뒤 프로세스가 잠시 대기할 수 있으나 UI 실행 중에는 기다리지 않는다. 추가 질문 없음.

추가 명확화: 히스토리 목록은 변경 파일 패널의 히스토리 탭을 의미한다. 공통 로딩 지연은 소스의 공유 설정이며 실행 옵션이나 사용자 설정 UI는 추가하지 않는다. 커밋 선택에서 발생하는 히스토리 조회와 같은 히스토리 탭의 재조회에 동일 정책을 적용한다. 추가 질문 없음.

2026-11-14 명확화 검토: 사용자 요청에 따라 로딩 안내 표시 대기만 150ms로 변경한다. 백엔드 인위적 지연 및 다른 타이머는 변경하지 않는다. 미해결 모호성은 없다.
