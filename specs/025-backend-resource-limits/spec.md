# 기능 명세: 백엔드 자원 사용 제한

## 사용자 시나리오와 검증

### 사용자 이야기 1 — 빠른 선택 변경 (우선순위 P1)

커밋·참조·파일 선택을 바꿔도 이전 조회가 쌓이지 않고 마지막 결과를 본다.
독립 검증: 지연 중 100회 조회를 교체하여 마지막 조회만 실행되는지 확인한다.
수용 시나리오: 대기 중 이전 조회는 실제 I/O 없이 종료하고, 실행 중 이전 결과는 최신 선택을 덮지 않는다. 프로젝트 닫기·시작 탭 전환·뷰어 비활성화는 이전 조회를 취소한다.

### 사용자 이야기 2 — 다른 작업의 반응성 보호 (우선순위 P1)

지연이 공용 실행기를 점유하거나 백엔드 동시 실행 수를 무제한 늘리지 않는다.
독립 검증: 동시 실행 상한, 대기 취소 및 오류·패닉 뒤 후속 작업 완료를 자동 검증한다.
수용 시나리오: 백엔드는 최대 2개 전용 스레드에서 실행한다. 쓰기는 선택 변경으로 취소하지 않는다. 기존 CLI와 중첩 지연은 유지한다.

### 경계 조건

- 이미 진입한 동기 Git 연산은 강제 종료하지 않고 다음 I/O 경계에서 취소한다.
- 취소는 오류 표시나 패닉 로그를 만들지 않으며 실제 오류와 패닉은 숨기지 않는다.
- 정상적인 CPU·디스크·GPU 사용까지 없애는 것은 불가능하다. 불필요한 자원을 제한하며 PC 전체의 반응성은 별도 측정한다.

## 요구사항

- FR-001: 앱 백엔드 작업은 최대 2개 전용 작업 스레드에서 실행하며 공용 실행기를 지연·수신 대기로 점유하지 않는다.
- FR-002: 패널·참조·diff 조회는 소유자별 최신 요청만 대기열에 유지하고 대체·비활성화·소멸 시 취소한다.
- FR-003: 지연 중 취소는 전체 지연을 기다리지 않고 깨어나 실제 I/O를 생략한다.
- FR-004: 기존 CLI 범위·기본값·중첩 지연·최신 결과 검증을 유지하며 변경·저장은 임의 취소하지 않는다.
- FR-005: Windows 공용 작업 제출은 일반 우선순위를 사용하고 시스템 전체 설정은 변경하지 않는다.
- FR-006: Git 작업 트리 상태 조회 내부의 병렬 작업 수도 제한한다.
- FR-007: 취소·지연·동시 실행·오류·패닉 복구를 자동 테스트한다.

## 주요 개체

- 조회 소유자: 새 선택·비활성화·소멸 시 현재 요청을 취소한다.
- 백엔드 작업: 취소 가능한 조회와 완료를 보장할 일반 작업을 구분한다.

## 성공 기준

- SC-001: 100회 조회 교체 시 동일 소유자의 실행 대기 조회는 최대 1개이며 취소된 조회는 실제 작업을 수행하지 않는다.
- SC-002: 동시 실행은 2개 이하이며 1500ms 지연 중 취소 요청은 1초 안에 반환한다.
- SC-003: 오류·패닉 이후 다음 요청과 일반 쓰기가 완료되고 기존 회귀 테스트가 통과한다.

## 가정과 명확화

명확화 단계 검토 결과 모든 범주에 구현을 막는 모호성이 없다. 읽기에만 취소를 적용하고 동기 Git 내부는 강제 중단하지 않는다. 공개 API와 저장 형식을 유지한다.
