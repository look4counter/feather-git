# 검증 결과

검증일: 2026-11-14

## 구현 결과

전용 작업 스레드 2개와 비동기 완료 전달을 도입했다. 공용 GPUI 실행기에서는 완료 Future만 기다리며 동기 I/O·지연·수신 대기는 전용 스레드로 이동했다. 기존 SessionWriter의 단일 저장 스레드와 종료 시 flush는 유지한다. 따라서 2개 상한은 backend::spawn과 조회 슬롯의 실행기 작업에 적용하며 프로세스 전체 스레드 수를 뜻하지 않는다.

조회 슬롯 교체·비활성화·소멸은 이전 토큰을 취소한다. 새 제출 시 취소된 대기 작업을 제거하여 캡처와 완료 대기를 해제한다. 지연 중인 조회는 조건변수 통지로 깨우며 실제 I/O를 생략한다. 동기 Git 내부에 진입한 작업은 강제 중단하지 않고 다음 gateway 또는 읽기 완료 경계에서 중단한다. 쓰기 작업은 취소 문맥을 사용하지 않는다.

Windows 공용 작업 제출은 Normal을 사용한다. 시스템 전체 우선순위나 타이머 설정은 변경하지 않는다. Git 상태 조회의 index/worktree 내부 작업 제한은 1이며 라이브러리의 디렉터리 순회 보조 스레드까지 없애는 설정은 아니다.

## 자동 검증

- 새 테스트를 먼저 연결한 실행은 실행기 타입이 아직 없어 컴파일 실패했다. 이후 구현을 연결하여 통과했다.
- cargo test --offline: 최종 164개 통과, 실패 0개, 기존 무시 2개.
- 새 실행기 테스트 6개: 동시 실행 상한 2 및 일반 작업 20개 완료, 100회 조회 교체 후 마지막 요청만 실행, 실제 1500ms 조건변수 대기 진입 후 취소 시 1초 이내 종료 및 I/O 0회, 진행 중 I/O 후 다음 경계 취소, 슬롯 소멸 취소·오류 보존·패닉 이후 작업 복구, 완료 Future 깨우기.
- 기존 UI 탐색 테스트에 프로젝트 전환·닫기·시작 탭·패널 전환의 조회 토큰 취소를 추가했다. 잘못된 탐색은 현재 요청을 취소하지 않는 것도 확인했다.
- 기존 backend gateway 지연·중첩·0값·오류·패닉 테스트와 최신 선택/저장 회귀 테스트가 통과했다.
- cargo fmt --check: 성공.
- cargo clippy --offline --all-targets: 성공. 기존 ui.rs의 collapsible_if, 기존 미사용 함수, GPUI의 실수 리터럴 및 의존성 미래 호환성 경고가 남는다. 새 실행기 경고는 없다.
- cargo check --offline 및 cargo build --offline: 성공.
- target/debug/feather-git.exe --backend-delay-ms 1500 --help: 종료 코드 0, 기존 한국어 도움말 출력.

## 미검증 범위와 한계

실제 GUI에서 0/1500 옵션을 번갈아 실행하며 CPU·GPU·디스크와 다른 프로그램 반응성을 비교하는 수동 측정은 수행하지 않았다. 기존 무시 테스트도 실행하지 않았다. 따라서 시스템 전체 무영향이나 체감 개선률을 측정한 것으로 보고하지 않는다. 이미 실행 중인 동기 외부 호출은 완료까지 자원을 사용할 수 있다.
