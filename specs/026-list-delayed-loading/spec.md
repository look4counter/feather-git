## 사용자 이야기와 수용 시나리오

### 사용자 이야기 1 — 히스토리 안내 유지 (우선순위 P1)

사용자는 커밋을 선택하면 현재와 동일하게 150ms 이후에만 히스토리 파일 목록의 ‘조회 중 입니다..’ 안내를 본다. 빠른 응답에는 문구가 나타나지 않는다.

독립 검증: 149/150ms 경계와 완료·오류·재선택·탐색 이후 상태를 확인한다.

수용 시나리오:
1. 요청 후 149ms에는 안내가 없고 150ms에 아직 진행 중이면 정확한 문구가 보인다.
2. 실제 백엔드가 완료되었으면 UI 완료 반영 전이라도 안내가 나타나지 않는다.
3. 새 선택·작업 트리 전환·프로젝트 닫기·시작 탭에서 이전 안내와 타이머가 남지 않는다.
4. 고정 커밋상세 행과 빈 목록·오류 표시 및 선택 안전성은 유지한다.

### 사용자 이야기 2 — 공통 목록 기능 재사용 (우선순위 P1)

개발자는 다른 목록에서도 공통 로딩 상태를 연결하여 지연 타이머와 문구를 재구현하지 않고 동일한 안내를 사용할 수 있다.

독립 검증: 두 목록 상태를 따로 생성하여 지연·완료·초기화가 서로 영향을 주지 않는지 확인한다.

수용 시나리오:
1. 히스토리 UI는 요청 시작·완료·무효화를 연결하고 목록 컴포넌트가 타이머와 문구를 담당한다.
2. 로딩 기능을 연결하지 않은 목록은 기존 가상화·스크롤·선택 동작을 유지한다.
3. 각 목록의 로딩 상태는 독립적이며 같은 상태를 복제하면 동일 요청을 관찰한다.

## 요구사항

- FR-001: 150ms 지연·공통 문구·표시 스타일을 공통 목록 기능으로 제공한다.
- FR-002: 목록 컴포넌트가 비차단 타이머 예약과 갱신을 담당하고 동일 요청의 렌더링마다 타이머를 추가하지 않는다.
- FR-003: 완료·오류·초기화·새 요청 시 이전 타이머와 완료 상태가 다음 요청에 영향을 주지 않는다. 닫힌 창이나 소멸한 목록에서 안전하게 종료한다.
- FR-004: 히스토리는 공통 기능을 사용하고 전용 타이머·문구 렌더링을 제거한다. 실제 백엔드 완료 신호를 유지한다.
- FR-005: 로딩 중 이전 행은 선택할 수 없고 기존 고정 행·오류·빈 결과·150ms 설정·백엔드 자원 제한을 유지한다.
- FR-006: 기존 목록 API는 호환되며 기능은 선택적으로 연결한다. 변경 파일 패널의 두 탭 외 다른 목록에 새 안내를 임의로 적용하지 않는다.
- FR-007: 지연 경계·요청 교체·완료 순서·독립성·기존 회귀를 자동 테스트한다.

## 주요 개체

- 목록 로딩 상태: 현재 요청 번호, 시작 시각, 표시 여부, 요청별 백엔드 완료 신호, 타이머 수명을 관리한다.
- 목록: 선택적으로 로딩 상태를 받아 진행 중에는 행 대신 지연 안내 영역을 렌더링한다.

## 성공 기준

- SC-001: 149ms 미표시·150ms 표시 및 완료 후 미표시를 자동 검증한다.
- SC-002: 히스토리 UI에 로딩 전용 타이머 예약과 문구 리터럴이 없고 공통 목록 연결만 남는다.
- SC-003: 서로 다른 목록과 이전 요청의 타이머·완료 신호가 현재 요청에 간섭하지 않는다.
- SC-004: 관련 테스트·포맷·정적 검사가 통과하고 빌드 및 GUI 검증 제한을 명시한다.

## 명확화 검토

List는 기존 VirtualList를 뜻한다. 150ms와 정확한 문구는 유지한다. 변경 파일 패널의 작업 트리·히스토리는 안내를 사용하고 그 외 목록은 자동 활성화하지 않는다. 기능·수명·오류·경계·성능·호환성 범주에 구현을 막는 미해결 모호성은 없다. 기존 실행 중인 앱은 강제 종료하지 않는다.

## 사용자 이야기 3 — 작업 트리 조회 안내 (우선순위 P1)

변경 파일의 작업 트리 탭에서도 백엔드 조회가 진행 중이면 공통 List의 지연 로딩 안내를 본다.

수용 시나리오: 작업 트리 조회 후 149ms에는 문구가 없고 150ms에 진행 중이면 기존 공통 문구를 표시한다. 실제 백엔드가 빨리 완료되었으면 표시하지 않는다. 성공·빈 결과·오류 후 안내가 사라지고 탭 전환 시 이전 타이머·완료 신호·결과가 새 안내를 변경하지 않는다.

- FR-008: 변경 파일 패널의 작업 트리 조회 시작과 대기 목록 렌더링에도 공통 로딩 핸들을 연결한다. 두 탭에 150ms와 동일한 문구·완료/무효화 정책을 사용한다.
- SC-005: 작업 트리의 시작·149/150ms·빠른 완료·성공/빈 결과/오류·탭 전환의 이전 요청 격리를 자동 검증한다.

추가 명확화: 사용자 요청은 변경 파일 패널의 작업 트리 탭에 기존 공통 안내를 활성화하는 것이다. 별도 타이머나 문구는 추가하지 않는다. 미해결 모호성은 없다.
