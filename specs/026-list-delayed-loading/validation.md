# 검증 결과: 공통 목록 지연 로딩 안내

검증일: 2026-11-14

## 변경 결과

src/virtual_list.rs의 ListLoading과 VirtualList::loading으로 지연 상태·타이머·공통 문구를 제공한다. 기존 src/loading.rs의 DelayedLoading과 150ms 상수를 재사용한다. 히스토리 UI는 요청 시작·완료 신호·결과 적용과 무효화만 연결하며 전용 타이머와 문구 리터럴을 제거했다.

진행 중에는 행과 선택 이벤트·스크롤바를 렌더링하지 않고 헤더를 유지한다. 히스토리의 고정 커밋상세 행은 목록 바깥의 기존 위치를 유지한다. 기본 loading=None인 다른 목록은 기존 경로로 렌더링한다. 새로운 안내를 다른 목록에 임의 적용하지 않았다.

## 자동 검증

- 공통 핸들 테스트를 먼저 연결하여 구현 전 타입 부재로 실패함을 확인했다.
- cargo test --offline: 최종 168개 통과, 실패 0개, 기존 수동 성능 측정 무시 2개.
- 신규 공통 목록 테스트 4개: 149/150ms 경계와 완료 후 초기화, 복제 공유·서로 다른 목록 및 이전 요청 완료 신호 독립성, 실제 백엔드가 UI 적용보다 먼저 완료한 경우 안내 억제, 반복 렌더링 10회 예약 1회·새 요청 재예약·초기화/완료 뒤 예약 없음·소멸 후 약한 참조 해제.
- 기존 UI의 빠른 응답·오래된 타이머·역순 결과·오류·재선택·탐색 회귀와 가상화·스크롤·선택 테스트가 통과했다. 히스토리 경계 테스트의 기존 99ms 입력은 149ms로 갱신했다.
- cargo fmt --check, cargo check --offline, cargo clippy --offline --all-targets: 성공. 기존 미사용 함수·UI collapsible_if·GPUI 실수 리터럴 및 의존성 미래 호환성 경고만 남는다.
- cargo build --offline: 컴파일·링크는 완료했지만 실행 중인 target/debug/feather-git.exe 교체가 접근 거부(os error 5)로 실패했다. 실행 중 앱은 종료하지 않았다.
- 최신 링크 산출물 target/debug/deps/feather_git.exe를 target/feather-git-list-loading.exe로 복사했다. SHA-256 일치를 확인했고 별도 실행 파일 --help가 종료 코드 0으로 기존 도움말을 출력했다.

## 남은 적용 및 미검증 범위

기본 target/debug/feather-git.exe는 실행 중 파일 잠금 때문에 갱신하지 못했다. 앱을 종료한 후 cargo build --offline를 다시 실행하면 기본 경로에 적용할 수 있다. 별도 빌드 산출물은 위 경로에 준비했다. 실제 GUI의 타이머 갱신·문구 배치·헤더와 스크롤 전환은 수동으로 확인하지 않았다. 자동 테스트와 소스 검토 결과를 시각 검증으로 대신 보고하지 않는다.

## 수렴 결과

요구사항 7개, 성공 기준 4개, 사용자 이야기 2개 및 계획의 상태 소유·비차단 타이머·Weak 수명·히스토리 연결·기본 호환성·검증 항목을 실제 코드와 대조했다. 구현 누락·부분 구현·모순·범위 외 변경은 0건이며 추가 구현 작업은 없다. 헌법은 미작성 템플릿이므로 규범 검사를 생략하고 AGENTS.md의 계층·호환성·기존 변경 보존을 확인했다. 기본 실행 파일 교체 실패와 GUI 미검증은 위 제한으로 남긴다. 수렴 점검 중 코드와 작업 목록은 변경하지 않았고, 점검 후 구현 결과 기록에서 T007을 완료 표시했다.

## 작업 트리 탭 안내 연결 검증

- 원인은 src/ui.rs의 히스토리 전용 조건 세 곳이었다. 로딩 begin, ListLoading 연결, 비어 있는 대기 목록 렌더링이 모두 file_history에 제한되어 작업 트리 조회에는 안내가 없었다.
- 유효한 패널 조회의 공통 begin, 변경 파일 List의 항상 연결, panel_waiting 중 빈 목록 렌더링으로 변경했다. 기존 List의 150ms·문구·타이머·완료 신호를 그대로 사용한다. 기존 고정 커밋상세 행과 오류·빈 결과 정책 및 다른 목록은 유지한다.
- 재현 테스트를 먼저 추가하여 작업 트리에서 panel_loading.is_pending()이 false라 실패함을 확인했다. 수정 후 신규 테스트 3개로 작업 트리 시작·149/150ms·빠른 완료·성공/빈 결과/오류·히스토리에서 전환 후 이전 신호/타이머/결과 격리를 검증했다.
- 최종 cargo test --offline: 171개 통과, 실패 0개, 기존 수동 성능 측정 무시 2개. cargo fmt --check, cargo check --offline, cargo clippy --offline --all-targets 성공. 기존 경고만 남는다.
- cargo build --offline는 컴파일·링크 후 실행 중인 기본 target/debug/feather-git.exe 교체가 os error 5로 실패했다. 강제 종료하지 않았다. 최신 링크 결과를 target/feather-git-worktree-loading.exe로 복사해 SHA-256 일치 및 --help 종료 코드 0을 확인했다. GUI 직접 표시는 미검증이다.

추가 수렴 점검: FR-008과 SC-005 및 사용자 이야기 3을 기존 요구사항과 함께 대조했다. 히스토리 제한 세 곳이 제거되고 두 탭의 공통 시작·완료·무효화와 이전 요청 격리 및 회귀 검증이 일치한다. 구현 누락·모순·불필요한 새 타이머/문구는 0건이며 추가 구현 작업은 없다. 기본 실행 파일 잠금과 GUI 미검증은 위 제한으로 남긴다. 수렴 점검 후 작업 결과 기록에서 T011을 완료 표시했다.
