# 기능 명세: 히스토리 커밋상세를 목록 항목으로 표시

## 사용자 이야기와 수용 기준

### 사용자 이야기 1 — 조회 완료 후 목록에서 커밋상세 확인 (우선순위 P1)

히스토리를 조회하는 동안 고정 커밋상세 행을 보지 않고, 조회 성공 후 ‘커밋상세’라는 이름의 항목을 변경 파일 목록에서 본다. 기존 아이콘을 유지한다.

독립 검증: 대기·지연 안내·성공·빈 변경·실패 시 목록 항목 수와 구성을 확인한다.
수용 시나리오: 조회 대기 중 커밋상세 행이 없고 기존 150ms 공통 로딩 안내만 적용된다. 성공하면 커밋상세가 첫 행이며 일반 파일과 함께 스크롤된다. 변경 파일 0개인 유효 커밋도 커밋상세 한 행을 표시한다. 오류·유효 커밋 없음·작업 트리에는 이 항목을 표시하지 않는다.

### 사용자 이야기 2 — 상세와 실제 파일 선택 (우선순위 P1)

커밋상세 항목은 기존 상세 뷰를 열고 파일 항목은 해당 파일 diff를 연다. 표시 이름이 같은 실제 파일도 안전하게 선택할 수 있다.

독립 검증: 상세 행과 첫/마지막 실제 파일을 순서대로 선택하여 대상·선택 강조를 확인한다.
수용 시나리오: 성공 후 기본 선택은 커밋상세이며 실제 파일 선택은 첫 행 추가 때문에 한 칸 어긋나지 않는다. 같은 이름의 실제 파일은 별도 파일로 취급한다. 재선택·탭/프로젝트 전환 후 이전 이벤트가 현재 선택을 바꾸지 않는다.

## 요구사항

- FR-001: 히스토리 조회 성공 후 커밋상세를 동일한 가상 목록의 첫 항목으로 표시하고 기존 고정 행을 제거한다.
- FR-002: 대기·오류·커밋 없음·작업 트리에서 커밋상세 항목을 숨긴다. 유효 커밋의 빈 변경 결과에는 상세 항목만 표시하고 잘못된 빈 목록 안내를 표시하지 않는다.
- FR-003: ‘커밋상세’ 이름과 기존 아이콘·상세 뷰 동작·기본 상세 선택을 유지하고 일반 행 선택/스크롤을 사용한다.
- FR-004: 표시 행 번호와 실제 파일 번호를 명확히 변환하여 첫/마지막 파일과 동명 파일도 정확히 선택한다. 실제 파일 데이터와 백엔드 API는 변경하지 않는다.
- FR-005: 기존 150ms 공통 로딩, 최신 요청 검증, 작업 트리, 오류 표시와 실제 파일 개수 배지는 유지한다.
- FR-006: 대기/성공/빈 결과/오류/커밋 없음·선택 매핑·이전 이벤트·기존 회귀를 자동 테스트한다.

## 개체

표시 목록은 선택적 상세 첫 행과 실제 변경 파일 행으로 구성한다. 상세 행은 파일 데이터가 아닌 UI 항목이다. 기존 실제 파일 선택 번호와 뷰어 대상은 유지한다.

## 성공 기준

- SC-001: 로딩 중 상세 행 0개, 정상 성공 시 상세 행 1개, 빈 변경의 유효 커밋은 전체 표시 행 1개다.
- SC-002: 상세·첫/마지막 파일·동명 파일의 표시 번호와 뷰어 대상이 일치하고 잘못된/오래된 이벤트는 무시된다.
- SC-003: 관련 테스트·전체 회귀·포맷·정적 검사를 통과하며 빌드와 GUI 검증 제한을 보고한다.

## 명확화와 경계

표시 위치는 기존처럼 첫 번째이며 목록 내부로만 이동한다. 커밋 선택에 따른 기존 상세 뷰 자동 선택 동작은 유지한다. 변경 파일 배지는 실제 변경 파일 수만 센다. 조회 실패 시 오류를 표시하며 성공한 척 상세 행을 추가하지 않는다. 저장소의 실제 파일명과 합성 항목은 문자열로 구분하지 않는다. 구현을 막는 모호성은 없다.
