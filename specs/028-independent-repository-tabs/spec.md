# 기능 명세: 저장소 탭 전환과 변경 파일 조회 분리

> 문서 정리일: 2026-11-17. 본문은 이 기능의 단계별 요구사항 이력을 포함한다. 현재 유효 기준과 검증 한계는 [전체 명세 색인](../README.md)을 함께 확인한다. 과거 검증 기록은 현재 버전의 재검증 결과가 아니다.
> 후속 변경 참고: [035](../035-viewer-loading-message/spec.md) · [080](../080-history-revert-reset/spec.md).
> 현재 기준: 현재 저장소에는 찾기 탭도 있다. 파일 패널 독립성은 유지하고 찾기 선택·메뉴·Enter는 080을 따른다.

작성일: 2026-11-14 · 상태: 검증 완료

## 사용자 이야기와 수용 시나리오

### 사용자 이야기 1 — 변경 파일을 유지하며 저장소 탭 전환 (우선순위 P1)

로컬·원격·태그·스태시 탭을 바꿔도 변경 파일 목록·선택·뷰어·스크롤이 그대로 유지된다.
독립 검증: 작업 트리와 히스토리에서 파일을 선택하고 네 저장소 탭을 교차 전환한다.
수용 시나리오: 탭 전환으로 파일 조회가 새로 예약되지 않고 완료된 목록의 로딩 안내가 다시 나타나지 않는다. 이미 진행 중인 파일 조회는 취소/초기화되지 않고 정상 반영된다. 커밋·프로젝트·파일 모드 변경과 실제 파일 변경은 필요한 파일 갱신을 수행하며 저장소 목록 갱신은 프로젝트 문맥 변경에만 함께 수행한다.

### 사용자 이야기 2 — 해당 저장소 목록만 최신 결과 반영 (우선순위 P1)

태그·스태시는 백그라운드에서 해당 참조 목록만 읽고 로컬·원격은 기존에 읽어둔 목록을 표시한다.
독립 검증: 태그와 스태시 결과를 역순 완료하고 다른 탭·프로젝트 이동 뒤 이전 결과를 적용한다.
수용 시나리오: 이전 탭 결과·오류가 현재 목록을 덮지 않고, 조회 실패는 해당 저장소 패널에만 반영된다. 저장소 탭이 바뀌면 이전 참조 행 선택 작업을 무효화하되 파일 패널은 유지한다.

## 요구사항

- FR-001: 저장소 탭 전환은 변경 파일 데이터·선택·뷰어·스크롤·요청 번호·로딩 수명에 영향을 주지 않는다.
- FR-002: 탭 전환으로 변경 파일 조회를 예약하지 않으며 진행 중인 파일 조회도 취소하지 않는다.
- FR-003: 태그·스태시 목록 조회를 파일 조회와 독립적으로 실행하고 최신 저장소 요청 번호·프로젝트·경로·탭을 검증한다.
- FR-004: 로컬·원격은 기존 스냅샷을 유지하고 추가 파일 조회나 강제 재조회 정책을 도입하지 않는다. 같은 활성 탭 재선택은 불필요한 재조회 없이 유지한다.
- FR-005: 탭 전환은 저장소 행 선택과 이전 참조 선택 요청만 초기화한다. 이전 목록 결과/오류는 폐기하고 현재 오류·빈 결과는 해당 목록에 표시한다.
- FR-006: 커밋/프로젝트/파일 모드/파일 변경의 기존 갱신과 150ms 공통 로딩·커밋상세 행·백엔드 실행 상한을 유지한다.
- FR-007: 보존·진행 중 완료·태그/스태시 단독 I/O·역순/실패/전환 무효화·기존 회귀를 자동 테스트한다.

## 주요 개체

- 변경 파일 요청: 파일과 그래프 준비만 담당한다.
- 저장소 목록 요청: 태그/스태시 모드와 프로젝트·경로·요청 번호를 포함한다.
- 참조 행 선택 요청: 목록 조회와 별개로 선택한 참조의 커밋을 찾는 기존 요청이다.

## 성공 기준

- SC-001: 두 파일 모드에서 저장소 탭 전환 후 변경 파일 요청 번호·선택·뷰어·스크롤이 같고 새 파일 요청 수는 0이다.
- SC-002: 탭 전환 중 기존 파일 요청 완료를 반영하고 태그/스태시 요청의 실제 gateway 호출은 참조 목록 조회뿐이다.
- SC-003: 역순 결과·오류와 다른 탭/프로젝트·닫힌 프로젝트의 결과를 안전하게 거절한다.
- SC-004: 전체 회귀·포맷·정적 검사를 통과하고 빌드/GUI 검증 범위를 보고한다.

## 명확화와 경계

참조 목록과 파일 목록을 분리하되 로컬·원격·태그·스태시의 기존 데이터 취득 정책은 유지한다. 참조 행 클릭으로 실제 커밋 선택이 바뀌면 파일을 갱신한다. 저장소 탭 전환 자체는 커밋 선택이 아니다. 미해결 모호성은 없다.

## 사용자 이야기 3 — 태그·스태시 지연 로딩 안내 (우선순위 P1)

태그나 스태시 조회가 오래 걸리면 저장소 목록 영역에서 기존 공통 List의 안내를 본다.
수용 시나리오: 149ms에는 안내가 없고 150ms에도 진행 중이면 공통 문구가 나타난다. 빠른 실제 완료는 안내를 억제하고 성공·빈 결과·오류 후에는 사라진다. 다른 탭/프로젝트 이동과 새 요청은 이전 안내·타이머·완료 신호를 무효화한다. 변경 파일 패널의 로딩·데이터·선택은 영향을 받지 않는다.

- FR-008: 태그·스태시 목록 조회에 기존 150ms 공통 ListLoading을 연결한다. 독립된 목록 핸들을 사용하고 요청 시작·실제 백엔드 완료·결과 반영·무효화 수명을 연결한다. 로컬·원격에는 새 안내를 표시하지 않는다.
- SC-005: 두 탭의 시작·149/150ms·빠른 완료·성공/빈 결과/오류·탭 전환 및 이전 요청 격리를 자동 검증하며 파일 패널의 상태를 유지한다.

추가 명확화: 기존 ‘조회 중 입니다..’ 공통 문구와 150ms를 그대로 사용한다. 별도 지연 옵션이나 타이머·스피너는 추가하지 않는다. 미해결 모호성은 없다.

## 사용자 이야기 4 — 파일 탭·커밋 선택에서도 저장소 목록 유지 (우선순위 P1)

변경 파일의 작업 트리/히스토리 탭 전환과 커밋 기록 행 선택은 필요한 파일만 조회한다. 저장소 목록을 다시 조회하거나 지연 안내를 재시작하지 않는다.

수용 시나리오: 두 파일 탭을 교차 선택하거나 다른/같은 커밋을 선택해도 저장소 목록 데이터·오류·요청 번호·로딩 수명·스크롤·진행 중 목록 요청이 유지된다. 파일 탭은 저장소 행 선택과 진행 중 참조 선택도 유지한다. 커밋 선택은 기존처럼 참조 행 선택을 무효화하여 늦은 참조 선택 결과가 새 커밋을 덮지 않게 하되 참조 목록 자체는 유지한다. 프로젝트 전환/저장소 열기/시작 탭에서는 전체 문맥을 갱신/무효화한다.

- FR-009: 파일 탭 전환·커밋 선택·활성 작업 트리 파일 변경의 파일 갱신은 저장소 목록 요청·데이터·로딩·스크롤을 건드리지 않는다. 프로젝트 문맥 변경은 두 패널 갱신을 유지한다.
- SC-006: 로컬/원격/태그/스태시의 완료/오류/진행 중 상태에서 파일 탭·커밋 전환 후 참조 목록 조회 예약이 0이고 기존 목록 요청 완료를 반영함을 자동 검증한다. 프로젝트 전환과 참조 선택 무효화 회귀도 검증한다.

추가 명확화: 파일 목록 요청과 저장소 목록 요청의 무효화 수명을 양방향 분리한다. 기존 커밋 행 선택에 따른 기본 상세 선택과 파일 재조회는 유지한다. 미해결 모호성은 없다.
