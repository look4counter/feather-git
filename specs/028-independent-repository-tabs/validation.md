# 검증 결과: 저장소 탭과 변경 파일 조회 분리

검증일: 2026-11-14

## 구현 결과

src/ui.rs의 저장소 탭 클릭은 select_repository_tab으로 분리했다. 저장소 목록과 이전 참조 행 선택만 무효화하며 변경 파일 목록·선택·뷰어·스크롤·panel_revision·ListLoading·진행 중 파일 조회를 유지한다. 파일 탭과 실제 커밋/프로젝트/파일 변경은 기존 전체 갱신을 사용한다.

src/workspace_backend.rs의 PanelRequest/PanelResult에서 참조 목록 필드를 분리하고 RepositoryListRequest/RepositoryListResult를 추가했다. 태그/스태시 요청은 기존 repository::panel_references만 호출하며 별도 요청 번호·ReadSlot·완료 검증을 사용한다. 파일 완료는 참조 목록을 변경하지 않는다. 로컬/원격 스냅샷 정책과 기존 2개 전용 실행 스레드는 유지한다. 기본 미변경 탭 재선택은 추가 요청을 만들지 않는다.

## 자동 검증

- UI 재현 테스트를 먼저 연결하여 구현 전 전용 탭 메서드/목록 상태 부재로 실패함을 확인했다.
- 신규 UI 테스트 4개: 두 파일 모드의 데이터·선택·뷰어·스크롤·파일 요청 번호·로딩·취소 토큰 보존, 진행 중 파일 요청과 완료 신호 보존 및 정상 완료, 태그/스태시 역순 오류·현재 오류·경로/프로젝트 닫기 무효화, 이전 참조 행 선택만 취소.
- 신규 백엔드 테스트 1개: 태그/스태시 각각의 성공/없는 경로 오류에서 gateway 호출이 repository::panel_references 1회뿐이고 파일 조회가 없음을 실제 요청으로 확인했다.
- 테스트 구동기는 새 목록 요청도 별도 스레드에서 완료하여 실제 결과 반영 메서드를 사용한다. 기존 늦은 파일 결과 테스트는 제거된 참조 필드 주입만 삭제하고 파일·참조 상태 보존 검증은 유지했다. 이전 참조 목록 오류는 전용 목록 테스트에서 검증한다.
- cargo test --offline: 179개 통과, 실패 0개, 기존 수동 성능 측정 무시 2개. 이번 전체 실행은 약 164초가 걸렸다.
- cargo fmt --check, cargo check --offline, cargo clippy --offline --all-targets: 성공. 기존 미사용 함수·UI collapsible_if·GPUI 실수 리터럴 및 의존성 미래 호환성 경고만 남는다.
- cargo build --offline: 컴파일·링크 후 실행 중인 target/debug/feather-git.exe 교체가 접근 거부(os error 5)로 실패했다. 실행 중 앱은 강제 종료하지 않았다.
- 최신 target/debug/deps/feather_git.exe를 target/feather-git-repository-tabs.exe로 복사하여 SHA-256 일치와 --help 종료 코드 0을 확인했다.

## 미검증 및 적용 제한

실제 GUI에서 탭을 바꾸며 목록·선택·스크롤과 로딩 안내가 유지되는지 수동 확인하지 않았다. 기본 실행 파일은 앱 종료 후 재빌드가 필요하며 별도 실행 산출물은 위 경로에 준비했다. 기존 무시된 성능 측정 테스트도 실행하지 않았다. 자동 검증을 GUI 체감 검증으로 보고하지 않는다.

## 태그·스태시 공통 지연 로딩 안내 검증

- src/ui.rs에 파일 패널과 별개인 repository_loading: ListLoading을 연결했다. 유효한 태그/스태시 요청 시작에 begin하고, 실제 백엔드 완료 신호를 저장하며, 유효한 결과 적용·새 요청·무효화에서 reset한다.
- 저장소 VirtualList에 핸들을 연결하고 이름 목록이 비어 있어도 repository_waiting이면 목록을 렌더링한다. 기존 공통 150ms·문구·타이머를 재사용하며 새 타이머/문구/백엔드 조회를 추가하지 않았다. 로컬/원격은 로딩 핸들이 비활성이다.
- 신규 테스트 3개를 먼저 연결하여 구현 전 필드 부재로 실패함을 확인했다. 수정 후 태그/스태시 각각의 시작·149/150ms·빠른 실제 완료·빈 결과/오류·정상 완료·이전 완료 신호/타이머/결과 격리·로컬/원격 및 시작 탭 이동 초기화를 검증했다. 파일 로딩/요청 번호/뷰어를 유지하는 검증도 포함한다.
- cargo test --offline: 최종 182개 통과, 실패 0개, 기존 수동 성능 측정 무시 2개. cargo fmt --check, cargo check --offline, cargo clippy --offline --all-targets 성공. 기존 경고만 남는다.
- cargo build --offline는 컴파일·링크 후 실행 중인 기본 target/debug/feather-git.exe 교체가 os error 5로 실패했다. 최신 링크 산출물을 target/feather-git-reference-loading.exe로 복사하여 SHA-256 일치와 --help 종료 코드 0을 확인했다. 기본 exe 적용은 앱 종료 후 재빌드가 필요하다. GUI 직접 표시는 미검증이다.

## 파일 탭 전환·커밋 선택의 반대 방향 결합 수정

- 원인은 두 경로가 refresh_panel_data를 호출해 저장소 상태까지 무효화·초기화하고 refresh_repository_list를 재예약한 것이었다.
- src/ui.rs의 파일 요청 무효화와 refresh_file_data를 분리하여 파일 탭·커밋 선택·활성 파일 변경에 연결했다. 파일 전용 경로는 저장소 목록 데이터·오류·요청 번호·로딩 핸들/완료 신호·스크롤·진행 중 목록 요청을 유지한다. 파일 탭은 참조 행 선택도 유지하고 커밋 선택은 기존처럼 이전 참조 행 선택을 무효화한다.
