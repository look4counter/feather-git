## 사용자 이야기와 수용 기준

### 사용자 이야기 1 — 대화상자 제출 후 전역 진행 표시 (우선순위 P1)

저장소 열기·생성·복제를 제출하면 입력 대화상자가 닫히고 앱 창 전체를 덮는 기존 ProgressOverlay가 나타난다.
수용 시나리오: 작업은 백그라운드에서 실행하고 중복 제출과 배경 입력을 차단한다. 성공 시 오버레이를 해제하고 프로젝트를 활성화한다. 실패 시 오버레이를 해제하고 오류를 알리며 이전 작업 공간을 유지한다. 취소·폴더 선택 단계에는 작업 진행 오버레이를 띄우지 않는다.
독립 검증: 세 작업의 시작·중복 방지·성공·실패 상태 전이와 포커스/입력 연결을 확인한다.

### 사용자 이야기 2 — 최근 저장소 열기의 동일한 진행 표시 (우선순위 P1)

최근 저장소를 클릭하면 기존 인라인 문구 대신 전역 오버레이를 사용한다. 완료와 오류는 첫 사용자 이야기와 같은 수명을 사용한다.
독립 검증: 기존 최근 저장소 재열기·실패 보존 테스트와 공통 작업 상태 테스트를 수행한다.

### 사용자 이야기 3 — 최근 저장소 이름·경로 가독성 (우선순위 P1)

사용자는 최근 저장소 이름과 경로가 모두 ‘...’로만 보인다고 보고했다. 각 카드가 최근 목록 영역의 폭을 사용하여 이름·경로를 각각 표시하고, 실제로 넘치는 경우에만 말줄임을 적용한다.
독립 검증: 저장된 값의 보존과 렌더링 폭/높이 제약을 확인하고 가능한 경우 GUI를 확인한다.

## 요구사항

- FR-001: 대화상자 제출 시 입력 창을 닫고 ProgressOverlay를 앱 루트의 최상위 오버레이로 렌더링한다.
- FR-002: 최근 저장소도 같은 전역 작업 상태·오버레이를 사용하고 기존 인라인 열기 문구를 제거한다.
- FR-003: 진행 중 마우스·스크롤·키보드 배경 입력과 중복 열기/탐색을 차단하고 이전 드래그를 취소한다. 포커스를 오버레이로 옮기고 완료 후 복원한다.
- FR-004: 성공·실패·창 종료에서 안전하게 종료한다. 실패는 닫힌 대화상자 엔티티에 의존하지 않고 기존 오류 경로를 사용하며 프로젝트·최근 목록을 임의 변경하지 않는다.
- FR-005: 기존 시작 전용 화면과 목록의 150ms 지연 안내·백엔드 실행 상한·저장 계약은 유지한다.
- FR-006: 최근 목록·카드·이름/경로 행에 실제 가용 폭을 전달하고 두 텍스트의 읽을 수 있는 높이를 확보한다. 이름·경로 데이터와 저장 형식은 변경하지 않는다.
- FR-007: 상태 전이·중복/입력 차단·성공/실패·최근 목록 회귀·전체 테스트를 검증하고 GUI 접근 제한을 명시한다.

## 주요 개체

전역 저장소 작업 상태는 실행 중인 작업 종류 또는 없음이다. 전역 진행 포커스와 복귀 포커스를 별도로 보유한다. 입력 대화상자는 유휴/폴더 선택 단계만 담당한다. 최근 저장소 데이터 형식은 유지한다.

## 성공 기준

- SC-001: 열기·생성·복제와 최근 열기에 진행 표시 수명이 하나이고 작업 중 새 요청은 거절한다.
- SC-002: 성공과 실패 후 진행 상태가 해제되고 기존 재열기·실패 시 상태 보존 테스트가 통과한다.
- SC-003: 대화상자 내부 진행 표시와 최근 저장소 인라인 작업 문구가 제거되며 전역 루트에서 기존 오버레이를 사용한다.
- SC-004: 최근 이름/경로 폭과 줄 높이를 명시하고 저장 데이터/동작 회귀를 유지한다. 자동 테스트·빌드·정적 검사 및 실제 GUI 검증 범위를 보고한다.

## 명확화와 경계

전역은 Feather Git 앱 창 전체이며 운영체제나 다른 앱을 덮지 않는다. 작업 완료 후 대화상자는 자동으로 다시 열지 않고 오류만 기존 경고로 표시한다. 사용자는 최근 이름·경로가 둘 다 말줄임만 보인다고 명확히 답했다. 화면 접근은 자동 승인 검토가 거절했으므로 원인 판단은 저장 값과 코드에 근거하며 시각 검증으로 단정하지 않는다. 미해결 모호성은 없다.
