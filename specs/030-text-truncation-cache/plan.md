# 구현 계획: 말줄임 측정 캐시의 폭 검증

## 기존 구조와 실제 원인

src/ui.rs의 최근 저장소 이름과 경로는 기존 값에 truncate를 적용한다. 앞선 명시적 폭·높이 보완은 유지한다. vendor/gpui/src/elements/text.rs의 TextLayout::layout은 Taffy의 측정 콜백에서 wrap_width와 truncate_width를 계산한다. 한 줄 텍스트는 wrap_width=None인데, 캐시 조건이 wrap_width.is_none()이면 항상 이전 size를 반환한다. 따라서 최초 좁은 폭에서 만들어진 ‘...’가 실제로 폭이 넓어진 뒤에도 재사용될 수 있다.

동시에 truncate_line은 전달된 runs를 짧게 변경한다. 기존 클로저가 외부의 mutable runs를 재사용하므로 캐시를 바로잡아 재측정을 하더라도 이전 잘라내기의 스타일 길이가 남을 수 있다. 원본 텍스트는 유지되지만 스타일 구간도 재측정마다 원본에서 시작해야 한다.

## 설계 및 변경 파일

- vendor/gpui/src/elements/text_layout_cache.rs: 폭 캐시 재사용 판정을 독립적인 작은 순수 함수로 추출한다. 줄바꿈 폭과 말줄임 폭이 모두 같아야 재사용한다. 외부 API를 추가하지 않고 부모 text 모듈에서만 사용한다.
- vendor/gpui/src/elements/text.rs: 기존 캐시 구조에 truncate_width를 보관하고 성공·실패 결과 모두 실제 폭 조건을 기록한다. 캐시 판정은 위 함수와 size 존재 여부를 사용한다. 원본 runs는 불변으로 캡처하고 캐시 미스마다 clone하여 truncate_line에 전달한다. 캐시 히트 때 불필요한 복사는 하지 않는다.
- src/main.rs: 테스트 빌드에서만 위 순수 운영 소스를 path 모듈로 포함한다. 기존 Windows IME 회귀 테스트의 vendor 소스 직접 검증 방식과 동일하며 테스트 전용 재구현을 만들지 않는다. 새 의존성이나 GPUI test-support 기능은 추가하지 않는다.
- src/ui.rs와 이전 전역 진행 표시·최근 목록 데이터/레이아웃은 변경하지 않는다.

## 헌법 및 영향 범위

헌법은 미작성 템플릿으로 규범 검사를 생략한다. AGENTS.md의 실제 원인 확인·중복 제거·기존 아키텍처/데이터/공개 API 보존·최소 변경을 준수한다. 공급된 GPUI의 내부 측정 캐시 오류 수정이며 의존성 교체나 공개 API 변경은 없다. 같은 텍스트 경로를 쓰는 다른 말줄임/줄바꿈 요소도 올바른 폭으로 재측정된다.

## 검증 전략

기존 판정을 순수 함수로 동일하게 옮기고 운영 경로를 연결한 상태에서 테스트를 먼저 실패시킨다. 0→넓음, 좁음→넓음, 넓음→좁음, 말줄임 제한 없음↔있음, 줄바꿈 폭/모드 변경, 같은 조건의 재사용을 검증한다. 이후 조건과 기록을 수정한다. 실제 운영 소스를 테스트하되 글꼴 측정/화면을 흉내 내는 별도 구현은 만들지 않는다. 스타일 원본 보존은 실제 clone 위치와 truncate_line의 변경 동작을 소스 검토한다.

전체 cargo test --offline, fmt, check, clippy, build를 실행하고 공급 GPUI의 변경 파일도 rustfmt로 확인한다. 화면 접근 자동 승인 거절을 우회하지 않으며 실제 GUI 말줄임 해소 여부는 미검증으로 구분한다. 기본 exe가 실행 중이면 별도 링크 산출물을 준비하고 제한을 보고한다.
