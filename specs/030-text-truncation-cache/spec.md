# 기능 명세: 최근 저장소 텍스트 말줄임 캐시 수정

> 문서 정리일: 2026-11-17. 본문은 이 기능의 단계별 요구사항 이력을 포함한다. 현재 유효 기준과 검증 한계는 [전체 명세 색인](../README.md)을 함께 확인한다. 과거 검증 기록은 현재 버전의 재검증 결과가 아니다.

작성일: 2026-11-14 · 상태: 명세 검증 완료

## 사용자 이야기와 수용 기준

### 사용자 이야기 1 — 넓어진 영역에 이름과 경로 표시 (우선순위 P1)

최근 저장소 이름·경로가 초기 좁은 폭의 말줄임 결과에 고정되지 않고 최종 가용 폭에 맞게 표시된다.
독립 검증: 폭 0/좁은 폭에서 측정한 말줄임 결과가 넓은 폭에 재사용되지 않는 회귀 테스트를 실행한다.
수용 시나리오: 폭이 넓어지면 원본 문자열을 다시 측정하고, 좁아지면 새 폭에 맞게 말줄임한다. 긴 한국어/경로의 원본 데이터는 유지하며 충분한 폭에서 ‘...’만 보이는 현상을 막는다.

### 사용자 이야기 2 — 일반 텍스트 동작과 캐시 유지 (우선순위 P1)

줄바꿈과 말줄임에 영향을 주는 폭 조건이 동일할 때만 측정 결과를 재사용한다. 재측정에는 이전 말줄임으로 짧아진 스타일 정보가 남지 않는다.
독립 검증: 동일 폭 재사용, 다른 줄바꿈/말줄임 폭과 제한 있음/없음 전환의 캐시 불일치를 검증한다.

## 요구사항

- FR-001: 말줄임 폭이 바뀌면 기존 측정 결과를 재사용하지 않는다. 초기 0→넓은 폭과 좁음/넓음 양방향을 포함한다.
- FR-002: 줄바꿈 폭과 말줄임 폭이 모두 일치하고 실제 측정 결과가 있을 때만 캐시를 재사용한다.
- FR-003: 매 재측정은 원본 텍스트와 원본 스타일 구간에서 시작하며 이전 잘라내기가 다음 측정을 손상시키지 않는다.
- FR-004: 기존 최근 저장소 데이터·목록 레이아웃·클릭·전역 ProgressOverlay·150ms 목록 안내를 유지한다. 새 의존성이나 공개 API 변경은 없다.
- FR-005: 실제 운영 코드가 사용하는 캐시 판정 로직을 회귀 테스트하며 전체 테스트·포맷·정적 분석·빌드와 GUI 검증 제한을 보고한다.

## 주요 개체

텍스트 측정 결과는 줄바꿈 폭과 말줄임 폭을 함께 보유한다. 원본 텍스트 스타일 구간은 재측정 간 변경하지 않는다.

## 성공 기준

- SC-001: 줄바꿈이 없는 한 줄 텍스트도 말줄임 폭 0→320, 24→320, 320→24에서 캐시 재사용을 거절한다.
- SC-002: 동일한 폭 조건은 재사용하고 줄바꿈/말줄임 폭 또는 제한 여부 변경은 거절한다.
- SC-003: 운영 측정 경로가 원본 스타일을 보존하고 전체 회귀·정적 검사가 통과한다. 실제 GUI 확인 여부와 실행 파일 교체 제한을 명시한다.

## 명확화와 경계

앞선 목록 폭/높이 보완은 유지하되 이번에는 GPUI의 측정 캐시 원인을 수정한다. 현재 실행 파일은 이전 산출물 이후 다시 빌드된 상태임을 확인하여 단순히 오래된 바이너리 사용으로 간주하지 않는다. 앞서 Feather Git 화면 접근이 자동 승인 검토에서 거절되었으므로 다른 캡처 방식으로 우회하지 않는다. 미해결 모호성은 없다.
