# 검증 결과: 말줄임 측정 캐시 폭 수정

검증일: 2026-11-14

## 원인과 변경

vendor/gpui/src/elements/text.rs의 기존 캐시 조건은 wrap_width=None인 한 줄 텍스트에 대해 다른 truncate_width를 무시하고 이전 size/글리프를 재사용했다. 따라서 처음 폭이 작아 ‘...’로 측정되면 이후 가용 폭이 커져도 같은 결과를 유지할 수 있었다. 단순한 최근 카드 폭/높이 보완만으로 이 경로를 해결할 수 없었다.

TextLayoutInner에 truncate_width를 기록하고 운영 can_reuse_layout 함수가 줄바꿈 폭과 말줄임 폭을 모두 비교하도록 변경했다. 두 폭이 같고 측정 결과가 있는 경우의 캐시는 유지한다. 성공·오류 측정 결과 모두 폭 조건을 기록한다.

truncate_line이 스타일 구간 길이를 변경하므로 외부 runs를 불변으로 캡처하고 실제 캐시 미스 뒤 runs.clone()을 사용한다. 이전 말줄임으로 짧아진 스타일을 다음 폭의 측정에 넘기지 않는다. 최근 저장소 데이터/레이아웃과 전역 오버레이는 변경하지 않았다.

## 회귀 증거

- 기존 조건을 순수 함수로 동일하게 추출하고 실제 text.rs 측정 경로에 연결한 뒤 앱 테스트로 실행했다. 4개 중 동일 조건 재사용 1개는 통과하고 폭 변경/제한 변경/줄바꿈 모드 변경 3개는 실패했다.
- 첫 실패는 말줄임 폭 0→320에서 캐시 재사용을 거절하지 못한 것이었다. 제한 없음→320과 줄바꿈 있음→없음도 잘못 재사용함을 확인했다.
- 수정 후 같은 운영 소스를 포함한 독립 rustc 테스트 하네스에서 4개가 통과했다. 새 글꼴/레이아웃 구현을 흉내 내지 않고 실제 판정 소스를 직접 검증했다.
- 최종 앱 전체 cargo test --offline: 194개 통과, 실패 0개, 기존 수동 성능 측정 무시 2개. 신규 테스트는 0/24→320, 320→24, 같은 폭/무제한, 말줄임 제한 추가/제거, 줄바꿈 폭/모드 변경을 포함한다.
- 스타일 보존은 실제 truncate_line의 runs 수정과 운영 캐시 미스 뒤 복사 위치를 소스에서 검토했다. 별도의 글꼴 렌더링/화면 테스트로 보고하지 않는다.
- 구현 중 매개변수 이름 변경 실수로 컴파일 1회 실패했으며 바로 수정한 뒤 최종 전체 검증을 통과했다.

## 미검증 범위

이전 Feather Git 화면 접근이 자동 승인 검토에서 거절되어 실제 최근 목록 표시나 창 크기 변경 시 글리프 복원을 화면에서 확인하지 못했다. 다른 UI 캡처 방식으로 우회하지 않았다. 따라서 재현된 캐시 결함 수정과 자동 검증을 실제 GUI 확인으로 대신 보고하지 않는다. 기본 실행 파일은 갱신되었으므로 새로 실행하여 확인할 수 있다.
