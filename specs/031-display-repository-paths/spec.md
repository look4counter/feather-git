# 기능 명세: 저장소 경로의 표시용 접두사 정리

> 문서 정리일: 2026-11-17. 본문은 이 기능의 단계별 요구사항 이력을 포함한다. 현재 유효 기준과 검증 한계는 [전체 명세 색인](../README.md)을 함께 확인한다. 과거 검증 기록은 현재 버전의 재검증 결과가 아니다.

작성일: 2026-11-14 · 상태: 명세 검증 완료

## 사용자 이야기와 수용 기준

### 사용자 이야기 1 — 읽기 쉬운 저장소 경로 (우선순위 P1)

최근 저장소와 현재 저장소 안내 및 앱이 직접 그리는 저장소 경로 문구는 Windows의 확장 접두사를 제외한 읽기 쉬운 경로를 표시한다.
수용 시나리오: `\\?\C:\repo`는 `C:\repo`, `\\?\UNC\server\share\repo`는 `\\server\share\repo`로 표시한다. 한국어·공백과 접두사 뒤 경로 내용은 유지한다. 보통 경로와 상대 경로는 바꾸지 않는다.
독립 검증: 드라이브·UNC·일반 경로의 표시 결과를 순수 함수로 검증한다.

### 사용자 이야기 2 — 내부 경로 호환성 유지 (우선순위 P1)

화면 표현만 변경하며 최근 저장소 재열기·저장·동일성 비교·실제 I/O에는 원래 경로를 사용한다.
수용 시나리오: 표시 함수를 호출해도 PathBuf와 세션/Request의 경로가 바뀌지 않는다. 정상 드라이브/UNC로 변환할 수 없는 장치 이름 공간과 불완전한 입력은 임의로 잘라 의미를 바꾸지 않는다.
독립 검증: 표시 결과와 내부 요청·세션의 원본 경로 보존을 함께 검증한다.

## 요구사항

- FR-001: 일반 확장 드라이브 경로의 접두사를 화면 표시에서 제거한다.
- FR-002: 확장 UNC 경로는 일반 UNC의 두 역슬래시를 복원한다. 대소문자 차이와 한국어·공백을 안전하게 처리한다.
- FR-003: 일반·상대·비 Windows 경로는 유지하고 불완전한 접두사·지원하지 않는 장치 이름 공간은 그대로 둔다.
- FR-004: 최근 저장소·현재 프로젝트 안내·파일 변경 실패 안내의 명시적 저장소 경로 표시에서 공통 함수를 사용한다. 저장·재열기 Request·경로 비교·사용자 입력 값은 변환하지 않는다.
- FR-005: 표준/UNC/경계 조건·원본 보존·관련 UI 상태와 전체 회귀를 검증하고 빌드 및 GUI 검증 범위를 보고한다.

## 주요 개체

표시 경로는 원본 Path를 읽어 만든 별도 문자열이다. 원본 PathBuf와 세션 형식은 변경하지 않는다.

## 성공 기준

- SC-001: 드라이브·UNC 표시 변환과 일반/불완전/장치 경로 유지가 자동 테스트를 통과한다.
- SC-002: 화면 안내에는 접두사가 없지만 실제 열기 요청과 저장 스냅샷에는 원래 접두사 경로가 유지됨을 검증한다.
- SC-003: 전체 테스트·포맷·정적 검사와 빌드 결과를 보고하고 GUI 직접 검증과 구분한다.

## 명확화와 경계

입력 상자의 원문은 실제 I/O 입력이므로 사용자 입력 문자열을 자동 변경하지 않는다. 라이브러리가 생성하는 임의 오류 문자열 전체를 치환하지 않고 앱이 직접 경로를 렌더링하는 위치에 공통 표시 함수를 사용한다. 일반 경로로 표현할 수 없는 장치/볼륨 이름 공간은 의미 보존을 위해 유지한다. 미해결 모호성은 없다.
