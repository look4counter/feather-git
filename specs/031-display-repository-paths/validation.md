# 검증 결과: 표시용 저장소 경로

검증일: 2026-11-14

## 구현 결과

src/path_display.rs에 파일 시스템 접근 없이 Path를 표시 문자열로 바꾸는 공통 함수를 추가했다. 알려진 확장 드라이브는 접두사를 제거하고 확장 UNC는 일반 네트워크 경로의 두 역슬래시를 복원한다. UNC 대소문자와 한국어·공백을 보존한다. 일반/상대/비 Windows·불완전/장치 이름 공간은 임의로 자르지 않는다.

src/ui.rs의 최근 저장소 카드와 현재 프로젝트 안내, src/diff_viewer.rs의 앱이 직접 포맷하는 파일 변경 실패 안내에 연결했다. 실제 entry_request·session_snapshot·PathBuf·폴더 선택 입력과 백엔드 데이터 형식은 변경하지 않았다.

## 자동 검증

- 기존 display 동작을 반환하는 함수에 테스트를 먼저 연결하여 드라이브/UNC 변환 2개가 실패하고 일반/경계 및 원본 보존 2개가 통과함을 확인했다.
- 수정 후 관련 테스트 5개가 통과했다. 드라이브 루트·소문자 드라이브·한국어/공백·대소문자 UNC·일반/상대/비 Windows·빈 문자열·불완전/장치 경로와 원본 PathBuf 보존을 포함한다.
- UI 상태 테스트에서 현재 안내/최근 표시의 변환 결과를 확인하고, 같은 원본 경로가 재열기 Request 및 세션의 open/recent 경로에 그대로 남는지 드라이브/UNC 모두 확인했다.
- cargo test --offline: 최종 199개 통과, 실패 0개, 기존 수동 성능 측정 무시 2개.
- cargo fmt --check, cargo check --offline, cargo clippy --offline --all-targets: 성공. 기존 미사용 함수/공통 Dialog::overlay·UI collapsible_if·GPUI 실수 리터럴 및 의존성 미래 호환성 경고만 남는다.
- cargo build --offline: 컴파일·링크 후 실행 중 기본 target/debug/feather-git.exe 교체가 접근 거부(os error 5)로 실패했다. 앱은 강제 종료하지 않았다.
- 최신 링크 결과를 target/feather-git-friendly-paths.exe로 복사하여 SHA-256 일치 및 --help 종료 코드 0을 확인했다. 기본 exe 적용은 앱 종료 후 재빌드가 필요하다.

## 미검증 및 한계

실제 GUI 라벨은 직접 확인하지 않았다. 기존 화면 접근 승인 제한을 우회하지 않았으며 순수 표시 문자열과 UI 상태 검증을 시각 확인으로 보고하지 않는다. 임의 라이브러리 오류 문자열과 실제 입력 원문은 표시 함수 적용 대상이 아니다. 내부 데이터를 바꾸지 않는 범위에서 앱이 직접 그리는 경로 라벨만 변경했다.
