# 최근 저장소 삭제

> 문서 정리일: 2026-11-17. 본문은 이 기능의 단계별 요구사항 이력을 포함한다. 현재 유효 기준과 검증 한계는 [전체 명세 색인](../README.md)을 함께 확인한다. 과거 검증 기록은 현재 버전의 재검증 결과가 아니다.
> 후속 변경 참고: [033](../033-hold-repository-deletion/spec.md).

## 사용자 시나리오와 검증

### 사용자 이야기 1 — 목록 정리 (우선순위 P1)
최근 저장소 각 행 오른쪽의 휴지통을 누르면 대상 이름·경로와 항목만 삭제, 저장소 파일 삭제, 취소 버튼이 표시된다. 항목만 삭제하면 목록과 저장된 최근 기록에서만 제거되고 폴더 및 열린 탭은 유지된다. 취소와 Escape는 변경하지 않는다. 휴지통 클릭으로 저장소가 열리지 않는다.

### 사용자 이야기 2 — 폴더 영구 삭제 (우선순위 P1)
저장소 파일 삭제를 명시적으로 선택하면 작업 파일과 .git을 포함한 대상 폴더 전체를 영구 삭제한다. 처리 중 전역 진행 표시를 보여주고 중복 조작을 막는다. 성공하면 최근 기록과 해당 폴더 아래의 열린 저장소 탭을 정리한다. 실패하면 오류를 표시하고 목록·탭을 유지한다. 부분 삭제가 발생할 수 있음을 오류 안내에 명시한다.

## 확인 사항

### 2026-11-14
- 질문: 파일 삭제 범위는? 답변: 저장소 폴더 전체(작업 파일과 .git 포함).
- 질문: 삭제 방식은? 답변: 복구할 수 없도록 영구 삭제.

## 기능 요구사항

- FR-001: 각 행 오른쪽에 휴지통을 표시하고 세 선택지가 있는 확인 팝업을 연다.
- FR-002: 항목만 삭제는 선택 경로의 최근 기록만 제거·저장하며 디스크와 열린 탭을 유지한다.
- FR-003: 취소와 Escape는 변경하지 않으며 Enter만으로 영구 삭제하지 않는다.
- FR-004: 파일 삭제는 선택한 정확한 저장소 폴더 전체를 영구 삭제하며 외부 링크 대상을 따라가지 않는다. 파일시스템 루트, 연결 경로, 저장소가 아닌 폴더 및 .git 내부 경로는 거절한다.
- FR-005: 비동기 처리와 전역 진행 표시로 UI를 유지하고 중복 저장소 작업을 막는다.
- FR-006: 성공 시 해당 폴더와 하위 폴더의 최근 기록·열린 탭을 정리하고 세션을 저장한다. 실패 시 상태를 유지하고 오류를 표시한다.
- FR-007: 표시 경로만 Windows 접두어를 숨기고 실제 처리는 원본 경로를 사용한다. 팝업은 행 인덱스가 아닌 경로를 보관한다.

## 경계 조건

없는 폴더, 권한 부족, 잠긴 파일, 링크·정션, 하위 폴더, 열린 저장소, 빈 최근 목록, 처리 중 중복 클릭을 검증한다. 영구 삭제는 원자적이지 않아 중간 오류 시 일부 파일이 이미 삭제되었을 수 있다. 기존 세션 형식은 유지한다.

## 핵심 엔터티

최근 저장소 항목은 이름과 원본 경로를 가진다. 삭제 확인 상태는 선택 항목과 포커스를 가진다. 삭제 실행 상태는 항목을 보관하고 완료 결과를 받는다.

## 성공 기준

- SC-001: 세 선택지 각각의 결과가 명세와 일치하고 휴지통 클릭으로 저장소 열기가 0회 발생한다.
- SC-002: 임시 저장소 삭제 시 폴더 전체가 없어지고 외부 형제 폴더는 보존된다.
- SC-003: 목록 전용 삭제·취소·실패 테스트에서 보호 대상 파일이 보존된다.
- SC-004: 관련 자동화 테스트와 정적 검사 및 빌드를 수행하고 실행 불가 범위를 보고한다.
