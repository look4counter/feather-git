# 실행 작업

## 1단계: 준비

- [x] T001 헤더와 선택 대상·응답 데이터 흐름을 분석하고 명세·확인·계획을 갱신한다.
- [x] T002 요구사항 4개와 계획·작업의 일관성을 분석한다.

## 2단계: 사용자 이야기 1

- [x] T003 [US1] src/diff_viewer.rs의 모든 헤더에서 두 버튼을 제거하고 공통 패널 스타일을 적용한다 (FR-001~003).
- [x] T004 [US1] src/diff_viewer.rs에서 응답 전 제목 회귀 테스트를 먼저 작성하고 현재 선택 대상에 기반한 제목을 구현한다 (FR-004).

## 3단계: 검증

- [x] T005 fmt/check/test/clippy/build를 실행하고 GUI 검증·exe 잠금 한계를 기록한다 (SC-001~003).
- [x] T006 speckit-converge로 코드·명세·계획의 일치를 확인한다.

## 순서와 전략

T001 → T002 → T004 → T003 → T005 → T006. 한 파일에서 순차 구현한다. 추가 병렬 작업은 필요하지 않다.

## 검증 결과

- 선택 제목 회귀 테스트가 구현 전 기본 제목을 반환해 실패하는 것을 확인한 뒤 현재 대상의 제목을 사용하도록 수정했다.
- 전체 테스트 211개 통과, 실패 0개, 기존 수동 성능 테스트 2개 제외.
- fmt/check/clippy 통과. 기존 경고와 버튼 제거로 호출되지 않는 open_keys 및 응답 title 필드의 미사용 경고가 남는다. 이번 범위 밖의 설정 코드·데이터 모델을 임의로 제거하지 않았다.
- 빌드 컴파일·링크 완료. 실행 중인 기본 exe 잠금으로 최종 파일 교체 실패(os error 5). 최신 링크 결과를 target/feather-git-viewer-header.exe에 복사해 해시와 --help 실행을 확인했다.
- 실제 GUI의 제목 변경 시점·스타일·버튼 유무는 실행 검증하지 않았다. 수동 절차는 quickstart.md에 있다.
- 일관성 분석: 요구사항 4개가 T003~T005에 모두 연결되며 누락·충돌·중복 0개다.
- 수렴 점검: 요구사항 4개·성공 기준 3개, 모든 대상 공통 헤더·응답과 분리된 제목·기존 조회와 키보드 보존을 코드와 테스트로 대조했다. 미구현 차이는 없으며 GUI 검증과 기본 exe 교체 한계는 위에 명시했다.
