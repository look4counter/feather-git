# 구현 계획

## 실제 흐름과 기술 맥락
Rust 2024·GPUI 앱이다. DiffViewer::set_target은 ReadSlot에 조회를 맡기고 generation과 target으로 오래된 결과를 거절한다. 현재 loading은 빈 안내를 숨길 뿐이며 viewer-lines VirtualList에 ListLoading을 연결하지 않아 조회 중 문구가 없다. 기존 ListLoading은 150ms 타이머·완료 AtomicBool·세대 무효화·본문 문구를 제공한다.

## 설계와 영향
src/diff_viewer.rs에 ListLoading 필드를 추가하고 기존 loading bool은 유지한다. 대상 전환·deactivate에 상태를 초기화하며 비동기 조회 시작에 generation으로 begin한다. 백엔드 클로저는 성공과 오류 모두 반환 전에 요청별 완료 플래그를 기록해 빠른 조회의 늦은 UI 적용으로 문구가 깜빡이지 않게 한다. 현재 응답 적용 시 reset한다. viewer-lines에 공통 loading 빌더를 연결한다. Text 대상은 동기 처리하므로 지연 상태를 시작하지 않는다. 헤더는 기존 target 기반 제목을 유지한다.

## 헌법과 제약
헌법은 미작성 템플릿이므로 규범 검사를 건너뛴다. AGENTS.md의 계층 분리와 기존 기능 재사용을 준수한다. 백엔드·공개 API·새 의존성 변경은 없다. 공통 로딩 구현을 복제하지 않는다.

## 검증
기존 공통 로딩 테스트는 150ms 경계·빠른 완료·세대 격리·타이머 수명을 검증한다. 연결한 뷰어 요청 주기의 시작·결과·비활성화 지점을 검토하고 기존 전체 테스트·fmt/check/clippy/build를 실행한다. 실제 GUI 확인이 불가하면 별도 기록한다.

## 상세 전환 보존 설계
분석: set_target이 data·width·scroll을 즉시 초기화하고 VirtualList도 pending이면 본문 없는 요소를 반환한다. UI viewer_target은 커밋 파일 조회 대기와 관계없이 선택 커밋의 Detail을 제공하므로 별도 UI 대상 변경은 필요하지 않다.
설계: prepare_detail_transition에서 같은 저장소·인코딩의 Detail 사이에 표시할 기존 데이터가 있으면 보존한다. DiffViewer는 상세 대상 여부를 공용 VirtualList에 전달하여 최초 상세 조회도 중앙 안내를 사용한다. 데이터 보존 범위는 기존 retaining_detail로 유지한다. VirtualList는 기본 동작을 유지하되 명시적 옵션에서 150ms 전까지만 기존 본문을 유지하고 안내가 나타나면 본문과 스크롤바를 숨긴 전체 본문 중앙 안내로 교체하고 기존 타이머·완료 플래그를 그대로 사용한다. 성공·오류 결과를 검증한 뒤 data·width·scroll을 새 화면으로 교체하고 보존 상태를 해제한다. 다른 대상 및 deactivate에서도 보존 상태를 해제한다. 기존 generation·target·encoding 검증을 유지한다.
영향 범위는 src/diff_viewer.rs, src/virtual_list.rs 및 내부 테스트이며 backend·UI 선택·공개 데이터 형식·의존성 변경은 없다. 헌법은 미작성 템플릿이고 공용 로딩 재사용 및 계층 분리를 준수한다.
검증: 실제 Diff 데이터의 연속 전환 보존과 다른 대상 초기화, 기존 오래된 요청 검증·지연 타이머 테스트 및 관련 뷰어 회귀를 실행한다. check·엄격한 Clippy·별도 빌드를 확인한다. 실제 GUI는 기존 앱 접근 거부로 미검증이다.

## 2026-11-17 표시 변경
공통 VirtualList의 본문 보존 옵션은 지연 안내 표시 전까지만 적용한다. 현재 사용자 이야기 3에서 모든 목록에 중앙 안내를 확장한다. 지연 상태와 완료 플래그의 기존 테스트를 확장하여 149ms·150ms·완료·초기화를 검증한다. 새로운 데이터 모델·의존성·외부 계약 변경은 없다.

## 모든 패널 안내 통일

호출 분석: VirtualList의 단일 조회 문구를 저장소 목록(ui.rs), 파일 목록(ui.rs), 히스토리(ui.rs), 파일 이력(file_history_dialog.rs), 비교·상세(diff_viewer.rs)가 재사용한다. 현재 중앙 정렬은 상세 옵션에만 걸려 있고 글자 크기는 부모를 상속한다. 파일 선택 안내는 diff_viewer.rs의 별도 분기이고 빈 VirtualList가 함께 남아 있다.

설계: src/virtual_list.rs에 12px·가로 세로 중앙·남은 공간 전체를 차지하는 공통 panel_message 함수를 제공한다. 조회 분기의 조건부 중앙 정렬을 없애고 모든 목록에서 이 함수를 사용한다. diff_viewer.rs도 빈 상태 문구에 같은 함수를 사용하고 빈 상태에는 빈 목록을 렌더링하지 않아 전체 본문을 차지하게 한다. EOF 표시 행이 있는 경우는 빈 상태로 처리하지 않는다. 제목·오류 상세·부가 설명·정상 행과 스크롤·조회 상태 로직은 유지한다. 새 의존성·외부 계약·데이터 모델 변경은 없다.

검증: 조회 문구가 단일 함수로 표시되는지와 호출 경로를 대조하고 기존 로딩·뷰어 회귀 테스트, 변경 파일 포맷 검사, check·전체 대상 엄격한 Clippy·별도 출력 빌드를 수행한다. 스타일 변경이므로 구현을 복제한 테스트는 추가하지 않는다. GUI 중앙 배치는 수동 미검증 범위를 명시한다. 헌법은 미작성 템플릿으로 검사를 생략하며 AGENTS.md의 공통 기능 재사용·계층 분리를 준수한다.

## 모든 지연 조회의 이전 화면 유지

분석: 지연 상태는 ListLoading을 쓰는 5개 호출 지점으로 수렴한다. 히스토리와 파일 이력은 기존 데이터를 결과 적용까지 유지하지만 VirtualList 기본 분기가 즉시 숨긴다. 저장소·변경 파일은 요청 시작에 모델 데이터를 비우므로 표시 옵션만 변경해서는 부족하다. DiffViewer의 prepare_detail_transition도 파일 대상을 즉시 비운다.

설계: VirtualList는 기본적으로 지연 안내 전까지 본문을 보존한다. pending 상태의 키보드 선택을 막고 투명한 입력 차단 영역으로 보존된 행의 클릭·컨텍스트 작업을 막는다. Workspace에는 저장소 이름과 파일 목록·상세 행 유무의 표시용 스냅샷만 추가한다. 실제 모델 초기화와 작업 대상 검증은 유지하며 렌더링에서만 스냅샷을 사용한다. 같은 진행 중 요청을 교체하면 스냅샷을 재사용하고 완료·취소 때 제거한다. 탭 전환 직전에 스냅샷을 준비하여 기존 표시를 유지한다. 프로젝트 이동·닫기에서는 무효화로 제거한다. 히스토리·파일 이력은 기존 데이터 수명을 재사용한다.

DiffViewer는 기존 상세 전환 보존 함수를 콘텐츠 전환 함수로 확장하여 같은 저장소·인코딩의 File 사이에도 보존하고 기존 완료·오류·세대 검증을 재사용한다. Files 대상은 개별 자식 뷰어의 기존 비동기 조회를 사용한다. 상태는 새 비즈니스 모델이 아닌 표시용 데이터이고 공개 API·백엔드·의존성은 변경하지 않는다. 헌법은 미작성 템플릿이므로 검사를 생략한다.

검증: 표시용 스냅샷 보존·연속 조회·취소·완료 및 파일 전환 범위 회귀를 추가하고 기존 지연 경계·빠른 완료·이전 응답 격리·파일 이력 테스트와 전체 테스트를 수행한다. check·엄격한 Clippy·변경 구간 포맷·별도 빌드를 확인한다. 실제 GUI는 미검증 범위를 보고한다.

같은 대상의 새로고침도 load_target의 강제 조회 경로를 사용한다. 기존처럼 target을 먼저 제거하지 않아 기존 콘텐츠를 보존하며 동일 대상의 중복 선택은 기존 조기 반환을 유지한다. FR-010·013 및 T019 범위에 포함한다.

## 커밋상세 행과 작업트리 비교의 깜빡임 수정

분석: src/ui.rs의 files는 display_file_list로 보존된 상세 행을 렌더링하지만 선택 인덱스는 file_list_selected_row가 실제 모델의 file_list_has_detail을 사용해 계산한다. panel_waiting 때 이 값이 false여서 보존된 행의 선택 배경이 사라진다. src/diff_viewer.rs는 File 사이에 데이터를 보존하지만 partial()이 loading 때 false를 반환하여 렌더링 도구 모음·행 체크박스·text_left 위치가 동시에 바뀐다.

설계: file_list_selected_row의 표시 선택 인덱스는 display_file_list의 파일 수·상세 행 유무로 계산한다. 모델 기반 작업 대상 해석과 panel_waiting 차단은 유지한다. DiffViewer의 렌더링 3곳(도구 모음, diff_row, text_left)은 보존된 data.partial 유무를 사용하고 기존 partial()은 조회 중 작업 권한 차단에 계속 사용한다. 작업 함수와 키보드·입력 차단은 유지한다. 새 추상화·데이터·공개 계약·의존성은 추가하지 않는다.

검증: 커밋상세 행 선택이 정상·연속 대기·완료 동안 유지되는 재현 테스트를 먼저 추가한다. 실제 작업트리 파일 선택 대상이 중간 빈 대상 없이 전환되고 파일 전환이 기존 부분 Stage 정보를 유지하는지 테스트한다. 전체 테스트·check·엄격한 Clippy·별도 빌드를 수행하고 실제 GUI 배치 미검증을 보고한다. 헌법은 미작성 템플릿으로 검사를 생략하며 기존 역할 분리를 준수한다.

최초 작업트리→히스토리 전환에서는 select_commit이 file_history를 바꾸기 전에 표시 스냅샷을 확보한다. 아직 로드되지 않은 커밋상세 행이 표시 선택 계산에 합성되지 않게 하며 기존 최초 조회·입력 차단 검증을 유지한다. T023과 FR-014·016에 포함된다.

## 하단 스크롤 영역 깜빡임 수정

분석: DiffViewer는 새 조회 결과 적용 시 ListScrollHandle::default로 위치와 측정값을 모두 버린다. VirtualList는 render 시 frame 크기로 Visibility를 계산하고 canvas가 실제 크기를 기록하면 다음 프레임을 요청한다. 따라서 이미 알고 있는 뷰어 크기도 0이 되어 새 결과 첫 프레임의 스크롤바와 하단 패딩이 사라질 수 있다.

설계: src/virtual_list.rs의 ListScrollHandle에 새 내용용 초기화 메서드를 추가한다. frame 값만 복사하여 유지하고 나머지 핸들·오프셋·트랙·드래그·호버는 기본 상태로 교체한다. src/diff_viewer.rs의 대상 초기화와 결과 적용의 두 지점에서 이 메서드를 사용한다. 실제 크기는 기존 canvas 측정으로 계속 갱신한다. 스크롤 범위·가시성 알고리즘·지연 안내·입력 차단·공개 데이터 형식은 변경하지 않는다. 헌법은 미작성 템플릿으로 검사를 생략한다.

검증: 측정된 크기를 설정한 핸들을 초기화한 뒤 첫 프레임 Visibility가 가로·세로 스크롤 필요 여부를 정확히 계산하는 회귀를 먼저 추가한다. 새 핸들·위치·드래그·호버 초기화와 짧은 내용·최초 미측정 상태도 확인한다. 전체 테스트·check·엄격한 Clippy·변경 파일 포맷·별도 빌드를 수행하고 실제 GUI 미검증 범위를 보고한다.

## 빈 패널 안내 전체 중앙 정렬

분석: src/ui.rs의 저장소·파일·히스토리 빈 상태와 최근 저장소 안내, src/file_history_dialog.rs의 이력 없음 안내는 별도 label/div로 상단에 표시된다. 최근 저장소는 빈 안내와 빈 목록 컨테이너가 형제로 공간을 나눈다. 기존 panel_message는 남은 본문 전체를 채우는 중앙 12px 표시지만 정적 문자열만 받는다. 프로젝트 없음 화면은 이미 중앙 정렬이고 설정의 원격 없음은 폼 내 설명이다.

설계: src/virtual_list.rs의 panel_message 입력을 SharedString으로 변환 가능한 값으로 확장해 동적 오류도 지원한다. src/ui.rs의 4개 빈 상태와 2개 오류 전용 목록, src/file_history_dialog.rs의 이력 없음·조회 오류를 재사용 함수로 교체한다. 최근 저장소 안내는 실제 목록의 flex 영역 내부에 둬 빈 목록과 공간을 나누지 않는다. 정상 목록의 조건과 이벤트·조회 상태는 유지한다. 히스토리 빈 안내는 grid_pending일 때 숨겨 조회 안내와 공간을 나누지 않게 한다. 새 상태·공개 계약·의존성은 추가하지 않으며 헌법은 미작성 템플릿으로 검사 생략한다.

검증: 모든 대상 문구의 호출을 검색하여 공통 함수 연결과 부모 flex 높이를 확인하고, 기존 빈 목록·오류·로딩 테스트를 포함한 전체 테스트·check·엄격한 Clippy·변경 파일 포맷·별도 빌드를 수행한다. 단순 스타일 변경의 구현 복제 테스트는 추가하지 않는다. 실제 GUI는 수동 미검증으로 보고한다.
