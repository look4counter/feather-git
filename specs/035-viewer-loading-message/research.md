# 조사 결과

ui.rs의 목록 조회가 사용 중인 ListLoading.completion 신호와 VirtualList.loading 빌더를 그대로 재사용할 수 있다. 백엔드가 완료 플래그를 기록하면 UI 응답 적용 전에 타이머가 깨어도 빠른 조회 문구가 나타나지 않는다. reset은 요청별 AtomicBool을 교체하므로 이전 완료는 새 요청에 영향을 주지 않는다.

## 커밋 상세 전환 보존
데이터 초기화만 늦추면 VirtualList가 pending 상태에서 기존 행을 숨기므로 깜빡임이 남는다. 명시적 본문 유지 옵션을 추가하여 기존 타이머와 완료 신호를 그대로 사용한다. 같은 저장소의 읽기 전용 커밋 상세에 한정하고 일반 파일 비교는 기존 동작을 유지한다.

## 2026-11-17 전체 본문 안내
결정: 기존 보존 옵션에서 지연 안내가 보이면 기본 로딩 분기로 전환하고 중앙 정렬한다. 상세 대상 여부로 옵션을 연결하여 최초 조회도 같은 배치를 사용한다. 이유: 기존 타이머와 완료 신호를 재사용하면서 이전 행과 스크롤바의 렌더링 자체를 생략할 수 있다. 대안인 불투명 오버레이는 숨겨진 행을 계속 렌더링하므로 선택하지 않았다. 새 데이터 모델이나 외부 인터페이스 변경은 없다.

## 패널 안내 통일 조사
결정: 공통 목록 모듈의 panel_message로 조회와 뷰어 빈 상태 표시를 통합한다. 이유: 조회 문구의 실제 구현은 한 곳이고 파일 선택 안내만 별도 분기이므로 두 곳의 스타일 복제를 피할 수 있다. 대안인 부모별 글자 크기 수정은 누락 가능성이 있어 사용하지 않는다. 헤더를 유지하고 남은 본문을 중앙 정렬한다.

## 모든 지연 조회 보존 조사
표시 전용 목록 스냅샷을 사용하면 기존 모델 초기화·안전 검증과 호환된다. 모델을 그대로 두는 대안은 이전 파일을 새 커밋의 작업 대상으로 오인할 가능성이 있어 채택하지 않는다. 히스토리와 파일 이력은 이미 데이터가 보존되므로 중복 캐시는 도입하지 않는다.

## 선택·배치 깜빡임 조사
표시 데이터만 보존하는 것으로는 충분하지 않았다. 선택 인덱스도 표시용 데이터에서 계산해야 하며 비교 배치는 비동기 작업 가능 여부와 분리해야 한다. 로딩 중 partial()을 무조건 true로 바꾸는 대안은 Stage 권한도 열 수 있으므로 사용하지 않는다. 렌더링에서만 보존된 부분 Stage 데이터 존재를 참조한다.

## 하단 스크롤 깜빡임 조사
기존 Visibility 계산은 viewport 크기가 0이면 양쪽 스크롤바를 숨긴다. 측정된 frame만 유지하는 초기화는 위치를 처음으로 되돌리는 정책을 유지하면서 중간 미측정 상태를 없앤다. 핸들 전체 재사용은 이전 스크롤 범위·트랙 상태가 남을 수 있어 채택하지 않는다.

## 빈 패널 안내 조사
기존 panel_message가 flex_1·양축 정렬·12px를 이미 제공하므로 이를 재사용한다. 최근 저장소는 안내 위치를 목록 컨테이너 안으로 옮겨 남은 영역 전체를 사용한다. 빈 목록과 조회 안내의 조건이 겹치지 않게 유지한다. 폼 내 설명이나 전체 화면 제목은 목록 빈 상태와 구분한다.
