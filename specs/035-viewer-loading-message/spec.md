# Diff Viewer 지연 로딩 안내

> 문서 정리일: 2026-11-17. 본문은 이 기능의 단계별 요구사항 이력을 포함한다. 현재 유효 기준과 검증 한계는 [전체 명세 색인](../README.md)을 함께 확인한다. 과거 검증 기록은 현재 버전의 재검증 결과가 아니다.

## 사용자 이야기 (P1)
파일 비교와 커밋 상세 조회가 150ms 이상 걸리면 본문에 기존 목록과 같은 조회 중 문구를 표시한다. 빠른 응답은 문구 없이 내용을 표시한다. 헤더는 현재 선택 제목을 즉시 유지한다.

## 확인

2026-11-14: 기존 공통 150ms 지연과 문구를 재사용한다. 파일 비교와 같은 뷰어에서 표시하는 커밋 상세에도 적용한다. 추가 모호성은 없다.

## 요구사항

- FR-001: 비동기 파일 비교·커밋 상세 조회가 150ms 이상 대기하면 공통 조회 안내를 본문에 표시한다.
- FR-002: 빠른 완료·성공·오류·선택 전환·뷰어 비활성화 시 이전 안내를 숨기고 이전 타이머나 완료가 새 안내를 변경하지 않도록 한다.
- FR-003: 즉시 표시되는 파일명 헤더와 동기 빈 화면·선택·기존 조회 기능을 유지한다. 로딩 완료와 오류는 기존 표시로 전환한다.

## 성공 기준과 경계

SC-001: 150ms 직전에는 문구가 없고 대기가 계속되면 150ms부터 공통 문구가 표시된다.
SC-002: 빠른 완료와 연속 파일 전환·오류·탭 이동에서 이전 문구가 남지 않는다.
SC-003: 관련 자동화 테스트·빌드·정적 검사를 실행하고 GUI 미검증 범위를 보고한다.

## 사용자 이야기 2: 커밋 상세 전환의 깜빡임 방지 (P1)
- FR-004: 같은 저장소·같은 인코딩의 커밋 상세 사이를 전환하면 이전 상세를 지연 안내가 표시되기 전까지 유지하고 새 결과가 준비된 순간 교체한다. 최초 조회와 파일·다른 저장소·인코딩 전환은 기존 초기화 동작을 유지한다.
- FR-005: 전환 후 150ms 미만에는 이전 본문을 유지한다. 150ms 이상 걸려 공통 조회 안내가 나타나면 이전 본문과 스크롤바를 숨기고 본문 패널 전체를 차지하는 영역 중앙에 안내를 표시한다. 빠른 조회에는 안내를 표시하지 않는다.
- FR-006: 연속 전환에서 이전 요청 결과를 거절한다. 성공 시 새 내용과 스크롤을 초기 위치로 교체하며 오류 시 이전 내용을 제거하고 오류를 표시한다. 대기 중 이전 내용을 새 대상의 편집·Stage에 사용하지 않는다.
- SC-004: 상세 내용 보존·전환 범위·연속 전환·오류 초기화 및 지연 안내 회귀 검증을 통과한다.
명확화(2026-11-17): 이전 내용 유지는 지연 안내 표시 전까지로 한정한다. 패널 제목과 완료·오류 처리는 유지한다. 임의 캐시나 파일 diff 전환 정책 변경은 포함하지 않는다. 추가 필수 질문 없음.

## 사용자 이야기 3: 패널 안내의 표시 통일 (P1)

저장소·파일·히스토리·파일 이력·비교 뷰어의 조회 안내와 뷰어의 빈 상태 안내를 쉽게 확인할 수 있도록 본문 중앙에 같은 크기로 표시한다.

- FR-007: 공통 조회 안내는 패널 제목과 목록 헤더를 제외한 남은 본문 영역에서 가로·세로 중앙에 표시한다.
- FR-008: 조회 안내와 뷰어의 “파일을 선택해 변경 내용을 확인하세요.”, “표시할 텍스트 차이가 없습니다.”, “오류 내용을 확인한 뒤 다시 조회하세요.” 안내는 모두 12px 글자 크기를 사용한다.
- FR-009: 빈 상태 안내는 빈 목록과 공간을 나누지 않고 남은 본문 전체를 차지한다. 실제 EOF 행이 있는 비교는 기존 행 표시를 유지한다. 오류 상세와 부가 설명, 정상 목록·조회 지연·완료·연속 전환 정책은 유지한다.
- SC-005: 모든 조회 안내 호출 경로와 빈 상태 안내가 같은 표시를 사용하며 관련 회귀 테스트와 빌드·정적 검사가 통과한다.

명확화(2026-11-17): 사용자가 추가로 지정한 파일 선택 안내도 포함한다. 글자 크기는 기존 뷰어 안내의 12px를 기준으로 통일한다. 추가 질문이 필요한 모호성은 없다.

## 사용자 이야기 4: 모든 지연 조회의 이전 화면 유지 (P1)

- FR-010: 저장소 목록·변경 파일 목록·히스토리·파일 이력·파일 비교의 지연 조회도 커밋 상세처럼 150ms 전까지 표시 가능한 이전 내용을 유지하고 현재 결과가 준비되면 교체한다. 최초 조회는 이전 내용 없이 대기한다.
- FR-011: 지연 안내가 표시되면 이전 본문과 스크롤바를 숨기고 기존 중앙 12px 안내를 표시한다. 완료·오류·무효화·닫기에서는 기존 상태 정책을 유지하며 이전 응답이 최신 화면을 덮어쓰지 않는다.
- FR-012: 이전 내용은 표시 전용이다. 조회 중인 목록 행의 선택·키보드 이동·컨텍스트 작업 및 이전 비교 내용의 편집·Stage를 실행하지 않는다. 표시용 데이터는 실제 작업 대상과 분리한다.
- FR-013: 파일 비교의 데이터 보존은 같은 저장소·인코딩의 파일 비교 사이에 적용한다. 다른 저장소·인코딩·동기 텍스트·비교와 상세 간 전환은 기존 초기화를 유지한다. 같은 목록의 연속 조회에서는 첫 번째로 보존한 화면을 최신 결과까지 유지한다.
- SC-006: 공통 지연 표시, 표시 전용 목록 보존·연속 전환·초기화, 파일 비교 보존 범위와 오래된 응답 거부를 자동 검증하고 관련 빌드·정적 검사를 통과한다.

명확화: “커밋 상세처럼”은 안내 표시 전까지 보존하는 기존 150ms 정책과 동일하다. 저장소·인코딩 경계는 기존 상세 정책을 적용한다. 파일 이력은 대화상자를 새로 열면 최초 조회이며 기존 세션을 캐시하지 않는다. 추가 필수 질문 없음.

## 사용자 이야기 5: 보존 화면의 선택·배치 깜빡임 수정 (P1)

- FR-014: 히스토리에서 커밋을 변경해 변경 파일을 조회하는 동안 보존된 커밋상세 행의 선택 배경과 선택 행 위치를 유지한다. 안내 표시와 완료 시점은 기존 정책을 따른다.
- FR-015: 작업트리 파일 비교를 전환하는 동안 보존된 이전 비교의 부분 Stage 도구 모음·체크박스 열·본문 시작 위치를 유지한다. 새 결과가 준비된 후 새 비교의 배치로 교체한다.
- FR-016: 화면 배치 보존이 Stage·체크·폐기 권한을 활성화하면 안 된다. 조회 중 기존 동작 차단과 오류·연속 전환·다른 저장소 및 인코딩 초기화를 유지한다.
- SC-007: 커밋상세 선택 표시의 요청 전·연속 대기·완료와 작업트리 파일 대상·이전 부분 Stage 데이터 보존을 회귀 검증하고 관련 검사·빌드를 통과한다.

명확화: 사용자 보고의 두 전환 경로를 수정한다. 150ms 이후 의도된 로딩 안내 전환이나 결과 교체를 제거하지 않는다. 별도 확인이 필요한 모호성은 없다.

## 사용자 이야기 6: 파일 전환 하단 스크롤 영역 깜빡임 수정 (P1)

- FR-017: 파일 비교의 새 결과를 표시하는 첫 프레임에서도 이미 측정한 뷰어 크기를 사용해 스크롤바와 하단 여백을 계산한다. 크기를 일시적으로 0으로 처리해 스크롤바가 사라졌다 다시 나타나는 중간 상태를 만들지 않는다.
- FR-018: 새 내용 적용 시 가로·세로 위치와 드래그·호버 상태는 초기화한다. 이전 내용 보존·150ms 안내·오류·저장소 및 인코딩 경계와 실제 창 크기 변경 처리는 유지한다.
- SC-008: 측정된 뷰포트의 보존과 새 내용용 스크롤 상태 초기화, 가로·세로 스크롤바 유무 경계가 자동 검증되고 관련 검사·빌드를 통과한다.

명확화: 사용자 보고의 하단 영역에 한정해 중간 측정값 초기화를 제거한다. 새 파일 길이에 따른 정상적인 스크롤바 유무 변경과 스크롤 위치 초기화는 유지한다. 추가 질문 없음.

## 사용자 이야기 7: 빈 패널 안내 전체 중앙 정렬 (P1)

- FR-019: 저장소의 “표시할 항목이 없습니다.”, “변경 파일이 없습니다”, “아직 커밋이 없습니다”, 파일 이력의 “이 파일의 커밋 이력이 없습니다.”, 최근 저장소의 “아직 열었던 저장소가 없습니다.”를 본문 영역의 가로·세로 중앙에 12px로 표시한다.
- FR-020: 오류만 남은 저장소·변경 파일·파일 이력 목록의 안내도 본문 중앙에 표시한다. 제목·탭·목록 헤더는 유지하고 비어 있는 목록이 메시지와 본문 공간을 나누지 않는다.
- FR-021: 기존 뷰어 빈 상태·조회 안내 중앙 표시와 정상 목록·조회 상태·선택·오류 내용을 유지한다. 설정 폼 설명과 작업 오류 배너는 본문 빈 상태가 아니므로 변경하지 않는다. 이미 중앙 정렬인 전체 프로젝트 없음 화면의 정렬은 유지한다.
- SC-009: 대상 빈 상태의 모든 렌더 경로가 공통 중앙 안내를 사용하고 관련 회귀·정적 검사·빌드가 통과한다.

명확화: 사용자 예시뿐 아니라 빈 패널의 모든 안내에 적용하며 기존 공통 12px 표시를 재사용한다. 추가 질문 없음.
