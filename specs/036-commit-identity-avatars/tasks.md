## 순서와 전략

T001 → T002 → T003 → T004 → T005 → T006 → T007. 테스트 가능한 통신·데이터를 먼저 구현하고 렌더링에 연결한다. 동일 파일 수정이므로 순차 수행한다.

## 검증 결과

- 전체 테스트 214개 통과, 실패 0개, 기존 수동 성능 테스트 2개 제외.
- 이메일 정규화와 공식 SHA256 예시, 빈 이메일, 허용 URL, 응답 크기, 포화 큐의 즉시 오류와 정상 응답 전달을 외부 통신 없이 검증했다.
- 상세 메타데이터 테스트를 요청한 이름·authored/committed 형식으로 갱신하고 초기·일반·병합 커밋의 부모 수 0~3에 대한 사진 행 매핑을 검증했다. 기존 메시지·선택·스크롤·조회 테스트를 유지했다.
- fmt/check/clippy 통과. 기존 미사용 코드·조건문·GPUI 숫자 타입·의존성 미래 호환성 경고는 유지된다.
- 빌드 컴파일·링크 완료. 실행 중인 기본 exe 잠금으로 최종 교체 실패(os error 5). 최신 링크 산출물을 target/feather-git-identity-avatars.exe에 복사해 해시 일치와 --help 실행을 확인했다.
- 실제 GUI에서 사진과 두 줄의 배치·선택 조작 및 실제 Gravatar 통신은 미검증이다. 사용자 이메일을 실서비스 검증에 사용하지 않았다. quickstart.md에 수동 절차가 있다.
- 일관성 분석: 요구사항 4개가 T003~T005·검증 T006에 모두 연결되며 누락·충돌·중복은 없다. TLS는 기존 GPUI와 동일한 rustls native roots로 정리했다.
- 수렴 점검: 요구사항 4개·성공 기준 3개, 데이터 매핑·두 행 사진 표시·기본 아이콘·전용 제한 작업·현재 선택과 기존 지연 로딩 보존을 코드와 테스트로 대조했다. 미구현 차이는 없고 GUI·실서비스 검증과 기본 exe 잠금 한계는 위에 명시했다.
