# GitHub 프로필 사진과 세션 캐시

> 문서 정리일: 2026-11-17. 본문은 이 기능의 단계별 요구사항 이력을 포함한다. 현재 유효 기준과 검증 한계는 [전체 명세 색인](../README.md)을 함께 확인한다. 과거 검증 기록은 현재 버전의 재검증 결과가 아니다.

## 사용자 이야기 (P1)
GitHub 원격이 연결된 저장소의 커밋 상세는 GitHub가 연결한 작성자·커미터 사진을 먼저 표시한다. GitHub 조회 실패·미연결 계정은 Gravatar를 사용하고 그것도 없으면 기본 아이콘을 사용한다. 이름·시간·본문은 사진을 기다리지 않는다.

## 확인

2026-11-14 사용자 후속 요구: 프로필과 사진은 앱 재시작 전까지 캐시하고 같은 정보를 매번 조회하지 않는다. 인증 연동은 요청 범위에 없으므로 공개 GitHub 저장소의 비인증 조회를 지원하고 비공개·권한·요청 제한 오류는 기존 대체 표시를 사용한다. 이후 요청으로 서비스 종류를 알 수 없는 원격에 대한 Gitea 및 Bitbucket Data Center의 비인증 조회를 추가한다. HTTPS 원격의 포트와 경로를 사용하고 SSH 원격은 같은 호스트의 기본 HTTPS를 시도한다. 인증이 필요한 서버와 별도 웹 호스트에서는 기본 아이콘을 사용할 수 있다.

## 요구사항

- FR-001: HTTPS·SSH·SCP 형태 GitHub 원격에서 저장소를 식별하고 origin을 우선한다. 커밋 API의 author와 committer를 각 역할에 맞게 사용한다. 원격 없음은 Gravatar를 유지한다.
- FR-002: GitHub 사진 조회 실패·계정 미연결·API 제한·비공개 저장소는 Gravatar, 기본 아이콘 순으로 대체한다. GitHub 사진 자체 실패도 대체한다.
- FR-003: GitHub 프로필 매핑·커밋 API 응답·사진 결과를 앱 메모리에 캐시해 재시작 전 동일 정보의 네트워크 요청을 반복하지 않는다. 같은 이메일의 다음 커밋은 기존 매핑을 재사용하고 작성자·커미터는 같은 커밋 API 응답을 공유한다. 실패 결과도 캐시한다.
- FR-004: 사진 조회는 기존 제한된 전용 작업에서 실행하고 텍스트·지연 로딩·선택·사진의 두 행 배치를 유지한다. 요청 URL에 원본 이메일·원격 인증정보를 넣지 않는다.

- FR-005: GitHub 원격을 찾지 못하면 우선 원격에서 Gitea와 Bitbucket Data Center의 커밋 API를 시도해 작성자·커미터 사진을 표시한다. 인증정보는 보내지 않고 원격 서버와 같은 출처의 사진만 가져온다. Gitea 커밋 응답에 사용 가능한 사진 주소가 없고 연결된 계정명이 있으면 사용자 API의 사진 주소를 사용한다. 이메일만 있는 경우 계정명을 추정하지 않는다. 같은 커밋의 두 역할은 응답을 공유한다. 실패하면 기본 아이콘을 표시한다.
- SC-004: 두 API의 역할별 응답과 순차 대체, 성공·실패 캐시, 하위 경로 및 출처 제한을 대역으로 검증한다.

## 성공 기준과 경계

SC-001: 서로 다른 GitHub 작성자·커미터 사진이 정확히 매핑된다.
SC-002: 같은 사람의 여러 커밋·같은 사진 반복 표시·실패 반복에서 캐시 이후 외부 재요청은 0회다. 앱 재시작 시 캐시는 초기화된다.
SC-003: 원격 형식·우선순위·대체 표시·캐시를 네트워크 대역 테스트로 검증하고 전체 테스트·빌드·정적 검사를 실행한다. GUI·실서비스 미검증은 명시한다.
