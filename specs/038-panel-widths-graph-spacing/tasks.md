# 실행 작업

> 정리 안내: 단계별 설계·작업 기록이며 후속 변경은 [현재 명세 색인](../README.md)과 해당 기능의 spec.md를 따른다. 기존 체크 상태와 과거 검증 이력은 현재 재검증 완료를 의미하지 않는다.

## 1단계: 준비

- [x] T001 사용자 정정과 현재 핸들·배치 구조를 분석하고 명세·확인·계획을 갱신한다.
- [x] T002 요구사항5개와 작업·계획의 일관성을 점검한다.

## 2단계: 구현

- [x] T003 [US1] src/panel_layout.rs의 공통 분할·축별/양축 드래그·최소 크기를 구현하고 기존 독립 행 테스트를 새 수용 기준으로 갱신한다 (FR-001~002).
- [x] T004 [US1] src/ui.rs의 십자 배치·전체 길이 선·투명 핸들·중앙 교차점과 두 좌표 이벤트를 연결한다 (FR-001~005).

## 3단계: 검증

- [x] T005 기존 드래그 수명·조회 비발생 테스트를 갱신하고 fmt/check/test/clippy/build를 실행한다 (SC-001~003).
- [x] T006 speckit-converge로 명세·코드의 차이와 GUI 미검증 범위를 확인한다.

## 순서

T001 → T002 → T003 → T004 → T005 → T006. 그래프19px와 관련 테스트는 유지한다.

## 검증 결과

- 사용자 정정에 따라 독립 행 너비 테스트를 공통 세로·가로·중앙 양축 수용 기준으로 대체했다. 최소 크기와 비정상 입력·기존 드래그 종료·조회 비발생 검증은 유지했다.
- 전체 테스트224개 통과, 실패0개, 기존 수동 성능 테스트2개 제외. 중앙 양축 이동과 가로선 단일 축 이동, 선택·본문·열 너비·요청 리비전 보존을 검증했다.
- 초기 상단 높이를 정수 논리 픽셀로 반올림해 기본54%계산의 부동소수점 오차를 제거했다.
- fmt/check/clippy 통과. 기존 경고는 유지된다.
- 빌드 컴파일·링크 완료. 실행 중인 기본 exe 잠금으로 최종 교체 실패(os error5). 최신 링크 결과를 target/feather-git-cross-resize.exe에 복사해 해시와 --help 실행을 확인했다.
- 실제 GUI의 십자 드래그·투명 핸들의 입력 영역·선의 연속성은 실행 검증하지 못했다. quickstart.md에 수동 절차를 남겼다.
- 일관성 분석: 요구사항5개와 T003~T005가 모두 연결되며 누락·중복·충돌은 없다.
- 수렴 점검: 요구사항5개·성공 기준3개, 공통 분할·두 축 이벤트·전체 길이 선 두 개·투명 핸들·기존 그래프와 UI 상태 보존을 코드와 테스트로 대조했다. 미구현 차이는 없고 GUI·기본 exe 교체 한계는 위에 기록했다.
