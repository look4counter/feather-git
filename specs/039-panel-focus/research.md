# 조사 결과

- 결정: 부모 캡처 단계에서 기본 포커스를 지정하고 자식 처리를 계속한다.
- 근거: GPUI capture_any_mouse_down은 해당 히트박스의 캡처 이벤트만 처리한다. 버블 단계 처리는 입력 자식의 포커스를 다시 덮어쓸 수 있다.
- 대안: 모든 구성요소에 FocusHandle을 추가하면 장식 요소까지 책임이 분산된다. 전역 blur만 수행하면 패널의 기본 포커스가 없어 채택하지 않는다.
- 결정: 포커스와 창 활성 변경을 구독해 커서를 갱신한다. 이벤트마다 전체 창을 강제로 새로 그리는 방식은 피한다.
