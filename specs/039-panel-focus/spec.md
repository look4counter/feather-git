# 기능 명세: 패널 클릭 포커스

> 문서 정리일: 2026-11-17. 본문은 이 기능의 단계별 요구사항 이력을 포함한다. 현재 유효 기준과 검증 한계는 [전체 명세 색인](../README.md)을 함께 확인한다. 과거 검증 기록은 현재 버전의 재검증 결과가 아니다.
> 후속 변경 참고: [071](../071-list-keys-detached-warning/spec.md).

작성일: 2026-11-14
상태: 명확화 완료
입력: 패널을 기본 포커스 단위로 삼고 내부 입력 요소의 포커스를 보존한다.

## 사용자 시나리오 및 검증

### 사용자 이야기 1 — 패널 전환 (우선순위 P1)
커밋 상세 또는 DiffViewer에서 텍스트를 선택한 뒤 참조·파일·히스토리 패널의 제목, 행, 빈 영역을 왼쪽 클릭하면 해당 패널이 포커스를 받는다.
독립 검증: 각 영역을 클릭한 뒤 이전 뷰어의 커서가 사라지고 뷰어 복사 및 이동 단축키가 실행되지 않는지 확인한다.
수용 기준: 뷰어 본문 클릭 시 다시 텍스트 선택과 복사가 가능하다.

### 사용자 이야기 2 — 자식 입력 보존 (우선순위 P1)
뷰어의 단축키 설정 입력창을 클릭하면 입력창이 최종 포커스를 받는다.
독립 검증: 입력창에서 타이핑하고 대화상자 표시 중 배경 패널을 클릭한다.
수용 기준: 입력은 자식에게 전달되며 대화상자의 포커스는 배경 클릭으로 바뀌지 않는다.

### 경계 조건
빈 목록, 조회 중, 오류 표시에서도 패널 기본 포커스가 동작한다. 오른쪽 클릭과 분할선 드래그는 포커스 전환을 요구하지 않는다. 창 비활성 상태에서는 뷰어 커서를 숨긴다.

## 요구사항

- FR-001: 참조·파일·히스토리·뷰어 패널에 안정적인 기본 포커스를 둔다.
- FR-002: 제목·본문·빈 영역 왼쪽 클릭으로 패널 포커스를 옮긴다.
- FR-003: 키보드 입력을 받는 자식의 포커스를 부모가 덮어쓰지 않는다.
- FR-004: 모달 또는 작업 차단 중 배경 패널은 포커스를 가져가지 않는다.
- FR-005: 뷰어는 실제 포커스와 창 활성 상태에 맞춰 커서를 다시 그린다.
- FR-006: 기존 선택·복사·입력·크기 조절 동작과 공개 인터페이스를 유지한다.

## 성공 기준

- SC-001: 네 패널의 제목·본문·빈 영역 클릭에서 포커스가 올바르게 전환된다.
- SC-002: 자식 입력 및 모달 시나리오에서 포커스 탈취가 없다.

## 가정 및 명확화

권장 구조를 수락한 대화로 범위와 동작이 확정되었다. 추가 질문 0개이며 중요한 모호성은 없다. 새 목록 단축키나 포커스 테두리 추가는 범위 밖이다.
