# 기능 명세: 커밋 재선택 방지와 단어 선택

> 문서 정리일: 2026-11-17. 본문은 이 기능의 단계별 요구사항 이력을 포함한다. 현재 유효 기준과 검증 한계는 [전체 명세 색인](../README.md)을 함께 확인한다. 과거 검증 기록은 현재 버전의 재검증 결과가 아니다.
> 후속 변경 참고: [049](../049-ignore-reselected-rows/spec.md).
> 현재 기준: 같은 커밋 재선택은 후속 049에 따라 모드와 무관하게 무시한다. 뷰어 단어 선택 계약은 유지한다.

작성일: 2026-11-14
상태: 명확화 완료

## 사용자 시나리오 및 검증

### 사용자 이야기 1 — 같은 커밋 유지 (우선순위 P1)
커밋 기록 모드에서 현재 선택된 행을 다시 클릭해도 파일 선택, 뷰어 내용, 스크롤, 진행 중 조회가 유지된다.
수용 기준: 같은 행 클릭은 새 조회나 선택 초기화를 발생시키지 않는다. 다른 행 클릭은 기존처럼 커밋 상세로 이동한다. 작업 트리 모드에서 행을 처음 선택하면 같은 인덱스라도 커밋 기록으로 전환한다.
독립 검증: 선택 전후 조회 세대, 취소 상태, 파일 선택, 뷰어 대상과 스크롤을 비교한다.

### 사용자 이야기 2 — 단어 더블클릭 (우선순위 P1)
커밋 상세 또는 diff 본문 글자를 더블클릭하면 그 단어만 선택하고 복사할 수 있다.
수용 기준: 한글·영문·숫자·밑줄이 연속된 범위를 단어로 선택한다. 기호는 클릭한 한 글자, 공백은 연속 공백을 선택한다. 빈 줄과 줄 끝 바깥 클릭은 빈 선택으로 처리한다. 일반 클릭과 Shift 클릭, 드래그 및 복사는 기존 동작을 유지한다.
독립 검증: 유니코드·탭·단어 경계·문장 부호·빈 줄의 선택 범위와 복사 결과를 확인한다.

## 요구사항

- FR-001: 같은 프로젝트의 현재 커밋 행 재선택은 커밋 기록 모드에서 조회·취소·파일 선택·스크롤을 변경하지 않아야 한다.
- FR-002: 다른 커밋 선택, 작업 트리에서 기록으로의 전환, 참조 선택에 따른 커밋 이동과 잘못된 이벤트 차단은 유지해야 한다.
- FR-003: 두 뷰어의 공유 본문에서 더블클릭한 단어를 문자 단위 범위로 선택해야 한다.
- FR-004: 더블클릭은 Shift 여부와 무관하게 클릭한 단어를 선택하며, 마우스를 미세하게 움직여도 선택이 바로 축소되지 않아야 한다.
- FR-005: 유니코드와 화면상 확장된 탭을 원문 위치로 변환하고 공백·기호·빈 줄·줄 끝을 안전하게 처리해야 한다.
- FR-006: 기존 클릭·Shift 선택·일반 드래그·복사·포커스·차단 조건은 유지해야 한다.

## 성공 기준

- SC-001: 동일 행 재선택 회귀 테스트에서 모든 관찰 상태가 유지되고 조회가 추가되지 않는다.
- SC-002: 단어 선택 경계 테스트에서 선택 범위와 복사 문자열이 기대값과 모두 일치한다.

## 가정 및 명확화

추가 질문 0개. 동일 행 무동작은 데이터와 선택 동작에 적용하며 기존 패널 클릭 포커스는 유지한다. 기록 모드 여부로 최초 진입과 재선택을 구분한다. 단어의 범위는 코드 식별자에 맞게 밑줄을 포함한다. 더블클릭 후 단어 단위 드래그 확장과 입력창의 더블클릭 변경은 범위 밖이다.
