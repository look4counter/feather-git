# 검증 결과

## 워크플로우와 일관성 분석

명세·명확화·계획·작업·일관성 분석·구현·수렴을 수행했다. 사용자 정정에 따라 Stage 버튼을 유지하고 Enter 제거를 FR-007과 사용자 이야기 3에 반영했다. 추가 질문은 0개이며 명세 품질 점검 5/5 통과다. FR-001은 T003, FR-002~005는 T004~006, FR-006~007은 T007, 검증은 T008~009에 대응한다. 세 사용자 이야기와 경계 조건 사이에 누락·모순·중복은 없다. Constitution은 미작성 템플릿이므로 적용 가능한 규칙은 없으며 확장 훅 파일도 없다.

## 구현 결과

- src/diff_viewer.rs: 번호·기호를 본문과 같은 shape_styled_line, 글꼴, 행 높이와 원점으로 그린다. 임의의 픽셀 보정을 사용하지 않는다.
- src/virtual_list.rs: 선택적 fixed_left_width 설정을 추가했다. 기본값 0은 기존 동작을 유지한다. 고정 모드의 세로 목록은 가로 이동하지 않고 본문 범위 계산용 투명 스크롤 컨테이너가 기존 수평 핸들을 관리한다. 가로 스크롤바 시작점은 본문에 맞춘다.
- src/diff_viewer.rs: diff 본문 그림·선택 배경·커서에 수평 오프셋을 적용하고 본문 경계에서 클리핑한다. 마우스 클릭·더블클릭의 좌표를 같은 원점으로 변환한다. 드래그와 커서 노출은 고정 여백을 제외한 영역을 사용한다. 상세 화면은 기존 전체 스크롤을 사용한다.
- Stage 버튼·체크박스·구간 Stage·기존 Stage 처리 함수는 유지했다. Enter 기본 바인딩과 저장된 Enter를 제거하고 Enter 키 명령을 무시한다. 다른 키 설정은 유지하며 Stage 단축키가 없으면 버튼에 괄호 안내를 표시하지 않는다.

## 자동 검증 결과

- cargo check --offline: 통과.
- cargo fmt --check: 통과.
- cargo test --offline: 230개 통과, 실패 0개, 기존 성능 측정용 2개 제외.
- 새 테스트는 고정 여백·본문 폭과 최대 스크롤 범위 보존, 스크롤바 이동, 좁은 폭, 본문 좌표, 커서 Home/End 노출, Enter 기본·저장 설정 제거 및 다른 키 유지와 버튼 문구를 검증한다.
- cargo clippy --offline --all-targets: 통과. 기존 미사용 코드·중첩 조건·의존성 경고는 남아 있다.
- cargo build --offline: 컴파일·링크 이후 target/debug/feather-git.exe 교체에서 액세스 거부로 실패했다. 실행 파일 잠금으로 보인다. 테스트 실행 파일의 컴파일·링크·실행은 성공했다.

## 화면 검증 제한

computer-use 스킬로 현재 앱 창을 조회했다. 새로 링크된 target/debug/deps/feather_git.exe를 화면 검증용으로 실행하려 했으나 자동 승인 검토가 해당 앱 사용이 승인되지 않았다는 이유로 거부했다. 추가 실행이나 기존 앱 종료는 수행하지 않았다. 실제 픽셀 정렬·고정 스크롤·휠·마우스 선택·버튼 클릭은 이번에 화면에서 검증하지 못했다. quickstart.md의 수동 시나리오와 자동 검증 범위를 구분한다.

## 수렴 검토

FR-001~007, SC-001~003, 세 사용자 이야기 및 계획의 단일 가상 목록·기존 핸들 재사용·좌표 변환·기존 기본 모드 보존·버튼 유지와 Enter 제거를 코드와 테스트로 대조했다. 미구현·부분 구현·상충·범위 밖 추가 항목은 0건이다. 추가 구현 작업은 없으며 화면 검증과 실행 파일 교체의 환경 제한은 위에 기록했다. 이 제한을 실제 GUI 검증 완료나 일반 빌드 성공으로 보고하지 않는다.
