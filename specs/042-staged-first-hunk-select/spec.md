# 기능 명세: Staged 우선 정렬과 구간 선택

## 사용자 시나리오 및 검증

### 사용자 이야기 1 — Staged 먼저 표시 (우선순위 P1)
사용자는 작업 트리 변경 파일에서 모든 Staged 항목을 미스테이지 항목보다 먼저 본다.
수용 기준: 경로명과 무관하게 Staged 그룹이 앞에 오고 각 그룹 내부는 기존 경로 순서다. 동일 파일에 두 상태가 있으면 두 행을 유지하며 클릭한 행에 맞는 diff를 연다. 커밋 기록의 파일 순서는 유지한다.
독립 검증: 앞선 경로의 미스테이지 파일과 뒤쪽 경로의 Staged 파일을 함께 만들고 목록·표시 상태·원본 모델의 순서를 확인한다.

### 사용자 이야기 2 — 구간 선택 (우선순위 P1)
사용자는 기존 구간 Stage 대신 구간 선택 버튼으로 해당 구간의 변경 줄 체크를 조작한다.
수용 기준: 버튼은 구간 선택으로 표시하고 클릭만으로 인덱스나 작업 파일을 변경하지 않는다. 해당 구간의 추가·삭제 줄을 모두 체크하고, 이미 모두 체크된 구간은 해제한다. 다른 구간의 체크는 유지한다. 실제 Stage는 선택한 줄 Stage 버튼으로 수행한다.
독립 검증: 두 구간의 체크 집합을 구간별로 선택·해제하고 비변경 행과 다른 구간이 영향을 받지 않는지 확인한다.

## 요구사항

- FR-001: 작업 트리 파일을 Staged 우선, 같은 상태에서는 경로 순으로 정렬한다.
- FR-002: 표시 행과 diff 원본의 인덱스를 일치시키고 중복 경로의 두 상태를 유지한다.
- FR-003: 커밋 기록 파일 순서와 기존 조회·새로고침·선택 보존을 유지한다.
- FR-004: 구간 Stage 버튼을 구간 선택으로 바꾸고 구간의 추가·삭제 줄 체크만 토글한다.
- FR-005: 다른 구간과 문맥 행을 보존하고 잘못된 구간·변경 줄 없음은 안전하게 처리한다.
- FR-006: 구간 선택 클릭은 쓰기 작업을 실행하지 않으며 로딩·작업 중 차단을 유지한다. 기존 선택한 줄 Stage 버튼과 Enter 비활성 정책은 유지한다.

## 성공 기준

- SC-001: 서로 다른 경로와 동일 경로 상태 조합의 정렬·행 대응 테스트가 통과한다.
- SC-002: 구간 선택·부분 체크·재클릭 해제·다른 구간 보존·경계 테스트가 통과한다.

## 가정과 명확화

추가 질문 0개. 버튼 이름 변경은 기능도 직접 Stage에서 체크 선택으로 변경하는 의미로 해석한다. 구간 선택은 기존 체크박스와 동일한 토글 규칙을 사용한다. 새 정렬 옵션이나 Stage 기능 변경은 범위 밖이다.
