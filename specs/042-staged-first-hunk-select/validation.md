# 검증 결과

## 워크플로우와 일관성

명세·명확화·계획·작업·일관성 분석·구현·수렴을 수행했다. 추가 명확화 질문 0개, 명세 품질 점검 5/5 통과다. FR-001~003은 T003~004, FR-004~006은 T005~006, 전체 검증은 T007~008에 대응한다. 두 사용자 이야기와 수용 기준에 누락·모순·중복은 없었다. Constitution은 미작성 템플릿이므로 규칙 검토를 생략했으며 확장 훅은 없다.

## 구현과 재현

- src/diff_git.rs: 작업 트리 정렬을 staged 내림차순 → path 오름차순으로 변경했다. 표시 모델과 diff 원본이 같은 순서를 사용하며 커밋 기록 조회는 변경하지 않았다.
- 실제 Git 저장소 회귀 테스트는 구현 전 a.txt 미스테이지가 먼저 나오는 실패를 확인했다. 수정 후 m.txt·z.txt Staged, a.txt·m.txt 미스테이지 순으로 통과했다. 표시 행·상태·실제 diff 원본의 대응과 커밋 기록 경로 순서도 검증했다.
- src/diff_viewer.rs: 구간 Stage를 구간 선택으로 바꾸고 기존 hunk_rows → toggle 경로로 연결했다. 구간 클릭은 체크 집합만 바꾸며 mutate·stage를 호출하지 않는다.
- 기존 체크 토글은 toggle_checked_rows로 추출해 체크박스·키보드 체크·구간 선택이 동일한 로직을 사용한다. 전체 선택·재클릭 해제·부분 선택 완성·다른 구간 보존·문맥 행 제외·빈 구간·잘못된 헤더 및 범위 밖 행을 검증했다.
- stage의 구간 매개변수는 제거하고 체크한 줄만 처리하도록 했다. 기존 선택한 줄 Stage 버튼과 사용자 지정 Stage 키 및 Enter 비활성 정책은 유지했다.

## 자동 검증

- cargo test --offline: 232개 통과, 실패 0개, 기존 성능 측정용 2개 제외. 새 회귀 테스트 2개를 포함한다.
- cargo fmt --check: 통과.
- cargo clippy --offline --all-targets: 통과. 기존 미사용 코드·중첩 조건·의존성 경고는 남아 있다.
- cargo build --offline: 컴파일·링크 후 target/debug/feather-git.exe 교체 단계에서 액세스 거부로 실패했다. 실행 파일 잠금으로 보이며 기존 앱을 종료하지 않았다. 테스트 실행 파일의 컴파일·링크 및 실행은 성공했다.

## 수렴 검토 및 한계

FR-001~006, SC-001~002, 두 사용자 이야기와 계획의 원본 정렬·표시 대응·기존 구간 분석 재사용·체크만 변경·실제 Stage 분리를 코드와 테스트로 대조했다. 미구현·부분 구현·상충·범위 밖 추가 항목은 0건이며 추가 구현 작업은 없다. 실제 창에서의 클릭과 목록 표시, 실행 파일 교체 완료는 미검증이다. quickstart.md에 실제 창 검증 절차를 남겼으며 이를 자동 테스트 성공과 구분한다.
