# 기능 명세: 패널별 하단 단축키 배지

> 문서 정리일: 2026-11-17. 본문은 이 기능의 단계별 요구사항 이력을 포함한다. 현재 유효 기준과 검증 한계는 [전체 명세 색인](../README.md)을 함께 확인한다. 과거 검증 기록은 현재 버전의 재검증 결과가 아니다.
> 후속 변경 참고: [050](../050-panel-context-menus/spec.md).
> 현재 기준: 하단 Space 안내는 050에서 제거했다. 현재 작업 안내는 컨텍스트 메뉴 배지를 사용하고 Space 동작은 유지한다.

작성일: 2026-11-14
상태: 명확화 완료

## 사용자 시나리오 및 검증

### 사용자 이야기 1 — 변경 파일 단축키 (우선순위 P1)
작업 트리의 변경 파일 패널에 포커스가 있으면 하단에 space 키 배지와 선택파일 스테이지 토글 설명이 표시된다. Space를 누르면 선택한 파일이 미스테이지이면 전체 Stage, Staged이면 Unstage된다.
수용 기준: 작업 파일 내용과 다른 파일의 Stage 상태를 보존한다. 선택 없음·커밋 기록·모달·조회 중·쓰기 중에는 실행하지 않는다. 완료 후 파일 목록과 뷰어를 갱신하고 가능하면 같은 파일의 반대 상태를 선택한다. 오류는 사용자에게 표시한다.
독립 검증: 추가·수정·삭제 및 최초 커밋 이전 파일의 Stage/Unstage와 잠금 오류를 테스트한다.

### 사용자 이야기 2 — 뷰어 단축키 안내 (우선순위 P1)
DiffViewer에 직접 포커스가 있고 구간 선택 가능한 변경이 있으면 하단에 space 배지와 현재 줄/범위 선택 설명이 표시된다.
수용 기준: 부분 Stage 가능한 diff에 추가·삭제 줄이 있을 때만 표시한다. 상세·Staged·로딩·모달·쓰기 중·설정 입력에는 표시하지 않는다. 사용자 지정 toggle 키가 있으면 실제 키를 배지로 표시한다. 기존 뷰어 내부 현재 줄/선택 범위 체크 안내는 삭제한다.
독립 검증: 각 상태의 안내 정책과 기존 체크·Enter 비활성 정책을 검증한다.

## 요구사항

- FR-001: 하단 상태 표시줄에 키 배지와 설명을 콜론 없이 나란히 표시하고 실제 포커스에 따라 즉시 갱신한다.
- FR-002: 변경 파일 작업 트리 패널의 안내는 space와 선택파일 스테이지 토글이다.
- FR-003: 변경 파일의 Space는 선택 파일 전체의 Stage/Unstage를 비동기로 수행하고 중복 입력을 막는다.
- FR-004: 인덱스 잠금과 오래된 상태 검사를 유지하고 작업 파일·다른 파일의 변경을 보존하며 오류를 표시한다.
- FR-005: 뷰어의 안내는 실제 toggle 키와 현재 줄/범위 선택이며 구간 선택이 가능한 변경 줄이 있을 때만 표시한다.
- FR-006: 기존 뷰어 내부의 현재 줄/선택 범위 체크 문구를 제거하고 체크·구간 선택·Stage 버튼·Enter 비활성은 유지한다.
- FR-007: 다른 패널·창 비활성·입력 자식·모달에서는 해당 안내나 단축키가 누출되지 않는다. 기존 하단 상태 정보는 유지한다.

## 성공 기준

- SC-001: 포커스·모드·조회·작업 상태에 따른 안내 정책 테스트가 통과한다.
- SC-002: 파일별 Stage/Unstage의 내용 보존과 오류·경계 회귀 테스트가 통과한다.

## 가정 및 명확화

추가 질문 0개. 하단은 기존 전역 상태 표시줄이다. Stage 토글은 선택한 단일 파일 행에 적용한다. 안내는 작업 트리 모드에서 표시하며 실행 가능한 선택이 없으면 입력은 무동작이다. 충돌 파일은 기존 해결 검증을 통과할 때만 Stage한다. 사용자 지정 키는 기존 설정을 유지한다. 새 단축키 설정 UI나 다중 파일 선택은 범위 밖이다.

## 표시 형식 보완

사용자 요청에 따라 두 패널의 단축키 배지와 설명 사이 콜론을 제거한다. 기존 간격·설명·단축키 동작은 유지한다. 추가 질문이 필요한 모호성은 없다.
