# 검증 결과

## 워크플로우와 일관성

명세·명확화·계획·작업·일관성 분석·구현·수렴을 수행했다. 추가 질문 0개, 명세 품질 점검 5/5 통과다. FR-001은 T006, FR-002~004는 T003~004, FR-005~006은 T005~006, FR-007은 T004~006에 대응한다. 두 사용자 이야기와 경계 조건에 미해결 모호성·누락·모순·중복은 없다. Constitution은 미작성 템플릿이므로 규칙 검토를 생략했으며 확장 훅은 없다.

## 구현 결과

- src/ui.rs: 기존 상태 표시줄에 키 배지와 설명을 추가했다. 작업 트리 변경 파일 패널 직접 포커스에서 space·선택파일 스테이지 토글을 표시한다. 모달·작업·조회·창 비활성 상태는 숨긴다. 목록 포커스 구독·창 활성 구독과 뷰어 observe로 하단을 갱신한다.
- src/diff_viewer.rs: 부분 선택 가능한 변경 줄이 있고 뷰어가 직접 포커스를 받을 때 실제 toggle 키·현재 줄/범위 선택을 제공한다. 설정 입력·로딩·쓰기·상세·Staged에는 표시하지 않는다. 기존 내부 현재 줄/선택 범위 체크 문구는 제거했다. 기존 체크·구간 선택·Stage 버튼과 Enter 비활성은 유지했다.
- src/ui.rs: 파일 패널에 수정키 없는 Space를 연결하고 현재 선택·모드·포커스·조회·모달·병행 쓰기를 검사한다. 비동기 실행 후 기존 갱신 경로로 목록을 재조회하고 같은 파일의 반대 상태를 선택한다. 오류는 기존 하단 상태 문구로 표시한다.
- src/diff_git.rs·src/backend.rs: 전체 파일 Stage/Unstage를 기존 I/O 게이트웨이·백그라운드 실행기·IndexLock·gix 필터 파이프라인으로 연결했다. 잠금 안에서 현재 인덱스와 예상 상태를 비교하고 Unstage는 HEAD의 해당 항목만 복원한다. 최초 커밋 이전 파일은 인덱스에서만 제거한다. 충돌은 기존 해결 검증 경로를 사용한다.

- cargo check --offline: 통과.
- cargo fmt --check: 통과.
- cargo test --offline: 236개 통과, 실패 0개, 기존 성능 측정용 2개 제외.
- 새 테스트 4개: 추가·수정·삭제 파일의 Stage/Unstage와 작업 파일·다른 Staged 파일 보존, 최초 커밋·잠금·stale 인덱스, 파일 요청의 선택·모드·조회·busy·수정키 가드, 뷰어 안내 조건과 사용자 지정 키를 검증했다.

## 수렴 검토 및 미검증 범위

FR-001~007, SC-001~002, 두 사용자 이야기와 계획의 직접 포커스·구독·배지·비동기 쓰기·인덱스 잠금·선택 보존·기존 문구 제거를 코드와 테스트로 대조했다. 미구현·부분 구현·상충·범위 밖 기능은 0건이며 추가 구현 작업은 없다. 실제 GUI에서 배지 배치·포커스 전환·키 입력·오류 표시를 실행한 검증은 하지 않았다. 일반 실행 파일 교체 완료도 미검증이다. quickstart.md에 실제 창 검증 시나리오를 남겼고 이를 자동 검증 통과와 구분한다.

## 콜론 제거 보완 검증

명세·명확화·계획·작업·일관성 분석·구현·수렴을기존 산출물에 이어 수행했다. 공통 하단 안내의 콜론 접두부 한 곳을 제거하여 파일 패널과 뷰어 패널 모두 적용했다. 기존 배지·간격·설명·입력 동작은 유지한다. 보완 요구사항과 구현의 불일치는 0건이다. cargo fmt --check 및 cargo check --offline가 통과했다. 표시 문자열 한 줄 변경이므로 새 테스트와 전체 회귀 테스트는 추가 실행하지 않았다. 실제 화면은 미검증이다.
