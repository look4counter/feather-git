# 검증 결과

## 워크플로우와 일관성

명세·명확화·계획·작업·일관성 분석·구현·수렴을 수행했다. 추가 질문 0개, 명세 품질 점검 4/4 통과다. FR-001~002는 T003, FR-003은 T004, FR-004~007은 T005~007에 대응한다. 세 사용자 이야기와 경계 조건에 누락·모순·중복은 없다. Constitution은 미작성 템플릿이므로 규칙 검토를 생략했고 확장 훅은 없다.

## 구현 및 재현

- src/ui.rs: 파일 갱신 요청 생성에서 그래프 준비 여부를 분리했다. 일반 탐색은 기존 정책을 유지하고 Stage 완료를 받는 viewer_changed는 request_file_data(false)를 사용한다. 원래 PanelRequest::execute의 작업 트리 조회는 load_stage만 수행하므로 저장소 전체·참조·커밋 기록 읽기는 추가하지 않는다.
- 기존 쓰기 갱신 회귀 테스트를 강화하여 그래프 캐시가 없는 조건에서 구현 전 request.graph.is_none 단언 실패를 재현했다. 수정 후 파일 요청만 생성하며 결과 history가 None이고 참조 세대·커밋 ID·스크롤·파일 선택이 보존됨을 검증했다.
- src/ui.rs: 태그는 명시적 #B9A2EF 분기로 첫 행과 다른 행 모두 보라색이다. 원격 붉은색·로컬 민트색 및 글자·아이콘 공통 색상 전달은 유지했다.
- src/diff_model.rs·src/diff_git.rs: Diff에 실제 파일 끝 행 집합과 빈 텍스트 EOF 표시 메타데이터를 추가했다. 이전·이후 파일의 마지막 줄을 생성했을 때만 표시 대상에 포함한다. 중간 구간이나 5,000줄 제한으로 중단된 결과에 가짜 EOF를 붙이지 않는다.
- src/diff_viewer.rs: 파일 diff에서만 공백 ·, 탭 →, EOF를 MUTED 장식으로 그린다. 원문 셰이핑·탭 4칸·좌표 변환을 유지하고 EOF 표시 폭은 가로 측정에 포함했다. 빈 파일 EOF는 표시 전용 행이다. 공백 장식은 가시 범위만 그리고 점·화살표 셰이핑은 행 안에서 재사용한다.

## 자동 검증

- cargo check --offline: 통과.
- cargo fmt --check: 통과.
- cargo test --offline: 239개 통과, 실패 0개, 기존 성능 측정용 2개 제외.
- 기존 Stage 갱신 회귀를 강화하고 새 테스트 3개로 원문 공백·탭·한글의 표시 위치와 복사, 파일 끝·마지막 개행 유무·추가·삭제·빈 파일·바이너리·중간 구간을 검증했다. 기존 부분 Stage·키보드·선택 테스트도 통과했다.
- 전체 테스트 후 5,000줄 잘림의 EOF 경계 단언을 보강하고 cargo test --offline eof_annotations를 재실행해 관련 테스트 2개가 통과했다. 이후 cargo fmt --check도 통과했다.
- cargo clippy --offline --all-targets: 통과. 기존 미사용 코드·중첩 조건·의존성 경고는 남아 있다.
- cargo build --offline: 컴파일·링크 후 target/debug/feather-git.exe 교체 단계에서 액세스 거부로 실패했다. 실행 파일 잠금으로 보이며 기존 앱을 종료하지 않았다. 테스트 실행 파일의 컴파일·링크·실행은 성공했다.

## 수렴 및 미검증 범위

FR-001~007, SC-001~002, 세 사용자 이야기와 계획의 갱신 경계·색상·실제 EOF·원문 장식·선택 및 Stage 보존을 코드와 테스트로 대조했다. 미구현·부분 구현·상충·범위 밖 추가 항목은 0건이며 추가 구현 작업은 없다. 실제 창에서 점·화살표·EOF 배치와 태그 색상, 마우스 선택 및 화면 갱신을 실행한 검증은 하지 않았다. 일반 실행 파일 교체 완료도 미검증이다. quickstart.md의 실제 창 검증과 자동 테스트 통과를 구분한다.
