# 구현 계획

## 기존 구조와 원인 분석

Rust 2024·GPUI 앱이다. Git의 읽기 전용 status는 사용자 지정 저장소에서 0건을 반환했다. core.autocrlf=true, core.filemode=false이며 LF·CRLF·혼합 줄바꿈 파일이 있다.
src/diff_git.rs의 status는 gix status iterator의 모든 IndexWorktree 항목을 변경 파일로 변환한다. 현재 사용 중인 gix 0.90.0 소스의 index_worktree::Item::summary는 EntryStatus::NeedsUpdate와 변경으로 취급하지 않는 디렉터리 항목에 None을 반환한다. 이 항목이 원인일 가능성을 조사했으나 실제 저장소 재현에서 유지보수 항목은 0개였고 직접 원인은 설치 설정의 core.autocrlf 누락으로 확정했다.

## 설계 및 영향 범위

src/diff_git.rs의 open에서 기존 libgit2 기본 설정의 줄바꿈 세 값을 메모리에 보완한다. 이미 지정된 gix 값과 기존 상태·충돌 경로는 유지한다. stat 필터 변경이나 인덱스 강제 갱신, 사용자 설정·파일 줄바꿈 변경은 하지 않는다.
같은 파일의 stat을 초기화한 임시 저장소로 구현 전 실패를 재현한다. 실제 사용자 저장소는 환경 변수로 경로를 받는 명시적 무시 테스트에서 읽기만 하며 조회 전후 인덱스 바이트가 같은지 확인한다. 수동 테스트는 기본 테스트 실행에서 제외한다.

## 아키텍처 검토

수정 범위는 src/diff_git.rs의 저장소 열기와 내부 테스트다. 기존 I/O 게이트웨이·비동기 UI·정렬·공개 데이터 형식·의존성은 유지한다. Constitution은 미작성 템플릿이므로 적용 규칙은 없다. 기존 Git 정규화 파이프라인을 재사용하고 내용 비교를 중복 구현하지 않는다.

## 검증

재현 테스트와 읽기 전용 실제 저장소 검증을 구현 전후 실행한다. 기존 실제 수정·추가·삭제·충돌·Stage 테스트를 포함한 전체 cargo test --offline, cargo fmt --check, cargo clippy --offline --all-targets, cargo build --offline를 수행한다. 실제 앱 화면·실행 파일 교체 제한을 별도로 기록한다.

## 실제 재현 후 원인 및 설계 갱신

외부 저장소 테스트에서 유지보수 항목은 0개, 줄바꿈을 실제 변경으로 판정한 항목은 85개였다. gix의 core.autocrlf는 없었고 Git과 기존 의존성 libgit2는 설치 설정에서 true를 읽었다. stat 재현은 수정 전부터 통과했으므로 summary 필터는 이번 문제의 해결책으로 추가하지 않는다.
기존 gix 설정 로드는 유지하고 기존 libgit2의 기본 설정에서 core.autocrlf·core.eol·core.safecrlf만 보완한다. gix에 해당 키가 이미 있으면 건드리지 않아 저장소·사용자 설정 우선순위를 보존한다. typed key 검증과 메모리 snapshot commit만 사용하며 설정 파일에는 쓰지 않는다. 외부 드라이버·명령 설정은 읽어 적용하지 않는다. 이 보완은 상태와 기존 Stage clean 파이프라인이 같은 기준을 사용하게 한다.
설정 상속·로컬 덮어쓰기·CRLF와 LF 동등성·실제 수정 보존 회귀 테스트를 추가한다. 기존 명세·계획·작업의 누락과 모순을 다시 점검한 뒤 구현한다.

## 크기 차이 최적화 경계 보완

로컬 회귀에서 LF 원문을 CRLF로 다시 저장한 경우를 검사하자, gix-status 0.37.0의 FastEq가 stat.size와 실제 파일 크기가 다르면 clean 변환 없이 content_change를 반환함을 확인했다. 같은 파이프라인의 clean 결과는 인덱스 blob과 동일했다. 외부 저장소 설정 보완만으로 실제 보고 사례는 해결됐지만 이 경계도 유지해야 한다.
줄바꿈 정규화가 true/input이고 내용 변경만 보고된 일반 파일이며 크기가 다른 경우에 한해 기존 clean 파이프라인 결과와 인덱스 blob을 비교한다. 정규화된 출력은 작은 버퍼로 읽고 비교하며 해시나 외부 필터 실행을 새로 구현하지 않는다. 실행 권한·타입·충돌·삭제·Staged는 이 검사로 제외하지 않는다. 실제 내용 차이가 있으면 기존대로 표시한다. 테스트의 깨끗함 단언은 유지하고 실패 원인을 구현에서 해결한다.
