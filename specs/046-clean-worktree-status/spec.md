# 기능 명세: 깨끗한 작업 트리의 잘못된 변경 표시 수정

> 문서 정리일: 2026-11-17. 본문은 이 기능의 단계별 요구사항 이력을 포함한다. 현재 유효 기준과 검증 한계는 [전체 명세 색인](../README.md)을 함께 확인한다. 과거 검증 기록은 현재 버전의 재검증 결과가 아니다.

작성일: 2026-11-14
상태: 명확화 완료

## 사용자 시나리오 및 검증

### 사용자 이야기 1 — 실제 변경만 표시 (우선순위 P1)
Git에서 변경이 없는 저장소는 앱 작업 트리에도 파일을 표시하지 않는다.
수용 기준: Git과 동일한 줄바꿈 설정을 적용하고 내용이 같은 파일을 변경으로 표시하지 않는다. 실제 미스테이지·Staged·추가·삭제·충돌은 계속 표시하고 기존 정렬과 diff 원본 대응을 유지한다.
독립 검증: 내용은 같고 인덱스 stat만 오래된 임시 저장소에서 Git과 앱이 모두 빈 변경 목록을 반환하는지 확인한다.

## 요구사항

- FR-001: Git 설치 설정에서 상속한 줄바꿈 정규화를 반영하여 실제 내용·상태 변화가 없는 파일을 변경 목록에서 제외한다.
- FR-002: 실제 변경·Staged·추가·삭제·충돌과 기존 정렬·선택·diff 연결은 유지한다.
- FR-003: 상태 조회는 인덱스나 작업 파일을 수정하지 않는다.
- FR-004: 사용자가 지정한 feather-git-old를 읽기 전용으로 검증하고 실제 Git 상태와 앱 결과를 비교한다.

- FR-005: 저장소·사용자 설정의 우선순위와 외부 필터 실행 차단을 유지하며 필요한 줄바꿈 값만 메모리에 보완한다.

## 성공 기준

- SC-001: stat 갱신만 필요한 저장소의 재현 테스트에서 변경 목록이 비어 있다.
- SC-002: 실제 대상 저장소를 읽는 수동 검증에서 Git과 앱이 모두 변경 0건이고 인덱스 내용은 유지된다.

## 경계와 명확화

추가 질문 0개. core.autocrlf=true와 LF/CRLF 혼합이 존재하므로 내용 정규화와 무관한 임의 무시 규칙은 추가하지 않는다. 진단 결과 이 저장소의 직접 원인은 설치 설정의 core.autocrlf 누락이다. 기본 설정에서 줄바꿈 값만 안전하게 보완한다. 사용자 저장소의 강제 갱신·checkout·인덱스 쓰기·설정 변경은 수행하지 않는다.
