# 구현 계획

## 기존 구조와 호출 관계
Rust 2024·GPUI 앱이다. src/diff_git.rs의 status는 원본 FileChange 목록을 Staged → 전체 경로 바이트 순서로 정렬한다. workspace_backend::changed_files는 같은 순서를 표시 모델로 변환하고 Workspace는 해당 인덱스로 diff 원본을 찾는다. 표시 목록만 따로 정렬하면 연결이 어긋나므로 원본 목록의 정렬 비교만 바꾼다. history는 별도 경로로 전체 경로 순서를 사용한다.

## 설계와 영향 범위
src/diff_git.rs에 작업 트리 비교 함수를 두어 Stage 상태 → 변경 종류 순위 → 평면 트리 경로 순으로 비교한다. 상태 순위는 U·M·D·A·기타다. 경로는 Git의 / 구분자로 컴포넌트를 읽고 같은 깊이에서 파일이면 폴더보다 앞에 두며 같은 종류면 이름 바이트순으로 비교한다. 공통 폴더 이름이면 다음 컴포넌트로 계속 비교한다. 경로 문자열을 재작성하거나 실제 트리·폴더 행을 추가하지 않는다.
수정 범위는 src/diff_git.rs와 내부 테스트다. 공개 모델·상태 조회 의미·Stage·UI·커밋 기록 정렬은 유지한다.

## 아키텍처 검토
Constitution은 미작성 템플릿이므로 적용 가능한 규칙은 없다. 기존 정렬 지점을 재사용하며 별도 UI 정렬이나 의존성을 추가하지 않는다. 바이트 경로를 그대로 비교해 유니코드 손실 변환과 플랫폼 경로 구분자 문제를 피한다.

## 검증
실제 임시 Git 저장소에서 두 Stage 그룹의 M·D·A와 루트·부모 폴더·깊은 폴더 파일을 만들고 구현 전 실패를 재현한다. 표시 모델 대응과 같은 경로의 두 상태 및 기존 history 순서를 확인한다. 순수 경로 비교로 접두어·대소문자·유니코드·충돌 상태를 검증한다. cargo fmt --check, cargo test --offline, cargo clippy --offline --all-targets, cargo build --offline를 실행하고 실제 화면 및 실행 파일 교체 제한을 기록한다.

## 2026-11-16 충돌 우선 변경 계획

기존 status → worktree_file_order → workspace_backend::changed_files → 화면·diff 선택의 데이터 흐름을 확인했다. 충돌은 status에서 unstaged U 행으로 수집한다. 분류는 바꾸지 않고 비교기의 상태 순위만 U·M·D·A·기타로 바꾼다. 비교기는 staged 우선이므로 unstaged 충돌을 staged 일반 파일보다 앞으로 옮기지 않는다. 공개 API·데이터·의존성·계층 변경은 없다. 헌장은 미작성 템플릿이며 기존 구조 원칙에 충돌하지 않는다.
검증은 두 그룹의 충돌·일반·기타 상태, 충돌 내 경로 순서, 빈 목록, 기존 충돌 수집과 표시 모델 대응 회귀 테스트로 수행한다. 변경 비교기는 src/diff_git.rs 한 곳으로 제한한다.
