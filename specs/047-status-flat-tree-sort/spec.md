# 기능 명세: 상태와 평면 폴더 트리 기준 정렬

> 문서 정리일: 2026-11-17. 본문은 이 기능의 단계별 요구사항 이력을 포함한다. 현재 유효 기준과 검증 한계는 [전체 명세 색인](../README.md)을 함께 확인한다. 과거 검증 기록은 현재 버전의 재검증 결과가 아니다.

작성일: 2026-11-14
상태: 명확화 완료

## 사용자 시나리오 및 검증

### 사용자 이야기 1 — 상태 우선 정렬 (우선순위 P1)
작업 트리 변경 파일에서 Staged 그룹과 미스테이지 그룹을 유지하면서 각 그룹을 충돌(U) → 변경(M) → 삭제(D) → 추가(A) 순으로 표시한다.
수용 기준: 경로 이름보다 변경 종류가 먼저 적용된다. 충돌(U)은 각 그룹의 맨 앞에 표시한다. 같은 파일의 두 Stage 상태는 별도 행으로 유지한다.
독립 검증: 실제 저장소에서 두 그룹의 M·D·A를 함께 만들고 정확한 전체 순서를 비교한다.

### 사용자 이야기 2 — 폴더 트리를 펼친 경로 순서 (우선순위 P1)
같은 상태의 항목은 루트 파일을 먼저 표시하고 각 하위 폴더의 파일을 재귀적으로 나열한다.
수용 기준: 같은 폴더의 파일은 파일명 오름차순, 하위 폴더는 폴더명 오름차순이며 현재 폴더 파일 뒤에 표시한다. 같은 상태의 예시는 index.html → backend/z.rs → backend/src/gemini.rs다. 실제 트리 UI나 폴더 행은 추가하지 않는다.
독립 검증: 루트·같은 폴더·깊은 폴더·이름 접두어·유니코드 경로의 순서를 확인한다.

## 요구사항

- FR-001: 작업 트리의 최상위 정렬은 Staged 우선·미스테이지 나중이다.
- FR-002: 그룹 내부는 U → M → D → A → 기타 상태 순으로 정렬한다.
- FR-003: 같은 상태의 경로는 현재 폴더 파일 우선, 하위 폴더는 이름순 재귀 순회로 정렬한다.
- FR-004: 경로 비교는 기존처럼 대소문자를 구별하고 원본 Git 경로를 사용한다. 표시 모델과 diff 원본 순서를 일치시킨다.
- FR-005: 커밋 기록 모드의 기존 파일 순서와 선택·Stage·오류·실제 변경 판정을 유지한다.

## 성공 기준

- SC-001: 두 Stage 그룹과 M·D·A 조합의 실제 저장소 순서 및 표시 행 대응 테스트가 통과한다.
- SC-002: 평면 폴더 트리 경계와 충돌·중복 상태 정렬 테스트가 통과한다.

## 가정 및 명확화

추가 질문 0개. 앞선 대화의 루트 파일 우선 기준을 각 폴더에서도 적용한다. 충돌은 각 그룹 맨 앞에 두고 알 수 없는 상태는 M·D·A 뒤에 둔다. 작업 트리 그룹 정렬만 변경하고 커밋 기록이나 파일명 대소문자 정책은 바꾸지 않는다.

## 2026-11-16 요구사항 갱신 및 명확화

사용자 요청에 따라 충돌을 각 staged·unstaged 그룹의 맨 앞으로 변경한다. 그룹 순서와 같은 상태 내 경로 순서는 유지한다. 충돌의 실제 분류를 변경하거나 두 그룹에 중복 표시하지 않는다. 두 그룹에 충돌·일반·기타 상태를 섞은 정렬 검증에서 그룹 우선과 충돌 우선이 동시에 성립해야 한다. 충돌이 없으면 기존 순서를 유지하며 빈 목록도 정상 처리한다. 명확화 검토 결과 추가 질문이 필요한 모호성은 없다.
