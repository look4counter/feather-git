# 조사 결과

- 결정: 기존 단일 목록 API는 어댑터로 보존하고 파일 목록만 다중 선택 이벤트를 사용한다. 다른 목록의 조작을 바꾸지 않는다.
- 결정: 기존 파일 DiffViewer를 자식으로 재사용한다. 한 Diff로 병합하는 대안은 행 인덱스·체크·Stage·충돌 범위를 다시 구현해야 하므로 제외한다.
- 결정: 선택 복원은 경로·Stage 상태 집합이다. 행 번호는 Stage 후 재정렬로 달라지므로 사용할 수 없다.
- 결정: 같은 경로의 두 상태는 사용자 답변대로 Stage 우선으로 합친다. 배치 실패는 파일별로 보고하고 성공한 결과를 숨기지 않는다.
- 결정: 숨겨진 쓰기 중 자식은 완료까지 유지하여 기존 비동기 완료 이벤트를 보존한다.
