# 기능 명세: 저장소·커밋 기록 중복 선택 무시

> 문서 정리일: 2026-11-17. 본문은 이 기능의 단계별 요구사항 이력을 포함한다. 현재 유효 기준과 검증 한계는 [전체 명세 색인](../README.md)을 함께 확인한다. 과거 검증 기록은 현재 버전의 재검증 결과가 아니다.

작성일: 2026-11-14
상태: 명확화 완료

## 사용자 시나리오 및 검증

### 사용자 이야기 1: 저장소 재선택 (우선순위 P1)
현재 저장소 탭에서 선택된 행을 다시 클릭하면 선택 후속 처리를 하지 않는다. 로컬·원격·태그·스태시에서 동일하게 적용한다.
수용 기준: 조회 중 재선택도 기존 조회를 취소/교체하지 않고, 변경 파일·커밋·스크롤·선택·오류 안내를 보존한다. 다른 행은 기존대로 선택한다.

### 사용자 이야기 2: 커밋 기록 재선택 (우선순위 P1)
현재 선택된 커밋을 다시 클릭하면 작업 트리/커밋 기록 모드에 관계없이 후속 처리를 하지 않는다.
수용 기준: 작업 트리에서 현재 강조된 커밋을 클릭해도 탭 전환·변경 파일 재조회가 없다. 다른 커밋은 기존대로 커밋 기록/상세를 연다. 조회 중 동일 클릭은 요청을 보존한다.

## 명확화

현재 강조된 행을 선택된 항목으로 간주한다. 커밋 기록은 작업 트리 모드에서도 현재 커밋을 강조하므로 동일 행은 모드 전환 없이 무시한다. 다른 행 선택의 기존 조회 동작 변경은 이번 범위 밖이다. 추가 질문이 필요한 모호성은 없다.

## 요구사항

- FR-001: 저장소 현재 탭에서 이미 선택된 유효 행의 재선택은 false를 반환하고 후속 이벤트·상태 갱신을 생략한다.
- FR-002: 커밋 기록의 현재 프로젝트·커밋 재선택은 모드와 무관하게 false를 반환하고 후속 처리를 생략한다.
- FR-003: 재선택 시 조회 요청·세대·취소 토큰·선택·본문 대상·스크롤·안내를 보존한다.
- FR-004: 다른 행 선택과 잘못된/오래된 이벤트 방어는 유지한다.

## 성공 기준

- SC-001: 저장소 네 탭과 커밋 두 모드의 재선택 보존 회귀 테스트가 통과한다.
- SC-002: 다른 행 선택 및 기존 전체 회귀 테스트가 통과한다.

## 경계 및 범위

첫 선택·빈 목록·탭 전환 후 선택·범위 밖·다른 프로젝트 이벤트를 구분한다. 포커스 획득은 기존 패널 정책을 유지하며 UI 프레임워크의 마우스 이벤트 전달 자체를 제거하지는 않는다. 중복 선택에 따른 애플리케이션 후속 처리를 차단한다.
