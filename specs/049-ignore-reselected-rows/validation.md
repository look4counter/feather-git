# 검증 결과

## 단계별 결과

speckit-specify로 네 저장소 탭·커밋 두 모드의 동일 행 재선택 무시를 정의했다. speckit-clarify에서 현재 강조된 커밋을 선택된 항목으로 판단하고 다른 행 선택 최적화는 범위 밖으로 확정했다. speckit-plan은 기존 선택 모델 반환값과 조회 호출 흐름을 분석했으며 speckit-tasks는 재현→구현→회귀 순서로 정의했다. speckit-analyze는 요구사항 네 개·성공 기준 두 개와 작업의 누락·모순·중복이 없음을 확인했다. 확장 훅 설정은 없으며 Constitution은 미작성 템플릿이다.

speckit-implement에서 기존 SingleSelection.select의 false를 저장소 선택 후속 처리 전에 반환하고 커밋 기록 가드의 file_history 조건을 제거했다. 마우스 이벤트 자체와 패널 포커스 처리는 기존대로 유지한다.

## 테스트와 정적 분석

- 새 재선택 테스트 두 개가 수정 전 실패하여 문제를 재현했다.
- 수정 후 전체 테스트: 250개 통과, 실패 0개, 기존 3개 제외.
- 조회 중/완료의 저장소 네 탭 재선택에서 요청·취소 토큰·세대·본문 대상·안내 보존을 검증했다.
- 작업 트리 커밋 재선택에서 모드·파일 선택·본문 대상·세대를 보존하고 다른 커밋 선택은 계속 동작함을 검증했다. 기존 커밋 기록 조회 중/완료 재선택 보존 테스트도 통과했다.
- 기존 실패 네 개는 테스트가 탭 필드를 직접 바꾸거나 반복 클릭으로 갱신을 시작하던 준비 동작이었다. 실제 탭 선택 API 및 현재 커밋과 다른 행을 선택하도록 준비를 수정했고, 반복 저장소 클릭의 기존 복귀 기대는 새 요구사항의 무동작과 세대 보존 검증으로 바꿨다. 기존 검증 목적은 유지했다.
- cargo fmt --check: 통과.
- cargo clippy --offline --all-targets: 통과, 기존 경고만 존재한다.
- cargo build --offline: 컴파일·링크 후 실행 중 target/debug/feather-git.exe 제거가 액세스 거부(os error 5)로 실패했다. 실행 파일 교체와 실행 중 앱 반영은 미완료다.

## 검증 한계

실제 GUI 입력은 검증하지 않았다. 현재 실행 중 앱은 교체되지 않았다. 다른 저장소 행을 새로 선택할 때의 기존 변경 파일 조회 동작은 이번 요청 범위에 포함하지 않아 유지한다.

## 수렴 점검

speckit-converge에서 FR-001~004, SC-001~002 및 두 사용자 이야기의 재선택/다른 선택 수용 기준을 src/ui.rs와 테스트에 대조했다. 저장소 가드는 후속 조회 취소와 세대 변경 전에 종료하며, 커밋 가드는 모드와 관계없이 동일 프로젝트·행에서 종료한다. bool 기반 UI 콜백은 false일 때 notify를 생략한다. 기존 유효성 가드·다른 행 선택·포커스 구조는 유지한다. 계획의 기존 모델 재사용과 영향 범위, T001~T004 구현/검증이 일치한다. 구체 Constitution 검사는 템플릿이므로 생략했다. 미해결 구현 차이 0개로 tasks.md를 추가 수정하지 않았다. GUI·실행 파일 교체 제한은 별도 기록했다.
