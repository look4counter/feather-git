# 기능 명세: 선택 파일 변경사항 폐기

## 사용자 시나리오 및 검증

### 사용자 이야기 1: 선택 파일 폐기 (우선순위 P1)
작업 트리 컨텍스트 메뉴에 변경사항 폐기를 표시한다. 선택한 파일의 스테이지·미스테이지 변경을 모두 HEAD 상태로 복구한다. HEAD에 없는 신규 파일은 삭제하고 인덱스에서도 제거한다. 같은 파일의 두 행은 한 번만 처리한다. 다른 파일과 커밋 이력은 보존한다.
수용 기준: 수정/삭제/추가 및 스테이지와 미스테이지가 함께 있는 파일을 처리한다. 첫 커밋 전 신규 파일도 지원한다. 바이너리·한글·공백·패턴 문자 경로도 해당 파일만 처리한다.

### 사용자 이야기 2: 실행 전 확인 (우선순위 P1)
메뉴 선택만으로 파일을 변경하지 않는다. 팝업은 대상 파일 수/경로와 스테이지 포함 모든 변경 폐기, 신규 파일 삭제, 복구 불가 안내를 표시한다. 취소/Escape는 아무 변경 없이 닫는다. 폐기 버튼을 명시적으로 눌러야 실행하고 Enter로 자동 실행하지 않는다.
수용 기준: 확인 전 상태를 읽기만 하고, 확인 후 외부에서 바뀐 HEAD/인덱스/파일을 덮어쓰지 않는다. 선택이나 저장소 전환을 팝업 동안 막고 포커스를 복원한다.

### 사용자 이야기 3: 안전한 비동기 결과 (우선순위 P1)
준비와 폐기는 비동기로 실행하고 중복 입력을 막는다. 파일별 실패는 숨기지 않고 성공 수와 실패 경로/원인을 알린다. 작업 뒤 변경 파일과 DiffViewer만 갱신하며 커밋·참조·그래프는 전체 재조회하지 않는다.
수용 기준: 인덱스 잠금·오래된 원본·경로 오류·쓰기 실패에서도 다른 파일을 훼손하지 않는다. 디렉터리 재귀 삭제와 링크/서브모듈을 통한 외부 접근은 하지 않는다. 지원하지 않는 파일 유형은 오류를 명시한다.

## 명확화

- 사용자 답변: 스테이지 포함 모든 변경 폐기.
- 사용자 추가 지시: 폐기 전 알림 팝업 확인.
- HEAD에 없는 선택 파일은 삭제하며 확인 팝업에 명시한다. 충돌 파일은 해당 경로의 HEAD 내용으로 복구하여 선택 파일 충돌 상태를 폐기한다.
- 심볼릭 링크·재분석 지점·서브모듈은 안전한 일반 파일 복원이 아니므로 명시적으로 거부한다. 파일 경로를 통한 디렉터리 재귀 삭제는 하지 않는다.

## 요구사항

- FR-001: 작업 트리 메뉴에 변경사항 폐기를 추가하고 유효 선택/조회·쓰기·모달 조건을 검증한다.
- FR-002: 경로별 중복을 제거하고 선택 파일의 작업 파일/인덱스를 HEAD로 복원하며 신규 파일은 삭제한다. 다른 경로는 보존한다.
- FR-003: 대상 수·경로·전체 변경 폐기/신규 삭제/복구 불가를 알리는 취소/폐기 확인 팝업을 제공한다. 취소/Escape/Enter는 파괴 작업을 실행하지 않는다.
- FR-004: 확인 전 준비는 읽기만 하며 실행 시 HEAD·인덱스·작업 파일 스냅샷을 재검증하고 잠금·원본 변경·안전하지 않은 경로는 거부한다.
- FR-005: 비동기 처리·중복 실행 차단·부분 성공/실패 안내와 파일만 갱신하는 기존 흐름을 유지한다.

## 성공 기준

- SC-001: 실제 임시 Git 저장소에서 스테이지/미스테이지 수정·추가·삭제·중복·충돌·첫 커밋 전·바이너리/리터럴 경로·다른 파일 보존·오래된 원본·잠금 거부 테스트가 통과한다.
- SC-002: 확인 전 무변경·취소·실행 조건을 자동 검증하고 서식·전체 회귀·Clippy를 통과한다. 실제 GUI 검증 한계는 별도 기록한다.

## 후속 요구사항: 폐기 단축키

- FR-006: 변경사항 폐기 메뉴에 Ctrl + D 배지를 표시한다. 작업 트리 패널 포커스에서 수정키 없는 Ctrl+D만 기존 폐기 준비/확인 팝업 경로를 호출한다. 메뉴가 열린 동안에도 같은 단축키로 해당 항목을 실행한다.
- 수용 기준: 빈 선택·조회/쓰기 중·확인 팝업·다른 패널/커밋 기록 모드에서는 실행하지 않는다. 확인 버튼 전에는 파일을 변경하지 않는다. 기존 Space는 유지한다.
- 명확화: 단축키는 폐기 즉시 실행이 아닌 기존 확인 팝업 열기다. 추가 질문이 필요한 모호성은 없다.
