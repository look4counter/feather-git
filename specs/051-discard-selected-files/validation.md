# 구현 및 검증 결과

## 단계별 결과

speckit-specify로 스테이지 포함 전체 폐기와 실행 전 팝업 요구를 명세했다. speckit-clarify에서 사용자 답변인 스테이지 포함 모든 변경 폐기 및 확인 팝업을 반영했다. HEAD 복원·신규 파일 삭제·현재 선택 유지·링크/서브모듈 거부·부분 실패를 정의했다. speckit-plan에서 기존 메뉴/선택·Stage·IndexLock·file_index_state·Dialog 호출과 영향을 분석했다. speckit-tasks로 준비/백엔드/실제 저장소 검증/UI/회귀 작업을 정의했다. speckit-analyze에서 요구사항과 계획/작업 간 누락·모순·중복은 없었다. 확장 훅 설정은 없고 Constitution은 미작성 템플릿이다.

## 주요 변경

- src/diff_git.rs: DiscardPreview/DiscardResult와 prepare_discard/discard_selected를 추가했다. 읽기 전용 준비는 경로 중복을 제거하고 HEAD·인덱스 모든 stage·작업 파일 바이트/권한을 보존한다. 실행은 파일별 기존 IndexLock 아래 원본을 재검증한다. git2의 정확한 경로 checkout_tree로 일반 파일을 복구하고 신규 파일은 remove_file로만 삭제한다. 인덱스는 gix로 선택 경로만 HEAD로 교체한다. 작업 실패 시 원래 파일 복구를 시도하고 실패도 함께 보고한다. 다른 파일·커밋·병합 메타데이터는 유지한다.
- src/backend.rs: 새 API/타입을 기존 비동기/계측 래퍼에 등록했다.
- src/ui.rs: 작업 트리 메뉴에 변경사항 폐기를 추가했다. 준비/실행 중과 확인 중에는 기존 busy 보호를 사용한다. 팝업은 파일 수·목록·스테이지 포함 폐기·신규 삭제·복구 불가를 안내한다. 취소/Escape는 실행하지 않고 Enter도 확인하지 않는다. 명시적 폐기 버튼만 쓰기를 시작한다. 프로젝트/패널 세대를 검사하고 중복 실행을 막는다. 완료는 기존 viewer_changed를 이용해 파일 목록/뷰어만 갱신한다. 성공 수/실패 경로와 원인을 표시한다.
- src/context_menu.rs: 단축키가 없는 폐기 항목은 빈 배지를 표시하지 않도록 했다.

## 자동 검증

- 폐기 관련 신규 테스트 5개 통과.
- 실제 임시 저장소에서 스테이지/미스테이지 혼합 수정·삭제·신규·스테이지 신규·중복 행을 HEAD로 복원하고 다른 파일의 인덱스/작업 파일 및 HEAD를 보존했다.
- 한글/공백/대괄호 경로와 바이너리 원본을 복구하고 패턴과 유사한 다른 파일을 보존했다.
- 첫 커밋 전 신규 파일 제거, 스테이지 삭제 복원, 외부 바이트 변경의 부분 실패, 인덱스 변경·HEAD 변경·기존 index.lock 거부를 검증했다.
- gitattributes 기반 CRLF 복원과 선택 충돌 파일의 HEAD 복원 및 병합 메타데이터 보존을 검증했다.
- 잘못된 상대 경로·.git·디렉터리·Windows junction 경로를 거부하고 외부 목적지 파일을 보존했다.
- 준비만으로 인덱스/작업 파일이 바뀌지 않음을 검사했다. UI 확인 상태에서 다른 선택/Stage가 차단되고 취소·오래된 프로젝트·중복 확인에서 실행/재조회가 없음을 검증했다. 실제 팝업 키 처리에 쓰는 함수에서 Enter/Space가 취소/확인 키가 아님을 확인했다.
- 최종 cargo test --offline: 257개 통과, 실패 0개, 기존 3개 제외.
- cargo fmt --check: 통과.
- cargo clippy --offline --all-targets: 통과. 기존 경고만 존재한다.
- cargo build --offline: 컴파일·링크 이후 실행 중 target/debug/feather-git.exe 제거가 액세스 거부(os error 5)로 실패했다. 현재 실행 파일 교체는 미완료다.

## 검증 한계

실제 GUI에서 메뉴/팝업 외형·버튼 클릭·포커스 복원은 직접 검증하지 못했다. 현재 실행 중 앱에는 반영되지 않았다. 실제 사용자 저장소에 폐기를 실행하지 않았고 파괴 동작은 테스트용 임시 저장소에서만 실행했다. 파일별 잠금과 검사로 처리하며 여러 파일 전체의 원자적 일괄 복구는 제공하지 않는다. 링크/재분석 지점·서브모듈은 명시적 오류로 거부한다. 작업 파일 복구 실패를 유발하는 실제 디스크 장애는 재현하지 않았다.

## 수렴 점검

speckit-converge에서 FR-001~005, SC-001~002 및 세 사용자 이야기 수용 기준을 src/ui.rs·src/context_menu.rs·src/diff_git.rs·src/backend.rs와 테스트에 대조했다. 메뉴/준비/확인/명시적 실행의 분리, HEAD 기준 복원과 신규 제거, 원본/경로/잠금 검증, 부분 실패 안내, 파일만 갱신하는 호출과 기존 아키텍처 재사용이 계획과 일치한다. T001~T006은 구현과 자동 검증을 완료했다. 미해결 구현 차이와 추가 작업은 없으며 수렴 단계에서 tasks.md는 변경하지 않았다. GUI와 실행 파일 교체 등 미검증 범위는 위에 별도 기록했다.

## 후속 폐기 단축키 검증

speckit-specify로 FR-006에 Ctrl + D 배지와 확인 팝업 호출을 명세했다. speckit-clarify에서 즉시 폐기가 아닌 기존 확인 경로를 열고 다른 수정키 조합은 거부함을 명확히 했다. speckit-plan은 파일 패널 키 처리와 메뉴 포커스의 단축키 전달 흐름을 분석하고 speckit-tasks로 T007~T009를 정의했다. speckit-analyze에서 명세·계획·작업의 누락/모순은 없었다. speckit-implement로 src/ui.rs의 Ctrl+D를 기존 포커스/활성 창/쓰기/조회/모달/선택 보호 뒤 prepare_file_discard에 연결했다. src/context_menu.rs는 표시된 단축키의 key/modifiers를 비교해 메뉴가 열린 상태에도 같은 콜백을 호출한다. 기존 확인 전 읽기 전용·명시적 폐기 버튼 정책은 유지한다.

Ctrl 단독 D/다른 수정키 거부와 메뉴 배지 키 매칭 테스트를 추가했다. 기존 확인 취소/오래된 프로젝트 보호 테스트도 통과했다. 최종 cargo test --offline는 259개 통과·실패 0개·기존 3개 제외다. cargo fmt --check와 cargo clippy --offline --all-targets도 통과했다. 테스트 실행 파일 컴파일·실행을 검증했으며 배포 실행 파일 빌드는 반복하지 않았다. 실제 GUI 키 입력과 실행 중 앱 교체는 수행하지 않았다.

speckit-converge에서 FR-006과 기존 FR-001/003~005의 포커스·선택/쓰기 가드·확인 전 무실행 및 T007~T009를 코드와 대조했다. Ctrl+D 메뉴/패널 경로와 표시가 일치하며 기존 Space 및 확인 정책도 유지한다. 미해결 구현 차이와 추가 작업은 없으며 수렴 단계에서 tasks.md는 수정하지 않았다.
