# 기능 명세: 변경 파일 행 공통 메뉴

> 문서 정리일: 2026-11-17. 본문은 이 기능의 단계별 요구사항 이력을 포함한다. 현재 유효 기준과 검증 한계는 [전체 명세 색인](../README.md)을 함께 확인한다. 과거 검증 기록은 현재 버전의 재검증 결과가 아니다.
> 후속 변경 참고: [053](../053-file-history-overlay/spec.md).

작성일: 2026-11-14
상태: 명확화 완료

## 사용자 시나리오 및 검증

### 사용자 이야기 1: 파일 행에서 메뉴 열기 (우선순위 P1)
변경 파일의 작업 트리/커밋 기록 모든 탭에서 실제 파일 행을 우클릭할 때만 메뉴를 연다. 패널 제목·탭·빈 공간·커밋상세 행에서는 열지 않는다. 이미 선택된 행 우클릭은 다중 선택을 유지하고, 선택되지 않은 행이면 해당 행만 선택한 뒤 메뉴를 연다. 작업 트리의 기존 스테이지/폐기 메뉴는 유지하며 커밋 기록에는 표시하지 않는다.

### 사용자 이야기 2: OS 파일 동작 (우선순위 P1)
공통 메뉴에 열기와 탐색기에서 보기를 추가한다. 열기는 우클릭한 파일 하나를 OS 기본 앱으로 연다. 탐색기에서 보기는 우클릭한 파일 하나가 있는 폴더를 OS 파일탐색기로 연다. 두 탭 모두 저장소 작업 디렉터리의 현재 파일 경로를 사용한다. 과거 커밋 blob을 임시 추출하지 않는다. 파일이 없으면 열기는 오류를 안내하고 탐색기는 가장 가까운 기존 상위 폴더를 연다.

### 사용자 이야기 3: 경로 복사 (우선순위 P1)
경로복사 메뉴와 Ctrl + Shift + C 배지를 추가한다. 선택한 모든 파일의 절대경로를 줄바꿈으로 구분해 복사한다. 같은 경로의 중복 상태 행은 한 번만 복사하고 목록 순서를 유지한다. 작업 트리/커밋 기록 파일 패널 포커스와 메뉴가 열린 상태에서 단축키를 지원한다. 빈 선택/커밋상세 선택은 실행하지 않는다.

## 명확화

사용자 답변: 열기와 탐색기에서 열기는 우클릭한 파일 하나만이고, 경로복사는 선택한 모든 파일이다. 최신 지시에 따라 우클릭한 행이 선택되지 않았으면 해당 행 하나로 선택을 바꾼다. 이미 선택된 행에서는 기존 선택을 유지한다. 메뉴 실행 가능 조건은 변경된 선택 기준으로 계산한다.

## 요구사항

- FR-001: 메뉴 트리거를 실제 파일 행 우클릭으로 제한하고 모든 탭에서 공통 메뉴를 제공한다. 커밋상세·제목·탭·빈 공간은 제외한다.
- FR-002: 열기는 우클릭한 현재 작업 디렉터리 파일 하나를 OS 기본 앱으로 연다.
- FR-003: 탐색기에서 보기는 우클릭한 파일이 있는 폴더를 OS 탐색기로 열고 없는 파일은 가장 가까운 기존 상위 폴더로 이동한다. Windows 확장 경로 접두사는 OS 호출 경계에서 일반 경로로 변환한다.
- FR-004: 경로복사 / Ctrl + Shift + C는 선택 파일 전체의 절대경로를 순서대로 중복 제거하여 복사한다. 파일 존재 여부와 무관하게 복사할 수 있다.
- FR-005: 현재 선택·포커스·쓰기/모달/조회 보호·오래된 프로젝트/탭/세대 방어와 기존 작업 트리 메뉴/단축키 정책을 유지한다.
- FR-006: 파일 상태 확인은 비동기로 처리하고 OS 열기 실패 준비 오류를 안내하며 Git 조회·쓰기·이력 변경을 추가하지 않는다.

## 성공 기준

- SC-001: 행 경계/상세 제외·두 탭·클릭 대상과 선택 대상 분리·중복 제거·절대경로·단축키/오래된 문맥·누락 파일 처리를 자동 검증한다.
- SC-002: 전체 회귀·서식·Clippy를 통과하고 실제 OS 앱/탐색기/클립보드 검증 한계를 기록한다.

## 경계 및 범위

한글·공백·패턴 문자 경로, 삭제 파일, 없는 상위 폴더, 빈/중복 선택, 다중 파일, 파일 읽기 오류를 고려한다. OS 실행은 사용자가 해당 메뉴를 선택했을 때만 수행한다. 개발 검증 과정에서 실제 사용자 파일을 외부 앱으로 열지 않는다.

## 후속 요구사항: 탐색기 호출과 메뉴 열 겹침 수정

- FR-007: 컨텍스트 메뉴의 이름과 단축키는 서로 겹치지 않고, 단축키는 줄바꿈/축소되지 않는다. 긴 이름은 확보된 이름 영역에서 말줄임한다. 현재 메뉴명과 Ctrl + Shift + C를 함께 표시할 충분한 너비를 제공한다.
- 명확화: 탐색기에서 보기는 해당 폴더를 여는 기능이므로 파일 선택을 위한 Shell COM API 대신 폴더 기본 열기를 사용한다. 추가 질문이 필요한 모호성은 없다.

## 후속 요구사항: 공통 메뉴 구분선

- FR-008: 변경 파일 메뉴의 경로복사 아래에 뒤따르는 항목이 있으면 구분선을 표시한다. 작업 트리 전용 항목과 공통 항목을 구분하며 마지막 항목 뒤에는 불필요한 선을 표시하지 않는다.
- 명확화: 구분선은 선택/실행 대상이 아니며 기존 메뉴 순서·키보드 탐색·단축키·동작은 유지한다. 추가 질문이 필요한 모호성은 없다.

## 후속 요구사항: 우클릭 선택과 헤더 집계

- FR-009: 실제 파일 행 우클릭 시 미선택 행은 일반 클릭처럼 단일 선택한 후 메뉴를 연다. 이미 선택된 행에서는 기존 다중 선택을 유지한다. 작업 트리/커밋 기록 모두 적용하고 커밋상세·오래된 문맥·조회/쓰기/모달 차단은 유지한다.
- FR-010: 최신 원복 지시에 따라 변경 파일 헤더는 기존 전체 파일 행 개수만 표시한다. Staged·M·D·A 세부 집계와 추가 배지는 표시하지 않는다. 우클릭 선택 정책은 유지한다.
- 명확화: 우클릭의 Shift/Ctrl 수정키로 범위를 확장하지 않으며 미선택 대상은 하나로 선택한다. 전체 개수의 기존 표시 행 기준을 유지하고 M/D/A 외 상태도 전체 개수에는 포함한다. 추가 질문이 필요한 모호성은 없다.

## 후속 명확화: 개수 표시 원복

개수 표시만 기존 전체 숫자 배지와 공통 헤더 스타일로 복구한다. 별도 집계 코드/전용 테스트는 제거하고 미선택 우클릭 선택 동작과 그 테스트는 유지한다. 추가 질문이 필요한 모호성은 없다. 이전 세부 집계 요구는 최신 원복 지시로 대체됐다.

## 후속 요구사항: 파일 상태 색상 유지

- FR-011: 변경 파일 목록의 상태 글자색은 Staged 여부와 관계없이 같은 실제 상태에 같은 색상을 사용한다. A는 기존 녹색, D는 붉은색 계열, 그 외는 기존 색상을 유지한다. 상태 표시 문자열과 선택/Stage 동작은 유지한다.
- 명확화: 표시용 S· 접두사를 제외한 실제 상태로 색상을 결정한다. 작업 트리와 커밋 기록 모두 적용한다. 추가 질문이 필요한 모호성은 없다.
