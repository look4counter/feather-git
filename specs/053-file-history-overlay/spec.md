## 사용자 시나리오 및 검증

### 사용자 이야기 1: 파일 하나의 이력 열기 (우선순위 P1)
변경 파일 공통 메뉴에 파일 변경 이력을 추가한다. 마지막 우클릭한 실제 파일 하나에만 적용한다. 최신 공통 메뉴 정책에 따라 미선택 행 우클릭은 해당 행을 선택하고, 이미 선택된 행은 다중 선택을 유지한다. 팝업을 여는 동작 자체는 그 선택을 추가로 변경하지 않는다. 작업 트리·커밋 기록 탭 모두 지원하며 커밋상세 행은 제외한다. 실행하면 팝업 오버레이를 연다.

### 사용자 이야기 2: 모든 브랜치의 현재 경로 이력 (우선순위 P1)
모든 로컬/원격 브랜치와 현재 HEAD에서 도달 가능한 커밋의 해당 파일 이력을 최신 위상/시간 순으로 보여준다. 우클릭한 현재 Git 경로만 조회하고 이름 변경 전의 다른 경로로 추적하지 않는다. 같은 커밋은 한 번만 표시하고 생성·수정·삭제·병합의 첫 부모 기준 변경을 지원한다. 신규 파일처럼 커밋 이력이 없으면 빈 상태를 명시한다.

### 사용자 이야기 3: 그리드와 diff (우선순위 P1)
팝업 왼쪽은 기존 커밋 기록 그리드를 재사용해 메시지·작성자·날짜·해시를 표시하고 그래프 열만 숨긴다. 오른쪽은 기존 DiffViewer를 읽기 전용 과거 파일 대상으로 재사용한다. 첫 항목을 기본 선택하고 다른 커밋을 선택하면 그 커밋에서 해당 파일 하나의 diff를 표시한다. 같은 행 재선택은 아무 동작도 하지 않는다. 현재 경로의 추가/삭제/최초 커밋도 올바른 비교 원본을 사용한다.

### 사용자 이야기 4: 상태와 닫기 (우선순위 P1)
조회는 비동기이고 로딩·오류·빈 상태를 표시한다. 닫기 버튼과 Escape로 닫고 포커스를 복원한다. 닫힌 팝업의 늦은 결과는 적용하지 않는다. 팝업은 독립 선택/스크롤 상태를 가지며 메인 저장소·커밋·파일 선택과 diff를 바꾸지 않고 다른 Git 쓰기를 추가하지 않는다.

## 명확화

- 사용자 답변: 모든 브랜치 이력.
- 최신 사용자 지시: 이름 변경 추적을 하지 않는다. 이전 답변을 대체한다.
- 로컬·원격 브랜치와 HEAD에서 도달 가능한 전체 커밋을 조회하며 태그에만 남은 커밋과 도달 불가 커밋은 범위 밖이다. 이름 변경 시 새 경로는 추가, 이전 경로는 삭제로 취급하며 두 경로를 연결하지 않는다. 병합 diff는 기존 DiffViewer와 동일하게 첫 부모 기준이다.

## 요구사항

- FR-001: 실제 우클릭 파일 하나의 파일 변경 이력 공통 메뉴와 독립 오버레이를 제공한다.
- FR-002: 전체 로컬/원격 브랜치·HEAD의 현재 경로 이력만 조회하고 중복 커밋을 제거한다. 기존 메인 목록의 200개 제한은 적용하지 않는다.
- FR-003: 기존 커밋 그리드의 행/열 표시를 재사용하고 그래프 열을 숨긴다.
- FR-004: 기존 DiffViewer를 읽기 전용으로 재사용하고 선택 커밋/경로의 정확한 전후 객체를 전달한다. 같은 행 재선택은 무시한다.
- FR-005: 비동기·로딩/오류/빈 상태·오래된 결과 거부·닫기/Escape·포커스 복원과 팝업 독립 상태를 유지한다.
- FR-006: 메인 상태와 파일을 변경하지 않고 메인 전체 재조회/추가 Git 쓰기를 하지 않는다.

## 성공 기준

- SC-001: 임시 저장소에서 브랜치 분기/원격·중복·이름 변경 전 경로 제외·삭제/생성·병합·200개 초과 및 변경 없는 커밋 제외와 diff 원본을 검증한다.
- SC-002: 팝업 독립 선택·같은 행 무시·닫힌 조회 무효화와 그리드 그래프 열 제외를 가능한 범위에서 자동 검증하고 전체 회귀·서식·Clippy를 통과한다. GUI 한계는 별도 기록한다.

## 후속 명확화: 이름 변경 추적 제거

현재 경로의 tree 항목만 첫 부모와 비교한다. 전체 트리 diff·rename 유사도·경로 별칭 수집과 두 번 순회를 제거한다. 전체 브랜치·중복 제거·200개 제한 없음·기존 팝업은 유지한다. 추가 질문이 필요한 모호성은 없다.
