# 구현 및 검증 결과

## 단계별 결과

speckit-specify로 우클릭 파일 하나의 독립 이력 오버레이와 기존 그리드/DiffViewer 재사용을 명세했다. speckit-clarify에서 모든 브랜치와 이름 변경 전 이력 추적이라는 두 사용자 답변을 반영했다. HEAD·로컬/원격 도달 가능 커밋, 첫 부모 diff, Git 유사도 기반 경로 연결을 명확히 했다. speckit-plan은 기존 메뉴·그리드 행/헤더/크기 조절·조회·DiffViewer·Dialog 호출과 영향 범위를 분석했다. speckit-tasks로 백엔드→임시 저장소 검증→공유 그리드→팝업/수명→전체 검증을 정의했다. speckit-analyze에서 요구사항·계획·작업 사이의 누락·모순·중복이 없었다. 헤더 공유와 독립 열 크기 조절 및 숨긴 그래프 계산 생략으로 계획을 구체화한 뒤에도 FR-003/005와 작업의 일관성을 재확인했다. 확장 훅은 없고 Constitution은 미작성 템플릿이다.

## 주요 변경 파일

- src/file_history.rs: 모든 로컬/원격 브랜치와 HEAD를 시작점으로 위상/시간 정렬한 전체 커밋을 읽는다. 첫 부모 diff의 Git rename 유사도 연결로 관련 경로 집합을 추적하고 전후 tree 객체와 Commit/FileChange를 반환한다. 같은 커밋은 한 번만 표시하고 메인 200개 제한을 적용하지 않는다. 작업 파일/인덱스 변경과 외부 Git 실행은 없다.
- src/backend.rs: 파일 이력 API/타입을 기존 계측 래퍼에 등록하고 작업 루프의 읽기 취소 checkpoint를 제공한다.
- src/ui.rs: 실제 우클릭 FileMenuRequest 대상의 파일 변경 이력 공통 메뉴를 추가했다. 클릭 파일과 다중 선택을 분리하는 기존 보호를 사용한다. 팝업 동안 메인 입력을 차단하고 닫기 이벤트에서 취소·뷰어 deactivate·포커스 복원을 수행한다. 메인 커밋/파일 선택과 재조회는 변경하지 않는다. 기존 커밋 행/헤더를 공유 함수로 추출해 메인과 팝업이 같은 렌더 및 열 경계 측정/조절을 사용한다.
- src/history_grid.rs: 공통 열 제목/가시 열과 그래프 제외 최소 너비를 제공한다. 기존 열 크기 조절 알고리즘은 유지한다.
- src/history.rs: without_graph로 파일 이력에서 불필요한 그래프 계산만 생략하고 기존 HistoryState 행 준비/캐시를 사용한다.
- src/file_history_dialog.rs: 별도 엔티티의 선택·스크롤·조회 취소 슬롯·로딩/오류/빈 상태·좌우 레이아웃과 닫기/Escape를 구현했다. 첫 항목 기본 선택, 같은 행 무시, 닫힌 요청의 늦은 결과 거부를 제공한다. 오른쪽은 기존 historical=true의 DiffViewer를 재사용하여 쓰기 기능 없이 과거 객체만 비교한다.
- src/main.rs: 팝업 모듈을 등록했다.

## 자동 검증

- 파일 이력 백엔드 테스트 2개: 로컬/원격 분기·원격에만 남은 변경·중복 제거·이름 변경 전 경로·생성/수정/삭제·비관련 커밋 제외·이력 없는 파일·첫 커밋 전·205개 이력·첫 부모 기준 병합 diff를 검증했다. 항목의 전후 객체로 기존 DiffViewer 백엔드를 실행하고 작업 파일과 인덱스가 유지되는지 확인했다.
- 팝업 상태 테스트 1개: 조회 중 선택 거부·첫 항목 선택·같은 행/범위 밖 선택 거부·닫힌 조회의 늦은 결과 거부·빈 상태·오류 상태를 검증했다.
- 그리드 테스트 1개: 그래프 제외 가시 열이 메시지/작성자/날짜/해시로 유지되고 최소 너비에서 그래프만 빠지는지 확인했다.
- 기존 파일 메뉴 상태 테스트를 보강하여 우클릭 파일 하나가 이력 대상으로 전달되고 메인 커밋/뷰어/다중 선택이 바뀌지 않음을 확인했다.
- 기존 메인 커밋 행/헤더 크기 조절·선택·스크롤·DiffViewer·Stage/폐기 전체 회귀 테스트가 통과했다.
- 최종 cargo test --offline: 267개 통과, 실패 0개, 기존 3개 제외.
- cargo fmt --check: 통과. include로 등록된 새 백엔드 파일도 rustfmt --edition 2024로 정리했다.
- cargo clippy --offline --all-targets: 통과. 기존 경고만 존재한다.
- cargo build --offline: 통과. 이번 빌드에서는 실행 파일 잠금이 없었다. 프로그램을 자동 실행하거나 재시작하지 않았다.

## 검증 한계

실제 GUI의 메뉴 실행·오버레이 크기/좌우 배치·열 드래그·가로 스크롤·텍스트 선택·닫기/Escape·포커스 복원은 직접 검증하지 못했다. 해당 경로는 코드와 순수 상태 테스트로 확인했으며 실제 GUI 성공으로 주장하지 않는다. 이름 변경은 Git 유사도 기반 경로 연결이므로 대규모 재작성이나 여러 연결 경로가 공존하는 복잡한 파일 정체성은 휴리스틱의 영향을 받는다. 한 커밋에 여러 관련 경로가 있으면 요청 경로/이름 변경을 우선한다. 태그에만 남거나 도달 불가능한 커밋은 조회 범위 밖이다. 대규모 실제 저장소의 처리 시간은 별도 측정하지 않았다.

## 수렴 점검

speckit-converge에서 FR-001~006, SC-001~002와 네 사용자 이야기의 클릭 대상/전체 브랜치/rename/공유 그리드/읽기 전용 diff/독립 수명 기준을 코드와 테스트에 대조했다. 파일 메뉴는 마지막 우클릭 원본을 전달하고 선택 집합을 변경하지 않는다. 조회는 독립 취소 슬롯의 작업 스레드에서 수행하며 같은 커밋 중복과 200개 제한이 없다. 공유 행/헤더/열 조절은 메인/팝업에서 같은 함수를 사용하며 팝업은 그래프 열만 제외한다. DiffViewer에는 historical=true의 객체 원본만 전달하고 닫기 시 조회와 뷰어를 취소한다. 메인 커밋/파일/스크롤의 별도 상태를 사용한다. 계획 결정과 T001~T007은 구현 및 자동 검증과 일치한다. 구체 Constitution 검사는 템플릿이므로 생략했다. 미해결 구현 차이와 추가 작업은 없으며 수렴 단계에서 tasks.md는 수정하지 않았다. 실제 GUI와 Git rename 휴리스틱/대규모 성능의 검증 한계는 위에 기록했다.

## 후속 이름 변경 추적 제거

최신 사용자 요청으로 이전 rename 추적 요구를 대체했다. speckit-specify에서 FR-002와 시나리오/수용 기준을 현재 경로만 조회하도록 갱신하고 speckit-clarify에서 다른 브랜치의 같은 경로는 유지하되 이전 이름으로 연결하지 않음을 명확히 했다. speckit-plan은 전체 diff/find_similar/별칭 수집/두 번 순회를 요청 경로 tree 비교의 한 번 순회로 대체했다. speckit-tasks로 T008~T011을 정의했고 speckit-analyze에서 문서/작업의 충돌·누락은 없었다.

speckit-implement로 src/file_history.rs의 rename 타입/연결/별칭/전체 트리 diff와 두 번째 커밋 순회를 제거했다. 각 revwalk 커밋과 첫 부모의 원본 경로 객체/모드를 비교하여 변경 행만 생성한다. 생성/삭제/수정 원본, 모든 브랜치·중복 제거·200개 제한 없음·읽기 취소·팝업/공유 그리드/DiffViewer는 유지한다.

- 기존 테스트를 현재 경로만 포함하도록 바꾼 뒤 수정 전 과거 경로까지 6개가 나오는 실패를 재현했다.
- 수정 후 현재 경로의 변경 4개만 포함하고 이전 경로의 생성/원격 변경을 제외하는지 확인했다. 원격 브랜치의 같은 현재 경로는 포함하며, 이전 경로를 따로 조회하면 해당 경로의 독립 이력이 보이는지 확인했다. 인덱스/작업 파일 보존과 과거 객체 diff 검증도 유지했다.
- 관련 백엔드 테스트 2개 통과, 최종 cargo test --offline 267개 통과·실패 0개·기존 3개 제외.
- cargo fmt --check, rustfmt --edition 2024 --check src/file_history.rs, cargo clippy --offline --all-targets 통과.
- cargo build --offline는 컴파일·링크 후 실행 중 feather-git.exe 제거가 액세스 거부(os error 5)로 실패했다. 이번 변경의 실행 파일 교체는 미완료다.
- 실제 6만 커밋 저장소의 처리 시간과 GUI 동작은 측정/확인하지 않았다. 향상 배율이나 응답 시간을 주장하지 않는다.

speckit-converge에서 갱신 FR-002와 FR-004~006의 현재 경로·모든 브랜치·원본/중복·취소/읽기 전용 보존 및 T008~T011을 코드에 대조했다. rename/전체 diff/별칭 코드는 없으며 revwalk 한 번에서 요청 경로만 비교한다. 변경된 명세와 구현이 일치하고 미해결 차이와 추가 작업은 없다. 수렴 단계에서 tasks.md는 수정하지 않았다. 실행 파일 잠금·실제 저장소 성능/GUI 미검증은 별도 기록했다.
