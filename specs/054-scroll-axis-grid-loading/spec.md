# 기능 명세: 스크롤 축 보호와 커밋 그리드 지연 로딩

## 사용자 시나리오 및 검증

### 사용자 이야기 1: 끝에서 가로 이동 방지 (우선순위 P1)
세로 휠은 목록의 위/아래 끝에 닿아도 가로 이동으로 변환하지 않는다. 세로 범위가 없는 경우도 동일하다. 실제 가로 휠과 Shift+휠은 기존 가로 이동을 유지한다. 여러 파일 사이의 부모 세로 스크롤 전달은 유지한다.
수용 기준: 일반 세로 입력은 가로 오프셋을 바꾸지 않고 Shift/가로 입력은 기존 범위 내에서 이동한다. 고정 gutter와 일반 가로 뷰포트 모두 적용한다.

### 사용자 이야기 2: 커밋 그리드 로딩 안내 (우선순위 P1)
메인 커밋 기록과 파일 변경 이력 팝업 그리드에서 조회가 150ms를 넘길 때 기존 목록과 같은 조회 중 입니다.. 문구를 표시한다. 빠른 완료는 깜빡이지 않고 완료/오류/취소/화면 전환 후 제거한다.
수용 기준: 메인 참조 커밋 조회/그래프 준비와 팝업 자체 조회에만 연결한다. 이미 준비된 커밋 그리드는 변경 파일 조회만으로 로딩 상태가 되지 않는다. 오래된 타이머/결과가 새 요청에 반영되지 않는다.

## 명확화 및 범위

스크롤은 실제 X 입력 또는 Shift에 의해서만 가로 이동한다. 세로 경계 이벤트는 소비하지 않고 부모 세로 이동에 사용할 수 있다. 로딩은 기존 ListLoading/150ms 정책을 재사용하며 메인/팝업의 실제 조회 상태를 분리한다. 추가 질문이 필요한 모호성은 없다.

## 요구사항

- FR-001: 일반 세로 휠을 가로로 변환하지 않고 네이티브 가로 컨테이너의 자동 축 fallback을 막는다.
- FR-002: Shift/실제 X 입력·기존 클램프·드래그·고정 gutter·부모 세로 전달을 유지한다.
- FR-003: 메인 커밋 그리드의 참조 조회/그래프 준비에 150ms 지연 안내를 연결하며 파일 조회와 구분한다.
- FR-004: 파일 이력 팝업도 같은 지연 안내를 사용하고 즉시 표시하던 로딩 문구를 대체한다.
- FR-005: 완료 신호·세대·취소/화면 전환을 반영해 빠른 완료/오래된 요청의 깜빡임과 잔류 문구를 막는다. Git 조회를 추가하지 않는다.

## 성공 기준

- SC-001: 휠 축/경계·Shift/X·클램프 테스트와 네이티브 가로 컨테이너 설정 검토가 통과한다.
- SC-002: 두 그리드의 지연/빠른 완료/취소·조회 구분 회귀 테스트 및 전체 테스트·서식·Clippy를 통과한다. 실제 GUI 한계는 기록한다.
