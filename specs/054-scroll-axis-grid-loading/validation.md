# 구현 및 검증 결과

## 단계별 결과

speckit-specify로 세로 경계 가로 이동 방지와 커밋 그리드 지연 로딩을 정의했다. speckit-clarify에서 실제 X/Shift만 가로 이동하며 부모 세로 전달과 기존 150ms 안내를 유지한다고 명확히 했다. speckit-plan에서 커스텀 휠/GPUI fallback·참조 조회/그래프 준비·팝업 상태를 분석했다. speckit-tasks로 T001~T006을 정의했고 speckit-analyze에서 명세·계획·작업의 누락·모순·중복은 없었다. 확장 훅 설정은 없으며 Constitution은 미작성 템플릿이다.

## 구현 결과

- src/scrolling.rs: 세로 범위가 없을 때 일반 Y를 X로 바꾸는 fallback을 제거하고 Shift일 때만 축 변환한다. 실제 X 입력과 클램프는 유지한다.
- src/virtual_list.rs: 고정 gutter용 가로 extent와 일반 가로 viewport 모두 restrict_scroll_to_axis=true를 적용했다. 경계 이벤트를 부모에 전달하는 기존 소비 조건을 유지해 여러 파일 사이 세로 이동은 보존한다. vendor 코드는 수정하지 않았다.
- src/ui.rs: 참조 확장 조회용 commit_loading을 추가하고 요청 시작/백엔드 완료 신호/유효 결과/취소·전환에 연결했다. 메인 그리드는 참조 조회 또는 실제 그래프 준비가 필요한 panel_loading만 사용한다. 준비 중 빈 그리드도 렌더하여 기존 ListLoading 타이머와 문구를 재사용한다. 이미 준비된 커밋 그리드는 파일만 조회할 때 로딩으로 가리지 않는다.
- src/file_history_dialog.rs: 팝업 상태에 ListLoading을 추가하고 begin/완료 신호/finish/close를 연결했다. 즉시 문구를 제거하고 조회 중 빈 VirtualList로 같은 150ms 안내를 표시한다. 오류/빈 상태·독립 선택·오래된 결과/닫기 보호는 유지한다.

## 자동 검증

- 수평 전용 목록에서도 일반 Y를 X로 바꾸지 않아야 한다는 기대값으로 수정 전 실패를 재현했다. 이는 실제 GUI 하단 이벤트 전달의 통합 재현이 아니라 별도 휠 fallback 정책의 재현이다.
- 스크롤 테스트 5개 통과: 상하 경계의 가로 오프셋 보존·Shift/실제 X 이동·클램프·드래그/스크롤바 계산을 확인했다. 네이티브 가로 두 컨테이너의 축 제한과 부모 전달은 코드로 검토했다.
- 메인 그리드 테스트: 참조 조회의 149ms 미표시/150ms 표시·동일 행 재선택 보존·백엔드 완료 즉시 숨김·오류 완료·탭 전환 취소·그래프 준비/파일 조회 구분을 확인했다.
- 팝업 테스트: 149ms 미표시/150ms 표시·완료/닫기 reset·늦은 결과 거부·빠른 완료 후 충분한 시간(1초)이 지나도 안내가 나타나지 않음을 확인했다.
- 전체 cargo test --offline: 272개 통과, 실패 0개, 기존 3개 제외. 빠른 완료 테스트의 미래 시각 조건을 보강한 뒤 해당 테스트도 다시 통과했다.
- cargo fmt --check: 통과.
- cargo clippy --offline --all-targets: 통과, 기존 경고만 존재한다.
- cargo build --offline: 컴파일·링크 후 실행 중 target/debug/feather-git.exe 제거가 액세스 거부(os error 5)로 실패했다. 실행 파일 교체는 미완료다.

## 검증 한계

실제 GUI의 휠 경계/다중 파일 부모 이동·Shift/터치패드·로딩 문구 외형/타이밍은 직접 확인하지 못했다. 코드와 순수 상태 테스트로 검증했으며 화면 검증 완료로 주장하지 않는다. 현재 실행 중 앱에는 반영되지 않았다. Git 조회/쓰기/외부 의존성은 추가하지 않았다.

## 수렴 점검

speckit-converge에서 FR-001~005, SC-001~002 및 두 사용자 이야기의 축/경계·부모 전달·실제 조회 구분·150ms/완료/취소/세대 기준을 코드와 테스트에 대조했다. 일반 Y fallback이 없고 두 네이티브 가로 영역이 축을 제한한다. 메인 참조/그래프와 팝업은 각각 기존 지연 상태를 사용하며 파일 조회만으로 커밋을 가리지 않는다. 계획과 T001~T006이 구현/자동 검증과 일치하고 미해결 구현 차이/추가 작업은 없다. 수렴 단계에서 tasks.md는 수정하지 않았다. GUI 및 실행 파일 잠금 제한은 위에 별도 기록했다.
