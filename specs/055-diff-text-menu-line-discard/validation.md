# 구현 및 검증 결과

## 단계별 결과

speckit-specify로 텍스트 전용 우클릭/공통 복사와 체크 줄 폐기를 명세했다. speckit-clarify에서 원문 폭의 hit·선택 유지·현재 인덱스 기준 부분 폐기·명시적 확인·나머지 작업/스테이지 보존을 정의했다. speckit-plan으로 기존 canvas/선택/키 복사·부분 Stage 알고리즘/원본 검사·IndexLock·Viewer 이벤트/Workspace Dialog를 분석했다. speckit-tasks로 T001~T005를 정의하고 speckit-analyze에서 누락·모순·중복이 없음을 확인했다. 확장 훅은 없고 Constitution은 미작성 템플릿이다.

## 구현 결과

- src/diff_viewer.rs: 두 패널 루트 Right 핸들러를 제거하고 selectable_text의 보이는 원문 bounds/editor viewport/원점/폭에서만 Right를 처리한다. header/gutter/스크롤바/빈 줄/끝 여백은 제외한다. 복사 / Ctrl + C를 공통 항목으로 제공하며 선택이 없으면 비활성이다. 기존 키 copy도 같은 원문 복사 함수를 사용한다. 실행 가능한 경우에만 선택한 줄 체크를 덧붙인다. 우클릭으로 선택을 변경하지 않고 메뉴 세대를 재검증한다.
- 같은 파일에서 체크한 줄 스테이지 옆에 체크한 줄 폐기를 추가했다. 요청에는 원래 뷰어 WeakEntity·세대/대상·파일·원문/표시 줄·체크 행을 보존한다. 다중 뷰어는 기존 이벤트 전달 구조로 요청을 부모에 전달한다.
- src/ui.rs: 기존 파일 전체 폐기 Dialog를 줄 폐기 확인에도 재사용한다. 파일명/체크 줄 수/Stage·나머지 보존/복구 불가를 표시하며 취소/Escape/Enter는 쓰지 않는다. 명시적 폐기 버튼만 요청을 실행한다. 확인 중 main 입력을 차단하고 포커스를 복원한다. 확인 후 원래 뷰어의 세대/대상을 검사하며 모달로 인한 interactive=false와 명시적 확인 권한을 구분한다. 기존 mutate의 성공/실패/파일만 갱신하는 경로를 사용한다.
- src/partial_stage.rs: Preview의 원문 전체 diff 순회와 검증을 공유하고 폐기 모드에서 체크한 삭제만 복원·미체크 추가만 유지한다. 표시되지 않은 변경도 after에 유지한다. 기존 apply도 같은 검증/알고리즘을 사용한다.
- src/diff_git.rs: 기존 IndexLock/경로/원본 검사 아래 작업 파일만 변경한다. 인덱스에 쓰지 않으며 동일 폴더의 새 임시 파일 기록/동기화·권한 보존·원본 재검증 후 교체한다. 신규 파일의 모든 추가 줄을 폐기하면 remove_file만 사용한다. 실패 시 생성한 임시 파일만 정리하며 기존 동명 파일은 제거하지 않는다. 읽기 전용 파일은 거부한다.
- src/backend.rs: 부분 폐기와 작업 파일 쓰기를 기존 래퍼에 등록했다. 외부 의존성/영속 형식/추가 전체 조회는 없다.

## 자동 검증

- 텍스트 hit 테스트 1개: gutter·끝 여백·빈 줄·세로 밖·가로 오프셋을 확인했다.
- 부분 폐기 테스트 4개: 실제 임시 저장소에서 부분 체크만 복원하고 기존 Stage/다른 작업 변경/다른 파일/인덱스 원문을 보존했다. 신규 파일 일부/전체 제거·삭제 파일 부분/전체 복원·CRLF·EOF·한글/패턴 문자 경로를 확인했다.
- 오래된 작업 파일/인덱스·기존 index.lock·필터·상위 경로를 거부하고 파일/잠금 소유자 데이터를 보존했다.
- 원문 6000줄 변경에서 표시 줄에 없는 변경을 유지함을 검증했다.
- 기존 원문 선택/공백/탭/복사·메뉴 조건·부분 Stage·전체 폐기·다중 뷰어/오래된 대상 회귀 테스트가 통과했다.
- 확인 Dialog의 취소/Escape/Enter 가드는 기존 공통 키 함수/전체 폐기 테스트를 재사용하며 줄 요청/다중 이벤트 전달·취소 무실행·실행 시 세대 검증의 연결은 코드로 검토했다. 실제 GUI 확인 통과로 주장하지 않는다.
- cargo test --offline: 277개 통과, 실패 0개, 기존 3개 제외.
- cargo fmt --check 및 rustfmt --edition 2024 --check src/partial_stage.rs: 통과.
- cargo clippy --offline --all-targets: 통과, 기존 경고만 존재한다.
- cargo build --offline: 컴파일·링크 후 실행 중 feather-git.exe 제거가 액세스 거부(os error 5)로 실패했다. 이번 실행 파일 교체는 미완료다.

## 검증 한계

실제 GUI의 텍스트 우클릭/선택·클립보드·확인 팝업/포커스·다중 파일에서 버튼 클릭은 직접 검증하지 못했다. 디스크 장애/동시 외부 파일 교체 경쟁의 모든 경우는 재현하지 않았다. 사용자 실제 저장소에는 폐기를 실행하지 않았으며 삭제/복원 테스트는 임시 저장소에서만 실행했다.

## 별도 diff 표시 문의 조사

실제 diff 코드는 before 객체와 after 작업 파일을 줄바꿈 정규화 없이 similar.diff_lines로 비교하고 표시 때만 CR/LF를 제거한다. 동일 similar 라이브러리의 독립 재현에서 인덱스 LF 3줄 대 작업 파일 CRLF 3줄(한 줄 수정)은 삭제 3/추가 3/동일 0, 줄바꿈을 맞춘 경우 삭제 1/추가 1/동일 2였다. 실제 문의 파일은 지정되지 않아 해당 파일의 원인을 확정하지 않는다. 이 문의는 읽기/재현 확인만 수행했고 diff 줄바꿈 코드를 수정하지 않았다.

## 수렴 점검

speckit-converge에서 FR-001~006, SC-001~002와 세 시나리오의 텍스트 경계/공통 복사/조건부 체크/체크 줄만 폐기/확인·세대·원본 보호/기존 흐름 보존을 코드와 테스트에 대조했다. 패널 Right는 없고 canvas 원문 hit에서만 열리며 복사와 체크는 기존 선택을 사용한다. 부분 폐기 알고리즘은 미체크/표시 밖 변경을 보존하고 인덱스에 쓰지 않는다. 명시적 확인 이벤트/다중 전달/취소 및 mutate/파일 갱신이 계획과 일치한다. T001~T005의 구현/자동 검증과 문서가 일치하고 미해결 구현 차이와 추가 작업은 없다. 수렴 단계에서 tasks.md는 수정하지 않았다. GUI/실행 파일 교체 및 별도 줄바꿈 조사 한계는 위에 기록했다.
