# 구현 및 검증 결과

## 단계별 결과

speckit-specify로 FR-001~004와 원문 보존/빈 행 기준을 정의했다. speckit-clarify에서 LF/CRLF만 비교 시 동등하게 취급하고 마지막 개행/공백/독립 CR은 유지하며 빈/공백 본문 행만 메뉴 범위를 넓힌다고 명확히 했다. speckit-plan으로 표시/부분 쓰기/토크나이저/EOF의 연결을 분석하고 speckit-tasks로 T001~T005를 정의했다. speckit-analyze에서 문서/작업 누락·모순은 없었다. 확장 훅은 없으며 Constitution은 미작성 템플릿이다.

## 변경 결과

- src/line_endings.rs·src/main.rs: 비교용 CRLF 정규화와 대상의 주된 개행 선택/새로 가져온 원문 줄의 개행 변환을 공유한다. LF 입력은 Cow로 불필요한 복제를 피한다.
- src/diff_git.rs: 비교에서만 정규화하고 원문 Preview·상태 검증·줄 번호/EOF·기존 내용 동일 안내를 유지한다.
- src/partial_stage.rs: 같은 비교와 similar 원문 tokenize_lines 인덱스로 매핑한다. Equal/유지 줄은 쓰기 대상 원문을 그대로 사용하고 상대에서 새로 가져오는 줄만 대상의 주된 개행에 맞춘다. 인덱스/작업 파일 일괄 변환이나 원본 검사 완화는 없다.
- src/diff_viewer.rs: 빈/공백 줄의 편집 영역과 빈 파일 EOF 행에서 메뉴를 허용한다. 일반 줄의 끝 여백·gutter·본문 밖·스크롤바 제외와 선택/복사/체크 조건은 유지한다.

## 검증

- 수정 전 교차 개행 테스트 2개 실패로 전체 3줄 삭제/추가 및 부분 Stage의 CRLF 혼입을 재현했다.
- 수정 후 인덱스 LF/작업 CRLF 한 줄 수정은 삭제/추가 1줄만 표시하고 줄바꿈만 바뀌면 변경 행이 없으며 마지막 개행 차이는 EOF와 함께 유지된다.
- LF↔CRLF 양방향·혼합 개행·마지막 개행 없음의 부분 Stage/폐기에서 인덱스·작업 파일·미변경 원문을 바이트로 확인했다.
- 정규화 함수에서 공백/탭·독립 CR·마지막 개행 보존과 원문 개행 선택을 확인했다.
- 빈/공백 행 hit와 비본문/일반 줄 끝 여백 제외 테스트가 통과했다.
- 최종 cargo test --offline: 280개 통과, 실패 0개, 기존 3개 제외.
- cargo fmt --check 및 cargo clippy --offline --all-targets: 통과. 기존 경고만 존재한다.
- cargo build --offline: 통과. 프로그램을 자동 실행/재시작하지 않았다.

## 수렴과 한계

speckit-converge에서 FR-001~004와 SC-001~002 및 T001~T005를 코드/테스트에 대조했다. 비교 정규화·원문/EOF 보존·동일 매핑·빈 행 메뉴가 일치하며 미해결 구현 차이와 추가 작업은 없다. 수렴 단계에서 tasks.md는 수정하지 않았다. 실제 GUI의 diff/EOF/우클릭/클립보드와 사용자 6만 커밋 저장소 동작은 직접 검증하지 않았다. 혼합 개행의 미변경 줄은 그대로 보존하며 새로 가져오는 줄은 대상의 주된 형식(동률 LF)을 사용한다.
