# 구현 계획

## 기존 구조 분석

FileHistoryDialog는 독립 FileHistoryState/선택/ReadSlot과 기존 커밋 행을 사용하지만 Right 핸들러가 없다. FileHistoryEntry는 Commit.id와 FileChange 원본을 보유한다. workspace_backend.prepare_file_location과 path_display.absolute_file_path가 저장소 위치/누락 상위 폴더를 준비한다. 공통 context_menu는 전역 overlay이며 Workspace는 repository_busy 때 이를 닫으므로 파일 이력 모달 내부 메뉴를 허용하는 조건 보완이 필요하다.

## 설계

src/file_history.rs에 export_revision을 추가하고 src/backend.rs 래퍼에 등록한다. 해당 커밋 tree에서 경로를 다시 확인해 일반 파일 blob만 읽는다. OS 임시 디렉터리 아래 앱 전용/커밋/고유 경로에 확장자를 유지한 파일을 create_new로 기록·동기화하고 읽기 전용으로 만든다. 파일명에는 커밋 접두사를 붙여 Windows 예약 이름과 충돌을 피한다. 성공한 추출 파일은 팝업이 열린 동안 보관하며, 닫기 및 정상 종료 시 아래 추가 설계에 따라 삭제한다. 실패 시 생성한 파일/빈 폴더만 정리한다. 테스트에는 target 아래 별도 임시 캐시를 전달한다.

src/file_history_dialog.rs에 행 우클릭 콜백과 공통 메뉴를 연결한다. 선택 뒤 generation/행으로 원래 항목을 캡처한다. 열기는 export_revision, 탐색기는 prepare_file_location을 별도 취소 슬롯에서 실행하고 완료 시 팝업/세대를 재검증한다. 경로 복사는 순수 절대경로 결합과 clipboard를 사용한다. 실패는 팝업 내 오류로 표시한다. 삭제/특수 모드 열기는 비활성이다. 현재 선택이 바뀌어도 요청한 원래 행을 대상으로 하되 팝업이 닫히거나 데이터 세대가 바뀌면 OS를 실행하지 않는다.

src/ui.rs의 전역 메뉴 닫기 조건은 다른 모달/차단에는 유지하면서 활성 파일 이력 오버레이 내부 메뉴를 허용한다. 메인 목록은 기존 repository_busy 보호로 계속 막는다. 외부 의존성/Git 쓰기는 없다. Constitution은 미작성 템플릿이다.

## 검증

실제 임시 Git 저장소의 두 커밋에서 원문 blob·확장자·읽기 전용·고유 추출과 현재 파일/인덱스 보존을 확인하고 삭제/이탈 경로/커밋 오류를 검증한다. 팝업 상태의 행/세대/닫기와 저장소 경로 대상을 검증한다. 전체 테스트·서식·Clippy·빌드를 실행하고 OS 실행/클립보드/GUI 미검증은 기록한다.

## 추가 설계: 팝업 종료와 앱 종료 정리

현재 export_revision은 경로만 반환하며 ReadSlot 취소 시 작업의 반환값이 버려질 수 있다. 따라서 UI 완료 콜백에서만 등록하면 파일이 누락된다. 별도 src/history_temp.rs의 팝업별 세션을 작업 스레드로 공유하고, 추출 함수가 반환하기 전에 등록한다. 닫힌 세션에 나중에 등록되는 파일도 즉시 정리한다. 세션 잠금으로 닫기와 등록을 직렬화한다.

앱 전체 레지스트리에 생성 파일을 함께 등록한다. 팝업 닫기는 해당 세션의 파일만 정리하고 성공하면 전역 목록에서도 제거한다. 실패 항목은 전역에 남긴다. Application.run 반환 후 main에서 남은 항목을 재시도한다. 세션 Drop은 비명시적 해제도 처리한다. 전역 종료 상태를 기록해 종료 이후 완료된 작업도 즉시 정리한다. 작업 중인 세션 파일도 전역에 있으므로 팝업이 열린 채 종료하는 경우를 다룬다.

읽기 전용 속성은 Windows에서만 해제한 뒤 파일과 해당 파일 전용 빈 디렉터리를 삭제한다. 재귀 삭제는 하지 않으며 등록한 경로 외 파일에 접근하지 않는다. 삭제 실패는 로그를 남긴다. tempfile은 현재 개발 의존성이며 자동 Drop만으로 실패 재시도 및 진행 중 작업 처리가 되지 않아 기존 추출 구조를 재사용한다. 외부 API/의존성 변경은 없다. 종료 시에도 OS 잠금이 남으면 삭제를 보장하지 않으며 다음 실행 정리는 추가하지 않는다.

검증은 실제 읽기 전용 추출물 정리, Windows 공유 금지 핸들로 삭제 실패 재현 후 종료 재시도, 중복 닫기, 닫기 이후 등록, 세션 격리, 전체 테스트·서식·Clippy·빌드로 수행한다. Constitution은 미작성 템플릿으로 충돌 검사를 적용할 규범이 없다.
