# 구현 및 검증 결과

## 구현 결과

- 파일 이력 커밋 행에 공통 컨텍스트 메뉴를 연결했다. 우클릭 행을 선택하고 해당 커밋 원문 열기, 저장소 위치 탐색기 열기, 저장소 절대경로 복사를 제공한다. 삭제 및 일반 파일이 아닌 항목의 열기는 비활성이다.
- src/file_history.rs·src/backend.rs는 정확한 blob을 확장자를 유지한 고유 읽기 전용 파일로 추출한다. 원본 작업 파일과 인덱스는 유지한다. 생성 실패 시 기존 파일을 제거하지 않도록 소유 파일 가드를 생성 성공 이후 설치했다.
- src/history_temp.rs는 팝업별 파일 세션과 앱 전체 미삭제 파일 목록을 관리한다. 읽기 전용 속성 해제는 Windows에만 적용한다. 파일과 파일별 빈 디렉터리만 삭제하며 재귀 삭제는 없다.
- src/file_history_dialog.rs는 작업 스레드에 세션을 공유하고 deactivate에서 세션을 닫는다. 추출 완료 시 반환 전에 등록하므로 취소로 반환값이 버려져도 파일은 추적된다. 닫힌 세션에 늦게 등록되면 즉시 삭제한다.
- src/main.rs는 GPUI 이벤트 루프 종료 후 전체 미삭제 목록을 재시도한다. GPUI Windows run이 종료 콜백 실행 후 반환하는 구현을 확인했다. 열린 팝업의 파일도 대상에 포함한다.
- src/ui.rs는 파일 이력 팝업 내부 메뉴가 저장소 작업 차단 상태 때문에 즉시 닫히지 않게 한다. 메인 목록의 모달 차단은 유지한다.

## 단계별 확인

기존 057 명세를 갱신하는 specify, 추가 질문이 필요 없는 clarify, 기존 호출 관계·취소 경계·종료 흐름을 반영한 plan, T005~007 tasks, 구현 전 analyze를 수행했다. 명세 FR-001~007과 SC-001~003은 작업 목록으로 모두 대응되고 모순·누락은 없었다. Constitution은 미작성 템플릿이며 확장 훅 파일은 없다. 검증된 작업 목록에 따라 implement를 수행했다.

## 자동 검증

- cargo test --offline: 286개 통과, 0개 실패, 3개 무시. 로그: target/history-row-all-tests.log.
- 실제 읽기 전용 파일 정리, 세션 격리, 중복 닫기, 닫기 이후 완료, 닫기와 등록의 경쟁, 열린 세션 종료 정리 및 종료 이후 등록을 검증했다.
- Windows 공유 금지 핸들로 삭제 실패를 재현했다. 팝업 닫기 후 실패 파일을 유지하고 핸들 해제 후 종료 시 파일 및 전용 디렉터리를 삭제함을 확인했다.
- 커밋별 blob 바이트·확장자·고유성·읽기 전용·원본/인덱스 보존 및 삭제/잘못된 경로/커밋 오류 테스트가 통과했다. 최초 CRLF 바이트 검증의 fixture는 전역 autocrlf 설정을 물려받아 실패했고, 해당 임시 저장소에 core.autocrlf=false를 명시해 원문 바이트를 검증했다. 기대 결과를 완화하지 않았다.
- cargo fmt --check 및 rustfmt --edition 2024 --check src/file_history.rs: 통과.
- cargo clippy --offline --all-targets: 종료 코드 0. 기존 미사용 코드·중첩 조건·의존성의 경고는 남아 있다. Windows 전용 읽기 전용 해제에는 Unix 권한 경고의 적용 제외 사유를 국소적으로 명시했다.
- cargo build --offline: 종료 코드 0.

## 한계

실제 GUI의 메뉴 배치·클립보드·OS 기본 앱 실행 및 앱 창 종료 동작은 직접 실행해 검증하지 않았다. 파일 정리 및 잠금 실패/재시도는 실제 파일 시스템 자동 테스트로 검증했다. 강제 종료와 정상 종료 시에도 계속 잠겨 있는 파일의 삭제는 보장하지 않는다. 실패는 로그를 남기며 재부팅 예약이나 다음 실행 정리는 추가하지 않았다.
