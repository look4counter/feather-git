# 조사 결과

## 디코더 선택

결정: 잠금 파일과 로컬 캐시에 있는 encoding_rs 0.8.44를 사용한다.
근거: 잘못된 바이트를 대체 문자 없이 거절하고 필요한 언어/UTF-16 디코딩을 제공한다. 별도 OS 의존 API와 수동 문자표를 피한다.
검토 대안: Windows 코드 페이지 API는 플랫폼 종속성이 늘고, 직접 구현은 중복과 오류 위험이 크다.

## 이름과 호환성

로컬 라이브러리 lib.rs의 문서와 조사 에이전트 검토로 확인했다. windows-949/EUC-KR는 EUC_KR, Windows-31J/Shift_JIS는 SHIFT_JIS 디코더를 공유한다. WHATWG 호환 확장을 포함하므로 엄격한 원형 EUC-KR/Shift_JIS 범위 구분은 하지 않는다. Big5도 HKSCS 확장을 포함한다.

## 원문 보존

선택 인코딩을 명시하므로 BOM 자동 감지로 다른 인코딩으로 전환하지 않는다. UTF-8 BOM은 기존대로 보존한다. UTF-16은 일치하는 BOM만 제거하고 반대 엔디언 BOM은 오류로 처리한다. 비 UTF-8에서는 부분 쓰기와 충돌 편집을 만들지 않는다.

## 상태와 재조회

GPUI 글로벌 선택은 앱 실행 동안만 유지한다. 조회 시작 시 복사하고 글로벌 구독과 generation으로 갱신한다. 동일 선택은 재조회하지 않는다. 미해결 조사 항목 없음.

## 증분 조회 조사

git2::Revwalk는 Repository 수명을 빌리므로 UI나 Send 요청에 직접 저장할 수 없다. 재탐색/skip 방식은 앞선 커밋 재조회 요구와 충돌한다. 별도 작업 스레드가 저장소·Revwalk를 함께 소유하고 채널로 읽는 방식을 선택한다. 기존 GraphBuilder::append를 복제한 상태로 백그라운드에 넘겨 새 200행만 계산한다. 마지막 페이지 캐시로 취소 후 동일 오프셋 재시도를 안전하게 처리한다.
