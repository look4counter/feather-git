# 기능 명세: Diff 인코딩 선택·하단 표시 정리·커밋 증분 조회

> 문서 정리일: 2026-11-17. 본문은 이 기능의 단계별 요구사항 이력을 포함한다. 현재 유효 기준과 검증 한계는 [전체 명세 색인](../README.md)을 함께 확인한다. 과거 검증 기록은 현재 버전의 재검증 결과가 아니다.
> 후속 변경 참고: [059](../059-footer-overlay-actions/spec.md) · [060](../060-settings-overlay/spec.md).
> 현재 기준: 인코딩은 060의 임시 선택 후 확인 방식이다. 행 선택·Enter/Space만으로 즉시 적용하지 않는다. 기록 1,500개·추가 200개 정책은 유지한다.

작성일: 2026-11-15
상태: 명확화 완료
요청: 우측 하단 UTF-8 라벨을 누르면 팝업에서 앞서 제시한 인코딩 목록을 선택한다.

## 사용자 시나리오와 검증

### 사용자 이야기 1: 인코딩 선택 (우선순위 P1)

고정 라벨 대신 선택 가능한 인코딩 표시를 제공하여 다른 인코딩의 파일을 확인한다.
독립 검증: 하단 라벨을 눌러 목록을 열고 인코딩을 선택하면 선택 표시와 라벨이 갱신된다. Escape와 바깥 클릭으로 취소할 수 있다.

### 경계 조건

열린 파일이 없어도 목록 선택이 가능하다. 같은 항목 선택은 불필요한 재조회를 일으키지 않는다. 해석 실패는 대체 문자로 숨기지 않고 안내한다. 새 선택 이전의 비동기 결과가 최신 결과를 덮어쓰지 않는다.

## 요구사항

- FR-001: 라벨 클릭으로 기존 UI 스타일의 팝업을 표시한다.
- FR-002: UTF-8, UTF-16LE, UTF-16BE, windows-949, EUC-KR, Windows-31J, Shift_JIS, GBK, GB18030, Big5, windows-1252를 제공하고 현재 선택을 표시한다.
- FR-003: 선택 시 팝업을 닫고 하단 라벨을 갱신한다. 기본값은 UTF-8이다.
- FR-004: 선택은 작업 파일·인덱스·과거 파일을 읽어 Diff 비교할 때만 적용한다. 선택과 재조회는 파일·인덱스·Git 설정의 바이트를 변경하지 않는다.
- FR-005: 기존 UTF-8 비교, 공백/줄바꿈 규칙, 전체 파일 Stage 동작을 보존한다.

### 주요 개체

인코딩 선택: 이름과 디코딩 방식으로 식별되는 현재 실행 중의 선택값.

## 성공 기준

- SC-001: 모든 11개 항목을 마우스 및 기존 메뉴 키보드 조작으로 선택할 수 있다.
- SC-002: 선택 변경 후 최신 선택에 해당하는 내용만 표시한다.
- SC-003: 파일 해석 오류를 명시적으로 알리며 기존 UTF-8 기능 회귀가 없다.

## 가정

선택은 앱 실행 중 공유하며 재시작 시 UTF-8로 시작한다. 자동 감지 및 설정 영구 저장은 요청 범위에 포함하지 않는다.

## 명확화

### 2026-11-15

- 질문: 보기만 변경하는가, 파일도 변환하는가? → 답변: 파일은 변경하면 안 되며 Diff 비교와 읽을 때만 적용한다.
- 적용 범위는 실행 중 공유하는 보기 설정이다. 커밋 메시지 등 이미 해석된 메타데이터는 변경하지 않는다.
- FR-006: UTF-8 이외의 보기에서는 원본을 UTF-8로 다시 저장할 위험이 있는 줄 단위 Stage/폐기 및 충돌 편집을 제공하지 않고 전체 파일 작업을 안내한다. UTF-8로 돌아오면 기존 동작을 복구한다.
- FR-007: 선택은 여러 파일 및 과거 파일 비교에도 적용한다. 잘못된 바이트·불완전 UTF-16·바이너리는 안내하며 오래된 비동기 결과를 거절한다.

## 추가 요청

- FR-008: 우측 하단 Feather Git 라벨을 제거한다.
- FR-009: 좌측 하단 기본 상태에서 프로젝트명을 제외한다. 저장소 경로 및 작업·오류 안내는 유지한다.
- SC-004: 프로젝트 전환과 경로 없는 상태에서도 기본 상태 문구에 프로젝트명 접두사가 없다.

### 사용자 이야기 2: 하단 표시 정리 (우선순위 P1)

우측 제품명과 좌측 기본 프로젝트명 접두사를 제거해 상태 영역을 간결하게 한다. 독립 검증은 프로젝트 전환·경로 없음 상태에서 경로와 작업/오류 안내가 유지되는지 확인한다.

## 사용자 이야기 3: 커밋 기록 증분 조회 (우선순위 P1)

최초 커밋 기록은 최대 1,500행을 표시한다. 하단 50행 이내가 보이면 다음 200행을 비동기로 조회하여 기존 그리드 뒤에 붙인다. 기존 커밋을 다시 조회하거나 그리드 전체를 교체하지 않는다.

- FR-010: 초기 조회 크기는 1,500이다. 전체 이력이 더 짧으면 실제 개수만 표시한다. 기존 참조 선택에서 오래된 대상까지 확장하는 동작은 유지한다.
- FR-011: 하단 50행 이내에서 다음 200개를 기존 탐색 커서로 읽어 추가한다. 중복 요청·중복 행·빠진 행이 없어야 한다.
- FR-012: 추가 시 기존 행 캐시, 그래프 연결/색, 선택된 커밋·파일, 가로/세로 스크롤 핸들과 오프셋을 유지한다. 전체 스냅샷 재조회와 기존 그래프 재계산을 하지 않는다.
- FR-013: 끝에 도달하면 추가 조회를 멈춘다. 실패 시 기존 행을 유지하고 오류와 재시도를 제공한다. 닫힌 프로젝트나 교체된 스냅샷의 늦은 결과는 버린다.
- SC-005: 1,905개 이력에서 1,500 → 1,700 → 1,900 → 1,905행으로 중복·누락 없이 확장되고 추가 조회가 끝난다.
- SC-006: 페이지를 붙인 그래프는 한 번에 생성한 그래프와 같고 기존 행/선택/스크롤 상태가 유지된다.

명확화 검토: 초기 크기와 증가 크기는 사용자 지정값이다. 하단 근접은 남은 50행으로 정의한다. 앱 실행 중 열린 저장소의 탐색 스냅샷을 이어가며 새 커밋 반영은 기존 새로고침 동작에 맡긴다. 파일 히스토리 팝업은 기존 별도 전체 조회를 유지한다. 추가 질문이 필요한 모호성 없음.
