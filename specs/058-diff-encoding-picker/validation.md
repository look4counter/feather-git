# 검증 결과: Diff 인코딩 선택·하단 표시 정리·커밋 증분 조회

## 수행한 절차

speckit-specify로 초기 명세를 작성하고 speckit-clarify에서 사용자 답변(파일 불변, 읽기·비교만 적용)을 반영했다. 하단 라벨 및 증분 조회 추가 요청도 명세·계획·작업에 반영하고 일관성을 재검사했다. speckit-plan 조사에서 로컬 디코더와 기존 그래프/조회 경로를 분석했다. speckit-tasks의 T001~T010에 따라 구현했다. 확장 훅 파일은 없고 헌법은 미작성 템플릿이므로 규범 검사는 생략했다.

## 주요 변경 파일

- src/text_encoding.rs, Cargo.toml, Cargo.lock, src/main.rs: 11개 보기 인코딩·디코딩·실행 중 공유 선택.
- src/diff_git.rs, src/diff_viewer.rs, src/backend.rs: 인코딩 조회, 원문 바이트 유지, 비 UTF-8 부분 쓰기 보호, 최신 조회만 표시.
- src/ui.rs: 인코딩 메뉴, 하단 라벨 정리, 근접 스크롤 요청·오류/재시도·늦은 결과 보호.
- src/repository.rs: 초기 1,500개와 다음 200개를 같은 Revwalk에서 읽는 커서, 중복 오프셋 재전달, 세션 종료.
- src/history.rs, src/graph.rs, src/workspace_backend.rs: 그래프 빌더와 기존 행 캐시/스크롤을 보존하며 새 페이지를 백그라운드 계산하고 추가.

## 자동화 검증

- cargo test --offline: 295개 통과, 실패 0개, 기존 명시적 무시 3개. 기록은 target/feature-tests.log.
- 최종 보강한 history_paging_reads_1500 테스트도 통과했다. 최초 조회 뒤 HEAD에 새 커밋을 추가해도 기존 탐색의 1,905개를 정확히 이어 읽는다. 기록은 target/paging-final.log.
- 11개 인코딩의 고정 바이트 디코딩, 잘못된 바이트·UTF-16 엔디언/BOM/불완전 코드 단위·빈 텍스트를 검증했다.
- 한국어 및 UTF-16 실제 임시 저장소 Diff에서 작업 파일/인덱스/설정 바이트 불변, 비 UTF-8 부분 쓰기/충돌 편집 차단과 UTF-8 복귀를 검증했다.
- 1,500/1,501 경계, 1,905개 연속 추가, 취소된 결과 재전달, 중복/잘못된 오프셋, 끝과 종료된 커서, 오래된 참조 확장을 검증했다.
- 전체 그래프와 증분 그래프가 일치하고 기존 행의 참조 캐시, 가로 오프셋, 세로 스크롤 핸들/목표 행이 유지됨을 검증했다.
- UI 상태 테스트로 하단 50행 임계값, 중복 요청 억제, 선택·패널 리비전 보존, 교체된 스냅샷 거절, 오류 후 명시적 재시도를 검증했다.
- cargo clippy --offline --all-targets 통과. 사용되지 않는 기존 함수/필드 및 기존 중첩 조건 경고, 사용 경로가 바뀐 build_commit_graph의 미사용 경고가 남는다. 공급 GPUI와 proc-macro-error2의 기존 경고도 유지된다.
- 변경 파일에 rustfmt --check 통과. src/diff_git.rs는 기존 압축된 비관련 코드의 재포맷을 피하고 변경한 Diff 함수와 신규 테스트 구간만 포맷했다.
- 기본 cargo build --offline는 실행 중인 target/debug/feather-git.exe 교체 단계에서 접근 거부로 실패했다. 컴파일/링크는 성공했다.
- cargo rustc --offline --bin feather-git -- -o target/feature-verified.exe는 종료 코드 0으로 통과했다. 실행 중인 앱을 교체하지 않고 검증 실행 파일을 생성했다. 기록은 target/feature-rustc.log.

## 제한과 미검증 사항

computer-use 스킬로 검증용 feature-preview 실행을 시도했으나 도구의 승인 검토가 해당 앱 사용을 허용하지 않았다. 실제 메뉴 배치·마우스/키보드 조작 및 스크롤에 따른 화면 갱신은 직접 검증하지 못했다. 자동화 결과가 GUI 확인을 대신한다고 판단하지 않는다. 실행 중인 앱은 이전 실행 파일이므로 변경을 보려면 새 실행 파일로 다시 실행해야 한다.

EUC-KR/windows-949와 Shift_JIS/Windows-31J는 라이브러리의 같은 호환 확장 디코더를 사용한다. 자동 인코딩 감지와 파일 변환/저장, 설정 영구 저장은 구현 범위에 포함하지 않는다. 손상된 Git 객체처럼 탐색 중 복구할 수 없는 오류는 세션 오류로 유지하며 저장소를 다시 열어야 한다.
