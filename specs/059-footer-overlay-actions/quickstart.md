# 검증 안내

1. cargo test --offline, cargo clippy --offline --all-targets와 변경 파일 포맷 검사를 실행한다.
2. 인코딩 버튼을 눌러 다른 공용 팝업과 같은 중앙 오버레이인지 확인한다. 선택/취소/Escape/키보드 이동 및 이전 포커스 복구를 확인한다.
3. 하단 원형 제거와 세 버튼의 동일 배경/패딩을 확인한다. 긴 저장소 경로에서 버튼이 가려지지 않아야 한다.
4. 열린 저장소에서 터미널·탐색기를 눌러 해당 폴더가 열리는지 확인한다. 새 탭/모달/처리 중에는 폴더 버튼이 동작하지 않아야 한다.
5. 폴더가 사라졌을 때 오류 안내와 다른 프로젝트 전환 뒤 오래된 오류가 표시되지 않는지 확인한다.

실제 외부 프로그램을 실행하지 않는 자동화 테스트와 GUI 직접 검증 범위를 구분하여 보고한다.

6. 하나의 커밋에 태그·로컬·원격 참조가 함께 있을 때 배지 순서와 흰색 아이콘을 확인한다. 현재 저장소 행은 아이콘·이름이 민트색이고 현재 라벨이 이름 뒤에 있으며 비현재 행의 색은 유지되어야 한다.

7. 100~200% 배율의 일반/현재 커밋에서 레인 선이 원 중심을 지나는지 확인한다. 원 크기·현재 흰색 내부·색·행 연결·레인 간격은 유지되어야 한다.

## 후속 검증

우측에 터미널·탐색기·인코딩·브랜치 순서로 정렬되고 동작 버튼의 외곽 크기가 배지와 같은지 확인한다. 그래프 분기/병합은 행 경계에서 수직으로 이어지고 행 안에서 직선으로 꺾여야 한다. 여러 배율에서도 원 중심과 경계 연결이 유지되는지 확인한다.

## 후속 검증: 셸·곡선·헤더

Git Bash와 Windows PowerShell 버튼이 별도로 보이고 현재 저장소 폴더에서 열리는지 확인한다. 미설치·없는 폴더는 오류를 안내해야 한다. 자동화에서는 실제 셸을 실행하지 않고 탐색과 명령의 작업 디렉터리/고정 인수를 확인한다. 18px 레인 간격과 곡선, 경계 수직성·원 중심·현재 원 여백을 확인한다. 메인/파일 히스토리의 헤더는 데이터 행 높이 24px이고 아래 구분선이 있어야 한다.

초기 1,500개 밖의 중간 참조로 건너뛴 뒤 하단에서 계속 조회하여 추가 200개 및 나머지를 오류 없이 붙이는지 확인한다. 기존 추가 페이지 진행 중 이동도 확인하고, 가장 오래된 참조 이동 후에는 추가 조회가 멈춰야 한다.
