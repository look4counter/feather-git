# 기능 명세: 공용 인코딩 오버레이와 하단 버튼

> 문서 정리일: 2026-11-17. 본문은 이 기능의 단계별 요구사항 이력을 포함한다. 현재 유효 기준과 검증 한계는 [전체 명세 색인](../README.md)을 함께 확인한다. 과거 검증 기록은 현재 버전의 재검증 결과가 아니다.
> 후속 변경 참고: [060](../060-settings-overlay/spec.md) · [062](../062-dialog-buttons-escape/spec.md).
> 현재 기준: 인코딩 확정은 060의 확인 버튼을 사용한다. 현재 배지는 071에 따라 저장소 행 맨 앞에 표시한다. 현재 브랜치의 하단 배지는 제거 상태다.

작성일: 2026-11-15
상태: 명확화 완료
요청: 인코딩 선택에 공용 팝업 오버레이 사용, 민트 원형 아이콘 제거, 경로 오른쪽 터미널·탐색기 버튼, 하단 버튼 배경·패딩 적용.

## 사용자 시나리오와 검증

### 사용자 이야기 1: 공용 인코딩 선택창 (우선순위 P1)

하단 인코딩 버튼을 누르면 다른 팝업과 같은 중앙 오버레이가 열린다. 기존 11개 목록과 현재 인코딩이 표시되며 선택 시 읽기·Diff에만 적용한다. Escape 또는 취소로 변경 없이 닫고 이전 포커스를 복구한다. 키보드 위아래와 Enter로도 선택할 수 있다.

### 사용자 이야기 2: 저장소 폴더 열기 (우선순위 P1)

우측 하단에 Git Bash·PowerShell(Windows 전용)·탐색기 버튼을 제공한다. 클릭한 시점의 현재 저장소 폴더에서 터미널 또는 탐색기가 열린다. 저장소가 없으면 비활성화하며 경로 확인·실행 실패를 안내한다.

### 사용자 이야기 3: 하단 버튼 시각 통일 (우선순위 P1)

민트 원형 아이콘을 제거하고 하단의 모든 동작 버튼에 배경·가로세로 패딩·호버·비활성 상태를 제공한다. 경로가 길어도 버튼은 읽을 수 있고 경로는 말줄임한다. 제품명·프로젝트명 접두사 제거와 다른 패널의 브랜치 표시는 유지한다.

## 명확화

추가 질문이 필요한 모호성은 없다. 공용 팝업은 기존 Dialog를 뜻한다. Git Bash와 Windows 전용 PowerShell은 현재 저장소 작업 폴더에서 열며 경로를 명령 문자열에 삽입하지 않는다. 인코딩 선택은 파일 변환 없이 기존 실행 중 설정을 유지한다. 바깥 영역은 기존 공용 Dialog처럼 배경 입력을 차단하고 취소 버튼·Escape로 닫는다. 커밋 증분 조회는 변경하지 않는다.

## 요구사항

- FR-001: 인코딩 선택은 기존 공용 중앙 팝업 오버레이를 사용하며 커서 위치 컨텍스트 메뉴를 사용하지 않는다.
- FR-002: 기존 11개 항목, 현재값, 마우스 및 위아래/Enter 선택, Escape/취소 및 포커스 복구를 제공한다.
- FR-003: 인코딩 선택은 읽기·Diff에만 적용하며 파일·인덱스를 변경하지 않는다. 선택 취소 시 기존 값을 유지한다.
- FR-004: Git Bash·PowerShell(Windows 전용)·탐색기·인코딩 버튼을 우측 하단에 배치하고 현재 브랜치명 배지는 표시하지 않는다. 경로와 상태 안내는 좌측에 유지한다.
- FR-005: 터미널 작업 폴더와 탐색기 대상은 클릭 시 현재 저장소 경로다. 공백·한글·특수문자가 있어도 경로를 명령으로 해석하지 않는다.
- FR-006: 저장소 없음·팝업/처리 중 상태에서는 해당 버튼을 비활성화한다. 존재하지 않는 폴더·실행 실패는 안내하며 UI 스레드에서 파일 조회나 프로세스 실행을 하지 않는다.
- FR-007: 하단 동작 버튼은 브랜치 배지와 같은 배경·가로 8px/세로 2px 패딩·11px 글꼴·모서리를 사용한다. 별도 고정 높이와 테두리로 배지보다 커지지 않으며 호버·비활성 상태와 긴 경로 말줄임을 유지한다.
- FR-008: 공용 팝업이 열린 동안 배경 조작을 막고, 선택/취소 후 기존 작업 상태를 보존한다. 비동기 오류가 다른 프로젝트의 알림을 덮어쓰지 않는다.

### 주요 개체

인코딩 대화상자: 현재 선택·키보드 커서·포커스·닫기 이벤트.
폴더 동작 요청: 클릭 시 프로젝트와 경로, 터미널/탐색기 구분.

## 성공 기준

- SC-001: 인코딩 버튼에서 공용 오버레이로 11개 선택을 제공하고 취소·선택 결과가 구분된다.
- SC-002: 테스트로 폴더 인수와 작업 디렉터리의 정확성, 경로 오류·빈 상태·잘못된 대상 보호를 검증한다.
- SC-003: 하단 원형 아이콘이 없고 세 동작 버튼에 동일 스타일이 적용된다.
- SC-004: 관련 테스트·정적 분석·빌드에 회귀가 없으며 GUI 미검증 범위는 별도 기록한다.

## 가정과 경계

Windows PowerShell은 시스템 기본 구성 요소를 사용한다. 외부 창 열기 동작은 버튼 클릭으로만 수행한다. 테스트에서는 실제 터미널·탐색기를 실행하지 않는다. 하단 작업 안내는 경로와 함께 유지하고 브랜치 라벨은 동작 버튼으로 바꾸지 않는다.

## 추가 요청: 커밋 배지와 현재 저장소 행

### 사용자 이야기 4: 배지와 현재 행 가독성 (우선순위 P1)

커밋 메시지의 태그·로컬 배지 아이콘을 흰색으로 바꾸고 배지를 태그 → 로컬 → 원격 순서로 표시한다. 저장소 목록의 현재 체크아웃된 로컬 행은 아이콘·이름을 민트색으로 표시하고 현재 라벨을 이름 바로 뒤에 붙인다. 아이콘과 이름 간격은 커밋 배지의 간격과 같은 4px로 줄인다.

- FR-009: 커밋 메시지 로컬·태그 배지 아이콘은 흰색이다. 배지 텍스트색과 원격 배지 아이콘은 기존 색을 유지한다.
- FR-010: 커밋 메시지 배지 순서는 태그, 로컬, 원격이다. 같은 종류 안에서는 기존 순서를 유지하고 기타 배지는 그 뒤에 둔다. 캐시와 증분 추가에도 같은 규칙을 적용한다.
- FR-011: 저장소 목록 현재 라벨은 이름 바로 뒤에 표시하고 오른쪽 끝으로 밀지 않는다. 아이콘/이름 간격은 배지와 같은 4px이다.
- FR-012: 현재 체크아웃된 로컬 저장소 행의 아이콘과 이름은 민트색이다. 비현재 행과 원격·태그 행의 색은 바꾸지 않는다.
- SC-005: 여러 종류/여러 개 배지가 섞인 입력에서도 종류별 순서와 같은 종류 안의 순서가 유지된다.
- SC-006: 현재/비현재·로컬/원격/태그의 스타일을 검증하고 현재 판정·선택·파일 조회 동작은 유지한다.

명확화 검토: 저장소 패널의 현재 행은 기존 현재 판정(체크아웃된 로컬 브랜치)을 유지한다. 커밋 메시지 배지와 저장소 행의 아이콘 색 요구는 별도 적용한다. 추가 질문이 필요한 모호성 없음.

## 사용자 이야기 5: 그래프 선과 원 중심 일치 (우선순위 P1)

그래프 레인 선이 커밋 원의 가로 중심을 통과해야 한다. 현재 원의 왼쪽 경계와 선의 중심을 서로 다른 기준으로 반올림해 100%에서 원 중심이 0.5px 이동할 수 있다.

- FR-013: 일반/현재 커밋 원의 중심은 해당 레인 선의 보정된 좌표와 일치한다. 기존 지름·테두리·색·레인 간격·행 연결은 유지한다.
- FR-014: 100/125/150/175/200% 배율과 소수 좌표에서도 같은 기준을 사용하며 원의 경계만 따로 반올림해 중심을 이동시키지 않는다.
- SC-007: 기존 구현에서 실패하는 중심 일치 재현 테스트를 먼저 확인한 뒤 수정하고, 크기/테두리/행 연결/레인 간격 회귀를 함께 검증한다.

명확화: 홀수 물리 픽셀 지름의 원과 짝수 픽셀 선을 정확히 같은 중심에 놓으면 원 경계는 반 픽셀에 위치할 수 있다. 기존 지름은 보존하고 원의 안티앨리어싱을 사용하며 중심 일치를 우선한다.

- FR-015: 그래프 분기·병합의 대각 연결은 곡선으로 표시한다. 행 상단 첫 4px와 하단 마지막 4px의 수직 구간은 유지하고 곡선의 접선도 해당 수직 구간에 맞춘다. 레인 연결·색·두께·원 중심과 크기는 유지한다.
- SC-008: 곡선 분기 경로가 모든 기존 배율/좌표 테스트에서 생성되고 위·중앙·아래 연결과 그래프 캐시가 유지된다.

- FR-016: 커밋 상세 패널의 상위 항목 명칭을 부모 커밋으로 표시한다. 표시 문구만 바꾸며 부모 ID와 조회 동작은 유지한다.


## 후속 명확화: 하단 위치와 행 경계 연결

터미널·탐색기는 우측의 인코딩 버튼 앞에 배치하고 브랜치 배지는 가장 오른쪽에 둔다. 세 동작 버튼은 공용 배지 스타일을 재사용한다. 그래프 꺾임은 행 내부의 수직 4px 구간과 직선 대각선으로 구성하며 곡선은 넣지 않는다. 24px 행의 상단/하단 경계에 닿는 선은 항상 수직이다. 추가 질문이 필요한 모호성 없음.

- SC-009: 하단 좌측에는 폴더 동작 버튼이 없고 우측 동작 버튼의 패딩/높이 기준이 브랜치 배지와 같다.
- SC-010: 분기/병합의 행 상단 첫 구간과 행 하단 마지막 구간이 모든 배율에서 수직이며 기존 행 경계 좌표와 레인/원 중심이 유지된다.



## 후속 명확화: 셸 구분과 압축된 곡선 그래프

- FR-017: 기존 터미널 버튼은 Git Bash로 표시하고 동작한다. Windows에서는 바로 옆에 PowerShell 버튼을 별도로 제공한다. 다른 운영체제에서는 PowerShell 버튼을 표시하지 않는다.
- FR-018: Git Bash는 PATH의 Git 설치 위치와 표준 시스템/사용자 설치 위치에서 실행 파일을 찾는다. 설치되지 않았거나 실행 실패 시 명확한 오류를 표시하며 다른 셸로 임의 대체하지 않는다.
- FR-019: 레인 간격을 19px에서 18px로 줄인다. 기존 원/테두리 크기와 인접 원 사이 최소 4px 공간을 유지한다.
- SC-011: Git Bash와 PowerShell 실행 대상을 구분하고 현재 저장소 폴더를 작업 디렉터리로 전달한다. 한글/공백/명령 특수문자 경로는 명령 인수로 해석하지 않는다.
- SC-012: 기본/사용자/사용자 지정 PATH 설치 탐색과 미설치 오류를 자동화로 검증하고, 새 간격에서도 기존 그래프 중심·경계 수직성·노드 간격 검증이 통과한다.

추가 질문이 필요한 모호성은 없다. 기존 그래프의 직접 직선 요구는 이번 곡선 요구로 대체한다. 행 경계 수직 연결과 공용 버튼 크기·비활성 조건은 유지한다. Git Bash는 Git for Windows 실행 파일을 사용하며 실행 인수 없이 작업 디렉터리를 지정한다.

- FR-020: 공용 커밋 기록 그리드 헤더 높이를 데이터 행과 같은 24px로 맞추고 아래쪽에 구분선을 표시한다. 메인/파일 히스토리의 공용 헤더와 목록 헤더 높이 인수를 함께 갱신하여 스크롤·리사이즈 좌표를 일치시킨다.
- SC-013: 공용 헤더와 두 사용처가 동일한 ROW_HEIGHT를 사용하고 헤더 하단 구분선이 적용된다. 기존 그리드 리사이즈·스크롤 검증이 유지된다.

## 버그 명세: 바로 건너뛰기 후 추가 조회 커서 일치

참조가 초기 조회 범위 밖에 있어 새 스냅샷을 읽은 경우 finish_reference가 커밋 목록과 more_commits만 교체하고 history_cursor를 이전 값으로 남긴다. 새 목록 길이와 이전 커서의 다음 오프셋이 달라 커밋을 더 읽을 수 없다는 오류가 발생할 수 있다.

- FR-021: 바로 건너뛰기로 새 커밋 스냅샷을 설치할 때 커밋 목록·추가 존재 여부·추가 조회 커서를 같은 결과에서 함께 반영한다. 끝까지 읽은 결과는 기존 커서를 제거한다.
- FR-022: 이동 후 추가 200개 조회가 새 스냅샷의 커서에서 계속되어야 하며, 이전 스냅샷의 늦은 페이지 결과는 버린다. 이동한 선택·행 스크롤 핸들·작업 트리 상태는 유지한다.
- SC-014: 초기 1,500개 밖의 참조로 이동한 뒤 남은 이력을 오류·중복·누락 없이 끝까지 추가한다. 이전 페이지가 진행 중인 경우에도 새 목록을 오염시키지 않는다.
- SC-015: 가장 오래된 참조로 이동하여 전체 이력을 읽은 경우 more_commits=false 및 history_cursor=None이고 추가 조회하지 않는다.

명확화: 기존 참조 선택/바로 건너뛰기 의미와 초기 1,500개·추가 200개 정책을 유지한다. 사용자 데이터나 Git 참조는 수정하지 않는다. 추가 질문이 필요한 모호성 없음.
