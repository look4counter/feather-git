# 검증 안내

각 대상 팝업의 버튼 높이·여백·테두리·주 동작 강조를 확인한다. ESC는 닫기/취소만 실행하고 중첩 창에서 한 단계만 닫는지 확인한다. 인코딩 취소와 삭제 누름 해제를 확인하고 전체 테스트·정적 분석·빌드를 실행한다.


## 검증 결과 (2026-11-15)

- 공통 dialog::button으로 높이 32, 가로 여백 16, 글자 13, 주/보조 색상·테두리·호버 및 비활성 스타일을 통일했다.
- 저장소 창의 탐색/확인/취소, 인코딩, 환경설정과 하위 추가 창, 알림, 파일 이력, 최근 저장소 삭제, 폐기 확인 및 뷰어 내부 설정 폼의 버튼을 대조했다.
- 환경설정의 ESC를 기존 close_settings에 연결했다. 이 경로가 중첩 창 우선 닫기, 작성 중 조합 보호, 저장 중 제한과 이전 포커스를 유지한다. 다른 대상 창과 문맥 메뉴는 기존 ESC 취소 경로가 있음을 확인했다.
- cargo test --offline: 348 통과, 실패 0, 수동 성능 측정 3 무시.
- cargo clippy --offline --all-targets -- -D warnings: 종료코드 0.
- cargo fmt --all -- --check: 종료코드 0.
- cargo build --offline: 종료코드 0. MSVC import library 생성의 linker stdout 안내 1건은 남아 있으며 소스 경고는 없다.
- 실제 GUI에서 배치·호버·ESC·포커스 조작 및 외부 인증은 미검증이다. 스타일 변경과 기존 취소 경로의 연결은 코드 대조로 확인했다.

## 수렴 점검

FR-001은 dialog.rs 공통 생성 함수, FR-002는 전체 대상 호출부, FR-003은 각 창의 ESC 및 Workspace의 중첩 취소 경로, FR-004는 기존 작업 가드·삭제 누름·전체 회귀 검사에 대응한다. 미구현 요구사항이나 명세·구현 불일치를 발견하지 못했다. 새 의존성 및 저장 형식 변경은 없다.

## 폐기 팝업 순서 변경 검증

공유 footer를 [확인][취소]로 변경했다. 기존 confirm=true/false와 ESC 동작은 유지한다. 폐기 관련 테스트 11개, fmt 검사와 엄격한 clippy가 통과했다. 일반 빌드는 실행 중인 target/debug/feather-git.exe의 액세스 거부로 실패했으며 사용자 프로세스를 종료하지 않았다. 별도 출력 target/discard-order-verified.exe 빌드는 성공했다. 실제 화면 조작은 미검증이다. 수렴 대조에서 요청한 순서·명칭 및 기존 콜백 유지와 구현이 일치하며 남은 구현 작업은 없다.
