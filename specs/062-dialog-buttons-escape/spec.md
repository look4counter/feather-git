# 기능 명세: 팝업 버튼 및 ESC 통일

> 문서 정리일: 2026-11-17. 본문은 이 기능의 단계별 요구사항 이력을 포함한다. 현재 유효 기준과 검증 한계는 [전체 명세 색인](../README.md)을 함께 확인한다. 과거 검증 기록은 현재 버전의 재검증 결과가 아니다.

작성일: 2026-11-15
상태: 명확화 및 품질 검증 완료

## 사용자 시나리오

### 사용자 이야기 1 — 버튼 스타일 통일 (우선순위 P1)
모든 앱 팝업에서 Open Repository와 같은 버튼을 사용한다.
수용 기준: 확인·저장 등 주 동작과 취소·닫기 등 보조 동작이 동일한 높이, 가로 여백, 글자 크기, 모서리, 테두리 및 호버 규칙을 따른다. 팝업 본문의 추가·삭제·탐색 버튼도 같은 기본 모양을 사용한다. 기존 기능·버튼명·순서를 유지한다.

### 사용자 이야기 2 — ESC 닫기 (우선순위 P1)
ESC로 모든 대화형 팝업을 닫거나 취소한다.
수용 기준: 환경설정 및 중첩된 원격·인증 추가 창도 ESC로 닫힌다. 가장 위의 창만 닫히고 포커스가 복원된다. 인코딩의 미확정 선택은 적용하지 않는다. 삭제/변경 폐기는 확정하지 않는다. 저장 중 닫기 제한과 한글 조합 중 ESC 처리는 기존 보호를 유지한다.

## 요구사항

- FR-001: 공통 버튼 스타일을 Open Repository 기준(높이 32, 가로 여백 16, 둥근 테두리, 주 동작 민트색 테두리와 선택 배경, 보조 동작 기본 테두리, 호버 배경)으로 제공한다.
- FR-002: 저장소 열기/생성/복제, 인코딩, 환경설정 및 하위 창, 알림, 파일 이력, 최근 저장소 삭제, 변경 폐기와 뷰어 설정 오버레이의 버튼을 적용 대상으로 한다. 비활성 버튼은 흐리게 표시하며 호버 및 포인터 강조를 하지 않는다.
- FR-003: 각 대화형 팝업의 ESC는 취소/닫기 경로만 호출한다. 중첩 창을 한 번에 여러 개 닫지 않는다.
- FR-004: 기존 저장, 인증 취소, 삭제 누름 유지, 포커스 복원, 비밀 보호와 회귀 테스트를 보존한다.

## 경계 조건과 가정
버튼이 없는 진행 표시와 네이티브 OS 창은 스타일 통일 대상이 아니다. 문맥 메뉴 항목·체크박스는 버튼으로 바꾸지 않는다. 실행 중인 저장의 보호는 유지하며 인증 대기 취소는 기존 취소 경로를 사용한다. ESC 추가는 앞선 단축키 제거 요구보다 우선하고 다른 설정 단축키는 복구하지 않는다. 미해결 모호성 없음.

## 성공 기준
모든 대상 팝업이 동일한 스타일 함수를 사용하고, ESC의 안전한 취소 동작과 기존 회귀 검증이 통과한다. 빌드·정적 분석·포맷 검사가 통과한다.

## 변경 명세: 폐기 팝업 버튼 순서

변경사항 폐기 팝업은 왼쪽 확인, 오른쪽 취소 순서로 표시한다. 기존 폐기 버튼의 명칭을 확인으로 변경하고 파일 전체 및 체크한 줄의 폐기 실행·취소·ESC 동작은 유지한다. 수용 기준은 두 경로 모두 [확인][취소] 표시와 기존 회귀 검증 통과이다. 모호성 없음.
