## 사용자 시나리오

### 사용자 이야기 1 — 공통 입력창 (우선순위 P1)
저장소·환경설정·원격·인증 입력창이 Open Repository와 같은 테두리·여백·배경·높이를 사용한다.
수용 기준: 편집·읽기 전용·비밀번호 입력이 공통 외곽 컴포넌트를 사용하고 기존 한글 조합·포커스·저장 동작과 비밀 보호를 유지한다.

### 사용자 이야기 2 — 공통 체크박스 (우선순위 P1)
환경설정과 Diff 줄 선택에 동일한 체크 모양을 사용한다. 문구는 박스 오른쪽에서 왼쪽 정렬한다.
수용 기준: 문구가 있는 체크박스는 왼쪽에 박스와 문구가 붙어 배치되고 가운데 정렬되지 않는다. Diff의 좁은 선택 열은 공통 표시를 사용하며 기존 클릭 동작을 유지한다.

### 사용자 이야기 3 — 더블클릭 단어 선택 (우선순위 P1)
입력창의 단어를 더블클릭하여 전체 단어를 선택한다.
수용 기준: 한글·영문·숫자·밑줄 단어, 공백, 구두점과 입력 끝을 처리한다. 한 번 클릭·드래그·복사·붙여넣기를 유지하고 읽기 전용에서도 선택한다. 비활성 입력은 선택하지 않는다. 비밀번호는 마스킹·복사 차단을 유지하고 더블클릭은 전체 비밀값을 선택하여 단어 경계를 노출하지 않는다.

## 요구사항

- FR-001: 입력창 외곽 및 라벨 구성을 공통화하고 Open Repository 기준을 적용한다.
- FR-002: 체크 표시와 문구가 있는 체크박스를 공통화하고 문구를 왼쪽 정렬한다.
- FR-003: 사용자 명확화 답변대로 클릭 위치의 단어 전체를 선택한다. 기존 Diff의 단어 구분 규칙을 재사용한다.
- FR-004: UTF-8·UTF-16·마스크 좌표, 수평 스크롤, 읽기 전용 및 비밀 보호를 유지한다.
- FR-005: 관련 자동화 회귀 검사·포맷·정적 분석·빌드를 통과한다.

## 경계 조건과 가정
읽기 전용 주소도 공통 입력 외곽을 사용한다. 설정용 축소 입력 높이는 공통 기본 높이로 통일한다. 외부 운영체제 입력창은 대상이 아니다. 복합 이모지의 세부 문자 분할은 기존 문자/선택 규칙을 유지한다.

## 명확화
질문: 더블클릭 선택 범위는 단어 전체와 문자 한 글자 중 무엇인가?
사용자 답변: 클릭한 위치의 단어 전체 선택.
문구 왼쪽 정렬은 박스 오른쪽 문구를 행 시작에 붙이는 의미로 적용한다. 미해결 모호성 없음.

## 성공 기준
모든 앱 입력창과 두 종류 체크박스가 공통 컴포넌트를 사용한다. 한글·영문·이모지·빈 문자열·끝 위치·구분자 선택 테스트와 기존 회귀 검증이 통과한다.

## 추가 요구사항: 삭제 아이콘과 정렬

FR-006: 환경설정의 원격 저장소와 인증 삭제 버튼의 X 표시를 휴지통 아이콘으로 교체한다. 버튼과 항목 행은 세로 가운데 정렬하고 원격 이름·주소와 인증 문구의 중심선을 맞춘다. 기존 삭제 범위·이벤트·보호를 유지한다. 다중 주소는 전체 항목 높이의 가운데에 버튼을 배치한다.
