# 검증 안내

설정의 두 목록과 삭제 버튼을 최근 저장소의 배치와 비교한다. 행 배경이 유지되는지, 체크박스 오른쪽 빈 영역은 전환하지 않는지, 포커스를 옮기면 입력 선택이 해제되는지 확인한다. 저장소 팝업 폴더 아이콘으로 기존 선택창이 열리는지 확인한다. 자동화 결과와 실제 화면 미검증을 구분한다.


## 검증 결과 (2026-11-15)

- 원격·인증 목록은 공통 list_row/title/detail/delete를 사용한다. 최근 저장소의 패딩12·간격12·제목20/보조18 줄높이·삭제 버튼30과 가운데 정렬을 적용했으며 행 배경 및 행 호버 배경은 추가하지 않았다. 모든 원격 주소와 계정/인증 방식은 유지하고 표시 주소를 가린다.
- 체크박스는 w_full을 제거하고 align_self FlexStart로 내용 너비를 유지한다. 설정 호출부의 포커스 배경을 제거했다.
- TextInput은 최초 렌더 때 on_blur와 창 활성화 구독을 보관한다. 포커스 상실 또는 창 비활성화에 선택을 현재 커서로 접고 드래그 상태를 해제한다. 내용·조합·비밀 보호는 변경하지 않는다.
- 저장소의 공용 탐색 버튼은 폴더 canvas 아이콘으로 대체했다. 세 작업의 Browse 이벤트와 is_busy 가드는 유지했다.
- cargo test --offline: 352 통과, 실패 0, 수동 성능 측정 3 무시. 새 선택 해제 테스트는 순방향·역방향·빈 범위를 포함한다.
- cargo fmt --all -- --check 및 cargo clippy --offline --all-targets -- -D warnings: 종료코드 0.
- cargo rustc --offline --bin feather-git -- -o target/settings-list-focus-verified.exe: 종료코드 0. 별도 출력 경로 및 MSVC 라이브러리 생성 안내 3건은 소스 경고와 구분한다.
- 실제 GUI 정렬·클릭 범위·포커스 이동·폴더 선택창 조작과 외부 인증은 미검증이다. 실행 중인 앱을 종료하지 않았다.

## 수렴 점검

FR-001은 공통 목록 스타일과 두 목록 호출부, FR-002는 내용 너비와 포커스 배경 제거, FR-003은 포커스 구독과 선택 해제 테스트, FR-004/005는 기존 가드 유지와 전체 회귀 검증, FR-006은 폴더 아이콘과 Browse 경로 유지에 대응한다. 미구현 요구사항이나 명세·구현 불일치를 발견하지 못했다. 저장 데이터 형식과 외부 의존성 변경은 없다.

## 탐색 UI 위치 조사

폴더 선택 버튼은 repository_dialog.rs의 repository-browse이며 세 저장소 작업이 공유한다. 하단 탐색기는 ui.rs의 footer-explorer, 변경 파일 문맥 메뉴는 ui.rs의 탐색기에서 보기, 파일 이력 문맥 메뉴는 file_history_dialog.rs의 탐색기에서 열기이다. 별도 파일 선택 버튼은 없다.
