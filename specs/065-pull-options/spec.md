# 기능 명세: Pull 옵션 실행 메뉴

> 문서 정리일: 2026-11-17. 본문은 이 기능의 단계별 요구사항 이력을 포함한다. 현재 유효 기준과 검증 한계는 [전체 명세 색인](../README.md)을 함께 확인한다. 과거 검증 기록은 현재 버전의 재검증 결과가 아니다.
> 후속 변경 참고: [079](../079-history-rebase/spec.md) · [080](../080-history-revert-reset/spec.md).
> 현재 기준: Pull 옵션은 Fetch·일반 Pull·ff-only다. Pull 병합 및 ff-only 실행은 080의 확인창을 거치며 Fetch에는 해당 확인을 추가하지 않는다.

작성일: 2026-11-15
상태: 사용자 명확화 완료

## 사용자 시나리오

### 사용자 이야기 1 — 툴바 선택 (우선순위 P1)
상단 샘플 작업 버튼들을 제거하고 Pull 분할 버튼에서 세 가지 작업을 선택하고 본체로 실행한다.
수용 기준: Fetch, Pull (fast-forward if possible), Pull (fast-forward only)가 이 순서로 제공된다. 화살표 메뉴에서 선택한 옵션을 유지하고 메뉴가 닫힌다. 옵션 선택은 실행하지 않고 본체 클릭에서만 한 번 실행한다. 저장소 없음·다른 쓰기/팝업·실행 중에는 실행하지 않는다.

### 사용자 이야기 2 — Fetch 및 Pull (우선순위 P1)
원격 변경을 가져오고 지정한 방식으로 현재 브랜치에 통합한다.
수용 기준: Fetch는 원격 추적 정보만 갱신한다. fast-forward if possible은 가능하면 분기 이동, 분기되었으면 병합 커밋을 만든다. fast-forward only는 분기되었으면 브랜치를 변경하지 않고 실패한다. 이미 최신이거나 로컬만 앞선 경우 불필요한 커밋을 만들지 않는다.

### 사용자 이야기 3 — 상태 및 오류 (우선순위 P1)
실행 중 상태를 보고 성공·실패 및 충돌 결과를 확인한다.
수용 기준: UI를 멈추지 않고 중복 실행을 막는다. 완료 후 성공·실패 모두 기록·브랜치·파일 상태를 재조회한다. 충돌은 실제 Git 상태와 변경 파일에 남기고 오류를 숨기지 않는다. 인증 오류에 URL 비밀값이 노출되지 않는다.

## 요구사항

- FR-001: 기존 샘플 작업 버튼 7개를 제거하고 Pull 선택 실행 버튼 하나를 제공한다. 툴바의 저장소 정보 표시는 유지한다.
- FR-002: 선택 가능한 세 옵션은 git fetch, git pull --no-rebase --ff, git pull --ff-only에 해당하는 동작을 제공한다.
- FR-003: Pull은 현재 로컬 브랜치의 upstream을 사용한다. upstream 없음·detached HEAD·기존 미완료 병합/리베이스는 명확한 오류로 알린다. Fetch는 현재 브랜치의 원격을 기본으로 하고 없으면 origin을 사용한다.
- FR-004: 기존 인증 콜백과 인프로세스 Git 계층을 재사용한다. 각 옵션은 본체 실행 버튼을 누른 경우에만 저장소를 변경한다.
- FR-005: 충돌·로컬 변경·잠금 오류를 감추거나 강제로 덮어쓰지 않는다. 자동 stash나 강제 reset을 하지 않는다.
- FR-006: 비동기 실행·작업 가드·오류 표시·기록 및 파일 상태 갱신과 회귀 검증을 제공한다.

## 사용자 명확화
사용자에게 각 옵션의 명령과 동작을 제시했고 “맞아. 그렇게 만들어줘.”로 승인받았다. Pull은 upstream 기준이며 최신 요청에 따라 SplitButton의 본체는 선택 옵션 실행, 화살표는 옵션 변경으로 구분한다. 추가 옵션·Push·Continue/Abort UI는 범위에 없다. 미완료 충돌은 기존 Git 도구와 변경 파일 화면에서 확인할 수 있다.

## 경계 조건
빈 저장소·원격 없음·네트워크/인증 실패·다중 원격·로컬 변경·충돌·분기·동일 커밋·로컬만 앞섬·잠금·시그니처 없음·오래된 결과를 고려한다. 초기화되지 않은 로컬 브랜치에서 Fetch는 가능하지만 Pull은 기존 브랜치/upstream을 요구한다.

## 성공 기준
선택 가능한 세 모드의 로컬 원격 저장소 통합 테스트, 충돌·오류·작업 중 가드 테스트와 기존 전체 검사 및 빌드가 통과한다. 사용자 원격과 실제 계정을 개발 과정에서 변경하지 않는다.


## 변경 명세: 공통 분할 버튼

- FR-007: 공통 컴포넌트 이름은 SplitButton이다. 본체에 아이콘을 표시하고 그 아래 Pull 문구를 둔다. 별도 화살표 영역은 옵션 변경 메뉴만 연다.
- FR-008: 선택한 옵션은 다른 저장소 이동과 반복 실행 및 앱 재시작 후에도 유지한다. 이전 설정 파일 또는 알 수 없는 옵션 값은 기본 Pull (fast-forward if possible)로 복원한다. 메뉴는 현재 옵션을 체크 표시한다.
- FR-009: 툴바의 높이와 가로 여백을 줄이고 우측 Git 저장소 문구와 브랜치 라벨을 제거한다.
- 수용 기준: 옵션 선택만으로 Git 작업이 시작되지 않는다. 본체 클릭은 유지된 옵션을 실행한다. 실행 중 본체와 화살표가 모두 비활성화된다. 기존 네 Git 모드와 보호를 유지한다.
- 명확화: 표준 용어는 분할 버튼(Split Button)이며 공통 컴포넌트에 이 이름을 사용한다. 기본 모드는 일반 Pull이고 설정은 기존 workspace 세션 파일의 선택 필드로 호환 저장한다. 미해결 모호성 없음.

## 변경 명세: 분할 버튼 배경 및 라벨

FR-010: SplitButton은 기본 배경색을 갖지 않고 활성 영역에 hover한 경우에만 배경을 표시한다. 비활성·실행 중 hover 강조는 적용하지 않는다.
FR-011: 선택 옵션이 Fetch이면 본체 라벨은 Fetch이며 나머지 세 옵션은 Pull이다. 메뉴의 네 옵션 문구·선택 저장·실행 방식은 유지한다.
수용 기준은 평상시 배경 없음, 두 영역의 hover 강조, Fetch/Pull 라벨 전환과 기존 선택·실행 가드 유지이다. 미해결 모호성 없음.

## 변경 명세: 전역 진행 표시

FR-012: Pull 분할 버튼에서 실행하는 Fetch와 세 Pull 작업은 기존 전역 ProgressOverlay를 작업 시작부터 Git 처리와 스냅샷 재조회가 끝날 때까지 표시한다. 완료 시 닫고 이전 포커스를 복원한다. 오류는 오버레이를 닫은 뒤 기존 알림으로 표시한다.
FR-013: 해당 작업은 하단 notice에 실행 중·완료·작업 결과 확인 문구를 기록하지 않는다. 저장소 경로 및 다른 기존 상태 문구는 유지한다.
수용 기준: 네 모드 모두 진행 중 전역 입력 차단, 성공·실패 후 닫기, 오래된 결과로 새 오버레이를 닫지 않음, 하단 실행 문구 미변경이다. 미해결 모호성 없음.

## 변경 명세: 작은 진행 창과 타이틀바 제외

FR-014: 전역 ProgressOverlay는 작업 영역 전체를 반투명 배경막으로 차단하고, 진행 애니메이션과 문구는 가운데 작은 카드에 표시한다. 카드가 화면 전체 크기가 되지 않는다.
FR-015: 전역 진행 배경막과 입력 차단 영역은 타이틀바를 덮지 않는다. Windows의 앱 타이틀바 높이를 제외하며 네이티브 타이틀바가 외부에 있는 플랫폼은 클라이언트 작업 영역 전체를 사용한다. 기존 진행 수명과 포커스·키보드 차단은 유지한다.
수용 기준: 약280 너비의 진행 카드, 반투명 배경, 타이틀바 외의 마우스 입력 차단, 기존 완료/오류 수명 유지이다. 미해결 모호성 없음.

## Pull rebase 옵션 제거

요청: Pull 버튼에서 Pull (rebase)를 제거한다.
수용 기준: 메뉴에는 Fetch·일반 Pull·빠른 전진 전용 Pull만 남는다. 기존 저장된 rebase 선택값은 일반 Pull로 복원하며 제거된 옵션을 UI에서 선택·실행하지 않는다. 세 옵션의 선택 저장·클릭 실행·진행 보호는 유지한다. 기록 메뉴 리베이스는 별도 요구사항으로 다룬다. 명확화할 모호성 없음.
