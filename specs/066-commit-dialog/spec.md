# 기능 명세: Commit 팝업과 실행

## 사용자 시나리오

### 사용자 이야기 1 — 커밋 팝업 (우선순위 P1)
Pull 왼쪽 Commit 버튼으로 팝업을 열고 여러 줄의 커밋 메시지와 두 옵션을 지정한다.
수용 기준: 공용 팝업·입력·체크박스·버튼 스타일을 사용한다. 커밋 메시지 TextArea, 바뀐 내용 즉시 푸시, 마지막 커밋 정정과 [확인][취소]가 표시된다. Enter는 메시지 줄바꿈이며 확인 버튼에서만 실행한다. 취소와 ESC는 실행 없이 닫는다.

### 사용자 이야기 2 — 스테이지 커밋 및 정정 (우선순위 P1)
사용자가 스테이지한 내용만 커밋한다. 선택 시 현재 HEAD를 정정한다.
수용 기준: 미스테이지·미추적 파일을 자동 추가하지 않는다. 일반 커밋은 스테이지 변경이 있어야 하며 메시지는 공백만일 수 없다. 정정은 마지막 메시지를 불러오고 원래 작성자를 유지하며 메시지만 정정하는 경우도 지원한다. HEAD가 없으면 정정할 수 없다. 충돌 인덱스는 거부하고 해결된 병합 커밋은 부모를 유지한다.

### 사용자 이야기 3 — 즉시 푸시와 결과 (우선순위 P1)
옵션 선택 시 커밋 성공 후 현재 브랜치를 푸시한다.
수용 기준: 기존 인증을 사용하고 강제 푸시하지 않는다. upstream이 있으면 해당 원격 브랜치, 없으면 origin의 같은 브랜치로 푸시한다. 커밋 성공 후 푸시 실패는 로컬 커밋을 유지하고 구분하여 알려 중복 커밋 재시도를 유발하지 않는다. 작업 중 전역 진행 표시와 입력 차단, 완료 후 기록·파일 갱신을 제공한다.

## 요구사항

- FR-001: Pull 왼쪽에 같은 아이콘 위/문구 아래 스타일의 Commit 버튼을 제공한다.
- FR-002: 공용 팝업에 여러 줄 메시지 입력과 두 체크박스, 확인·취소를 제공한다. 기본 옵션은 둘 다 해제한다.
- FR-003: 사용자의 명확화 답변대로 스테이지된 변경만 커밋한다.
- FR-004: 마지막 커밋 정정은 HEAD amend이며 원래 작성자와 부모를 유지한다. 옵션 전환 시 일반/정정 메시지 초안을 보존한다.
- FR-005: 즉시 푸시는 커밋 뒤에만 실행하고 강제 푸시는 하지 않는다. 푸시 실패로 로컬 커밋을 되돌리지 않는다.
- FR-006: 빈 메시지·변경 없음·HEAD 변경·잠금·미해결 충돌·서명 정보 없음·진행 중 리베이스·네트워크/인증/서버 거부를 처리한다. 오류에 URL 비밀값을 노출하지 않는다.
- FR-007: TextArea는 기존 TextInput의 편집·한글 IME·선택·복사·붙여넣기·포커스 상실 선택 해제를 재사용한다. 여러 줄 표시·줄바꿈·상하 이동·스크롤을 지원하고 기존 단일 줄 입력은 유지한다.
- FR-008: 확인 후에만 백그라운드 실행하고 중복 실행을 막는다. 성공은 창을 닫고 커밋 실패는 메시지를 보존한다. 푸시만 실패한 경우 창을 닫고 별도 알림을 표시한다. 실제 실행은 개발 중 사용자 저장소가 아닌 격리 fixture에서 검증한다.

## 명확화
질문: 스테이지된 변경만 커밋할지 모든 변경을 자동 스테이지할지?
사용자 답변: 스테이지된 변경만 커밋.
기본 커밋은 git commit, 정정은 git commit --amend에 해당한다. 정정과 푸시를 함께 선택해도 강제 푸시는 하지 않는다. 기존 upstream이 없는 푸시는 origin의 현재 브랜치를 대상으로 하며 자동 upstream 설정은 추가하지 않는다. 미해결 모호성 없음.

## 경계 조건과 성공 기준
첫 커밋·메시지만 정정·다중 줄 Unicode·범위 교체·역방향 선택·로컬 미스테이지 보존·외부 HEAD 변경·충돌·푸시 부분 실패를 테스트한다. 관련 테스트와 전체 회귀·fmt·엄격한 clippy·빌드가 통과한다. 실제 GUI 및 외부 원격 인증 검증 제한은 구분한다.
