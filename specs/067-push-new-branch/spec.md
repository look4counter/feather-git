# 기능 명세: Push와 새 브랜치

> 문서 정리일: 2026-11-17. 본문은 이 기능의 단계별 요구사항 이력을 포함한다. 현재 유효 기준과 검증 한계는 [전체 명세 색인](../README.md)을 함께 확인한다. 과거 검증 기록은 현재 버전의 재검증 결과가 아니다.
> 후속 변경 참고: [068](../068-commit-push-checkout/spec.md) · [080](../080-history-revert-reset/spec.md).
> 현재 기준: Push의 조용한 종료 조건은 068을 따르고 실제 툴바 Push 실행은 080의 확인창을 거친다.

## 사용자 시나리오 및 수용 기준

### 사용자 이야기 1: Push (P1)
Commit, Pull, Push, Branch 순서의 툴바에서 Push를 실행한다. 기존 추적 브랜치로 현재 로컬 브랜치를 푸시한다. 추적 관계가 없으면 origin의 같은 이름 브랜치를 만들고 성공 후 추적 관계를 설정한다. 거부·인증 오류는 알리고 강제 푸시는 하지 않는다.

### 사용자 이야기 2: New Branch (P1)
Branch로 New Branch 공용 팝업을 열고 브랜치명을 입력한다. 기본 해제인 생성 후 체크아웃 옵션과 [확인][취소]가 있다. 확인하면 현재 HEAD에서 로컬 브랜치를 만들고 선택한 경우 체크아웃한다. 취소·ESC는 변경하지 않는다. 실패하면 입력을 유지한다.

## 기능 요구사항
- FR-001: Pull 오른쪽 Push, 그 오른쪽 Branch를 기존 아이콘 위·문구 아래 공용 버튼으로 제공한다.
- FR-002: Push는 현재 브랜치의 upstream을 사용하고 없으면 origin의 동일 이름으로 전송 후 추적 관계를 설정한다. 기존 인증과 비강제 전송을 재사용한다. detached HEAD, 초기 커밋 없음, 원격 없음, 서버 거부를 오류로 처리한다.
- FR-003: New Branch는 공용 단일 줄 입력·체크박스·팝업·확인/취소 버튼을 사용한다. 공백 이름은 확인 비활성화, 유효하지 않거나 중복된 이름은 오류로 알린다.
- FR-004: 새 브랜치는 실행 시 현재 HEAD 커밋에서 생성한다. 기존 브랜치 덮어쓰기와 자동 푸시는 하지 않는다. 체크아웃을 선택해도 인덱스와 작업 파일을 보존한다. HEAD 없음과 진행 중 병합/리베이스는 거부한다.
- FR-005: 비동기 실행 중 기존 타이틀바 제외 전역 진행 오버레이·중복 실행 방지를 적용한다. 결과 후 기록·브랜치·파일 상태를 갱신하고 오류는 알린다. 생성 성공 후 체크아웃 실패는 생성 결과를 구분하여 중복 생성 시도를 막는다.
- FR-006: 팝업의 Enter 확인·ESC 취소·Tab 포커스 이동과 한글 조합 중 실행 방지를 제공한다. 오류 후 초안을 보존한다.

## 명확화 및 가정
2026-11-15: 사용자는 원격 브랜치 생성이 push인지 질문했다. 최초 푸시에는 origin 동일 이름과 추적 설정을 사용한다고 안내했다. Branch는 현재 선택된 기록 행이 아닌 현재 체크아웃 HEAD에서 생성한다. 생성 후 체크아웃 기본값은 해제다. 중요 미해결 모호성 없음.

## 성공 기준 및 경계
격리 저장소에서 최초/기존 upstream 푸시·비 fast-forward 거부·브랜치 생성/체크아웃·미커밋 보존·중복/잘못된 이름/HEAD 없음 검증이 통과한다. 전체 테스트·포맷·엄격한 Clippy·빌드를 확인한다. 사용자 저장소와 실제 외부 원격은 개발 검증에 사용하지 않는다. GUI와 외부 인증 미검증은 별도 보고한다.
