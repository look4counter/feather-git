## 사용자 시나리오 및 검증

### 사용자 이야기 1: Commit 확인 활성화 (P1)
메시지나 스테이지 상태와 관계없이 Commit 팝업의 확인 버튼을 누를 수 있다. 빈 메시지·스테이지 없음은 누른 후 오류로 안내하고 초안을 보존한다. 상태 조회 중·실패도 버튼을 비활성화하지 않고 상황을 안내한다. 실행 중 중복 실행과 한글 조합 중 확정은 방지한다.

### 사용자 이야기 2: 보낼 내용 없는 Push (P1)
초기 커밋이 없거나 현재 브랜치에 원격으로 보낼 커밋이 없으면 오류·완료 알림 없이 종료한다. 원격 브랜치가 없으면 최초 Push를 수행한다. 실제 변경이 있고 인증·서버 거부·분기 불일치가 있으면 기존 오류를 유지한다.

### 사용자 이야기 3: 참조 더블클릭 체크아웃 (P1)
저장소의 로컬·원격·태그 목록을 더블클릭하여 실제 체크아웃한다. 로컬은 해당 브랜치, 원격과 태그는 해당 커밋을 직접 체크아웃한다. 한 번 클릭하는 기존 기록 탐색과 스태시 동작은 유지한다.

## 기능 요구사항
- FR-001: Commit 확인 버튼은 항상 활성 스타일로 표시하고 Tab 이동 대상에 포함한다. 메시지/스테이지 사전 비활성 조건을 없애고 실행 시 검증한다.
- FR-002: Commit 확인 시 상태 조회/실패를 안내하고, 빈 메시지·변경 없음 등의 실행 오류와 초안을 유지한다. 중복 실행·IME 조합 중 실행은 차단한다.
- FR-003: Push는 초기 커밋 없음·원격과 동일·로컬이 뒤에만 있는 경우 조용히 종료한다. 원격이 없거나 분기되었거나 연결 실패인 경우는 실제 오류를 숨기지 않는다. 실제 전송이 필요한 경우 기존 비강제 전송·최초 upstream 설정을 유지한다.
- FR-004: 로컬·원격·태그 목록의 왼쪽 더블클릭은 정확한 참조를 사용한다. 로컬은 브랜치 HEAD, 원격/태그는 대상 커밋으로 detached HEAD가 된다. 태그 객체는 커밋까지 해석한다. 스태시에는 적용하지 않는다.
- FR-005: 체크아웃은 충돌하는 로컬 변경·미추적 파일을 덮어쓰지 않는다. 진행 중 병합/리베이스·참조 없음·HEAD/인덱스 잠금을 처리한다. 실패 시 오류를 표시한다.
- FR-006: 체크아웃은 백그라운드에서 실행하고 기존 타이틀바 제외 전역 진행 표시와 작업 차단을 재사용한다. 완료 후 HEAD·참조·기록·파일을 갱신하고 오래된 조회 결과를 무효화한다. 기존 단일클릭 탐색과 목록 가상화는 유지한다.

## 명확화 및 범위
사용자가 해당 커밋 체크아웃을 요청했으므로 원격·태그는 로컬 브랜치를 자동 생성하지 않고 직접 커밋으로 전환한다. 이 기본 동작을 사용자에게 안내했다. 항상 활성은 버튼의 표시와 입력/스테이지 조건 제거를 의미하며, 실행 중 중복 요청과 조합 중 확정은 계속 막는다. Push의 보낼 내용 없음은 로컬 커밋이 대상 원격보다 앞서지 않고 분기되지 않은 경우다. 중요 미해결 모호성 없음.

## 성공 기준·경계 조건
격리 저장소에서 초기/동일/뒤처진 Push 무시, 분기 거부와 인증/원격 없음 오류, 로컬/원격/일반·주석 태그 체크아웃, 충돌 보호·잠금·상태 오류, 단일/더블클릭 라우팅을 검증한다. 전체 테스트·포맷·엄격한 Clippy·빌드가 통과한다. 실제 사용자 저장소에서 Git 변경은 실행하지 않는다. 실제 GUI/외부 인증 미검증은 별도 보고한다.
