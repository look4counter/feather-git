# 기능 명세: 파일 이력 커밋 상세

> 문서 정리일: 2026-11-17. 본문은 이 기능의 단계별 요구사항 이력을 포함한다. 현재 유효 기준과 검증 한계는 [전체 명세 색인](../README.md)을 함께 확인한다. 과거 검증 기록은 현재 버전의 재검증 결과가 아니다.

작성일: 2026-11-15
상태: 명세 검증 완료
입력: 파일 변경 이력 팝업의 커밋 이력 패널을 위아래로 반분하고 아래에 기존 커밋 상세를 표시한다.

## 사용자 시나리오 및 검증

### 사용자 이야기 1: 이력과 상세 동시 확인 (우선순위 P1)

사용자는 파일 이력에서 선택한 커밋의 상세와 파일 변경을 함께 확인한다.
독립 검증: 파일 이력 팝업을 열어 최초 선택과 다른 행 선택을 확인한다.

1. 이력 조회 성공 시 왼쪽 위에는 이력, 아래에는 최초 선택 커밋 상세가 표시된다.
2. 다른 커밋을 선택하면 아래 상세와 오른쪽 파일 변경이 같은 커밋으로 갱신된다.
3. 긴 상세와 많은 이력은 각 영역에서 스크롤할 수 있다.

### 경계 조건

- 조회 중, 빈 이력, 조회 실패에는 선택되지 않은 커밋의 상세를 표시하지 않는다.
- 빠른 선택 변경 시 이전 조회 결과가 최신 상세를 덮어쓰지 않는다.
- 팝업 종료 시 상세 조회도 비활성화한다.

## 요구사항

- FR-001: 왼쪽 커밋 패널을 동일 높이의 상하 영역으로 나눈다.
- FR-002: 아래 영역에 선택된 커밋의 기존 상세 보기를 재사용한다.
- FR-003: 최초 선택 및 선택 변경 시 상세와 파일 변경을 함께 갱신한다.
- FR-004: 빈 상태, 실패, 빠른 선택 변경 및 종료를 기존 보기의 처리 방식으로 안전하게 처리한다.
- FR-005: 오른쪽 파일 diff, 이력 열 너비 조절 및 행 메뉴를 유지한다.

### 주요 개체

- 선택 커밋: 저장소 경로와 커밋 식별자로 상세를 조회한다.

## 성공 기준

- SC-001: 왼쪽 상하 영역 높이 차이가 테두리를 제외하고 1픽셀 이하이다.
- SC-002: 최초 선택과 행 전환에서 상세 및 파일 변경의 커밋 식별자가 모두 일치한다.
- SC-003: 빈 상태와 종료 후 선택 커밋 상세가 남지 않는다.

## 가정 및 명확화

추가 질문 0개. 반분은 고정 50:50을 뜻하며 분할선 드래그는 범위에 포함하지 않는다. 팝업 좌우 비율은 유지한다. 기존 상세의 조회 실패 표시와 스크롤을 재사용한다.
