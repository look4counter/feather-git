# 기능 명세: 체크아웃 컨텍스트 메뉴

> 문서 정리일: 2026-11-17. 본문은 이 기능의 단계별 요구사항 이력을 포함한다. 현재 유효 기준과 검증 한계는 [전체 명세 색인](../README.md)을 함께 확인한다. 과거 검증 기록은 현재 버전의 재검증 결과가 아니다.
> 후속 변경 참고: [071](../071-list-keys-detached-warning/spec.md) · [072](../072-reference-delete/spec.md) · [080](../080-history-revert-reset/spec.md).
> 현재 기준: 후보가 한 개여도 선택창을 표시하고 Detached HEAD 항목을 함께 제공한다. 후보가 없으면 기존 detached 경고 확인을 거친다.

상태: 명확화 완료

## 사용자 시나리오 및 검증

### 사용자 이야기 1: 참조 메뉴 (P1)
로컬·원격·태그 탭의 항목을 우클릭하면 해당 행이 선택되고 체크아웃 메뉴가 열린다. 메뉴 실행은 기존 더블클릭과 동일한 체크아웃을 수행한다. 로컬은 브랜치 전환, 원격은 기존 추적 브랜치 재사용·생성 흐름, 태그는 Detached HEAD 전환이다.

### 사용자 이야기 2: 커밋 기록 메뉴 (P1)
커밋 기록의 행을 우클릭하면 해당 커밋이 선택되고 체크아웃 메뉴가 열린다. 실행하면 선택 커밋의 로컬 브랜치를 우선 체크아웃한다. 여러 후보는 선택 창에서 고르고 브랜치가 없으면 정확한 커밋으로 Detached HEAD 전환한다.

## 요구사항

- FR-001: 로컬·원격·태그 행에 체크아웃 우클릭 메뉴를 제공하고 우클릭 대상 선택을 반영한다. 스태시는 제외한다.
- FR-002: 메인 커밋 기록의 행에 동일한 메뉴를 제공하고 선택한 커밋 ID를 사용한다.
- FR-003: 로컬 변경 보호, 잠금·충돌·진행 상태 검사, 백그라운드 실행, 오류 표시 및 완료 재조회는 기존 체크아웃 경로를 재사용한다.
- FR-004: 빈 목록, 잘못된 행, 오래된 메뉴, 프로젝트·탭·선택 변경 및 작업 중 실행을 차단한다.
- FR-005: 기존 단일클릭 탐색과 더블클릭 참조 체크아웃을 유지한다.

## 성공 기준

- SC-001: 세 참조 탭 및 커밋 기록의 정확한 대상으로 체크아웃한다.
- SC-002: 충돌하는 로컬 변경은 보존되고 실패를 표시한다.
- SC-003: 오래된 메뉴와 유효하지 않은 대상은 실행되지 않는다.

## 경계 조건 및 명확화

질문 0개. 우클릭한 행을 선택하는 기존 파일 메뉴 방식을 따른다. 커밋은 브랜치를 자동 생성하지 않는다. 이번 커밋 기록 범위는 메인 화면 목록이며 파일 이력 팝업은 포함하지 않는다. 전체 커밋 ID만 추가 허용하고 임의 revision 표현식은 허용하지 않는다.

## 사용자 이야기 3: 브랜치가 있는 커밋 체크아웃

명확화: 사용자가 로컬 브랜치 우선, 원격만 있을 때 기존 원격 체크아웃 흐름 사용을 선택했다.
수용 기준:
1. 기록의 체크아웃 메뉴와 더블클릭은 같은 규칙을 사용한다. 후보가 한 개여도 브랜치와 Detached HEAD를 고르는 선택창을 표시한다. Detached HEAD를 선택한 경우 기존 경고 확인창을 거친다.
2. 로컬 브랜치가 여러 개면 Detached HEAD를 포함하는 브랜치 선택 팝업을 열고 확인·취소를 제공한다. 선택·화살표·Tab·Enter·Escape와 스크롤을 지원한다. 확인 전이나 취소 시 Git 작업은 하지 않는다.
3. 로컬이 없으면 실제 원격 브랜치만 후보로 삼아 기존 추적 브랜치 재사용·생성 흐름을 사용한다. 여러 원격이면 같은 팝업에서 선택한다. 원격 HEAD 별칭과 태그는 브랜치 후보에서 제외한다.
4. 브랜치가 없으면 기존 정확한 커밋 Detached HEAD 확인을 유지한다.
5. 선택 중 프로젝트·경로·커밋·후보·작업 상태가 달라지면 실행하지 않는다. 로컬 참조가 실제 실행 전에 다른 커밋으로 이동하면 백엔드에서 거절한다.

- FR-006: 로컬 우선 후보를 결정하고 후보가 하나여도 브랜치와 Detached HEAD를 고르는 확인·취소 선택창을 표시한다. 후보가 없는 경우 기존 detached 경고 확인을 사용한다. 080 FR-009가 단일 후보 즉시 전환 조건을 대체한다.
- FR-007: 후보 선택은 기존 안전한 비동기 체크아웃과 갱신을 재사용하고 로컬 참조의 선택 커밋 일치를 실제 잠금 아래 검증한다.
- SC-004: 단일·다중·로컬/원격 우선·후보 없음·취소·오래된 후보·실행 직전 참조 이동 검증을 통과한다.

범위는 메인 기록 패널이다. 브랜치가 없는 커밋에 로컬 브랜치를 자동 생성하지 않는다. 기존 원격 흐름의 추적 브랜치 생성 확인은 유지한다. 추가 질문이 필요한 모호성 없음.

## 브랜치 선택 목록 표시 오류 보완
여러 브랜치 후보가 있으면 안내 문구와 함께 후보 이름·선택 상태를 실제로 표시한다. 목록은 최대 8행 높이를 차지하고 후보가 더 많으면 스크롤할 수 있어야 한다. 확인·취소와 기존 키보드 선택 동작을 유지한다.
명확화: 사용자 보고는 다중 후보 팝업의 목록 미표시이며 후보 해석이나 체크아웃 정책 변경은 요구하지 않는다. 추가 질문 없이 기존 요구사항을 유지한다.

## 사용자 이야기 4: 인코딩 선택과 같은 브랜치 선택 스타일 (P1)
- FR-008: 브랜치 선택 창을 인코딩 선택 창과 같은 폭, 28픽셀 행, 행 사이 간격, 둥근 모서리, 선택 배경·체크 표시, hover 배경으로 표현한다.
- FR-009: 브랜치 후보 정책과 확인·취소, 키보드 이동·포커스, 최대 8행 이후 스크롤 및 오래된 요청 차단은 유지한다.
- SC-005: 인코딩 선택과 동일한 행 시각 속성을 사용하고 선택된 한 행에만 체크 표시가 나타난다. 클릭만으로 체크아웃하지 않으며 기존 관련 회귀 테스트를 통과한다.
명확화: 요청은 시각 스타일 통일이다. 기존 선택 및 확인 동작은 유지하며 인코딩 선택의 순환 키보드 이동 등 동작 변경은 포함하지 않는다. 불명확한 필수 결정 없음.
