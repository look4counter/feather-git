# 기능 명세: 목록 키보드 이동과 detached HEAD 확인

> 문서 정리일: 2026-11-17. 본문은 이 기능의 단계별 요구사항 이력을 포함한다. 현재 유효 기준과 검증 한계는 [전체 명세 색인](../README.md)을 함께 확인한다. 과거 검증 기록은 현재 버전의 재검증 결과가 아니다.
> 후속 변경 참고: [072](../072-reference-delete/spec.md) · [080](../080-history-revert-reset/spec.md).
> 현재 기준: 현재 배지는 맨 앞이다. 원격 체크아웃의 동명 로컬 브랜치는 072에 따라 재사용한다. 기록 브랜치 선택창은 080에 따라 Detached HEAD도 제공한다.

작성일: 2026-11-15
상태: 명확화 완료

## 사용자 이야기

### 이야기 1: 목록 선택 이동 (P1)
목록에 포커스를 두고 위·아래 화살표로 이전·다음 항목을 선택한다. 메인 저장소의 네 탭, 파일·상세 항목, 커밋 기록, 파일 이력 팝업, 최근 저장소, 설정 원격·인증 목록을 포함한다. diff 본문은 기존 텍스트 커서 이동을 유지한다.

### 이야기 2: detached HEAD 확인 (P1)
태그·커밋 체크아웃을 요청하면 브랜치에 연결되지 않는 상태임을 알리는 확인·취소 팝업을 표시한다. 취소·Escape는 실행하지 않는다. 로컬 브랜치 전환은 기존대로 실행한다.

## 요구사항

- FR-001: 포커스가 있는 선택 목록의 수정키 없는 위·아래 입력은 이전·다음 선택을 수행하고 화면 밖 선택을 노출한다.
- FR-002: 빈 목록은 무시하고 첫·마지막 항목에서 멈춘다. 미선택 목록은 첫 이동에 첫 항목을 선택한다. 입력 필드와 diff 본문의 화살표 처리를 침범하지 않는다.
- FR-003: 선택 변경에 따른 기존 상세·파일 조회를 재사용하며 이동만으로 체크아웃·저장소 열기·삭제를 실행하지 않는다.
- FR-004: detached HEAD를 유발하는 모든 UI 체크아웃 진입점에서 경고 확인 후에만 기존 안전한 작업을 실행한다.
- FR-005: 취소와 Escape는 변경 없이 닫고 포커스를 복원한다. 확인 중 배경 조작을 막으며 프로젝트·경로가 바뀐 요청을 실행하지 않는다.

## 성공 기준 및 경계 조건

SC-001: 모든 선택 목록에서 연속 방향키 이동·끝 경계·빈 상태를 검증한다.
SC-002: 로컬 체크아웃은 경고 없이, 태그·커밋은 경고 확인 후 한 번만 실행한다. 원격은 New Branch 확인 후 추적 브랜치를 생성·체크아웃한다.
SC-003: 취소 및 오래된 요청에서는 Git 작업이 실행되지 않는다.

## 명확화

질문 0개. 수정키 조합 및 다중선택 확장은 범위 밖이며 일반 방향키는 단일 선택한다. 설정 목록은 항목 포커스로 선택을 나타낸다. 최근 저장소는 Enter로만 선택 항목을 연다. 경고에 확인·취소를 제공하며 Escape는 취소한다.

### 사용자 이야기 3: 로컬 브랜치 배지 (P1)
로컬 탭의 현재 브랜치는 현재 배지가 행의 맨 앞에 표시된다. 각 로컬 브랜치는 실제 upstream 설정의 원격 추적 브랜치를 이름이 포함된 배지로 표시한다.

- FR-006: 현재 배지를 아이콘·브랜치명보다 앞에 둔다. 실제 원격 upstream만 배지로 표시하고 이름 일치로 추정하지 않는다. upstream이 없는 경우 표시하지 않는다.
- SC-004: 이름이 다른 추적 관계, 추적 없음, 로컬 브랜치 추적 및 갱신 이후 배지를 검증한다.
- 가정: Git의 표준 upstream은 로컬 브랜치별 하나이며 실제 설정만 표시한다. upstream 자체가 로컬인 경우 원격 배지로 표시하지 않는다.

### 사용자 이야기 4: 원격에서 추적 브랜치 생성 (P1)
원격 탭의 메뉴·더블클릭 체크아웃은 New Branch 팝업을 연다. 사용자가 이름을 입력하고 확인하면 정확한 원격 커밋에서 로컬 브랜치를 만들고 upstream을 지정한 뒤 안전하게 체크아웃한다. 취소는 저장소를 변경하지 않는다.

- FR-007: 원격 체크아웃은 기존 New Branch 팝업을 재사용한다. 원격 대상과 기본 브랜치명을 표시하고 생성 후 체크아웃을 적용한다. 기존 이름은 덮어쓰지 않으며 누락 대상·설정·체크아웃 실패를 표시한다.
- SC-005: 확인 후 로컬 브랜치의 HEAD·upstream·파일이 선택한 원격과 일치하며 취소·이름 중복·충돌 시 로컬 변경이 보존된다.

### 사용자 이야기 5: 추적 관계 표시 통일 (P1)
로컬 탭에서 추적 관계를 로컬 브랜치명 → 원격 아이콘과 붉은 글씨의 짧은 브랜치명으로 표시한다. 커밋 기록과 같은 배지 스타일을 사용한다.

- FR-008: 추적 대상이 있는 로컬 브랜치명 뒤에 오른쪽 화살표를 표시하고, 그 뒤에 커밋 기록과 같은 원격 아이콘·붉은색 글씨·짧은 이름의 배지를 표시한다. origin/feature/login은 feature/login으로 표시하며 실제 추적 참조는 바꾸지 않는다.
- FR-009: 추적 대상이 없으면 화살표와 배지를 모두 생략한다. 현재 배지는 맨 앞에 유지한다. 원격 이름에 슬래시가 있어도 설정된 원격 이름 전체만 제거하고 브랜치 경로는 보존한다.
- SC-006: 추적 없음·일반 원격·경로형 브랜치·슬래시가 있는 원격 이름의 표시를 검증한다.
- 명확화: 질문 0개. 간단한 브랜치명은 커밋 기록과 동일하게 원격 이름 접두사를 제외한 브랜치 경로를 의미한다.
