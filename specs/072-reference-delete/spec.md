# 기능 명세: 저장소 항목 삭제 메뉴

> 문서 정리일: 2026-11-17. 본문은 이 기능의 단계별 요구사항 이력을 포함한다. 현재 유효 기준과 검증 한계는 [전체 명세 색인](../README.md)을 함께 확인한다. 과거 검증 기록은 현재 버전의 재검증 결과가 아니다.

작성일: 2026-11-15
상태: 명확화 완료
입력: 저장소 로컬·원격·태그·스태시 탭의 컨텍스트 메뉴에 삭제를 추가한다.

## 사용자 시나리오와 검증

### 이야기 1: 로컬 브랜치·태그 삭제 (P1)
행을 우클릭하면 해당 행을 선택하고 기존 체크아웃 메뉴와 삭제 메뉴를 표시한다. 삭제를 누르면 대상·영향 확인 팝업이 열리며 승인 후 삭제하고 목록과 기록을 갱신한다.

### 이야기 2: 원격 브랜치 삭제 (P1)
원격 행의 삭제 확인에 서버 브랜치를 지운다는 사실을 표시한다. 승인 후 정확한 원격 서버 브랜치를 삭제하고 로컬 원격 추적 참조를 갱신한다. 실패는 표시하며 서버 삭제 후 로컬 정리 실패도 구분한다.

### 이야기 3: 스태시 삭제 (P1)
스태시 행의 삭제 메뉴는 정확한 스태시를 확인한 뒤 삭제한다. 다른 항목이 추가되어 인덱스가 바뀌면 다른 스태시를 삭제하지 않는다.

## 요구사항

- FR-001: 네 탭의 우클릭 항목에 삭제 메뉴를 제공한다. 기존 체크아웃 메뉴는 가능한 탭에서 유지하며 커밋 기록에는 삭제를 추가하지 않는다.
- FR-002: 모든 삭제는 대상과 영향이 명시된 확인·취소 팝업에서 승인해야 실행한다. Escape·취소는 Git 변경 없이 포커스를 복원한다.
- FR-003: 로컬은 현재 체크아웃 또는 다른 worktree에서 사용 중인 브랜치를 거부한다. 미병합 브랜치는 강제 삭제하지 않고 오류를 표시한다. 태그는 로컬 태그만 삭제한다.
- FR-004: 원격은 실제 fetch refspec으로 대상 서버 브랜치를 찾아 삭제하고 성공 후 로컬 추적 정보를 정리한다. 원격 HEAD 별칭·매핑 불가 대상은 거부한다. 인증·서버 거부·대상 변경을 오류로 알린다.
- FR-005: 확인 당시 정확한 객체 ID와 참조·스태시 인덱스를 검증한다. 오래된 프로젝트·경로·행·선택과 변경된 대상을 실행하지 않는다.
- FR-006: 백그라운드 작업·중복 차단·오류 표시·완료 재조회를 기존 작업 경로로 통합하며 작업 파일과 인덱스를 변경하지 않는다.

## 성공 기준

SC-001: 네 탭의 삭제와 취소·빈 목록·오래된 대상 거부를 검증한다.
SC-002: 격리 저장소에서 로컬·태그·스태시 삭제 결과와 HEAD·작업 파일 보존을 검증한다.
SC-003: 로컬 bare 원격에서 서버 브랜치 삭제와 로컬 정리, 서버 변경 거부를 검증한다.

## 명확화

질문 1개 응답 완료. 원격 삭제는 서버 브랜치 삭제 후 로컬 원격 추적 정보 갱신으로 확정했다. 로컬은 안전한 미병합 보호를 기본으로 하며 강제 삭제 기능은 포함하지 않는다. 태그는 로컬 삭제이며 원격 태그 삭제는 범위 밖이다. 실제 사용자 저장소에서 삭제 작업을 실행하지 않는다.

### 사용자 이야기 4: 기존 로컬 브랜치 재사용 (P1)
원격 탭에서 체크아웃할 때 원격의 짧은 브랜치명과 같은 로컬 브랜치가 있으면 해당 로컬 브랜치를 체크아웃한다. 없을 때만 기존 New Branch 팝업을 연다.

- FR-007: 원격 체크아웃은 실제 원격 이름을 제외한 브랜치명으로 기존 로컬 브랜치를 찾는다. 존재하면 기존 커밋 위치와 추적 설정을 유지하고 안전하게 로컬 체크아웃한다. 팝업 확인 중 같은 이름이 생긴 경우도 기존 로컬 브랜치를 재사용한다.
- SC-004: 기존 로컬 브랜치 재사용 시 HEAD가 그 로컬 브랜치가 되고 upstream과 브랜치 위치가 변경되지 않는다. 충돌 시 로컬 작업을 보존한다.
- 명확화: 원격 이름 접두사 제거는 커밋 기록과 같은 규칙이다. 기존 로컬의 추적 대상을 임의로 변경하지 않는다.
