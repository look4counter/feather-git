# 검증 안내

HEAD가 아닌 커밋을 우클릭하고 태그 추가를 선택한다. 대상 ID·태그명 입력·기본 해제된 원격에 Push·확인·취소를 확인한다. Tab·Space·Enter·Escape·한글 조합을 확인한다. 로컬 생성 후 태그 탭과 커밋 기록 갱신을 확인한다. 체크 시 태그 하나만 원격에 전송되며 실패 시 로컬 생성 여부를 구분한다. 실제 사용자 저장소의 생성·외부 Push는 실행하지 않는다.

## 실행 결과

- 전체 테스트: 423개 통과, 실패 0개, 수동 성능 테스트 3개 제외.
- 태그 테스트 3개: 비HEAD 커밋 지정·잘못된 이름·동명 로컬·누락 커밋·HEAD와 파일 보존, 설정 원격에 태그 하나만 전송, origin 기본값·detached HEAD 전송·원격 충돌·Push 실패 시 로컬 태그 보존을 검증했다.
- UI 소유자 테스트 1개: 팝업의 고정된 커밋과 프로젝트·경로 변경 거부를 검증했다. 기존 Push·원격 삭제·체크아웃 회귀는 전체 테스트에 포함됐다.
- 초기 원격 태그 충돌 테스트가 libgit2의 기존 태그 이동을 재현했다. 태그 전송 negotiation에 기존 객체 보호를 추가하고 재실행 및 전체 테스트가 통과했다.
- cargo check, cargo clippy -- -D warnings, cargo fmt --check, 새 파일 rustfmt --check 통과.
- cargo rustc --bin feather-git -- -o target/073-feather-git.exe 별도 실행 파일 빌드 성공. 기존 실행 파일은 교체하지 않았다.
- 실제 GUI 포커스·IME·팝업 조작과 외부 서버 인증·정책은 미검증이다. 자동 테스트는 격리 저장소와 로컬 bare 원격만 사용했으며 실제 사용자 저장소에 태그 생성·외부 Push를 실행하지 않았다.

## 최종 코드 대조

요구사항 5개, 성공 기준 3개, 사용자 이야기 2개와 계획의 공용 팝업·공통 Push·고정 대상·비강제 보호·부분 성공·완료 갱신을 코드 및 테스트에 대조했다. 미해결 구현 불일치나 추가 작업 없음. 헌법은 미작성 템플릿으로 유효 규범 검사를 생략했다. 화면 및 외부 인증 검증 제한은 위와 같다.
