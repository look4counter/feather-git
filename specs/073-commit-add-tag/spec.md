# 기능 명세: 선택 커밋에 태그 추가

> 문서 정리일: 2026-11-17. 본문은 이 기능의 단계별 요구사항 이력을 포함한다. 현재 유효 기준과 검증 한계는 [전체 명세 색인](../README.md)을 함께 확인한다. 과거 검증 기록은 현재 버전의 재검증 결과가 아니다.
> 후속 변경 참고: [074](../074-tag-delete-history-stash/spec.md).

작성일: 2026-11-15
상태: 명확화 완료
입력: 커밋 기록 컨텍스트 메뉴에 태그 추가와 태그명·원격에 Push 팝업을 추가한다.

## 사용자 시나리오와 수용 검증

### 이야기 1: 로컬 태그 생성 (P1)
커밋 행을 우클릭하면 해당 행이 선택되고 태그 추가 메뉴가 표시된다. 메뉴를 선택하면 대상 커밋·태그명 입력·원격에 Push 체크박스·확인·취소가 있는 팝업이 열린다. 이름 입력 후 확인하면 현재 HEAD와 무관하게 해당 커밋에 태그가 생성되고 기록과 태그 목록이 갱신된다. 취소·Escape는 변경하지 않는다.

### 이야기 2: 선택적 태그 Push (P1)
원격에 Push를 체크하고 확인하면 로컬 생성 후 해당 태그만 원격에 전송한다. 체크하지 않으면 네트워크 작업을 실행하지 않는다. 전송 실패 시 로컬 생성 사실과 실패를 알린다.

## 요구사항

- FR-001: 메인 커밋 기록의 컨텍스트 메뉴에 태그 추가를 제공한다. 클릭한 커밋의 정확한 ID와 저장소 경로를 팝업에 고정한다. 다른 저장소 목록 메뉴는 변경하지 않는다.
- FR-002: 팝업에 태그명과 기본 해제된 원격에 Push 체크박스, 확인·취소를 제공한다. Tab 이동·체크박스 Space·Enter 확인·Escape 취소와 한글 조합 중 오확정 방지를 기존 팝업과 동일하게 제공한다.
- FR-003: 유효한 이름으로 선택 커밋에 경량 태그를 생성한다. 빈 이름·잘못된 이름·누락 커밋·동명 태그는 오류로 처리하며 기존 태그를 덮어쓰지 않는다. 입력과 선택한 대상은 실패 시 보존한다.
- FR-004: Push 체크 시 현재 로컬 브랜치에 설정된 원격을 사용하고 설정이 없거나 detached HEAD면 origin을 사용한다. 생성한 태그 하나만 비강제로 전송한다. 원격 없음·연결·인증·충돌·서버 거부는 로컬 생성 사실과 구분하여 표시한다.
- FR-005: 확인은 비동기로 실행하고 중복 입력과 배경 변경을 막는다. 프로젝트·경로가 달라진 요청은 거부한다. 완료 후 태그·커밋 기록을 갱신하고 HEAD·작업 파일·인덱스는 유지한다.

## 성공 기준

SC-001: HEAD가 아닌 커밋에 정확한 태그를 생성하고 기존 태그·HEAD·파일을 보존한다.
SC-002: 체크하지 않은 경우 원격 없이 성공하며, 체크 시 지정 원격에 태그 하나만 전송한다.
SC-003: 취소·잘못된 대상·이름 오류는 태그를 만들지 않는다. 원격 실패는 로컬 태그를 보존하고 명시한다.

## 명확화와 가정

질문 0개. 태그 메시지 입력 요청이 없으므로 경량 태그를 생성한다. Push 기본값은 해제하며 기존 Push 정책과 같이 현재 브랜치의 원격 설정, 없으면 origin을 따른다. 전체 태그 Push·강제 덮어쓰기·태그 체크아웃은 범위 밖이다. 실제 사용자 저장소에는 태그 생성·외부 Push를 실행하지 않는다.
