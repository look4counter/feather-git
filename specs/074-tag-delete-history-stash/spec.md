# 기능 명세: 원격 태그 삭제·커밋 더블클릭·Stash

> 문서 정리일: 2026-11-17. 본문은 이 기능의 단계별 요구사항 이력을 포함한다. 현재 유효 기준과 검증 한계는 [전체 명세 색인](../README.md)을 함께 확인한다. 과거 검증 기록은 현재 버전의 재검증 결과가 아니다.

작성일: 2026-11-15
상태: 명확화 완료

## 사용자 시나리오와 검증

### 이야기 1: 원격 태그 삭제 선택 (P1)
태그 삭제 확인 팝업에 기본 해제된 원격 태그 삭제 체크박스를 표시한다. 해제하면 기존 로컬 삭제만 수행한다. 체크 후 확인하면 해당 원격 태그와 로컬 태그를 삭제한다. 취소는 변경하지 않는다.

### 이야기 2: 커밋 더블클릭 체크아웃 (P1)
커밋 기록 행을 왼쪽 더블클릭하면 해당 커밋으로 체크아웃을 요청한다. 기존 detached HEAD 경고에서 확인 후 실행한다. 단일클릭과 방향키는 기존 선택·상세 조회만 수행한다.

### 이야기 3: Stash 생성 (P1)
툴바 Branch 오른쪽에 Stash 버튼을 표시한다. 누르면 스태시명·기본 해제된 스테이지 변경사항 유지 체크박스·확인·취소 팝업이 열린다. 확인하면 입력한 이름으로 추적 파일의 변경을 스태시에 저장하고 목록과 파일을 갱신한다.

## 요구사항

- FR-001: 원격 태그 삭제 체크박스는 태그 삭제 팝업에만 표시한다. 마우스·Tab·Space로 조작하고 기본값은 해제한다.
- FR-002: 원격 태그 삭제는 태그 Push와 동일하게 현재 브랜치의 원격 설정, 없거나 detached이면 origin을 사용한다. 동명 원격 태그가 확인 당시 로컬 객체와 다르면 삭제하지 않는다. 원격에 이미 없으면 로컬 정리를 진행한다. 서버 실패는 로컬 태그를 유지하고 서버 성공 후 로컬 실패는 부분 결과를 표시한다.
- FR-003: 메인 커밋 기록의 왼쪽 정확히 두 번 클릭만 기존 체크아웃 확인 경로로 연결한다. 잘못된 행·프로젝트·조회 중·작업 중 입력은 무시한다. 오른쪽 메뉴·단일클릭·키보드 선택은 유지한다.
- FR-004: Stash 버튼과 입력 팝업은 기존 툴바·폼 스타일과 포커스·IME·오류·취소 처리를 따른다. 스태시명은 필수이며 유지 체크박스는 기본 해제한다.
- FR-005: Stash는 추적 파일의 staged·unstaged 변경을 저장한다. 유지 해제면 해당 변경을 작업 폴더·인덱스에서 정리하고 체크면 staged 변경을 유지한다. 미추적·무시 파일은 포함하거나 삭제하지 않는다. HEAD는 변경하지 않는다.
- FR-006: Stash의 변경 없음·초기 커밋 없음·충돌·진행 중 작업·서명 실패·잠금은 오류로 표시한다. 비동기 실행·중복 차단·소유자 검증·완료 재조회를 기존 작업 경로로 통합한다.

## 성공 기준

SC-001: 원격 체크 해제·삭제 성공·미존재·변경 대상 거부·취소를 격리 원격으로 검증한다.
SC-002: 단일·더블·다중 클릭·방향키 경로와 오래된 입력 거부를 검증한다.
SC-003: Stash의 keep-index 양쪽과 저장 이름·스태시 내용·HEAD·미추적 파일 보존·오류 처리를 검증한다.

## 명확화와 가정

질문 0개. 스테이지 변경사항 유지는 표준 keep-index 의미다. 입력 이름은 필수이고 미추적 파일 포함 옵션은 추가하지 않는다. 원격 태그 삭제는 태그 Push의 원격 규칙을 공유한다. 실제 사용자 저장소나 외부 서버에는 변경을 실행하지 않는다.
