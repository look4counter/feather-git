# 기능 명세: 스태시 적용 메뉴

> 문서 정리일: 2026-11-17. 본문은 이 기능의 단계별 요구사항 이력을 포함한다. 현재 유효 기준과 검증 한계는 [전체 명세 색인](../README.md)을 함께 확인한다. 과거 검증 기록은 현재 버전의 재검증 결과가 아니다.

작성일: 2026-11-15
상태: 명확화 완료
입력: 저장소 스태시 탭의 컨텍스트 메뉴에 스태시 적용을 추가한다.

## 사용자 시나리오와 수용 검증

### 이야기 1: 선택 스태시 적용 (P1)
스태시 행을 우클릭하면 해당 행이 선택되고 스태시 적용과 기존 삭제 메뉴가 표시된다. 스태시 적용을 누르면 해당 스태시를 현재 작업 폴더에 적용하고 파일 목록을 갱신한다. 적용된 스태시는 목록에 남는다.

### 이야기 2: 실패와 오래된 대상 보호 (P1)
빈 목록·잘못된 행·오래된 메뉴·저장소 또는 선택 변경은 실행하지 않는다. 스태시 순번·객체가 변경되면 다른 항목을 적용하지 않는다. 기존 로컬 변경과 충돌하거나 잠금·미해결 충돌·진행 중 작업이 있으면 강제로 덮어쓰지 않고 오류를 표시한다. 실패 후에도 스태시는 유지된다.

## 요구사항

- FR-001: 스태시 탭에만 스태시 적용 메뉴를 추가하고 우클릭한 선택 행을 대상으로 한다. 기존 삭제와 다른 탭 메뉴를 유지한다.
- FR-002: 적용은 표준 stash apply처럼 스태시를 삭제하지 않는다. 별도 index 복원 옵션은 제공하지 않는다. HEAD를 변경하지 않고 미추적 파일과 충돌하는 기존 변경을 강제 덮어쓰지 않는다.
- FR-003: 적용 준비와 실행은 백그라운드에서 수행한다. 프로젝트·경로·탭·행·표시 설명·정확한 객체 ID를 검사하며 순번 변경 시 거부한다. 중복 실행을 차단한다.
- FR-004: 기존 전역 진행·오류 표시·작업 차단·완료 재조회 흐름을 재사용한다. 성공과 실패 모두 최신 파일·스태시 상태를 반영한다. 충돌 등 오류 시 스태시 보존 사실과 확인할 상태를 안내한다.

## 성공 기준

SC-001: 선택한 스태시의 내용이 복원되고 스태시 목록과 HEAD는 유지된다.
SC-002: 순번 변경·잘못된 대상·로컬 충돌·잠금에서 다른 스태시를 적용하거나 기존 파일을 강제 덮어쓰지 않는다.
SC-003: 메뉴 상태와 비동기 완료 갱신을 테스트하고 기존 생성·삭제 기능의 회귀를 검사한다.

## 명확화와 가정

질문 0개. 적용은 pop이 아닌 apply로 해석하며 별도 확인 팝업은 추가하지 않는다. stage 상태 복원 옵션은 추가하지 않고 기본 apply 동작을 따른다. 실제 사용자 저장소에는 스태시를 적용하지 않고 격리 저장소만 사용한다.
