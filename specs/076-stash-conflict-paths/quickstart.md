# 검증 안내

스태시 적용에 충돌하는 여러 로컬 파일을 준비하고 오류 팝업의 경로·개수·정렬을 확인한다. 목록이 많을 때 200픽셀 높이 안에서 스크롤하며 확인 버튼이 유지되는지 확인한다. 일반 잠금 오류에는 빈 경로 영역을 표시하지 않는다. 스태시 행의 0: On main: 이름 형식과 두 번째 항목 적용·삭제의 정확한 대상을 확인한다. 자동 검증은 격리 저장소를 사용하며 실제 사용자 저장소를 변경하지 않는다.

## 관련 검증 결과

- 다중 checkout 충돌의 정확한 경로·정렬·기존 파일 보존·ToolbarResult 전달 테스트 통과.
- 인덱스의 세 충돌 stage가 같은 파일을 가리킬 때 경로 중복 제거 테스트 통과.
- Alert의 2,000개 경로 보존·정렬·중복 제거·빈 목록 및 기존 알림 회귀 테스트 통과.
- 새로운 순번: 설명 표시, 숫자와 행 일치 검사, 두 번째 스태시 적용, 삭제 확인·취소 및 오래된 메뉴 보호 테스트 통과.
- 오래된 작업·저장소 경로·다른 작업의 충돌 경로를 표시하지 않는 UI 상태 테스트 통과.
- cargo check, cargo clippy -- -D warnings, cargo fmt --check 및 stash_actions.rs rustfmt --check 통과.
- cargo rustc --bin feather-git -- -o target/076-feather-git.exe 별도 실행 파일 빌드 성공. 기존 실행 파일은 교체하지 않았다.
- 실제 GUI의 고정 높이·스크롤·포커스 조작은 미검증이다. 모든 Git 변경 테스트는 격리 저장소에서 수행했고 실제 사용자 저장소에는 변경하지 않았다.
- 전체 회귀 테스트: 440개 통과, 실패 0개, 수동 성능 테스트 3개 제외.

## 최종 코드 대조

요구사항 4개, 성공 기준 3개, 사용자 이야기 2개와 계획의 구조 오류·경로 수집/전달·정렬/중복 제거·200픽셀 스크롤·일반 알림 보존·새 표시와 실제 locator 분리를 코드 및 테스트에 대조했다. 구현상 미해결 누락·모순과 추가 작업 없음. 헌법은 미작성 템플릿으로 유효 규범 검사는 생략했다. GUI의 실제 고정 높이·스크롤 조작 검증 제한은 위와 같다.
