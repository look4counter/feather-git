# 기능 명세: 스태시 충돌 경로와 목록 표시

> 문서 정리일: 2026-11-17. 본문은 이 기능의 단계별 요구사항 이력을 포함한다. 현재 유효 기준과 검증 한계는 [전체 명세 색인](../README.md)을 함께 확인한다. 과거 검증 기록은 현재 버전의 재검증 결과가 아니다.

작성일: 2026-11-15
상태: 명확화 완료

## 사용자 시나리오 및 수용 기준

### 이야기 1: 충돌 경로 확인 (P1)
스태시 적용 중 충돌이 발생하면 오류 팝업에서 충돌 파일 경로와 개수를 확인한다. 경로 목록은 고정 높이 안에서 스크롤하며 많아도 팝업 전체 높이를 계속 늘리지 않는다. 기존 오류 설명과 확인·Enter·Escape 닫기를 유지한다.

### 이야기 2: 간결한 스태시 목록 (P1)
저장소 스태시 탭의 행은 stash@{0}: On main: 스태싱 대신 0: On main: 스태싱으로 표시한다. 실제 적용·삭제는 기존 정확한 스태시를 대상으로 한다.

## 요구사항

- FR-001: checkout 충돌 알림과 적용 전후 인덱스의 미해결 충돌에서 경로를 수집한다. 정렬·중복 제거한 저장소 상대 경로를 구조화하여 UI에 전달한다. 경로가 없는 일반 오류는 기존 오류 팝업을 유지한다.
- FR-002: 충돌 팝업은 경로 개수와 높이 200픽셀인 스크롤 목록을 제공한다. 경로 수 때문에 높이가 늘어나지 않으며 모든 항목을 스크롤로 확인할 수 있다. 기존 닫기·포커스와 상태 갱신은 유지한다.
- FR-003: 스태시와 기존 로컬 변경을 강제로 덮어쓰지 않고 성공·실패 후 기존 상태 재조회를 유지한다. 오래된 프로젝트·작업 결과의 경로가 다른 저장소 팝업에 표시되지 않도록 한다.
- FR-004: 스태시 목록은 순번: 설명으로 표시하고 원래 설명을 보존한다. 표시 형식만 바꾸며 적용·삭제 locator와 객체 검증은 유지한다.

## 성공 기준

SC-001: 로컬 변경 때문에 적용 거부된 여러 파일과 인덱스 충돌 경로가 누락 없이 수집되고 중복 제거된다.
SC-002: 다수 경로가 고정 높이 목록 데이터에 보존되고 경로 없는 오류에서는 목록을 표시하지 않는다.
SC-003: 새 표시 형식으로도 두 번째 스태시 적용·삭제와 오래된 선택 거부가 동작한다.

## 명확화와 가정

질문 0개. 경로는 저장소 상대 경로이며 고정 높이는 200픽셀로 한다. 스태시 설명의 On main: 같은 내용은 그대로 유지한다. 복사·탐색기 열기 등 추가 기능은 범위 밖이다. 실제 사용자 저장소에는 변경을 실행하지 않는다.
