# 검증 가이드

1. cargo test로 저장소 병합·기존 Pull·커밋·화면 회귀를 검증한다.
2. cargo check, cargo clippy --all-targets -- -D warnings, cargo build를 실행한다.
3. 앱에서 기록 커밋을 우클릭해 병합을 선택하고 브랜치 유지와 갱신을 확인한다.
4. 충돌 시 알림과 변경 파일을 확인하고 기존 해결·커밋 흐름을 사용한다.

실행 결과는 검증 후 기록한다.

## 실행 결과

- cargo test --offline: 444개 통과, 실패 0개, 기존 제외 3개.
- cargo check --offline: 통과.
- cargo clippy --offline --all-targets -- -D warnings: 통과.
- cargo build --offline: 사용 중인 target/debug/feather-git.exe 교체 권한 오류로 기본 출력 갱신 불가.
- cargo rustc --offline --bin feather-git -- -o target/history-merge-verified.exe: 별도 실행 파일 빌드 성공. 출력 경로 지정 안내와 MSVC 라이브러리 생성 안내 경고만 발생.
- 병합 통합 검증: 빠른 전진·이미 포함됨·두 부모·충돌 상태·로컬 변경·인덱스 잠금·잘못된 식별자·없는 커밋·공통 조상 없음·빈 HEAD·Detached HEAD·성공 및 실패 후 갱신 통과.
- 화면 실행 보호는 기존 checkout_menu_target 검증을 재사용하며 해당 선택·프로젝트·로딩·진행 중 상태 회귀 테스트가 통과했다.
- 실제 앱 메뉴 클릭과 시각적 표시의 수동 검증은 수행하지 않았다. 실행 중인 앱은 종료하거나 교체하지 않았다.

## 일관성 및 수렴 결과

구현 전 명세·계획·작업 대응 분석에서 FR-001~004 전체가 T002~T004에 대응하며 누락·모순·중복은 없었다. 백엔드 I/O 래퍼 등록 발견 후 계획과 작업을 보완하고 재분석했다.
구현 후 요구사항 4개, 수용 시나리오 4개, 성공 기준 3개와 계획의 기존 도우미·백그라운드 실행·I/O 경계·갱신·최소 변경 결정을 대조했다. 헌장은 미작성 템플릿으로 별도 원칙 검사는 제외했다. 누락·부분 구현·충돌·요청 외 추가 모두 0건이다. 수렴 완료이며 추가 구현 작업은 없다.

## 병합 실패 경로 진단 검증 결과

- 재현 테스트를 구현 전에 추가하여 오류 타입·경로 수집이 없는 상태의 실패를 확인했다.
- stage 후 unstage 재현에서 빠른 전진·분기 병합의 실제 차단 경로 두 개와 한글·공백 경로를 확인했다. 병합과 무관한 unstaged 수정은 제외했다.
- libgit2 사전 차단은 checkout 알림 없이 발생함을 재현했고 설치된 merge.c의 merge_check_index·merge_check_workdir와 같은 인메모리 결과 비교로 보완했다. 병합 결과와 일치하는 staged 변경은 차단으로 오인하지 않고, 결과와 다른 staged 변경은 실제 차단 원인으로 포함한다.
- 추가 진단 테스트 5개: 정상 통과. 실제 잠금은 경로 없이 분류하고 기존 잠금 파일을 보존하며, 실제 병합 충돌은 경로와 병합 상태를 보존한다. Pull·툴바 경로 전달과 오래된 응답 거절을 검증했다.
- cargo test --offline: 457개 통과, 실패 0개, 기존 제외 3개. 공용 수집기로 이동한 스태시·기존 Alert·병합·Pull·커밋 회귀 포함.
- cargo check --offline 및 cargo clippy --offline --all-targets -- -D warnings: 통과.
- cargo rustc --offline --bin feather-git -- -o target/merge-diagnostics-verified.exe: 빌드 성공. 출력 경로 지정과 MSVC 라이브러리 생성 안내 경고만 발생했다.
- 실제 오류창의 시각적 표시·스크롤은 수동 검증하지 않았다. 실행 중 기본 앱은 교체하지 않았다. 모든 재현은 임시 저장소에서 수행했고 nonmac 저장소의 파일·인덱스·참조·잠금은 변경하지 않았다.

### 병합 진단 일관성과 수렴

명세 품질 점검 7개 모두 통과했다. 구현 전 추가 FR-005~008·수용 기준 5개를 T008~T010과 검증에 대응시켰고 누락·모순·중복 0건이었다. 사전 검사 발견 후 계획·조사·작업을 갱신하고 기존 요구사항 범위 안에서 재분석했다.
구현 후 전체 요구사항 8개, 수용 시나리오 9개, 성공 기준 4개와 실제 원인 수집·공통 인덱스 도우미·구조 경로 전달·비동기 유효성 검사·원래 오류 보존·데이터 보호 결정을 대조했다. 헌장은 미작성 템플릿으로 별도 원칙 검사 제외. 누락·부분 구현·모순·요청 외 추가 모두 0건이며 수렴 완료다.
