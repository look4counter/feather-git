> 문서 정리일: 2026-11-17. 본문은 이 기능의 단계별 요구사항 이력을 포함한다. 현재 유효 기준과 검증 한계는 [전체 명세 색인](../README.md)을 함께 확인한다. 과거 검증 기록은 현재 버전의 재검증 결과가 아니다.
> 후속 변경 참고: [078](../078-history-operation-toolbar/spec.md) · [080](../080-history-revert-reset/spec.md).
> 현재 기준: 기록 메뉴명은 Merge이며 실제 실행 전에 080의 확인창을 표시한다. Git 병합 동작과 오류 경로 계약은 유지한다.

작성일: 2026-11-16. 상태: 검토 완료.
입력: 기록 컨텍스트 메뉴에서 선택 커밋을 현재 체크아웃 브랜치에 병합한다.

## 사용자 시나리오 및 검증

### 사용자 이야기 1: 선택 커밋 병합 (우선순위 P1)

사용자가 커밋을 우클릭하고 병합을 선택하여 현재 브랜치에 반영한다.
독립 검증: 별도 저장소에서 병합 후 브랜치 이름·파일·부모 관계를 확인한다.

수용 시나리오:
1. 빠른 전진 가능 시 현재 브랜치 이름을 유지하고 대상 커밋으로 이동한다.
2. 분기된 경우 현재 커밋과 선택 커밋을 부모로 하는 병합 커밋을 만든다.
3. 이미 포함된 커밋은 변경 없이 성공한다.
4. 충돌은 오류를 알리고 파일과 병합 상태를 보존하여 기존 해결·커밋 흐름으로 이어진다.

### 경계 조건

Detached HEAD, 빈 저장소, 잘못된 커밋, 진행 중인 작업, 공통 조상 없음, 인덱스 잠금, 덮어쓸 로컬 변경은 안전하게 거절한다. 메뉴 이후 선택·프로젝트·경로가 바뀌거나 작업 중이면 실행하지 않는다.

## 요구사항

- FR-001: 기록 커밋 메뉴에 병합을 제공하고 선택한 정확한 커밋을 대상으로 한다.
- FR-002: 현재 로컬 브랜치에 일반 병합을 수행하며 빠른 전진·두 부모 병합·이미 포함됨을 처리한다. 원격 조회는 하지 않는다.
- FR-003: 오류와 충돌을 알리고 로컬 변경을 강제 덮어쓰지 않으며 충돌 해결 상태를 보존한다.
- FR-004: 기존 비동기 진행 표시와 실행 중 보호를 적용하고 성공·실패 후 기록과 파일을 새로 읽는다.

### 주요 개체

대상은 선택 커밋의 고유 식별자이며 목적지는 실행 시 체크아웃된 로컬 브랜치이다.

## 성공 기준

- SC-001: 메뉴 선택 한 번으로 현재 브랜치에 선택 커밋을 반영한다.
- SC-002: 빠른 전진·분기·이미 포함됨 검증 모두 예상 브랜치와 부모 관계를 유지한다.
- SC-003: 충돌·잘못된 상태·로컬 변경 보호 검증에서 사용자 데이터를 보존한다.

## 가정 및 명확화

추가 병합 옵션과 별도 확인창은 범위에 포함하지 않는다. 기존 일반 Pull과 같은 병합 규칙을 사용한다.
명확화 단계에서 범위·상태·오류·데이터·화면 일관성을 검토했고 차단 모호성은 없다. 추가 질문 0건.

## 사용자 이야기 2: 병합 실패 원인과 파일 확인 (우선순위 P1)

사용자는 병합을 막은 파일을 오류창에서 확인하고 로컬 변경 차단·실제 잠금·병합 충돌을 구분한다.
독립 검증: 별도 저장소에서 파일을 수정·stage·unstage한 뒤 해당 파일을 바꾸는 커밋을 병합한다.
수용 기준:
1. 로컬 파일 변경으로 병합이 차단되면 원인과 실제 대상 경로를 표시하고 커밋·스태시 안내를 제공한다.
2. 여러 파일은 중복 없이 정렬된 목록으로 표시하며 한글·공백 경로를 유지한다. 병합과 무관한 수정 파일을 포함하지 않는다.
3. 실제 잠금은 잠금으로 안내하고 경로를 추측하지 않는다. 권한 오류를 잠금 존재로 단정하지 않는다.
4. 병합 후 미해결 충돌은 해결 필요로 안내하고 실제 충돌 파일과 병합 상태를 보존한다.
5. 같은 병합 도우미를 쓰는 Pull·빠른 전진에도 진단을 전달하고 오래된 작업의 경로를 현재 알림에 표시하지 않는다.

### 추가 요구사항과 성공 기준

- FR-005: 실제 Git 작업에서 확인한 차단·충돌 경로를 수집하여 공통 오류창 목록에 표시한다.
- FR-006: 로컬 변경으로 인한 차단·실제 잠금·병합 후 충돌을 구분하고 원래 오류를 보존한다. 경로를 알 수 없으면 추측하지 않는다.
- FR-007: 비동기 작업 결과에 구조화된 경로를 전달하고 프로젝트·경로·revision이 유효할 때만 표시한다.
- FR-008: 진단 때문에 강제 덮어쓰기·잠금 삭제·자동 stage/unstage·외부 저장소 변경을 하지 않는다.
- SC-004: stage 후 unstage 재현·다중 경로·비관련 파일 제외·잠금 구분·충돌 상태·Pull 전달·오래된 응답 검증을 통과한다.

명확화: 재현과 검증은 임시 저장소로 수행한다. 사용자 nonmac 저장소에는 어떤 수정이나 실제 병합도 하지 않는다. 새 진단은 기록 병합과 기존 병합·빠른 전진 도우미에 한정하고 리베이스 진단 확대는 범위 밖이다. 추가 질문 없음.
