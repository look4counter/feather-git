# 기능 명세: 커밋 기록 작업 상태 툴바

> 문서 정리일: 2026-11-17. 본문은 이 기능의 단계별 요구사항 이력을 포함한다. 현재 유효 기준과 검증 한계는 [전체 명세 색인](../README.md)을 함께 확인한다. 과거 검증 기록은 현재 버전의 재검증 결과가 아니다.
> 후속 변경 참고: [079](../079-history-rebase/spec.md) · [080](../080-history-revert-reset/spec.md).
> 현재 기준: 작업 상태별 Merge·Rebase·Revert 조작 버튼을 제공한다. 병합에서만 버튼을 제공한다는 초기 제한은 079·080에서 확장되었다.

작성일: 2026-11-16. 상태: 명확화 완료.
입력: Git 작업 중이라는 사실을 커밋 기록 패널 상단 툴바로 표현한다.

## 사용자 시나리오와 검증

### 사용자 이야기 1: 실행 및 후속 처리 상태 인지 (우선순위 P1)

사용자는 커밋 기록 상단에서 현재 작업 실행과 해결·완료 대기를 구분한다.
독립 검증: 병합을 실행하고 충돌을 만든 뒤 해결·커밋하여 툴바 상태 전이를 확인한다.
수용 시나리오:
1. 병합·Pull·커밋 등 앱의 Git 명령 실행 중에는 해당 작업의 실행 중 문구를 표시한다.
2. 실행이 끝나도 병합·리베이스 등의 미완료 작업이 있으면 진행 중 문구를 유지하며 충돌이 있으면 해결 필요를 명시한다.
3. 충돌을 모두 해결한 뒤에도 작업이 남으면 완료 대기로 표시하고 작업 완료 후 툴바를 숨긴다.
4. 저장소 열기와 기존 목록 새로 읽기에 외부에서 시작한 작업 상태를 반영한다.
5. 프로젝트를 전환하면 해당 저장소의 상태를 표시하며 오래된 결과를 적용하지 않는다.

## 경계 조건

정상·빈 저장소는 툴바를 숨긴다. 작업 상태 조회 실패는 정상으로 오인하지 않도록 확인 실패를 표시한다. 충돌만 있고 특정 작업 정보가 없는 경우에도 충돌 해결 필요를 표시한다. 실행 중 상태는 이전 스냅샷보다 우선한다. 제목·빈 기록·열 크기·스크롤은 유지한다.

## 요구사항

- FR-001: 기록 패널 제목 아래, 목록 위에 작업이 있을 때만 상태 툴바를 표시한다.
- FR-002: 현재 앱 명령의 실행 중 문구와 미완료 Git 작업 상태를 구분한다.
- FR-003: 병합·리베이스·체리픽·되돌리기·이분 탐색·패치 적용과 충돌 유무를 표현한다.
- FR-004: 열기·기존 작업 결과·목록 갱신에서 상태를 비동기로 읽고 오래된 결과를 거절한다. 화면 렌더링에서 Git I/O를 하지 않는다.
- FR-005: 정상 복귀 시 툴바를 숨기고 조회 실패는 명시한다. 기존 모달·진행 표시·Git 동작과 데이터는 유지한다.

## 주요 개체

저장소 작업 상태: 작업 종류와 미해결 충돌 여부. 실행 표시: 앱에서 실행한 명령의 이름.

## 성공 기준

- SC-001: 실행 → 충돌 해결 필요 → 완료 대기 → 정상 전이 검증을 모두 통과한다.
- SC-002: 프로젝트 전환·오래된 응답·상태 조회 실패 검증에서 다른 저장소 상태나 잘못된 정상 표시가 없다.
- SC-003: 정상 및 빈 기록에서도 기존 기록 UI를 유지한다.

## 가정과 명확화

기존 작업 보호·모달을 유지하고 작업이 있을 때만 툴바를 표시한다. 병합 커밋·병합 취소 버튼을 추가하며 초기 단계에서는 다른 작업 조작 버튼을 제외했으나 현재는 079·080의 Rebase·Revert 버튼을 제공한다. 외부 변경 실시간 감시는 추가하지 않는다. 기존 새로 읽기 시 외부 상태를 반영한다. 명확화 검토 결과 질문이 필요한 모호성 없음.

## 사용자 이야기 2: 병합 완료 또는 취소 (우선순위 P1)

독립 검증: 충돌 병합에서 버튼 상태를 확인하고 해결·커밋 또는 취소 후 정상 상태로 돌아오는지 확인한다.
수용 시나리오:
1. 미완료 병합이면 병합 커밋·병합 취소 버튼을 표시하고 다른 작업에는 표시하지 않는다.
2. 충돌이 있으면 병합 커밋을 비활성화한다. 해결 후 활성화하면 기존 커밋 창을 연다.
3. 병합 취소는 파일과 충돌 해결 내용에 영향을 줄 수 있음을 알리는 확인창을 열고 기본 선택은 취소다. 취소·Escape는 아무 Git 작업도 하지 않는다.
4. 확인 시 현재 프로젝트·경로·HEAD·병합 상태를 검사하고 비동기로 취소한다. 성공·실패 모두 갱신하며 실패는 원인을 표시하고 강제 초기화하지 않는다.
5. 실행·다른 모달·목록 갱신 중에는 버튼을 비활성화하고 중복 실행을 막는다. 확인은 한 번만 소비한다.

### 추가 요구사항과 성공 기준

- FR-006: 작업별 버튼은 병합·리베이스·Revert에 제공한다. 병합에서만 제공한다는 초기 제한은 079·080으로 확장되었다. 충돌·작업 중·조회 오류·모달 보호는 유지한다.
- FR-007: 병합 커밋은 기존 커밋 창을 열며 미해결 충돌을 거절하고 두 부모 커밋 흐름을 재사용한다.
- FR-008: 병합 취소는 확인창과 안전한 표준 취소를 사용하며 오류·오래된 대상·잠금을 검사하고 성공·실패 후 갱신한다.
- SC-004: 버튼 활성화·확인창 취소·오래된 대상·취소 성공·실패·기존 병합 커밋 회귀 검증을 통과한다.

명확화: 앞선 합의대로 별도 충돌 파일 보기 버튼은 추가하지 않는다. 취소는 병합 전 상태 복귀를 시도하며 복구 불가능한 로컬 변경은 강제로 버리지 않고 오류를 표시한다. 추가 질문이 필요한 모호성 없음.

## 사용자 이야기 3: 병합 버튼 표시 개선 (우선순위 P1)

요청: 병합 취소 확인창 버튼을 확인·취소로 변경하고 병합 툴바 버튼을 줄이며 공통 hover를 적용한다.
수용 기준:
1. 병합 취소 확인창은 확인·취소 버튼을 표시한다. 확인은 병합 취소를 실행하고 취소·Escape는 닫기만 한다. 기본 포커스는 취소다.
2. 툴바의 병합 커밋·병합 취소는 기존보다 작은 크기이며 서로 동일한 크기 규칙을 사용한다.
3. 활성 버튼은 공용 버튼과 같은 hover 효과가 보이고 비활성 버튼은 hover·실행이 적용되지 않는다.

- FR-009: 확인창의 버튼 문구를 확인·취소로 표시하고 기존 동작과 기본 취소 선택을 유지한다.
- FR-010: 툴바 두 버튼을 소형 공용 스타일로 표시하고 병합 취소를 포함한 활성 버튼에 식별 가능한 공통 hover를 적용한다.
- SC-005: 확인창 두 문구·툴바 크기 축소·활성 hover·비활성 실행 보호를 충족한다.

명확화: 크기는 기존 소형 공용 버튼과 일치하도록 합리적으로 정한다. Git 동작 변경은 없다. 추가 질문이 필요한 모호성 없음.
