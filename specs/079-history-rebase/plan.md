# 구현 계획: 커밋 기록 양방향 리베이스

## 요약과 기술 맥락

Rust 2024·GPUI 0.2.2·git2 0.21 Windows 데스크톱 앱이다. 네트워크 없는 로컬 리베이스와 기존 비동기·상태·알림을 연결한다. 의존성·세션 형식 변경 없음.

## 기존 호출·데이터 흐름과 영향

- src/context_menu.rs는 단일 메뉴와 활성 전역 상태·포커스 복원을 관리한다. MenuItem에 선택적 자식 목록을 추가하고 기존 평면 메뉴를 그대로 지원한다. 열린 자식 패널과 키보드 깊이를 관리하고 부모 행 위치 기준으로 별도 패널을 표시하며 창 오른쪽에서는 왼쪽으로 펼친다. 왼쪽·오른쪽·Escape·Enter·hover·외부 클릭·활성 해제를 처리한다.
- src/ui.rs의 open_checkout_menu가 기록 행을 선택하고 checkout_menu_target으로 오래된 대상·작업 상태를 검증한다. 선택 커밋의 references에서 다른 로컬 브랜치 후보를 모아 역방향 메뉴를 구성한다. 다중 후보는 브랜치 자식 메뉴로 구분하고 참조 목록에는 추가하지 않는다.
- src/synchronization.rs의 기존 rebase는 Pull용 초기화·커밋 순환을 갖는다. 이를 src/rebase_actions.rs의 같은 Git 계층 내부 모듈로 옮겨 기존 Pull 회귀와 새 기록 리베이스가 공유한다. 기존 with_locked_index를 같은 계층에서 공유한다.
- 새 RebaseRequest는 선택 커밋·예상 현재 HEAD/참조·선택적 역방향 브랜치를 가진다. 실제 상태와 참조를 검증하고 libgit2의 branch/upstream 인자를 사용하여 역방향에서도 불필요한 선행 checkout 없이 시작한다. 이미 포함된 경우 정방향은 그대로, 역방향은 유효 대상 브랜치를 안전하게 체크아웃한다.
- 로컬 수정은 libgit2의 staged·unstaged 사전 조건과 같은 비교로 경로를 수집한다. 미추적 파일은 실제 checkout CONFLICT 알림으로 보호한다. RebaseFailure는 경로·문구와 원래 오류를 보존한다. 충돌 인덱스 수집은 기존 공용 함수를 재사용한다.
- 계속은 현재 적용 중인 커밋을 먼저 완료한 뒤 다음 패치를 진행하며 추가 충돌은 상태를 유지한다. 취소는 상태·HEAD·잠금 확인 후 표준 git rebase --abort를 숨긴 콘솔로 실행한다. 강제 초기화 대안은 사용하지 않는다.
- repository.rs·backend.rs에서 같은 I/O 경계에 노출하고 ToolbarAction에 시작·계속·취소를 추가한다. 성공·실패 갱신과 경로 전달을 재사용한다.
- ui.rs의 기존 병합 취소 확인창을 작업 종류에 따라 재사용한다. 기본 취소·한 번 소비·경로/HEAD 검증을 보존한다. 리베이스 상태 툴바의 계속은 충돌 없을 때만, 취소는 유효 상태에서만 활성화한다.
- Pull 옵션 제거는 specs/065-pull-options의 OPTIONS·저장값 정규화·선택 및 실행 보호 구현을 유지한다.

## 헌장 및 구조 검사

헌장은 미작성 템플릿이다. 기존 UI·비동기·Git 계층과 오류·데이터 보존 원칙을 유지한다. 새로운 모듈은 재사용 가능한 기존 리베이스 책임을 분리하기 위한 것이며 새 계층이나 의존성은 아니다. 메뉴 하위 목록은 요청한 UI에 필요하며 기존 평면 메뉴 계약을 보존한다. 설계 전후 위반 없음.

## 검증과 순서

명세·명확화·조사·모델·계약 → 작업 목록 → 일관성 분석 → 하위 메뉴·대상·방향·계속·취소·오류 테스트 → 구현 → 전체 회귀·컴파일·엄격한 Clippy·별도 빌드 → 수렴.
검증은 임시 로컬 저장소만 사용한다. 양방향 브랜치·내용·작성자·메시지, 빠른 전진·이미 포함됨, 다중 커밋 충돌 계속 및 취소·잠금·로컬 변경·미추적 파일·대상 이동·다른 worktree를 포함한다. UI는 후보·상태 가드와 기존 메뉴 회귀로 검증하고 수동 검증 한계를 명시한다.

검증 보완: 미추적 파일과 충돌할 때 libgit2 rebase 초기화가 HEAD를 먼저 이동시킬 수 있음을 재현했다. 초기화 전 같은 index 잠금 안에서 checkout dry_run 안전 검사를 수행해 작업 파일·HEAD·참조를 쓰지 않고 사전 차단한다. 진단 알림으로 실제 경로를 수집한다. 계속 처리의 후속 충돌은 기존 리베이스 상태로 보존한다. 관련 명세·작업 재분석 결과 FR-003 데이터 보호를 충족하며 범위 확대 없음.

최종 사전 검사 구현: git2 dry_run의 NONE 매핑 때문에 해당 대안은 사용하지 않는다. tracked 변경을 먼저 거절한 뒤 현재 트리→기준 트리의 실제 변경 경로와 미추적·ignored 경로의 동일·부모·자식 겹침을 검사한다. 경로와 원인을 표시하고 초기화 전에 중단하여 HEAD를 보존한다. 명세·작업 재분석 결과 기존 데이터 보호 조건에 일치한다.

사전 경로 검사는 기준 트리뿐 아니라 재적용할 고유 커밋의 실제 변경 경로까지 포함하여 역방향의 후속 패치가 미추적 파일과 겹치는 경우도 시작 전에 차단한다.

사전 상태 조회는 실제 변경 경로와 파일 형태의 부모 장애 경로에 literal pathspec을 적용한다. 관련 없는 ignored 빌드·패키지 디렉터리를 전체 순회하지 않으며 공백·대괄호 경로를 패턴으로 오인하지 않는다.

## 역방향 완료 후 원래 현재 브랜치 복귀 계획

기존 start_rebase는 libgit2 기본값으로 재배치 대상 브랜치를 체크아웃한다. continue_rebase와 abort_rebase는 시작 요청을 받지 않고 디스크 상태로 재개하므로 UI 메모리에만 복귀 정보를 저장하면 재시작 후 잃는다.
수정은 src/rebase_actions.rs의 작업 수명에 한정한다. 즉시 성공 시 시작 요청의 expected_reference·HEAD를 검증하여 기존 checkout_reference로 복귀한다. 역방향에서 이미 포함된 경우 불필요하게 대상 브랜치로 전환하지 않는다. 충돌이면 rebase-merge 디렉터리에 시작 브랜치·HEAD와 재배치 브랜치·원래 tip을 작은 JSON 문맥으로 기록한다. 계속·취소 전 같은 리베이스의 orig_head와 일치하는지 검증해 읽고, 성공 후 문맥의 원래 브랜치로 안전하게 checkout한다. 디렉터리 정리는 기존 Git 완료·취소가 담당한다. 정상 정방향·외부 리베이스는 문맥이 없으므로 기존 동작을 유지한다.
문맥 읽기·쓰기 실패는 숨기지 않고 작업 상태와 원래 오류를 보존한다. 복귀 체크아웃 실패는 리베이스 완료/취소 결과를 되돌리지 않고 부분 성공을 명확히 알리며 사용자 파일·브랜치를 강제 변경하지 않는다. 세션 형식·UI·공개 함수 서명 변경 없음. 헌장 템플릿·기존 계층 원칙에 충돌 없음.
검증: 두 방향 결과 tip·작성자·메시지 보존을 유지하면서 HEAD·작업 파일을 별도로 확인한다. 역방향 무변경·연속 충돌·계속·취소·문맥 재읽기·복귀 잠금 실패를 회귀로 검증하고 전체 테스트·컴파일·정적 분석·빌드 후 수렴한다.

복귀 체크아웃도 기록 체크아웃과 공유하는 예상 커밋 검증 코어를 사용하여 복귀 참조의 사전 확인과 실제 잠금 사이에 ref가 이동한 경우도 거절한다.
