# 검증 안내

1. cargo test --offline로 양방향·계속·취소·데이터 보호·메뉴·Pull 회귀를 확인한다.
2. cargo check --offline, cargo clippy --offline --all-targets -- -D warnings를 실행한다.
3. 실행 중 앱을 교체하지 않도록 별도 경로에 cargo rustc로 빌드한다.
4. 임시 저장소에서 기록 리베이스의 두 방향과 충돌 후 Stage·계속·취소를 확인한다.

실행 결과와 실제 GUI 검증 여부는 완료 후 기록한다. 실제 사용자 저장소는 검증에 변경하지 않는다.

## 검증 결과

- 구현 전 양방향·계속·취소·보호 테스트의 미구현 API 컴파일 실패를 확인했다.
- 전체 cargo test --offline: 468개 통과, 실패 0개, 기존 제외 3개.
- 최종 리베이스 사전 검사 보완 후 cargo test --offline history_rebase: 9개 통과, 실패 0개.
- 공용 메뉴 cargo test --offline context_menu::tests: 5개 통과.
- Pull 옵션 cargo test --offline footer_action_tests: 6개 통과. 세 옵션·이전 rebase 저장값 복원·선택 거절·실행 보호·갱신 포함.
- 최종 cargo check --offline, cargo clippy --offline --all-targets -- -D warnings: 통과. 최초 Clippy의 중첩 if 지적을 수정하고 재검증했다.
- rustfmt --edition 2024로 새 리베이스 모듈과 변경한 메뉴 파일을 정리했다.
- cargo rustc --offline --bin feather-git -- -o target/history-rebase-verified.exe: 별도 실행 파일 빌드 성공. 출력 지정과 MSVC 라이브러리 생성 안내 경고만 발생했다.
- 검증 범위: 두 방향 브랜치·조상·작성자·메시지·다른 tip 보존, 연속 충돌 해결·Stage·계속, 방향별 취소와 복귀, 실제 충돌 경로 및 작업 결과 갱신, dirty·인덱스 잠금·HEAD 이동·Detached HEAD·다른 worktree·대상 이동·미추적 덮어쓰기 보호, 빠른 전진·이미 포함됨, 한글 외 기존 경로·공백·대괄호·부모 경로 장애, UI 후보 필터·상태·취소 소비 및 메뉴 선택·배치 계산.
- 최초 미추적 충돌 테스트에서 libgit2 초기화의 HEAD 선행 이동을 발견하여 읽기 전용 사전 검사를 추가했다. 설치된 git2 dry_run은 검사 없는 NONE 전략이라 사용하지 않는다. 최종 구현은 실제 기준·고유 커밋 변경 경로와 미추적/ignored 경로만 literal pathspec으로 확인하며 해당 실패를 초기화 전에 차단한다.
- 실제 GUI의 hover·중첩 메뉴 클릭·키보드 및 툴바 버튼은 수동 검증하지 않았다. 메뉴 순수 모델과 배치 및 기존 입력 회귀는 자동 검증했다. 외부 대화형 rebase 편집·exec·skip 전용 UI는 범위 밖이다. 기본 실행 중 앱은 교체하지 않았고 nonmac 등 실제 사용자 저장소는 변경하지 않았다.

## 일관성과 수렴

구현 전 요구사항 6개·이야기 2개·수용 기준 9개와 T002~T007의 대응을 확인했다. 품질 체크리스트 5개 모두 통과했으며 누락·모순·중복 없음. 초기화 사전 검사 발견 시 계획·조사·작업을 갱신하고 기존 데이터 보호 요구 안에서 재분석했다.
구현 후 FR-001~006, 수용 기준 9개, 성공 기준 3개와 하위 메뉴·양방향 대상·루프 공유·계속·표준 취소·공통 확인·진단·비동기 갱신·Pull 옵션 제한 결정을 대조했다. 헌장은 미작성 템플릿으로 별도 원칙 검사 제외. 누락·부분 구현·모순·요청 외 추가 모두 0건이며 수렴 완료다. 추가 구현 작업 없음.

## 역방향 후 원래 현재 브랜치 복귀 검증

- 역방향의 재배치 브랜치 tip·작성자·메시지는 그대로 검증하며 완료 후 HEAD와 작업 파일은 시작 현재 브랜치로 복귀하도록 기대값을 갱신했다. 변경 전 대상 브랜치가 남는 재현 실패를 확인했다.
- 충돌 때 시작 브랜치·HEAD 및 재배치 브랜치·원래 tip을 rebase-merge/feather-return.json으로 보관하고 계속·취소 전 실제 rebase orig_head와 검증한다. 앱 메모리에 의존하지 않는다. Git의 정상 완료·취소가 문맥을 함께 정리한다.
- 검증 범위: 역방향 즉시 성공·이미 포함됨·연속 충돌 해결 후 계속·취소·새 저장소 핸들에서 문맥 재읽기·손상된 문맥 거절·복귀 브랜치 잠금의 부분 성공 안내 및 잠금 보존. 원래 현재 브랜치 tip은 변경하지 않고 대상 재배치 결과는 보존한다.
- 복귀도 기록 브랜치 체크아웃과 공유하는 예상 커밋 검증 코어로 수행하여 실제 ref 잠금 아래 이동을 거절한다.
- 전체 테스트 474개 통과, 기존 제외 3개. 마지막 공통 코어 보완 후 리베이스 관련 15개 및 기록 체크아웃 관련 3개 재검증 통과. 최종 컴파일·엄격한 Clippy·branch-aware-checkout-verified.exe 별도 빌드 성공.
- 실제 UI 복귀·팝업은 수동 검증하지 않았다. 변경 전에 이미 진행 중이던 리베이스처럼 앱 복귀 문맥이 없는 작업은 기존 동작을 유지하며 브랜치를 추측하지 않는다. 실제 사용자 저장소는 수정하지 않았다.
