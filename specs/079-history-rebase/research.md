# 조사 결과

- 결정: 기존 libgit2 리베이스 초기화·커밋 루프를 공유한다. branch 인자로 역방향 브랜치를 지정하면 Git의 일반 동작처럼 해당 브랜치를 재배치하고 완료·취소 시 그 브랜치가 체크아웃된다. 별도 강제 checkout·reset 구현은 제외한다.
- 결정: operation_current가 있으면 계속 시 해당 커밋을 먼저 완료한다. 이미 반영된 패치는 Applied로 처리한다. 작성자·메시지는 원래 커밋을 사용한다.
- 결정: 공용 컨텍스트 메뉴에 자식을 추가한다. 평면 메뉴로 두 항목을 나열하거나 부모 메뉴를 교체하는 대안은 요청한 하위 메뉴와 다르므로 제외한다.
- 결정: 역방향은 참조가 있는 로컬 브랜치만 대상으로 하며 다중 후보는 한 번 더 선택한다. 브랜치를 새로 만들거나 원격 참조를 직접 변경하지 않는다.
- 결정: 기존 작은 버튼·확인창·전역 진행·경로 목록을 재사용한다. Pull 옵션은 별도로 세 가지를 유지한다.
- 설치된 git2와 libgit2 소스로 상태·dirty 검사·리베이스 순환·취소 동작을 확인했다. 미해결 기술 질문 없음.

사전 검사 보완: 설치된 git2 CheckoutBuilder::dry_run은 libgit2의 검사 없는 NONE 전략으로 매핑되어 충돌 사전 검사를 수행하지 않음을 확인했다. unsafe/raw API나 새 의존성을 도입하는 대신 이미 확인한 tracked clean 조건과 실제 target 변경 경로·미추적/ignored 경로의 겹침을 읽기 전용으로 검사한다.

역방향 복귀 결정: 즉시 성공은 요청 문맥으로 복귀하며 충돌 재개는 리베이스 디렉터리의 검증 가능한 문맥으로 처리한다. UI 메모리만 저장하는 대안은 앱 재시작 후 잃고, onto tip을 가리키는 브랜치를 추측하는 대안은 여러 후보에서 잘못 복귀하므로 제외했다.
