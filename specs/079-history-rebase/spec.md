# 기능 명세: 커밋 기록 양방향 리베이스

> 문서 정리일: 2026-11-17. 본문은 이 기능의 단계별 요구사항 이력을 포함한다. 현재 유효 기준과 검증 한계는 [전체 명세 색인](../README.md)을 함께 확인한다. 과거 검증 기록은 현재 버전의 재검증 결과가 아니다.
> 후속 변경 참고: [080](../080-history-revert-reset/spec.md).
> 현재 기준: 기록 메뉴명은 Rebase이며 시작 전에 080의 확인창을 표시한다. 계속·취소는 기존 상태 검증 경로를 유지한다.

작성일: 2026-11-16. 상태: 사용자 명확화 완료.

## 사용자 시나리오와 검증

### 사용자 이야기 1: 기록에서 방향 선택 (우선순위 P1)

사용자가 커밋 기록의 리베이스 하위 메뉴에서 정방향 또는 역방향을 선택한다.
독립 검증: 공통 조상에서 분기한 두 로컬 브랜치로 방향별 조상·브랜치 이름·파일·메시지를 확인한다.
수용 기준:
1. 리베이스 하위에 정방향 (현재를 대상 브랜치로), 역방향 (대상을 현재 브랜치로)를 표시한다. 하위 메뉴는 클릭·hover·키보드로 열고 닫을 수 있다.
2. 정방향은 현재 브랜치의 고유 커밋을 선택 커밋 위에 재적용한다. 선택 커밋에 브랜치가 없어도 정방향은 가능하다.
3. 역방향은 선택 커밋을 가리키는 다른 로컬 브랜치를 현재 HEAD 위에 재적용하며 완료 후 처음 체크아웃되어 있던 현재 브랜치로 돌아온다. 로컬 후보가 없으면 비활성화하고 여러 후보면 브랜치별 하위 항목으로 선택한다. 현재 브랜치·태그·원격 참조는 역방향 후보에서 제외한다.
4. 브랜치와 커밋이 바뀌면 오래된 메뉴 요청은 실행하지 않는다. 네트워크 가져오기는 하지 않는다.

### 사용자 이야기 2: 충돌 계속·취소 (우선순위 P1)

독립 검증: 여러 커밋의 충돌을 해결·Stage·계속하고 완료 또는 취소 후 원래 상태를 확인한다.
수용 기준:
1. 실행 중 전역 진행과 리베이스 문구를 표시하며 성공·실패 모두 기록·파일·브랜치·상태를 새로 읽는다.
2. 충돌 시 실제 경로를 오류창에 표시하고 파일·인덱스·리베이스 상태를 남긴다.
3. 리베이스 상태 툴바에 리베이스 계속·리베이스 취소를 소형 공용 버튼으로 표시한다. 충돌이 남으면 계속을 비활성화하고, 모든 충돌을 Stage하면 다음 커밋으로 진행한다. 추가 충돌이 발생하면 다시 대기한다.
4. 취소는 확인·취소 확인창을 열며 기본 선택은 취소다. 취소 확인 시 리베이스 시작 전 브랜치·파일로 복귀한다. 역방향 취소는 대상 브랜치를 원래 tip으로 복원하고 처음 체크아웃된 브랜치로 돌아온다.
5. 작업 중·다른 모달·갱신·오래된 HEAD·잘못된 상태에서 계속·취소를 실행하지 않는다.

## 요구사항

- FR-001: 기록 메뉴에 양방향 리베이스 하위 메뉴와 유효 대상 보호를 제공한다.
- FR-002: 방향별 실제 대상 브랜치만 재배치하고 원래 작성자·메시지를 보존한다. 불필요한 병합 커밋은 만들지 않는다.
- FR-003: 변경될 브랜치가 다른 작업 트리에서 사용 중이면 거절한다. 로컬 변경·충돌·잠금·없는 커밋·공통 조상 없음·Detached HEAD·빈 저장소·진행 중 작업은 안전하게 처리하며 강제 초기화나 자동 stash는 하지 않는다.
- FR-004: 기존 백그라운드 작업·진행 보호·결과 갱신·공통 오류 경로 표시를 재사용한다.
- FR-005: 계속·취소와 확인 취소·중복 소비·실제 상태·HEAD 검증을 제공하고 실패를 숨기지 않는다.
- FR-006: Pull rebase 제거와 이전 저장값의 일반 Pull 복원을 유지하며 기록 리베이스를 Pull 동작과 분리한다.

## 경계 조건과 주요 개체

정방향 대상은 선택 커밋, 역방향 대상은 그 커밋을 가리키는 로컬 브랜치다. 이미 기준 커밋을 포함한 브랜치는 불필요하게 재작성하지 않는다. 빠른 전진은 새 커밋을 만들지 않는다. 미추적 파일은 덮어쓰지 않는다. 잠금과 dirty 상태는 원인과 경로를 알리고 데이터는 보존한다. 외부 대화형 리베이스의 별도 편집·exec·skip UI는 추가하지 않는다.

## 성공 기준

- SC-001: 두 방향의 브랜치·조상·작성자·메시지·파일 검증이 통과한다.
- SC-002: 충돌 계속·추가 충돌·취소·잠금·로컬 변경·오래된 대상 검증이 통과한다.
- SC-003: 하위 메뉴 탐색·후보 필터·기존 컨텍스트 메뉴·Pull 세 옵션 회귀가 통과한다.

## 명확화와 가정

사용자가 양방향 하위 메뉴와 계속·취소를 요청했다. 역방향은 로컬 브랜치만 대상으로 하고 여러 후보는 선택 항목으로 구분한다. 역방향 완료·취소 후에는 처음 체크아웃된 브랜치로 돌아오는 사용자 지정 동작을 따른다. 실제 사용자 nonmac 저장소를 개발 검증에 변경하지 않는다. 추가 질문이 필요한 모호성 없음.

## 역방향 후 현재 브랜치 복귀

명확화: 대상 브랜치를 현재 HEAD 위로 재배치하되, 완료 후 체크아웃은 시작 당시 현재 브랜치로 복귀한다. 현재 브랜치의 tip 자체를 리베이스 결과로 이동시키는 변경은 아니다.
수용 기준: 즉시 성공·이미 포함됨·충돌 해결 후 계속·취소 모두 원래 브랜치로 복귀한다. 충돌 진행 중에는 해결 가능한 상태를 유지한다. 앱을 다시 열어 계속·취소해도 원래 브랜치를 알 수 있도록 작업 문맥을 보존한다. 복귀 브랜치가 삭제·이동·잠금·다른 worktree 사용 중이면 강제 변경하지 않고 실제 결과와 복귀 실패를 알린다. 추가 질문이 필요한 모호성 없음.
