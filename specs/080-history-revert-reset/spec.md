# 기능 명세: Git 작업 확인·전역 새로고침·찾기

> 문서 정리일: 2026-11-17. 본문은 이 기능의 단계별 요구사항 이력을 포함한다. 현재 유효 기준과 검증 한계는 [전체 명세 색인](../README.md)을 함께 확인한다. 과거 검증 기록은 현재 버전의 재검증 결과가 아니다.
> 현재 기준: 찾기 결과는 커밋 선택 즉시 이동·파일 이력 메뉴만 제공한다. 그래프 추가 부모는 가장 왼쪽 기존 레인과 색을 재사용하고 후보가 없을 때만 새 레인을 만든다.

작성일: 2026-11-17. 상태: 명확화 완료.

## 사용자 시나리오와 검증

### 사용자 이야기 1: 커밋 Revert (우선순위 P1)

커밋 기록의 컨텍스트 메뉴에서 Revert를 선택하면 대상 커밋과 no-commit 체크박스, 확인·취소를 표시한다. 확인 전에는 저장소를 변경하지 않는다. 체크하지 않으면 반대 변경을 새 커밋으로 기록하고 체크하면 커밋 없이 인덱스와 작업트리에 적용한다.

수용 기준: 정상·최초 커밋·병합 커밋, no-commit 두 상태를 검증한다. 병합 커밋은 첫 부모를 기준으로 되돌리며 팝업에 이 기준을 표시한다. 충돌은 Git 상태와 파일을 보존하고 오류·경로를 알린다.

### 사용자 이야기 2: 커밋 Reset (우선순위 P1)

커밋 기록의 Reset 팝업에서 Soft·Mixed·Hard를 단일 선택한다. 인코딩 선택창과 같은 체크 표시·선택 배경·행·확인·취소를 사용한다. 기본은 Mixed이다.

수용 기준: Soft는 HEAD만, Mixed는 HEAD와 인덱스, Hard는 HEAD·인덱스·작업트리를 대상 커밋으로 바꾼다. 선택한 방식의 영향을 설명하고 Hard가 미커밋 변경을 제거함을 확인 전에 표시한다. 취소는 아무 변경도 하지 않는다.

### 사용자 이야기 3: 실행 전 확인 (우선순위 P1)

병합·양방향 리베이스·Push를 실행하기 전에 대상 저장소·현재 브랜치·선택 커밋 또는 방향 정보를 보여주는 확인·취소 창을 표시한다. Pull 병합과 fast-forward only 시작도 같은 확인을 거친다. 리베이스 계속·취소의 기존 흐름과 제거된 Pull rebase 옵션은 유지한다.

수용 기준: 메뉴·툴바의 실행이 팝업만 열고 확인에서만 한 번 실행된다. 취소·Escape·오래된 이벤트·저장소/HEAD/브랜치/대상 변경은 실행하지 않는다. 팝업 동안 다른 작업은 차단하고 닫으면 포커스를 복원한다.

## 기능 요구사항

- FR-001: 커밋 기록에 Revert와 Reset 메뉴를 추가하고 유효한 대상과 작업 가능 상태에서만 활성화한다.
- FR-002: Revert의 no-commit은 기본 해제이며 Git 표준 의미를 따른다. 병합 커밋의 첫 부모 기준을 명시한다.
- FR-003: Reset 세 방식을 인코딩 선택 UI 형태로 제공하고 Mixed를 기본 선택한다. Hard의 파일 변경 제거를 명시한다.
- FR-004: Revert·Reset·병합·리베이스·Push 및 Pull 병합은 확인 전 실제 작업을 시작하지 않으며 취소·Escape는 무변경이다.
- FR-005: 팝업은 대상·예상 HEAD·현재 참조·프로젝트 경로를 보관하고 확인 시 유효성을 재검증하며 한 번만 소비한다. Revert·Reset은 백엔드에서도 실제 HEAD·참조·대상·진행 상태를 재검증한다.
- FR-006: 기존 비동기 전역 진행·성공과 오류 후 목록·그래프·파일·작업 상태 갱신을 재사용한다. 충돌과 오류를 숨기지 않는다.
- FR-007: 팝업은 확인·취소·키보드 선택·Escape·포커스 복원과 배경 작업 차단을 제공한다. 기존 체크아웃·태그·계속/취소 작업은 호환성을 유지한다.
- FR-009: 기록 체크아웃의 브랜치 선택창에 Detached HEAD 항목을 항상 제공한다. 후보 브랜치가 하나여도 선택창을 표시하며 Detached HEAD 선택은 기존 경고 확인창을 거친다. 후보·대상·프로젝트 변경과 취소는 무변경이다.
- FR-008: 그래프 HEAD 표시 수정은 사용자가 철회했으므로 포함하지 않는다. 대용량 파일 기능도 포함하지 않는다.

## 경계와 가정

no-comit은 Git의 no-commit을 의미한다. 기본 해제와 Mixed 기본값은 Git 기본 동작이다. 병합 커밋은 추가 옵션 없이 첫 부모를 사용하며 화면에서 이를 알린다. detached HEAD에서도 유효한 Revert·Reset을 허용한다. 진행 중인 Git 작업·충돌·미확정 대상·오래된 요청에서는 새 Revert·Reset을 거절한다. Hard는 표준 Git reset --hard와 같은 데이터 변경을 하며 팝업 확인이 실행 승인이다. 자동 테스트는 임시 저장소에 한정한다.

## 성공 기준

- SC-001: Revert 두 상태, Reset 세 상태가 임시 저장소에서 HEAD·인덱스·작업파일의 예상 결과와 일치한다.
- SC-002: 취소·Escape·중복 확인·오래된 문맥에서 쓰기 작업이 0회이며 유효한 확인은 1회만 처리된다.
- SC-003: 충돌·진행 중 작업·잠금·HEAD 변경과 오류 후 갱신을 검증하고 관련 테스트·정적 검사·빌드가 통과한다. 실제 GUI 미검증 범위는 별도 보고한다.

## 명확화

2026-11-17: 사용자 요청과 기존 구조에 따라 위 기본값과 경계를 적용한다. 필수 질문이 필요한 미해결 모호성은 없다. Push 확인 요청을 포함하고 당시 현재 HEAD 표시 건은 사용자 철회로 제외했다. 이후 부모 레인 선택 요청은 별도 FR-023으로 반영했다.

명확화 추가: 브랜치 후보가 있는 커밋에도 Detached HEAD를 선택할 수 있어야 한다. 후보가 없는 커밋은 기존 detached 확인 흐름을 유지한다.

## 사용자 이야기 4: 전역 로컬 새로고침 (P1)

- FR-010: 수정키 없는 F5는 현재 프로젝트의 어느 패널에서든 원격 Fetch 없이 로컬 저장소 참조·커밋 기록·작업 상태·변경 파일·뷰어를 갱신한다. 기존 파일 패널 한정 F5와 뷰어 단독 F5는 전역 동작으로 통합한다.
- FR-011: 기존 커밋 ID와 선택 파일의 경로·Stage 구분, 스크롤을 가능한 범위에서 유지한다. 바쁜 작업·확인창·시작 화면·비활성 창·수정키 조합은 새로고침을 시작하지 않는다. 동일 대상 뷰어도 실제 파일을 다시 읽는다.

## 사용자 이야기 5: 저장소 찾기 탭 (P1)

기존 feather-git-old의 git_search와 검색 UI를 읽기 전용으로 분석했다. 전체 로컬·원격·태그 및 detached HEAD 이력에서 커밋 메시지 본문·파일 경로·UTF-8 텍스트 내용을 대소문자 구분 없이 검색하고 작업트리 추적/미추적 파일도 포함한다. 중복 파일은 경로별로 합치고 내용 일치 여부를 표시한다.

- FR-012: 저장소 패널에 찾기 탭과 입력·검색 실행·공통 가상 목록·빈 상태·지연 조회를 제공한다. 검색은 백그라운드에서 실행하고 이전 쿼리·프로젝트 결과가 최신 화면을 덮어쓰지 않는다.
- FR-013: 커밋 결과는 선택으로 기록의 해당 커밋으로 이동하고 파일 결과는 파일 이력 메뉴로 연결한다. FR-022에 따라 커밋 메뉴·복사는 제공하지 않는다. 초기 기록에 없는 커밋도 로컬 조회로 찾아 선택하며 old의 Space/O 등 전용 단축키를 추가하지 않는다.
- FR-014: 기존 디자인의 탭·입력·버튼·공통 목록·메뉴·로딩·파일 이력 UI를 재사용한다. 바이너리 내용은 검색하지 않으며 저장소 밖 링크 파일 내용을 읽지 않는다. 기존 네 탭 동작은 유지한다. 선택 결과 실행은 쿼리·프로젝트·목록 세대를 재검증한다.

추가 성공 기준: 전역 F5의 로컬 갱신과 선택·차단 회귀, old의 메시지/경로/과거 내용/추적·미추적/대소문자/바이너리 검색 회귀 및 stale 결과·메뉴 실행 보호가 통과해야 한다. old 소스와 사용자 저장소는 변경하지 않는다.

## 사용자 이야기 6: Revert 계속·취소 (P1)

- FR-015: Revert 또는 RevertSequence 상태에서 커밋 기록 툴바에 Revert 계속·Revert 취소를 표시한다. 계속은 충돌이 없을 때만 활성화하고 취소는 확인·취소 창을 거친다.
- FR-016: 계속·취소는 실제 진행 상태와 예상 HEAD를 다시 검증하고 성공/실패 모두 기존 목록·파일·작업 상태 갱신을 수행한다. 오래된 확인·중복 입력·다른 작업 상태는 실행하지 않는다.
- FR-017: 앱에서 no-commit으로 시작한 Revert가 충돌하면 계속 후에도 자동 커밋하지 않고 해결·Stage된 변경을 유지한다. 앱을 재시작해도 이 옵션을 보존한다. 일반 Revert와 외부 Git Revert는 표준 계속·취소 동작을 따른다.
- FR-018: 커밋 기록 컨텍스트 메뉴의 병합·리베이스 표기는 각각 Merge·Rebase로 변경한다. 다른 메뉴·옵션의 의미와 실행 확인은 유지한다.

## 사용자 이야기 7: 입력창 선택과 검색 Enter (P1)

- FR-019: 모든 공통 텍스트 입력에서 Shift+Home은 활성 커서부터 줄 처음, Shift+End는 줄 끝까지 선택한다. 한 줄 입력은 전체 문자열 처음·끝을 사용한다. 기존 선택의 기준점을 유지하여 선택 축소·확대·방향 전환을 지원한다.
- FR-020: 비활성 입력은 선택을 변경하지 않고 읽기 전용·비밀번호도 기존 선택/복사 제한을 유지한다. 빈 문자열·빈 줄·한글·이모지·줄 경계에서 UTF-8 범위를 보존한다.
- FR-021: 찾기 입력에 포커스가 있고 IME 조합 중이 아닐 때 수정키 없는 Enter로 검색을 실행한다. 검색 버튼과 같은 경로를 사용하고 다른 패널·결과 목록 Enter와 조합 확정 Enter는 검색하지 않는다.

추가 성공 기준: Revert 충돌 계속·취소·no-commit 재시작·상태/HEAD/잠금 보호, 툴바 활성 조건·취소 단일 소비, 양방향 줄 선택과 IME/검색 포커스 경계의 회귀 검증 및 관련 빌드/정적 검사가 통과해야 한다.

명확화: 계속은 충돌 해결 및 Stage 후 동작한다. no-commit의 기존 의도는 계속 후에도 보존한다. 취소 확인은 기존 병합/리베이스 UI를 재사용한다. Shift+Home/End는 여러 줄 입력에서 현재 줄 단위 선택이며 Ctrl 조합의 기존 문서 이동은 변경하지 않는다. Enter 검색은 최신 사용자 요청으로 추가한다. 필수 질문 없음.

## 찾기 동작 변경

- FR-022: 찾기 탭의 복사 메뉴를 제거한다. 커밋 결과는 컨텍스트 메뉴를 제공하지 않고 마우스/키보드로 선택하면 해당 커밋으로 이동한다. 파일 결과에는 파일 이력 보기 메뉴만 남긴다. 커밋 이동 대기 중 다른 행을 선택하면 이전 이동 결과가 선택을 덮어쓰지 않는다. 이 요구사항은 FR-013의 커밋 컨텍스트 메뉴와 복사 부분을 대체한다.

## 추가 요구사항: 기존 부모 레인 선택

- FR-023: 추가 부모를 기다리는 기존 레인이 여럿이면 가장 왼쪽(레인 번호가 가장 작은) 레인으로 연결한다. 기존 레인이 없는 경우에만 새 레인을 추가한다. 첫 부모 처리, 정렬, 페이지 연속성은 유지한다.
- 수용 사례: 7817dfdf의 부모는 1bed9c3b와 703b5ac3다. 두 번째 부모를 기다리는 첫 번째 레인과 f5e33c1 쪽 레인이 있을 때 첫 번째 레인을 재사용해야 한다.
- 명확화: 사용자의 정정으로 이전의 독립 레인 해석을 폐기한다. 문제는 기존 레인 합류 자체가 아니라 중복 부모를 기다리는 레인 중 마지막 레인을 고르는 것이다. 추가 질문이 필요한 모호성은 없다.
