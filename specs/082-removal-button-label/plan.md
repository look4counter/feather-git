# 구현 계획: 삭제 버튼 문구 중복 수정

## 요약과 기술적 맥락

Rust 2024 및 GPUI 0.2.2 기반 기존 앱이다. src/recent_repository_dialog.rs만 수정한다. 새 의존성은 없다.

## 기존 구조 및 영향 분석

공통 src/dialog.rs의 button은 전달받은 label을 자식으로 추가한다. 삭제 팝업 render는 해당 함수에 label을 전달한 다음 진행 표시·이벤트 영역을 추가하고 마지막에 상대 배치한 label을 다시 추가한다. 따라서 세 버튼 모두 중복된다.

공통 버튼에는 빈 문구를 전달하고, 진행 표시 뒤의 상대 배치된 문구를 그대로 유지한다. 데이터 흐름과 이벤트 핸들러·누름 상태·삭제 처리에는 영향이 없다. 공통 button은 다른 화면에서 사용하므로 수정하지 않는다.

## 헌장 점검

헌장은 미작성 템플릿이다. 기존 UI·저장소 계층과 의존성 및 삭제 안전장치를 유지하므로 충돌은 없다.

## 검증

표시 문구 추가 경로를 코드로 확인한다. 기존 recent_repository_dialog 테스트와 cargo check --all-targets, cargo clippy --all-targets, git diff --check를 실행한다. 단순 표시 수정에 구현을 복제하는 테스트나 새 추상화는 추가하지 않는다. 실제 화면 미확인 여부는 결과에 명시한다.
