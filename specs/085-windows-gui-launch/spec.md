# 기능 명세: Windows 배포 실행 시 콘솔 제거

## 사용자 시나리오 및 검증

### 사용자 이야기 1 — 앱 창만 실행 (우선순위: P1)

사용자는 Windows 배포 실행 파일을 열 때 불필요한 콘솔 없이 앱 창을 사용한다.
독립 검증: 실행 파일의 Windows 실행 유형을 확인하고 탐색기에서 실행한다.

인수 시나리오:
1. Windows 배포 실행 파일을 탐색기에서 열면 앱 창만 열리고 자동 콘솔은 생성되지 않는다.
2. 개발 빌드는 기존 콘솔 진단 동작을 유지한다.

### 경계 조건

- 다른 운영체제의 실행 설정은 바뀌지 않는다.
- 사용자가 명시적으로 여는 외부 터미널은 기존대로 동작한다.
- 배포판의 도움말·오류 출력은 별도 콘솔을 생성하지 않는다. 인수 해석과 종료 코드는 유지한다.

## 요구사항

- **FR-001**: Windows 배포 실행은 앱 자체의 콘솔 창을 자동 생성하지 않아야 한다.
- **FR-002**: 개발 진단, 기존 앱 초기화·인수 처리·종료 및 명시적 터미널 실행 동작을 유지해야 한다.
- **FR-003**: 다른 운영체제의 실행 동작을 유지해야 한다.

## 성공 기준

- **SC-001**: Windows 배포 실행 시 자동 생성되는 앱 콘솔 창이 0개다.
- **SC-002**: 기존 초기화 경로를 유지하고 관련 빌드 검증이 통과한다.

## 가정 및 명확화 검토

직전 메시지의 release 실행 파일을 수정 대상으로 해석한다. 개발 콘솔은 유지한다. 데이터·인증·저장소 형식 변경은 없다. 범위·경계·완료 기준 검토 결과 구현을 막는 모호성은 없으며 추가 질문은 필요하지 않다.
