# 기능 명세: 찾기 목록 공통 스크롤

작성일: 2026-11-18
상태: 명세 및 명확화 검증 완료
입력: 저장소 찾기 탭 목록에 공통 스크롤을 적용한다.

## 사용자 시나리오 및 검증

### 사용자 이야기 1: 검색 결과 탐색 (우선순위: P1)

사용자는 많은 검색 결과를 스크롤하고 목록 클릭 후 위·아래 방향키로 선택을 이동한다.
우선순위 근거: 화면 밖 결과에 접근하기 위한 기본 동작이다.
독립 검증: 화면 높이를 초과하는 결과에서 휠, 스크롤바, 방향키로 마지막 행에 접근한다.

1. 결과가 화면보다 많으면 세로 스크롤바가 나타나고 휠과 드래그로 이동한다.
2. 결과 클릭 후 방향키를 연속 입력하면 선택이 이동하며 재렌더링 후에도 포커스와 스크롤 위치가 유지된다.
3. 새 검색을 실행하면 선택과 스크롤 위치가 초기화된다.

### 경계 조건

빈 결과와 검색 오류는 기존 안내를 표시한다. 조회 중 선택 차단을 유지하고 비활성 상태에서는 스크롤과 방향키를 차단한다. 첫 행과 마지막 행에서 선택이 범위를 벗어나지 않는다.

## 요구사항

- FR-001: 기존 공통 목록과 같은 휠·스크롤바 동작으로 전체 결과에 접근할 수 있어야 한다.
- FR-002: 같은 결과를 다시 그릴 때 목록 포커스와 스크롤 위치가 유지되어야 한다.
- FR-003: 새 검색 시 선택과 스크롤 위치를 초기화해야 한다.
- FR-004: 조회 중 및 비활성 상태 입력 차단과 기존 커밋 선택·파일 메뉴·검색 입력 동작을 보존해야 한다.

### 주요 개체

검색 결과 목록은 결과, 선택 행, 스크롤 위치와 포커스를 보유한다.

## 성공 기준

- SC-001: 화면 밖 마지막 결과까지 휠과 스크롤바로 접근할 수 있다.
- SC-002: 재렌더링 후 방향키를 3회 연속 입력해도 선택이 정상 이동한다.
- SC-003: 새 검색·빈 결과·조회 중·비활성 상태에서 요구한 초기화와 차단이 적용된다.

## 가정 및 명확화

기존 세로 스크롤과 위·아래 방향키 선택을 사용한다. 가로 스크롤과 새 단축키는 추가하지 않는다. 긴 텍스트 생략을 유지한다. 범위, 상태 수명, 오류, 호환성에 중요한 모호성이 없으므로 추가 질문은 없다.

## 사용자 이야기 2: 검색 컨트롤 크기 맞춤 (우선순위: P1)

사용자는 검색 버튼을 저장소 탭 버튼만큼 작게 보고 입력창도 같은 높이로 사용한다.
독립 검증: 탭 버튼과 검색 버튼·입력창의 높이를 비교하고 한글 입력 및 Enter 검색을 확인한다.

- FR-005: 검색 버튼은 탭과 같은 높이 30px, 글자 12px, 좌우 여백 12px를 사용한다.
- FR-006: 검색 입력창은 높이 30px로 버튼과 정렬되며 글자와 커서가 잘리지 않는다.
- FR-007: 다른 화면의 기본 입력창과 다이얼로그 버튼 크기, 검색·IME·목록 동작을 보존한다.
- SC-004: 검색 버튼과 입력창의 높이가 모두 30px이며 탭 버튼과 일치한다.

명확화: 탭 크기는 현재 저장소 패널 탭 스타일을 기준으로 한다. 추가 질문이 필요한 모호성은 없다.

## 사용자 이야기 3: 결과 종류 색상 구분 (우선순위: P1)

사용자는 찾기 목록에서 파일을 의미하는 F를 민트색, 커밋을 의미하는 C를 노랑 계열로 구분한다.
독립 검증: 파일과 커밋 결과가 함께 있는 목록에서 표식 색과 본문을 비교한다.

- FR-008: 파일 표식 F는 민트색, 커밋 표식 C는 노랑 계열로 표시한다.
- FR-009: 표식 외 제목·경로·내용 일치 안내의 기존 색과 생략, 선택·스크롤·메뉴 동작을 유지한다.
- SC-005: 파일과 커밋 표식에 서로 다른 지정 색상이 적용되고 본문에는 표식 색상이 전파되지 않는다.

명확화: 색상 변경 대상은 F와 C 표식이다. 기존 테마와 어울리는 민트와 노랑을 사용하며 추가 질문은 없다. 빈 결과와 조회 중 안내에는 표식이 없고 긴 제목·경로는 기존처럼 생략한다.
