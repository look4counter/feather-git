# 구현 계획: 작업 트리 파일 전체 선택

## 기술 환경 및 기존 구조

Rust 2024·GPUI 0.2.2 Windows 앱이다. `focusable_panel(1)`은 자식 목록 포커스를 포함해 `files_key_down`에 키를 전달한다. 이 함수는 창 활성·패널 포커스·뷰어 작업 상태를 검사하고 Space, Ctrl+D, Ctrl+Shift+C를 처리한다. `file_selection`은 `MultiSelection`이며 `restore`로 모든 인덱스와 기준·활성 행을 설정할 수 있다. 뷰어는 기존 선택 집합을 `ViewerTarget::Files`로 변환하므로 새로운 선택 모델이나 백엔드는 필요 없다.

## 설계 및 영향 범위

수정 파일은 `src/ui.rs`다. 엄격한 Ctrl+A 판별 함수를 추가한다. 기존 키 처리의 포커스·창 활성·뷰어 작업 검사를 재사용하고 전체 선택 분기에서 작업 트리, 현재 프로젝트, 조회·모달·저장소 작업 및 파일 읽기 성공 여부를 검사한다. `select_all_worktree_files`가 `file_selection.restore(0..count, count)`를 호출하고 알림으로 기존 뷰어 갱신을 유도한다. 빈 목록은 안전하게 처리하고 히스토리는 선택하지 않는다. 텍스트 편집기는 기존 SelectAll 액션 처리를 유지한다.

## 헌법과 제약

헌법은 미작성 템플릿으로 구체 원칙 검사는 생략한다. 기존 UI→선택 모델→뷰어 흐름, 공개 형식, 저장 형식과 의존성을 보존한다. 앞선 검색 UI의 미커밋 변경은 그대로 보존한다. 기존 공통 다중 선택을 재사용하며 별도 추상화나 공통 목록의 다른 소비자 변경은 없다.

## 검증 및 진행

단축키 조합, 전체 선택·반복·빈 목록·히스토리·대기·모달·시작 화면 차단을 검증하는 테스트를 구현 전에 작성한다. 기존 작업 트리 다중 선택 테스트와 새 테스트를 실행하고 cargo check·Clippy·diff 검사를 수행한다. 실제 GUI 포커스와 입력란 상호작용을 직접 검증하지 못하면 기록한다. 명세→명확화→계획→작업→분석→구현→수렴 순서로 진행한다.
