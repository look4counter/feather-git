# 기능 명세: 안전한 강제 Push 옵션

작성일: 2026-11-18
상태: 명세·명확화 검증 완료
입력: Push 팝업에 안전한 강제 푸시 체크박스를 추가한다. --force-with-lease 옵션이다.

## 사용자 시나리오 및 검증

### 사용자 이야기 1: 선택한 경우에만 안전한 강제 Push (우선순위: P1)

사용자는 Push 확인 팝업에서 안전한 강제 푸시를 선택해 재작성한 브랜치 이력을 보낸다. 기본은 일반 Push다.
독립 검증: 로컬 원격 추적 정보가 서버와 일치하는 재작성 이력은 성공하고, 서버가 추적 정보와 다르면 거부되는지 확인한다.

1. 팝업을 열면 체크박스가 해제되어 있고 클릭과 Space로 변경할 수 있다.
2. 체크한 뒤 확인하면 안전한 강제 Push가 실행된다.
3. 원격에 아직 가져오지 않은 변경이 있으면 전송을 거부하고 서버 참조를 보존한다.
4. 취소하거나 팝업을 다시 열면 강제 옵션이 남지 않는다.

### 경계 조건

추적 참조가 없으면 원격 브랜치가 존재하지 않을 때만 생성할 수 있다. 원격 브랜치가 삭제되거나 변경되면 기존 추적 값과 다르므로 거부한다. 일반 Push, 최초 Push의 추적 브랜치 설정, 사용자 지정 원격·대상 브랜치, 인증 및 오류 보고를 유지한다. 태그 Push와 커밋 후 Push에는 옵션을 전파하지 않는다.

## 요구사항

- FR-001: Push 팝업에 기본 해제된 안전한 강제 푸시 체크박스와 --force-with-lease 표기를 제공한다.
- FR-002: 확인한 체크 상태가 실행 요청에 전달되고 취소·대상 변경 시 실행되지 않는다.
- FR-003: 선택 시 대상 원격 브랜치의 현재 값과 로컬 원격 추적 값을 비교하여 일치할 때만 강제 업데이트한다. 추적 값이 없으면 원격 부재만 허용한다.
- FR-004: 미선택 시 일반 Push를 유지하며 태그·커밋 후 Push와 다른 확인 팝업은 기존 동작을 유지한다.
- FR-005: 거부 시 원격을 덮어쓰지 않고 안전한 강제 푸시 실패 원인을 사용자에게 알린다.

### 주요 개체

Push 옵션은 팝업별 체크 상태다. 보호 기준은 실행 시작 시 로컬에 저장된 대상 원격 추적 참조 값이다. 저장 형식 변경은 없다.

## 성공 기준

- SC-001: 일치하는 보호 기준의 재작성 이력 Push는 성공한다.
- SC-002: 일치하지 않는 보호 기준에서는 원격 참조가 변경되지 않는다.
- SC-003: 기본·취소·키보드 조작·일반 Push 회귀 검증이 통과한다.

## 가정 및 명확화

명시적 대상 하나를 푸시하는 기존 동작에 --force-with-lease의 보호 의미를 적용한다. 체크 상태는 저장하지 않는다. 새로운 원격 선택이나 일반 --force 옵션은 추가하지 않는다. 추가 질문이 필요한 모호성은 없다.
