# 구현 계획 — 전역 진행 표시 연결

## 기존 구조와 설계

- Rust·GPUI 워크스페이스가 기존 `ProgressOverlay`를 그린다. 파일 작업의 `file_stage_busy`는 변경 적용 및 폐기 미리보기 준비를 감싼다. 기존 상태를 전역 표시 조건에 추가한다.
- 차이 보기는 자체 작업 및 접힌 하위 보기를 관리한다. 진행 상태에 작업 종류를 포함하여 스테이징·폐기를 식별한다. 기존 하위 보기 관찰을 통해 작업 시작·완료를 워크스페이스에 전달한다. 충돌 해결은 기존 로컬 표시를 유지한다.
- 찾기 패널은 백그라운드 요청과 교체된 요청을 자체 관리한다. 워크스페이스에서 현재 저장소와 찾기 탭에 해당하는 패널만 관찰하고, 기존 대기 상태를 읽는다.
- 워크스페이스의 표시 조건을 입력 차단에 사용한다. 기존 마우스 차단을 재사용하고, 포커스가 진행 카드 밖에 남아 있어도 키 입력을 먼저 차단한다. 제목표시줄에는 기존 카드의 제외 영역을 유지한다.

## 헌장과 검증

헌장은 미작성 양식이다. 저장소 지침에 따라 백엔드 작업과 UI 책임, 공개 API 및 파일 형식을 보존한다. 작은 단위 회귀 테스트로 작업 상태의 표시 조건을 확인하고 관련 테스트, 컴파일 검사 및 릴리스 빌드를 실행한다.

## 표시 지연 설계

워크스페이스에서 대상 작업의 대기 상태와 카드 표시 여부를 분리한다. 기존 파일 작업의 시작·종료, 차이 보기 및 검색 관찰 통지로 공통 지연 타이머를 관리한다. 상태가 비면 타이머를 취소한다. 타이머는 화면 갱신만 요청하고 카드 표시 여부는 렌더 시점의 활성 작업 시작 시간으로 판단한다. 입력 차단은 대기 여부를 사용하고 기존 전역 진행 조건은 즉시 표시를 유지한다. 149ms와 150ms, 완료 및 재시작 경계를 테스트한다.

진행 레이어는 지연 중에 투명한 입력 차단 영역으로 유지한다. `src/progress.rs`에서 카드와 배경 표시를 조건부로 적용한다.

## 스테이징 화면 안정화 설계

- 기존 작업 상태가 버튼의 외관과 입력 허용 판단에 같이 쓰인다. 화면 표시에서 작업 트리 쓰기 상태의 일시적 흐림을 제외하되, 각 실행 경로의 보호와 전역 입력 차단을 유지한다. 기존 전역 진행 카드와 배경 암전은 150ms 이후 카드가 표시될 때 함께 적용한다.
- 작업 트리 쓰기 후 파일 요청은 목록, 선택 및 차이 보기 대상을 유지한다. 결과가 수락될 때 파일 상태와 선택을 교체한다. 요청 세대와 저장소 검증을 계속 사용한다. 탭 변경이나 명시적 전환으로 다른 대상을 요청하는 경로는 기존 초기화를 유지한다.
- 기존 워크스페이스 갱신에서 최신 차이 보기를 한 번 요청한다. 차이 보기의 로컬 중복 조회와 진행 문구로 인한 레이아웃 이동을 제거한다. 같은 작업 파일의 왼쪽·오른쪽 비교가 바뀌면 기존 내용을 새 비교가 준비될 때까지 유지한다. 여러 파일의 경우 기존 정확한 일치가 우선이며 필요한 경우 같은 경로의 비교 보기를 재사용한다.
- 회귀 테스트로 새 파일 목록을 기다리는 동안의 선택·대상 보존, 완료 후 변경 반영, 실패 시 선택 해제, 기존 저장소 조회 및 다른 작업 차단을 검증한다.

보존 중인 목록은 기존 가상 목록의 대기 가드를 사용하고 로딩 문구로 교체되는 타이머는 시작하지 않는다.
